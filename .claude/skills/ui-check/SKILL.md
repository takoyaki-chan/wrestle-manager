# /ui-check — UI頻出違反の自己検査

顔・セリフ・進行を扱うコードを書いたら、**出す前に**このチェックを実行する。

## 1. 機械検査

```bash
node test/ui-baseline-guard-test.js
```

失敗があればまず直す。ただし機械検査が拾えるのは一部。**最後は目視**。

## 2. 目視チェックリスト(7項目)

書いたコードを自分で読み直し、各項目に○/×を付けて報告する:

1. **選手画像は 2:3 か** — 素材は256×384。1:1.2の枠に入れると顔が切れる。梯子(XL 172×258 / L 150×224 / M 132×194 / S 108×162 / chip 46×66)から段を選ぶだけにする
2. **正方形の顔は 52px 以下か** — それより大きく見せたいなら2:3に切り替える。80〜120pxの丸アイコンで主役を見せない
3. **吹き出しは画像の「上」か** — `margin-top`で下に付けない。尻尾は画像の水平中心。白(クリーム)+黒文字。**名前・所属を吹き出しの中に書かない**
4. **複数人は隊列になっているか** — 個々に額縁を付けて並べない。群の外枠1つ・18px重ね・`drop-shadow`
5. **勝敗が画像から読めるか** — 敗者は `grayscale(.9) brightness(.72)`。記号は○×△。**`LOSE`の文字は使わない**
6. **待ちに時限の保険を掛けたか** — コールバック待ちにはタイムアウト+二重起動防止フラグをセットで(§5-D 鉄則1)
7. **1操作=1進行か** — 進行ハンドラは自分が動ける状態か検証してから進む(§5-D 鉄則2)

## 3. 設計ドキュメント準拠の確認

- ハードコード16進カラーを使っていないか(必ず `var(--*)` トークン)
- Office / Stage / Ceremony の3カテゴリを混同していないか
- 該当画面の `docs/ui/03-screens/<画面名>.md` があれば実装状況フィールドを更新したか

## 4. 報告

7項目の○×と機械検査の結果を完了報告に含める。×があれば直してから出す。
