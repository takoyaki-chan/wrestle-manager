# /finish — 作業完了フロー

実装が一区切りついたら、以下を**この順番で**実行する。飛ばした工程がある場合は完了報告に「未実施」と明記する。

## 手順

1. **worklog追記** — `docs/worklog.md` の**先頭**に詳細ログを追記する
   - 日付 / タスク名 / 変更内容 / 触ったファイル / 検証結果(auto-sim等) / 残課題
   - ロードマップに長文ログを書かない(2026-07-08 分離ルール)
2. **roadmap更新** — `docs/game-system-roadmap.md` の該当項目のステータスを**1行だけ**更新
3. **specs確認** — docs/ 指示書ベースの作業だった場合:
   - specs/ の該当箇所を更新(既存spec変更 or 新規spec作成)
   - 新規specを作ったら `specs/INDEX.md` に追記
   - specs更新のdiffをKeisukeに確認してもらう。**specs未更新のまま指示書をアーカイブしない**
4. **manifest確認** — 新規JS/CSS/アセットを追加した場合、`release/manifest.json` に追記したか確認
5. **ローカルcommit** — `git add`(対象ファイルのみ) → `git commit`。**pushはしない**(Cloudflare Pages自動デプロイのため、pushタイミングはKeisukeが判断)
6. **完了報告** — 以下を含める:
   - 何をしたか(結果先行・平易に)
   - **確認してほしい画面・操作・表示を具体的に列挙**(UI確認はKeisukeに委任する)
   - 未実施の工程があればその旨

## 注意

- auto-sim はStopフックがターン末に自動で回すので、能動的に追加実行しない(較正判断が必要な場合のみ例外)
- コミットメッセージは既存の履歴のトーン(日本語・種別プレフィックス)に合わせる
