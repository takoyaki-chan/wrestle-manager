## 設計原則

1. **コーチは投資** — 雇用費+維持費がかかるが、長期的に選手の成長を加速する
2. **スタイル一致が鍵** — 選手と同じスタイルのコーチをつけると成長倍率が上がる
3. **特性が個性を作る** — コーチの特殊能力が育成方針に幅を持たせる
4. **枠は団体の成長とともに** — orgPopに応じて枠が増え、段階的にコスト上昇

## §2 コーチ属性

### §2.1 基本属性

| 属性 | 説明 |
|------|------|
| grade | C / B / A — 格。成長倍率・給与・解放条件に影響 |
| salary | 週給（万） |
| hireFee | 雇用費（万）= salary × 8 |
| minOrgPop | 雇用可能orgPop下限（C:0, B:30, A:55）🔧 |
| observation | E / D / C / B / A — 観察眼。レポート品質に影響 |
| style | Grappler / Striker / Aerial / Submission / Brawler / Allround |
| abilities | 特殊能力の配列（§3参照） |
| gMult | 基本成長倍率（1.08–1.25） |

### §2.2 スタイル一致ボーナス

| 一致度 | 倍率 🔧 | UI表示 |
|--------|:------:|--------|
| specialist一致 | +0.08 | 緑（✦一致） |
| allround | +0.05 | 金（○万能） |
| 不一致 | +0.00 | 灰 |

## §4 コーチ観察レポート

### §4.1 発生ルール

| 項目 | 仕様 |
|------|------|
| 発生率 | **25%/週** 🔧 |
| 表示 | 道場バナー内コーチ吹き出し |
| 持続 | 1週（transient: currentCoachReport） |

### §4.2 ランク別レポート品質

| 観察眼 | 内容 |
|--------|------|
| E–D | 曖昧（「誰か調子良さそう」程度） |
| C | 名前指定 + ムード情報 |
| B | 名前指定 + stat方向性 |
| A | trainCap接近ヒント |

### §4.3 精度揺らぎ

COACH_OBS_INACCURACY: レポート値にランダムノイズを加算

## §6 コーチプール

### §6.1 候補生成

| 項目 | 仕様 |
|------|------|
| 候補数 | **5–8名** 🔧 |
| 更新タイミング | 週次 |
| フィルタ | minOrgPop ≤ 現orgPop |

### §6.2 雇用/解雇

- 雇用: hireFee一括 + salary週次
- 解雇: 即時（違約金なし）
- アサイン解除: 即時
