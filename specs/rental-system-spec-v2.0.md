## 設計原則

1. **即戦力の補強** — 自前で育てる時間がないとき、他団体やFAから実力者を借りる
2. **コストと制約のバランス** — レンタルは高額で、タイトル戦に出せない。依存しすぎると経営を圧迫する
3. **人間関係への影響** — 外から来た選手は既存ロスターとの関係に微妙な波紋を起こす

---

## §1 供給元

| ソース | 対象 | 制限 |
|--------|------|------|
| ライバル団体 | AI団体の選手 | OVR上位 **3名** 🔧 を除外 |
| フリーエージェント | FA選手全員 | 制限なし |

## §2 契約条件

| 項目 | 仕様 |
|------|------|
| 期間 | **1〜4シーズン** 🔧（12〜48週） |
| 支払い | 前払い一括 |
| 中途解約 | 不可 |
| 同時枠数 | ロスター8人未満: **2枠**、8人以上: **3枠** 🔧 |

## §3 費用計算

### §3.1 基本式

```
baseFee = (ovr / 50) ^ 2.5 × 25

tierMul:
  S級: 1.40 🔧
  A級: 1.15 🔧
  B級: 1.00 🔧
  FA: 0.85 🔧

discount = 0.35 + 0.35 × min(1, (ovr - 30) / 65)

perSeason = max(20, round(baseFee × tierMul × 12 × discount))
totalFee = perSeason × seasons
```

### §3.2 費用の目安

| OVR | S級1期 | A級1期 | FA 1期 |
|-----|:------:|:------:|:------:|
| 40 | ≈60万 | ≈50万 | ≈35万 |
| 50 | ≈147万 | ≈120万 | ≈90万 |
| 60 | ≈290万 | ≈240万 | ≈175万 |
| 70 | ≈500万 | ≈410万 | ≈300万 |
| 80 | ≈800万 | ≈660万 | ≈485万 |

## §4 レンタル選手の制約

| 項目 | 可否 |
|------|------|
| 通常興行出場 | ✓ |
| タイトル挑戦・防衛 | ✗ |
| コーチアサイン | ✗（AI管理の軽練習） |
| 育成画面表示 | ✗ |
| 成長 | 独立進行（プレイヤーのコーチ恩恵なし） |
| 怪我 | 契約継続（早期帰還なし） |

| orgPop貢献 | **50%** 🔧（MQ平均算出時 weight=0.5） |

## §6 週次処理

```
processWeeklyRental(state):
  for each contract in state.rentals:
    weeksLeft -= 1
    if weeksLeft <= 0:
      帰団処理（§7）
    else:
      roster上のrentalWeeksLeftを更新
```

---

## §7 帰団処理

### §7.1 帰還先

| ソース | 帰還先 |
|--------|--------|
| ライバル団体 | 元の団体ロスター |
| フリーエージェント | FAプール |

人気・怪我状態は保持して引き渡し。

### §7.2 関係性影響

- 帰団時: 同僚→帰還選手 bond **-6〜-3** 🔧（別れ）

---

## §8 シーズン末処理

`advanceWeek offWeek1` で `Engine.rental.processSeasonEnd` を実行:
- `seasonsLeft--` → 0で帰団処理
- レンタル選手は `applySeasonEnd` / `checkRetirement` の対象外（加齢・wear・引退スキップ）

---

## §9 関係性イベント

| タイミング | 効果 |
|-----------|------|
| レンタル加入時 | 既存ロスター→レンタル選手 bond **-2〜+2** 🔧 |
| 再接触チェック | 過去の同僚判定（orgTimeline参照） |

---

## §10 ロスター表示

- 自社選手とレンタル選手を分離表示
- レンタル枠は金枠セクション「🤝 レンタル枠（N/M）」
- スカウトタブでFA+ライバル混合テーブル表示
