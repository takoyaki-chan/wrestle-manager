# 春のタッグリーグ spec v0.2 — 2ブロック制への作り直し

起票 2026-08-01。`specs/spring-tag-league-spec-v0.1.md` からの**構造の差し替え**。
v0.1 の §1 参加チーム数 / §2 チーム編成 / §3 リーグ戦 / §4 決勝戦 を置き換える。
それ以外（§5 試合処理・§6 ベストタッグ称号・§7 演出・§9 GameState など）は v0.1 を継承する。

## 0. なぜ作り直すか

Keisuke（2026-08-01）:
> リーグ戦で順位が1、2、3、4まで決まったのに、なぜか決勝戦があるのはやめた方がいい。
> 決勝戦を作るのであれば、**4チームのリーグを2つ作って、それでそのリーグ1位同士の決勝戦**に
> するならありかな。

**総当たりで1位が決まっているのに、その1位と2位がもう一度やる**——これが v0.1 の構造的な
矛盾だった。総当たりの結果を決勝が上書きしてしまうので、リーグ戦の6試合が「決勝進出者を
2チームに絞るためだけの予選」に見えてしまう。

2ブロック制なら**1位同士は一度も当たっていない**ので、決勝に意味が生まれる。

## 1. 参加チーム数と出場枠

| 項目 | v0.1 | **v0.2** |
|---|---|---|
| 参加チーム数 | 4（各団体1） | **8（団体順位に応じた傾斜配分）** |
| 形式 | 総当たり + 上位2の決勝 | **4チーム×2ブロック + ブロック1位同士の決勝** |
| 試合数 | リーグ6 + 決勝1 = 7 | **各ブロック6×2 + 決勝1 = 13** |

### 出場枠（Keisuke 裁定 2026-08-01）

**団体ランキング順に 3 / 2 / 2 / 1 チーム。** 合計8チーム。

| 業界順位 | 出場チーム数 |
|---|---|
| 1位の団体 | **3** |
| 2位の団体 | **2** |
| 3位の団体 | **2** |
| 4位の団体 | **1** |

- 順位の参照元は `Engine.ranking`（団体ランキング spec v2.1 の総合評価）。
  **Week 10 のアナウンス時点**で確定させ、以降その大会中は動かさない
- **自団体が何位でも同じ表で決まる**。自団体だけ優遇しない
- 1団体から複数チームが出るので、**同じ団体のチーム同士が当たりうる**。
  これは潰さない（強い団体が内輪で潰し合うのは自然な帰結）
- ただし**同一団体のチームは可能な限り別ブロックに散らす**（§2 組み分け）

### 選手数の下限

3チーム = 6名を出す団体が必要。**ロスターが足りない団体は枠を返上**し、
その分は下位の団体へ繰り下げる（8チーム未満での開催も許す。最低6チーム）。
6チーム未満なら**その年は中止**（v0.1 の中止条件を継承）。

## 2. 組み分け

Week 11（エントリー週）に確定。

1. 出場8チームを**業界順位の高い団体のチームから順に**並べる
2. 蛇行配置（1→A / 2→B / 3→B / 4→A / 5→A / 6→B / 7→B / 8→A）で2ブロックへ振る
3. **同一団体のチームが同じブロックに3つ入る場合のみ**、下位ブロックの1つと入れ替える

蛇行にするのは、強い団体のチームが片方に固まると**片ブロックだけ死のブロックになる**ため。

ブロック名は **Aブロック / Bブロック**。

## 3. リーグ戦

各ブロック4チームの総当たり。**組み合わせ・勝ち点・タイブレーカーは v0.1 §3 をそのまま継承**
（勝3 / 分1 / 敗0、MQ60以上で接戦ボーナス+1、`ROUND_ROBIN` の順序も同じ）。

- 各ブロック6試合 → 計12試合
- **順位は各ブロック内で独立**に付く。全体順位は付けない

## 4. 決勝戦

| 項目 | v0.2 |
|---|---|
| 対戦 | **Aブロック1位 vs Bブロック1位** |
| 配置 | 興行のメインイベント（最終試合） |
| 試合条件 | condition は持ち越し（§5 継承）、matchTier 2（ビッグマッチ） |
| 引き分け | **勝ち点 → 接戦ボーナス数 → 直接対決なし → 総MQ の順で上位を勝ちとする** |

引き分け裁定が v0.1 から変わる点に注意。v0.1 は「リーグ1位の勝ち」で済んだが、
**v0.2 の両者は別ブロックなので直接対決の結果が存在しない**。§3 のタイブレーカーを
ブロックをまたいで適用する。

## 6. 殿堂入りポイント

v0.1 §12.3 は「優勝 +3/回（両選手）」。**v0.2 でもこの値は変えない。**
ただし出場チームが倍になったぶん優勝の希少性が上がるので、
**将来の見直し対象**としてここに記録しておく（今回は据え置き）。

> **注意**: 殿堂入りのポイント改定は別途 Keisuke の承認が要る。このspecでは動かさない。

## 7. UI への影響

- **順位表が2つ**になる。1画面に縦積みするか横並びにするかは
  `docs/codex-tasks/task-74`（特別興行の作り直しモック）で決める
- 「進行の俯瞰」は **Aブロック6試合 → Bブロック6試合 → 決勝** の13試合
- 決勝カードは**ブロック名を明示**する（「A1位 vs B1位」が分かること）

## 8. 実装時の不変条件（数値目標と対で書く）

1. **出場チーム数は 3/2/2/1 の合計8**。枠を返上した団体が出ても**繰り下げで埋める**
2. **6チーム未満なら中止**。5チーム以下で無理に開催しない
3. **同一団体のチームが1ブロックに3つ入らない**（§2-3 の入れ替えが効いていること）
4. **決勝は必ず別ブロックの1位同士**。同一ブロックの2チームが決勝に並ばない
5. **リーグ順位は各ブロック内で独立**。全体を通した1〜8位を作らない
6. 試合数は **12 + 1 = 13**。v0.1 の7試合から増えるので、
   **1興行に収まる長さか**を実機で確認する（収まらないなら演出のスキップ導線を見直す）
7. 既存セーブ互換: `G.springTagLeague` の構造が変わるので、
   **旧構造のセーブを読んでも落ちない**こと（旧大会の記録は旧形式のまま表示）
