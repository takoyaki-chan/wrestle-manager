# 信頼度システム リデザイン v2.1

> **作成日**: 2026-03-06
> **目的**: 「整数ベタ書き」の信頼度変動値を、体験逆算・母体スケール・相対比較に基づく小数値でリデザインする

---

## §1 基本設計

### §1.1 母体
- スケール: 0〜100（内部float、表示は整数）
- 初期値: 50
- 判定タイミング: 興行ごと（隔週、シーズン24興行）

### §1.2 設計思想の変更
- **旧**: 勝敗が信頼度の主要な変動要因
- **新**: 「団体が自分をどう扱っているか」が信頼度の変動要因。勝敗は信頼度に影響しない
- 理由: 勝敗は選手自身の問題。社長/団体がコントロールできるのは「誰を」「どんな舞台に」出すか

### §1.3 閾値（変更なし）
| 値 | 帯 | 効果 |
|---|---|---|
| 70+ | high | 残留率↑、引退勧告受容↑ |
| 40〜69 | normal | 通常 |
| 25〜39 | low | 直訴イベント発火対象 |
| 25未満 | critical | ロッカールーム士気に影響 |

## §2 基本値: 出場 / 不出場

### §2.1 導出過程

体験目標から逆算:
- 順調な選手: 24興行中20回出場 → 1シーズンで50→70（+20）
- 冷遇選手（出場率33%）: 12興行中4回出場 → 半シーズンで50→35（-15）

連立方程式:
- 20X − 4Y = +20
- 4X − 8Y = −15

解: **X = 1.53**, **Y = 2.64**

### §2.2 基本値

| 条件 | 値 | 検算 |
|---|---|---|
| 出場した | **+1.53** | 順調20回: +30.6、不出場4回: -10.56 → 差分+20.04 ✓ |
| 出場できなかった（怪我以外） | **−2.64** | 完全干され6興行: -15.84 → 50→34.2（危険圏） ✓ |

### §2.3 不出場の連続蓄積

| 連続不出場 | 倍率 | 値 | 根拠 |
|---|---|---|---|
| 1回目 | ×1.00 | −2.64 | 基本 |
| 2連続 | ×1.15 | −3.04 | 「たまたまじゃない？」と疑い始める |
| 3連続 | ×1.35 | −3.56 | 「自分は必要ない？」 |
| 4連続以上 | ×1.55 | −4.09 | 確信。上限あり |

検算: 3連続で −2.64−3.04−3.56 = −9.24。50→40.8（low帯手前）
4連続で −13.33。50→36.7（直訴圏突入）

## §4 高信頼帯の上昇逓減

### §4.1 設計思想
信頼70を超えると上昇ペースが鈍り、80到達は困難。
ただし80に到達すれば、80→40（危険圏）まで40ポイントの距離自体が保険になるため、下降側の特別な緩和は不要。

### §4.2 上昇逓減係数

信頼70以上で正方向のdeltaに適用（負方向には適用しない）:

```
gainMult = trust < 70 ? 1.0 : 1.0 − ((trust − 70) / 30) ^ 1.4
```

| 信頼 | 上昇倍率 | 出場の実効値 | 感覚 |
|---|---|---|---|
| 50 | ×1.00 | +1.53 | 通常ペース |
| 70 | ×1.00 | +1.53 | ここから逓減開始 |
| 73 | ×0.87 | +1.33 | やや鈍い |
| 75 | ×0.79 | +1.21 | 明確に鈍い |
| 78 | ×0.64 | +0.98 | かなり遅い |
| 80 | ×0.52 | +0.80 | 相当頑張って微増 |
| 85 | ×0.24 | +0.37 | ほぼ天井 |
| 90 | ×0.05 | +0.08 | 実質上限 |

### §4.3 適用ルール
- 出場基本値、舞台追加、ケアアクション、直訴対応 → すべてこの逓減が適用される
- 不出場ペナルティ、直訴無視、引退勧告拒否 → 逓減なし（通常通り減る）
- メンタル係数（§10）の後、この逓減を適用する

## §5 low帯の回復減衰

### §5.1 設計思想
一度信頼がlow帯（40未満）に落ちると、出場させるだけでは信頼が戻りにくい。
「出してはもらえたけど、一度失った信頼はそう簡単には…」
→ リカバリーにはケアアクション（=資金投入）が必要。

### §5.2 回復減衰係数

信頼40未満の選手が出場した場合の基本値に減衰がかかる:

```
recoveryMult = 0.35 + (trust / 40) × 0.65
```

| 信頼値 | 減衰倍率 | 出場の実効値 | 根拠 |
|---|---|---|---|
| 39 | ×0.98 | +1.50 | ほぼ通常 |
| 30 | ×0.84 | +1.28 | やや鈍い |
| 20 | ×0.68 | +1.04 | 明確に遅い |
| 10 | ×0.51 | +0.78 | 出すだけでは全然戻らない |
| 5 | ×0.43 | +0.66 | ほぼ無力。ケアなしではどうにもならない |

## §6 ケアアクション

### §6.1 OVR傾斜係数

OVRが低い選手ほどケアの効果が高い。エースには効果が薄い。

```
careOvrMult = 0.7 + (100 − OVR) / 100 × 0.9
```

| OVR | 倍率 | 意味 |
|---|---|---|
| 30 | ×1.33 | 若手/弱い選手。「自分みたいな選手にここまで…！」 |
| 50 | ×1.15 | 中堅。素直に嬉しい |
| 70 | ×0.97 | 上位。「まあ、ありがとう」 |
| 85 | ×0.84 | エース級。「当然でしょ」 |
| 95 | ×0.75 | トップ。ほぼ響かない |

### §6.2 ケアアクション信頼度値

以下はOVR倍率適用前の基本値。

| アクション | コスト | 信頼度 | OVR40時（×1.24） | OVR85時（×0.84） | 根拠 |
|---|---|---|---|---|---|
| ボーナス支給 | 50万 | +4.59 | +5.69 | +3.86 | 出場3回分。不出場1回を帳消し+お釣り |
| コスチューム新調 | 80万 | +5.36 | +6.65 | +4.50 | ボーナスよりコスト高い分上。「自分専用」の特別感 |
| 専属トレーナー | 160万 | +5.97 | +7.40 | +5.01 | 最高コスト級。成長実利もある |
| メディア露出 | 120万 | +5.36 | +6.65 | +4.50 | コスチュームと同格。人気の実利が大きい |
| 声かけ | 0 | +0.77 | +0.95 | +0.65 | タダ。「見てくれている」の最小表現 |
| リフレッシュ休暇 | 100万 | +5.36 | +6.65 | +4.50 | 休暇中は不出場ペナルティ免除。実質価値はさらに高い |
| 打ち上げ（全体） | 15万/人 | +1.84/人 | +2.28/人 | +1.55/人 | 全体向けだから個人効果は低い |
| 合宿（全体） | 40万/人 | +1.84/人 | +2.28/人 | +1.55/人 | 同上 |

### §6.3 ケアアクションにはlow帯減衰が適用されない

ケアは「金を使って信頼を回復する手段」なので、low帯の出場減衰（§5.2）は適用しない。
ただしOVR傾斜（§6.1）は適用する。

### §8.1 連続関数化

旧: `-1 + Math.floor(mental / 50)` → 段階的（0か1か）

## §9 ロッカールーム士気

### §9.1 母体
- スケール: 0〜100、初期60
- 判定: 興行ごと

### §9.2 信頼度による影響（連続関数）

信頼40未満の選手が士気に与えるマイナス影響。信頼が低いほど強い。

```
moralePenalty = −(40 − trust) / 40 × 3.06  （trust < 40の選手ごと）
```

| 信頼値 | 士気ペナルティ/人 | 根拠 |
|---|---|---|
| 35 | −0.38 | ギリギリ。ほぼ影響なし |
| 25 | −1.15 | 明確に雰囲気を悪くしている |
| 15 | −1.91 | 深刻。周囲にも波及 |
| 5 | −2.68 | 壊滅的。1人で士気を引きずり下ろす |

### §9.3 上昇要因

| 条件 | 値 | 根拠 |
|---|---|---|
| 興行成功（平均MQ65+） | +1.84 | 月+3.68。好興行が続けば70〜80で安定 |
| 人望特性 | +1.84 | 「この人がいると安心」。興行成功と同格 |
| ムードメーカー特性 | +2.53 | 「積極的に空気を作る」。人望の1.37倍 |

### §9.4 人望 × ムードメーカーの重複

重複可。ただし2人目は半減。

```
if (人望あり && ムードメーカーあり) {
  // 高い方をフルで適用、低い方を半減
  delta += 2.53 + 1.84 × 0.5  // = +3.45
} else if (ムードメーカーあり) {
  delta += 2.53
} else if (人望あり) {
  delta += 1.84
}
```

重複なし: +2.53（ムードメーカーのみ）
重複あり: +3.45（+0.92の追加価値。意味はあるが倍にはならない）

## §12 実装指示

### §12.1 変更対象ファイル

**data.js:**
- `FRESHNESS_CONFIG` — 変更なし（後続specで対応）
- `CARE_ACTIONS` — 各アクションの `effects.trust` を §6.2 の値に差し替え
- `LOSING_STREAK_PENALTIES` — trust変動を含まないため変更なし（人気システム側）

**engine.js:**

#### A. `Engine.trust.applyShowTrust()` — 全面書き換え
- 勝敗判定（won/isDraw）を信頼度計算から**完全に削除**
- 出場: 基本値 +1.53 に low帯減衰（§5.2）を適用。高信頼帯逓減（§4.2）も適用
- 不出場: −2.64 に連続蓄積（§2.3）を適用。蓄積には `fighter.noAppearStreak` を参照
- 舞台追加（§3）: メイン判定は `results` 内の試合順序（最後の試合 = メイン）、タイトルは `r.isTitle`、因縁は `r.rivalryLevel` の存在、好試合は `r.mq >= 70`
- 自然変動を §8.1 の連続関数に差し替え
- メンタル係数（§10）と反骨心（§11）は維持

#### A2. 高信頼帯の上昇逓減（§4）
- 正方向のdeltaにのみ適用する関数を追加:
  ```
  gainMult(trust) { return trust < 70 ? 1.0 : Math.max(0, 1.0 - Math.pow((trust - 70) / 30, 1.4)); }
  ```
- メンタル係数適用後、gainMultを乗算する
- 負方向のdelta（不出場・直訴無視等）には適用しない

#### B. `noAppearStreak` のステート管理
- `fighter` オブジェクトに `noAppearStreak: 0` を追加（初期値0）
- `applyShowTrust` 内で:
  - 出場した → `noAppearStreak = 0` にリセット
  - 不出場 → `noAppearStreak += 1`
  - 怪我中 → 変更なし（怪我中は信頼変動なし、ストリークもリセットしない）

#### C. `Engine.trust.calcMonthlyNatural()` — 差し替え
- 旧: `return -1 + Math.floor((mental || 50) / 50);`
- 新: `return -0.46 + ((mental || 50) / 217);`

#### D. `Engine.trust.updateLockerRoomMorale()` — 書き換え
- 信頼25未満一律→ §9.2 の連続関数（trust < 40 の全選手に適用）
- 興行成功: +3 → +1.84
- 人望: +3 → +1.84
- ムードメーカー: +5 → +2.53
- 重複処理: §9.4 に従い、両方いる場合は高い方フル+低い方半減

#### E. ケアアクション効果適用（`Engine.careActions` 関連）
- trust加算時に OVR傾斜係数（§6.1）を乗算
- low帯減衰は**適用しない**（§6.3）
- data.js の `CARE_ACTIONS[x].effects.trust` の値を §6.2 に差し替え

#### F. 選択型イベント効果（`Engine.eventSystem.applyChoiceEffect`）
- 各 `applyTrust(event.fighter, N)` の整数値を以下に差し替え:
  - S1（タイトル挑戦要求）: 受諾 +4.59, 保留 -3.06, 却下 -6.07
  - S3（休養願い）: 休ませる +2.30, 励ます -1.53, 無視 -3.82
  - S4（不満・退団示唆）: 待遇改善 +5.97, 励まし +2.30, 突っぱねる -9.18
  - S5（特訓志願）: 許可 +2.30, 別メニュー +0.77
  - E1（メディア出演）: 出す +1.53
  - E6（引き抜き）: 契約金 +6.89, 説得成功→変化なし（引き止めただけ）, 放出→退団
- 引退勧告拒否: -5 → -3.82

#### G. `Math.round` の除去
- `applyShowTrust` 内の `Math.round(oldTrust + delta)` → 丸めずにfloatのまま保持
- `applyChoiceEffect` 内の `Math.round(...)` も同様に除去
- 表示時のみ `Engine.util.dispTrust(v)` （= `Math.round(v || 50)`）を使う
- `Engine.util` に `dispTrust` を追加

#### H. `describeChange` の閾値調整
- 旧: d >= 8 / d >= 4 の閾値
- 新: d >= 5.0 / d >= 2.5 に変更（値のスケールが変わったため）

### §12.2 テスト観点
- 順調な選手が1シーズンで trust 50→68〜72 に到達するか
- 冷遇選手（出場率33%）が半シーズンで 50→33〜37 に落ちるか
- 完全干され6興行で 50→33〜36 に落ちるか
- low帯（trust 30）からケアなしで毎興行出場しても回復が遅いか（12興行で +8〜10 程度）
- low帯（trust 30）からケア併用で回復が現実的か（6興行+ケア3回で trust 40超え）

### §12.3 注意
- 内部値はfloat。`GameState` のセーブ/ロードでtrustがfloatで保存されることを確認

## §13 信頼度イベント リデザイン

### §13.1 段階設計

信頼度の低下に伴い、選手の反応が段階的にエスカレーションする。

```
70〜50  日常。何も起きない。
50〜40  内面の変化。システム的な微影響 + コーチからの早期警告
40〜25  態度の表面化。プレイヤーに選択を迫るイベント
25未満   危機。引き止め困難、退団リスク
15未満   突然の退団（低確率）
```

### §13.2 信頼50〜40: 不安の芽生え（通知型）

プレイヤーに「この選手、まずいかも」と気づかせる段階。選択肢はなし。

#### N-練習孤立
- **発火条件**: trust < 50、週10%の確率
- **効果**: 対象選手のその週の成長効率 ×0.7
- **通知**: 「〇〇が最近、練習で一人でいることが増えた…」
- **設計意図**: 数値インパクトは小さいが、名前が出ることでプレイヤーの意識に引っかかる

#### N-コーチ報告
- **発火条件**: trust < 45、コーチ在籍時、週15%の確率（N-練習孤立と排他）
- **効果**: なし（純粋な情報提供）
- **通知**: 「コーチ〇〇が報告: 『△△の様子が最近おかしい。少し気にかけてやってほしい』」
- **設計意図**: コーチの価値を上げる副次効果。コーチがいなければこの警告は出ない

#### システム的影響（イベントではない）
- **モチベーション低下**: trust < 45 の選手は週次コンディション回復が ×0.8
- **試合中の意欲低下**: trust < 35 の選手は試合時のMQに −1.53 ペナルティ（「リングに立っても気持ちが入らない」）

### §13.3 信頼40〜25: 不満の表面化（選択型）

#### S1: タイトル挑戦要求（既存・変更なし）
- 発火条件: trust 30〜55、人気30+、タイトル未保持
- 選択肢と効果はv2.1の§7で定義済み

#### S-練習ボイコット（新規）
- **発火条件**: trust < 38、週8%の確率
- **セリフ**: personality×archetypeに応じた不満表現
- **選択肢**:
  1. 「話を聞く」→ trust +2.30（声かけ以上、ケア未満）、その週の成長ゼロ
  2. 「放っておく」→ trust −1.53、その週の成長ゼロ + コンディション −3
  3. 「ボーナスで釣る」（50万）→ trust +3.82（OVR傾斜適用）、その週の成長ゼロ
- **設計意図**: どの選択でも成長は失われる。問題は「関係の修復に何を使うか」

#### S-ロッカールーム愚痴（新規）
- **発火条件**: trust < 35、ロスター4人以上、週6%の確率
- **効果**: ロッカールーム士気 −2.30。さらにランダムな同僚1名の信頼 −0.77
- **セリフ**: 「〇〇がロッカールームで不満をこぼしている…周囲に波及し始めた」
- **選択肢**:
  1. 「個別に声をかける」→ 本人trust +1.53、士気ペナルティそのまま
  2. 「全体ミーティングを開く」→ 本人trust +0.77、士気 +1.23（差し引きで微回復）
  3. 「無視する」→ 士気さらに −1.23
- **設計意図**: 信頼低下が個人の問題からチームの問題に波及する。無視すると雪だるま式に悪化

#### S-SNS匂わせ（新規）
- **発火条件**: trust < 30、人気40+、週5%の確率
- **通知**: 「〇〇のSNSに意味深な投稿が…『自分の居場所はどこなんだろう』」
- **効果**: orgPop −0.77（ファンが気づいて団体イメージ微ダウン）
- **選択肢**:
  1. 「直接話す」→ trust +2.30、orgPopペナルティそのまま
  2. 「メディア対応する」（30万）→ orgPopペナルティ相殺、trust変化なし
  3. 「放置する」→ orgPop さらに −0.77（拡散される）
- **設計意図**: 内部の問題が外部に漏れ始める。人気がある選手ほど発火しやすく、ダメージも大きい

### §13.4 信頼25未満: 危機（選択型）

#### S4: 不満・退団示唆（既存・大幅リデザイン）

**発火条件**: trust < 25、60%/興行（変更なし）

**引き止めコストの変更**:
- 旧: 固定100万
- 新: **選手の週給 × 12（3ヶ月分）**
  - 週給178万のエース王者 → 引き止め約2,136万
  - 週給87万の上位 → 引き止め約1,044万
  - 週給40万の中堅 → 引き止め約480万
  - 週給15万の若手 → 引き止め約180万
  - 設計意図: 引き止め費用は「入口のチケット代」。真のコストはその後のケア継続（ボーナス・トレーナー・メディア等）で積み上がる。入口を払える金額にすることで「引き止めたけど正しかったのか」と悩ませる

**選択肢**:
1. 「待遇改善（-市場価値50%）」→ trust +10.0のみ。**信頼キャップ発動**（後述）
2. 「出場を約束する」→ trust変化なし。約束フラグ。次興行で出さないとtrust −6.07
3. 「励ましの言葉」→ trust +2.30（ほぼ焼け石に水）
4. 「突っぱねる」→ trust −9.18、ロッカールーム士気 −4.59

**信頼キャップ（S4後遺症）**:
- 引き止め成功後、対象選手に `trustCap: 60` を8週間設定
- 期間中は信頼が60を超えない
- 「引き止めてもらったけど、わだかまりは残っている」
- キャップ解除後も信頼は60からの再スタートではなく、現在値のまま。上限が外れるだけ

**2回目のS4**:
- 同一選手が2回目のS4を発火した場合:
  - 引き止めコスト ×1.5（市場価値の75%）
  - 信頼キャップ: 55（より低い）、12週間（より長い）
  - 選択肢に「放出する」を追加（移籍金を回収して退団）

**ロッカールームへの波及**:
- S4発火時点でロッカールーム士気 −2.30（引き止め成否に関わらず）
- 「退団騒動があった」という事実自体がチームに影響する

#### E6: 他団体からの引き抜き（既存・調整）

**発火条件**: trust < 45、人気40+、30%/興行（変更なし）

**変更点**:
- 引き止めコストを選手の週給×12に統一（S4と同じ基準）
- 説得の成功率をtrust依存に（現行と同じだが、閾値を明確化）:
  - trust 35+ → 60%成功
  - trust 25〜34 → 30%成功
  - trust 24以下 → 10%成功
- 引き止め成功後もS4と同様のtrust_cap(60, 8週)を適用

#### 突然の退団（新規）

- **発火条件**: trust < 15、2.5%/興行
- **選択肢なし**: 朝起きたら選手がいなかった
- **効果**: 即座にrosterから除外。移籍金なし。ロッカールーム士気 −4.59
- **通知**: 「〇〇が荷物をまとめて団体を去った。誰も止められなかった。」
- **前提**: N5通知（trust閾値接近警告）がこれより前に必ず1回は出ている設計。プレイヤーが警告を見て何もしなかった結果として起きる
- **退団先**: ライバル団体（人気40+）またはフリー（人気39以下）

### §13.5 ポジティブイベント（信頼70+）

#### P-自発的残留

- **発火条件**: シーズン末の契約交渉フェーズ、trust 75+
- **効果**: その選手の契約交渉イベントがスキップされる
- **セリフ**: personality×archetypeで1行
  - normal: 「残ります。ここが自分の居場所ですから」
  - bold: 「他に行く理由がない。ここで頂点を目指す」
  - quiet: 「………（静かにうなずいている）」
  - shy: 「あの…来年もよろしくお願いします…！」
  - easygoing: 「いやー当然残るでしょ！ここ楽しいもん！」
  - earnest: 「来年も精一杯頑張ります。よろしくお願いします」
  - emotional: 「ここで戦えることが幸せなんです…（涙）」
- **設計意図**: 派手ではないが、信頼を維持してきたことへの静かなご褒美。交渉の心配をしなくて済む安心感

#### P-後輩への好影響（システム効果）

- **条件**: trust 70+ の選手がrosterに存在
- **効果**: roster全体の自然減衰（§8.1）を緩和
  - trust 70+の選手1人につき、全員の自然減衰に +0.05/興行
  - 最大3人分（+0.15）まで
- **見え方**: イベントとしては表示しない。ベテランが抜けた時に「最近みんなの雰囲気が…」と体感で気づく
- **設計意図**: 高信頼のベテランが「見えないチームの柱」になる。失った時の喪失感がドラマを生む

### §14.1 新規イベント追加

**data.js:**

- `CHOICE_EVENT_DIALOGUES` に S-練習ボイコット、S-ロッカールーム愚痴、S-SNS匂わせのセリフを追加（personality×archetype構造）
- `CARE_ACTIONS` の `S4.cost` を固定100万 → 動的計算に変更
- P-自発的残留のセリフを personality×archetype で追加

**engine.js:**

#### A. `Engine.eventSystem.generateNotifEvent()` 拡張
- trust < 50 で N-練習孤立（10%）、N-コーチ報告（15%、コーチ在籍時のみ）を抽選に追加
- 既存のN1〜N5と重み付きで共存

#### B. `Engine.eventSystem.generateChoiceEvent()` 拡張
- S-練習ボイコット（trust < 38, 8%）: S4判定の後、S3の前に挿入
- S-ロッカールーム愚痴（trust < 35, 6%）: S-練習ボイコットの後に挿入
- S-SNS匂わせ（trust < 30, pop 40+, 5%）: S-愚痴の後に挿入

#### C. S4 リデザイン
- コスト計算: `Math.round(Engine.util.calcSalary(fighter) * 12)`
- `calcSalary` は既存の `Engine.util.salary()` を参照
- 引き止め成功時: trust +10.0 + `trustCap: { value: 60, expiresWeek: currentWeek + 8 }`
- 2回目判定: `fighter.s4Count` をインクリメント。2回目以降はコスト×1.5、キャップ55/12週
- 発火時点でロッカールーム士気 −2.30

#### D. trustCap の処理
- `fighter.trustCap` = `{ value: 60, expiresWeek: N }` or null
- `applyShowTrust` 内で、trust更新後に `if (trustCap && trust > trustCap.value) trust = trustCap.value`
- 週次処理で `if (currentWeek >= trustCap.expiresWeek) trustCap = null`

#### E. 突然の退団
- `Engine.trust.checkSuddenDeparture(fighter, rng)`: trust < 15, 2.5%/興行
- 発火時: roster除外、移籍金なし、ロッカールーム士気 −4.59
- 退団先: pop 40+ → ライバル団体振り分け、pop 39以下 → フリー
- `advanceWeek` 内でapplyShowTrustの前に判定（退団したらtrust処理をスキップ）

#### F. システム的影響
- trust < 45: コンディション回復 ×0.8（`Engine.condition` 内で判定）
- trust < 35: 試合時MQ −1.53（`simulateMatch` 内の外部ペナルティに追加）

#### G. P-自発的残留
- `Engine.contract.generateNegotiations()` 内で trust 75+ の選手をスキップ
- スキップ時にセリフを表示（通知型）

#### H. P-後輩への好影響
- `Engine.trust.calcMonthlyNatural()` の呼び出し箇所で、trust 70+選手の数をカウント
- 自然減衰に `+0.05 × min(count, 3)` を加算
