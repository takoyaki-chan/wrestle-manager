# Bond/Rivalry/Trust イベント設計スペック v1.0

> 2026-03-13 作成
> 目的: bond/rivalry/trustの数値帯が引き起こすドラマチックなイベントを体系的に設計する

---

## 1. 概要

### 1.1 解決する問題

1. **因縁段階が試合数ベース**: `RIVALRY_THRESHOLDS` が matches で段階を決定しており不自然
2. **高bondの在籍中恩恵がない**: 仲が良いことがゲーム中に感じられない
3. **低bondのゲームプレイ影響がない**: 仲が悪くてもペナルティがない
4. **trust中間帯（40〜60）が空白**: 低くも高くもない帯域でイベントが発生しない
5. **rivalry×bondの組み合わせが活用されていない**: 好敵手/宿怨等のドラマが存在しない
6. **非対称関係のドラマがない**: 片側因縁以外に「温度差」を表現するイベントがない

### 1.2 設計方針

- `RIVALRY_THRESHOLDS` のtier 1/2/3とmatchesベース昇格を**廃止**
- rivalry値を**連続的なMQボーナスカーブ**に変換（bondのバンドと同じ思想）
- 因縁決着を**rivalry値ベース**に再設計し、**bond値による結末分岐**を導入
- イベントを**第1層（双方条件）**と**第2層（非対称条件）**の2層で設計
- trust中間帯に**感度カーブ**を導入

## 2. 因縁段階システムの再設計

### 2.1 廃止するもの

- `RIVALRY_THRESHOLDS` の tier 1/2/3 概念
- `entry.matches` ベースの昇格判定（L962-979）
- `checkResolution` の `requiredMatches` 条件（L834）
- UI側の `entry.matches >= t.matches` 判定（ui-common.js L2125）

`matches` カウント自体は「通算○戦」表示用に残すが、判定には使用しない。

### 2.2 新設計: rivalry値の連続的MQボーナス

tierの階段ではなく、rivalry値がそのまま連続的にMQボーナスに変換される。

| rivalry帯 | MQボーナス | 表示ラベル | emoji | 色 |
|---|---|---|---|---|
| 0〜29 | 0 | — | — | — |
| 30〜49 | +1 | 因縁 | ⚡ | #fdcb6e |
| 50〜69 | +2〜+3 | 宿敵 | 🔥 | #e17055 |
| 70〜89 | +4〜+5 | 宿命 | 💥 | #d63031 |
| 90〜100 | +6 | 宿命 | 💥 | #d63031 |

**実装候補関数**:

```javascript
getRivalryMQBonus(rivalry) {
  if (rivalry < 30) return 0;
  return Math.min(6, Math.floor((rivalry - 20) / 15));
}
// rivalry30→+0.67→0, rivalry40→+1.33→1, rivalry50→+2, rivalry65→+3,
// rivalry80→+4, rivalry95→+5, rivalry100→+5.33→5
// ※最終的な数値はシミュレーションで調整
```

**片側因縁は維持**: 片方rivalry50+ / 片方rivalry30未満 → MQ+1（現行通り）

### 2.3 表示ラベルのバンド化

bondの toxic/hostile/strained/neutral/close/devoted と同じ思想で、
rivalry値のバンドは**表示専用ラベル**として機能する。
tierの昇格/降格ではなく、値がバンド境界を越えたタイミングでティッカー通知を出す。

## 3. 因縁決着の再設計

### 3.1 1回目決着（因縁決着）

| 項目 | 設計 |
|---|---|
| 条件 | 双方rivalry ≥ 60 + PPV + MQ動的閾値（現行ceiling×0.80方式を維持） |
| rivalryリセット先 | bond ≥ 50 → 10〜20 / bond < 50 → 25〜35 |
| resolutionCount | = 1 |
| popボーナス | 両選手 +4 |
| orgPopボーナス | +1.5（逓減適用） |

1回目決着のbond依存リセットにより、低bond関係は再燃しやすくなる。

### 3.2 2回目決着（最終決着）— bond分岐

| 項目 | 好敵手ルート | 宿怨ルート |
|---|---|---|
| 条件 | 双方rivalry ≥ 80 + PPV + MQ閾値 + **bond ≥ 50** | 双方rivalry ≥ 80 + PPV + MQ閾値 + **bond < 50** |
| resolved値 | `'goodRival'` | `'bitter'` |
| 残留rivalry | 0〜5（凍結） | 30〜40（凍結） |
| 再対戦MQ | +2 | +3 |
| emoji/色 | 🤝 #74b9ff | 💀 #636e72 |
| bond変動 | 凍結 or 緩やかに上昇 | 凍結 or 緩やかに下降 |
| 片方引退時 | 「感謝」演出 | 「因縁の相手がいなくなった」演出 |
| 再接触時 | 「再会」イベント | 「まだ終わっていない」不穏イベント |

### 3.3 M-14（尊敬ルート）

**条件**: rivalry80+ かつ bond60+ かつ MQ75+
**効果**: resolutionCount不問で一発好敵手
**位置づけ**: 通常の2段階決着を経なくても、尊敬し合う激しいライバルが名勝負で直接好敵手になれるショートカット

## 4. 第1層: 双方条件イベント

rivalry×bondの4象限に基づき、在籍中に発火するイベントを設計する。

### 4.1 親友ゾーン（双方bond70+ / 双方rivalry40未満）

#### 週次イベント
| イベント | 効果 | 備考 |
|---|---|---|
| 連携ボーナス | 双方condition回復 +1〜2 | 同じ興行に出場した週 |
| スランプの支え | スランプ脱出率 5% → 8% | 親友が在籍中のみ |
| 連敗時の支え | trustペナルティ × 0.5 | 3連敗以上時 |

#### 低確率イベント
| イベント | 確率 | 効果 | 備考 |
|---|---|---|---|
| 退団引き留め | trust低下時自動 | trust +2〜3 | trust40以下で親友が在籍 |
| 引退延期 | 引退勧告時判定 | 引退を1シーズン延期 | bond80+の親友がいる場合 |

#### 試合効果
- 親友同士の対戦: MQ +1（息が合う）

### 4.2 憎い敵ゾーン（双方rivalry40+ / 双方bond40未満）

#### 週次イベント
| イベント | 効果 | 備考 |
|---|---|---|
| 不穏な空気 | 団体モラル −0.5/週 | 上限−2（複数ペアでもキャップ） |
| 衝突イベント | condition −2〜3、trust微マイナス | 4〜6%/週。**次回対戦MQ+1〜2**の一時ボーナス付与 |
| 練習の激化 | 成長判定に**中〜高ボーナス** | **同時に怪我確率も上昇**。ハイリスク・ハイリターン |

#### 低確率イベント
| イベント | 確率 | 効果 | 備考 |
|---|---|---|---|
| 対戦要求 | rivalry70+ bond20以下 | カード編成時の特殊演出テキスト | 「あいつとやらせろ」 |

#### 試合効果
- rivalry由来のMQボーナス適用（§2.2の連続カーブ）
- 衝突イベント後の対戦: 追加MQ+1〜2

### 4.3 好敵手的ゾーン（双方rivalry40+ / 双方bond50+）

MQが最も高くなるペア。

#### 週次イベント
| イベント | 効果 | 備考 |
|---|---|---|
| 切磋琢磨 | 成長判定に**小ボーナス** | 怪我リスクなし。憎い敵ゾーンより控えめ |
| 意識テキスト | ティッカー表示 | 「○○は△△の試合結果を気にしている」 |

#### 低確率イベント
| イベント | 確率 | 効果 | 備考 |
|---|---|---|---|
| 名勝負後ブースト | MQ70+の対戦後 | breakthrough判定 × 1.3 | 好敵手的ペアの対戦限定 |

#### 試合効果
- rivalry MQボーナス + 息が合うMQ+1 = **二重取り**

### 4.4 無関心ゾーン（双方rivalry30未満 / 双方bond40〜60）

**何も起きない。** 他ゾーンへの入口としてのみ存在する。

### 4.5 成長効果の対比

| ゾーン | 成長ボーナス | 怪我リスク | 差し引き |
|---|---|---|---|
| 親友 | なし（condition/trust保護） | なし | 安定 |
| 憎い敵 | 中〜高 | 上昇 | ハイリスク・ハイリターン |
| 好敵手的 | 小 | なし | ローリスク・小リターン |

## 5. 第2層: 非対称イベント

A→BとB→Aの値に**温度差**がある場合に発火するイベント。
判定は**差分ベース**（差が30以上等）を基本とし、一部は固定閾値を使用。

### 5.1 片思い（A→B bond70+ / B→A bond40以下、差30以上）

「Aは慕っているが、Bはそうでもない」

#### 週次イベント
| イベント | 効果 | 備考 |
|---|---|---|
| 空回り | 親友ゾーンの恩恵がA側に適用されない | B側は完全に無反応 |
| Aの不安定化 | A trust −0.3/週 | B→A bond30以下の場合 |

#### 低確率イベント
| イベント | 確率 | 効果 | 備考 |
|---|---|---|---|
| 裏切られた感覚 | Bが他キャラとbond80+成立時 | A→B bond −3〜5 | 嫉妬。1回限り |
| 献身 | Bスランプ時自動 | Bスランプ脱出率微増 | 見返りなし |

### 5.2 一方的な敵意（A→B rivalry50+ bond30以下 / B→A rivalry20以下）

片側因縁の拡張。「Aは恨んでいるが、Bは気にしていない」

#### 週次イベント
| イベント | 効果 | 備考 |
|---|---|---|
| Aの執着 | A trust −0.3〜0.5/週 | Bがタイトル保持中 or 連勝中の場合 |
| Aの練習激化 | A側のみ成長ボーナス＋怪我リスク上昇 | 憎い敵ゾーンの片側適用 |

#### 低確率イベント
| イベント | 確率 | 効果 | 備考 |
|---|---|---|---|
| 突っかかり | 3〜4%/週 | A condition−2、B rivalry+2 | Bにとっては「なんか絡まれた」 |
| 逆転の火種 | AがBに勝利時 | B→A rivalry通常より多く上昇 | 片側→相互因縁への導線 |

### 5.3 温度差（A→B bond70+ / B→A bond50〜65、差15〜29）

致命的ではないが、Aの方が温度が高い。最もありふれた非対称。

#### 週次イベント
| イベント | 効果 | 備考 |
|---|---|---|
| 恩恵半減 | 親友ゾーンのcondition回復等が0.5倍 | A側のみ |

#### 低確率イベント
| イベント | 確率 | 効果 | 備考 |
|---|---|---|---|
| すれ違い | 2%/週 | A→B bond −1 + ティッカー | 積み重なると片思いに移行 |
| 歩み寄り | 1%/週 | B→A bond +2〜3 | 温度差縮小方向 |

### 5.4 クロス非対称（rivalry×bondの非対称組み合わせ）

#### A: 高riv+高bond / B: 低riv+低bond
- Aは好敵手的ゾーンの恩恵（切磋琢磨）を得る。Bは何も得ない
- Aの引退時にBへの特別テキスト。Bからは無反応
- 専用ティッカーテキスト（最も切ない関係）

#### A: 高riv+低bond / B: 低riv+高bond
- ❶片思い + ❷一方的な敵意が**同時成立**する最悪のすれ違い
- **覚醒イベント**（低確率）: Bがキレる → B→A rivalry +15〜20、bond −10〜15。「もう我慢の限界」。相互因縁への発展導線

## 6. trust中間帯（40〜60）のイベント設計

### 6.1 trust感度カーブ

新規イベントを大量に追加するのではなく、既存のtrust変動イベント全てに**帯域別の感度係数**を掛ける。

```javascript
trustSensitivity(trust) {
  if (trust <= 44) return 1.3;  // 警告帯: やや敏感
  if (trust <= 60) return 1.5;  // 中間帯: 最も敏感
  if (trust <= 75) return 1.0;  // 安定帯: 基準
  return 0.7;                   // 盤石帯: 鈍感
}
```

中間帯の選手は同じイベントでもtrust変動が1.5倍。「気を配らないといけない層」が自然に生まれる。

### 6.2 警告帯イベント（trust 40〜49）

| イベント | 効果 | 備考 |
|---|---|---|
| ティッカー警告 | なし（純粋な通知） | 「○○の表情が最近曇っている」 |
| 練習効率低下 | 成長判定 × 0.9 | モチベーション低下 |
| bond形成阻害 | 新規bond上昇量 × 0.7 | 団体不信 → 仲間との距離 |

### 6.3 心変わりの瞬間（trust 50〜60）

| イベント | 条件 | 効果 | 備考 |
|---|---|---|---|
| 抜擢への反応 | 初タイトル戦・初PPVメイン等 | trust +5〜8 | 中間帯でこそ響く |
| 約束と裏切り | PPVカード差し替え等 | trust −3〜5 | 高trust帯なら許容されるが中間帯は傷つく |

### 6.4 trust帯域別キャラクター一覧

| 帯域 | 性格 | プレイヤーへの意味 |
|---|---|---|
| 80+ | 盤石（感度×0.7） | 安心して任せられるエース |
| 61〜79 | 安定（感度×1.0） | 手がかからない |
| 45〜60 | 敏感（感度×1.5） | 気配りが必要、放置危険 |
| 40〜44 | 警告（感度×1.3） | 手を打たないと30台に落ちる |
| 15〜39 | 危険 | 契約交渉、引き抜きリスク |
| 0〜14 | 崩壊 | 突然退団 |

### 9.2 各フェーズの詳細

#### Phase A: 因縁段階の連続化（Sonnet）

**既存の仕組みを壊して作り替えるコアフェーズ。最も慎重に。**

1. `RIVALRY_THRESHOLDS` のtier/matches判定を廃止（data.js, engine.js）
2. `getRivalryLevel` をrivalry値ベースの連続MQボーナスに全面改修（§2.2）
3. `checkResolution` からrequiredMatches条件を除去、rivalry値+bond分岐に改修（§3）
4. 宿怨（resolved='bitter'）用の定数追加（BITTER_RIVAL_*）
5. `recordRivalry` のmatchesカウントは記録のみ、判定には不使用に変更
6. tier昇格チェック（L950-990）を廃止、バンド境界越え通知に置換
7. UI表示（ui-common.js）をmatches→rivalry値ベースに変更
8. 既存セーブデータの移行処理（tier→廃止、resolvedの文字列化）
9. auto-sim 500シーズン検証

#### Phase B: 第1層イベント — ロジック（Sonnet）

1. `processWeeklyRelationships` に4象限判定ロジック追加
2. 親友ゾーン: condition回復、スランプ脱出率UP、trustペナルティ軽減、退団引き留め、引退延期
3. 憎い敵ゾーン: モラルマイナス、衝突イベント→次戦MQボーナス、練習激化（成長↑+怪我↑）、対戦要求
4. 好敵手的ゾーン: 切磋琢磨（小成長ボーナス）、名勝負後ブースト
5. 試合MQ効果: 親友+1、好敵手的は既存rivalryボーナス+1の二重取り
6. ティッカーテキストは **プレースホルダ文字列** で仮実装（E-2で差替え）
7. auto-sim検証

#### Phase C: 第2層イベント — ロジック（Sonnet）

1. 非対称判定ロジック（差分ベース / 固定閾値）の追加
2. 片思い: 空回り、trust微減、裏切られた感覚、献身
3. 一方的な敵意: 執着trust減、片側練習激化、突っかかり、逆転の火種

### 9.3 モデル分担まとめ

| モデル | 担当 | 理由 |
|---|---|---|
| **Sonnet** | Phase A, B, C, D, E-1 | ロジック改修・条件分岐・数値処理。スペックが明確なので機械的に実装可能 |
| **Opus** | Phase E-2 | セリフ・世界観テキスト・演出文の執筆。キャラクター性・物語性・日本語の質が重要 |

### 9.4 実装上の注意

- Phase A は既存の仕組みを壊すため、**他フェーズより慎重に**。auto-simは500シーズンで検証
- Phase B, C のティッカーテキストは一旦プレースホルダ（`"[TODO:ticker]"` 等）で仮実装し、E-2で差替え
- Phase E-2 は B, C 完了後に着手。プレースホルダの位置とフォーマットを把握してから執筆に入る
- 各フェーズで新規追加した定数は `data.js` の関連セクションにまとめ、既存定数の近くに配置
- テスト指示には実装コードを含めない。検証手順のみを記述
