## 設計原則

1. **社長の判断が問われる** — 3択の選択肢に正解はない。コスト・リスク・信頼のトレードオフ
2. **キャラクターの物語を動かす** — イベントは数値処理ではなく、ドラマの起点
3. **頻度を制限する** — 大型イベントは希少だからこそ印象に残る

## §2 B1: 練習中の怪我

### §2.1 発生条件

- 重み: **3** 🔧
- 対象: condition最低の選手
- 重症度: condition 30–49 → 軽傷 / condition < 30 → 中傷

### §2.2 選択肢と結果

**選択肢A: 特別治療（-200万）**

| 重症度 | 怪我期間 | 成長ペナルティ | trust |
|--------|:-------:|:----------:|:-----:|
| 軽傷 | 2週 | 3週 ×0.7 | +5 |
| 中傷 | 3週 | 7週 ×0.4 | +5 |

**選択肢B: 通常治療**

| 重症度 | 怪我期間 | 成長ペナルティ |
|--------|:-------:|:----------:|
| 軽傷 | 3週 | 6週 ×0.7 |
| 中傷 | 6週 | 14週 ×0.4 |

**選択肢C: 強行出場**

- trust **+3**
- **40%** で悪化 → 中傷扱い（6週怪我 + 14週ペナルティ）
- 60%で軽傷扱い（3週怪我 + 6週ペナルティ）

## §4 B3: 他団体からの挑戦状

### §4.1 発生条件

- 重み: **2** 🔧
- 条件: orgPop > **20** 🔧
- 挑戦団体: 順位隣接（±1位）のAI団体

### §4.2 フロー

| Step | 選択 | 効果 |
|------|------|------|
| 0 | A: 受諾 | Step 1（代表選出）へ |
| 0 | B: 辞退 | 評判ダメージ |
| 1 | 代表選手を選択 | Step 2（試合）へ |
| 2 | 試合結果 | orgPop変動、rivalry変動 |

### §4.3 試合結果

- 勝利: 自団体選手→挑戦者 rivalry +8〜+12, orgPop増加
- 敗北: 相手団体にorgPop流出

**団体人気の表(2026-09-26 K-9 残り)**: 素の値は自団体・AI団体共通の `Engine.orgPop.B3_RAW_DELTA`(勝ち+3/引き分け+1/負け−1/辞退−1)。
上げ幅には興行の逓減(`Engine.orgPop.applyOrgPopChange`)を、**それぞれの団体自身の人気で**掛ける(下げ幅はそのまま)。

| 結果 | 自団体 | 挑戦してきたAI団体(AIの立場) |
|---|---|---|
| 自団体の勝ち | +3×逓減 | −1 |
| 自団体の負け | −1 | +3×逓減 |
| 引き分け | +1×逓減 | +1×逓減 |
| 辞退(Step0 B) | −1 | 動かない(AI同士の辞退でも挑戦側は動かない) |

- 例: 自団体の人気75(逓減0.22)・挑戦団体の人気45(逓減0.35)なら、自団体の勝ちで 自団体+0.66/相手−1、負けで 自団体−1/相手+1.05
- 実装: `applyLargeEventEffect` の B3 Step2 が、代表選手の履歴と一緒に相手のAI団体の人気を動かした `aiOrgs` を返す
  (`Engine.orgPop.applyToAiOrg`。人気の欠損だけ50で補い、0は0のまま)。画面の2経路(観戦・スキップ=`App._finalizeB3Match`→
  `_applyLargeEventResult`、興行内の挑戦状=`_finalizeShowImpl` の `b3Updates`)はどちらも返り値の `aiOrgs` をそのまま反映する
- 旧来(〜2026-09-25)は、相手のAI団体の人気は勝っても負けても動かなかった
- ログ・新聞に相手の人気の数値は出さない(ログの文面は自団体の変化量だけで従来どおり)
- プレイヤーが出す挑戦(奪還挑戦状・直訴シリーズ・遠征)は、自団体・相手とも団体人気を動かさない(表が無い)

### §4.3b 挑戦者(ゲスト)を所属団体へ戻すとき(2026-09-26)

受けた挑戦状の試合は次の通常興行のメインで行う(`reserveScheduledSingleMatch`)。

**挑戦者は予約を消化する時点(興行準備・興行の開催)の本物の選手から作る**(2026-09-26 Keisuke 裁定「直す」。直訴 `getScheduledCard`・
全国統一王座戦 `getIncomingMatch` と同じ作り方)。`Engine.challengeRequest.getScheduledSingleChallenge` が、予約 `_pendingIncomingB3Match`
の写し `challenger` の id で、挑戦してきた団体(`orgId`。記録の無い古い予約だけ、いまいる AI団体)の最新のロスターから本人を引いて返す。
写しは id・名前を引くためだけに残る。興行はその本人の写しに一時印 `isB3ChallengeGuest` / `_b3GuestOrgId` を付けて自団体のロスターへ
一時的に入れ、試合後の処理(`Engine.show.finalize`)を自団体の選手と同じく通す。

- **本人が出られなければ予約は成立しない(消滅)**: 怪我・引退・移籍(挑戦してきた団体のロスターにいない)・団体の解散・自団体のロスターに
  来ている(レンタル等)。代表の選手(自団体)が怪我・休養・謹慎のときと同じく、興行準備の画面と開催の時点で予約を解除し
  「⚠ 挑戦試合の出場条件が整わないため、予約を解除しました」を出す(直訴・統一王座戦の予約と同じ扱い。持ち越さない)
- 他団体の選手の「出られない」は**怪我だけ**で見る(全国統一王座戦の `_available` と同じ)。休養(`forcedRest`)は付けた団体の「次の興行」までの印で、
  自団体の興行に呼ぶ他団体の選手を縛るものではない(2026-09-26 まで AI団体では外れず何十週も残っていた。いまは AI の興行の開始で外れる。rival-org-spec §4.0)
- 前後の差(`tools/b3-guest-source-compare.js`、seed 42/7919/15838 の S2〜S4・通常興行週ごとに代表は自団体の OVR 上位3人・
  前の週に届いた挑戦状、実プレイと同じ興行の処理): 挑戦者の怪我 **100%(513/513)→ 8.7%(43/492)**(同じ試合の代表の怪我 8.7%)。
  代表の勝ち 47.8% → 47.8%(同じ組で勝敗が入れ替わったのは 3/492)。予約の解除(挑戦者が届いた後に怪我)21/513
- 旧来(〜2026-09-26)は挑戦状が届いた時点の写し `event.challenger`(id・名前・能力5つ・スタイル・役割・人気・特性だけ)から作っていた。
  写しに体調が無いため怪我の判定の確率が NaN になり(`Engine.injury.check` の `rng > NaN` が常に偽)**挑戦者は毎回必ず怪我をした**。
  年齢が無く成長は17歳扱い、自己最高評価・信頼も欠けたまま、届いた後に伸びた能力も入らず、予約の後に本人が怪我・移籍しても試合に出てきた

清算(`App._finalizeHookGuests`)の最後に、所属団体のロスターにいる本物の選手へ `Engine.challengeRequest.mergeReturningGuest(本物, 興行に入れたときの写し, 興行後のゲスト)` で戻す。
**写しを本物へ被せず、この興行で起きたこと(前後の差)だけを反映する**:

| 反映するもの | 本物への反映のしかた |
|---|---|
| 怪我 | 新しい怪我・体調は min(本物の体調, 30)・怪我の前の人気(本物に記録が無いときだけ)・今季の怪我数+1・成長の減速(重い方を残す)。どれも `Engine.injury.check` と同じ規則 |
| 試合の記録 | 直近戦績は本物の末尾に今回の1戦を足して5戦・最後の勝敗・連敗数(勝ち/引き分けで0、負けで本物+1)・自己最高評価は大きい方・経歴(careerRecord は重複を除いて合流、careerHistory・growthLog は末尾に足す)・プロモの蓄積(0) |
| 人気・能力 | 興行の前後の差を本物に足す(人気は1〜100、能力は本物の上限 trainCap まで)。今季の伸びは能力に実際に足せた分だけ |
| 調子の波 | 本物の3つ(絶好調・スランプ・モチベ喪失)が興行に入れたときと同じなら、試合後の処理の結果をそのまま持ち帰る(始まり・勢いの変化・終わり。2026-09-26〜)。違うときは、本物がどれも持っていないときだけ新しく始まったものを持ち帰る(エンジンもそういう選手にしか始めない) |

- それ以外(体調・契約・年齢・勝敗数など)は本物のまま。**信頼の即時ボーナス `_trustBonus` は持ち帰らない**(自分の団体の舞台での出来事への信頼なので、他団体の興行からは持ち込まない)
- 一時印は必ず外す。直訴(`isCRGuest`)・遠征(`isAwayChallengeGuest`)の返却も `Engine.challengeRequest.stripGuestMarkers` で外す(この2つのゲストは最新のロスターから作った本物の写しなので、中身はそのまま戻す)。印が残った選手が後で自団体に入ると、保存(`App.serialize`)とロード時の修復が一時ゲストとみなしてロスターから消すため
- 既存セーブに残った印は、ロード時の `Engine.saveDoctor.repairOnLoad` が AI団体のロスターとフリーの選手から外す(修復の記録 `guest_markers_stripped:N`)
- 旧来(〜2026-09-26)は写しを本物へ `{ ...本物, ...ゲスト }` で被せていた。ゲストが怪我をすると本物の体調が NaN(validateGameState が毎週違反)、自己最高評価が今回の評価に下がり、今季の伸びが0に戻り、直近戦績が1戦になり、一時印と信頼の即時ボーナスが残っていた。失われた過去の値は戻せない
- 回帰テスト: `test/b3-guest-return-test.js`(返却)・`test/b3-guest-from-real-fighter-test.js`(開催の時点の本物から作る・出られない本人の予約の消滅・本物の興行での怪我の率・調子の波)。点火 `b3-challenge` / `b3-challenge-watch` が興行中のゲスト(体調・年齢を持ち、同じ時点の本物と同じ値)と返却後の本物の選手(体調・自己最高評価・直近戦績・一時印)を検算する
- 2026-09-26 までの「未決」(写しに体調が無く挑戦者が毎回必ず怪我をする・17歳扱い・予約の後の怪我を見ない)は、同日の裁定で上の「開催の時点の本物から作る」に直した

### §4.4 AI団体間 B3（NPC vs NPC、2026-04-27 追加）

MVPレースの公平性を保つため、B3挑戦状はAI団体間でも自動発生する。

- **判定**: 週次、`week % 4 === 0`、両AI団体とも `orgPop > 18`、双方の `lastB3Week` から6週経過
- **発生率**: 5%（ペアあたり）
- **対戦相手**: ランキング±1〜±2位のAI団体（プレイヤー除外）
- **挑戦側代表**: 健全な選手のOVRトップ5から1名（ランダム）
- **受諾側代表**: 健全な選手のOVRトップ3から1名（チャンピオン50%優先、対抗戦と同じ）
- **受諾判定**:
  - 挑戦側=格下（受諾側=格上）: 受諾率 **85%**
  - 同格: 受諾率 **75%**
  - 挑戦側=格上（受諾側=格下）: 受諾率 **45%**
- **試合**: `Engine.battle.simulateMatch(c, d, rng, matchTier=2)`（ビッグマッチ扱い）
- **結果適用**:
  - 勝者: orgPop +3×逓減、選手 popularity +3、trust +5
  - 敗者: orgPop -1、trust -3
  - 引き分け: 両orgPop +1×逓減、両者 trust +2
  - 団体人気は自団体と同じ表(§4.3)と同じ逓減(`applyOrgPopChange`)を、それぞれの団体自身の人気で掛ける(2026-09-26 K-9 残り。旧: 逓減なしの+3/+1)
  - rivalry +8〜12（isCrossOrg=true で applyMatchResult）
  - h2h履歴・MVPレース v2 の `b3Challenge` 履歴を両者に記録
- **辞退時**:
  - 受諾側 OVRトップ3に `b3Decline` 履歴（MVP -4pt）+ orgPop -1
  - 挑戦側に `b3Rejected` 履歴（MVP +4pt）
- **新聞**: `aiB3Result`（priority 138, MQ90+で +20）/ `aiB3Decline`（priority 105）

実装: `Engine.rival.processAIB3Challenge(rng, state)` (management.js)、`tickWeek` の `processAIWar` 直後で呼ぶ。
