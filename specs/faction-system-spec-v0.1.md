## 設計原則

1. **Bond/Rivalry だけでも対立は起きる** — moraleや trustは背景の増幅係数に過ぎず、派閥と対立の主軸はペア関係（Bond/Rivalry）の集約
2. **派閥は物語装置、最適化対象ではない** — 数値効果は控えめに、ドラマの起点としての役割を重視
3. **数値は嘘をつかない** — 派閥は既存の bond/rivalry から自然に浮かび上がるクラスタであり、勝手に作られた概念ではない
4. **数値は見せない、帯とフレーバーで見せる** — 対立度・勢いは内部値、UI にはフレーバー表現のみ
5. **リーダー・幹部クラスの対決でのみ盛り上がる** — 末端同士の対立は効果を持たない。「強い選手同士の抗争」が派閥を意味あるものにする
6. **既存バランスを壊さない** — appeal加算は排他・キャップで制御し、rivalry/タイトル/派閥の重複による暴走を防ぐ

## §1 データモデル

### §1.1 派閥（Faction）

```
GameState.factions = [
  {
    id: number,                      // 派閥ID（連番）
    name: string,                    // 「○○組」リーダー名ベース
    leaderId: number,                // リーダーの fighter.id
    memberIds: number[],             // 全メンバーの fighter.id（leader含む）
    type: 'loyal' | 'rivalrous',     // 忠誠型 / 対立型（対立相手がいる）
    authoritativeTag: boolean,       // F01でAを選んで結成された場合 true（権威化）
    dictatorTag: boolean,            // F07でAを複数回選んだ場合 true（独裁化）
    momentum: number,                // 勢い -100〜+100
    createdSeason: number,
    createdWeek: number,
    lastLeaderChangeSeason: number,  // 後継発生時の更新用
    lastLeaderChangeWeek: number,
  },
  ...
]
```

### §1.2 対立度（Hostility）

**矢印モデル（非対称）**: 派閥A→B と B→A を別々に持つ。

```
GameState.factionHostility = {
  "fA>fB": 60,   // 派閥Aから派閥Bへの敵意
  "fB>fA": 45,   // 派閥Bから派閥Aへの敵意
  ...
}
```

| 帯 | 範囲 | フレーバー |
|----|------|-----------|
| 冷え込み | 0–19 | 表面的には無関心 |
| 小競り合い | 20–39 | たまに衝突する程度 |
| 抗争 | 40–59 | 明確な敵対関係 |
| 泥沼 | 60–79 | 憎悪が日常化 |
| 血みどろ | 80–100 | 殲滅戦 |

### §1.3 勢い（Momentum）

派閥ごとに独立（ペアではない）。-100〜+100 の符号付き整数。

| 帯 | 範囲 | フレーバー |
|----|------|-----------|
| 隆盛 | +60以上 | 乗りに乗っている |
| 上昇 | +30〜+59 | 勢いが増している |
| 平常 | -29〜+29 | 標準 |
| 陰り | -59〜-30 | 陰りが見える |
| 衰退 | -60以下 | 崩壊寸前 |

### §1.4 イベントクールダウン

```
GameState.factionEventCooldowns = {
  "F04:fA>fB": { lastTriggeredWeek: number },
  "F05:fA": { lastTriggeredWeek: number },
  ...
}
```

## §2 検出・ライフサイクル

### §2.1 発生条件（発生イベントが発動することで顕在化）

常時自動検出ではない。週次で発生チェックを走らせ、条件を満たすと発生イベントをキューに積む。

**忠誠型発生（F01）発火条件:**
- 自団体ロスターが **10人超** 🔧
- 現在の派閥数が **0**
- OVRトップ3のいずれかを核に、その選手から bond **60以上** 🔧 のフォロワーが **2人以上**（※ v0.2 閾値変更: 65→60。実測bond分布が50後半〜60台に張り付いており、65だと13年プレイでも発生しないため）
- 週次チェックで **60%** 🔧 の確率でイベント発動

**派閥抗争勃発（F02）発火条件（v0.4 改訂）:**
- 自団体ロスターが **10人超**
- **既存の派閥が2つ以上存在** し、そのうち **抗争中でないペア** が存在する
- 派閥間メンバーの平均 rivalry が **40以上** 🔧
- 週次チェックで **80%** 🔧 の確率でイベント発動

> **v0.4 方針転換:** 旧仕様は「無派閥ロスターから2クラスタを同時発生」させる「対立型結成」だったが、「対立は派閥ができた後に関係性の変化で生まれる」という設計思想に合わないため再設計。派閥は基本的に `type: 'loyal'` として生まれ、既存派閥同士の関係が悪化した時点で F02 が `inHostility: true` フラグを立てて抗争状態に遷移させる。`type: 'rivalrous'` フィールドは legacy として保持（後方互換）。

### §2.2 メンバー加入

派閥存在時、週次で以下を判定:

- 対象: 無派閥選手（ロスターに所属、派閥未所属）
- 条件: 既存メンバーとの **平均bond が 60以上** 🔧 になった選手
- 発動: 条件を満たした選手ごとに、該当 bond 平均値に応じた確率で加入
  - bond 60〜69: 20%/週 🔧
  - bond 70〜79: 40%/週 🔧
  - bond 80以上: 60%/週 🔧
- 勢いによる修正（対立型のみ）:
  - 派閥の勢い +30超: 加入率 ×1.5 🔧
  - 派閥の勢い -30未満: 加入率 ×0.7 🔧
- **サイズ倍率（v0.8 追加 / 人数偏り対策）** 🔧: 勢い修正の**後**に派閥サイズ（加入前）で乗算
  - 3〜4 人: ×1.0
  - 5〜6 人: ×0.6
  - 7 人: ×0.3
  - 8 人以上: ×0.0（実質ストップ）
- **単独派閥の加入凍結（v0.8 追加）** 🔧: 派閥数 1 かつサイズ 5 人以上の状態では、新規加入判定そのものをスキップ。凍結解除条件は以下のいずれか:
  1. 第二派閥誕生（F01 再発火 / F02 / F05-B 分裂）
  2. 当該派閥の F05-B 分裂（上記 1 の一種）
  3. メンバー脱退でサイズが 4 人以下に戻る
  （状態フラグは持たず、毎週条件評価）
- UI通知: ログに静かに「○○が○○組に加わったようだ」

### §2.3 メンバー離脱（寝返り以外）

週次で以下を判定:

- 条件: リーダーへのbondが **40未満** 🔧 に低下
- 発動率: 10%/週 🔧
- 勢いによる修正（対立型のみ）:
  - 派閥の勢い -30未満: 離脱率 ×1.5 🔧
  - 派閥の勢い -60未満: 離脱率 ×2.0 🔧、さらにメンバー全員 trust -0.3/週追加 🔧

### §2.4 メンバー消滅

- メンバー数が **3人未満** になった派閥は自動消滅
- 対立派閥があった場合、その派閥の勢い -3〜-5（張り合いを失う）
- 消滅は即時、通知のみ（演出イベントはなし）

### §2.5 リーダー喪失時の後継判定

リーダーが退団・引退・長期離脱（8週以上の重傷等）のいずれかになった時点で F03 を発動。§9.3 を参照。

### §2.6 派閥制度の解散

1つの派閥がロスターの **80%以上** 🔧 を占めた場合、派閥制度そのものを解散:

- 全派閥を消滅させる
- 対立度・勢いをクリア
- authoritativeTag / dictatorTag もクリア
- 通知: 「派閥は事実上、団体そのものとなった。派閥という区分は意味を失った」
- §2.1 の発生条件を再び満たした時点で、新たに派閥が発生しうる

## §3 属性決定ルール

### §3.1 リーダー

派閥内 **OVR最上位** の選手。

### §3.2 幹部

リーダーを除いた派閥内 **OVR上位2人**。合計で派閥の「顔役」は3人（リーダー＋幹部2名）。

### §3.3 派閥名

リーダー名をベースに「○○組」形式で自動生成。リーダーが交代した場合は派閥名も更新される。

### §3.4 派閥類型

強く分類しない。基本は「リーダー+子分」の構造で、メンバーの年齢分布やスタイルは副次的情報。類型ごとの特殊効果は設けない。

## §4 対立度の変動ルール

### §4.1 初期化

対立型派閥が成立した時点で、A→B と B→A の対立度を初期化:

- F01からの発展（忠誠型→対立型）: 平均rivalry値をそのまま採用（対称的、中庸）
- F02発生イベント:
  - C（調停）: A→B と B→A を **30〜45** 🔧（対称、低め）
  - A/B（肩入れ）: 肩入れされた側への敵意を高める（矢印非対称）
    - 支持された側→敵対派閥: **55〜70** 🔧
    - 敵対派閥→支持された側: **65〜80** 🔧
  - D（静観）: 平均rivalry値（対称、中庸）

### §4.2 週次変動

**上昇要因:**

| 要因 | 変動量 🔧 | 方向 |
|------|---------|------|
| 派閥幹部級試合で敗北 | 敗者派閥→勝者派閥 **+3〜+5** | 矢印 |
| 派閥リーダー同士の試合で敗北 | 敗者派閥→勝者派閥 **+3〜+5**（上記に追加） | 矢印 |
| D-F系列シリアスイベント（F04/F07/F08） | **+5〜+15** | イベントごとに指定 |

**減衰要因:**

| 要因 | 変動量 🔧 | 方向 |
|------|---------|------|
| 時間減衰 | **-0.3/週** | 両方向 |
| 派閥間メンバー平均bondが50超 | 追加 **-0.3/週** | 両方向 |
| リーダー交代（F03継承） | 現値 **×0.7** | 両方向（世代交代で希薄化） |

末端メンバー同士の試合は対立度に影響しない（代表戦ではない）。

### §4.3 効果

| 対立度（両方向の平均） | 効果 |
|-------------------|------|
| 40+ | 派閥抗争マッチ属性の集客加算発動 +5 appeal 🔧 |
| 60+ | 集客加算 +10 appeal 🔧、寝返り率 ×0.7（忠誠心強化） 🔧 |
| 80+ | F08対立ヒートアップイベントの発動条件解放 |
| 20未満 | F06和解イベントの発動条件解放 |

## §5 勢いの変動ルール

### §5.1 初期化

派閥成立時、勢い = 0。F02発生イベントでの初期修正は §9.2 を参照。

### §5.2 週次変動

| 要因 | 変動量 🔧 |
|------|---------|
| 幹部級試合で勝利 | 勝者派閥 **+8〜+12**、敗者派閥 **-8〜-12** |
| リーダー同士の試合で勝利 | 勝者派閥 **+15〜+20**、敗者派閥 **-15〜-20** |
| 時間減衰 | 絶対値を0方向へ **-1.0/週** |

末端メンバーの試合は勢いに影響しない。

### §5.3 効果（対立型派閥のみ適用）

| 勢い | 効果 |
|------|------|
| +30超 | 無派閥選手の加入率 ×1.5 🔧、メンバー離脱率 ×0.7 |
| +60超 | さらに加入率補正、敵対派閥メンバーが寝返り候補化（F04の条件成立確率+） |
| -30未満 | 離脱率 ×1.5 🔧、加入率 ×0.7 |
| -60未満 | 離脱率 ×2.0、メンバー trust 追加減衰 **-0.3/週** 🔧（沈む船） |

忠誠型派閥には勢い概念を適用しない（敵対派閥が存在する場合のみ意味を持つ）。

## §6 派閥抗争マッチ（集客加算）

### §6.1 適用条件

既存の因縁カードの**追加属性**として機能。新規の試合カテゴリは作らない。

- 両者が異なる派閥に所属
- 両者がそれぞれの派閥の **リーダーまたは幹部**（§3参照）
- 派閥間の対立度（両方向の平均）が **40以上**

上記すべてを満たす場合のみ、「派閥代表戦」タグが自動付与される。

### §6.2 加算値

| 対立度（両方向の平均） | 加算 appeal 🔧 |
|-------------------|-------------|
| 40〜59 | +5 |
| 60〜79 | +10 |
| 80以上（通常時） | +10 |
| 80以上 + F08対決として発動 | +15〜+20（§9.8参照） |

MQ加算は一切しない。

### §6.3 重複制御ルール

**案A（排他）＋キャップ**で制御:

1. **派閥抗争appealと rivalry appeal は排他**: 同じ試合で重複した場合、`max(rivalryAppeal, 派閥抗争appeal)` のみ採用
2. **F08直接対決ボーナス**は上記とは別枠で加算されるが、タイトル戦と同時発動時は ×0.5
3. **因縁系ボーナス合計の上限キャップ**: rivalry + 派閥 + F08 の合計が **+30** 🔧 を超えた場合、30に丸める
   - 乱闘蓄積（pendingClashBonus）は別枠として扱い、このキャップには含めない
   - タイトル戦・ファン期待・初顔合わせも別枠

### §6.4 計算順序（calcMatchAppeal 内）

既存の calcMatchAppeal に以下を追加:

1. rivalry appeal を算出（既存）
2. 派閥抗争条件を判定し、派閥 appeal を算出
3. F08発動中の試合なら F08ボーナスを算出、タイトル戦との同時発動なら ×0.5
4. **排他処理**: `rivalryAppealEffective = max(rivalryAppeal, 派閥抗争appeal)`
5. **キャップ処理**: `feudSum = rivalryAppealEffective + F08ボーナス` を +30でクランプ
6. 他のappeal要素（タイトル、ファン期待、初顔合わせ、乱闘、ヒールvsベビー、OVR拮抗）を加算
7. totalAppeal を返す

## §7 UI仕様（案X: 団体タブ＋データベース分散）

### §7.1 団体タブ（screen-roster）

自団体の派閥情報をサブセクションとして表示:

  - 対立関係（フレーバー: 「△△組と泥沼状態」等）

### §7.2 データベースタブのリデザイン

現状7サブタブを3グループに再編:

| グループ | サブタブ |
|---------|---------|
| 個人 | 👤 全選手 / 🏋️ 全コーチ |

| 記録 | 📰 新聞 / 🏅 殿堂 / 📖 年代記 |

### §7.3 派閥比較サブタブ（🎭 派閥比較）

団体比較（⚔ 団体比較）と同様に、2派閥対置の形式:

- 対置項目:
  - リーダー名・ポートレイト・OVR

  - 勢い帯（フレーバー）
  - 対立度の両方向帯（フレーバー）

### §7.4 相関図タブ（🔗 相関図）の派閥レイヤー

既存の相関図に派閥可視化を追加:

- 派閥ごとに色分け（派閥ID順で自動割当、プレイヤーが色を変更できる将来拡張の余地）
- リーダーに王冠アイコン
- 幹部に小さな星アイコン
- 派閥間の敵対関係を線で表示（太さ = 対立度、ただし数値は出さない）

### §7.5 選手ポップアップ

選手名の下に、派閥所属を小さくテキスト表示:

- 派閥所属: 「○○組」「○○組・幹部」「○○組・リーダー」
- 無派閥: 「中立」または表示なし

数値は一切出さない。

## §8 D系列独立枠（イベント発動制御）

### §8.1 B系列との分離

既存のB系列大型イベント（B1〜B4、発生率2.5%/週、クールダウン8週）とは別の **D系列独立枠** として派閥イベントを管理。

理由: 派閥イベントは条件成立時に必ず発火すべき種類のイベントであり、B系列のランダム抽選枠に入れると条件を満たしても他イベントに負けて発動しないケースが生じる。

### §8.2 発動制御

| イベントID | 条件成立後の発動率 🔧 | クールダウン 🔧 | 備考 |
|----------|-------------------|--------------|------|
| F01 忠誠型結成 | 60%/週 | なし（一度限り） | 派閥0時のみ |
| F02 対立型結成 | 80%/週 | なし | 派閥0または1時 |
| F03 リーダー喪失 | 即時発動 | なし | 喪失時自動 |
| F04 寝返り | 30%/週 | 12週 | ペアごと |
| F05 派閥内亀裂 | 40%/週 | 12週 | 派閥ごと |
| F06 和解の兆し | 50%/週 | 16週 | 派閥ペアごと |
| F07 リーダーの横暴 | 40%/週 | 12週 | 派閥ごと |
| F08 対立ヒートアップ | 50%/週 | 24週 | 派閥ペアごと |

### §8.3 競合解決

同じ週に複数のFイベント条件が成立した場合、以下の優先順位で1つだけ発動:

1. F03（リーダー喪失、最優先）
2. F08（対立ヒートアップ、緊急性）
3. F04（寝返り）
4. F05（派閥内亀裂）
5. F07（リーダー横暴）
6. F06（和解）
7. F01/F02（結成は派閥0の場合のみ、自然と競合しない）

## §9 D-F系列イベントカタログ

### §9.1 F01 忠誠型結成

**発火条件**: §2.1 の忠誠型発生条件を満たす。

**ドラマ**: ロッカールームで、ある選手の周りに自然と子分たちが集まっている。リーダー格が場を仕切り、周囲がそれに従う空気ができつつある。

**演出**: 中量版（4シーン＋結果演出）

### §9.10 F05H 活動休止（リーダー長期離脱）

F03（リーダー喪失＝解散）と並ぶが、**旗を降ろすのではなく畳む**イベント。リーダーが長期離脱（怪我）中の派閥は解散ではなく活動休止 `status: 'hiatus'` に退避し、リーダー復帰で自動的に `active` へ戻る。

**発火条件**:
- `status === 'active'` の派閥のリーダーが怪我状態 `injury.weeksLeft >= 8`
- 即時発動 100%（確率ゲートなし、`pickWeeklyEvent` 内で F03 の次に最優先で評価）
- 選択肢なし（通知のみ）

**影響**:
- `faction.status` を `'hiatus'` へ遷移
- `inHostility = false` へ解除（対立型→通常型退避）
- `momentum = 0` リセット
- `factionTimeline` にエントリ追加（ログのみ）
- 派閥メンバーの trust / bond / rivalry には直接影響しない（離脱の事実のみを記述）

**クールダウン**: なし（status が `hiatus` の間は `checkF05HConditions` が false を返す）

**自動復帰**:
- 毎週 `applyHiatusRecovery` が `hiatus` 派閥を走査
- リーダーの `injury.weeksLeft === 0` になれば `status` を `active` へ戻す
- 通知なし（ログのみ）。復帰演出は将来の F07 系で検討
- リーダーがロスターから消えていた場合は `hiatus` のまま据え置き（次週以降に F03 経路へ委ねる）

**F03 との区別**:
- F03＝旗を降ろす（復帰不可・解散）
- F05H＝旗を畳んで棚に置く（再起可能な保留）
- 長期重傷での解散を避けるためのセーフガード。リーダー退団・引退は F03 へ、長期怪我は F05H へルーティング

**演出**: 追悼型 Stage 全画面、ただし「戻ってくるまで」という時限つき待機トーン。BGM は `Soft Bids, Sharp Minds.mp3` を `SOFT_VOL × 0.7` 低音量で、終止に `f06_fin_chime_v1.mp3` を控えめに1打。

**実装参照**:
- `Engine.factions.detectHiatusTrigger(state)` — 毎週判定
- `Engine.factions.applyF05HResult(state, payload)` — 状態遷移
- `Engine.factions.applyHiatusRecovery(state)` — 自動復帰
- UI モーダル: `showFactionHiatusModal` (ui-common.js)、ディスパッチャ: `handleFactionEvent` eventId `'F05H'`

### §9.11 F02 進展 4 種

F02「派閥抗争の勃発」発火後、抗争は以下 4 経路のいずれかで進展する。UI モーダルは ui-common.js 実装済み、エンジン配線は `src/factions.js` の該当関数群。優先順位は pickWeeklyEvent で `F02_ENDLESS > F02_PEACE > ... > F02 > F01`、試合フック経由の `F02_IGNITE` / `F02_RESOLUTION` は `!s._pendingFactionEvent` ガードで早い者勝ち。

#### §9.11.1 F02① ignite（発火）

**発火条件**:
- `state.factionPendingIgnite` が登録済み（F02 時に選択肢 **A: 煽る** を選んだ場合に登録）
- 興行カードに両派閥リーダー同士のシングル試合が含まれる
- `expireWeek`（登録時 + 4週）未超過

**影響**:
- 両方向 hostility **+12**
- `factionTimeline` に `IGNITE` エントリ追加
- `factionPendingIgnite` 消費（null 化）

**クールダウン**: なし（`expireWeek` 超過時は `expireF02PendingIgnite` がサイレントクリア）

**演出**: 試合開始前の通過点モーダル。抗争が公式戦の形を得た瞬間。

---

#### §9.11.2 F02② peace（沈静化）

**発火条件**:
- `state.f02MediationWatches` に登録された watch が存在（F02 時に選択肢 **B: 仲裁** を選んだ場合、`deadlineWeek = 登録週 + 12` で登録）
- 両方向 hostility が **base から -20 以上減衰**（仲裁時点 hostility からの下げ幅）
- `state.lockerRoomMorale ≥ 55`

**影響**:
- 両方向 hostility **-40**
- 両派閥 momentum 0 リセット
- `inHostility = false` 解除（対立型→通常型へ戻る）
- 両リーダー間 bond **+3**
- 対応 watch 削除
- `factionTimeline` に `PEACE` エントリ追加

**クールダウン**: なし（deadline 超過時は `sweepF02PeaceWatches` がサイレント削除）

**演出**: 和解シーン中量版。リング外で両リーダーが視線を交わす。

---

#### §9.11.3 F02③ resolution（決着）

**発火条件**:
- 両派閥リーダー同士の試合（シングル）でドロー以外の結果
- 両方向 hostility **≥60**
- 試合結果フック 4 パス（finalizeShow / executeShow / finalizeWar / finalizePPV）で判定

**影響**:
- 勝者派閥 momentum **+18〜+25**、敗者派閥 momentum **-22〜-25**
- 勝者リーダー trust **+6〜+8**、敗者リーダー trust **-3〜-5**
- 勝者派閥メンバー→リーダー bond **+5〜+8**、敗者派閥メンバー→リーダー bond **-6〜-9**
- 両方向 hostility **-40**
- 敗者派閥下位 2〜3 名 trust **-4〜-6**
- `factionTimeline` に `RESOLVED` エントリ追加

**クールダウン**: なし（hostility リセットで再燃まで時間を要する自然 CD）

**連鎖**: 敗者派閥は momentum 大幅ダウンで自然消滅経路（F03 `checkDissolutionConditions`）に入りやすい。専用モーダルは持たず F03 へフォールスルー。

**演出**: 試合終了直後の重量版。勝者派閥歓喜、敗者派閥のメンバーが離れていく。

---

#### §9.11.4 F02④ endless（無限抗争）

**発火条件**:
- 両方向 hostility 平均 **≥55** が **52週連続**（`factionEndlessStreak[pairKey]` で管理）
- クールダウン **52週**

**影響**:
- 両派閥メンバー全員の `mentalCoeff` **-0.02**（0.85 床）
- `factionTimeline` に `ENDLESS` エントリ追加
- streak リセット、CD マーク

**クールダウン**: 52週

**演出**: 重量版の諦念トーン。終わりの見えない抗争の重さを描く。

**FACTION_CONFIG 定数**:
- `f02EndlessHostilityMinAverage: 55`
- `f02EndlessStreakWeeks: 52`
- `f02EndlessCooldown: 52`

## §10 イベント連鎖マトリクス

派閥イベントは連鎖的に発動する設計。主な連鎖経路:

```
F01-A（権威化）
  └→ F07（リーダー横暴）発動確率+
       ├→ F07-A（認める）→ dictatorTag → F07発動確率更に+
       │    └→ 悪循環 → F05発動確率+
       └→ F07-C（幹部重用）→ F05発動確率+

F01-C（静観）
  └→ 時間経過 → F02発動条件（忠誠型1→対立型2）
       または F05（亀裂通知）発動 → 70%自然分裂 → 対立型2派閥へ / 30%亀裂継続

F02 / F05自然分裂（対立型成立）
  ├→ 対立度+ → F08（ヒートアップ）
  │    ├→ F08-A 直接対決 → 試合結果次第で対立度・勢い大変動（CD 24週）
  │    └→ F08-C 煽らず組まず → 熱持続・CD 立たず再判定継続
  ├→ 片側が勢い-60以下 → F04（寝返り）発動条件+
  │    └→ F04-A 放置 → 対立度+
  └→ 時間経過/bond+ → F06（和解の兆し）→ A 後押し or B 放置

F04-C（告げ口）
  └→ 派閥内火種 → F05発動確率+

F03（リーダー喪失）
  ├→ 83%以上継承 → 派閥継続、対立度×0.7
  ├→ 70-82% 動揺 → メンバー大幅trust低下
  └→ 70%未満 解散 → 派閥消滅、対立相手の派閥も勢い低下
```

## §11 セリフ方針

- セリフの格納場所: `src/data-faction-dialogue.js`（新規ファイル）または `src/data.js` の追記
- spec には例示のみ、量産は実装フェーズ

**6 効果:**

| # | 効果 | 対象 | 変動量 | タイミング |
|---|------|------|--------|-----------|
| 1 | 派閥内結束 | 同派閥メンバー全ペア bond | +0.15/週 | 週次 |

**効果 2/3 の抗争ペア検出:**

`_collectHostilePairs(state)` が `state.factionHostility` を走査し、`value > 0` な記録を持つ派閥ペアを列挙（無向ペアで重複排除）。両派閥とも存在する組のみ返す。

**効果 3 の判定式:**

**効果 6 の RNG:**

`_dissolveFaction` 内で `Engine.rng.derive(rngSeed, season, week, 0xFA1A) ^ factionId` から rng を生成し `-(5 + float*5)` を 1 回ロール。全元メンバーペアに同一 delta を適用（「この消滅は苦々しかった/あっさりしていた」のばらつきを 1 派閥 1 ロールで表現）。

- `0xFA1A`: `_dissolveFaction` 余波 bond ロール用
