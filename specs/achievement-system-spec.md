# 実績システム リデザイン仕様書（叩き台）

## 1. 背景と課題

### 現状
ゲーム進行に応じた実績は **MILESTONE_EVENTS の3個だけ**:
1. 旗揚げ興行（初興行完了）
2. 地元で話題に（orgPop 20）
3. 因縁の芽生え（初因縁）

全て序盤で消化され、以降は何も発生しない。
別途 SURVIVAL_MILESTONES（5個）があるがサバイバルモード専用。

### 問題点
- 中盤〜終盤に「次に何を目指すか」の指針がない
- ゲームが大幅に進化（PPV・対抗戦・殿堂入り・因縁Tier・人間関係etc）したが、それらを実績として拾えていない
- プレイヤーの達成感を可視化する仕組みがない

---

## 2. 設計コンセプト：「社長の勲章」

- 社長として団体を導いた結果、自然と解除されていくもの
- スプレッドシート最適化にならないよう、条件を明示しすぎない
- 解除時の演出で「おっ」と思わせる
- ※選手個人の経歴（Engine.milestone）は別システムとして現行維持

---

## 3. 4層構成

| 層 | 名前 | 性格 | 想定数 |
|---|---|---|---|
| **A** | マイルストーン | ゲーム進行ガイド。選択肢+報酬あり | 5〜7個 |
| **B** | 実績 | やりこみ証明。解除通知のみ（報酬なし or 小報酬） | 20〜30個 |
| **C** | 隠し実績 | 条件非公開。偶然や珍事を記録 | 5〜10個 |
| **D** | 演出イベント | 選択肢・報酬なし。全画面セレモニー演出のみ。キャラ演出あり | 都度追加 |

### D層の特徴
- プレイヤーの判断を介さない（ゲーム進行を一時停止する演出のみ）
- 主力選手のセリフ演出（personality × archetype）が入る
- `G.milestones` フラグ共用（一度発火したら再発火しない）
- 報酬バフなし
- 現行実装: `first_dome_show`（ドーム初興行前）/ `first_dome_sellout`（ドーム初満員後）

## 7. UI案

### 表示場所
- データベースタブに「実績」サブタブ新設（相関図と同列）

### レイアウト
- ヘッダー: 解除率（例: 15/35 = 42%）
- カテゴリ別グリッド
- 解除済み = カラー表示（アイコン+名前+解除日）
- 未解除 = グレーアウト（名前のみ or ???）
- 隠し実績 = 解除前は「???」、解除後に名前と条件が出現

### 解除時演出
| 層 | 演出 |
|---|---|
| A（マイルストーン） | 全画面オーバーレイ+選択肢（現行踏襲） |
| B（実績） | ティッカーに金色で流す + トースト通知 |
| C（隠し実績） | 新聞パネルに特別記事 |


## 9. 議論したいポイント

1. **B層の個数**: 20個? 30個? 多すぎるとスプレッドシートゲーム化のリスク
2. **条件の見せ方**: B層の未解除実績に条件テキストを出すか（完全公開 / 曖昧ヒント / ???）
3. **A層の報酬路線**: 一時バフ継続 vs 恒久的なアンロック（新機能解放など）
4. **セーブデータ互換**: 既存プレイヤーに遡及解除するか、新規のみか
5. **「苦い実績」の是非**: 大脱走・番狂わせなど、ネガティブ事象の実績は面白いか不快か
6. **解除セリフ演出**: キャラのセリフ / 社長のモノローグ / 新聞記事 / 組み合わせ
7. **小報酬の有無**: B層にも「解除すると小ネタがデータベースに追加される」等の報酬を付けるか
8. **具体的な項目の取捨選択**: 上記リストから何を残し、何を足すか
