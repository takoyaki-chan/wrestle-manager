## 設計原則

1. **会場は選ぶもの** — popReqを撤廃。どの会場でも選べるが、ガラガラのリスクを負う
2. **カードが客を呼ぶ** — 試合カードの魅力に加え、興行としての消費枠数が動員を左右する
3. **勢いは伝播する** — 満員が続けば勢いがつき、ガラガラが続けば客足が遠のく
4. **正確な予測はさせない** — プレイヤーには「ざっくり予測」のみ。数字のスプレッドシート化を防ぐ

### §2.3 Draw変換

```
drawFloor = 0.3   // 慣性集客（最低保証）
drawScale = 0.7   // アピール比率の倍率
drawCap = 2.0     // 最大倍率
draw = clamp(drawFloor + showDraw / expectedDraw × drawScale, 0.3, 2.0)
```

`expectedDrawCurve` は `[[0,20],[10,90],[20,160],[30,270],[40,340],[50,380],[60,410],[70,440],[80,470],[90,500],[100,530]]` を区間線形補間する。

### §2.4 集客ボリューム係数 V（v1.1）

実効試合数は**消費枠数**で数える。成立したシングルは1枠、成立したタッグは2枠である。タッグは4選手全員のIDが有効なときだけ2枠、シングルは左右のIDが有効なときだけ1枠として数え、未成立の表示枠は数えない。これはタッグの優遇・冷遇ではなく、枠を興行の尺として扱う中立設計である。

適正消費枠数を `m`、消費枠数を `s` とする。`s < m` のときは会場帯と不足数 `k = m - s` に応じた V を用いる。`k = 4以上` は同じ列を使う。

| 会場帯（Idx） | k=1 | k=2 | k=3 | k=4以上 |
|---------------|:---:|:---:|:---:|:------:|
| 小（0–2） | 0.85 | 0.65 | 0.50 | 0.50 |
| 中（3–5） | 0.85 | 0.60 | 0.40 | 0.40 |
| 大（6–7） | 0.80 | 0.50 | 0.30 | 0.20 |
| 大会場（8） | 0.75 | 0.45 | 0.25 | 0.15 |
| ドーム（9） | 0.70 | 0.40 | 0.20 | 0.10 |

小会場帯の下限は0.50である。適正ちょうど（`s = m`）は V=1.00。

適正より多い場合は、会場の最大枠数までの超過枠ごとに V へ加算する。現在の定義では適正が最大枠数−1のため、超過はフル枠の1段だけである。

| 会場帯（Idx） | 1超過枠あたり β | 上限段数 | フル枠時 V |
|---------------|:----------------:|:--------:|:----------:|
| 小（0–2） | +0% | 1 | 1.00 |
| 中（3–5） | +2% | 1 | 1.02 |
| 大（6–7） | +3% | 1 | 1.03 |
| 大会場（8） | +4% | 1 | 1.04 |
| ドーム（9） | +6% | 1 | 1.06 |

### §2.5 最終動員と適用順

V はカード魅力の重みや `showDraw` を直接変更しない。`calcAttendanceV2` の計算順は次のとおりである。

```
reach = interpolate(reachCurve, orgPop)
expected = interpolate(expectedDrawCurve, orgPop)
draw = clamp(drawFloor + (showDraw / expected) × drawScale, drawFloor, drawCap)
rawAttendance = reach × draw
rawAttendance = rawAttendance × V
rawAttendance = rawAttendance × heatMult × fluctuation × (1 + attendanceMomentum)
rawDemand = applySoftCap(rawAttendance, reach)
attendance = clamp(round(rawDemand), max(10, round(capacity × 0.05)), capacity)
```

このため V は heat、週次揺らぎ、momentum、ソフトキャップより前に効く。`rawDemand`（会場キャパでクランプする前の、ソフトキャップ適用後の需要）にも同じ V が反映され、会場の熱からMQへ至る経路も薄い興行では低下する。

## §4 興行全体の集客力（Show Draw）

### §4.1 ポジション重み

| 位置 | 重み 🔧 |
|------|:------:|
| メイン | 1.0 |
| セミ | 0.7 |
| 第3試合 | 0.5 |
| 以降 | 0.35 |

### §4.2 計算式

```
showDraw = Σ(appeal × positionWeight) + nonMatchPromo × 2
```

出場選手のpromoStackは試合appealへ1スタックあたり+8、非出場選手のpromoStackは全体へ1スタックあたり+2を加算する。

### §4.3 試合数評価の一本化

旧 `shortPenalty1` / `shortPenalty2` は撤去済みであり、`showDraw` に試合不足ペナルティは掛けない。試合数による需要補正は §2.4 の V だけが担う。これにより二重罰を防ぐ。

## §7 観客MQへの反映

`rawDemand` は会場キャパでクランプする前の、ソフトキャップ適用後の需要である。`calcAttendanceV2` はV適用後のこの値を返し、会場の熱からMQを算出する経路の入力となる。従って、同じカード内容でも消費枠数が少なければ観客MQへの寄与も低くなる。

## §8 チケット収入と経済への副作用

### §8.1 チケット収入

| 動員帯 | 単価(万) 🔧 |
|--------|:--------:|
| 0–2,000 | 0.55 |
| 2,000–5,000 | 0.45 |
| 5,000–10,000 | 0.35 |
| 10,000+ | 0.25 |

帯ごとに累積計算し、§6の入場率チケット倍率を掛ける。

### §8.2 v1.1 の経済影響と監視

旧実装はタッグを「1試合」と数えて不足判定していたため、タッグ入りカードが大箱で隠れペナルティを受けていた。消費枠数評価でこれを解消した結果、auto-sim 40年では平均動員 **+52%**、興行収入 **+32%**、★5興行率 **30%→20%** が観測された。

Vのフル枠ボーナスは最大でもドームの+6%であり、この差の全てを直接説明するものではない。満員→勢い→人気成長→reach増という複利効果を含む。実機で経済を継続監視し、必要なら `expectedDrawCurve` または超過ボーナス β を調整レバーとする。

## §10 不変条件・対象外

- 適正消費枠数ちょうどの通常興行は V=1.00であり、V以外の集客計算を変えない。
- orgPop80・大ホール・成立シングル2試合では、実装の V=0.50 が適用される。
- 成立タッグ2試合+成立シングル1試合（5枠）は、成立シングル5試合と同じ V を用いる。
- PPV GRAND FINAL、天頂戦、ジュニアトーナメント、春のタッグリーグ、秋の勝ち残り対抗戦は対象外。これらは `Engine.specialEventFinance` の固定収益経路を使い、通常興行の `calcAttendanceV2` を通らない。
