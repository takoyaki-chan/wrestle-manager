# オフシーズン導線・引退タイミングフォローアップ設計 v1.0

## 背景

プレイ会話から、次の4点が課題として見えた。

1. シーズンリポートが出ないケースがある
2. ロスター上限時の契約導線が弱い
3. `⚠ 衰え` 表示が早く、体感とズレる
4. 引退勧告の入口が早く、25歳前後で急にラストラン感が出る

現状は「内部の衰え進行」と「UI表示」と「引退勧告可能条件」が別々に設計されており、しかも入口が近すぎる。
そのため、選手がまだ十分戦えている時期から「もう終盤なのか」という印象を与えやすい。

このフォローアップでは、数値ロジックそのものを大きく壊さず、以下を行う。

- オフシーズン導線の欠損を塞ぐ
- ロスター上限時の契約体験を改善する
- `衰え` の見せ方を遅らせる
- 引退勧告を「年齢」より「落ち幅」に寄せる

## 現状整理

### A. 引退勧告

現行の `Engine.retirement.canAdvise(fighter)` は以下のいずれかで true:

- `wear >= 20`
- `careerSeasons >= 6`
- `age >= 25`

そのため、数値的な低下がまだ軽微でも、25歳になった時点で引退勧告対象に入る。

### B. シーズン末の自動引退

現行の `Engine.rival.checkRetirement(rng, fighter)` は概ね以下:

- `currentOVR < notionOVR * 0.60` が2シーズン続く
- `wear 40-59` で 20%
- `wear 60-79` で 50%

つまり自動引退側は wear / 実力低下寄りだが、勧告側は age / careerSeasons 寄り。

### C. `⚠ 衰え` 表示

現行UIは `wear >= 20` で即 `⚠ 衰え` を表示している。
これは内部処理の「軽度衰退開始」と完全に同期しているが、プレイヤー体感ではまだ成長や活躍が続くため、見た目だけ先に老けて見えやすい。

## 目標

### 1. シーズンリポート

- オフシーズン第1週に入ったのにレポート/表彰導線が欠ける状態を潰す
- `pendingAwards` の transient 欠損があっても、詰まずに先へ進める

### 2. ロスター上限契約

- 「上限なので無理です」で終わらせず、その場で整理して契約まで完結できるようにする

### 3. 衰え表示

- 内部で軽度衰退が始まっても、見た目の `衰え` は少し遅らせる
- 「ピークより明確に落ちてきた」と感じる頃に初めて表示する

### 4. 引退勧告

- age 単独で入口が開く設計をやめる
- 「ピークから落ちた」「wear が本格化した」「低調が続いた」など、プレイヤーが納得しやすい条件へ寄せる

## 実装方針

## §1 シーズンリポート欠損ガード

### 問題

`pendingAwards` はオフシーズン第1週で生成される transient field で、UI側はこれを前提に表彰式チェーンへ進む。
この値が欠けると、レポートや表彰の導線が抜けたまま進行しうる。

### 方針

`App._safeAwardsChain()` に「欠損時の復旧パス」を追加する。

### 仕様

- 条件:
  - `G.offSeason === true`
  - `G.offWeek === 1`
  - `G.pendingAwards` がない
- このとき、即 return せず復旧を試みる

### 復旧内容

1. `G.seasonHistory` の末尾を参照し、直前シーズンのアーカイブが存在するか確認
2. アーカイブが存在する場合:
   - 「シーズンレポートは完了済みだが、表彰データが欠損している」とみなす
   - `Engine.awards.generate(rng, G)` を再実行して `pendingAwards` を再生成
3. 再生成できたら、そのまま通常の表彰チェーンへ進む
4. 再生成できない場合でも、進行を止めず `App._checkAndShowMilestone(...)` へフォールバックする
5. `gameLog` に診断用ログを1件積む

### 触る箇所

- `src/app.js`
  - `_safeAwardsChain`
  - 必要なら `_recoverMissingSeasonArtifacts` ヘルパー新設

### 受け入れ条件

- 通常進行では従来通り引退演出 → 表彰式 → 新シーズンとなる
- オフシーズン第1週セーブをロードして `pendingAwards` が欠けていても進行不能にならない
- レポート画面だけ見えて表彰が出ない、という取りこぼしがなくなる

## §2 ロスター上限時の「入れ替えて契約」導線

### 問題

現在は以下の獲得経路で、上限時に alert を出して終了している。

- FA契約
- スカウト獲得
- 交渉成功時の加入

この方式だと、プレイヤーは「誰を外せばよいか」を別画面で考え直す必要がある。

### 方針

「上限到達時にその場で1人解雇して契約する」共通モーダルを追加する。

### 新規状態

`G.pendingRosterOverflowSigning`

想定構造:

```js
{
  source: 'fa' | 'scout' | 'negotiation',
  fighter: {...},
  cost: number,
  meta: {...}
}
```

### 発火条件

- 上限チェックで弾く代わりに、上限到達時は `pendingRosterOverflowSigning` をセット
- その直後に専用モーダルを表示

### モーダル仕様

- タイトル: `所属上限に達しています`
- 説明: `1名解雇すると、この選手と契約できます`
- 表示内容:
  - 加入予定選手の要約
  - 現所属選手一覧
  - 各選手に `解雇して契約` ボタン
  - `やめる` ボタン
- 解雇対象から除外:
  - レンタル選手
  - 必要なら `lastRun` 中の選手

### 契約確定フロー

1. 対象選手を解雇
2. 既存の解雇時関係値処理を流す
3. 加入予定選手を roster に追加
4. コストを支払う
5. `pendingRosterOverflowSigning` をクリア
6. 元のソースに応じて後始末
   - scout なら候補から除外
   - negotiation なら pendingNegotiation をクリア

### 実装上の注意

- 契約処理を3箇所に散らさず、共通ヘルパー化する
- 「解雇」と「加入」が別々に失敗しないよう、1アクションにまとめる

### 触る箇所

- `src/app.js`
  - FA契約分岐
  - スカウト契約分岐
  - 交渉成功分岐
- `src/ui-common.js` または専用UI関数
  - 新モーダル描画

### 受け入れ条件

- 上限到達時に alert で終わらず、その場で入れ替え契約できる
- 解雇時の trust / relationships / gameLog が既存ルール通りに動く
- キャンセル時は現状維持

## §3 `衰え` 表示の遅延

### 問題

今は `wear >= 20` で即 `⚠ 衰え` を表示している。
しかし内部ロジック上はこの段階でも成長や好成績があり得るため、見た目だけが先走りやすい。

### 方針

内部の wear ロジックはそのまま使い、UIに出すタイミングだけ遅らせる。

### 新規ヘルパー

`Engine.retirement.getDeclinePresentation(fighter)`

返り値案:

```js
{
  visible: boolean,
  stage: 'none' | 'early' | 'major' | 'terminal',
  dropRatio: number,
  peakOVR: number,
  currentOVR: number
}
```

### 表示判定

- `peakOVR` は `fighter.careerRecord.peakOVR` を優先
- `dropRatio = (peakOVR - currentOVR) / peakOVR`
- 表示ルール:
  - `wear >= 60` → `⬇⬇ 限界`
  - `wear >= 40` → `⬇ 衰退期`
  - `dropRatio >= 0.05` → `⚠ 衰え`
  - それ未満 → 非表示

### 意図

- 軽度の内部衰退は隠す
- プレイヤーが「さすがにピークから落ちたな」と感じる段階で初めて表示する
- 本格衰退と末期は引き続き wear ベースで明示する

### 備考

- `wear 20-39` でも `dropRatio < 0.05` なら表示しない
- 逆に `wear < 40` でもピーク比 5%以上落ちていれば `⚠ 衰え` を出す

### 触る箇所

- `src/engine.js`
  - helper 新設
- `src/ui-render.js`
  - roster 一覧の wear badge
- `src/ui-common.js`
  - 選手詳細の wear badge

### 受け入れ条件

- `wear 20` 到達直後に必ず `⚠ 衰え` が出る挙動は消える
- ピークから落ちていない選手に `衰え` が先出しされない
- 末期の分かりやすさは落とさない

## §4 引退勧告の入口見直し

### 問題

`age >= 25` 単独で勧告対象になるため、数値的にはまだ戦えている選手にも「もう終盤」という空気が出る。

### 方針

`canAdvise` を「年齢」から「落ち幅 / wear / 低調継続」に寄せる。

### 新しい勧告条件

以下のいずれかを満たすと `canAdvise = true`:

1. `wear >= 40`
2. `peak比 5%以上低下`
3. `lowPerformanceSeasons >= 1`
4. `careerSeasons >= 7 && age >= 26`

### この条件にする理由

- `wear >= 40`
  - 本格衰退なので勧告対象として自然
- `peak比 5%以上低下`
  - ユーザー体感と一致しやすい
- `lowPerformanceSeasons >= 1`
  - 自主引退ルートの手前なので勧告を出せてよい
- `careerSeasons >= 7 && age >= 26`
  - 長期所属ベテランに対する「円満な区切り」は残す
  - ただし age 単独では開かない

### 実装詳細

`Engine.retirement.canAdvise(fighter)` を次のように分解する。

- `getPeakDropRatio(fighter)` を新設
- `canAdvise(fighter)` では上記4条件だけを見る

### 受諾率

`calcAcceptance` の係数はまず維持する。
ただし入口が絞られるため、体感はかなり改善する見込み。

必要なら次段階で以下も検討:

- `dropRatio >= 0.10` で受諾率 +10
- `peakOVR` と `currentOVR` の差が大きい元エースは受諾率を少し上げる

今回は first step としては入れない。
入口変更だけで挙動差を見たい。

### 触る箇所

- `src/engine.js`
  - `Engine.retirement.canAdvise`
  - peak drop helper 新設
- `src/ui-common.js`
  - 引退勧告セクションの表示条件
  - 必要ならコーチ助言文のトーン微調整

### 受け入れ条件

- 25歳になっただけでは勧告対象にならない
- 明確に落ちてきた選手、本格衰退の選手、長期所属ベテランだけが対象になる
- ラストランが「急に始まる」感じを抑えられる

## テスト方針

### 手動確認

1. オフシーズン第1週で表彰式が必ず出る
2. `pendingAwards` を意図的に欠いたセーブでも進行不能にならない
3. 上限いっぱいの状態で FA / scout / negotiation の各契約導線から入れ替え契約できる
4. wear 20 到達直後の選手に `⚠ 衰え` が出ないケースがある
5. peak 比 5%以上落ちた選手に `⚠ 衰え` が出る
6. 25歳になっただけの選手に引退勧告ボタンが出ない
7. wear 40+ または明確な落ち幅がある選手には勧告ボタンが出る

### 自動確認候補

- `tests/` に以下を追加
  - `retirement-advice-threshold-test.js`
  - `decline-presentation-test.js`
  - `roster-overflow-signing-test.js`
