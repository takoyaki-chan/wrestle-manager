## 設計原則

1. **実力には相応の値段がつく** — 能力が高い選手は高い。潜在能力がトップ級の選手は特に高い
2. **市場評価は簡単には変わらない** — 一度ついた値段は、大きな出来事がない限り動かない
3. **弱小団体は門前払い** — 団体の格が足りなければ、交渉のテーブルにすら着けない。「まだ相手にされていない」を体感させる
4. **上振れ下振れが存在する** — 評価額には最大±30%の市場ノイズがある。掘り出し物も割高もある
5. **レンタルは穴埋め** — トップ層は出てこない。中堅以下のみ。料金体系はシンプルに

## §1 評価額（assessedValue）システム

### §1.1 概要

選手の「市場価値」を表す `assessedValue` を導入する。スカウト契約金・フリー選手契約金の基準となる。

- 選手の生成時に一度だけ算出し、以後は特定条件でのみ再評価（§4参照）
- 週ごとに変動するものではない
- NPC団体が内部的に把握している「この選手はこのくらいの価値がある」という相場

### §1.2 ティア分類

5段階のティアで基礎額を決定する。現行の3段階（原石/有望/逸材）から拡張。

| ティア | 条件（いずれかを満たす） | 基礎額（万）🔧 |
|:------:|----------------------|:------------:|
| 素材 | 潜在値合計 < 550 かつ 現在値合計 < 180 | 30〜80 |
| 原石 | 潜在値合計 550〜649 かつ 現在値合計 < 220 | 80〜150 |
| 有望 | 潜在値合計 650〜749 または 現在値合計 220〜299 | 150〜300 |
| 逸材 | 潜在値合計 750〜849 または 現在値合計 300〜349 | 300〜500 |
| 超逸材 | 潜在値合計 850以上 または 現在値合計 350以上 | 500〜800 |

**判定優先順位**: 条件を上のティアから順に判定し、最初にマッチしたティアを採用。
ただし潜在値が高ティア条件を満たす場合はそちらを優先（例: 現在値180未満でも潜在値750以上なら「逸材」）。

### §1.3 評価額の算出

```javascript
function calcAssessedValue(fighter, rng) {
  const currentTotal = sum(fighter.current);   // 現在値5パラ合計
  const potentialTotal = sum(fighter.potential); // 潜在値合計

  // ティア判定
  let tier, baseMin, baseMax;
  if (potentialTotal >= 850 || currentTotal >= 350) {
    tier = 'superElite'; baseMin = 500; baseMax = 800;
  } else if (potentialTotal >= 750 || currentTotal >= 300) {
    tier = 'elite';      baseMin = 300; baseMax = 500;
  } else if (potentialTotal >= 650 || currentTotal >= 220) {
    tier = 'promising';  baseMin = 150; baseMax = 300;
  } else if (potentialTotal >= 550 || currentTotal >= 180) {
    tier = 'raw';        baseMin = 80;  baseMax = 150;
  } else {
    tier = 'material';   baseMin = 30;  baseMax = 80;
  }

  // 基礎額をティア内でランダム決定
  const baseValue = randomRange(rng, baseMin, baseMax);

  // 市場ノイズ（±30%）
  const variance = 0.70 + Engine.rng.float(rng) * 0.60; // 0.70〜1.30
  
  const assessedValue = Math.round(baseValue * variance);
  
  return {
    assessedValue,   // 最終評価額（万円）
    tier,            // ティア名
    variance,        // 市場ノイズ倍率（保存用）
    assessedSeason   // 評価時点のシーズン番号
  };
}
```

### §1.4 評価額の実効レンジ

市場ノイズ（±30%）込みの実効レンジ:

| ティア | 基礎額 | 実効レンジ（万）🔧 | 初期資金比 |
|:------:|:------:|:----------------:|:---------:|
| 素材 | 30〜80 | **21〜104** | 0.4〜2.1% |
| 原石 | 80〜150 | **56〜195** | 1.1〜3.9% |
| 有望 | 150〜300 | **105〜390** | 2.1〜7.8% |
| 逸材 | 300〜500 | **210〜650** | 4.2〜13.0% |
| 超逸材 | 500〜800 | **350〜1,040** | 7.0〜20.8% |

> 初期資金5,000万に対して、超逸材は最大1,040万。序盤では手が出ない。

## §2 門前払いシステム（交渉資格）

### §2.1 団体人気による交渉制限

団体の知名度（orgPop）が一定以上でないと、上位ティアの選手に交渉できない。

| ティア | 必要orgPop 🔧 | 序盤の状況 |
|:------:|:------------:|----------|
| 素材 | 0（制限なし） | 最初から獲得可能 |
| 原石 | 0（制限なし） | 最初から獲得可能 |
| 有望 | 25 | ミッション達成（orgPop25）後に解放 |
| 逸材 | 50 | 中堅団体レベルで解放 |
| 超逸材 | 70 | 上位団体に肩を並べる頃に解放 |

> **プレイヤー初期orgPop = 10** → 序盤は素材・原石しか獲れない。
> AI団体: S級=75, A級=55, B級=35 → S級団体の超逸材にアクセスするには、A級以上の知名度が必要。

### §2.2 UI表現

交渉不可の選手はスカウトレポートに名前が載るが：
- 能力レーダーチャートはグレーアウト
- 「⛔ 団体の知名度不足 — 交渉できません」と表示
- 必要orgPopを薄く表示（「人気50以上で交渉可能」）

**設計意図**: 「あの選手がいるのに手が出せない」→ 団体を大きくするモチベーション。見えるけど手が届かない、という演出。

### §2.3 フリー選手への適用

フリー選手（常時契約可能な選手プール）にも同じorgPop制限を適用する。

- 素材・原石 → 制限なし
- 有望以上 → orgPop閾値を満たさないと契約ボタンが無効化

ただし、フリー選手プールの構成上（§9.2: 新人級×6、若手級×8、中堅級×5、主力級×1）、逸材・超逸材がフリーに存在する確率は非常に低い。

## §3 競合システムの調整

### §3.1 競合発生率

ティア細分化に合わせて5段階に拡張。

| ティア | 競合発生率 🔧 | 競合時追加コスト倍率 🔧 |
|:------:|:----------:|:-------------------:|
| 素材 | 5% | ×1.1 |
| 原石 | 15% | ×1.15 |
| 有望 | 50% | ×1.3 |
| 逸材 | 85% | ×1.5 |
| 超逸材 | **95%** | **×2.0** |

### §3.2 競合時の選択肢（変更なし）

scout-system-spec §5.2 と同じ:
- A) 追加コストを払って確定獲得
- B) 通常額のまま勝負 → 50%で競り負け 🔧
- C) 諦める

### §3.3 超逸材の特別ルール

超逸材に限り、選択肢Bの競り勝ち率を下げる:

| ティア | 通常額で勝負した場合の獲得率 🔧 |
|:------:|:---------------------------:|
| 素材〜逸材 | 50% |
| 超逸材 | **30%** |

**設計意図**: 超逸材は「追加コストを払ってでも獲る」か「諦める」の二択に近い。中途半端な投資では取れない。

## §4 評価更新タイミング（案C: ハイブリッド方式）

### §4.1 基本方針

**「普段は動かない。大きな出来事があれば動く」**

- 通常時: 評価額は固定。毎週や毎シーズン自動的に変わることはない
- イベント駆動: 特定のイベントが発生した場合のみ再評価
- 定期微調整: 3シーズンごとに全選手の評価に小さなゆらぎ（±10%）

### §4.2 イベント駆動の再評価トリガー

以下のイベントが発生したとき、該当選手の `assessedValue` を再計算する。

| トリガー | 再評価の方向 | 備考 |
|---------|:----------:|------|
| タイトル獲得 | ↑ 上方修正 | 新ティアで再算出。最低でも前回の110% |
| タイトル防衛3回以上 | ↑ 上方修正 | 現ティアの上限寄りで再算出 |
| シーズンMVP（MQ最高） | ↑ 上方修正 | 現ティアの上限寄りで再算出 |
| 年齢30歳到達 | ↓ 下方修正 | 現在値ベースで再算出。variance × 0.8 |
| 年齢35歳以上 | ↓↓ 大幅下方修正 | 強制的に1段下のティアで再算出 |
| 重傷（長期離脱） | ↓ 下方修正 | variance × 0.85 |
| 後遺症発覚 | ↓ 下方修正 | variance × 0.7 |

```javascript
function triggerReassessment(fighter, reason, rng, currentSeason) {
  // 現在の能力で基本ティアを再判定
  let base = calcAssessedValue(fighter, rng);
  
  switch (reason) {
    case 'titleWin':
      base.assessedValue = Math.max(base.assessedValue, 
        Math.round(fighter.assessedValue * 1.1));
      break;
    case 'titleDefend3':
    case 'seasonMVP':
      // ティア内上限寄りに引き上げ
      base.variance = Math.max(base.variance, 1.1);
      base.assessedValue = Math.round(base.assessedValue * 1.1);
      break;
    case 'age30':
      base.assessedValue = Math.round(base.assessedValue * 0.8);
      break;
    case 'age35plus':
      // 1段下のティアで再算出（calcAssessedValueの結果をそのまま使用、
      // ただし加齢により現在値が下がっているので自然に下がる）
      base.assessedValue = Math.round(base.assessedValue * 0.6);
      break;
    case 'severeInjury':
      base.assessedValue = Math.round(base.assessedValue * 0.85);
      break;
    case 'aftereffect':
      base.assessedValue = Math.round(base.assessedValue * 0.7);
      break;
  }
  
  base.assessedSeason = currentSeason;
  return base;
}
```

### §4.3 定期微調整（3シーズンごと）

| 項目 | 仕様 |
|------|------|
| タイミング | 3シーズンごとのオフシーズン処理で実行 |
| 対象 | 全選手（ロスター＋AI団体＋フリー選手プール） |
| 変動幅 | ±10% 🔧 |
| 算出 | `newValue = round(assessedValue × randomRange(0.90, 1.10))` |
| ティア変更 | なし。微調整では基礎ティアは変わらない |

**設計意図**: 「同じ選手がずっと完全に同じ値段」という違和感を防ぐ。ただし大きくは動かない。

### §4.4 assessedValue の保存

選手データに以下のフィールドを追加:

```javascript
{
  assessedValue: 350,      // 評価額（万円）
  assessedTier: 'elite',   // ティア名
  assessedSeason: 3,       // 最終評価時のシーズン番号
  assessedVariance: 1.12   // 市場ノイズ倍率
}
```

## §5 レンタル料

### §5.1 現行維持

レンタル料は現行のロジック（rival-org-spec §8.3）をそのまま維持する。

```javascript
function calcWeeklyFee(fighter, org) {
  const ovr = average(fighter.current);
  let base = ovr >= 60 ? 50 : ovr >= 45 ? 30 : 15;
  const tierMul = { S: 1.5, A: 1.2, B: 1.0 }[org.tier] || 1.0;
  return Math.round(base * tierMul);
}
```

### §5.2 変更しない理由

- レンタルはあくまで穴埋め。精緻な価格設定は不要
- トップ層は出てこない（Overall 3位以下のみ）
- 給与はレンタル料に含まれる（別途発生しない）
- 4週間固定の短期利用なので、市場評価との連動は過剰設計

### §5.3 レンタル料のレンジ（参考）

| Overall帯 | 週料（万） | 4週合計: B級 | 4週合計: S級 |
|:---------:|:--------:|:----------:|:----------:|
| 60〜 | 50 | 200 | 300 |
| 45〜59 | 30 | 120 | 180 |
| 〜44 | 15 | 60 | 90 |

| パターン | スカウト費（万） | 備考 |


### §8.2 データマイグレーション

既存の全選手（98名＋AI団体選手＋フリー選手）に `assessedValue` を初期付与する必要がある。

```javascript
function migrateAssessedValues(allFighters, rng, currentSeason) {
  return allFighters.map(f => {
    if (f.assessedValue) return f; // 既に設定済み
    const assessment = Engine.scout.calcAssessedValue(f, rng);
    return { ...f, ...assessment, assessedSeason: currentSeason };
  });
}
```
