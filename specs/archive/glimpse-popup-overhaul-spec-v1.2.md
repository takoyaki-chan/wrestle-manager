## §1 設計思想 — 「心の垣間見え」

### §1.1 核心コンセプト

選手の感情・内面の変化が**ゲームプレイの随所で垣間見える**仕組み。
プレイヤーは団体の経営者として日々を回していく中で、ふとした瞬間に選手の表情や呟きを目撃する。すべてが見えるわけではない。見えないことも多い。だからこそ、見えたときに「おっ」と思う。

### §1.2 二層構造

| 層 | 名称 | 発火率 | 閉じ方 | 用途 |
|---|---|---|---|---|
| **A層** | 重要イベント | 80〜100% | クリック必須 | 関係性の質的変化、成長イベント |
| **B層** | 日常の垣間見え | 5〜20% | クリック閉じ（最低4秒表示保証） | 毎週の小さな感情変動 |

**設計原則**:
- A層は「起きたら高確率で見せる」。プレイヤーが見逃すべきでない重要な変化
- B層は「たまに見える」。見えなくても問題ないが、見えるとキャラクターに愛着が湧く
- 1週あたりのB層表示は**最大2件**に制限（情報過多防止）
- A層は制限なし（重要なら全部見せる）

### §1.3 表示形式

共通UIフォーマット「**Glimpseパネル**」:

```
┌─────────────────────────────┐
│  [顔画像]  選手名            │
│                              │
│  「セリフ（内面の声）」       │
│                              │
│  ─── 状況説明テキスト ───    │
│  [変化の詳細（あれば）]      │
│                              │
│        [ OK / ボタン ]       │
└─────────────────────────────┘
```

- A層: 専用オーバーレイ（画面中央、背景暗転）、ボタンクリックで閉じ
- B層: 画面下部スライドイン（既存 `notifEventToast` と同系統）、クリックで閉じ、最低4秒表示

## §2 A層 — 重要イベントのポップアップ

### §2.1 関係性の質的変化

bond/rivalryが特定の閾値を**跨いだ瞬間**に発火。
「跨いだ」= 前の値が閾値未満 → 今の値が閾値以上（上昇時）、またはその逆（下降時）。

| トリガー | 閾値 | 発火率 | トーン | イベント名 |
|---|---|---|---|---|
| bond上昇: 普通→好意 | bond 60到達 | **90%** | positive | 打ち解けた様子 |
| bond上昇: 好意→盟友 | bond 80到達 | **100%** | gold | 深い絆の芽生え |
| bond下降: 好意→普通 | bond 59以下に落下 | **85%** | negative | 距離ができた |
| bond下降: 普通→苦手 | bond 39以下に落下 | **90%** | negative | 不和の兆し |
| rivalry上昇: →因縁 | rivalry 30到達 | **85%** | dramatic | 因縁の始まり |
| rivalry上昇: →宿敵 | rivalry 50到達 | **95%** | dramatic | 宿敵として意識 |
| rivalry上昇: →宿命 | rivalry 70到達 | **100%** | dramatic/gold | 宿命のライバル |
| rivalry下降: 因縁→意識 | rivalry 29以下に落下 | **80%** | calm | 因縁の終息 |

**双方向判定**: A→B と B→A を個別にチェック。片方だけ閾値を超えた場合も発火。
ただし同一ペアの同一方向で**8週クールダウン**（頻繁な行き来を防ぐ）。

#### セリフ例（性格×アーキタイプで分岐、既存のsnapshot感情テキストと同じ仕組み）

**bond 60到達（打ち解けた様子）**:
- bold: 「あいつとはいい空気だ。背中を預けられる気がする」
- quiet: 「……最近、あの人といると落ち着く」
- earnest: 「一緒に練習してて楽しいんです。もっと強くなれる気がして」
- shy: 「あ、あの人が近くにいると…なんか安心するかも…」

**rivalry 50到達（宿敵として意識）**:
- bold: 「あいつだけは…絶対に負けたくない」
- cool: 「……認めたくないけど、意識してる」
- emotional: 「くっ…あの人のことを考えると熱くなる…！」

### §2.2 信頼度（trust）の閾値変化

| トリガー | 閾値 | 発火率 | トーン |
|---|---|---|---|
| trust危険水域突入 | trust < 35に低下 | **95%** | warning |
| trust最低水域 | trust < 20に低下 | **100%** | danger |
| trust安定圏到達 | trust ≥ 75に上昇 | **85%** | positive |

- trust閾値も同一選手で**12週クールダウン**

### §2.3 成長イベント（既存拡張）

| イベント | 現状 | 変更 |
|---|---|---|
| ブレークスルー | ✅ ポップアップあり | 変更なし |
| スランプ開始/終了 | ✅ ポップアップあり | 変更なし |
| モチベ喪失/回復 | ✅ ポップアップあり | 変更なし |
| **絶好調終了** | ❌ ログ文字列のみ | **B層・Glimpseパネルを追加** |

**絶好調終了**:
- 発火率: **100%**（ただしB層表示 = 地味め演出）
- トーン: calm（ポジティブでもネガティブでもない、自然な終わり）
- セリフ例:
  - bold: 「……身体が元に戻ってきた。でも悪くない、いい時間だった」
  - quiet: 「……ふぅ。あの調子は続かないか」
  - earnest: 「絶好調は終わったけど…あの期間で掴んだものがある」
  - shy: 「あ…なんか、普通に戻っちゃった…かな」

## §3 B層 — 日常の垣間見え

### §3.1 発火タイミング

毎週の `tickWeek` 処理後に判定。以下のトリガーそれぞれで独立した確率判定を行い、
発火したものの中から**最大2件**を重み付き抽選で選出。

### §3.2 トリガー一覧

| ID | トリガー | 確率 | 重み | 条件 |
|---|---|---|---|---|
| GL-01 | 試合後の感情 | **15%** | 3 | 今週試合に出場した選手 |
| GL-02 | 練習中のひとこと | **8%** | 2 | 練習中の非負傷選手 |
| GL-03 | 信頼度の揺れ | **10%** | 3 | trust変動があった選手（±3以上） |
| GL-04 | 仲間への想い | **8%** | 2 | bond 50+のペアが存在する選手 |
| GL-05 | ライバルへの意識 | **10%** | 3 | rivalry 30+のペアが存在する選手 |
| GL-06 | 不出場の鬱憤 | **12%** | 3 | 興行に出場できなかった選手 |
| GL-07 | コンディション不良 | **10%** | 2 | condition < 40 の選手 |
| GL-08 | 連敗のストレス | **15%** | 4 | losingStreak ≥ 2 の選手 |
| GL-09 | 連勝の自信 | **12%** | 2 | winStreak ≥ 3 の選手 |
| GL-10 | 怪我中の焦り | **8%** | 2 | 負傷中の選手 |

**週あたり最大2件制限**: 全候補から重み付き抽選で最大2件を選出。
同一選手は1週に1件まで。同一選手は**4週クールダウン**。

### §3.3 セリフ生成

既存のスナップショット通知と同じ仕組み（性格×アーキタイプのマトリクス）を使う。
ただしスナップショット通知の「語り手が第三者（ナレーター）」とは異なり、
Glimpseパネルは**選手本人の内面の声**として表現する。

#### GL-01: 試合後の感情（例）

**勝利時**:
- bold×delinquent: 「へっ、当然の結果だろ」
- earnest×polite: 「勝てた…！ もっと上を目指します」
- quiet×cool: 「……悪くない」
- emotional×normal: 「やった…！ この調子で…！」

**敗北時**:
- bold×delinquent: 「ちっ…次は絶対ぶっ倒す」
- earnest×polite: 「悔しい…もっと練習しないと…」
- quiet×cool: 「……足りないか」
- shy×normal: 「う…また負けちゃった…ごめんなさい…」

**好試合（MQ70+）で敗北**:
- bold: 「負けたけど…悔しいけど…いい試合だった」
- emotional: 「くっ…認めたくないけど、あの人は強かった…！」

#### GL-06: 不出場の鬱憤（例）

- bold: 「なんで出してくれないんだ…腕が鳴ってるのに」
- earnest: 「出場できなかった…次こそは選んでもらえるように頑張らないと」
- quiet: 「……（リングを見つめている）」
- easygoing: 「まあ今週は仕方ないか〜。でもちょっと寂しいな」

#### GL-08: 連敗のストレス（例）

- bold: 「…このまま終わるつもりはない」
- emotional: 「もう…どうしたらいいの…」
- quiet: 「……（無言で練習を続けている）」
- shy: 「わ、私…足引っ張ってますよね…ごめんなさい…」

### §3.4 二人表示

GL-04（仲間への想い）、GL-05（ライバルへの意識）は二人の顔を表示。
一方の選手の視点でセリフを出す。

## §4 ポップアップ閉じ方の統一改修

### §4.1 方針

**全通知をクリック/タップ閉じに統一する。自動消失は廃止。**

| 通知種別 | 現在 | 変更後 |
|---|---|---|
| `showToast` | 1.8秒自動消失 | **最低4秒表示 + クリック閉じ** |
| `_showCareReaction` | 3.5〜5.5秒自動消失 | **クリック閉じのみ**（自動消失なし） |
| `showNotifEventToast` | 8〜15秒 + クリック閉じ | **クリック閉じのみ**（自動消失なし） |
| `showSeasonFanfare` | 4秒自動 + タップ | **クリック閉じのみ**（自動消失なし） |
| `showGrowthEventPopups` | ボタンクリック | 変更なし ✅ |
| `showNewspaperPanel` | クリックで次へ | 変更なし ✅ |
| **新設: B層・Glimpseパネル** | — | **クリック閉じ（最低4秒表示保証）** |

### §4.2 実装詳細

#### showToast の改修

```
変更前: setTimeout(() => el.classList.remove('show'), duration || 1800)
変更後:
- el.classList.add('show') で表示
- 4秒後に el.classList.add('dismissable')（視覚的に「閉じられます」を示す）
- el.onclick = dismiss（4秒経過後のみ反応、4秒以内はクリック無効）
- 自動消失タイマーなし
- ただし安全策として30秒後にフォールバック自動消失
```

#### _showCareReaction の改修

```
変更前: setTimeout で 3.5〜5.5秒後に消失
変更後:
- 自動消失タイマーを廃止
- パネル下部に「タップで閉じる」テキスト追加
- el.onclick = dismiss
- 安全策: 30秒後にフォールバック自動消失
```

#### showNotifEventToast の改修

```
変更前: 8〜15秒後に自動消失 + クリック早期閉じ
変更後:
- 自動消失タイマーを廃止
- クリック閉じのみ
- 安全策: 60秒後にフォールバック自動消失
```

#### showSeasonFanfare の改修

```
変更前: 4秒後に自動クローズ + タップ
変更後:
- 自動クローズタイマーを廃止
- タップ/クリック閉じのみ
```

### §4.3 フォールバック安全策

全通知に**上限タイマー**（30〜60秒）を設ける。
万が一クリックイベントが発火しない環境（タッチ問題等）でもゲームが止まらないようにする。
ただしこのタイマーは「異常時の保険」であり、通常はクリック閉じが前提。

### §4.4 ポップアップUI統一 — 位置・サイズ・レイアウト標準化

#### 現状の問題点

| 要素 | 現在の位置 | 顔サイズ | セリフ文字 | 問題 |
|---|---|---|---|---|
| `notif-event-toast` | `top:68px`（上部固定） | 80〜120px | 11px | ナビバーに被る、小さい |
| `care-reaction-toast` | 同上（top:68px継承） | 120〜140px | 13px | 同上 |
| `growth-event-overlay` | 画面中央（✅） | 80px | 12px | 顔が小さい、セリフも小さい |
| `toast` | `bottom:72px` | なし | 13px | テキストのみ、問題なし |

#### 統一方針: 2パターンに集約

**パターン①: モーダル型（A層 + 重要通知全般）**

画面中央、背景暗転、クリック閉じ。対象:
- 成長イベント（ブレークスルー/スランプ等）
- A層Glimpse（関係性閾値変化、trust閾値変化）
- ケアリアクション
- 大型イベント通知（B2/B3/B4等）
- シーズンファンファーレ

```css
/* モーダル型共通 */
position: fixed; inset: 0;
background: rgba(0,0,0,0.88);
display: flex; align-items: center; justify-content: center;
z-index: 265;

/* 内部ボックス */
max-width: 440px; width: 92%;
padding: 32px 28px;
border-radius: 14px;
text-align: center;
```

**パターン②: スライドイン型（B層 + 軽い通知）**

画面中央やや下、背景暗転なし、クリック閉じ。対象:
- B層Glimpse（日常Glimpse）
- 軽い情報通知

```css
/* スライドイン型 */
position: fixed;
top: 50%; left: 50%;
transform: translate(-50%, -50%);  /* ← 画面ど真ん中 */
z-index: 261;
max-width: 400px; width: 88%;
padding: 20px 20px;
border-radius: 12px;
```

※ 現在の `top:68px` を `top:50%; transform:translate(-50%,-50%)` に変更し、
画面中央に配置する。

**パターン③: テキストトースト（最軽量）**

`showToast` 用。画面下部、テキストのみ。現状の `bottom:72px` を維持。
ただし表示時間を4秒に延長し、クリック閉じを追加。

#### 顔画像サイズの統一

| パターン | 1人表示 | 2人表示 |
|---|---|---|
| モーダル型（A層） | **120px** | **100px × 2** |
| スライドイン型（B層） | **100px** | **80px × 2** |

現状の80pxは小さすぎる。キャラクターの表情が読み取れる最低ラインは100px。
A層は120pxでしっかり見せる。

#### 文字サイズの統一

| 要素 | 現在 | 変更後 | 備考 |
|---|---|---|---|
| 選手名 | 14px | **16px** | 誰の話かすぐ分かるように |
| セリフ（「」内） | 11〜12px | **15px** | ★最重要。ゲームの核心部分 |
| タイトル（ブレークスルー！等） | 28px | **28px** | 変更なし |
| 状況説明テキスト | 12〜13px | **14px** | 補足情報 |
| 詳細（ステータス変化等） | 12px | **13px** | 微増 |
| 「タップで閉じる」 | — | **11px** | 控えめ |

**セリフが最も大事**。選手の内面を伝えるテキストが11pxでは読む気にならない。15pxに拡大して存在感を出す。

#### 二人表示の専用レイアウト（A層用）

bond/rivalry閾値変化時の二人並び表示:

```
┌───────────────────────────────────┐
│                                   │
│    [顔A 100px]  ←→  [顔B 100px]  │
│    選手A名          選手B名       │
│                                   │
│    ──── タイトル（例: 宿敵化）──── │
│                                   │
│  「セリフ（A視点の内面の声）」     │
│                                   │
│    bond/rivalry変化の詳細          │
│                                   │
│          [ OK ボタン ]            │
└───────────────────────────────────┘
```

- 二人の顔を横並び（gap: 24px）で中央配置
- 間に関係性を示すアイコン（⚡🔥💥 or 💙🤝）
- セリフはA側の視点（B側のセリフが必要な場合は2ページ目として連続表示）

## §6 試合決着表記 — 技名優先フォーマット

### §6.1 方針

**決め技が主役、決着方法は補足。**

プロレスにおいて重要なのは「何の技で決まったか」。フォール/ギブアップ/TKOは決着の形式に過ぎない。

### §6.2 フォーマット変換

| finType | 現在の表示 | 新フォーマット |
|---|---|---|
| フォール | `フォール / ジャーマンスープレックス` | **`ジャーマンスープレックス → 3カウント`** |
| ギブアップ | `ギブアップ / 腕ひしぎ十字固め` | **`腕ひしぎ十字固め → ギブアップ`** |
| TKO | `TKO / ラリアット` | **`ラリアット → レフェリーストップ`** |
| ピン | `ピン / エルボードロップ` | **`エルボードロップ → 3カウント`** |
| 丸め込み | `丸め込み / エビ固め` | **`エビ固め → 丸め込み`** |
| HP判定 | `HP判定` | `HP判定`（変更なし） |
| 時間切れドロー | `時間切れドロー` | `時間切れドロー`（変更なし） |

### §6.3 変換ロジック

```javascript
function formatFinish(finType, finMove) {
  if (!finMove) return finType || '激闘決着';
  switch (finType) {
    case 'フォール':
    case 'ピン':
      return `${finMove} → 3カウント`;
    case 'ギブアップ':
      return `${finMove} → ギブアップ`;
    case 'TKO':
      return `${finMove} → レフェリーストップ`;
    case '丸め込み':
      return `${finMove} → 丸め込み`;
    default:
      return finType || '激闘決着';
  }
}
```

### §6.4 フィニッシャー連動（将来拡張）

フィニッシャーシステムが既に実装済み。フィニッシャーで決まった場合の特別表記:

- フィニッシャー: `★ デスバレーボム → 3カウント`（★マーク付き）

判定: `finMove` がその選手の `finisher.name` と一致するかをチェック。

## §8 決定事項メモ（議論により確定済み）

1. **セリフ量**: 性格×アーキタイプのフルマトリクスで最初から書く。省略しない。ここがゲームの核心であり最重要部分。
2. **B3辞退時のBPペナルティ**: -1.0〜-2.0（小数第1位を含むランダム）を適用する。§5.2に反映済み。
3. **A層の二人同時表示演出**: 専用レイアウトを作る。bond/rivalry閾値超え時に二人の顔を並べた専用パネル。§4.4に詳細記載。
4. **既存スナップショット通知との関係**: まず並存で実装する。スナップショットは第三者ナレーター視点、Glimpseパネルは本人の内面視点。運用して違和感があれば後で統合を検討。
5. **ポップアップUI統一**: 全通知の表示位置を画面中央に統一。顔画像を拡大（A層120px/B層100px）、セリフ文字を15pxに拡大。§4.4に詳細記載。
6. **システム名称**: Glimpse で確定。
