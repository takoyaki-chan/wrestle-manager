> 旧設計: specs/archive/ppv-awards-spec.md Part 1

---

## 1. コンセプト

シーズン最終週（Week 48）に全4団体が集結する年間最大の合同興行。
プレイヤーの選手が他団体の選手と直接ぶつかる、一年の締めくくりにふさわしいドラマの舞台。

**体験の核:**
- 「うちのエースが S級のエースと戦う」という夢のカード
- 対戦相手は当日まで不明 → ドキドキの発表演出
- 因縁のある相手と PPV で決着がつく可能性
- サミット（頂上決戦）が合同興行のメインイベントとして自然に組み込まれる

---

## 2. 参加条件

**orgPop ≥ 30 で PPV 出場資格を獲得。**

- 初めて orgPop 30 に到達した週に通知ポップアップ:
  「🏟️ PPV GRAND FINAL への出場資格を獲得しました！年末の大舞台に選手を送り出せます」
- 一度解禁されたらフラグ永続（orgPop が後で 30 を下回っても出場可能）
- GameState に `ppvUnlocked: true` フラグ追加

**orgPop < 30 のシーズン（未解禁時）:**
- PPV はスキップされず「テレビ観戦」モードで他団体の結果を閲覧可能
- 自団体の選手は出場しない
- ポイント変動やサミットの結果は通常通り処理される

---

## 3. 全体フロー

```
Week 43（非興行週）: PPVエントリー
  ├─ ppvUnlocked=true → エントリー選択画面
  └─ ppvUnlocked=false → スキップ（Week 48 でテレビ観戦）

Week 44〜47: 通常運営
  └─ エントリー選手が怪我中でも特別処理なし

Week 48（興行週）: PPV GRAND FINAL 当日
  ├─ 怪我チェック → 怪我中のエントリー選手は自動繰り上げ
  ├─ マッチメイク自動生成
  ├─ 全試合を順に発表＋観戦（スキップ可）
  ├─ メインイベント = サミット（条件を満たす場合）
  └─ 結果表示＋ポイント変動

→ Week 48 超 → オフシーズンへ
```

## 4. エントリーフェーズ（Week 43）

### 4.1 枠数

| ランキング順位 | 枠数 |
|:-:|:-:|
| 1位 | 5名 |
| 2位 | 4名 |
| 3位 | 3名 |
| 4位 | 2名 |
| **合計** | **14名 → 7試合** |

```js
const PPV_SLOTS = { 1: 5, 2: 4, 3: 3, 4: 2 };
```

### 4.2 プレイヤーのエントリー

- チャンピオンがいる場合は自動エントリー（1枠消費）
- 残り枠をプレイヤーが選択
- 選択可能条件: 怪我中でないこと、レンタル選手でないこと
- エントリー後の変更不可（確定ボタンで決定）

### 4.3 AI団体のエントリー

- OVR上位から枠数ぶん自動選出（怪我中は除外）
- AI団体にチャンピオン概念はないが、エースを優先選出

### 4.4 GameState追加

```js
ppvUnlocked: false,       // orgPop 30到達で永続true
ppvEntries: null,         // { player: [id,...], org_s: [id,...], ... } | null
ppvPhase: null,           // null | 'entry' | 'locked' | 'show' | 'tv'
ppvName: '',              // その年の大会名
```

### 4.5 tickWeek での発火

```
Week 43 の advanceWeek:
  if (ppvUnlocked) → weekPhase: 'ppvEntry'
  else → ppvPhase: 'tv'（テレビ観戦モード予約）
```

## 5. PPV当日（Week 48）

### 5.1 怪我→自動繰り上げ

Week 48 の処理開始時に全エントリー選手の状態をチェック:

```
エントリー選手が怪我中（injury !== null で Week 48 時点で未復帰）:
  → ロスター内の非エントリー・非怪我・非レンタル選手から OVR 最高を自動繰り上げ
  → 繰り上げ通知:「⚠ [選手名]が出場不能のため、[代替選手名]が緊急出場！」
  → ロスターに繰り上げ可能な選手がいない場合 → 枠削減（試合数減少）
```

### 5.2 マッチメイク

**制約:**
- 同団体同士は対戦しない

**優先順位:**
1. **因縁（rivalries）** — 宿敵以上のペアがエントリーにいれば最優先マッチング
2. **盛り上がりスコア** — 残りの選手を最適組み合わせ

```js
// 盛り上がりスコア（ペアの品質指標）
function calcExcitement(f1, f2) {
  const ovrSum = Engine.util.ov(f1) + Engine.util.ov(f2);
  const popSum = (f1.popularity || 0) + (f2.popularity || 0);
  const ovrGap = Math.abs(Engine.util.ov(f1) - Engine.util.ov(f2));
  return ovrSum + popSum * 0.5 - ovrGap * 2;
}
```

3. **チャンピオン / エースは後半に配置** — スコア昇順で並べ、前座→メインの盛り上がりカーブを作る

### 5.3 サミット（メインイベント）統合

**サミットは常にPPVのメインイベント（最終試合）。** ランク1位 vs 2位のエース対決。

**プレイヤーがランク2位以上の場合:**
- プレイヤーのエース（エントリー内OVR最高）vs ランク1位AI団体のエース
- 通常のマッチメイクからこの2名を除外し、残りで前座カードを組む
- 勝利時: 対戦pt +10（BATTLE_POINT_CFG.summit）
- 敗北時: 対戦pt -10

**プレイヤーがランク3位以下の場合:**
- ランク1位AI vs ランク2位AIのエース同士でサミットが行われる
- プレイヤーは観戦する側（メインイベントとして全員が見届ける）
- AI同士のサミットもバトルエンジンで計算し、対戦pt ±10 移動

### 5.4 試合発表演出

1試合ずつ順番に発表。前座から始まり、メインイベントへ盛り上がっていく。

**各試合の発表フロー:**
```
① カード番号 + 両選手の団体名表示
② 左側の選手（名前＋顔画像＋OVR＋団体名）
③ 「VS」演出
④ 右側の選手を発表（名前＋顔画像＋OVR＋団体名）
⑤ 煽り文テキスト表示
⑥ 対戦相手の一言セリフ（相手がプレイヤー選手でない場合）
⑦ [🎬 試合を観る] [⏭ スキップ] ボタン
```

**「試合を観る」:** バトルエンジン（battle-engine.html）で通常の観戦モードへ
**「スキップ」:** 試合結果（勝者＋MQ）だけ表示して次の試合へ

### 5.6 煽り文

カードの特徴に応じてテンプレートを選択:

| 条件 | 煽り文タイプ |
|------|------------|
| 因縁ペア | 「因縁の対決！{name1}と{name2}、この大舞台で決着か！」系 |
| ティア差あり | 「{tier}の壁！{name1}は{name2}を越えられるか！」系 |
| OVR接近 | 「実力伯仲！どちらが勝ってもおかしくない」系 |
| 人気者同士 | 「スター対決！夢のカードが実現！」系 |
| サミット | 「団体の威信を懸けた頂上決戦！」系 |

## 6. テレビ観戦モード（orgPop < 30 / 未解禁時）

自団体は出場しないが、PPV自体は開催される。

**表示内容:**
- 「📺 PPV GRAND FINAL [大会名] — テレビ中継」ヘッダー
- 全試合の結果を一覧表示（勝者＋敗者＋MQ）
- サミットの結果（ランキング1位 vs 2位のAI同士として処理）
- 対戦ポイント変動の表示
- 「来年こそはこの舞台に…」的なフレーバーテキスト

**AI同士のサミット（プレイヤー未参加時）:**
- ランク1位 vs 2位のエース同士で自動処理（プレイヤーがランク3位以下、またはPPV未解禁時）
- バトルエンジンで計算、対戦pt ±10 移動

## 7. 収入

PPV出場報酬（合同大会の分配金）:

```js
const PPV_REWARD = { 1: 300, 2: 200, 3: 150, 4: 100 }; // 万円
```

- ランク依存の固定額。興行収入（チケット・グッズ）は発生しない
- テレビ観戦モード（未出場）の場合は報酬なし

## 8. 結果処理

### 8.1 試合結果

- 全試合はバトルエンジン（Engine.battle.simulateMatch）で計算
- 人気変動: 通常興行と同じルール（MQ依存）
- 因縁: PPVでの試合も因縁カウント対象（決着判定あり）
- ヒート変動: 通常興行と同じ
