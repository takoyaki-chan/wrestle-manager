# 試合画面UI刷新 + full画像活用 — 確定仕様書

## 1. 画像体系

| 種類 | サイズ | 比率 | 形式 | 用途 |
|---|---|---|---|---|
| face | 256×256 | 1:1 | PNG | 顔アイコン（HUD、一覧、名前横） |
| upper | 256×384 | 2:3 | WEBP透過 | 正面ポートレート（勝利演出、選手詳細ポップアップ、選手感情表現） |
| stand | 256×384 | 2:3 | WEBP透過 | 横サイドビュー上半身（**試合画面メイン**） |
| full | 512×768 | 2:3 | WEBP透過 | 全身立ち絵（対戦カード、PPVマッチカード、練習画面詳細） |

### データ関数
- `getPortraitUrl(id)` — 既存
- `getUpperUrl(id)` — 既存（※実態はstand画像のパス `image/stand/stand_{name}.webp` を返している。関数名と実態のミスマッチあり → リファクタ時に整理）
- `getFullUrl(id)` — **未実装、data.jsに追加が必要**
- ファイルパス: `image/full/full_{name}.webp`

### 画像の反転ルール
- 左側キャラクターは常に `scaleX(-1)` で反転して右向きにする
- stand画像・full画像ともに同じルール

## 2. full画像の使用箇所（3箇所に限定）

### 2-1. 対戦カード紹介画面（確定済み）

#### タイミング
- 試合開始前（バトルエンジン読み込み後、最初のNEXTクリック前）
- battle-engine.html内に組み込み

#### レイアウト — ポスター構図
- 左右それぞれ幅50%にfull画像が画面上端から下端まで埋める
- 中央にテキスト情報が挟まれる配置
- 画像: `object-fit:cover` + `object-position:center 95%`（つま先まで収まる調整）
- 左キャラは `scaleX(-1)` 反転

#### 背景
- 暗い会場背景（`battle-bg_venue_N.webp` 1920×1200）。現在venue_4のみ作成済み
- 中央に暗幕グラデーション（テキスト可読性用の楕円形ダーク）
- リング床ライン（ゴールドの水平ライン）
- スキャンライン + 四隅コーナーフレーム

#### 中央テキスト（上から順に）
1. 興行名（例: 「WRESTLE MANAGER GRAND PRIX 2026」）
2. 第N試合
3. 試合形式（「SINGLES MATCH」等）
4. 選手名（大きく）+ スタイル名（Grappler / Striker等）
5. 「VS」（Bebas Neue 42px ゴールド）
6. 対戦成績（2行構成）
   - 1行目:「対戦成績」ラベル
   - 2行目:「高津 3勝 ／ 橘 2勝」
   - 初顔合わせの場合は代わりに「— 初 顔 合 わ せ —」
7. バッジ（該当する場合のみ）
   - 🔥 RIVAL — ライバル関係がある場合
   - 🏆 TITLE MATCH — タイトルマッチの場合

#### 操作
- NEXTボタンで試合画面に遷移（自動タイマーなし。じっくり見れる）

#### 遷移演出タイムライン
| 時間 | 内容 |
|---|---|
| 0ms | NEXTボタン押下。ボタン無効化 |
| 0ms | ゴングフラッシュ（白フラッシュ150ms）+「カーン」SE |
| 200ms | 「FIGHT!」テキストが画面中央にスケールインで出現 |
| 800ms | 「FIGHT!」テキストがスケールアウトで消去 |
| 1000ms | 対戦カード画面がフェードアウト |
| 1200ms | バトル画面アクティブ化。左右パネルが画面外からスライドイン（**この時点で既にstand画像**）。cubic-bezier(0.22,1,0.36,1)のイージング |
| 1200ms〜 | 中央パネルがtranslateY(30px)から上昇しつつフェードイン（0.3s遅延） |
| 2200ms | 全パネル定位置。NEXTボタン再有効化。バトル開始可能 |

## 3. 試合画面（バトル中）UI仕様

### ベース
- **Concept Fが最終採用ベース**（`concept-f-panel-hud.html`）
- ファイル: `src/battle-engine.html`（単体HTML、iframe経由で呼び出し）
- `.app` のサイズ: `max-width:1400px; padding:20px`（現行battle-engineと同一）

### 3-1. レイアウト構造

│ ┌────────┐ │              │ ┌────────┐   │
│ │stand画像│ │  ターン表示   │ │stand画像│   │
│ │(反転)   │ │  ナレーション │ │         │   │

### 3-2. HUDバー

- 3カラムの**上に独立した**バーとして配置
- 左側: 顔アイコン（丸枠、青ボーダー）+ 選手名 + スタイル名
- 中央: TURN表示 + PHASE表示
- 右側: 選手名 + スタイル名 + 顔アイコン（丸枠、赤ボーダー）
- HPバー: 左右対称の対面式（左HP← HP →右HP）+ パーセント数値表示
- モメンタムバー: 左右で色分け（青/赤）、割合で可変

### 3-3. 選手パネル

#### 画像表示エリア（portrait-area）
- aspect-ratio: 2/3
- stand画像: height:105%, object-fit:contain, object-position:center bottom
- スキャンライン（::before疑似要素、repeating-linear-gradient）
- ビネット（::after疑似要素、radial-gradient）
- コーナーフレーム（ゴールド角飾り）
- 左パネルは青い内側グロー、右パネルは赤い内側グロー

#### 選手情報エリア（fighter-info）
- 選手名（font-weight:900）— **クリックで詳細ポップアップ（showFighterPopup相当）を表示**
- ロールタグ（FACE / HEEL）
- スタイル名（**正式名称**: Grappler / Striker等。「Power Fighter」「Speed Fighter」は廃止）
- ライバルバッジ（🔥 RIVAL）— ライバル関係がある場合、**両方のパネルに表示**
- タイトルマッチの場合: ベルト表示
- 能力値バー（POW / SPD / TEC / STA / MN）
- 戦績（W-L）は**不要**（ここでは表示しない）

### 3-4. 中央パネル

- **全要素中央寄せ**（text-align:center）
- ターン番号: **カタカナ「ターン 8」形式**（旧T8形式は廃止）。Noto Sans JP 20px 太字 ゴールド。中央配置
- フェーズ表示（PHASE 1/2/3）: ターン番号の横に配置
- **ナレーションボックス（実況欄 — メインの見せ場）**
  - 攻撃者表示: 16px太字
  - ナレーションテキスト: **16px太字**（最も大きく目立つ。実況の臨場感を出す）
  - ダメージ数値: 14px太字、赤
  - 左ゴールドボーダーは廃止、中央寄せに変更
- 技名表示ボックス: **18px太字**（やや大きめ）
- モメンタムバー（中央パネル内にも表示）
- バトルログ: **小さめ表示**（9px/8px）。終わった情報なので控えめに。中央寄せ

### 3-5. 維持するエフェクト

- スキャンライン（パネル上のモニター調横線）
- コーナーフレーム（ゴールドの角飾り）
- ビネット（パネル端の暗がり）
- 背景のupper画像は**不要**（パネルの暗いトーンだけ）

## 4. ダメージ表現

### 廃止するもの
- `exhausted` — 画像暗転
- `critical` — 画像暗転＋赤パルス
- `flash-hit` — 赤枠フラッシュ

### 通常ダメージ
- **shake**: 被弾側パネル全体が揺れる（`shakePanel` 0.25s ease-out、±6px→±3px→0）
- **ダメージ数字ポップアップ**: パネル中央上部に数字が出現→上に浮いて消える（0.85s）。赤色（#e85d75）

### クリティカルダメージ
- **画面全体フラッシュ**: 白い半透明オーバーレイが0.25sで明滅
- **スクリーンシェイク**: パネルのshakeが通常より強い
- **金色大ダメージ数字**: 通常より大きく（48px）、色はゴールド（--gold-l）、ゴールドのtext-shadow

### HP25%以下（ダメージ蓄積演出）
- 被弾側パネルの**足元に赤い光が脈動**
- radial-gradientで**下部45%**に赤グロー（広め・強め）
- ellipse 130%幅で枠を超えるほど広く、opacity 0.45の濃い赤
- 1.8sのease-in-outで明滅ループ（opacity 0.5→1.0→0.5）
- HPが25%超に回復したら消える

## 5. ビッグムーブ演出（決め技カットイン）

### 方式
- **セリフカットインベース**。full画像パン方式は没。
- 攻撃側のupper画像+決め技系セリフがカットインとして画面中央にポップアップ
- カットイン後に技名表示 → ダメージ適用
- ビッグムーブ用の溜め音（低音ライザー）はそのまま使用

### トリガー条件
- 一定以上のダメージが「入るかもしれない」技が**候補に上がった段階**で発動
- この時点で技の成否は**未確定**（カウンターされる可能性あり）
- フィニッシャーに限らず、ダメージ閾値で判定

### 発動頻度
- 1試合あたり **0〜3回** 程度
- あまり頻発すると冷めるので抑制的に

### 演出タイムライン（技が通る場合）

| 時間 | 内容 |
|---|---|
| 0.0s | 攻撃側のセリフカットイン表示（upper画像+決め技セリフ）。溜め音開始 |
| 0.0s | SE: cutinSlide（スワイプ音）+ bigmoveCharge（低音ライザー） |
| 1.5s | セリフカットイン消去 |
| 1.8s | 技名（例:「パワーボム」）が画面中央にドンと表示。Bebas Neue 56px ゴールド |
| 2.3s | 技名フェードアウト + ダメージ適用。SE: bigmoveImpact（重い衝撃音）|
| 3.0s | クリーンアップ |

### セリフカットインの仕様
- 通常のセリフカットインと同じUI（upper画像100×150 + テキスト）
- ただし内容は決め技系セリフ（「ここで…決める！！」「全力で…いくよ！！」等）
- 性格×属性で分岐
- **クリックで消せる**（通常セリフと同じ操作性）

## 6. カウンター演出

### 方式
- ビッグムーブ（§5）と**同じ導入**（セリフカットイン+溜め音+技名表示）の後、COUNTER!文字が技名を吹き飛ばす
- ビッグムーブが発動しない通常攻撃にはカウンター演出は付かない

### 演出タイムライン

| 時間 | 内容 |
|---|---|
| 0.0s | ビッグムーブと同じ導入: セリフカットイン + 溜め音 |
| 1.5s | セリフカットイン消去 |
| 1.8s | 技名（例:「パワーボム」）が画面中央に表示 |
| 2.3s | **「COUNTER!」文字が防御側の方向から横スライドイン**（80px シアン色） |
| 2.3s | 技名が**反対側に吹き飛ばされる**（回転+縮小しながら画面外へ） |
| 2.3s | 防御側パネルが白フラッシュ + scale(1.05)拡大 |
| 2.3s | SE: counterSE（重い衝撃ノイズ「バケッ！」） |
| 2.8s | 防御側フラッシュ解除 |
| 3.2s | COUNTER!フェードアウト + 攻撃側に反撃ダメージ |
| 3.8s | クリーンアップ |

### COUNTER!のスライド方向
- **防御（カウンター）側の位置から入ってくる**
  - 右キャラがカウンター → COUNTER!が**右から左へ**スライドイン、技名は左に吹き飛ぶ
  - 左キャラがカウンター → COUNTER!が**左から右へ**スライドイン、技名は右に吹き飛ぶ

### 技名の吹き飛び
- `blown-right`: translate(120%) + rotate(8deg) + scale(0.7) で右に飛散
- `blown-left`: translate(-220%) + rotate(-8deg) + scale(0.7) で左に飛散
- 0.3sのcubic-bezier(0.5,0,1,0.5)で勢いよく飛ぶ

### カウンターSE
- 旧（高音ピョン）は廃止
- 新: ノイズバースト + 低音ドン + 高域クラック。「バケッ！」という重い衝撃音
- 実装: `mkNoise(.12,.3) + osc(sine,150→40) + mkNoiseLP(.15,.2,500) + osc(square,800→200)`

## 7. カットインシステム（セリフ・ダメージセリフ・ダメージボイス）

### 共通仕様
- 画面中央にオーバーレイ表示（z-index:60）
- upper画像（100×150px、角丸4px、枠付き）+ テキスト
- 左キャラは左からスライドイン、右キャラは右からスライドイン（0.35s）
- **クリックで消す**（自動消去なし）。「CLICK TO CLOSE」表示
- SE: cutinSlide（短い高音スワイプ）

### 7-1. セリフ
- **用途**: 挑発、気合い、感情表現。フェーズ切り替え時のライバルカットイン等
- **テキスト分岐**: 性格×属性
- **デザイン**: ゴールド枠、ゴールドの名前テキスト、白の太字セリフ（20px）
- **表示**: 名前（性格・属性）+ 「セリフ」

### 7-2. ダメージセリフ
- **用途**: 試合終盤、大技を食らった時の苦悶の言葉
- **トリガー条件**:
  - 試合終盤（決着が近い場面）に限定
  - 関節技を耐えている時
  - 大技・必殺技級を食らった時
  - ダメージ蓄積が深い状態での被弾
- **テキスト分岐**: 性格×属性（意味のある長めのセリフ）
- **デザイン**: 赤系枠、赤の名前テキスト、ピンク系のセリフ（20px）
- **SE**: cutinSlide + dmgVoice（鈍い低音）
- **例**:
  - 熱血×Grappler: 「ぐっ…！ まだ…立てる…！」
  - 冷徹×Striker: 「…っ！ …こんなの…」
  - 天然×Striker: 「ひゃあっ！？ い、痛い…！」
  - 女王×Grappler: 「っ…！ この私に…よくも…！」

### 7-3. ダメージボイス
- **用途**: クライマックス、決着がつくかもしれない最終局面での短い悲鳴
- **トリガー条件**: ダメージセリフよりさらに限定的。決着間際の被弾
- **テキスト分岐**: **属性のみ**（性格は不問。短い悲鳴なので細かい意味合いが薄い）
- **デザイン**: 濃い赤系枠+背景、大きめ文字（28px）。upper画像は暗め+彩度低め
- **SE**: cutinSlide + dmgVoice
- **例**:
  - Grappler: 「ぐぅっ…！」「がはっ…！」
  - Striker: 「きゃあっ！」「うわっ…！」
  - Technician: 「くぅ…！」「あ…ぁ…っ！」
  - Aerial: 「きゃっ！」「あぁっ！」

## 9. 技術的な注意事項

- `battle-engine.html` は単体HTMLでiframe呼び出し
- `.app` のサイズ: `max-width:1400px; padding:20px`（現行battle-engineと同一）
- 画像パスは `../../image/` 相対パス（iframe内からの参照）
- `getUpperUrl` は実際にはstand画像のパスを返している → リファクタ時に `getStandUrl` に改名 or 整理
- `getFullUrl(id)` を `data.js` に新規追加
- upper画像パス: `image/upper/upper_{name}.webp`（カットインシステムで使用）
- 会場背景画像: `battle-bg_venue_N.webp`（1920×1200 webp）。venue規模別に増やせる命名体系。現在venue_4のみ
- full画像はバトル中の演出には使用しない（対戦カード・PPVマッチカード・練習画面詳細のみ）
