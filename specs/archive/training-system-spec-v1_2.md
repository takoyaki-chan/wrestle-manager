## 設計原則

1. **Notion値は「一人前の基準」** — 入団時はNotion値より低い。成長してNotion値に到達して一人前。さらにその先は才能次第
2. **100超えはトップオブトップ、130は奇跡** — 大半の選手は全盛期で80〜90台。100を超えられるのはごく一握り
3. **MNTは先天的な才能** — 練習で伸びない。入団時からほぼ変わらない固定値
4. **育成はシンプル操作** — プレイヤーは「練習/プロモ/休養」の3択のみ。何を伸ばすかはスタイルとコーチで自動決定
5. **35歳で引退** — 30歳から衰退が始まり、35歳が引退適齢期。それ以降は確定衰退
6. **毎回違う育成体験** — trainCapはニューゲームごとにランダム。毎週の成長にもブレがある。「今回はどこまで行くかな」の偶然性

## §1 パラメータの数値レイヤー

### §1.1 レイヤー定義

| レイヤー | 名称 | 範囲 | プレイヤーへの公開 |
|---------|------|:----:|:----------------:|
| 現在値 | value | 0〜200 | ✅ 公開 |
| Notion値 | notionValue | 11〜95 | ❌ 非公開（内部基準） |
| 育成上限 | trainCap | §1.4で算出 | ❌ 非公開 |
| 潜在値 | potential | 74〜185 | ❌ 非公開 |

```
入団時の値 < Notion値 ≤ trainCap ≤ 潜在値 ≤ 200

プレイヤーに見えるのは「現在値」だけ。
あとどれだけ伸びるかは、育ててみないとわからない。
```

### §1.2 Notion値の位置づけ

Notion値は「その選手が一人前になった時の能力」を表す内部基準値。

| 項目 | 仕様 |
|------|------|
| 定義 | 選手が一人前のプロレスラーとして完成した時の能力値 |
| 全選手平均 | 約64（合計319.9 / 5パラ） |
| 到達時期の目安 | 16歳入団→22〜25歳頃にNotion値到達（約6〜9シーズン）|
| プレイヤーへの表示 | 非公開。成長の鈍化で間接的に感じる |

### §1.3 入団時の値

入団年齢に応じて、Notion値に対する割合で入団時の現在値が決まる。

```javascript
function getStartValue(notionValue, entryAge) {
  let startRatio
  if (entryAge <= 17)      startRatio = 0.55 + random(0, 0.10)  🔧  // 高校生
  else if (entryAge <= 20)  startRatio = 0.65 + random(0, 0.10)  🔧
  else if (entryAge <= 24)  startRatio = 0.75 + random(0, 0.10)  🔧
  else if (entryAge <= 29)  startRatio = 0.85 + random(0, 0.10)  🔧  // 全盛期入団
  else                      startRatio = 0.90 + random(0, 0.10)  🔧  // ベテラン入団

  return round(notionValue × startRatio)
}
```

**具体例**:

| 選手 | 年齢 | Notion PWR | 入団時PWR（推定） | 備考 |
|------|:----:|:---------:|:---------------:|------|
| 高津小春 | 16 | 73 | 40〜47 | 高校生。入団時はまだ未完成 |
| 阿武隈塔子 | 16 | 95 | 52〜62 | 才能は高いが若い |
| 佐藤ヨーコ | 16 | 19 | 10〜15 | マスコット枠 |
| 大久保桃子 | 27 | 72 | 61〜68 | OL。入団時でほぼ一人前 |
| 高槻千歳 | 33 | 71 | 64〜71 | 団地妻。入団時≒Notion値 |

### §1.4 育成上限（trainCap）のランダム生成

> **🟢 v1.2で確定**（旧Notion依存式から0ベース式に変更）

**trainCapは選手が団体に所属する時点で、全パラメータごとに個別にランダム決定される。**

| 状況 | trainCap生成タイミング |
|------|:-------------------:|
| 初期所属選手（プレイヤー・AI団体） | ゲーム開始時 |
| スカウトで入団 | 入団確定時（scout-system-spec §6.2） |
| フリー→正式契約 | 契約時 |
| 未登場プールの選手 | 団体所属が決まるまで未生成 |

```javascript
function generateTrainCap(potential) {
  let factor = randomRange(0.50, 0.80)  🔧  // 乗数0.50〜0.80（平均0.65）
  let cap = round(factor × potential)
  return cap  // 0ベース。潜在値に対する純粋な割合
}
```

#### v1.1以前との変更点

| | 旧式（v1.1以前） | **新式（v1.2〜）** |
|---|---|---|
| 計算式 | `Notion + factor × (Pot - Notion)` | **`factor × Pot`** |
| factor範囲 | 0.10〜0.50 | **0.50〜0.80** 🔧 |
| Notion依存 | あり（低Notion=低trainCap） | **なし** |
| 設計思想 | 現在値からの伸びしろ | **潜在値に対する到達率** |

#### 変更理由

旧式では `trainCap = Notion + factor × (Pot - Notion)` のため、**Notion値が低く潜在値が高いキャラ（原石アーキタイプ）が構造的に不利**だった。

例: 高島さや（Notion合計109, Pot合計676）
- 旧式 factor=0.50（大当たり）: trainCap合計392 → OVR 79
- 阿武隈塔子 旧式 factor=0.10（ハズレ）: trainCap合計440 → OVR 88
- **さやの大当たり < 阿武隈のハズレ** という逆転が発生

新式では潜在値のみで計算されるため、原石キャラも潜在値に見合ったtrainCapを得られる。

#### 新式での具体例

**高津小春 PWR（Pot=155）:**

| factor | trainCap | 意味 |
|:----:|:--------:|------|
| 0.50（不運） | 78 | 今回の小春はあまり伸びない… |
| 0.65（平均） | 101 | **100超え。よく育った** |
| 0.80（大当たり） | 124 | **大化け。トップオブトップ** |

**阿武隈塔子 PWR（Pot=184）:**

| factor | trainCap | 意味 |
|:----:|:--------:|------|
| 0.50 | 92 | 才能あるのに今回は伸び悩み |
| 0.65 | 120 | トップオブトップらしい到達点 |
| 0.80 | 147 | **伝説級。ここまで行けば奇跡** |

**高島さや TEC（Pot=166）:**

| factor | trainCap | 意味 |
|:----:|:--------:|------|
| 0.50 | 83 | Notion19から83。原石が光る |
| 0.65 | 108 | **100超え！さやの才能が開花** |
| 0.80 | 133 | **大化け。誰も予想しなかった成長** |

**設計意図**:
- 同じ選手を何回プレイしても、異なる育成結果になる
- trainCapが非公開なので「今回のこの子はどこまで伸びるんだろう」のワクワク感がある
- 才能（潜在値）が高い選手ほどtrainCapの振れ幅が大きく、大化けの可能性がある
- **原石キャラ（低Notion/高Pot）も潜在値相応の天井を持てる**
- 既存の上位キャラのバランスは factor=0.65 付近で旧式 factor=0.30 とほぼ同値を維持

### §1.5 潜在値の個別上書き

潜在値は基本的に character-data-spec §2.2 の公式で算出される。

```
潜在値 = min(185, round(Notion値 × 1.3 + 60))
```

ただし、**幼いキャラや特殊設定のキャラは「Notion値は低いが才能は別」**というケースがあるため、潜在値を個別に上書きできる。

```javascript
// characters.json での指定
{
  "id": "satou_youko",
  "params": { "pwr": 19, ... },
  "potential": { "pwr": 85, ... },           // 公式通り
  "potentialOverride": { "pwr": 130, ... }   // 個別上書き（設定する場合のみ）
}

// 上書きがある場合はそちらを優先
effectivePotential = potentialOverride ?? potential
```

> 個別上書きの具体的な対象キャラと数値は後日調整する。

### §1.6 MNTの扱い（固定値）

MNTは**練習で成長しない先天的な精神力**。

```javascript
// MNTの初期値 = Notion値そのまま（年齢補正なし）
fighter.mnt = notionValue_MNT

// MNTは練習の成長対象外
// MNTは加齢による衰退もほぼなし（§5.4）
// MNTが変動するのは以下のケースのみ:
//   - 覚醒イベント（フェーズ4で設計）
//   - 35歳以降の微確率衰退（5%で-1）
```

## §2 成長の基本メカニクス

### §2.1 成長の対象

| パラメータ | 練習成長 | 試合成長 | 加齢衰退 |
|-----------|:-------:|:-------:|:-------:|
| PWR | ✅ | ✅ | ✅（30歳〜） |
| SPD | ✅ | ✅ | ✅（30歳〜、最も早く衰える） |
| TEC | ✅ | ✅ | ✅（30歳〜、最も衰えにくい） |
| STA | ✅ | ✅ | ✅（30歳〜） |
| MNT | ❌ | ❌ | ほぼなし（35歳〜微確率のみ） |

### §2.2 成長の発生タイミング

| タイミング | 条件 | 備考 |
|-----------|------|------|
| 練習選択週 | 「練習」を選んだ週の週末処理時 | メイン成長手段 |
| 試合後 | 試合出場時（微量） | 試合経験による成長 |

> プロモ選択週・完全休養週はパラメータ成長しない

### §2.3 練習による成長（全自動・ランダム幅あり）

プレイヤーは**「練習 / プロモ / 休養」の3択のみ**。練習を選ぶと、選手のスタイルとコーチに応じて自動的にパラメータが成長する。**毎週の成長量にはランダム幅がある。**

```javascript
// 1週間の練習で得られる成長量（パラメータごとに算出）
baseGain = styleGain[param]                  // スタイル別の成長配分（§3）
         × ageMultiplier(age)                // 年齢補正（§5.2）
         × coachMultiplier(param, coaches)   // コーチ倍率（§4）
         × facilityMultiplier(facilityLv)    // 施設レベル補正（§6）
         × convergenceFactor(value, trainCap) // 上限収束（§2.4）

// 毎週のランダム幅: 0.5倍〜1.5倍のブレ
weeklyVariance = randomRange(0.5, 1.5)  🔧
rawGain = baseGain × weeklyVariance

actualGain = max(0, round(rawGain × 10) / 10)  // 小数第1位まで保持（内部値）

// 表示は整数（小数部分は内部的に蓄積し、1を超えた時点で表示値に反映）
displayValue = floor(internalValue)
```

**ランダム幅の意味**:
- 同じ条件で練習しても、週によって「よく伸びた週」と「あまり伸びなかった週」がある
- trainCapのランダム（プレイごとの大きな違い）＋週次ランダム（毎週の小さな揺れ）の二重構造
- baseGainが0.5の場合：実際の成長は0.25〜0.75の間。体感として「伸びる時と伸びない時がある」

### §2.4 上限への収束ロジック

> **🟡 改定予定**（v1.3で「イベント駆動型成長モデル」に移行予定。以下は旧仕様の参考記載）
>
> **改定理由**: 現行の線形収束では、18年×31週の練習だけでほぼ全員がtrainCap付近（93〜100%）に到達してしまい、キャリアのバラつきが生まれない。日常練習だけではtrainCapの60〜70%程度に留まり、残りはブレークスルーや絶好調期間などの離散イベントに依存する新モデルに移行する（§7参照）。

現在値がtrainCapに近づくほど成長が鈍化する。

```javascript
function convergenceFactor(value, trainCap, notionValue) {
  if (value >= trainCap) return 0  // 上限到達で成長停止

  remaining = trainCap - value
  totalRange = trainCap - 30  🔧  // 下限30を基準とした成長レンジ

  baseFactor = remaining / totalRange

  // Notion値を超えてからは追加鈍化（一人前の先は険しい道）
  if (value >= notionValue) {
    baseFactor *= 0.4  🔧  // Notion値超え後は成長速度が40%に
  }

  return clamp(baseFactor, 0.02, 1.2)  🔧
}
```

**設計意図**:
- 入団時〜Notion値: 比較的スムーズに成長。「一人前に育っていく実感」
- Notion値〜trainCap: 成長速度が激減。「壁を超えるのがいかに難しいか」
- trainCapが非公開なので、プレイヤーからは「伸びが鈍ってきた…どこまで行けるんだろう」と感じる

### §2.5 試合による成長（サブ・ランダム幅あり）

試合に出場するだけで微量の成長が発生。練習とは別枠。

```javascript
// 試合1回あたりの成長量（PWR/SPD/TEC/STAのみ。MNTは対象外）
matchBaseGain = 0.2  🔧
matchVariance = randomRange(0.0, 2.0)  🔧  // 0〜2倍。伸びない試合もある
matchGain = matchBaseGain × matchVariance

// 適用条件
if (試合出場 && 正規選手) {
  各対象パラメータに matchGain × convergenceFactor を加算
}
```

## §3 スタイル別自動成長配分

### §3.1 成長配分テーブル

練習を選択した週に、スタイルに応じて4パラ（PWR/SPD/TEC/STA）に自動配分される。

| スタイル | PWR | SPD | TEC | STA | 配分の意図 |
|---------|:---:|:---:|:---:|:---:|-----------|
| Grappler | 1.0 | 0.4 | 0.8 | 0.8 | パワーとテクニックの投げ技師 |
| Striker | 0.8 | 0.8 | 0.4 | 1.0 | 打撃＋スタミナ。スピードもそこそこ |
| Submission | 0.3 | 0.4 | 1.0 | 0.8 | テクニック特化。体力も必要 |
| Aerial | 0.3 | 1.0 | 0.7 | 0.5 | スピード全振り。テクニックも |
| Allrounder | 0.7 | 0.7 | 0.7 | 0.7 | 均等に伸びる万能型 |
| Brawler | 1.0 | 0.5 | 0.2 | 1.0 | パワーとスタミナのケンカ屋。技術は伸びにくい |

🔧 配分値は全て調整可能パラメータ

### §3.2 成長速度の具体例

**例: 高津小春（Striker, 16歳入団, コーチなし, 施設Lv1）**

Notion値: PWR=73, SPD=75, TEC=47, STA=79, MNT=91(固定)
入団時推定: PWR=42, SPD=43, TEC=27, STA=45, MNT=91

Striker配分: PWR=0.8, SPD=0.8, TEC=0.4, STA=1.0

```
最初の1週のPWR成長（ランダム幅あり）:
  baseGain=0.8 × age=1.5 × coach=1.0 × facility=1.0 × convergence≒0.55
  = 0.66/週（基準値）

  実際の成長: 0.66 × weeklyVariance(0.5〜1.5)
  → 0.33〜0.99/週（週によって違う）

→ 1シーズン（48週）のうち練習30週 + 試合成長:
  PWR: 42 → 約55〜65（ランダム幅で±5程度のブレ）

→ 3シーズン後（18歳末）:
  PWR: 約68〜76。ランダム次第でNotion値に届くことも、まだ届かないことも。
```

## §4 コーチシステムの育成効果

### §4.1 コーチ倍率（character-data-spec §4.5 準拠）

```javascript
coachMultiplier = 1.0  // コーチなしの基準

for (each coach) {
  if (param がコーチの primarySpecialty) {
    coachMultiplier = max(coachMultiplier, coach.primaryBonus)
  }
  else if (param がコーチの secondarySpecialty) {
    coachMultiplier = max(coachMultiplier, coach.secondaryBonus)
  }
}
```

| ティア | primary倍率 | secondary倍率 | 週コスト | 得意分野 |
|:------:|:----------:|:------------:|:-------:|---------|
| S | ×1.40 | ×1.25 | 75〜80万 | 全パラメータ |
| A | ×1.30 | ×1.15 | 50万 | 2パラメータ |
| B | ×1.25 | ×1.10 | 25〜30万 | 2パラメータ |

## §5 加齢システム

### §5.1 年齢の設定

| カテゴリ | 入団年齢 | 備考 |
|---------|:-------:|------|
| 学園女子プロレス | 16歳 | 高校入学時に入団 |
| 女子高生プロレス | 16歳 | 同上 |
| 団地妻プロレス | Notion記載年齢 | 23〜37歳。入団時≒Notion値 |
| OLプロレス | Notion記載年齢 | 27〜31歳 |
| その他 | 指定なければ20歳 | |
| 新規スカウト選手 | 16〜22歳（ランダム）🔧 | |

### §5.2 年齢フェーズと成長倍率

> **🟡 調整予定**（新人期×1.5→×1.2、若手期×1.2→×1.1、衰退期の数値も見直し予定。イベント駆動型成長モデル§7と連動して最終調整）

```javascript
function ageMultiplier(age) {
  if (age <= 18) return 1.5   // 新人
  if (age <= 21) return 1.2   // 若手
  if (age <= 25) return 1.0   // 成長期
  if (age <= 29) return 0.7   // 全盛期
  if (age <= 32) return 0.3   // 衰退初期
  if (age <= 34) return 0.1   // 衰退期
  return 0                    // 引退適齢期（成長完全停止）
}
```

| 年齢 | フェーズ名 | 成長倍率 🔧 | パラ衰退 | 状態説明 |
|:----:|:--------:|:---------:|:-------:|---------|
| 16〜18 | 新人 | ×1.5 | なし | 入団直後。Notion値に向かって急成長する時期 |
| 19〜21 | 若手 | ×1.2 | なし | 一人前が見えてくる。伸び盛り |
| 22〜25 | 成長期 | ×1.0 | なし | Notion値に到達し、さらに上を目指す段階 |

### §5.3 加齢による衰退（シーズン末判定）

**30歳以降**、シーズン終了時（オフシーズン処理）にパラメータ衰退判定が入る。

```javascript
function applyAging(fighter) {
  if (fighter.age < 30) return  // 29歳以下は衰退なし

  for (each param in [PWR, SPD, TEC, STA]) {
    decayChance = DECAY_TABLE[agePhase][param]  // §5.4 参照
    if (random() < decayChance) {
      decayAmount = DECAY_AMOUNT[agePhase][param]
      // 下限 = Notion値の70%
      fighter[param] = max(round(fighter.notionValue[param] × 0.7), fighter[param] - decayAmount)  🔧
    }
  }

  // MNT特殊処理（ほぼ衰えない）
  if (fighter.age >= 35 && random() < 0.05) {  🔧
    fighter.mnt = max(round(fighter.notionValue.mnt × 0.85), fighter.mnt - 1)  🔧
  }
}
```

## §9 成長イベントシステム（設計中）

> **🟡 セッション8で方針確定。次セッションで詳細設計→実装予定**
> 旧§9（覚醒/スランプ/ターニングポイントの予約枠）を全面改定。

### §9.1 背景と課題

現行の「日常練習主体」モデルでは成長の主エンジンが「毎週の練習成長の蓄積」のため、18年×31週=558回の試行により大数の法則が効き、**ほぼ全員がtrainCapの93〜100%に到達**してしまう。大スランプやシーズン不調を導入しても、残り期間で取り戻せるため根本解決にならない。

### §9.2 新モデルの方針

**成長の二本柱:**

| 柱 | 役割 | trainCapへの貢献 |
|---|---|---|
| 日常練習 | 基盤を作る。これだけでは一流になれない | trainCapの**60〜70%**まで |
| 離散イベント | ブレークスルー・絶好調が実際の到達点を決定 | 残りの**0〜30%** |

日常練習の係数を抑制（現行比×0.5程度を想定。イベント設計とセットで最終調整）し、**イベントの有無でキャリアが分岐する**構造にする。

### §9.3 プラスイベント

| イベント | 発生頻度 | 効果 | 備考 |
|---------|---------|------|------|
| **試合ブレークスルー** | 試合後に低確率（年≈3〜5%） | 1パラメータが即座に+3〜8ジャンプ | trainCapを超えない |
| **絶好調期間** | ブレークスルー後の約20%で発動 | 1〜2年間、成長速度×2.0 | 連鎖的な大化けを可能にする |

### §9.4 マイナスイベント

| イベント | 発生頻度 | 効果 | 期間 |
|---------|---------|------|------|
| **スキャンダル/モチベ喪失** | 年≈2.5% | 成長完全停止 | 数ヶ月〜5年 |
| **怪我** | 年≈8% | 成長停止 + パラ微減 | 1〜6ヶ月 |
| **精神ダメージ** | 年≈5% | 成長大幅鈍化（×0.15） | 3ヶ月〜1年 |
| **複合（怪我+精神）** | 年≈1% | 怪我+精神が同時発生 | 長期離脱+パラ減少 |

### §9.5 シーズン品質（検討中）

上記イベントに加え、無数の小さな要因（軽い不調、コンディション波、モチベーション変動）をシーズン単位の品質倍率として合成する案も検討中。

### §9.6 シミュレーション結果（参考値）

セッション8でのプロトタイプ試行結果。日常練習×0.5＋上記イベント込み。

|--------|:--------:|:--------:|:---:|:------:|:------:|:------:|
| 阿武隈PWR 大当たり | 140 | 116.4 | 5.4 | 110 | 116 | 123 |
| 阿武隈PWR 平均 | 122 | 106.0 | 4.8 | 101 | 105 | 112 |
| 阿武隈PWR ハズレ | 104 | 94.7 | 4.0 | 91 | 93 | 101 |

## §10 ランダム性のまとめ

本システムには3層のランダム性がある。

| 層 | 何がランダムか | 決定タイミング | 影響の大きさ |
|:--:|-------------|:------------:|:----------:|
| 第1層 | trainCap（育成上限） | ニューゲーム時に1回 | **大** — 到達点そのものが変わる |
| 第2層 | 入団時の値（startRatio） | 選手入団時に1回 | 中 — スタート地点が変わる |
| 第3層 | 週次成長量（weeklyVariance） | 毎週の練習時 | 小 — 成長過程のブレ |

**プレイヤーの体験**:
- 第1層: 「今回の小春はどこまで行くかな」（プレイごとの大きな違い）
- 第2層: 「入団時点でこの子はちょっと強いぞ」（初見のワクワク）
- 第3層: 「今週はよく伸びた！」「今週は停滞気味…」（毎週の小さな一喜一憂）

全てプレイヤーには非公開。見えるのは現在値の変化だけ。
