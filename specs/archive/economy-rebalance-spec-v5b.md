## §0 設計思想

### 問題
現行の経済システムは中盤以降で利益が爆発的に増大し、プレイヤーの資金がダブつく。興行を開くだけで投資額の何倍ものリターンが得られるため、経営判断の緊張感がない。

### 原因
1. チケット単価が全会場一律0.5万/人で、集客が増えるほど利益が線形に膨張する
2. 集客計算が二乗カーブ（`(orgPop/100)² × 10000`）のため、団体人気が上がると一気にキャパ上限に張り付く
3. 支出に変動要素がなく、収入だけが天井なしに伸びる

### 解決方針
**収入も支出も両方縮小する。** 収支バランス（赤字/黒字の境目）はあまり変えず、利益の絶対額を圧縮する。加えて、会場規模が大きくなるほどチケット単価が下がる「規模逓減」を導入し、後半の利益の伸びにブレーキをかける。

### 結果のイメージ
- 序盤: 赤字度合いはほぼ変わらない（体験を壊さない）
- 中盤: 黒字にはなるが薄利。油断したらすぐ赤字
- 終盤（アリーナ）: 満員維持で薄い黒字。堅実経営
- 大会場・ドーム: **通常興行では基本赤字。勝負カードを揃えた大勝負の時だけ使う**

## §1 チケット単価の逓減（核心の変更）

**現行**: 全会場一律 0.5万/人
**改善**: 会場規模に応じて単価が下がる

| 会場 | キャパ | 現行単価 | **新単価** | 削減率 |
|:-----|------:|--------:|---------:|------:|
| 公民館 | 150人 | 0.50万 | **0.50万** | 0% |
| 小ホール | 400人 | 0.50万 | **0.46万** | -8% |
| 市民会館 | 1,000人 | 0.50万 | **0.40万** | -20% |
| 中ホール | 2,500人 | 0.50万 | **0.33万** | -34% |
| アリーナ | 6,000人 | 0.50万 | **0.26万** | -48% |
| 大会場 | 12,000人 | 0.50万 | **0.20万** | -60% |
| ドーム | 30,000人 | 0.50万 | **0.15万** | -70% |

### 設計根拠
小さい会場はコアファン中心で客単価が高い。大会場になるとライト層が増え、チケット単価を下げないと集客できない。現実のプロレス興行と同じ構造。

### data.js 実装

```javascript
// 現行: const TICKET_PRICE = 0.5;
// ↓ 会場別単価テーブルに変更
const TICKET_PRICE_TABLE = [0.50, 0.46, 0.40, 0.33, 0.26, 0.20, 0.15];
// index: 公民館=0, 小ホール=1, 市民会館=2, 中ホール=3, アリーナ=4, 大会場=5, ドーム=6
```

**大会場・ドーム**: 満員にしても利益率が非常に低い。6〜7割の入りでは赤字になる。これは意図的な設計で、**大会場とドームは「勝負興行」専用の位置づけ**。最高のカードを揃え、Heatを最大にし、タイトルマッチを組んで初めて成立する。通常興行でホイホイ使う会場ではない。

## §6 収支シミュレーション結果

### 2週間あたりの純損益

| フェーズ | 現行 | **改善後** | 利益圧縮 |
|:---------|-----:|--------:|:---------|
| 序盤A（開始直後） | -147万 | **-147万** | 据え置き |
| 序盤B（成長期） | -141万 | **-128万** | やや改善 |
| 中盤A（NEUTRAL） | -127万 | **-98万** | やや改善 |
| 中盤B（WARM） | **+157万** | **+52万** | **67%削減** |
| 中盤C（HOT） | **+226万** | **+87万** | **62%削減** |
| 終盤A（アリーナ） | **+489万** | **+143万** | **71%削減** |
| 終盤B（大会場66%入り） | **+221万** | **-94万** | 赤字化 |
| 覇権級（ドーム40%入り） | -3,793万 | **-1,377万** | 赤字縮小 |

### 読み方

- **序盤**: 赤字度合いが変わらない ← 収支が両方下がっているから
- **中盤WARM**: +157万→+52万。黒字だが薄い。「ギリギリの経営」の緊張感
- **中盤HOT**: +226万→+87万。HOTにしてもこれだけ。金がダブつかない
- **終盤アリーナ**: +489万→+143万。暴利が薄利に。堅実経営の会場
- **終盤大会場**: +221万→-94万。**普通にやったら赤字**。勝負興行専用
- **ドーム**: 両方赤字だが、改善後は支出も縮小されるため赤字幅は減少

## §7 engine.js 変更箇所

### §7.1 calcShowRevenue の変更

```javascript
// 現行
calcShowRevenue(roster, venueIdx, attendance) {
  const rawTicketRev = Math.round(attendance * TICKET_PRICE);
  // ...
}

// 改善後
calcShowRevenue(roster, venueIdx, attendance) {
  const ticketPrice = TICKET_PRICE_TABLE[venueIdx];
  const rawTicketRev = Math.round(attendance * ticketPrice);
  const opCost = Math.round(attendance * VENUE_OP_COST[venueIdx]);
  // ...
  return { ticketRev, goodsRev, venueCost: v.cost, opCost, ... };
}
```

### §7.2 processSettlement の変更

興行支出に変動運営費（opCost）を追加。UI表示にも反映。

```javascript
// 追加
totalExpense += rev.opCost;
if (rev.opCost > 0) {
  details.push({ label: `運営費（${attendance}人×${VENUE_OP_COST[G.showVenue]}万）`,
                 val: -rev.opCost, type: 'expense' });
}
```
