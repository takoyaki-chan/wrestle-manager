## 設計原則

1. **年に一度の4団体全面戦争** — 既存対抗戦（rivalry war）が「日常の抗争（確率発火・2団体）」であるのに対し、4団体勝ち残り対抗戦は「固定開催・4団体総出の祭典」。住み分けで両立する
2. **勝ち抜き戦の本体は消耗** — 「3人抜きした先鋒は満身創痍で大将と戦う」。消耗は固定値ではなく**試合の実ダメージから算出**する（数値は嘘をつかない）
3. **社長の采配は人選と並び順のみ** — 3名を選び、先鋒・中堅・大将の順番を決める。それが社長の手の届く全て
4. **統一王座なしで「団体間の頂点争い」の受け皿になる** — 保留した統一王座構想が担うはずだった年次の団体間決着をここで見せる

### §1.1 チーム勝ち抜きルール

```
先鋒同士でスタート
  → 敗者は脱落、勝者はリングに残り相手チームの次の選手と連戦（消耗持ち越し）
  → チームの3名全員が脱落したら、そのチームの負け
```

- 脱落は**当該チーム戦内のみ**。決勝には3名全員が復帰する（消耗だけ引き継ぐ、§4）
- 引き分け（両者KO等）が起きた場合は両者脱落、次の選手同士で再開 🔧（バトルエンジンの引き分け発生率を実装時確認）

## §3 連戦消耗モジュール（共通機構 — 本スペックが定義元）

同一興行内で連戦が発生するイベント（4団体勝ち残り対抗戦 / 4年に一度PPVトーナメント / 春タッグリーグ）で共用する。**2026-07-17 に B案（実測連動方式）で決定**。

### §3.1 消耗の算出

```
wear = 12 + (1 - hpRatio) × 20        // レンジ 12〜32
hpRatio = 勝者の試合終了時 残HP ÷ 開始HP
```

- 秒殺した選手はほぼ無傷（12前後）で次へ、死闘を生き延びた選手はボロボロ（30前後）で次へ
- シミュレーションの実ダメージが次の試合のドラマを作る

### §3.2 次戦コンディション

```
次戦 condition = clamp(前戦 condition - wear + recovery, floor, 80)
```

| イベント | 初期 | 試合間 recovery | チーム戦/ラウンド間 recovery | floor |
|---------|:----:|:---------------:|:---------------------------:|:-----:|
| 4団体勝ち残り対抗戦 | 80 | **0**（フォール間は回復なし） | +15（準決→決勝） | 40 |
| 4年に一度PPVトーナメント | 80 | — | wear累計の 2/3 回復 | 50 🔧 |
| 春タッグリーグ | 80 | wear の 1/2 回復 | 同左（決勝含む） | 40 |

- 4団体勝ち残り対抗戦だけ回復なし: 消耗こそが勝ち抜き戦の本体。3人抜きは満身創痍であるべき
- PPVトーナメントは回復高め: 年間最高峰の決勝が低コンディションの凡戦になるのを防ぐ

### §3.3 実装ノート

- イベント試合は既存準拠で **roster 本体の condition に影響しない**（`resolveEventMatch` が `{...fighter, condition: X}` のコピーで戦う）。消耗はイベント内限定の概念
- 怪我なし（イベント試合準拠）
- `MATCH_TIER = 1`。各フォールは通常試合ルールと `ENG` の通常HP基準で開始HPを作る。大一番ルール／`BIGMATCH_ENG` は使わない。
- 消耗式、初期80、floor 40、準決勝→決勝の回復+15はtier変更後も据え置く。
- `simulateMatch` の残HP比からwearを計算する。観戦時だけ `recordFrames` を要求し、framesはGameStateへ保存しない。

## §4 決勝

| 項目 | 仕様 |
|------|------|
| 出場 | **3名全員が復帰**（準決勝の脱落は当該チーム戦内のみ） |
| 消耗 | 準決勝で戦った選手は消耗を持ち越し（+15回復後） |
| 並び順 | 両チームとも組み直し可。プレイヤーは消耗表示を見て再編成 |
| 配置 | 興行のメイン（準決勝2試合 → 決勝） |

準決勝を3人抜きで勝ったチームはエースが消耗した状態で決勝へ — 「楽に勝ち上がったチームが有利」という自然な力学が生まれる。

### §6.1 進行UI

- `#showResultOverlay` は使わず、専用の `#autumnWarOverlay` / `#autumnWarScreen` で全phaseを描画する。`data-phase` は `intro / entry / board / reorder / result / mvp`。
- Week 36開始後は大会終了までグローバルChromeを覆い、Officeへ戻る導線を持たない。
- **採用ハイブリッド**: 現在対戦中の2団体・計6名を全身画像で中央対面表示し、案2の小型クライムラインを勝ち上がり補助、4団体全体は小型ステータスレールで表示する
- **編成**: Desktopは同サイズのフル画像3名を先鋒・大将が前、中堅が背後上の三角配置。人物画像はクリックを受けず、自団体側の人物直下・右半分内に独立した役割ボタン3つを置く。相手側の直下は文字なし空欄3枠。375pxはL1縦カード。候補棚はスタンド画像の横スクロール。相手の平均OVR・OVR幅を両方で表示する。
- OVR数値は選手データベース共通の閾値色を使い、主要な選手画像・名前から選手詳細を開ける。
- **戦況ボード**: プレイヤー参加戦は相手団体を左、自団体を右に固定し、左側画像だけを反転して中央へ向き合わせる。6名の役割・名前・RING/WAIT/OUTと、現在フォールの2名・コンディションを表示する
- フォールごとに結果を逐次表示、勝ち残り選手の連戦を強調
- 大会開始時に全結果を作らない。「結果を見る」ごとにリング上の2名だけをシミュレートし、勝敗・消耗・脱落・勝ち抜き数・RNG状態を保存する
- 「観戦する」も同じ逐次関数を1回だけ呼び、その確定結果とframesをバトル画面へ渡す。観戦完了／中断時に再シミュレートせず、保存済みの1フォールを戦況ボードへ表示する。
- 「まとめてスキップ」は確認を挟み、現在の団体戦の残りだけを同じ `simulateNextBout` で1フォールずつ決着まで進める。大会全体や次カードは自動進行せず、団体戦決着画面で止める。観戦／1試合結果／まとめてスキップの3ボタンは同寸にする。
- プレイヤー決勝進出時は、準決勝後の回復状態を確認して3名を再配置する。決勝カードは布陣確定後に初めて生成し、準決勝の再計算は行わない
- 3人抜き達成時は特別演出（新聞見出し・ティッカー）
- 各フォール開始前は55%で両選手の掛け合いを表示する。準決勝は既存大会の `preMatch`、決勝は `preFinal` の personality × archetype 文面を使う
- 各フォール結果は60%で勝ち残った選手の一言を表示する。文面は `postMatchWin` の personality × archetype から解決する
- 優勝結果は75%で優勝チーム代表の一言を表示する。代表は優勝3名の最多勝ち抜き選手（同数はID順）とし、秋大会 `champion` 文脈の personality × archetype 文面を使う
- セリフ有無と文面は大会・フォール・選手IDから作るローカルseedで決定し、GameStateの大会RNGを消費せず、再読込や再描画でも変化させない
- 優勝結果の後にMVP選手だけを映す一言シーンを表示。台詞は結果文脈（3人抜き / 優勝 / 敗退）× personality × archetype で解決する

## §7 既存対抗戦（rivalry war）との整理

| 項目 | 既存対抗戦 | 4団体勝ち残り対抗戦 |
|------|-----------|--------|
| 発火 | 確率（シーズン55%+干ばつ補正） | 毎年固定 |
| 相手 | 隣接ランク1団体 | 全4団体 |
| 形式 | 3〜7試合全消化・勝ち越し判定 | 勝ち抜き（イリミネーション） |
| 位置付け | 日常の抗争 | 年次の祭典 |

- 既存対抗戦は**存続**（役割が異なる）
- **要変更**: `checkRivalryWar` のチェック窓 W12/24/36 → **W10/22/34 に移動** 🔧（春リーグW12・4団体勝ち残り対抗戦W36 との同週衝突回避。W24ジュニアとの現状の同居挙動も実装時に確認）
