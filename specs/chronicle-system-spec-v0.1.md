## 1. 背景と目的

### 1.1 動機

長期プレイにおいて、トップに届かなかった選手や世代が記録として残らない問題がある。現状のシステムでは：

- **HoF（殿堂入り）**：個人の頂点を讃える場。ハードルが高く、OVR・タイトル戴冠が基準を超えた選手しか入れない。
- **careerHighlights / エピテット**：HoF入り選手の中での輝きを記録するもの。HoF入りしなかった選手には適用されない。
- **`retiredFighters`**：引退選手データを保持するが、リサイクル対象でやがて消える。

つまり、「団体のエースとして時代を背負ったが、レジェンドの一歩手前で終わった選手」「人気で観客を支えたが OVR は伸びなかった選手」が、引退後しばらくすると団体史から消えてしまう。

### 1.2 設計コンセプト：「届かなかった世代の物語を残す」

ウイニングポストの血統が「数値が伸びなかった馬も、確かに後に何かを残した」という余韻を生むように、本システムは「届かなかった世代も、確かに団体に何かを残した」という記録を提供する。

- **HoF が個人の頂点を讃える場**であるのに対し、**年代記は世代の物語を残す場**である。
- 全世代が等しく章を持つ。届いた世代も届かなかった世代も同じ扱いで記録される。
- 数値ではなく、読み返せる物語として残る。

### 1.3 設計原則

1. **気持ちの問題が主、メカニクスは従**。年代記は「感じるためのもの」であって、「使うためのもの」ではない。
2. **数値は見せない**。気風（伝統値）は内部で動くが、UI には数値として一切露出しない。
3. **ゲームバランスを動かさない**。気風の効果はハードキャップで保護され、最適化対象にならない。
4. **記録は消えない**。気風の積算は永遠に止まらない。事実としての痕跡が残り続けることが本質。
5. **HoF と棲み分ける**。年代記は HoF を補完するものであって、置き換えるものではない。

## 2. 全体像

### 2.1 構成要素

年代記は3つの要素で構成される：

| 要素 | 役割 | 永続性 |
|---|---|---|
| **章（Chapter）** | 世代ごとの物語の単位。エース・同期・主な出来事を含む | 表示時に再計算（後述） |
| **気風（Tradition Spirit）** | 引退選手が団体に残す伝統値。スタイル軸に沿った蓄積 | 永続（GameStateに保存） |
| **章末フレーバー** | 各章の末尾に表示される一行。気風の方向を自然な日本語で描写 | 章生成時に算出 |

### 2.2 既存システムとの関係

```
[careerRecord.history] ──┬──→ [HoF: 個人の頂点を讃える]
                         │
                         └──→ [年代記: 世代の物語を残す] ←─ [G.chronicle.spirit: 永続的な気風]
                                       │
                                       ↓
                              [新人生成時に薄く影響]
```

`careerRecord.history` は本システムのデータソースとして既に十分な情報を持つ。気風データのみ追加で永続化する。

### 3.3 注意：retiredFighters のリサイクル問題

**要確認事項**：現状のコードで `G.retiredFighters` が時限消去される条件と、消去前に必要なデータが他に保存されているかを確認すること。

仮に `retiredFighters` が消える設計であっても、HoF入りした選手は `G.allHallOfFame` に永続保存されているため、HoF入り選手の章生成は問題なく可能。問題になるのは「HoF未入り の引退選手」。これらの選手の peakOVR / peakPopularity / careerRecord を `G.chronicle.fighterArchive` に最小限スナップショットとして保存する仕組みを実装する。

スナップショット作成タイミング：選手が引退処理される瞬間（`Engine.career.addEvent` で `type: 'retire'` が呼ばれる箇所）に、HoF入り判定とは独立に `fighterArchive` への登録を行う。

## 4. 章の自動生成ロジック

### 4.1 基本方針：再計算ベース

章は永続データではなく、**毎回 `fighterArchive` + `roster` から再計算される**。これにより：

- アルゴリズムの改善があれば、再計算するだけで既存セーブにも反映できる
- 「現在進行形の章」が自然に最新状態を反映する
- データ構造のバージョン管理が不要

ただし計算コストを抑えるため、確定済み章はキャッシュする（後述）。

### 4.2 章境界の決定アルゴリズム

#### Step 1: 候補選手の収集

団体に在籍した経験のある全選手を、以下の条件で集める：

- 現役ロスター（`G.roster`）
- HoF入り選手（`G.allHallOfFame.player`）
- HoF未入り引退選手（`G.chronicle.fighterArchive` のうち team が player のもの）

#### Step 2: 各選手の英雄値（hero score）算出

```
英雄値 = peakOVR_normalized * 0.6 + peakPopularity_normalized * 0.4

peakOVR_normalized      = peakOVR / 100
peakPopularity_normalized = peakPopularity / 100
```

OVR の重みをやや高めに設定（0.6:0.4）。これは「実力派寄りの選定」を基本とするための初期設定。**要チューニング**。

#### Step 3: ピーク年表の作成

各選手の `peakOVRSeason` をシーズン軸にプロットして、ピーク密度のヒストグラムを作る。

#### Step 4: 谷間検出による章境界

ヒストグラム上で「ピークが集中している区間」と「次に集中している区間」の **間の谷間**で境界を引く。具体的には：

- 推奨章長は **5〜7シーズン**
- ただし、章内にエース級候補（英雄値上位）の peak season が含まれていれば、**境界を強制せずに章を伸ばす**
- 連続したピーク群の谷間（前後N章のピーク密度が一定値以下のシーズン）に境界を置く
- 「ピーク真ん中で章が切れる」ことが構造的に起きない

#### Step 5: 候補不足時の処理

- 章期間内のエース級候補が **0名** → 章を作らない（団体成立前 or 空白期）
- **1名** → 「孤高のエース」として1名のみで章を作る
- **2名** → 2名構成で章を作る
- **3名以上** → 通常の選定ロジックへ

### 4.3 エース・同期の選定

#### エース（章の代表、1名）

英雄値が最大の選手を章のエースとする。

ただし、以下の場合は **2枚看板** として2名を章のエースに昇格：

- トップ2名の英雄値差が **0.04以下**（≒ peakOVR換算で約4以内）
- かつ両者のキャリア期間が章期間内で大きく重なる

2枚看板の場合、章カードの大ポートレートを2つ並べる構成になる（要UIモック）。

#### 同期（副官、原則4名）

エースに選ばれなかった候補から、英雄値順に選ぶ。

**人気派枠の特別処理**：

1. まず英雄値順で実力派3名を選ぶ（peakOVR上位優先）
2. 次に「人気派候補」を探す：
   - 上記3名に含まれていない選手のうち
   - **peakPopularity ≥ 80**
   - 章期間と十分にキャリアが重なる
   - その中で peakPopularity が最も高い1名
3. 人気派候補が見つかれば → **実力派3 + 人気派1 = 4名**
4. 見つからなければ → **実力派4名**

人気派閾値 80 は **要チューニング**。

候補不足時：

- 同期候補が3名しかいない → 3名で章を作る
- 2名 → 2名
- 0名 → 章のエースのみで章を作る（極小章）

### 4.4 章の自動命名

#### タイトル：「{苗字}世代」

エースの苗字を取る。2枚看板の場合は「{苗字A}・{苗字B}世代」。

#### サブタイトル：戦績テンプレート選択

章の特徴を判定して、テンプレ群から1つ選ぶ：

| 条件 | サブタイトル候補 |
|---|---|
| ピークOVR ≥ 95 + タイトル戴冠 ≥ 3 | 「黄金の刻」「絶対の時代」 |
| ピークOVR ≥ 90 + 対S級勝率 < 0.2 | **「届かなかった頂」**「壁の前で」 |
| ピークOVR ≥ 85 + **対S級団体勝利 ≥ 1** | 「挑戦の章」「気鋭の時代」 |
| ピークOVR < 85 + 在籍長期 | 「雌伏の時」「静かなる継承」 |
| 初期団体（章番号1-2） | 「黎明」「礎を築く者たち」 |
| 人気派エースが章のエース | 「華やかなる時代」 |
| その他 | 「{苗字}の章」 |

サブタイトル決定後、ランダム要素は加えない（同じセーブで開き直しても同じ章タイトルになる）。サブタイトルテンプレは **要拡充**。

### 4.5 章のステータス（確定 / 進行中）

#### 進行中（in_progress）

以下のいずれかに該当する章：

- 章のエース or 同期に、現役ロスターの選手が含まれている
- 章のエース or 同期の引退から **3シーズン以内**

進行中の章は、年代記を開くたびに再計算される。タイトル・サブタイトル・同期構成・章末フレーバーが変動する可能性がある。章扉に「進行中の章」と明示する。

#### 確定（confirmed）

含まれる全選手が引退して 3シーズン以上経過した章。**キャッシュに保存**され、以降は再計算されない（手動再構築ボタンで強制再計算は可能）。

### 4.6 手動再構築

年代記タブに「年代記を再構築」ボタンを設置。押すと `chaptersCache` を破棄して全章をゼロから再生成する。

利用シーン：

- アルゴリズムが改善された後、既存セーブで反映したい
- プレイヤーが「この章の切り方は違う」と思ったとき
- デバッグ時

## 5. 気風システム（伝統値の積算）

### 5.1 軸の定義

5軸固定。スタイルとの対応は以下：

| 内部キー | 表示語 | 対応スタイル |
|---|---|---|
| `striker` | 打撃 | Striker |
| `grappler` | 組技 | Grappler |
| `submission` | 関節技 | Submission |
| `brawler` | 喧嘩 | Brawler |
| `allround` | 万能 | Allround |

タグ名（「剛なる気風」など）は **使わない**。フレーバー文では普通の語をそのまま使う。

### 5.2 1人あたりの寄与計算

引退選手1人が `G.chronicle.spirit` に寄与する値：

```javascript
function calcSpiritContribution(fighter) {
  const seasons = fighter.careerSeasonsEnd - fighter.careerSeasonsStart + 1;
  const peakOVR = fighter.peakOVR || 0;

  // 基礎寄与: 0.05〜0.20 の極小値
  let base = 0;
  if (seasons >= 3 && peakOVR >= 70) base = 0.05;        // 在籍だけしてた選手
  if (seasons >= 5 && peakOVR >= 75) base = 0.08;        // 戦力だった選手
  if (seasons >= 5 && peakOVR >= 80) base = 0.12;        // 主力だった選手
  if (seasons >= 7 && peakOVR >= 85) base = 0.16;        // エース格だった選手
  if (seasons >= 7 && peakOVR >= 90) base = 0.20;        // 一時代を築いた選手

  // 戴冠による微増
  const titleBonus = (fighter.titleReigns || 0) * 0.02;

  return base + titleBonus;  // 最大でも 0.3 程度
}
```

数値は **要チューニング**。原則：1人あたり 0.05〜0.30 に収める。

### 5.3 適用先と圧縮

積算された生の `spirit` 値は、**新人生成時の potential（pot）への補正値** に変換される。

```javascript
function calcPotBonus(spiritValue) {
  // log圧縮: 大きく積んでもなだらかにしか効かない
  const compressed = Math.log(spiritValue + 1) * 1.8;

  // ハードキャップ: 絶対に超えない天井
  return Math.min(compressed, 5.0);
}
```

#### 想定される到達カーブ

| 累計 spirit 値 | 補正値 | プレイ年数の目安 |
|---|---|---|
| 1.0 | +1.25 | 5世代程度 |
| 2.5 | +2.25 | 10〜15世代程度 |
| 5.0 | +3.22 | 20〜25世代程度 |
| 10.0 | +4.32 | 35〜40世代程度 |
| 20.0 | +5.00（キャップ） | 通常プレイでは到達しない |

**40世代プレイしても +3 台に届くか届かないか**、というカーブを目指す。+5 への到達は実質的に防衛ライン。

### 5.4 新人生成への適用

新人が生成されるタイミング（ドラフト・FA・スカウトなど、player団体に加入する場合）で、その新人のスタイルに対応する spirit 軸の補正を pot に薄く加算する。

```javascript
// 例：新人が Striker スタイルだった場合
const bonus = calcPotBonus(G.chronicle.spirit.striker);
newFighter.pot.pw += Math.round(bonus * 0.6);  // pwに優先配分
newFighter.pot.sp += Math.round(bonus * 0.4);  // spにも一部
```

スタイル軸ごとの配分マッピングは別途定義する（**要設計**）。配分後の値は最大でも **+5 / 軸**。

#### 重要：プレイヤーには見せない

- 新人プロフィールに「気風補正 +X」のような表示は **しない**
- 新人加入時の新聞記事に「気風が薄く乗った」のようなフレーバーを **出さない**
- 数値はコードの中にのみ存在する
- プレイヤーが体験する形は唯一、**章末フレーバーの一行**だけ

### 5.5 章末フレーバーの生成

章生成時、その章に含まれる選手たちが積んだ spirit 寄与を集計し、軸別の寄与量から章末フレーバーを決定する。

```javascript
function generateChapterClosing(chapter, contributionsByAxis) {
  // 最も寄与した軸を選ぶ
  const topAxis = findTopAxis(contributionsByAxis);
  const magnitude = classifyMagnitude(contributionsByAxis[topAxis]);

  const axisLabel = AXIS_LABELS[topAxis];  // 'striker' → '打撃'

  if (magnitude === 'slight') {
    return `この世代は、${G.orgName}の流儀をわずかに ${axisLabel} へと寄せた。`;
  } else if (magnitude === 'moderate') {
    return `この世代は、${G.orgName}に ${axisLabel} の色を残していった。`;
  } else { // strong
    return `${G.orgName}は、この世代を経て ${axisLabel} の色がはっきりと濃くなった。`;
  }
}
```

magnitude 判定の閾値は **要チューニング**。フレーバー文も **要拡充**（同じ章を読み返したときに飽きないよう、複数バリエーション）。

#### 例外：寄与が極小の章

その章の総寄与が一定値以下（例: 0.1未満）の場合、章末フレーバー自体を出さない。または「目立った気風は残さなかった」のような中立文を出す。**要検討**。

## 6. UI 仕様

### 6.1 配置

データベースタブに新サブタブ「**年代記**」を追加：

```
[全選手] [全コーチ] [団体比較] [殿堂] [年代記] [相関図] [新聞]
                                  ↑ 新規
```

`_dbSubTab` 列挙値の追加と、対応するレンダリング関数 `_renderDbChronicle()` を実装する。

### 6.2 章カードのレイアウト

確定済みモックアップ：`docs/archive/mockups/chronicle-mockup-chapter-v5.html`

主要セクション（上から）：

1. **Meta top**：`CHRONICLE | {団体名} 団体年代記 | {章番号} / {総章数}`
2. **Timeline strip**：全章を点で並べた水平タイムライン。現在章がハイライト
3. **Chapter opener**：章番号 + タイトル + サブタイトル + 期間
4. **エース feature**：大ポートレート + 名前 + meta（peak OVR / style / seasons / titles）+ 記者コメント
5. **二段組本文**：
   - 左：この時代の主な出来事（careerRecord.historyから抽出）
   - 右：この時代の同期4名 + この時代の通算スタッツ
6. **章末フレーバー**：気風行（中央配置、控えめなオーナメント）
7. **章ナビ**：前章 / 次章ボタン

### 6.3 同期欄の人気派表現

人気派として選ばれた選手の同期カードは：

- ピンク〜マゼンタ系のアクセント色（`#b03366`）
- 薄いピンク背景 + 左端カラーバー
- ポートレートもピンク系グラデ
- 名前の上に **★ IDOL OF THE ERA** ラベル
- メタ情報には特性（華・ファンサービスなど）を優先表示

### 6.4 進行中章の表示

進行中ステータスの章は、章扉に **「進行中の章」** バッジを表示する（具体デザインは別途モック）。「この章はまだ書きかけです」が伝わる控えめな表示。

### 6.5 章カードのナビゲーション

- 前章 / 次章ボタンで章間を移動
- タイムラインの点を直接クリックして任意章に飛ぶ
- 同期欄の選手名をクリック → その選手のプロフィール（HoF入りしていれば HoF 詳細、現役なら roster 詳細）

### 6.6 空状態（章が0件のとき）

団体結成直後など、章生成条件を満たすデータがまだない場合の表示：

> 月光女子プロレスの歴史は、まだ始まったばかりです。
> エース級の選手が引退し、ひとつの世代が終わったとき、ここに最初の章が刻まれます。

## 7. 既存システム連携

### 7.1 careerRecord.history の参照

章の `highlights` セクションは `careerRecord.history` を参照して構築する。各イベントタイプのアイコン・色分けは既存の `_getHighlightIcon()` を流用する。

### 7.2 HoF タブとの相互リンク

- 章カードのエース・同期がHoF入りしている場合、その選手名にバッジを表示し、クリックでHoF詳細にジャンプ
- HoF詳細モーダルから「この選手が登場する章を開く」ボタンを追加

### 7.3 引退処理への組み込み

`Engine.career.addEvent({ type: 'retire' })` が呼ばれる箇所（`src/app.js` 内の複数箇所）で、追加処理として：

```javascript
if (fighter.team === 'player') {
  G = Engine.chronicle.archiveFighter(G, fighter);
  G = Engine.chronicle.applySpiritContribution(G, fighter);
}
```

を実行する。これにより、

1. `fighterArchive` に最小限スナップショットが保存される
2. spirit 値が更新される

両処理は HoF 入り判定とは独立。

## 8. マイグレーション

### 8.1 既存セーブへの遡及生成

既存セーブで本システムを初めて起動するとき、以下を一括実行する：

1. `G.chronicle = { spirit: {...0}, chaptersCache: {...}, fighterArchive: [] }` を初期化
2. `G.allHallOfFame.player` の全エントリを `fighterArchive` に変換して登録
3. `G.retiredFighters` のうち player 所属のものを `fighterArchive` に変換して登録（存在すれば）
4. 各 archive 選手について `applySpiritContribution()` を実行 → spirit 値を遡及積算
5. 章生成を初回実行（`forceRebuild: true`）
6. マイグレーション完了フラグを立てる

これにより、20シーズン経過の既存セーブを開いた瞬間に、過去20シーズンの全世代が章として一気に立ち上がる。

### 8.2 マイグレーションフラグ

```javascript
G._migrated_chronicle_v1 = true;
```

を立てて二重実行を防ぐ。

## 11. 仕様の核

最後に、本システムが守るべき根本原則を改めて記す：

> **年代記は、感じるためにあって、使うためにはない。**
>
> 数値は内部で動くが、プレイヤーには気配としてしか伝わらない。
> ゲームバランスは決して動かない。
> しかし、過去の世代が積み上げた事実は、永遠に消えない。
>
> 届かなかった世代も、人気で支えた選手も、ここに記される。
> それが「無駄じゃなかった感」の正体である。
