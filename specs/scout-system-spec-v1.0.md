## 設計原則

1. **年2回のビッグイベント** — スカウトは年2回。日常ではなく「ドラフト会議」的な特別感
2. **目利きの面白さ** — 情報は不完全。潜在値もtrainCapも見えない。「この子は化けるかも」の直感と賭け
3. **C方式の契約金** — 即戦力度（現在値）と才能度（潜在値）の複合評価。安い原石 vs 高い即戦力のトレードオフ
4. **競合がドラマを生む** — 逸材ほど他団体も狙ってくる。資金を積むか、諦めるか
5. **ライフサイクルの循環** — 入団→育成→全盛期→衰退→引退→次世代スカウト。世代交代がゲームのリズム

### §3.2 Notion値の生成

候補者は既存80名とは別に新規生成される。

```javascript
function generateScoutCandidate() {
  // 全パラ平均の目標帯をまず決める
  let tierRoll = random()
  let avgTarget
  if (tierRoll < 0.05)       avgTarget = randomRange(75, 90)   // 逸材（5%）
  else if (tierRoll < 0.25)  avgTarget = randomRange(60, 74)   // 有望（20%）
  else if (tierRoll < 0.70)  avgTarget = randomRange(45, 59)   // 普通（45%）
  else                        avgTarget = randomRange(25, 44)   // 素材（30%）

  // 5パラメータをavgTarget周辺でランダム生成
  for (each param in [PWR, SPD, TEC, STA, MNT]) {
    notionValue[param] = clamp(avgTarget + randomRange(-15, 15), 11, 95)  🔧
  }

  return notionValue
}
```

**ティア分布の設計意図**:
- 既存80名の平均Notion値が約64（合計319.9）
- スカウト候補は「普通」（平均45〜59）が最多 → 既存選手よりやや低め
- 逸材（平均75〜90）は年間で0〜1名程度しか出ない

### §3.3 潜在値の算出

既存の公式をそのまま適用（character-data-spec §2.2 準拠）:

```
潜在値 = min(185, round(Notion値 × 1.3 + 60))
```

## §5 契約交渉

### §5.1 契約金の算出（C方式：複合評価）

即戦力度（現在値）と才能度（潜在値）の両方を評価して契約金を決定。economy-system-spec §5.1 のテーブルと整合。

```javascript
function calcContractCost(candidate) {
  let currentTotal = sum(candidate.startValues)    // 入団時の現在値5パラ合計
  let potentialTotal = sum(candidate.potential)     // 潜在値合計（NPC側は把握している前提）

  let baseCost
  if (potentialTotal >= 750 || currentTotal >= 300) {
    baseCost = randomRange(200, 300)  // 逸材帯
  } else if (potentialTotal >= 650 || currentTotal >= 220) {
    baseCost = randomRange(100, 200)  // 有望/即戦力帯
  } else {
    baseCost = randomRange(50, 100)   // 原石帯
  }

  return baseCost  // 万円
}
```

| 候補ランク | 契約金（万）🔧 | 判断基準 | economy-spec対応 |
|:---------:|:------------:|---------|:---------------:|
| 原石 | 50〜100 | 潜在値合計 < 650 かつ 現在値合計 < 220 | §5.1 原石 |
| 有望/即戦力 | 100〜200 | 潜在値合計 650〜749 または 現在値合計 220〜299 | §5.1 即戦力 |
| 逸材 | 200〜300 | 潜在値合計 750以上 または 現在値合計 300以上 | §5.1 逸材 |

**設計意図**:
- 「今は弱いが潜在値が高い原石」→ 有望/逸材帯の契約金。NPC団体は才能を見抜いている
- 「現在値は高いが潜在値は普通」→ 即戦力として有望帯。確実に戦力になるが天井は低い
- プレイヤーには潜在値が見えないので、「なぜこの子がこんなに高いんだ？」→ 才能が隠れているサイン

### §5.2 他団体との競合

| 候補ランク | 競合発生率 🔧 | 競合時の追加コスト倍率 🔧 |
|:---------:|:----------:|:--------------------:|
| 逸材 | 80% | ×1.5 |
| 有望/即戦力 | 40% | ×1.2 |
| 原石 | 10% | ×1.1 |

```javascript
function resolveCompetition(candidate, playerBid) {
  let competitionRate = COMPETITION_TABLE[candidate.rank]

  if (random() >= competitionRate) {
    // 競合なし → 通常契約金で獲得
    return { result: "success", cost: candidate.baseCost }
  }

  // 競合発生
  let additionalCost = round(candidate.baseCost × ADDITIONAL_MULTIPLIER[candidate.rank])

  // プレイヤーに選択肢を提示
  // A) 追加コストを払って確定獲得
  // B) 通常額のまま勝負 → 50%で競り負け 🔧
  // C) 諦める
}
```

**競り負けた場合の候補の行方**:

| 行き先 | 確率 🔧 | 結果 |
|-------|:------:|------|
| 他団体に加入 | 70% | 以後その団体の選手として登場（⑨ライバル団体AIで使用） |
| フリー選手プールに追加 | 30% | 後日フリー出場 or 正式契約で再チャンスあり |

### §5.3 獲得上限

| 回 | 最大獲得数 🔧 |
|:--:|:----------:|
| 第1回（オフ） | 3名 |
| 第2回（Q3） | 2名 |
| 年間合計 | 最大5名 |

**設計意図**: ロスターが膨らみすぎると給与負担（economy-spec §1）で経営が圧迫される。自然なブレーキ。

## §6 入団処理

### §6.1 入団時の値

training-system-spec §1.3 の公式をそのまま適用。

```javascript
function getStartValue(notionValue, entryAge) {
  let startRatio
  if (entryAge <= 18)      startRatio = 0.40 + random(0, 0.30)  // 若手: 0.40〜0.70
  else if (entryAge <= 20)  startRatio = 0.50 + random(0, 0.25)  // 中堅: 0.50〜0.75
  else                      startRatio = 0.75 + random(0, 0.10)  // ベテラン: 0.75〜0.85

  // MNTはNotion値をそのまま使用（年齢補正なし）
  return (param === 'mn') ? notionValue : round(notionValue × startRatio)
}
```

**入団年齢16歳への対応**: 最若年は16歳。startRatioの下限が0.40と低いため、16歳入団は現在値が非常に低い＝最も長期育成が必要な投資。上限0.70はランダム幅が広く、当たり外れが大きい。

### §6.2 trainCapの生成

入団確定時にtrainCapを生成（training-system-spec §1.4 準拠）。

```javascript
function generateTrainCap(notionValue, potential) {
  let factor = randomRange(0.10, 0.50)  🔧
  let cap = notionValue + round(factor × (potential - notionValue))
  return cap
}
```

### §6.3 MNTの扱い

training-system-spec §1.6 準拠。MNTはNotion値がそのまま初期値（年齢補正なし）。

### §6.4 給与の適用

入団と同時にeconomy-system-spec §1 の給与テーブルが適用される。

```
新人のOverall = 入団時5パラ平均
→ ほぼ全員がOverall〜49帯 = 週給8万
```

### §6.5 デフォルトスケジュール

入団時は「バランス」パターンが自動設定される（weekly-gameloop-spec §3.2 準拠）。

### §7.2 年齢引退の確率

```javascript
function checkRetirement(fighter) {
  if (fighter.age < 35) return false

  let retireChance
  switch (fighter.age) {
    case 35: retireChance = 0.30; break  🔧
    case 36: retireChance = 0.50; break  🔧
    case 37: retireChance = 0.75; break  🔧
    case 38: retireChance = 0.90; break  🔧
    default: return true  // 39歳以上は確定引退
  }

  // 後遺症があると引退確率UP
  retireChance += fighter.afterEffects.length × 0.10  🔧

  return random() < retireChance
}
```

### §7.5 自主引退の詳細

```javascript
function checkVoluntaryRetirement(fighter) {
  let notionOverall = sum(fighter.notionValues) / 5
  let currentOverall = sum(fighter.currentValues) / 5

  if (currentOverall < notionOverall × 0.60) {  🔧
    fighter.lowPerformanceSeasons += 1
  } else {
    fighter.lowPerformanceSeasons = 0
  }

  if (fighter.lowPerformanceSeasons >= 2) {  🔧
    // 自主引退を申し出る
    return true
  }
  return false
}
```

**設計意図**: 衰退で大幅に弱体化した選手が自動的に引退する仕組み。プレイヤーが引退させ忘れてロスターを圧迫するのを防ぐ。

| 1 | 開催時期 | 年2回。オフシーズン第2週 + Q3第5週 |
| 2 | 候補人数 | 第1回8〜10名、第2回4〜6名 |
| 3 | 年齢分布 | 16〜17歳が最多（40%）、20歳はレア（15%） |

| 5 | 潜在値 | 既存公式（min(185, round(Notion値×1.3+60))）準拠 |

| 7 | 契約金 | C方式（現在値＋潜在値の複合評価）。economy-spec §5.1 整合 |
| 8 | 競合 | 逸材80%、有望40%、原石10%。追加コストで確定獲得 or 50%勝負 |
| 9 | 獲得上限 | 第1回3名、第2回2名、年間最大5名 |
| 10 | 引退条件 | 年齢（35歳〜確率判定、39歳確定）/ 後遺症3個 / 自主（低パフォ2季） |
| 11 | 引き留め | 1選手1回のみ。成功率50% |
| 12 | フリー選手 | いつでも正式契約可。同じ契約金算出式。競合なし |
