## 設計原則

1. **春は始動のシーズン** — タッグ編成という新しい戦略軸でシーズンの幕開けを飾る
2. **ケミストリーを育てる動機** — bond/rivalry/タッグ経験がゲームに直結する唯一の公式大会
3. **リーグ戦でタッグの醍醐味を引き出す** — 同じチームが複数試合を戦うことで、ケミストリー・疲労蓄積・チームの成長/消耗が自然に可視化される
4. **トーナメントとの差別化** — 夏(ジュニア)/秋(統一王座挑戦)がトーナメントである以上、春はリーグ戦にすることで年間イベントの形式バラけを確保
5. **一夜限りの祭典** — 年1回、優勝チームは称号「総合ベストタッグ」を1年間保持
6. **4団体頂点対決** — 各団体のエースタッグが集結する頂点リーグ

## §3 リーグ戦

### §3.1 勝ち点制 🔧

| 結果 | 勝ち点 |
|------|:------:|
| 勝ち | **3点** |
| 引き分け | **1点** |
| 負け | **0点** |
| **MQ60+ ボーナス** | **+1点**（勝敗問わず、接戦・名勝負加点） |

MQボーナスは「負けたけど内容が良かった」試合を報い、消化試合の発生を抑える。

### §3.2 対戦組み合わせ

4チーム総当たり = 6試合。試合順はシード順に自動決定：

```
第1試合: A vs B
第2試合: C vs D
第3試合: A vs C
第4試合: B vs D
第5試合: A vs D
第6試合: B vs C
  ↓ リーグ戦終了、順位確定
第7試合（決勝）: リーグ1位 vs リーグ2位
```

### §3.3 タイブレーカー

リーグ戦で勝ち点同数の場合、以下の順で順位決定：

1. 直接対決の勝者
2. 合計MQの高い方
3. ランダム（決定論的シード）

## §5 試合処理

### §5.1 試合条件

| 項目 | 仕様案 |
|------|------|
| condition初期値 | 80固定（PPV準拠） 🔧 |
| matchTier | 2（ビッグマッチ） |
| エンジン | タッグマッチエンジン（tag-match-system-spec準拠） |
| 怪我 | なし（condition固定のため） |

### §5.2 試合間コンディション

**リーグ戦ならではの疲労蓄積を活かす** 🔧:

| 処理 | 値 |
|------|---|
| 試合ごと消耗 | -20 |
| 試合ごと回復 | +10 |
| 実質 | -10/試合の蓄積ダメージ |

決勝進出チームは3試合（リーグ2 + 決勝）を戦うため、決勝では60前後のコンディションになる。スタミナ・MNTの真価が問われる設計。

### §5.3 ケミストリー

- 同じチームが複数試合を戦う → タッグ経験値が蓄積 → 終盤にかけてケミストリー向上
- bond高ペアは後半戦で有利、初対決ペアは前半がピーク
- リーグ戦フォーマットがタッグ戦ならではの「成長/消耗」を可視化する

## §11 トーナメント案(v0.1 旧案)からの変更点

初版v0.1は「8チームシングルエリミネーション」で設計していたが、以下の理由でリーグ方式に変更：

1. **年間4イベントのうち3つがトーナメントになるワンパターン回避**（夏ジュニア・秋統一王座挑戦がトーナメントのため）
2. **タッグの醍醐味「ケミストリー」が複数試合で自然に表現される**
3. **リーグ表の推移という独自のドラマ要素**がトーナメントにはない視覚的魅力
4. **消化試合回避のMQボーナス制**がプレイヤーの戦略性を増す
5. **実装上ジュニアトーナメントのブラケット処理は流用しにくいが、順位表処理は新規実装の必要あり**（副作用）
