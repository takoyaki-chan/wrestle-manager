# 技選択ロジック再設計 v0.1

> 作成: 2026-07-20
> ステータス: **実装完了・較正済み（2026-07-20）**。確定パラメータは **§3.5** を参照（本文の各節は設計意図と経緯の記録）。残作業はタッグの較正のみ（§13）
> 対象: `Engine.battle.selMove`（`src/match-engine.js`）/ `PHASES`・`catW`・技プール（`src/data.js`）

---

## 1. 背景と問題

### 1.1 症状

試合終盤でも地味な小技が出て、そのまま決着技になることが多い。タイトルマッチのクライマックスで「ストンピング」が決め手になる。

### 1.2 原因

現行の `selMove` は2つのプールを確率で切り替えている。

```js
const use  = rng < ph.sCh;                    // Climax なら 70
const pool = use ? styleMoves[style] : commonMoves;
```

- `styleMoves` = スタイル別、ダメージ **10〜16**
- `commonMoves` = 共通、ダメージ **2〜10**

フェーズが進むと `sCh` が上がるため大技プールを引く**確率**は上がる。しかし**共通プールの中身は最初から最後まで不変**であり、クライマックスでも30%の確率で d2 の技（ストンピング／チンロック／ロックアップからの押し込み）が候補に入る。

共通プール73技のうち約34技が d≤5。掛け合わせると **クライマックスのターンの約14%が d≤5 の小技**となる。終盤は相手HPが減っているため、この小技がそのまま決着打になる。

### 1.3 副次的な不具合：カテゴリ抽選がプールと噛み合っていない

```js
const cat   = Engine.rng.weighted(rng, catW[resolvedStyle]);
const cands = pool.filter(m => m.c === cat);
return cands.length ? Engine.rng.pick(rng, cands) : Engine.rng.pick(rng, pool);
```

カテゴリを `catW` から引いてからプールを絞り込むが、`styleMoves` は各12技しかなく全カテゴリを網羅していない。例えば `styleMoves.Grappler` には aerial / ground / rollup が1つも無いのに `catW.Grappler` はその3つに計25%を割り当てている。該当なしのとき**プール全体からの完全ランダム**にフォールバックするため、スタイル別の重み付けが意図どおり効いていない。

## 2. 設計方針

技を**威力による3ティア**に分類し、フェーズごとにティアの出現重みを持たせる。`sCh` と2プール切替は廃止する。

**データの書き換えは不要**。既存の `d` 値で仕分けるだけで境界が綺麗に割れる。

---

## 3. ティア定義

| ティア | ダメージ | 主な出典 | 例 |
|---|---|---|---|
| 小技 | 2〜5 | commonMoves | ストンピング、チンロック、ヒップトス |
| 中技 | 6〜10 | commonMoves（+ styleMoves の d10） | ブレーンバスター、DDT、ラリアット |
| 大技 | 11〜16 | styleMoves | パワーボム、卍固め、450スプラッシュ |
| ├ 通常大技 | 11〜13 | styleMoves | ジャーマン、シャープシューター |
| └ **フィニッシュ級** | 14〜16 | styleMoves | ラストライド、ツームストン、SSP |

- ティアは**プール名ではなく `d` 値で決まる**。`styleMoves` の d10 エントリー（カナディアン・バックブリーカー等）は中技に落ちる
- 選手ごとの候補集合 = `commonMoves ∪ styleMoves[style]` を `d` で3分割したもの
- 大技はすべて `styleMoves` 由来のため、**スタイルの個性は大技帯に集約される**（設計意図どおり）
- `rollup` は本ティア制の**対象外**（§6）

## 4.5 小技では決着しない

**小技（d2〜5）による攻撃では、フォール決着およびギブアップ決着が発生しない。**

ティア重みをどう調整しても地味な決着が原理的に発生しなくなる、本仕様の要となる規則。重みによる抑制と違って抜け道がない。

### 適用範囲

| 決着タイプ | 小技での発生 | 備考 |
|---|---|---|
| フォール | **不可** | |
| ギブアップ | **不可** | |
| **TKO** | **可** | 小技を浴び続けて壊れる展開は地味決着ではなくドラマである。既存条件（`tkoConsecutiveThreshold` 3連続 + `tkoHpThreshold` 15%以下）が十分に厳しく、乱発はされない |

### HPの下限

小技によるダメージでは**防御側のHPが1を下回らない**（下限1でクランプする）。

小技でHPが0に到達したまま決着せず膠着する事態を防ぐための措置。中技以上が入るまで倒れない、という素直な読みになる。クライマックスは小技0%のため、この下限が効く場面は序盤〜中盤に限られる。

### 丸め込みは対象外

丸め込み（`rollup`）は d4〜5 のため放置すると小技に分類されるが、**フォール決着こそが本体**であるため本規則の対象外とする。丸め込みはそもそもティア制の枠外にある（§6）。

## 5. フィニッシュ級の解禁条件

**フィニッシュ級（d14〜16）は、防御側のHPが一定値を下回るまで選択されない。**

- 専用定数 `finisherUnlockHpThreshold` を用いる
  - **通常試合: 0.50 / ビッグマッチ: 0.40**
- 未解禁のあいだ、大技ティアの抽選対象は d11〜13 のみ
- 全7スタイルとも d11〜13 の技を6本以上持つため、候補枯渇は起きない

### v0.1 初版からの変更（2026-07-20 実測を受けて改訂）

初版では**新規定数を作らず `pinAttemptHpThreshold`（通常0.35 / ビッグ0.25）をそのまま参照する**設計だった。「フォールが狙える瞬間とフィニッシュ級の解禁を同じ線に揃えれば、フィニッシュ級が出た＝決めに来た、という読みが生まれる」という意図である。

しかし実装後の auto-sim（100シーズン）で **フィニッシュ級が 0.115回/試合・89%の試合で一度も出ない**ことが判明した。想定は1〜2回/試合であり、10分の1である。

原因は、同じ35%が**フォールが飛び始める閾値でもある**こと。フィニッシュ級が解禁された瞬間から試合は終わりに向かって走り出すため、窓が1〜2ターンしか開かない。そこに大技ティアを引く確率を掛けると、ほぼ出現しない。意味を揃えることに気を取られ、**その窓に時間的な幅があるかを検証していなかった。**

加えて、順序としても誤っていた。プロレスの理屈では「大技で削り切る → フォール圏に入る → 決めにいく」であるべきだが、初版では両方が同時に解禁されていた。

### 出現頻度に目標値は設けない（2026-07-20 Keisuke 判断）

**フィニッシュ級が1試合あたり何回出るか、という目標は持たない。出ないなら出なくてよく、数試合に一度で構わない。**

初版の §11 では「1試合あたり1〜2回に収まっているか」を検証項目に挙げていたが、これは撤回する。この目標を追った結果、task-09 で解禁閾値が 0.50 → 0.75（大一番 0.40 → 0.80）へ緩められ、下記の設計意図が壊れた。**頻度は結果であって目標ではない。**

以後、フィニッシュ級の出現頻度を上げるために解禁閾値を緩めたり、大技ティア内で優先的に選ぶ重み付けを入れたりしないこと。

### 設計意図（改訂後）

解禁を **50%（ビッグマッチ 40%）** に前倒しし、フォール閾値（35% / 25%）との間に **15ポイントの帯**を設ける。これにより終盤が二段階に分節される。

| 防御側HP | 状態 |
|---|---|
| 50%〜（ビッグ40%〜） | 通常大技まで。フィニッシュ級は出ない |
| 35〜50%（ビッグ25〜40%） | **フィニッシュ級が解禁。削り切りにいく帯** |
| 〜35%（ビッグ〜25%） | フォール・ギブアップが飛び始める。決めにいく帯 |

通常とビッグマッチで15ポイントの差を等しく保つことで、ビッグマッチでも同じリズムが再現される。

拮抗したまま防御側HPが閾値を割らずに時間切れとなった試合では、フィニッシュ級は一度も出ない。これは正しい挙動である（互角の勝負では決め手が出ないまま判定に流れ込む）。

## 6. 丸め込み（rollup）の扱い

丸め込み系（スクールボーイ d4、首固め d4、回転エビ固め d5 ほか7技）は**意図的に低ダメージ**であり、ティア制に載せると小技扱いとなりクライマックスで出現しなくなる。これは望ましくない——丸め込みは地味な決着ではなく**事件**だからである。

したがって丸め込みは**ティア制の対象外**とし、独立した抽選経路を持つ。

- 毎ターン、ティア抽選の**前に**丸め込み判定を行う
- 成立したら丸め込み技を選択し、ティア抽選をスキップする
- Opening では発生しない（既存の `ph.name !== 'Opening'` ガードを踏襲）

| フェーズ | 丸め込み発生率 |
|---|---|
| Opening | 0% |
| Mid | 3% |
| End | 5% |
| Climax | 7% |

- `catW` から `rollup` エントリーを削除する（二重抽選になるため）
- 決着処理（`rollupHpThreshold` / `rollupBaseSuccess` / `rollupTecBonus`）は**現行のまま変更しない**

## 7. 大技クールダウン

**大技（フィニッシュ級を含む）を選択した次の自分のターンは、大技ティアを選べない。**

- 対象は「選択」時点。命中/失敗/カウンターされたかは問わない（空振りにも「間」が生まれるべき）
- クールダウン中は小技・中技の重みを再正規化して抽選する
  - 例: Climax（小0/中35/大65）でクールダウン中 → 中技100%
- 選手ごとに1ターンフラグを持つ（`bigMoveCooldown` 等）

### 設計意図

ティア分けだけを入れると、クライマックスで大技が連打され「パワーボム→デスバレーボム→ラストライド」のような別種の単調さが生まれる。プロレスの終盤には大技のあいだに必ず「間」がある。クールダウンにより「大技 → 繋ぎ → 大技」のリズムが自動的に生まれる。

**ティア制と必ずセットで実装すること。**片方だけでは別の問題に化ける。

---

## 8. カテゴリ抽選の修正

カテゴリは、**選ばれたティア内に実在するカテゴリだけで正規化して**抽選する。

```
1. ティアを抽選（§4、クールダウン考慮）
2. そのティアの候補集合に実在するカテゴリを列挙
3. catW[style] の重みを、列挙されたカテゴリだけで正規化
4. カテゴリを抽選 → 該当技から一様抽選
```

これにより「該当なし → プール全体からランダム」のフォールバックが消滅し、スタイル別の重み付けが設計どおり機能する。

## 10. バランスへの影響（要注意）

本変更はターンあたりの平均ダメージを**フェーズごとに逆方向へ動かす**。

序盤が遅く、終盤が速くなる。これは起承転結として意図どおりだが、**試合全体の長さ・決着率・MQ分布が動く**。

### 10.1 試合が長くなる方向への圧力（要監視）

以下の3点はいずれも**試合を長くする**方向に働く。

1. Opening の小技比率を 55 → **70** に引き上げた
2. End の大技比率を 40 → **30** に引き下げた
3. **小技で決着しなくなった**（§4.5）

**→ 解決済み（2026-07-20）。**実測では時間切れ率はむしろ下がった（5.99% → 5.96%、最終的に約1.6%）。その後のフェーズ・HP同時較正（task-09 以降）で `MAX_T` は 21、平均ターン数は約14.2 になっている。確定値は §3.5 を参照。

## 11. 検証項目（auto-sim）

- **決着技のダメージ分布** — d≤5 の技による決着が消えているか（本件の主目的）
- **フェーズ別のティア出現率** — §4 の設計値と一致するか
- **フィニッシュ級の出現回数** — 実測して記録するのみ。**目標値は設けない**（§5「出現頻度に目標値は設けない」参照。数試合に一度で構わない）
- **大技の連続出現** — クールダウンが効き、2連続が発生していないか
- **平均ターン数・時間切れ判定率** — 現行比で大きく動いていないか（§10）
- **MQ分布** — 全体が押し上げ/押し下げられていないか
- **勝率への影響** — OVR差帯ごとの勝率が現行から動いていないか（技選択の是正が実力差の意味を変えてはならない）

## 12. 実測結果と残課題（2026-07-20 初回実装後）

`node test/auto-sim.js 100 42` の結果。

### 達成できたこと

| 項目 | 結果 |
|---|---|
| 小技によるフォール／ギブアップ | **0件**（主目的達成） |
| 小技によるTKO | 321件（許可済み） |
| 通常大技の2連続 | 0件（クールダウン正常） |
| 平均ターン数 | 11.94 → 12.27 |
| 時間切れ率 | 5.99% → 5.96%（長期化は起きなかった） |
| 平均MQ | 54.19 → 53.70 |

格上勝率は差20以上で 95.48% → 93.36%（−2.12pt）。番狂わせが 4.5%→6.6% と相対で5割増えており、**方向としては「実力差を残酷に」の意図と逆**。開幕大技（`opening-execution-spec-v0.1.md`）が約+1pt戻すため実質 −1pt 程度で、現時点では許容範囲と判断。

### ✅ 残課題A: フィニッシュ級の出現率 — 解決済み

解禁閾値を 0.50 / 0.40 へ改訂。**その後 task-09 で頻度目標を満たすため 0.75 / 0.80 まで緩められ、終盤の二段構造が壊れた**（大一番のほうが早く解禁される逆転状態にもなっていた）。task-15 で 0.50 / 0.40 へ復帰させ、**頻度目標そのものを撤回**（§5「出現頻度に目標値は設けない」）。

最終実測: 通常戦 0.444回/試合（0回率64.5%）/ 大一番 0.341回/試合（0回率72.0%）。**大一番のほうが出にくい**という設計上の順序も回復している。

### ✅ 残課題B: 大技の実効上限がクールダウンで約50% — 解決済み

**Climax の大技重みを 65 → 55、中技を 35 → 45 へ書き換え済み**（§3.5）。あわせて task-09 で**フィニッシュ級をクールダウンの対象外**としたため、実効上限は50%より上がっている（実測 Climax 大技率 約54%）。通常大技（d11〜13）のクールダウンは維持。

以下は判明当時の記録。



| フェーズ | 設定 | 実測 |
|---|---|---|
| End 大技 | 30% | 24.25% |
| Climax 大技 | **65%** | **45.12%** |

大技を撃った次のターンは必ず中技以下になるため、**大技の実効上限は約50%**。Climax に65を設定しても50で頭打ちになり、20ポイントが空振りしている。

害はないが、設定値が挙動を表していないため今後の較正で誤解を生む（「Climaxを70に上げよう」としても何も起きない）。**Climax の大技重みを実態に合わせて 50 前後に書き換えるべき。**残課題Cの結論と合わせて確定する。

### ✅ 残課題A': 解禁と同時にフォールが飛び始める構造 — 解決済み

**フィニッシュ級をクールダウンの対象外にした**（task-09）ことで、下記の「大技で解禁 → クールダウンで中技 → ようやくフィニッシュ級」の2ターン遅延は解消。あわせてフェーズ構成の較正で Climax の平均滞在が 1.13T → 約3.4T に伸び、窓そのものが広がった。

なお本節にある「想定（1〜2回/試合）に届かない」という評価は**撤回済み**。出現頻度に目標値は設けない（§5）。

以下は判明当時の記録。



| 項目 | 改訂前(0.35) | 改訂後(0.50) |
|---|---|---|
| フィニッシュ級／試合 | 0.115 | **0.203** |
| 0回で終わる試合 | 89.09% | **81.28%** |

1.77倍に増えたが、想定（1〜2回/試合）には遠い。格上勝率は差20以上で 93.36% → **95.02%**（変更前95.48%）まで戻り、番狂わせ増加の懸念は解消した。小技決着0件・大技2連続0件も維持。

律速として新たに判明した相互作用:

- フィニッシュ級の解禁判定は**攻撃前**に行われるため、**HPを50%以下に落とす一撃そのものにはフィニッシュ級を使えない**
- そのHPを削る一撃はたいてい大技であり、**大技を撃つとクールダウンが立つ**
- 結果、「大技で解禁 → クールダウンで中技 → ようやくフィニッシュ級」と**最短でも2ターンの遅れ**が構造的に発生する
- Climax の平均滞在が 1.13ターンしかないため、この2ターンが確保できない

→ **フィニッシュ級をクールダウンの対象外とする**案が有力（「大技で畳み掛けてフィニッシュ」はプロレスとして自然であり、解禁条件が別途あるため乱発にはならない）。較正タスクで扱う。

### ✅ 残課題C: フェーズ構成が実態と乖離している — 解決済み

**フェーズ境界とHPを同時に較正して解消**（task-09 / task-10 / task-12）。Climax到達率は 通常50.43%→約87% / 大一番11.85%→約94%、Climax平均滞在は 1.13T→約3.4T / 0.28T→約5.0T。確定値は §3.5 を参照。

途中、大一番の異常値（Climax到達11.85%）は**連戦疲労で開始HPの減った試合がサンプルの66.75%を占めていたことによる誤読**だったことが task-08 の統制比較で判明している（同一条件なら大一番は通常戦より+37〜40%長い）。

以下は判明当時の記録。



| | 通常試合 | ビッグマッチ |
|---|---|---|
| Climax到達率 | 50.43% | **11.85%** |
| Climax平均滞在 | 1.13ターン | **0.28ターン** |
| End平均滞在 | 3.12ターン | 2.00ターン |
| 最多の終了フェーズ | End 41.93% | **Mid 44.10%** |

**通常試合**: 決着ターンに **T13 の 18.50%** という突出したピークがある。T13 は Climax の開始ターンであり、倍率が 1.05→1.30、大技重みが 30→65 に跳ぶ瞬間。**Climax が「段階」ではなく「試合が終わる瞬間」になっている。**

**ビッグマッチ**: 半数近くが Mid で終わっており、End/Climax の技重みにほとんど到達していない。**現状、大舞台は通常試合よりも構造的に盛り上がらない。**

#### 診断結果（task-08 / 2026-07-20）

**上記の数値は誤読だった。**実運用サンプル2,283試合のうち **66.75% が連戦疲労で開始HPが減った試合**であり、それが平均を押し下げていた（大半が秋の4団体勝ち残り戦。単一イベントで全体の54.7%を占める）。

同一カード・全員全快・同一シードでの統制比較では、大一番は全帯で **+37〜40% 長い**（12.2 → 17.0ターン）。最大HP比1.42倍は設計どおり効いており、**エンジンは正常**である。

**教訓**: バランスを測るときは比較する群の条件（開始HP・カード構成・試合ルール）を揃えたシミュレーションを組むこと。実運用サンプルをそのまま並べない。

#### 残る問題と対処方針（2026-07-20 決定）

全快だけを見ても、フェーズ表と実際の試合長が噛み合っていない。

| | 平均ターン | Climax到達 | Climax滞在 |
|---|---|---|---|
| 通常試合 | 12.22 | 50.43% | 1.13T |
| 大一番（全快） | 15.51 | 27.01% | 0.66T |

**フェーズ境界を実測に合わせる（①）と、試合そのものを長くする（②）を同時に行う。**

①だけでは成立しない。Climax の高倍率（通常1.30 / 大一番1.20）と大技重みが前倒しされて試合がさらに短くなり、到達率が再び下がるフィードバックループがあるため。②だけでも、フェーズ表と実態のずれは残る。

目標は通常15ターン前後 / 大一番22ターン前後、Climax到達70%以上、Climax滞在2.5〜3.5T（大一番3.5〜5.0T）。

→ `docs/codex-tasks/task-09-phase-and-hp-calibration.md`。残課題A'（フィニッシュ級をクールダウン対象外に）と残課題B も同タスクに統合。
