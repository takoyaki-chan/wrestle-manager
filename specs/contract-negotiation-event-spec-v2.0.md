## §1 概要

シーズン開幕前（OffWeek 4）に発生する、選手との1対1の契約更新交渉イベント。

毎年全選手と契約更新を行うが、大多数は自動残留。**信頼（trust）が低い選手** または **給与が実力に見合っていない選手** が「意見あり」として交渉対象になる。

交渉では選手の性格と状況に応じたセリフが表示され、プレイヤーは昇給・交渉・拒否などの選択肢で対応する。対応次第で残留・退団・モラール変動が発生する。

**設計思想:** 信頼が高くても、給料が不当に低ければ交渉は発生する。交渉が一切発生しないのは「お金にも文句がなく、実力と評価にズレがなく、信頼も十分な選手」だけ。

## §2 基本ルール

| 項目 | 内容 |
|---|---|
| タイミング | OffWeek 4（シーズン開幕前、週進行の前に1回） |
| 対象 | ロスター全選手（レンタル除外。毎年更新、契約年数の概念なし） |
| 最大交渉人数 | **4名**（深刻度順にソートし上位4名を選出） |
| 交渉後処理 | 全交渉完了後、ロスター全員のcontractOVR/contractPopを現在値で更新（§9参照） |

### §2.1 契約OVR制との連携

本仕様は `contract-ovr-salary-spec-v1.0.md` を前提とする。

- シーズン中の給与は `contractOVR` / `contractPop`（シーズン開始時に固定された値）で計算される
- シーズン中に選手が成長しても給与は変わらない
- OffWeek 4 の契約更新完了時に `contractOVR` / `contractPop` が現在値に更新される
- **この「据え置き」と「現在値」の差が給与ギャップを生む**

## §3 給与ギャップ（新設）

### §3.1 定義

```
fairSalary    = getSalary(現在OVR, 現在pop)        // 今の実力で契約し直した場合の給与
currentSalary = getSalary(contractOVR, contractPop)  // 現在の契約給
gapRatio      = fairSalary / currentSalary
```

- `gapRatio = 1.0` → 実力通りの給与。不満なし
- `gapRatio = 1.2` → 本来の8割しかもらっていない。不満の種
- `gapRatio = 2.0` → 本来の半額。明確に不当

### §3.2 ギャップ3段階

| ギャップ区分 | gapRatio | 意味 |
|---|---|---|
| **なし** | < 1.1 | 10%未満の差。誤差の範囲。「まあこんなもんか」 |
| **あり** | 1.1 〜 1.3 | 10〜30%の差。気づいている、不満はあるが我慢可能 |
| **大** | ≥ 1.3 | 30%以上の差。明確に不当。黙っていられない |

### §3.3 閾値の根拠

| 閾値 | 根拠 |
|---|---|
| 1.1倍 | OVR +3〜5程度の微成長で到達。1シーズンの安定成長で生じうる最小ギャップ。月給30万が33万になる程度で、「来年調整されるだろう」と思える範囲 |
| 1.3倍 | OVR +8〜10程度の成長で到達。月給30万が本来39万であるべき状態。年間108万の損失。これは社会通念上、雇用者に説明責任が生じるライン |

### §3.4 具体的な給与ギャップ例（SALARY_PARAMS基準、pop=0）

| contractOVR | 現在OVR | 契約給 | 適正給 | gapRatio | 区分 |
|---|---|---|---|---|---|
| 40 | 43 | 7万 | 8万 | 1.1 | なし→あり境界 |
| 40 | 48 | 7万 | 10万 | 1.4 | 大 |
| 40 | 60 | 7万 | 23万 | 3.3 | 大（深刻） |
| 50 | 55 | 12万 | 17万 | 1.4 | 大 |
| 50 | 60 | 12万 | 23万 | 1.9 | 大（深刻） |
| 60 | 65 | 23万 | 31万 | 1.3 | あり→大境界 |
| 60 | 70 | 23万 | 42万 | 1.8 | 大 |

## §4 交渉発火マトリクス（trust × ギャップ）

### §4.1 マトリクス全体図

| trust＼ギャップ | なし（< 1.1） | あり（1.1〜1.3） | 大（≥ 1.3） |
|---|---|---|---|
| **75+** | 自発的残留 | 丁寧な昇給相談 | 昇給要求 |
| **40〜74** | 自動残留 | 昇給要求 | 強めの昇給要求 |
| **30〜39** | 昇給要求（穏やか） | 昇給要求（不満） | 昇給要求（怒り） |
| **15〜29** | 移籍志願 | 移籍志願（強め） | 移籍志願（怒り） |
| **< 15** | 移籍志願（最後通告） | 突発退団リスク(30%) | 突発退団リスク(50%) |

### §4.2 trust帯域の定義と設計根拠

| 帯域 | trust範囲 | 選手の心理 | 根拠 |
|---|---|---|---|
| 高信頼 | 75+ | 団体に愛着がある。お金の話は別にするが、辞める気はない | trustシステムのanchor(64)を大きく超えた状態。ケアや出場を継続しないと到達しない |
| 安定 | 40〜74 | 特に不満はない。お金に問題なければ黙っている | trust初期値域(35-65)の中央〜上。通常プレイで維持できる範囲 |
| 不満蓄積 | 30〜39 | 不満が溜まっているが、まだ話し合いで解決可能 | trustグラビティ(anchor=64)からの自然減衰で到達しうるギリギリのライン |
| 危険 | 15〜29 | 半分出て行く気。金で引き留められるかもしれないが基本は移籍志願 | 出場させない・ケアしないが続いた状態 |
| 決裂 | < 15 | 関係修復不能。突発退団の可能性 | 意図的な冷遇か長期の放置がないと到達しない |

### §4.3 ギャップ起因の交渉（trust 40+）の態度マッピング

trust 40+ の選手は現行では交渉が発生しない。新設計では給与ギャップがある場合のみ発生する。

| trust | ギャップ | attitude | tone | 備考 |
|---|---|---|---|---|
| 75+ | 1.1〜1.3 | `raise` | `polite` | 信頼関係があるからこそ正直に言える |
| 75+ | ≥ 1.3 | `raise` | `normal` | 丁寧だが明確に要求 |
| 40〜74 | 1.1〜1.3 | `raise` | `normal` | 通常の昇給要求 |
| 40〜74 | ≥ 1.3 | `raise` | `firm` | 強めの要求。対応を誤ると不満残留 |

### §4.4 trust 39以下の深刻度設計

#### trust 30〜39 — 不満蓄積ゾーン

まだ話し合いで解決できる段階。主に昇給要求。

| ギャップ | attitude | 対応失敗時の展開 |
|---|---|---|
| < 1.1 | `raise`（穏やか） | trust低下のみ |
| 1.1〜1.3 | `raise`（不満） | 移籍志願にエスカレートあり |
| ≥ 1.3 | `raise`（怒り） | 移籍志願にエスカレートしやすい |

#### trust 15〜29 — 危険ゾーン

本人は半分出て行く気。基本は移籍志願。ギャップが重なると引き留め成功率にペナルティ。

| ギャップ | attitude | 引き留め影響 |
|---|---|---|
| < 1.1 | `transfer` | 引き留め可能（標準成功率） |
| 1.1〜1.3 | `transfer`（強め） | 引き留め成功率ペナルティ |
| ≥ 1.3 | `transfer`（怒り） | 引き留め成功率大幅ペナルティ |

#### trust < 15 — 決裂ゾーン

関係修復不能。突発退団が発生しうる。

| ギャップ | 展開 | 確率 |
|---|---|---|
| < 1.1 | 移籍志願（最後通告） | 引き留め可能だが低確率 |
| 1.1〜1.3 | **突発退団リスク** | 30%で交渉不可→即退団 |
| ≥ 1.3 | **突発退団リスク** | 50%で交渉不可→即退団 |

突発退団が発生しなかった場合は、移籍志願（最後通告）にフォールバック。

### §4.5 発火確率（現行ロジック維持 + ギャップ補正）

trust < 40 の選手に対する基本発火確率（現行ロジック）:

```
昇給要求（trust 25〜39）:
  trust 30〜39: baseProb = 0.60 + (40 - trust) * 0.03
  trust 25〜29: baseProb = 0.90

移籍志願（trust < 25）:
  trust 15〜24: baseProb = 0.50 + (25 - trust) * 0.05
  trust < 15:   baseProb = 1.0（確定）
```

**特性補正（現行ロジック維持）:**

| 特性 | 補正 | 備考 |
|---|---|---|
| 忠誠心 | baseProb × 0.5 | 乗算。発火しにくい |
| 反骨心 | baseProb + 0.20 | 加算。発火しやすい |
| 野心（非チャンピオン） | baseProb + 0.15 | 加算 |
| チャンピオン | baseProb - 0.30 | 減算。チャンピオンは辞めにくい |
| 最終clamp | 0.05 〜 1.0 | |

**ギャップ起因の発火（trust 40+ — 新設）:**

trust 40+ の選手はギャップがない限り発火しない（発火確率の概念がない）。ギャップがある場合:
- gapRatio ≥ 1.1 → **確定発火**（確率判定なし。給与問題は確実に言及される）

### §4.6 交渉人数の上限

- 全候補を **深刻度スコア** 順にソートし、上位4名を選出
- 深刻度スコア = `(100 - trust) + (gapRatio - 1.0) * 100`
  - trust 10, gapRatio 2.0 → スコア 190（最優先）
  - trust 35, gapRatio 1.0 → スコア 65
  - trust 60, gapRatio 1.5 → スコア 90
- 5名以上の候補がいる場合、溢れた選手は交渉スキップ（自動残留扱い、ただしtrust/ギャップ問題は翌年に持ち越し）

## §5 態度の種類

### §5.1 昇給要求（`raise`）

- **発生条件:** trust 30+ でギャップあり、または trust 25〜39 でギャップなし
- **選手の主張:** 待遇への不満、評価されていない感覚、給与と実力の乖離
- **深刻度:** 中程度。対応次第で穏便に収まる

### §5.2 移籍志願（`transfer`）

- **発生条件:** trust < 25、または trust < 15 で突発退団が発生しなかった場合
- **選手の主張:** この団体を離れたい、やり直したい
- **深刻度:** 高い。引き留めにはコストが必要、失敗もありうる

### §5.3 突発退団（`sudden_departure` — 新設）

- **発生条件:** trust < 15 かつ gapRatio ≥ 1.1
- **確率:** gapRatio 1.1〜1.3 で30%、gapRatio ≥ 1.3 で50%
- **選手の主張:** 「もう決めました」— 交渉の余地なし
- **深刻度:** 最大。プレイヤーは見送ることしかできない

**設計意図:** trust放置 + 給与放置のダブルパンチに対するペナルティ。「こうなる前にケアすべきだった」という学びを与える。逆に言えば、trustが低くても給与をちゃんと払っていれば（ギャップなし）突発退団は起きない。

## §6 プレイヤーの対応フロー

### §6.1 昇給要求への対応

```
【昇給要求】
  ├─ A: 昇給を受ける（salaryBonus += raiseAmount）
  │    → 残留、trust +12
  │
  ├─ B: 交渉する（中間案を提示、salaryBonus += counterOffer）
  │    ├─ 選手が受諾 → 残留、trust +6
  │    └─ 選手が拒否 → trust -8、以下に分岐:
  │         ├─ 20%: 即退団（trust < 20 の場合のみ）
  │         ├─ 30%: 移籍志願にエスカレート（UIで再交渉）
  │         └─ 50%: 不満を抱えたまま残留
  │
  └─ C: 拒否する
       → trust -15、以下に分岐:
            ├─ 40%: 移籍志願にエスカレート
            └─ 60%: 不満を抱えたまま残留
```

### §6.2 移籍志願への対応

```
【移籍志願】
  ├─ A: 引き留める（funds -= retentionBonus）
  │    ├─ 成功 → 残留、trust +8、morale +2
  │    └─ 失敗 → 退団
  │
  ├─ B: 理由を聞く（中間選択肢）
  │    → 選手が不満の理由を語る
  │    → サブ選択:
  │         ├─ 引き留める（A と同じ処理）
  │         └─ 送り出す（C と同じ処理）
  │
  └─ C: 送り出す（放出を受け入れる）
       → 退団
```

### §6.3 突発退団（新設）

```
【突発退団】
  │
  └─ 選択肢なし。選手が一方的に退団を宣言
       → [……わかった] ボタンのみ
       → 退団処理
```

### §6.4 エスカレーション

昇給要求のB（交渉失敗）またはC（拒否）で移籍志願にエスカレートした場合:
1. 昇給要求のリアクションセリフを表示
2. 移籍志願の交渉画面に遷移（§6.2のフローに入る）
3. エスカレート後の移籍志願は通常より引き留め成功率が低い（要検討）

## §7 金銭計算

### §7.1 昇給額（`calcRaiseAmount`）

```javascript
calcRaiseAmount(fighter, state) {
  const currentSalary = getSalary(fighter, state.titles);
  const ovr = ov(fighter);
  const pop = fighter.popularity || 1;
  const ovrFactor = Math.pow(ovr / 60, 1.5);
  const baseRaisePct = 0.15 + (pop / 100) * 0.10;
  const raw = Math.round(currentSalary * baseRaisePct * ovrFactor);
  return clamp(raw, 3, 30);
}
```

| パラメータ | 値 | 設計意図 |
|---|---|---|
| baseRaisePct | 0.15 + (pop/100) × 0.10 | pop 0 で15%、pop 100 で25%の昇給率。人気選手ほど要求が高い |
| ovrFactor | (ovr/60)^1.5 | OVR 60を基準1.0。高OVR選手の要求額を非線形に拡大 |
| clamp | 3〜30 | 最低3万/週（≒月12万）、最高30万/週（≒月120万）|

**課題（B-1）:** この計算は `currentSalary`（契約給）ベースであり、給与ギャップを考慮していない。contractOVR 40 の選手（契約給7万）が OVR 60 に成長していても、7万 × 15% × 1.0 = 1万 程度の昇給しか要求しない。本来の適正給23万との差16万に対して1万の昇給要求は不自然。**→ 改善案は§14に記載。**

### §7.2 中間提示額（`calcCounterOffer`）

```javascript
calcCounterOffer(raiseAmount) {
  return Math.max(2, Math.round(raiseAmount * 0.5));
}
```

raiseAmount の半額、最低2万。

### §7.3 引き留めボーナス（`calcRetentionBonus`）

```javascript
calcRetentionBonus(fighter, state) {
  const currentSalary = getSalary(fighter, state.titles);
  const ovr = ov(fighter);
  const weeksFactor = 8 + Math.floor(ovr / 20);
  return Math.round(currentSalary * weeksFactor);
}
```

| OVR | weeksFactor | 意味 |
|---|---|---|
| 30 | 9 | 9週分の給与 |
| 50 | 10 | 10週分の給与 |
| 70 | 11 | 11週分の給与 |

**課題（B-1）:** calcRaiseAmount と同じく契約給ベース。ギャップが大きい選手の引き留めボーナスが安すぎる。**→ 改善案は§14に記載。**

### §7.4 交渉B（中間案）の成功率

```
successRate = 0.50
  + (trust - 30) × 0.01
  + (mn - 50) × 0.005
  + 特性補正（忠誠心: +0.15、野心: -0.10、反骨心: -0.15）
clamp: 0.15 〜 0.85
```

**課題（B-4）:** trust 30前後の選手が交渉対象になる設計なのでtrust項の寄与がほぼゼロ。MN項も微小。実質50%のコイントス。**→ 改善案は§14に記載。**

### §7.5 引き留め成功率

```
retainRate = 0.55
  + (trust - 15) × 0.015
  + careerSeasons × 0.03
  + 特性補正（忠誠心: +0.20、反骨心: -0.15）
  + 初期メンバー: +0.10
clamp: 0.10 〜 0.80
```

**ギャップ補正（新設）:**

| ギャップ | retainRate補正 |
|---|---|
| < 1.1 | なし |
| 1.1〜1.3 | -0.10 |
| ≥ 1.3 | -0.20 |

## §8 性格タイプシステム

### §8.1 2軸構造: personality × archetype

セリフのトーンは `personality`（性格）で決まり、語彙・口調は `archetype`（キャラ類型）で決まる。

#### personality（第1軸 — トーン決定）

| personality | 昇給要求のトーン | 移籍志願のトーン | 退団時のトーン |
|---|---|---|---|
| bold | 突きつける | 宣言する | 強がる |
| quiet / shy | おどおど切り出す | 申し訳なさそう | 静かに去る |
| easygoing | 軽く聞いてくる | さらっと言う | 笑って別れる |
| earnest | 筋を通して伝える | 悩み抜いた末に | 礼を尽くす |
| emotional | 怒りが混じる | 涙ぐむ | 恨みか感謝、極端に |
| normal | 標準的 | 標準的 | 標準的 |

#### archetype（第2軸 — 口調決定）

| archetype | 口調の特徴 |
|---|---|
| _default | 標準的な口調 |
| ojousama | 丁寧語・お嬢様言葉 |
| delinquent | ぞんざい・ヤンキー口調 |
| seductive | 色っぽい・誘うような口調 |
| cool | 寡黙・短文 |
| polite | 丁寧・控えめ |

### §8.2 性格タイプ判定（`getPersonalityType`）

```
1. fighter.personality が設定済み（≠ 'normal'）→ そのまま使用
   - quiet → introverted にマッピング
   - easygoing → carefree にマッピング
   - その他（bold, earnest, emotional, shy）→ そのまま

2. personality 未設定 or 'normal' → 特性ベースの推論にフォールバック:
   - 威圧感/野心/闘志/反骨心 → bold
   - 破天荒/ムードメーカー/華 → carefree
   - 負けず嫌い/ライバル体質/ガラスの身体 → emotional
   - 努力家/忠誠心/リーダー気質/人望/適応力 → earnest
   - 晩成/遅咲き/不屈/番狂わせ体質 → introverted
   - role: Heel → bold
   - role: Babyface → earnest
   - 該当なし → introverted
```

### §8.3 セリフ選択（`getDialoguePool`）

```
1. fighter.voice が設定 → _voice[voice] を優先
2. personality → archetype の2段階フォールバック:
   pool[personality][archetype]
   → pool[personality]._default
   → pool._default (or pool.normal)
   → ['…']
```

## §9 セリフ生成システム

### §9.1 フェーズ一覧

## §10 退団処理

### §10.1 退団前の関係値更新

退団が確定した選手に対し、roster除外前に:
- 残った同僚全員 → 退団選手: bond -15〜-8、rivalry +5〜+10

### §10.2 roster除外

- roster から除外
- コーチアサインから除外（`unassignFromCoach`）
- ワールドタイトル保持者の場合、タイトル空位化

### §10.3 退団先決定（`determineDeparture`）

```
1. wear ≥ 50 OR age ≥ 25:
   → 確率 0.4 + (wear/200) で引退

2. OVR ≥ 50:
   → ロスター12未満のライバル団体があれば、60%でそこに移籍

3. 上記に該当しない:
   → フリーエージェントになる
```

**課題（B-2）:** このロジックは暫定的で設計意図が不明確。age 25 で引退候補は若すぎる可能性がある。OVR 49以下は全員FAになるのも不自然。**→ 改善案は§14に記載。**

### §10.4 退団先別の処理

| 退団先 | 処理 |
|---|---|
| 引退 | `retiredFighters` に追加 |
| ライバル団体 | 該当団体のrosterに追加（trust=50, salaryBonus=0にリセット） |
| FA | `freeAgents` に追加（trust=50, salaryBonus=0にリセット、orgId=undefined） |

## §14 改善提案

### §14-A. 現行動作を壊さない小改善

#### A-1. calcRaiseAmount を適正給ベースに

**現行:** `currentSalary`（契約給）× baseRaisePct × ovrFactor
**問題:** ギャップが大きい選手の昇給要求額が不当に安い
**改善:** `fairSalary`（適正給）と `currentSalary` の差額をベースにする

```javascript
calcRaiseAmount(fighter, state) {
  const currentSalary = getSalary(fighter, state.titles);     // 契約給
  const fairSalary = getSalary_fair(fighter, state.titles);   // 適正給（現在OVR/pop）
  const gap = fairSalary - currentSalary;

  if (gap <= 0) {
    // ギャップなし — 現行ロジック（trustベースの昇給要求）
    const pop = fighter.popularity || 1;
    const baseRaisePct = 0.10 + (pop / 100) * 0.05;
    return clamp(Math.round(currentSalary * baseRaisePct), 2, 15);
  }

  // ギャップあり — 差額の50〜80%を要求
  const demandPct = 0.50 + (pop / 100) * 0.30;
  return clamp(Math.round(gap * demandPct), 3, 50);
}
```

**意図:** 契約給7万、適正給23万の場合 → 差額16万の50〜80% = 8〜13万の昇給要求。現実的な数字。

#### A-2. calcRetentionBonus も適正給ベースに

同様に、引き留めボーナスを適正給ベースにする。実力40万相当の選手を引き留めるのに、7万×10週=70万では安すぎる。

#### A-3. 残留成功時にモラール+2〜+4

現行は退団時にモラール低下のみ。残留成功時に小さなモラール上昇を追加。

```
残留成功 → morale +2（通常）/ +4（初期メンバーの場合）
```

### §14-B. 抜本改修（要承認）

#### B-1. 退団先決定ロジックの再設計

**現行の問題:** age 25で引退候補、OVR 49以下は全員FA、12人上限の根拠不明

**改善案:**

```
1. 引退判定:
   - wear ≥ 70 OR age ≥ 28 → 引退確率 = 0.3 + (wear/150) + (age-28)*0.05
   - wear < 70 AND age < 28 → 引退判定スキップ

2. ライバル団体移籍:
   - OVR ≥ 40（現行50→40に緩和）
   - 候補団体: ロスターがCAP未満の団体（現行の固定12→各団体のCAP値を参照）
   - 移籍確率: 0.5 + (ovr - 40) * 0.01（OVR高いほどライバル団体が欲しがる）

3. FA:
   - 上記に該当しない場合
```

**根拠:**
- age 28: このゲームの選手は17歳前後で入団、キャリア10年程度が標準。28歳は中堅後期
- OVR 40: 入団時OVR 30前後なので、OVR 40は「多少育った選手」。他団体が興味を持つ最低ライン
- wear 70: 現行50は低すぎる。wearシステム全体との整合性を要確認

#### B-2. 交渉B成功率の再設計

**現行の問題:** 実質コイントス

**改善案:** ギャップ比率を成功率に反映

```
successRate = 0.60                          // ベースを50→60に引き上げ
  + (trust - 30) * 0.02                    // trust寄与を倍に
  + gapSeverity                             // ギャップが小さいほど交渉しやすい
  + 特性補正

gapSeverity:
  gap < 1.1  → +0.10（ギャップなし、交渉しやすい）
  gap 1.1〜1.3 → 0（中立）
  gap ≥ 1.3  → -0.10（ギャップ大、選手の不満が強く交渉しにくい）
```

**意図:** プレイヤーが給与ギャップを放置した度合いが交渉難易度に直結する。
