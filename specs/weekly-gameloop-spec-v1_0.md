## 設計原則

1. **判断は興行に集中** — 練習管理は自動化し、プレイヤーの主な判断ポイントを興行カード編成に絞る
2. **単調作業を排除** — デフォルトスケジュール＋スキップ進行で毎週の手動操作を最小化
3. **2週サイクルが基本リズム** — 非興行週（準備）→ 興行週（本番）の繰り返し
4. **序盤からカードが組める** — フリー選手システムにより少人数ロスターでも興行が成立
5. **Q末にクライマックス** — 12週ごとの特別興行がゲームのリズムを生む

### §1.4 オフシーズン（4週間）

シーズン間に自動処理＋簡易操作を行う期間。

| 処理 | タイミング | 内容 |
|------|:---------:|------|
| コンディション回復 | 自動 | 全選手のコンディションが基本値に回復（§1.2 of condition-spec参照） |
| 怪我回復 | 自動 | 離脱期間の消化。残週がオフ期間内に収まれば復帰 |
| 引退判定 | 自動＋確認 | 年齢・古傷・後遺症に基づく判定。引退候補をプレイヤーに提示 |
| **AI団体シーズン末処理** | **自動（第1〜2週）** | **AI選手の成長・衰退・人気・引退・スカウト・AI間移籍・rating再計算。rival-org-spec §4** |
| 契約更新 | プレイヤー操作 | 選手の給与テーブル再計算。高額選手のリリース判断 |
| スカウト | プレイヤー操作（第2週） | 入団テスト結果を受けて指名。scout-system-spec参照 |
| **引き抜きウィンドウ** | **プレイヤー操作＋自動（第3週）** | **AI選手の引き抜き（年1名）＋プレイヤー選手の流出判定。rival-org-spec §7** |
| フリー選手入れ替え | 自動 | プールの一部が入れ替わる（引退＋新規追加） |
| 施設投資 | プレイヤー操作 | オフ中にアップグレード可能 |
| シーズン総括レポート | 表示 | 成績・収支・MVP・ベストバウトなどのまとめ |

## §2 1週間のフェーズ構成

### §2.1 興行週と非興行週

ゲームは**興行週と非興行週を交互に繰り返す**。操作量は大きく異なる。

#### 非興行週（偶数ターン以外）

| フェーズ | 内容 | プレイヤー操作 |
|---------|------|:------------:|
| ① 選手管理 | 練習/プロモ/休養の指示 | **通常は自動**（変更したい選手のみ手動） |
| ② 週末処理 | コンディション変動・イベント発生・収支計算 | 閲覧のみ |

#### 興行週（2週に1回）

| フェーズ | 内容 | プレイヤー操作 |
|---------|------|:------------:|
| ① 選手管理 | 練習/プロモ/休養の指示 | **通常は自動** |
| ② 興行準備 | 会場選択・マッチカード編成 | **★ メイン操作** |
| ③ 試合実行 | バトルエンジンによる試合処理 | 観戦（自動 or 詳細表示） |
| ④ 週末精算 | 試合結果・MQ・人気変動・収支・イベント | 閲覧＋判断（怪我対応等） |

### §2.2 フェーズ詳細

#### ① 選手管理フェーズ

| 項目 | 仕様 |
|------|------|
| 基本動作 | デフォルトスケジュールに従って**自動実行** |
| 手動介入 | 変更したい選手のみタップして指示を上書き |
| 選択肢 | 練習（パラメータ成長）/ プロモ（人気UP）/ 完全休養（成長ゼロ・回復最大） |
| 自動休養 | コンディションが設定値以下の選手は自動で完全休養（condition-spec §3.5） |
| 怪我中 | 軽傷＝プロモのみ可。中傷・重傷＝一切不可（condition-spec §10.2） |

#### ② 興行準備フェーズ（興行週のみ）

| 項目 | 仕様 |
|------|------|
| 会場選択 | 団体人気に応じて解放された会場から選択 |
| カード編成 | 後述の§4マッチカード編成を参照 |
| ゲスト選択 | フリー選手プールから出場選手を選択（§5参照） |
| プレビュー | 予想集客数・予想収入の概算を表示 |

#### ③ 試合実行フェーズ

| 項目 | 仕様 |
|------|------|
| 処理 | バトルエンジン（battle-engine-spec-v4.0）に基づく自動処理 |
| 表示 | 試合ごとにダイジェスト or 詳細表示を選択可能 |
| 怪我判定 | 試合中にリアルタイム判定（condition-spec §5.3） |
| MQ算出 | 試合終了時に即時計算 |

#### ④ 週末精算フェーズ

| 処理 | 内容 |
|------|------|
| 試合結果 | 全試合の勝敗・MQスコア・ハイライトの表示 |
| 人気変動 | 個人人気・団体人気の増減 |
| Heat更新 | 団体Heatランクの変動 |
| コンディション | 試合消耗＋回復の適用 |
| 怪我報告 | 怪我の重症度・離脱期間の確定 |
| 収支報告 | チケット収入・グッズ・支出の精算 |
| イベント | ランダムイベント・因縁発生・後遺症発覚等 |

## §3 デフォルトスケジュール制

### §3.1 設計思想

> 毎週8〜10人の選手に「練習/プロモ/休養」を手動指定するのは単調作業になる。
> 基本は自動で回し、プレイヤーは「変えたい時だけ触る」方式にする。

### §3.2 デフォルトパターン

選手ごとに事前設定する行動パターン。いつでも変更可能。

| パターン名 | 行動 | 推奨対象 |
|:---------:|------|---------|
| 練習優先 | 通常：練習。コンディション低下時：自動休養 | 育成中の若手、伸び盛り |
| プロモ優先 | 通常：プロモ。コンディション低下時：自動休養 | 人気を稼ぎたい選手 |
| バランス | 興行週：プロモ。非興行週：練習。コンディション低下時：自動休養 | 多くの選手のデフォルト |
| 休養重視 | 通常：練習。コンディション60以下で自動休養 | 怪我がちな選手、ベテラン |

### §3.3 デフォルト設定のUI

| 項目 | 仕様 |
|------|------|
| 設定場所 | 選手詳細画面の「週間スケジュール」タブ |
| 初期値 | 全選手「バランス」 |
| 自動休養ライン | パターンごとに異なる（休養重視＝60、他＝30）🔧 |
| 手動上書き | 当該週のみ有効。翌週からデフォルトに戻る |

## §4 マッチカード編成

### §4.1 試合数

会場規模に連動。プレイヤーが±1の範囲で調整可能。

| 会場ランク | 基本試合数 🔧 | 調整可能範囲 |
|:---------:|:-----------:|:----------:|
| 公民館 | 3 | 2〜4 |
| 小ホール | 3 | 2〜4 |
| 中ホール | 4 | 3〜5 |
| アリーナ | 5 | 4〜6 |
| 大会場 | 5 | 4〜6 |
| ドーム | 6 | 5〜7 |

| 興行種別 | 試合数補正 🔧 |
|---------|:----------:|
| 定期興行 | 基本試合数 |
| 特別興行 | 基本試合数 **+1** |
| PPV | 基本試合数 **+2** |

### §4.2 試合枠の構成

試合枠にはランクがあり、上位枠ほど集客・MQへの影響が大きい。

| 枠 | 名称 | 集客への影響 🔧 | MQボーナス 🔧 |
|:--:|:----:|:-------------:|:----------:|
| 1 | メインイベント | ×1.5 | +10 |
| 2 | セミファイナル | ×1.2 | +5 |
| 3〜 | アンダーカード | ×1.0 | +0 |

### §4.3 メインイベント選定ルール

| 項目 | 仕様 |
|------|------|
| 選定 | プレイヤーが自由に決定 |
| ペナルティ | メインに配置した両選手の**個人人気合計**が一定未満の場合、集客にペナルティ 🔧 |
| ペナルティ閾値 | 両者人気合計 < 40 の場合、集客 ×0.8 🔧 |
| タイトルマッチ | メイン枠に配置するとMQボーナスさらに +5 🔧 |

### §4.4 推奨カードシステム

#### 概要

興行準備画面で、システムが**推奨カード**を5〜8個提示する。プレイヤーはこれを採用してもよいし、完全に無視して自由にカードを組んでもよい。

#### 推奨カードの生成ソース

| ソース | 説明 | 期待度 |
|-------|------|:------:|
| ライバル因縁 | ライバル度が高いペア | ★★★ |
| リベンジマッチ | 前回敗者が再挑戦 | ★★〜★★★ |
| タイトル関連 | 挑戦権保持者 vs チャンピオン | ★★★ |
| 初対決 | 過去に対戦歴がないフレッシュな組み合わせ | ★★ |
| 実力伯仲 | Overall差が小さく接戦が期待できる | ★★ |
| ランダム提案 | 上記に該当しない組み合わせ | ★ |

#### 期待度ボーナス

| 期待度 | MQボーナス 🔧 | 集客ボーナス 🔧 |
|:------:|:----------:|:----------:|
| ★★★ | +10 | +10% |
| ★★ | +5 | +5% |
| ★ | +0 | +0% |

推奨カードを採用した場合にのみボーナスが発生。自由編成にペナルティはない。

### §4.5 出場選手の制約

| 制約 | 仕様 |
|------|------|
| 1興行1試合 | 1選手が同一興行で複数試合に出場することは不可 |
| 怪我離脱中 | 出場不可（強行出場オプションあり。condition-spec §5.5） |
| コンディション警告 | 40未満の選手にはカード編成時に警告表示（出場は可能） |
| フリー選手 | 1興行あたり最大3名まで 🔧 |

## §5 ゲスト参戦（フリー選手）システム

### §5.1 設計思想

> 序盤の少人数ロスターでもカードが組める。
> フリー選手に頼る弱小時代→自前の選手で回せる中堅団体、という成長感を生む。

### §5.2 フリー選手プール

| 項目 | 値 🔧 |
|------|------|
| プール人数 | **20名** |
| ランク分布 | 新人級×6、若手級×8、中堅級×5、主力級×1 |
| 成長 | **なし**（フリー選手は成長しない） |
| 入れ替え | **シーズンごと**（オフシーズンに2〜4名が引退、同数が新規追加） |
| 正式契約 | 可能（スカウト契約金が発生。契約後は自団体選手として成長対象になる） |

### §5.3 出場料

| フリー選手ランク | 出場料（万/試合）🔧 |
|:--------------:|:----------------:|
| 新人級（Overall〜49） | 10 |
| 若手級（Overall 50〜64） | 20 |
| 中堅級（Overall 65〜79） | 40 |
| 主力級（Overall 80〜） | 80 |

### §5.4 フリー選手の制約

| 制約 | 仕様 |
|------|------|
| 1興行あたり上限 | **3名**まで 🔧 |
| メインイベント | フリー選手をメインに起用可能だが、自団体選手を最低1名メインに配置する必要あり |
| 人気貢献 | フリー選手の個人人気は**集客に反映されない**（自団体ファンが付いていないため） |
| コンディション | フリー選手は常にコンディション70固定（管理不要） |
| 怪我 | フリー選手も怪我しうるが、治療費はプレイヤー負担ではない。次回以降一定期間利用不可になるのみ |

### §5.5 他団体レンタル → rival-org-spec-v1.0.md §8 で確定済み

| 項目 | 仕様 |
|------|------|
| 方向 | プレイヤー ← AI団体（借りるのみ） |
| タイミング | シーズン中いつでも申請可 |
| 期間 | 4週間固定 🔧 |
| 同時レンタル | 1名まで 🔧 |
| 対象 | AI団体のOverall 3位以下 |
| レンタル中 | 試合出場可、成長なし、怪我あり、トレーニング不可 |

詳細（料金・交渉成功率・レンタル中の扱い）は **rival-org-spec-v1.0.md §8** を参照。

## §6 週間スキップ機能

### §6.1 設計思想

> 非興行週を1週ずつポチポチ進めるのは単調作業の元凶。
> 判断が必要な場面でだけ止まり、それ以外はスキップする。

### §6.2 スキップモード

プレイヤーが2つのモードから選択可能。

| モード | 動作 | 推奨場面 |
|-------|------|---------|
| **次の興行まで進む** | 非興行週を一括スキップし、次の興行準備画面まで進む | 通常プレイ。最も頻繁に使うモード |
| **次のイベントまで進む** | 何かイベントが発生するまで進み、発生時に停止 | じっくりプレイ。細かい判断をしたい時 |

### §6.3 スキップ中の自動処理

| 処理 | 動作 |
|------|------|
| 選手管理 | デフォルトスケジュールに従って自動実行 |
| コンディション | 消耗・回復を自動計算 |
| 自動休養 | 設定値以下の選手は自動で完全休養 |
| 収支 | 週間固定支出・スポンサー収入を自動精算 |

### §6.4 スキップ停止条件（割り込みイベント）

以下のイベントが発生した場合、スキップを中断してプレイヤーに通知する。

| イベント | 停止 | 理由 |
|---------|:----:|------|
| 怪我の発生 | ✅ | 強行出場・カード変更の判断が必要 |
| 後遺症の発覚 | ✅ | 重大な情報 |
| 選手の引退通告 | ✅ | 引き留め判断 |
| スカウト機会 | ✅ | 入団テスト関連（フェーズ3） |
| 資金警告（500万以下） | ✅ | 経営判断が必要 |
| 赤字転落 | ✅ | 緊急事態 |
| 因縁イベント発生 | ✅ | ストーリー上の分岐 |
| タイトル防衛期限警告（残り3週） | ✅ | 防衛戦の編成判断が必要（title-system-spec §4.2） |
| 練習中の成長イベント | ❌ | まとめてレポート表示 |
| 通常のコンディション変動 | ❌ | まとめてレポート表示 |

### §6.5 スキップ後のサマリーレポート

スキップ完了後に「週間サマリー」を表示。

```
━━━ 第3週〜第4週 サマリー ━━━

【コンディション変動】
  山田: 75 → 65（練習消耗）
  佐藤: 40 → 65（完全休養で回復）⚠️ 自動休養発動

【成長】
  田中: PWR 62 → 63（+1）
  鈴木: SPD 70 → 71（+1）

【収支】
  スポンサー収入: +120万
  固定支出: −330万
  残高: 2,450万

【次の興行】
  第4週 定期興行 #2 → カード編成へ
━━━━━━━━━━━━━━━━━━━━
```

## §7 興行種別の詳細

### §7.1 定期興行

| 項目 | 仕様 |
|------|------|
| 頻度 | 2週に1回 |
| 年間回数 | 20回（特別興行・PPVを除く） |
| 会場 | プレイヤーが選択 |
| 試合数 | 会場連動（§4.1） |
| 消耗倍率 | ×1.0 |

### §7.2 特別興行

| 項目 | 仕様 |
|------|------|
| 頻度 | Q末に自動開催（Q1末・Q2末・Q3末） |
| 年間回数 | 3回 |
| 性質 | 通常興行の**置き換え**（追加開催ではない） |
| 会場 | プレイヤーが選択（通常より1ランク上の会場を推奨表示） |
| 試合数 | 基本試合数 **+1** |
| チケット単価 | 通常の **×1.3** 🔧 |
| 消耗倍率 | ×1.2（condition-spec §2.2） |
| タイトルマッチ | 優先的に組むことを推奨（推奨カードに表示） |

## §9 システム連携サマリー

| 連携先 | 週間ゲームループとの関係 |
|-------|----------------------|
| **経済** | 興行収入・支出の週次精算。会場選択・フリー選手出場料が経営判断 |
| **コンディション** | 2週サイクルの消耗と回復。デフォルトスケジュールの自動休養と連動 |
| **バトルエンジン** | 試合実行フェーズで呼び出し。カード編成がMQ・人気に直結 |
| **Heat** | 興行結果→Heat変動→次の興行の集客に影響する循環 |
| **育成** | 非興行週の練習で成長。デフォルトスケジュールで自動化 |
| **MQ** | 推奨カードのボーナス。メイン枠のボーナス。特別興行・PPVの補正 |
| **フリー選手** | カード編成時にプールから選択。序盤の穴埋め→成長に伴い依存度低下 |
