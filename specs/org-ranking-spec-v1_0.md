## 設計原則

1. **団体の「格」は選手の質で決まる** — チャンピオンの数、人気選手の数、人気の総和が評価の柱
2. **1位のAI団体を超えたらクリア** — 明確な勝利条件。ただしクリア後も永続プレイ可能
3. **借金1,000万超でゲームオーバー** — 経営破綻は即敗北
4. **AI団体は3〜4団体** — プレイヤー団体を含めて4〜5団体でランキングを競う

## §1 団体評価値（Organization Rating）

### §1.1 評価値の構成

団体の「格」を表す複合評価値。全団体（プレイヤー＋AI）で共通の計算式。

```javascript
orgRating = championScore      // チャンピオンの数と質（§1.2）
          + starPowerScore     // 人気選手の数（§1.3）
          + totalPopScore      // 人気の合計値（§1.4）
```

### §1.2 チャンピオンスコア

所属選手が保持しているタイトル（チャンピオンベルト）に応じた得点。

```javascript
championScore = Σ (各タイトルの格 × 保持ポイント)
```

| タイトル格 | ポイント 🔧 | 備考 |
|:---------:|:----------:|------|
| メジャータイトル | 30 | 団体の頂点。1つだけ |
| 準メジャータイトル | 20 | 2番目の格 |
| マイナータイトル | 10 | タッグ、新人王等 |

> **注**: タイトルの種類・数・取得条件は title-system-spec-v1.0.md で確定済み。
> タイトル設立はプレイヤーの任意操作。ゲーム開始時はchampionScore = 0。

### §1.3 スターパワースコア（人気選手の数）

一定以上の人気を持つ選手が何人いるかで得点。**スターの厚み**を評価する。

```javascript
starPowerScore = 0

for (each fighter in roster) {
  if (fighter.popularity >= 70) starPowerScore += 15  🔧  // トップスター
  else if (fighter.popularity >= 50) starPowerScore += 8  🔧  // スター
  else if (fighter.popularity >= 30) starPowerScore += 3  🔧  // 中堅
  // 30未満は加算なし
}
```

| 人気帯 | 呼称 | 1人あたりポイント 🔧 |
|:------:|:----:|:------------------:|
| 70〜 | トップスター | 15 |
| 50〜69 | スター | 8 |
| 30〜49 | 中堅 | 3 |
| 〜29 | 若手/無名 | 0 |

**例**: トップスター2人 + スター4人 + 中堅6人 = 30 + 32 + 18 = **80**

### §1.4 トータルポピュラリティスコア（人気の合計値）

ロスター全体の人気の総和。**団体の層の厚さ**を評価する。

```javascript
totalPopScore = round(Σ(全所属選手の popularity) × 0.1)  🔧
```

**例**: 選手20人、平均人気35 → 合計700 × 0.1 = **70**

### §1.5 評価値の計算例

**序盤のプレイヤー団体（ゲーム開始1シーズン目末）**:

| 要素 | 内訳 | スコア |
|------|------|:------:|
| チャンピオン | タイトル未取得 | 0 |
| スターパワー | スター0人、中堅3人 | 9 |
| トータルポピュラリティ | 選手10人、平均人気20 → 200×0.1 | 20 |
| **合計** | | **29** |

**中盤のプレイヤー団体（5シーズン目末）**:

| 要素 | 内訳 | スコア |
|------|------|:------:|
| チャンピオン | メジャー1 + マイナー1 | 40 |
| スターパワー | トップスター1 + スター3 + 中堅5 | 54 |
| トータルポピュラリティ | 選手15人、平均人気40 → 600×0.1 | 60 |
| **合計** | | **154** |

**強豪AI団体（1位）**:

| 要素 | 内訳 | スコア |
|------|------|:------:|
| チャンピオン | メジャー1 + 準メジャー1 + マイナー2 | 70 |
| スターパワー | トップスター3 + スター5 + 中堅8 | 109 |
| トータルポピュラリティ | 選手25人、平均人気45 → 1125×0.1 | 113 |
| **合計** | | **292** |

→ この例では、プレイヤー団体が**292を超えたらクリア**

## §2 団体ランキング

### §2.1 ランキング構造

```javascript
// 全団体の評価値を毎シーズン末に算出し、降順でランキング
rankings = allOrganizations
  .map(org => ({ name: org.name, rating: calcOrgRating(org) }))
  .sort((a, b) => b.rating - a.rating)
```

| 順位 | 団体 | 評価値 |
|:----:|------|:------:|
| 1位 | AI団体A（最強） | 292 |
| 2位 | AI団体B | 215 |
| 3位 | AI団体C | 170 |
| 4位 | プレイヤー団体 | 154 |

### §2.2 ランキング更新タイミング

| タイミング | 処理 |
|-----------|------|
| シーズン末（オフシーズン開始時） | 全団体の評価値を再計算し、ランキングを更新 |
| PPV終了後 | タイトル移動があった場合のみ、臨時更新 |

### §2.3 ランキングの表示

プレイヤーには以下が見える：

- 自団体の評価値と内訳（チャンピオン/スターパワー/トータルポピュラリティ）
- 他団体の評価値と順位（内訳は見えない or 概要のみ）
- 1位との差

## §3 勝利条件

### §3.1 クリア条件

```javascript
// シーズン末のランキング更新時に判定
if (playerOrg.rating > rankings[0].rating) {
  // rankings[0] = AI団体の1位
  triggerVictoryEvent()
}
```

**クリア条件**: シーズン末の評価値で、AI団体1位を**上回る**

- 同率は不可。**超えなければならない**
- クリア時にエンディングイベント（演出）が発生する
- **クリア後もゲームは継続可能**。永続プレイ

### §3.2 クリア後の世界

| 要素 | クリア後の動作 |
|------|-------------|
| ゲーム継続 | そのまま永続プレイ可能 |
| AI団体 | 引き続き変動する。再び抜かれることもある |
| 新たな目標 | 自然発生（連覇、全タイトル制覇、伝説の選手育成 等） |
| 2度目以降の1位 | 追加演出なし（初回クリアのみ特別） |

## §4 敗北条件

### §4.1 ゲームオーバー条件

```javascript
// 週末処理の最後に判定
if (playerOrg.debt > 10_000_000) {  🔧  // 借金1,000万円超
  triggerGameOverEvent()
}
```

**敗北条件**: 借金（負債）が**1,000万円を超えた**時点でゲームオーバー

### §4.2 借金の発生

economy-system-spec との連携:

```javascript
// 週末の収支処理
weeklyBalance = income - expenses

if (playerOrg.funds + weeklyBalance < 0) {
  // 資金がマイナスに → 借金として記録
  playerOrg.debt = abs(playerOrg.funds + weeklyBalance)
  playerOrg.funds = 0
}
```

| 状態 | 資金 | 借金 | 状況 |
|------|:----:|:----:|------|
| 健全 | 500万 | 0 | 問題なし |
| 赤字突入 | 0 | 200万 | 警告表示 |
| 危険 | 0 | 800万 | 深刻な警告 |
| ゲームオーバー | 0 | 1,001万 | 敗北 |

### §4.3 借金時の警告と救済

| 借金額 | 表示 🔧 | 制限 |
|:------:|--------|------|
| 0 | なし | なし |
| 1〜300万 | ⚠️「経営が赤字です」 | なし |
| 301〜600万 | 🔴「深刻な赤字です」 | 施設アップグレード不可 |
| 601〜999万 | 🆘「経営破綻寸前です」 | 施設アップグレード不可、S級コーチ雇用不可 |
| 1,000万超 | ゲームオーバー | — |

**救済手段**（借金を返済する方法）:
- 選手をリリースしてコスト削減
- コーチを解雇
- 施設をダウングレード（維持費削減）
- PPVで大きな収入を狙う
- プレイヤーの経営判断に委ねる（自動救済はなし）

## §5 AI団体

### §5.1 AI団体の基本設計

AI団体は3〜4団体。プレイヤー団体を含めて4〜5団体でランキングを競う。

```javascript
const AI_ORGS = [
  { id: "ai_org_s", name: "EMPRESS GRAND", tier: "S", championScore: 60 },  🔧
  { id: "ai_org_a", name: "NOVA IMPACT", tier: "A", championScore: 40 },  🔧
  { id: "ai_org_b", name: "CRESCENT RISE", tier: "B", championScore: 20 },  🔧
]
```

| AI団体 | ティア | championScore 🔧 | 役割 |
|--------|:-----:|:-------------------:|------|
| EMPRESS GRAND | S | 60 | **クリア目標**。業界の頂点。超えるのが最終目標 |
| NOVA IMPACT | A | 40 | 中堅強豪。中盤のライバル |
| CRESCENT RISE | B | 20 | 下位団体。序盤の目標 |
| プレイヤー | — | 0（タイトル未設立） | ゲーム開始時は最下位からスタート |

> championScoreは title-system-spec-v1.0.md §8.3 で定義。
> 評価値（orgRating）は実データから算出（rival-org-spec-v1.0.md §10）。初期評価値の固定値は廃止。

### §5.2 AI団体の評価値算出

~~簡易変動モデル（±15ランダム＋基準値回帰）は廃止。~~

AI団体も実データ（所属選手の能力値・人気値）からプレイヤー団体と同じ計算式（§1）で評価値を算出する。詳細は **rival-org-spec-v1.0.md §10** を参照。

AI団体の選手はシーズン末に一括で成長・衰退・人気変動が処理される。これにより評価値も自然に変動する。詳細は **rival-org-spec-v1.0.md §4** を参照。

## §6 ゲーム進行の全体像

### §6.1 典型的なゲーム進行

```
【序盤: 1〜3シーズン目】
  プレイヤー評価値: 20〜60
  ランキング: 4〜5位（最下位）
  目標: AI団体C（160）に追いつく
  状況: 選手が弱く、人気も低い。赤字にならないよう経営を安定させる

      ↓

【中盤: 4〜8シーズン目】
  プレイヤー評価値: 80〜180
  ランキング: 3〜4位
  目標: AI団体B（210）を超える
  状況: エースが一人前に。スター選手が出始め、タイトル獲得も

      ↓

【終盤: 9〜15シーズン目】
  プレイヤー評価値: 180〜300
  ランキング: 1〜2位
  目標: AI団体A（280）を超える
  状況: 複数のスター、タイトル保持。あと一歩で業界の頂点

      ↓

【クリア】
  評価値がAI団体Aを上回る → エンディングイベント

      ↓

【クリア後: 永続プレイ】
  目標: 自由。連覇、全タイトル制覇、伝説の選手育成、新人発掘…
  AI団体は変動し続けるため、1位維持も挑戦になる
```

### §6.2 クリアまでの目安

| 項目 | 想定 🔧 |
|------|--------|
| クリアまでの目安シーズン数 | 10〜15シーズン |
| 1シーズンのリアル所要時間 | プレイスタイルによる |
| 最短クリア | 理論上8シーズン程度（最適プレイ + 運） |
| ゲームオーバーの頻度 | 序盤の経営ミスで発生しうる。中盤以降は稀 |
