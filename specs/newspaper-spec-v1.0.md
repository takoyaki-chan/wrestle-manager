## 0. この紙面の考え方

**枠を先に決めず、その週に起きたことの大きさが紙面の大きさを決める。**

固定面（毎週必ずある2面・3面・4面）は廃止した。特集は出る週にだけ出る。
静かな週は静かな紙面でよい——中身の無い記事で埋めない。

## 1. 面の構成

| 面 | 中身 | 出る条件 |
|---|---|---|
| 1面 興行 | トップ / 肩 / MVP小窓 / 準トップ / 小記事+短信 / 黒田コラム(最下段固定) / 目次 | 常時 |
| 2面 団体比較 | 4軸比較・エース対決・主力対決・黒田の論説 | **節目のみ**（§4） |
| 3面 因縁列伝 | 9象限分類 + h2h + 黒田叙述 | 語れる因縁がある週のみ |
| 4面 MVPレース | 順位・点差・narrative | 一面の小窓「詳細 ▶」から開いたときのみ |

判定は `_npFeatureOn(page)`（`src/ui-render.js`）。
**特集が出ない週に前回開いていた面のまま来ると空の紙面になるので、タブを描く前に1面へ戻す。**

## 2. ニュースバリュー採点（`Engine.newspaper.newsValue`）

```
最終点 = 基礎点(何が起きたか) + 主役補正(誰に起きたか) + 強度補正(どれくらい大きいか)
```

`generate()` のソート直前で**全記事へ一括適用**する。
`stories.push` は約25箇所に散っているので、各所で点を作ると必ず足し忘れる経路が生まれる。

### 2-1. 基礎点

`Engine.newspaper.PRIORITY`（約80種）。
**主役を種別へ焼き込んだ特例は作らない。** `topChampionInjury` は 305 → **140**（怪我の基礎点）へ分解し、
王者であることは主役補正が、離脱の長さは強度補正が担う。

### 2-2. 主役補正（`protagonistBonus`）

対象選手の「いま持っている注目」。**上位2属性だけ**を数える（1位 + 2位×0.5、上限 **+120**）。
全部盛りで無限に跳ねるのを防ぐための上限であり、外すと設計が壊れる。

| 属性 | 補正 |
|---|---|
| 団体王者（全団体） | +90 |
| MVPレース首位 / 2〜3位 / 4〜10位 | +80 / +55 / +30 |
| 団体のエース（org内OVR 1位） / 主力（トップ3） | +55 / +35 |
| 業界人気トップ3 | +45 |
| 当該シーズンの大会優勝者 | +40 |
| ルーキー逸材（超逸材ティアの1年目） | +35 |
| 連勝中（5連勝以上、連勝数で微増・上限+15） | +25〜 |
| 派閥リーダー | +20 |

参照は `buildValueContext(state)` で**1週につき1回だけ**作る。
MVPレース順位は**トップ10しか無く、1週古い**（recalc は advanceWeek 側）。

### 2-3. 強度補正（`intensityBonus`）

| 対象 | 増減 |
|---|---|
| 怪我: 全治週数 | +4×週数（上限 +60） |
| 連勝: 団体記録との距離 | 更新 +40 / 王手 +20 |
| 王座: 初戴冠 / 長期政権（3度防衛以上）の陥落 | +30 |

**MQ の「記録更新 +80」は足さない。** `mqAllTimeRecord`/`mqTagRecord` は
基礎点（320/310）自体が記録更新を表しており、重ねると二重計上になる。

### 2-4. 枠の資格線（`slotOf`）

帯は重なってよい。固定するのは資格線だけ。

| 枠 | 資格線 |
|---|---|
| 一面トップ | **260以上 かつ 写真あり** |
| 肩・準特大 | 190以上 |
| 準トップ・中記事 | 100以上 |
| 小記事 | 50以上 |
| 短信 | それ未満 |

実際の枠は合成点の降順で上から詰める。同じ週にトップ資格が2本あれば2本目は自動的に肩へ回る。

### 2-5. 検算不変条件（`test/newspaper-news-value-test.js` で固定）

1. 無補正の日常ネタ・練習怪我は、強度を積んでも一面トップに届かない
2. 王者または MVP首位の長期離脱（全治10週+）は必ず一面トップ資格に届く
3. C帯基礎点（70以下）は主役補正が上限でも一面トップに届かない
4. トップ資格が同週に2本なら、2本目以降は下の枠へ落ちる

## 3. ニュース源

### 3-1. 週次スキャンで拾うもの（`scanRosterNews`）

**発生地点を追いかけない。** 怪我の付与も streak の加算も移籍の成立も呼び出し元が散っており、
そこへ1つずつ push を足すと必ず取りこぼす。**毎週スキャンして前回から変わったものだけ拾う。**
出した分は `G.newsSeen` に覚え、同じネタを毎週出さない。

| type | 基礎点 | 拾い方 |
|---|---|---|
| `longInjury` | 140 | 全治4週以上。残り週数は減るので「記録より増えていたら別の怪我」で判定 |
| `winStreakMilestone` | 100 | 5/10/15/20/25/30 連勝。強度補正で節目スケール(+4/連勝、5連勝=+0〜上限+40)と団体記録との距離(更新+40/王手+20)が乗る。2026-08-13裁定「ただの5連勝は一面ではない」: 5連勝は王手+主役補正上限でも240<top(260)で一面不可、記録絡みのみ一面資格 |
| `loseStreakMilestone` | 95 | 同じ節目 |
| `transferDone` | 150 | 所属が変わった週。**レンタルは数えない**。初回は基準づくりのみ |
| `retirementDeclare` | 180 | `retiredFighters` の新規。オフに確定するので開幕号に載る |

#### 3-1a. 引退記事の格付け（task-77・2026-08-02）

引退は基礎点(retirementDeclare 180 / aiAceRetirement 160 / aiRetirement 100)を変えず、
**強度補正に「引退の格」を積む**(`Engine.newspaper.retirementGrade`、上限+120)。

```
戴冠歴: reigns>=3 → +55 / 2 → +40 / 1 → +25 / 0 → 0
ピーク: peakOVR>=90 → +50 / 80-89 → +30 / 70-79 → +5 / それ未満 → 0
在籍:   seasons>=12 → +10
現役王者のまま引退: +45
```

同じ情報で本文ティアも変える: **L**(reigns>=2 または peakOVR>=90) / **A**(reigns>=1 または peakOVR>=80) /
**B**(peakOVR>=65) / **C**(それ以外)。各ティア3バリアント(`RETIREMENT_TEMPLATES`)を、
同一号に同ティアが複数出る場合は `pickRetirementVariant` が順繰りに回して同文の並びを避ける。
`{reigns}` を含むバリアントは reigns>=1 のときだけ選ぶ(無冠の看板/レジェンドには非使用バリアントを割り当てる)。

入口は `_newsRetirements`(AIシーズン末キュー→aiAceRetirement/aiRetirement)と
`retirementDeclare`(週次スキャン)の2系統。`aiInjuryRetirement`(怪我引退)は本文を独自の負傷フレーバーのまま
維持し、強度補正のみ格スコアを効かせる。peakOVR は `careerRecord.peakOVR`(衰え前のピーク)を使い、
現在OVR(衰え後)では代用しない。reigns は `careerRecord.totalTitleWins`。

#### 3-1b. 王座交代記事の組み立て式本文（task-80・2026-08-02）

対象は `aiChampionChange`(AI団体)と `playerTitleChange`(自団体、`titleChange` industry news event)。
点数(`aiChampionChange` 130 / `playerTitleChange` 180)は変えず、**本文だけ**
「リード+プロフィール+戴冠歴+締め」の組み立て式(`Engine.newspaper.composeChampionChangeBody`、
テンプレは `CHAMPION_CHANGE_TEMPLATES` 全26本)に拡充する。

- プロフィール文は**年齢帯4分割**で選ぶ: 若手(≤21)/伸び盛り(22〜24)/完成期(25〜29)/ベテラン(30+)。
  22〜24帯だけ専用テンプレが6本あり、慎重系3本・前向き系3本が混在する
- 戴冠歴文は初戴冠/複数回目で分岐。複数回目は `[取り返した版, 汎用版]` の順で並び、
  **同じ王座を過去にも保持していた場合のみ**「取り返した」版を選択肢に含める
  (`Engine.newspaper._isRepeatSameTitleReign`。`careerRecord.history` を `orgName`(例:「○○王座」)で
  スコープし、同じ orgName の `titleWin` が2件以上あれば再戴冠と判定する。beltId は常に `'world'` 固定で
  団体をまたいだ判別に使えないため使わない)
- ペイロードは `age` / `styleJa`(`Engine.newspaper.STYLE_JA` で英字styleを和名変換) /
  `titleReigns`(`careerRecord.totalTitleWins`、今回の戴冠を含む) /
  `careerSeasons`(`(careerSeasons||0)+1`、今シーズンを含む在籍年数)を持つ。
  AI側は `recordTitleWin` 適用後の roster から、自団体側(`Engine.title.crownChampion`)も
  `recordTitleWin` 適用後の `newRoster` から引く(=どちらも今回の戴冠が反映された値)
- パーツ選択は `(season*131 + week*17 + fighterId)` を種にした擬似ランダム(乱数は使わない)。
  同じ組文が続かないようにキャラ・週で散らす
- 組み立てに必要な情報が無い場合(自団体側で `age` が取れない等)は旧・単文テンプレへフォールバックする

### 3-2. 特別興行の事前記事

**「事前の記事は、下手をすると結果の記事以上の注目度があるものです、新聞では」**（Keisuke）。

`tenchosenAnnounce` 300 / `autumnWarAnnounce` 230 / `springTagAnnounce` 220（結果と同じ帯）。

本文には `eventPreviewParagraph` が優勝候補3名と注目カードを足す。
**並びは OVR ではなく「見えている実績」**（`eventContenders`）——
王座 / MVPレース順位 / 業界人気 / 過去大会の優勝 / 今季の連勝。
生の OVR・ステータス・trainCap・見立ての内部値は**一切見ない**（隠しステが読めると冷める）。
**断定しない**（記者の予想であって結果ではない）。語れる実績が無ければ候補に挙げず、素材が無ければ段落ごと出さない。

> 「業界人気トップN」は母数の下限を切る（トップ3は全団体10人以上、トップ10は25人以上）。
> 8人しかいない世界で「業界屈指の人気」と書くと嘘になる。

### 3-3. ドラフト総括（`draftRoundup` 150）

団体ごとの記事とは別に、指名全体を1本で振り返る。**並びは見立てティア**（`assessedTier`）で、
能力値の降順にしない。同ティア内は id 昇順（乱数を使わないので同じドラフトなら毎回同じ並び）。

#### 3-3a. 自団体ドラフト1面（`draftPlayerResult` 165、task-77・2026-08-02）

本文は「リード文+注目選手文(1〜2名)+締め文」の組み立て式（`Engine.newspaper.composeDraftPlayerResult`）。
注目選手は獲得選手を `assessedTier` 降順で見て、superElite/eliteがいれば2名目まで、
promising以下しかいなければ1名だけ。raw/material しかいない年は注目選手文を出さない
（リード+締めの2部構成に落ちる）。同一記事内で2名に言及する場合、同ティアでも必ず別バリアントを使う。
内部数値(pot/trainCap/OVR)は一切使わない — 使うのは `assessedTier`/年齢/身長/スタイルだけ。

### 3-4. 静かな週の読み物（後追い記事）

**一面トップ資格が1本も無い週にだけ**1本足す。**捏造禁止（実話主義）。**
素材は直近1〜4週の `careerRecord.history` といまのロスター状態だけ。

| 元イベント | type | 基礎点 |
|---|---|---|
| ブレークスルー | `followUpBreakthrough` | 115 |
| 記録樹立・戴冠 | `followUpRecord` | 112 |
| デビュー・移籍から数週 | `followUpNewcomer` | 108 |
| 進行中の連勝 | `followUpStreak` | 105 |

**同じ選手を読み物にする間隔は8週**（`FOLLOWUP_COOLDOWN`）。
連勝は「継続状態」であって出来事ではないので、これが無いと同じ選手の同じ記事が毎週出る
（初版は実測で**一面の40%**を占めた）。
クールダウンの記録は `publish` 側で行う——`generate()` は状態を書かない純粋関数のままにする。

**対応する出来事が無い週は作らない。** 紙面が薄い号があってよい。

## 4. 特集の発火条件

| 特集 | 条件 |
|---|---|
| 2面 団体比較 | **節目主義**。シーズン開幕号 / 総括号（W47以降）/ 対抗戦・4団体戦の前後 / 春タッグ前後。**業界順位の入れ替わりは主トリガーにしない**（希少なので、起きた週は一面側で加点されて上がる） |
| 3面 因縁列伝 | `_pickRivalryFeatured` が拾えた週のみ |

### 因縁列伝の見出し（N-6 / N-7）

- **見出しは1本**。カテゴリラベル（kicker）+ 大見出しのみ。サブ見出しは撤去した（大見出しの言い直しだった）
- **見出しと本文は1本の抽選値から引く**。`headlines[k]` と `bodies[k]` を対にして編集できる
  （本数が違うので k はそれぞれの長さで折り返す）。本文の残り2本は別種で埋める

## 5. MVPレース

- 固定4面は廃止。一面の肩記事下に小窓（首位3名+点差、4〜5位は1行）→「詳細 ▶」で開く
- **4位以下の本文には因縁の話を書かない**（N-12）。`_composeChaseLine` が
  「この順位にどう食らいついているか」だけで構成する:
  追う側か逃げる側か / 点差の詰まり方 / 残り週数

## 6. 写真ルール

優先順は **人物写真（アッパー）→ 記事用の汎用画像 → 写真なし**（`_npPhotoBg(id, story)`）。
人物写真が最優先で、逆順にすると顔が出なくなる。

- 人物写真は**反転禁止**。トップ 190×228 / 肩 84×126 / 小 46×66
- 汎用画像は `image/news/`。**9カテゴリ×3枚＝27枚**、256×384 webp / 40KB以内。
  1カテゴリ3枚を週で回すので同じ写真が続かない
- 記事種別→カテゴリの対応表は `NP_GENERIC_PHOTO`（`src/ui-render.js`）
- **割り当ての無い記事では無理に画像を出さない**
- 配布は `assetDirectories: ["image"]` の再帰コピーで入る（manifest への個別追記は不要）

> 綴り違いは黒い枠になって初めて気づくので、
> **参照先が実在すること**を `test/newspaper-generic-photo-test.js` が毎回検査する。

## 7. 文章のルール

- **格言・慰め・断定を書かない。** 記者の事実記述にする
- プレイヤー向けに内部語（condition / orgPop / trainCap）を出さない
- 大会名をセリフ内で連呼しない
- 見出し・本文とも `NEWS_HEADLINE_TEMPLATES`（`src/data.js`）に置く。
  **点だけ足してテンプレを作らないと、紙面には一行も出ない**
- **記事の地の文に `OVR` / `MQ` の英字トークンを出さない**（task-80・2026-08-02）。
  「OVR78」「（MQ78）」のような生表記は「総合力78」「（試合評価78）」へ日本語化するか、削除する。
  数値そのもの・点数・週数・回数はOK。**例外**は MVPレース欄・戦力レーダー・fact-item バッジのような
  「表・数字欄」——ラベル付きの数値表示は現状維持でよい。対象はあくまで**文章として読ませる地の文**
  （新聞1〜4面の story 本文、`_NEWSPAPER_HEADLINES`/`_NEWSPAPER_ARTICLES`（`src/app.js`）、
  `KURODA_SPOTLIGHT`（`src/kuroda-text.js`、2面 団体比較の寸評）、MVPレースの叙述文
  （`Engine.mvpRace.generateNarrative`/見出し生成）ほか）

## 8. 実装の所在

| もの | 場所 |
|---|---|
| 採点・ニュース源・特集判定の材料 | `src/management.js` `Engine.newspaper` |
| 週次スキャン | `Engine.newspaper.scanRosterNews`（tickWeek 内、新聞生成の直前） |
| 連勝の団体記録 | `Engine.streak`（refresh は**新聞生成の後**。先に更新すると自分自身と比べてしまう） |
| 業界人気トップN | `Engine.popularity.getIndustryTopIds` |
| 描画 | `src/ui-render.js` `_npFrontV3` / `_npRenderPage2..4` / `.np-*`（`src/index.html`） |
| 記事テンプレ | `src/data.js` `NEWS_HEADLINE_TEMPLATES` |
| 黒田の在庫 | `src/kuroda-text.js` |

### 文字のルール（1面から2面以下へ）

- **明朝は見出しだけ。本文はゴシック**（`.np-paper` の `Noto Sans JP` を継承）
- 数字・ローマ字専用の表示（GRADE / VS / 点数）だけ Bebas Neue・Oswald。
  **日本語が入る要素に Latin 専用フォントを当てない**（和文だけブラウザ既定に落ちて細くなる）
- 両方向を `test/newspaper-font-latin-leak-test.js` が固定する。
  片方だけ縛ると、次に触った人が全部ゴシックにして新聞に見えなくなる

## 9. 実測（40シーズン・1298号 / `WM_FRONTPAGE_FIXTURE=1`）

| | 再設計前 | 現在 |
|---|---|---|
| 一面トップの合成点 中央値 | 163 | **194** |
| `aiShowHighlight`（基礎点45）が一面 | 27.8% | **4.9%** |
| 一面が成立する号 | 1215 | 1298 |

資格線260以上は約22%。**これは設計どおり**——「王者の全治14週=286」級の出来事は毎週起きない。
残りの静かな週は §3-4 の読み物が受け持つ。ここを埋めるために点を水増しすると、
「数値は嘘をつかない」という芯が壊れる。
