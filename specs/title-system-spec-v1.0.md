## 設計原則

1. **タイトルは3階級** — メジャー / 準メジャー / マイナー。管理負荷を抑えつつ、ゲームに十分な目標の階層を作る
2. **防衛義務で緊張感** — チャンピオンは定期的に防衛しなければベルトを失う
3. **挑戦権は実力＋ストーリーで決まる** — ランキング自動算出＋因縁・指名による割り込み
4. **自団体内で完結** — AI団体との対戦は⑨で拡張予約のみ。本specだけで機能する
5. **PPVが最大の舞台** — 全タイトルマッチがPPVに集まり、シーズンのクライマックスを演出

## §1 タイトル一覧

### §1.1 3階級のタイトル

| # | タイトル格 | 名称（デフォルト） | championScore 🔧 | 性格 |
|:-:|:---------:|:-----------------:|:----------------:|------|
| 1 | メジャー | 無差別級王座 | 30 | 団体の頂点。エースの証。最も集客力のあるベルト |
| 2 | 準メジャー | ハイパーファイト王座 | 20 | 中堅〜スターの目標。メジャーへの登竜門 |
| 3 | マイナー | ライジング王座 | 10 | 若手〜中堅の目標。実力証明の場 |

> **名称はプレイヤーがいつでも自由に変更可能**（選手管理画面 or 団体設定画面から）。
> 上記はデフォルト名。シーズン中でも何度でも変更できる。

### §1.2 タイトル設立条件

ゲーム開始時にはタイトルは存在しない。団体の成長に応じて設立する。

| タイトル | 設立条件 🔧 | 設立コスト 🔧 |
|---------|-----------|:----------:|
| マイナー | 所属選手 **8名以上** | 100万 |
| 準メジャー | 所属選手 **12名以上** ＋ マイナー王座が存在 | 200万 |
| メジャー | 所属選手 **16名以上** ＋ 準メジャー王座が存在 ＋ 団体人気 **30以上** | 300万 |

- 設立時に**初代王者決定トーナメント**が自動開催される（§3参照）
- 設立はプレイヤーの任意操作。条件を満たしても自動設立はしない
- 一度設立したタイトルは廃止できない（選手数が条件以下になっても存続）

### §1.3 ジュニアチャンピオン（シーズン限定称号）

| 項目 | 仕様 |
|------|------|
| 種別 | **タイトル（ベルト）ではない**。シーズン限定の称号 |
| デフォルト名 | ジュニアチャンピオン（プレイヤーがいつでも変更可能） |
| 開催時期 | Q4（weekly-gameloop-spec §1.3） |
| 対象 | 20歳以下の自団体選手 |
| 形式 | トーナメント（§3.3で詳細） |

| 該当者不足 | 対象者が4名未満の場合、その年は開催しない |

## §2 挑戦者決定システム

### §2.1 タイトルランキング

各タイトルごとに、挑戦権の優先順位を示す**タイトルランキング**を自動算出する。

```javascript
function calcTitleRanking(title, roster) {
  const eligible = roster.filter(f => isEligible(f, title))

  return eligible.map(fighter => ({
    fighter,
    score: calcChallengerScore(fighter, title)
  })).sort((a, b) => b.score - a.score)
}
```

### §2.2 挑戦者スコア

```javascript
function calcChallengerScore(fighter, title) {
  let score = 0

  // 直近シーズンの戦績（勝利数ベース）
  score += fighter.seasonWins × 10                   🔧
  score += fighter.seasonLosses × (-3)               🔧

  // 直近の連勝ボーナス
  score += min(fighter.currentWinStreak, 5) × 5      🔧  // 上限5連勝

  // 個人人気
  score += fighter.popularity × 0.3                  🔧

  // タイトル格に応じた実力フィルタ
  score += fighter.overall × titleOverallWeight(title) 🔧

  return round(score)
}
```

| タイトル格 | overallの重み 🔧 | 想定される上位選手 |
|:---------:|:---------------:|----------------|
| メジャー | 0.5 | Overall 80〜のエース級 |
| 準メジャー | 0.4 | Overall 65〜の中堅〜主力 |
| マイナー | 0.3 | Overall 50〜の若手〜中堅 |

### §2.3 挑戦者の決定フロー

```
1. タイトルランキング1位 → 自動的に「第1挑戦者」に認定
2. プレイヤーが指名 → ランキング外の選手を挑戦者に指定可能（§2.4）
3. 因縁補正 → ライバル因縁がある場合、推奨カードとして提示（§2.5）
```

### §2.4 プレイヤー指名制度

| 項目 | 仕様 |
|------|------|
| 指名権 | プレイヤーはランキングに関係なく任意の選手を挑戦者に指名できる |
| 制約 | 指名された選手のchallengerScoreがランキング1位の**50%未満**の場合、「格落ち警告」が表示される 🔧 |
| 格落ちペナルティ | 警告を無視して組んだ場合、そのタイトルマッチのMQボーナスが半減 🔧 |
| 意図 | ストーリー重視のカード編成を許容しつつ、実力差がありすぎる凡戦を抑止 |

### §2.5 因縁による挑戦権割り込み

| 項目 | 仕様 |
|------|------|
| 発生条件 | チャンピオンとのライバル因縁度が一定以上（フェーズ4 ⑪で詳細化） |
| 効果 | 推奨カードに「因縁タイトルマッチ」として★★★で表示 |
| ランキング | 因縁挑戦はランキングを無視して組める（格落ちペナルティなし） |
| 頻度 | 因縁は自然発生するため、プレイヤーがコントロールしきれない面白さ |

### §2.6 挑戦資格

| タイトル格 | 最低Overall 🔧 | 最低シーズン勝利数 🔧 | 備考 |
|:---------:|:------------:|:------------------:|------|
| メジャー | 70 | 3勝 | エース級のみ |
| 準メジャー | 55 | 2勝 | 中堅以上 |
| マイナー | 40 | 1勝 | 若手でも挑戦可能 |

- チャンピオン自身はランキングから除外
- 怪我離脱中の選手はランキングに残るが、挑戦不可
- フリー選手はタイトルに挑戦できない

## §3 トーナメント

### §3.1 初代王者決定トーナメント

タイトル設立時に開催される特別トーナメント。

| 項目 | 仕様 |
|------|------|
| 参加者数 | **8名**（候補が5〜7名の場合は **4名**に縮小）🔧 |
| 選出方法 | 挑戦者スコア上位から自動選出。プレイヤーが2名まで入れ替え可能 |
| 形式 | シングルエリミネーション（8名=3回戦、4名=2回戦） |
| 開催 | **特別興行またはPPVで決勝を実施**。準決勝以前は通常興行で消化 |
| スケジュール | 設立宣言→次の興行から1回戦開始。8名=最短3興行（6週）、4名=最短2興行（4週）で決着 |
| 最低人数 | 候補が4名未満の場合、設立条件を満たしていてもトーナメント開催不可（候補が揃うまで待つ） |
| 試合処理 | 通常のバトルエンジンで処理。MQ・人気変動あり |
| 集客ボーナス | トーナメント試合は集客 **×1.2** 🔧 |

### §3.2 トーナメントのスケジュール例

```
Week 2:  興行 → トーナメント1回戦（4試合。うち2試合をこの興行で消化）
Week 4:  興行 → トーナメント1回戦（残り2試合）
Week 6:  興行 → 準決勝（2試合）
Week 8:  興行 → 決勝（1試合。メインイベントに配置推奨）
```

> トーナメント試合は通常のカード編成枠に組み込む。専用興行ではない。
> プレイヤーがどの興行に組むかを決められる（ただし順序は固定）。

### §3.3 ジュニアチャンピオントーナメント

| 項目 | 仕様 |
|------|------|
| 開催時期 | Q4（第37〜48週の間） |
| 参加資格 | 20歳以下の自団体選手 |
| 参加者数 | 対象者全員（4〜8名）。4名未満の場合は開催しない 🔧 |
| 形式 | 4名=準決勝から。5〜8名=シングルエリミネーション |
| 決勝 | PPV（Q4末）のアンダーカードに配置推奨 |
| 優勝特典 | 人気+10、次シーズン成長率×1.1（§1.3） |
| championScore | なし（称号であってベルトではない） |

## §4 防衛義務

### §4.1 防衛ルール

| 項目 | 仕様 |
|------|------|
| 防衛期限 | 前回防衛（or 戴冠）から **12週以内** に次の防衛戦を行うこと 🔧 |
| カウント開始 | 戴冠した週 or 前回防衛戦の週 |
| PPVリセット | PPVで防衛した場合、次の12週カウントが新シーズンのQ1から開始 |
| 違反 | 12週を過ぎても防衛戦を行わない場合 → **ベルト剥奪**（§4.3） |

### §4.2 防衛戦の予告と警告

| 残り週 | 表示 |
|:------:|------|
| 6週以内 | ⚠️「（タイトル名）の防衛期限が近づいています」 |
| 3週以内 | 🔴「（タイトル名）の防衛期限まであと○週！」 |
| 期限超過 | 🆘 → 自動剥奪処理 |

防衛戦の予告はスキップ中の**割り込みイベント**としても機能する（残り3週で停止）。

### §4.3 ベルト剥奪

| 剥奪条件 | 処理 |
|---------|------|
| 防衛期限超過 | 自動剥奪。タイトルランキング1位が新チャンピオンに認定（試合なし） |
| 重傷以上で長期離脱 | 離脱期間が**12週以上**の場合、自動剥奪 🔧 |
| 引退 | 即時剥奪。タイトルランキング1位が新チャンピオン |
| リリース（契約解除） | 即時剥奪。タイトルランキング1位が新チャンピオン |

> 剥奪によるチャンピオン認定は「試合なし」で行われるため、MQ・集客のボーナスは発生しない。
> ストーリー上の盛り上がりに欠けるため、プレイヤーはできるだけ防衛戦を組むべき。

### §4.4 返上

| 項目 | 仕様 |
|------|------|
| 操作 | プレイヤーが任意のタイミングでベルトを返上できる |
| 用途 | 上位タイトルに集中させたい場合、コンディション管理等 |
| 処理 | 返上→タイトルランキング1位と2位で**王座決定戦**を次の興行で実施 |
| 制約 | PPVの2週前以降は返上不可（PPVのカード編成を保護） |

## §5 タイトルマッチのルール

### §5.1 タイトルマッチの試合ルール

| 項目 | 仕様 |
|------|------|
| 試合形式 | 通常のバトルエンジン処理（battle-engine-spec-v4.0） |
| 特別ルール | タイトルマッチ専用の特別ルールはなし（将来拡張可能） |
| 引き分け | 引き分けの場合、**チャンピオン防衛**（挑戦者が「勝たなければならない」） |
| ダブルKO | ダブルKOの場合もチャンピオン防衛 |

### §5.2 タイトルマッチのMQ・集客ボーナス

既存specとの整合。weekly-gameloop-spec §4.3, §4.4 で予約済みのボーナスを確定する。

| ボーナス源 | 値 | 条件 |
|-----------|:-----:|------|
| タイトルマッチMQボーナス | MQ **+5** | タイトルマッチであること自体のボーナス（v4.2: 旧複合ボーナスを一律+5に簡素化） |
| タイトルマッチ集客ボーナス | 集客 **×1.15** | タイトルマッチの集客乗数（attendBonus: 1.15） |

> **v4.2変更**: 旧仕様のメイン枠+5/推奨カード+10/基本+8/メジャー追加+5の4重ボーナスは廃止。タイトルMQは一律+5に簡素化。MQ外部ボーナスはMQ_EXTERNAL_CAP=12の上限あり。

**レンタル選手のタイトル制限**: レンタル選手（G.rentals）はタイトルマッチに出場できない。executeShow・toggleTitle・renderShowPrepの3箇所でisRentalチェックを実施。

### §5.3 タイトルマッチの配置ルール

| 興行種別 | タイトルマッチの配置 |
|---------|-------------------|
| 定期興行 | 任意。0〜1試合が現実的 |
| 特別興行 | **推奨**。1〜2試合（推奨カードに表示） |
| PPV | **全タイトルマッチ必須**（weekly-gameloop-spec §7.3） |

#### PPVでの全タイトルマッチ必須ルール

| 項目 | 仕様 |
|------|------|
| 対象 | 設立済みの全タイトル |
| 配置 | メジャー→メインイベント、準メジャー→セミファイナル、マイナー→アンダーカード（推奨。変更可能） |
| 挑戦者 | タイトルランキング1位が自動エントリー。プレイヤーが変更可能（§2.4の指名制度） |
| タイトルが未設立 | その分の枠は自由カードになる。全タイトル未設立ならタイトルマッチ0でもPPV開催可能 |
| チャンピオン欠場 | チャンピオンが怪我離脱中の場合、ランキング1位vs2位の**暫定王座決定戦**を実施 |

## §6 暫定王座

### §6.1 暫定王座の発生条件

| 条件 | 処理 |
|------|------|
| PPV時にチャンピオンが怪我離脱中 | ランキング1位 vs 2位で暫定王座決定戦 |
| 防衛期限内にチャンピオンが試合不可能 | プレイヤー判断で暫定王座戦を設定可能 |

### §6.2 暫定王座のルール

| 項目 | 仕様 |
|------|------|
| championScore | 正規王座の **半分**（メジャー15/準メジャー10/マイナー5）🔧 |
| 統一戦 | 正規チャンピオン復帰後、**8週以内**に統一戦を実施すること 🔧 |
| 統一戦未実施 | 正規チャンピオンが剥奪され、暫定王者が正規認定される |
| 同時保持 | 同一タイトルに正規＋暫定は1人ずつまで |
| 表示 | UI上で「暫定」マークを明示 |

## §7 複数タイトル保持

### §7.1 ルール

| 項目 | 仕様 |
|------|------|
| 複数保持 | **可能**。1選手が複数タイトルを同時保持できる |
| 上限 | **2つまで** 🔧 |
| 防衛義務 | タイトルごとに個別に12週カウント |
| ダブルタイトルマッチ | 1試合で2つのベルトを同時に賭けることは**不可**。別々の試合が必要 |
| championScore | 保持タイトルすべてのポイントを加算 |

### §7.2 複数保持の戦略的意味

- **メリット**: championScoreが大幅増加。団体評価値に大きく貢献
- **デメリット**: 防衛義務が2倍。コンディション管理が困難。怪我リスク増

## §8 タイトル変動とランキング更新

### §8.1 org-ranking-spec との連携

タイトル移動時にorg-ranking-specのランキングを**臨時更新**する（org-ranking-spec §2.2）。

```javascript
function onTitleChange(event) {
  // event: 戴冠 / 防衛成功 / 陥落 / 剥奪 / 返上
  recalcChampionScore(event.organization)

  // ランキング臨時更新（PPV後 or タイトル移動時）
  if (event.type !== 'defense_success') {
    updateOrgRankings()
  }
}
```

### §8.2 championScore計算

```javascript
function calcChampionScore(org) {
  let score = 0
  for (const title of org.titles) {
    if (title.champion) {
      if (title.isInterim) {
        score += title.points × 0.5  // 暫定王座は半分
      } else {
        score += title.points        // 正規王座はフルポイント
      }
    }
  }
  return score
}

// 最大値: メジャー30 + 準メジャー20 + マイナー10 = 60
// AI団体Aの参考championScore: 70（メジャー30+準メジャー20+マイナー10×2と想定）
```

### §8.3 AI団体のchampionScore（⑨で詳細化するが、暫定値を設定）

AI団体はタイトルシステムを内部的に持たないが、championScoreとして固定的な値を持つ。

| AI団体 | ティア | championScore暫定値 🔧 | 内訳イメージ |
|--------|:-----:|:-------------------:|------------|
| AI団体A | S | 60 | メジャー+準メジャー+マイナー全保持相当 |
| AI団体B | A | 40 | メジャー+マイナー相当 |
| AI団体C | B | 20 | 準メジャー相当 |

> これらの値はAI団体の評価値変動（org-ranking-spec §5.2）の中で
> drift として含まれるため、独立して変動はしない。
> ⑨ライバル団体AI設計時に詳細ロジックを確定する。
