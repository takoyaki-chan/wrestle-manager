## 設計原則

1. **覗き見の窓** — プレイヤーが普段見えない選手の内面・関係を垣間見る
2. **押し付けない** — 週最大2件。情報過多にしない
3. **緊急は見逃さない** — embedded型は確実に表示。重大イベントを取りこぼさない
4. **キャラの声で伝える** — personality×archetypeで一人ひとり異なるセリフ

## §2 生成フロー

### §2.1 週次処理（tickWeek末尾）

1. **候補収集** — 全条件を判定し、該当するスナップショットを集める
2. **クールダウン除外** — CD中のスナップショットを除外（R3は例外: CD無視）
3. **分離** — embedded型とslot型を分ける
4. **重み付き抽選** — slot型から最大 **2件** 🔧 を選出
5. **テキスト生成** — personality×archetypeでセリフ解決
6. **クールダウン更新** — 発火した項目に6週CDを設定
7. **transientフラグクリア** — `_grievanceFlags`, `_relationshipFlags` 等をリセット

### §2.2 R3の特別処理

- bond高い仲間の退団/引退で**100%発火**
- CDを無視
- bond 75+: **モーダルダイアログ**（重要度が高い）
- それ以外: 通常のscene表示

## §3 クールダウン

| 項目 | 仕様 |
|------|------|
| 通常CD | **6週** 🔧 |
| R3（仲良し退団） | CDなし |
| embedded | CDなし |
| CD保存 | `_snapshotCooldowns` にペアキー（min>max）で保存 |
| 古いCDの削除 | 24週以上前のエントリは自動削除 |

## §4 テキストシステム

### §4.1 テキストカテゴリ

| カテゴリ | 視点 | 用途 |
|---------|------|------|
| scene | 三人称叙述 | 環境描写 |
| voice | 一人称独白 | キャラの内面 |
| staff | スタッフ観察 | 外部視点 |
| modal | モーダル専用 | R3の重要通知 |

### §4.2 Personality解決

personality値に基づいてセリフテンプレートを選択:
- 基本5種: normal / bold / quiet / earnest / emotional
- archetype上書き: ojousama / delinquent / seductive / cool / polite

### §4.3 変数展開

| 変数 | 内容 |
|------|------|
| `{name}` | 対象選手名 |
| `{name2}` | ペア相手名 |
