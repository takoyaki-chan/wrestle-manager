## 設計原則

1. **オリンピックイヤー** — 4年に一度だけ、年間最大イベントが特別な形に化ける。周期そのものが価値
2. **業界総力戦の尺** — 16名シングルエリミ15試合。通常年（7試合+頂上決戦）の約2倍の尺を持つ、4年に一度だけ許される大興行（2026-07-18 決定。v0.1の「通常PPVの尺を守る」8名案を破棄）
3. **優勝は記録と名誉** — 数値バフなし（2026-07-17 決定）。「4年に一度の覇者」はキャリアの勲章として経歴・年代記・殿堂に刻まれる
4. **実力がものを言う** — 全試合ビッグマッチルール。長尺で乱数のブレが収束し、実力差がシビアに現れる。番狂わせは起きにくいからこそ、起きたとき本物になる（2026-07-18 決定）

## §3 トーナメント

### §3.1 形式

| 項目 | 仕様 |
|------|------|
| 規模 | **16名シングルエリミネーション**（2026-07-18 決定、8名案から変更） |
| 試合数 | 1回戦8 + 準々決勝4 + 準決勝2 + 決勝1 = **15試合** |
| シード | エントリー確定時のOVR順。1vs16 / 8vs9 / 4vs13 / 5vs12 / 2vs15 / 7vs10 / 3vs14 / 6vs11 の標準ブラケット |
| 同団体対決 | 1回戦では可能な限り回避（シード近傍スワップで解消） |
| メイン | **決勝戦**（トーナメント年は頂上決戦を開催しない — 決勝が代替） |

### §3.2 試合条件・消耗

- **全試合ビッグマッチルール**（matchTier 2: `BIGMATCH_MAX_T` / `BIGMATCH_PHASES` / `BIGMATCH_ENG` 適用）。長尺ルールにより実力差が結果に反映されやすい（2026-07-18 明文化。通常PPVも tier 2 だが、本大会は1回戦から決勝まで全15試合を tier 2 固定とする）
- condition 初期80 / 怪我なし（イベント標準）
- ラウンド間の消耗は**全ラウンド持ち越し**（連戦消耗モジュール = autumn-gauntlet-war-spec §3、実測連動 B案）:
  - `wear = 12 + (1 - 残HP率) × 20`
  - ラウンド間 recovery = wear累計の **2/3 回復** / floor **50** 🔧
  - **注意**: v0.1（8名・最大3試合）で仮置きした回復2/3・floor50は、16名化で優勝者が最大4試合を戦うため再較正が必要。決勝が凡戦にならないラインを **auto-sim で決勝MQ分布を通常年PPVと比較**して決める
- 因縁MQボーナス等の試合処理は通常PPV準拠（applyPPVResults 系）

## §4 ポイント・報酬（2026-07-17 仮確定 → auto-sim 実測で最終調整）

### §4.1 対戦ポイント

| 試合 | 対戦pt |
|------|:------:|
| 決勝 | 勝者 +7 / 敗者 -7（通常年の頂上決戦 `summit` の載せ替え） |
| 1回戦〜準決勝 | 移動なし 🔧 |

### §4.2 シーズン実績ポイント

| イベント | 加点 | アイテムID |
|---------|:----:|-----------|
| トーナメント優勝者所属団体 | **20pt**（通常年の PPV 15pt の代わり） | `ppvT_${season}` |

減衰モデル（1年満額→×0.5/年）により「オリンピック覇者の栄光も次の大会までに色褪せる」— 4年周期と噛み合う設計。

### §4.3 殿堂ポイント

| 実績 | pt |
|------|:--:|
| トーナメント優勝 | **+8**（通常年の頂上決戦勝利 5 の上位。4年に一度しか取れない最高峰） |

### §4.4 称号・記録（効果なし — 2026-07-17 決定）

- 優勝者に「第N回大会覇者」🔧名称未定。**大会名は日本語名とする**（2026-07-18 Keisuke 裁定、英語候補は破棄）。候補: 天頂戦 / 王冠祭 / 四年の頂 / 覇天祭（モックアップv0.3で切替比較可） — **数値効果は一切なし**。記録と名誉のみ
- `careerRecord.history` に記録:

```js
{ type: 'ppvTournament', season, result: 'champion'|'runnerUp'|'semiFinal'|'quarterFinal'|'firstRound' }
```

- 表示先: 選手詳細 / 経歴年表 / 殿堂ハイライト文 / 年代記

### §4.5 賞金 🔧

| 順位 | 賞金 |
|------|------|
| 優勝 | ¥3,000万 |
| 準優勝 | ¥1,200万 |
| ベスト4 | ¥500万（2名） |
| ベスト8以下 | なし |

※ 通常PPVの実装値 `PPV_PRIZE = { champion:2000, runnerUp:1000, semiFinal:500 }`（頂上決戦系・国庫収入）に対し、優勝1.5倍・準優勝1.2倍・ベスト4同額で整合確認済み（2026-07-18）。トーナメント年は PPV_PRIZE 系の支払いを行わず本表に置き換える。

## §6 演出（2026-07-18 UI方向決定 → 同日 画像文法追記）

- 開催年予告（シーズン開幕・新聞）+ **大会約1ヶ月前（Week 43〜44 🔧）にエントリーイベント**: 出場選手を自団体ロスターから選ぶ。枠数は団体順位連動（§2.1）。4年に一度の空気づくりとして通常PPVエントリーより一段重い演出にする 🔧 詳細は実装時
- **クライムライン型ブラケットUI で確定**（モックアップ採用。最新: `docs/ui/mockups/mockup-ppv-tournament-v0.3.html`）:
  - JTクライムライン（jtc-*一式）を大会色差し替え（`--jtc-color` → 金）で流用
  - 段構成: 頂上（👑覇者・決着まで空位）← 決勝 ← 準決勝 ← 準々決勝 ← 1回戦（8セル）
  - **段別の画像文法**（2026-07-18 Keisuke 裁定）: 1回戦・準々決勝 = 丸アイコン（小） / **準決勝以上 = JT準拠の 2:3 矩形アッパー画像**（準決勝 md 112px / 決勝 lg 132px / 頂上 150×225 相当）。勝者=大会色下ボーダー / 敗者=モノクロ落ち
  - **1回戦8セルの段組みは実装時判断** 🔧: 横スクロール / 2段折り(4+4) / 縮小8列 — モックは縮小8列+モバイル横スクロール
  - 勝者ライン点灯 / 決着時間+MQ表示 / シードチップ（1-16 / 8-9 …）を1回戦セルに表示
- **エンブレム画像**: 季節イベント（`image/emblem-spring.png` 等）と同様に大会専用エンブレムをヘッダー最上部に置く。**仮エンブレムをモックに配置済み（インラインSVG）→ 本番アセットは Keisuke が描き直して差し替え** 🔧（ファイル名は名称確定後）

- 優勝セレモニー: クライムライン頂上せり上がり → 優勝画面（称号線+光条。優勝者画像も 2:3 矩形の頂上様式）
- 大会名称: 🔧 Keisuke 裁定待ち（**日本語名**。候補4案をモックのプルダウンで比較可能）
- UI実装前に `docs/ui/03-screens/` に画面仕様書を起こす（docs/ui/ 手順）

## §6.5 関係性ドラマ（2026-07-18 方針決定・詳細DRAFT）

4年に一度の大舞台は関係性が動く場でもある。試合結果から絆/因縁が生まれ・激発展し、**セリフを交えたドラマ**として見せる。

### 方針（Keisuke 裁定）

- この大会の試合をきっかけに、良好な関係が生まれることも、悪い関係が激しく発展することもある
- セリフは**キャラクター属性（archetype 6種）ごとに書き分け**、「このキャラだから喋っている」感覚をプレイヤーに与える。テンプレ禁止
- スポットライト原則: 全カードに配らない。**1大会 1〜2件** 🔧 をその瞬間輝く（または軋む）ペアに当てる

### トリガー分類（叩き台 🔧 実装前に別途詰める）

| 分類 | 条件案 | 関係変化案 |
|------|--------|-----------|
| 名勝負 | 準決勝以上で MQ 閾値超え | 相互 rivalry+bond 上昇（好敵手系。M-CO1 好敵手認定との接続を検討） |
| 番狂わせ / 屈辱 | シード差の大きい敗北・ヒールの敗北 | 敗者→勝者の片方向 rivalry 激発展 |
| 同門対決の後遺症 | 同団体・同派閥対決の実現 | bond 低下 or 逆に深化（関係性・性格で分岐） |

### 実装接続（想定）

- 既存機構: relationships の bond/rivalry 2軸 / h2h.history / relationship-flags / glimpse 系演出（吹き出しは頭上 `.fc1m-bubble` 系、下段クリームパネル禁止）
- セリフ執筆: archetype 6種 ×（勝者/敗者）× 分類。草案は Opus 委譲 → Keisuke 全文レビュー（composed は oyou-style-guide 準拠）
- 詳細設計（発火判定・変化量・モーダルUI）は実装前に本仕様の改訂 or 別spec化 🔧
