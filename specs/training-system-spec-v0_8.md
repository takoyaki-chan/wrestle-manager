# WRESTLE MANAGER v0.8 — 高度なトレーニングシステム仕様書

## 概要
コーチ→選手アサイン制による戦略的育成システム。  
プレイヤーは「どのコーチを雇い、誰に付けるか」で育成方針を決定。  
週の進行は自動、唯一の任意アクションは「強化練習」ボタンのみ。

---

## 1. コーチアサインシステム

### 1.1 基本ルール
| 項目 | 値 |
|---|---|
| コーチ1人の担当上限 | **4人** |
| 選手は複数コーチに付けられるか | **不可**（1人の選手に1コーチまで） |
| 未アサイン選手 | 基礎成長のみ（コーチボーナスなし） |
| アサイン変更 | いつでも自由（週の処理前なら反映） |

### 1.2 データ構造の変更

**v0.7（現行）**
```js
G.coaches = [1, 3]  // 雇用中コーチIDの配列
```

**v0.8（新）**
```js
G.coaches = [1, 3]  // 雇用中コーチIDの配列（変更なし）
G.coachAssign = {
  1: [2, 5, 12, 30],  // コーチID:1 → 選手ID配列
  3: [1, 8, 15]        // コーチID:3 → 選手ID配列
}
```

### 1.3 選手側にも逆引き用ヘルパー
```js
function getCharCoach(charId) {
  for (const [coachId, members] of Object.entries(G.coachAssign)) {
    if (members.includes(charId)) return Number(coachId);
  }
  return null; // 未アサイン
}
```

## 2. コーチタイプ別の効果

### 2.1 ステ系コーチ（PW/SP/TE/ST/MN）

| コーチ | 専門 | 担当選手への効果 |
|---|---|---|
| 鬼塚道場長 | PW | PW成長×2.0 / 他ステ×1.2 |
| 飛鳥トレーナー | SP | SP成長×2.0 / 他ステ×1.2 |
| 鶴見師範 | TE | TE成長×2.0 / 他ステ×1.2 |
| 岩田フィジカルコーチ | ST | ST成長×2.0 / 他ステ×1.2 |
| 沢村メンタルコーチ | MN | MN成長×2.0 / 他ステ×1.2 |

**成長計算（改）**
```
担当選手の練習時:
  - 成長対象ステを選択（後述のウェイト制）
  - 専門ステの場合: 成長量 × コーチ倍率（2.0）
  - 他ステの場合:   成長量 × 副次倍率（1.2）

未アサイン選手:
  - 成長量 × 1.0（ボーナスなし）
```

**成長ステの選択ウェイト（v0.8 新規）**

v0.7ではランダムに1ステを選んでいたが、コーチ専門分野に偏るよう変更：

```
コーチ専門ステ:  重み 40%
他4ステ:        重み 各15%（計60%）
```

例）鬼塚（PW）の担当選手 → PW 40% / SP 15% / TE 15% / ST 15% / MN 15%  
→ 自然とPWが伸びやすく、他もゆっくり伸びる

未アサイン選手は各20%均等（v0.7と同じ）。

### 2.2 全般コーチ（朝日総合アドバイザー）

| コーチ | 担当選手への効果 |
|---|---|
| 朝日総合アドバイザー | 全ステ成長×1.4 / ウェイト均等20% |

専門偏りなし。すべてのステが均等に1.4倍。若手の底上げやバランス型に最適。

### 2.3 MQコーチ（紅林セコンド）

| コーチ | 担当選手への効果 |
|---|---|
| 紅林セコンド | 担当選手が出場する試合のMQ基底値に+3 |

**変更点**: v0.7では雇用するだけで全試合+3だったが、v0.8では担当選手の試合のみ。  
担当4人のうち誰かが出場する試合のみボーナスが乗る。  
→ エース級に付けるのが効率的という戦略判断が生まれる。

### 2.4 POPコーチ（白川マネージャー）

| コーチ | 担当選手への効果 |
|---|---|
| 白川マネージャー | 担当選手のプロモ活動時に人気+1追加 |

**変更点**: v0.7では全員のプロモ+1だったが、v0.8では担当選手のみ。  
担当選手がプロモ活動（balance/promo時）の場合のみボーナス。

## 3. 強化練習（⚡追い込み）

### 3.1 概要
任意アクション。特定の選手を「今週は追い込む」と指定する。  
通常練習と排他（強化練習を選んだ週は通常のスケジュールを上書き）。

### 3.2 効果とリスク

| 項目 | 値 |
|---|---|
| 成長倍率 | ×1.5（コーチ倍率の上にさらに乗算） |
| コンディション消耗 | 通常練習の2倍（6〜14ダウン vs 通常3〜7） |
| 練習怪我リスク | **8%** の確率で軽傷（1〜2週離脱） |
| 使用条件 | コンディション50以上 / 怪我なし / 休養中でない |

### 3.3 制限
- 1選手あたり **連続2週まで**（3週連続はできない / cooldown 1週必要）
- コーチ未アサインでも使用可能（ただし基礎成長×1.5のみ）

### 3.4 データ
```js
// 選手オブジェクトに追加
c.intensiveWeeks = 0   // 連続強化練習カウント（0/1/2）
c.intensive = false     // 今週強化練習するか
```

## 4. スケジュールシステム改修

### 4.1 v0.7からの変更

v0.7の4択スケジュール（balance/practice/promo/rest）は **維持** するが意味が変わる：

| スケジュール | v0.7 | v0.8 |
|---|---|---|
| バランス | 興行週=プロモ、他=練習 | **変更なし** |
| 練習優先 | 毎週練習 | 毎週練習（コーチ効果あり） |
| プロモ優先 | 毎週プロモ | 毎週プロモ（POPコーチ効果あり） |
| 休養重視 | 毎週休養 | **変更なし** |
| ⚡ 強化練習 | なし | **新規**：練習の強化版 |

### 4.2 processManagePhase() 変更点

```
1. 強化練習フラグが立っている選手は → 強化練習処理
2. それ以外は従来のスケジュールに従う
3. 練習時の成長計算でコーチアサインを参照
4. プロモ時のPOPボーナスでコーチアサインを参照
5. 週末に強化練習カウントを更新
```

## 6. セーブデータ互換性

### 6.1 v0.7セーブのロード時
```js
if (!G.coachAssign) {
  G.coachAssign = {};
  G.coaches.forEach(id => { G.coachAssign[id] = []; });
}
// 選手の新フィールド
G.roster.forEach(c => {
  if (c.intensiveWeeks === undefined) c.intensiveWeeks = 0;
  if (c.intensive === undefined) c.intensive = false;
});
```
→ v0.7セーブをロードすると、コーチは雇用済みだがアサインは空の状態。  
→ プレイヤーがトレーニング画面でアサインする。

## 7. バランス考察

### 7.1 コーチアサインによる成長差

| 条件 | PW成長期待値（gap=100基準） |
|---|---|
| 未アサイン | base × 1.0 = 約3.5/週 |
| PW専門コーチ担当 | base × 2.0 × ウェイト40% = 約5.2/週（PW） |
| 全般コーチ担当 | base × 1.4 = 約4.9/週（全ステ均等） |
| PW専門 + 強化練習 | base × 2.0 × 1.5 × ウェイト40% = 約7.8/週（PW） |

→ コーチ未アサインと専門コーチ+強化では約2.2倍の差。十分な戦略的意味がある。

### 7.2 強化練習のリスク/リターン

```
強化練習（1週あたり）:
  リターン: 成長+50%
  コスト:   コンディション-6〜14（通常の2倍）
  リスク:   8%で軽傷（1〜2週離脱）

2週連続で追い込んだ場合:
  リターン: 2週分の成長+50%
  コスト:   コンディション計-12〜28
  リスク:   累計約15.4%でどちらかの週に軽傷
```

→ 興行前の週に追い込むのはハイリスク。オフ期間に集中育成するのが合理的。
