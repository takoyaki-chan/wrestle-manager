## 設計原則

1. **勝敗ではなく団体行動で決まる** — 信頼は「試合に出してもらえたか」「どんな舞台を用意されたか」で変動する。勝ち負けでは動かない
2. **低い信頼は回復しにくい** — 一度失った信頼を取り戻すには、出場させるだけでは足りない。ケアアクションが必要
3. **高い信頼は維持にコストがかかる** — trust 70+は上昇が逓減し、60超は自然減衰コストが発生する
4. **選手の性格が影響する** — メンタル係数によって信頼変動の感受性が異なる
5. **ロッカールームは生き物** — 個人の信頼が集団士気に影響し、士気が個人の信頼に跳ね返る

## §1 データモデル

### §1.1 信頼値（trust）

| 項目 | 仕様 |
|------|------|
| 範囲 | 0–100（内部は float、表示は整数） |
| 初期値 | 50 🔧 |
| 判定タイミング | 興行ごと（2週に1回、年間24回） |

### §1.2 信頼帯

| 帯 | 範囲 | 効果 |
|----|------|------|
| 高帯 | 70+ | 残留率↑、引退受諾率↑、上昇逓減あり |
| 通常帯 | 40–69 | 標準的なゲームプレイ |
| 低帯 | 25–39 | 直訴イベント発生、回復減衰あり |
| 危険帯 | 15–24 | ロッカールーム士気への悪影響大 |
| 臨界帯 | 0–14 | 突然退団リスク（2.5%/興行）🔧 |

### §1.3 追加フィールド

| フィールド | 型 | 説明 |
|-----------|-----|------|
| `noAppearStreak` | int | 連続不出場回数（出場でリセット） |
| `lastTitleShowWeek` | int | 最後にタイトル戦に出場した週 |
| `trustCap` | `{value, expiresWeek}` | S4イベント後の一時的な上限 |

## §2 出場・不出場の基本変動

### §2.1 出場ボーナス

| 項目 | 値 |
|------|-----|
| 基本出場ボーナス | **+1.53** 🔧 |

### §2.2 不出場ペナルティ

| 項目 | 値 |
|------|-----|
| 基本不出場ペナルティ | **-2.64** 🔧 |

連続不出場で加速:

| 連続回数 | 倍率 🔧 | 実効値 |
|---------|--------|-------|
| 1回 | ×1.00 | -2.64 |
| 2回 | ×1.15 | -3.04 |
| 3回 | ×1.35 | -3.56 |
| 4回+ | ×1.55 | -4.09 |

計算式: `lossDelta = -2.64 × streakMult`

## §4 高信頼帯の上昇逓減（gainMult）

trust 70以上でプラス方向の変動に逓減がかかる。マイナス方向には適用しない。

### §4.1 計算式

```
gainMult(trust) = trust < 70 ? 1.0 : max(0, 1.0 - pow((trust - 70) / 30, 1.4))
```

### §4.2 逓減テーブル

| trust | 倍率 | 出場実効値 |
|-------|------|----------|
| 50 | ×1.00 | +1.53 |
| 70 | ×1.00 | +1.53 |
| 75 | ×0.79 | +1.21 |
| 80 | ×0.52 | +0.80 |
| 85 | ×0.24 | +0.37 |
| 90 | ×0.05 | +0.08 |

> **設計意図**: trust 90が実質的な天井。維持だけで大変な「絶大な信頼」を表現する。

---

## §5 低信頼帯の回復減衰（recoveryMult）

trust 40未満で出場時の回復効率が低下する。

### §5.1 計算式

```
recoveryMult(trust) = trust >= 40 ? 1.0 : 0.35 + (trust / 40) × 0.65
```

### §5.2 減衰テーブル

| trust | 倍率 | 出場実効値 |
|-------|------|----------|
| 39 | ×0.98 | +1.50 |
| 30 | ×0.84 | +1.28 |
| 20 | ×0.68 | +1.04 |
| 10 | ×0.51 | +0.78 |
| 5 | ×0.43 | +0.66 |

### §5.3 適用範囲

- **適用する**: 出場ベース値（+1.53）、舞台ボーナス（§3）
- **適用しない**: ケアアクション（§6）— ケアは低帯から引き上げるための手段

## §6 ケアアクション

### §6.1 OVR傾斜（全ケアに適用）

低OVRの選手ほどケアが響く。

```
careOvrMult = 0.7 + (100 - OVR) / 100 × 0.9
```

| OVR | 倍率 | 意味 |
|-----|------|------|
| 30 | ×1.33 | 「自分なんかに…？」 |
| 50 | ×1.15 | 嬉しい |
| 70 | ×0.97 | 「まあ当然でしょ」 |
| 85 | ×0.84 | あまり響かない |

### §6.2 ケアアクション一覧

| アクション | コスト(万) 🔧 | trust Δ 🔧 | 備考 |
|-----------|:-----------:|:--------:|------|
| ボーナス支給 | 50 | +4.59 | 出場3回分の価値 |
| コスチューム新調 | 80 | +5.36 | 個人への特別扱い |
| 専属トレーナー | 160 | +5.97 | 最高コスト |
| メディア露出 | 120 | +5.36 | 人気上昇効果もあり |
| 声かけ | 0 | +0.77 | 無料だが効果小 |
| リフレッシュ休暇 | 100 | +5.36 | 練習スキップあり |
| 打ち上げ・慰労会 | 15/人 | +1.84/人 | 全体向け |
| 合宿 | 40/人 | +1.84/人 | 成長ボーナスあり |

### §6.3 適用ルール

- recoveryMult（§5）は**適用しない**（ケアは低帯回復の手段）
- careOvrMult（§6.1）は**適用する**
- gainMult（§4）は**適用する**（高帯では逓減）
- コスチューム/メディアは**2週間隔制限** 🔧
- コスチューム/メディアは**orgPop 20以上**で解放 🔧
- 特別待遇は**orgPop 40以上**で解放 🔧

## §7 メンタル係数

選手の `mental` パラメータ（1–100）が全trust変動に影響する。

### §7.1 計算式

```
applyCoeff(delta, mental) {
  mn = clamp(mental, 1, 100)
  if delta > 0: return delta × (1.0 + (100 - mn) / 200)
  if delta < 0: return delta × (1.0 - mn / 200)
}
```

### §7.2 効果一覧

| mental | プラス変動の増幅 | マイナス変動の抑制 |
|--------|----------------|-----------------|
| 100 | ×1.00（変化なし） | ×0.50（半減） |
| 50 | ×1.25（25%増） | ×0.75 |
| 10 | ×1.45（45%増） | ×0.95（ほぼそのまま） |

> **適用順序**: gainMult / recoveryMult の**前**に適用

## §8 自然減衰（月次）

興行ごとに計算される自然変動。何もしなければ信頼は緩やかに下がる。

### §8.1 計算式

```
calcMonthlyNatural(mental, seniorCount, trust, morale) {
  base = -0.46 + (mental / 217)
  seniorBonus = 0.05 × min(seniorCount, 3)
  natural = base + seniorBonus

  // trust維持コスト: trust 60超で1ptあたり-0.04
  if trust > 60: natural -= (trust - 60) × 0.04

  // 低士気浸食: 士気45未満で追加減衰
  if morale < 45: natural -= (45 - morale) / 100

  return natural
}
```

### §8.2 mental別自然変動

| mental | 基本変動/興行 | 意味 |
|--------|------------|------|
| 100 | ±0.00 | 精神安定 |
| 75 | -0.11 | 前向き |
| 50 | -0.23 | 平均的 |
| 25 | -0.35 | 不安定 |

### §8.3 補正要素

- **先輩ボーナス**: trust 70+の選手1人につき+0.05/興行（最大3人 = +0.15）
- **trust維持コスト**: trust 60超は1ptあたり-0.04/興行（trust 80 = -0.80追加）
- **低士気浸食**: 士気45未満で-(45-morale)/100/興行

## §9 ロッカールーム士気

### §9.1 基本仕様

| 項目 | 仕様 |
|------|------|
| 範囲 | 0–100 |
| 初期値 | 60 🔧 |
| 更新タイミング | 興行ごと |

### §9.2 変動要因

| 要因 | 条件 | 変動値 🔧 |
|------|------|---------|
| 平均回帰 | 常時 | -(current - 55) × 0.12 |
| 好興行 | avgMQ ≥ 65 | +1.5 |
| 凡戦 | avgMQ 45–54 | -0.5 |
| 悪興行 | avgMQ < 45 | -1.5 |
| 低trust選手 | trust < 40の選手ごと | -(40 - trust) / 40 × 3.06 |
| ロスター過多 | 自社選手 > 8人 | -(ownCount - 8) × 0.15 |
| 怪我多発 | 怪我3人+ | -0.5（5人+でさらに-0.5） |
| ムードメーカー | 特性保持者あり | +1.5（士気70超なら+0.75） |
| 人望 | 特性保持者あり | +0.3 × troubledCount（上限+1.2） |

### §9.3 士気のtrust低下ペナルティ

| trust | 1人あたりペナルティ |
|-------|:------------------:|
| 35 | -0.38 |
| 25 | -1.15 |
| 15 | -1.91 |
| 5 | -2.68 |

> **設計意図**: 1人の不満選手が全体に波及する。放置するとロッカールームが崩壊する。

## §10 待遇不満（Grievance）

興行ごとに蓄積される構造的不満。条件を満たす限り毎興行減り続ける。

### §10.1 不満要因

| ID | 要因 | 条件 | ペナルティ/興行 🔧 |
|----|------|------|:-----------------:|
| G1 | 給与不公平 | OVR±5の平均給与の80%未満 | -0.4 |
| G2 | 後輩高給 | 年齢差3+、後輩が110%超の給与 | -0.6 |
| G3 | タイトル機会なし | OVRランク3位以内 + 非王者 + 8興行タイトル戦なし | -0.5 |
| G4 | ロスター過密 | ロスター10人+ + 連続不出場2回+ | -0.35 |

> 条件は重複加算（例: G1+G2 = -1.0/興行）

## §14 適用順序（applyShowTrust内）

1. 出場/不出場判定 → 基本delta算出
2. メンタル係数適用（§7）
3. recoveryMult適用（§5、trust < 40かつ出場時）
4. gainMult適用（§4、trust ≥ 70かつプラスdelta時）
5. 舞台ボーナス加算（§3、出場時）
6. 成功体験ボーナス加算（§12）
7. 待遇不満delta加算（§10）
8. 選手間関係delta加算（§11）
9. 自然減衰加算（§8）
10. trustCap適用（§13.2）
11. clamp(0, 100)
