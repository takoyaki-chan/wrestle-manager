## 1. 自動休養ラインをプレイヤーが決められるようにする

**背景**: フィードバックフォーム 2026/04/29「自動休養に入るラインを自分で決められるようになりたい。60だとケガが怖いので」。

**現状**: `src/management.js` の週処理で `if (action !== 'rest' && nc.condition < 60)` が固定値。直後に `if (nc.condition <= 30) action = 'rest';` の安全弁がある。

**やること**:
- 保存データ(`G`)に `autoRestLine` を持たせる。既定値 60。旧セーブで未定義なら 60 として読む。
- 固定値 60 を `G.autoRestLine` 参照に置き換える。**安全弁の30は変更しない**(30未満は必ず休養のまま)。
- 選べる値は **50 / 60 / 70 / 80** の4段。UIは「今週」タブの「🤖 おまかせ」ボタンの隣に小さなセレクトを置く。
  - ラベル(日本語): `自動休養ライン` / 選択肢は `体調50未満` `体調60未満` `体調70未満` `体調80未満`
  - English: `Auto-rest line` / `Below 50` `Below 60` `Below 70` `Below 80`
  - ツールチップ(日本語): `この体調を下回った選手は、育成方針にかかわらず自動で休養します。体調30未満は設定にかかわらず必ず休養します。`
  - English: `Fighters below this condition rest automatically, regardless of their training policy. Below 30 they always rest.`
- 変更したら即座に次の週処理から効く。過去の週の結果は作り直さない。
- テスト: 既定60で従来と同じ挙動になること、80にすると体調75の選手が自動休養になること、30未満の安全弁が効くことの3点を `test/` に追加。

## 2. アンケート(フィードバックフォーム)への導線を増やす

**背景**: 報告の多くがバージョン不明で、修正済みの不具合が再報告されている。今の導線はタイトル最下部の1か所だけで、文字色が `rgba(255,255,255,0.25)` でほぼ見えない。

**やること**:
- `src/index.html` の `.title-feedback` の文字色を `rgba(255,255,255,0.55)`、hover を `rgba(255,255,255,0.9)` に上げる(位置・文言はそのまま)。
- 「❓ ヘルプ」画面(`#screen-help`)の末尾に同じリンクを1つ追加する。既存の `FEEDBACK_FORM_URL` を使う。
  - 文言(日本語): `📝 ご意見・バグ報告を送る(Googleフォーム)`
  - English: `📝 Send feedback or a bug report (Google Form)`
  - 補足の1行(日本語): `不具合の報告には、タイトル画面に出ているバージョン番号と、お使いのブラウザ名を書いてもらえると助かります。`
  - English: `When reporting a bug, please include the version number shown on the title screen and the name of your browser.`
- **増やすのはこの2か所まで**。ゲーム中の他の画面には出さない。

## 3. 更新履歴をタイトル画面から見られるようにする

**背景**: 「最新版にしたのに直っていない」という報告があり、プレイヤーが自分の版と修正内容を確認できない。

**やること**:
- 新規ファイル `src/data-changelog.js` に配列 `WM_CHANGELOG` を作る。要素は `{ version:'1.37', date:'2026-09-17', ja:['…','…'], en:['…','…'] }`。
- 中身は `release/dist/DLsite更新情報_v1.35.txt` `_v1.36.txt` `_v1.37.txt` の「■」項目を1行ずつに直して入れる(v1.35・1.36・1.37 の3版ぶん)。英語は日本語の直訳でよい。
- タイトル画面の `Credits` / `Fighter File` と同じ並びに `更新履歴`(English: `What's New`)を足し、押すと一覧のモーダルを出す。見た目は既存の Credits のモーダルに合わせる。
- モーダルの先頭に現在のバージョン(`VERSION 1.37` と同じ値)を出す。
- `release/manifest.json` の `sourceFiles` に `src/data-changelog.js` を追加する(忘れると配布物に入らない)。
- 版を追加する時に `data-changelog.js` へ1ブロック足すだけで済む形にする。

## 4. ダウンロード購入者向けにウェブ版を開く(入口の分離)

**背景**: ダウンロード版は再ダウンロードしないと修正が届かない。ウェブ版を購入者にも開けば、進行不能バグの修正をすぐ届けられる。

**現状**: `functions/_middleware.js` は「Patreon連携が構成済みなら支援者判定」「未構成なら固定パスワード(wrestle2025)」の二択。

**やること**:
- Patreonモードのときでも、環境変数 `BUYER_PASSWORD` が設定されていれば **購入者用パスワード**でも入れるようにする。
  - `?password=` での入場と、入力欄からの送信の両方に対応。合格したら既存と同じ署名クッキーを発行する(有効期間は既存のまま)。
  - `BUYER_PASSWORD` が未設定なら今までと完全に同じ挙動(事故防止)。
- ログイン画面に、購入者向けの入力欄と一行の案内を足す。
  - 日本語: `ダウンロード版をご購入の方は、商品ページに記載のパスワードを入力してください。`
  - English: `If you bought the download edition, enter the password shown on the store page.`
- パスワードは環境変数だけで管理し、**コードにもドキュメントにも実物を書かない**。
- `docs/cloudflare-patreon-auth-setup.md` に「購入者用パスワードの設定手順(Pagesの環境変数に `BUYER_PASSWORD` を入れる/変更したら全員入り直し)」の節を足す。

**この4番だけは、実装後に作者の確認を取ってから公開する**。デプロイはしないこと。
