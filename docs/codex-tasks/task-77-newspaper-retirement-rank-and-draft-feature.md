# task-77: 新聞 — 引退記事の格付けとドラフト1面の拡充

> 起票: 2026-08-02(Keisuke実機フィードバック)
> 依存仕様: specs/newspaper-spec-v1.0.md(採点フレーム §2 は変更しない。枠内で拡張する)
> 記事テンプレ文: **本書 §5 の確定版を使う**(Opus起草→Keisukeレビュー済みのものを貼る。空欄の間は着手しない)

## 背景(実機で起きたこと)

シーズン13新年号の実画面より:

1. 引退記事が同じ号に4本並び、**全員が同一文**「看板選手の退団は団体にとって大きな痛手だ。」で処理された。10季の中堅も15季の元王者も同じ扱い。現行の格判定は `ovr >= 70` の二値だけ(management.js 29156。パリティ実装でAIのOVRが上がったため、ほぼ全引退者が「看板」側に落ちる)
2. 自団体ドラフト指名が一面トップに来たのに、本文が「{names}が加入。どこまで伸びるかは、これからの一年が決める。」の**2行だけ**で寂しい

Keisuke裁定: 引退の扱いは**格**(OVR実績・王座歴など)で優先順位と記事の重みを変える。ドラフト1面は**注目選手1〜2名に言及**して本文を厚くする。

## A. 引退記事の格付け

### A-1. 格スコア(強度補正として実装)

newspaper-spec §2 のフレームを守る: 基礎点(retirementDeclare 180 / aiAceRetirement系)はいじらず、**強度補正(intensityBonus)に「引退の格」を追加**する。主役補正に焼き込まない(引退者は現役の注目属性をほぼ持たないため、キャリア実績は強度側が正しい置き場)。

```
引退の格(強度) = 戴冠歴 + ピーク到達 + 長期在籍 + 現役王者のまま引退
  戴冠歴:   reigns>=3 → +55 / 2 → +40 / 1 → +25 / 0 → 0
  ピーク:   peakOVR>=90 → +50 / 80-89 → +30 / 70-79 → +15 / それ未満 → 0
  在籍:     seasons>=12 → +10
  現役王者: 引退時に王座保持 → +45
  上限:     合計 +120(主役補正の上限と同じ思想)
```

### A-2. 本文ティア(同じ格情報で記事の文面も変える)

| ティア | 条件 | 文面 |
|---|---|---|
| L(レジェンド) | reigns>=2 または peakOVR>=90 | §5-L |
| A(看板) | reigns>=1 または peakOVR>=80 | §5-A |
| B(中堅) | peakOVR>=65 | §5-B |
| C(その他) | 上記以外 | §5-C |

- 同一号に同ティアが複数出る場合、テンプレのバリアント(各3種)を**順繰りに変えて**同文の並びを作らない
- 現行の `isAce = ev.ovr >= 70` 二値と固定文は廃止

### A-3. データ配線

- `_newsRetirements` のイベントペイロード(processSeasonEnd内で構築)に **peakOVR / reigns(生涯戴冠数) / wasChampion(引退時王座保持)** を追加する。`aiInjuryRetirement` は既に `titleReigns` を持っている(29177)ので取得元はそこに揃える。peakOVR は careerRecord/updateCareerPeaks 系の記録値を使い、**現在OVR(衰え後)で代用しない**
- 週次スキャン側の `retirementDeclare`(retiredFighters 新規)にも同じ格スコアを効かせる。**引退ニュースの入口は2系統ある**(AIシーズン末キュー / retiredFighters スキャン)ので、格スコアの計算は共通ヘルパー1つに寄せて両方から呼ぶ
- 着手前に全経路を列挙すること: `_newsRetirements` / `retirementDeclare` / `aiAceRetirement` / `aiRetirement` / `aiInjuryRetirement` / `_newsContractDepartures`(引退destinationのもの)。**想定した経路ではなく、実際に紙面に出る経路から壊れる**

### A-4. 不変条件(newspaper-news-value-test.js に追加)

1. 無冠・peakOVR70未満・11季以下の引退は、一面トップ資格(260)に届かない
2. reigns>=3 または peakOVR>=90 のレジェンド引退は、肩・準特大資格(190)以上に必ず届く
3. 既存の検算不変条件1〜4(newspaper-spec §2-5)を壊さない — 既存テスト全PASS維持
4. 格スコアの追加で「引退以外の記事」の点が1点も動かないこと

## B. ドラフト自団体1面の拡充

### B-1. 組み立て式本文

現行テンプレ(data.js `draftPlayerResult` 16891-16896)を「**リード文+注目選手文(1〜2名)+締め文**」の組み立て式に置き換える。パーツは §5-D。

- 注目選手の選出: 獲得選手を `assessedTier` で降順ソート(TIER_ORDER は ui-common.js 5885 に既存)し上位1〜2名。superElite/elite がいれば2名目まで、promising 以下しかいなければ1名だけ言及
- 見立てティアを紙面に出す前例は draftRoundup(5906-5915、実名+ティアラベル)にあり、同じ流儀でよい。**内部数値(pot/trainCap/OVR)は出さない**(newspaper-spec §3-2 の原則)
- リード/注目/締めの各パーツはシーズン値などで擬似ランダムに選び、毎年同じ組文にならないこと
- 獲得0名の年は現行どおり(記事なし)。1名だけの年はリード+その1名への言及+締め

### B-2. 適用範囲

- `draftPlayerResult`(自団体)のみ。`draftAiResult` / `draftRoundup` は現行維持(スコープ外)
- 基礎点165は変更しない(体裁の問題であり、注目度の問題ではない)

### §5-D(ドラフト自団体1面: リード+注目選手+締め)

**リード文**
- 今季のドラフトで{org}は{count}名を指名した。{names}の顔ぶれが、そのまま来季の若手層になる。
- {org}の指名は{count}名。{names}が新たに名簿に加わった。
- {count}名。今季{org}が迎え入れたのは{names}の面々だ。指名順を見るかぎり、狙いを絞った指名だった。

**注目選手文(超逸材級)**
- {age}歳・{h}cmの{rookieName}には、{org}のスカウト陣が近年例を見ない評価を付けた。{styleJa}としての完成度ではなく、伸びしろの底が見えないという言い方だった。
- 注目は{age}歳の{rookieName}。{h}cmの体格と{styleJa}としての組み立ては、担当したスカウト陣が最上位の見立てを最後まで崩さなかった理由でもある。
- {styleJa}の{rookieName}は、複数のスカウトが揃って最上位の評価を付けた一人だ。{age}歳、{h}cm。入り口の段階でここまで評価が割れなかった新人は珍しい。

**注目選手文(逸材級)**
- {age}歳の{rookieName}は、{styleJa}として上の年代と噛み合う下地があるとの見立てだ。{h}cmという体格をどう使うかで、伸び方の幅は変わってくる。
- {h}cm・{age}歳の{rookieName}にも高い評価が付いた。{styleJa}の型がすでに一本通っており、あとは実戦で削られたときに何が残るか。
- スカウト陣が推したのは{styleJa}の{rookieName}。{h}cm、{age}歳。すぐ上位に食い込む種類ではないが、二、三年で計算が立つという読みだった。

**注目選手文(有望級)**
- {age}歳の{rookieName}は、{styleJa}としての基礎を評価されての指名。{h}cmの体をどこまで作れるかが最初の課題になる。
- {rookieName}は{h}cm・{age}歳。{styleJa}の適性は認められたが、見立ては分かれた。使われ方次第という但し書きが付く。

**締め文**
- 新体制での練習は来週から始まる。{org}がこの{count}名をどの順で人前に出すかで、来季の興行の形も変わってくる。
- 顔ぶれは揃った。{org}にとって次に問われるのは、誰を早く実戦に置くかの判断のほうだ。
- 指名の当たり外れが数字になるのは何年も先の話だ。{org}の来季は、この新しい名前をどこに置くかから始まる。
