## 2. 変更点

### G15 — スタイル一致の二重計上(`getCharGrowthMult`)
招聘中は `getCharCoach` が招聘コーチを返すため、スタイル一致(+0.08/+0.05)が
`calcInviteMult`(trainerMult側)と `getCharGrowthMult`(coachMul側)の**両方**に乗っていた。
一致ボーナスの居場所を `calcInviteMult` に一本化し、招聘コーチが相手のときは coachMul 側で足さない。
`gMult` は「その期間の指導者の地力」として残す。**雇用コーチ経路は分岐に入らないので不変**。

### P3-4 — ①分岐順 ②A級ゲート
① `calcInviteMult` を `coach.style === fighter.style` 先行判定に。旧順では Allround コーチが先に
食われ、Allround選手(43名)に specialist(+0.08)の経路が**定義上存在しなかった**。
② 招聘のA級解禁を `orgPop>=55 || coachSlots>=4` へ。C級(壁なし)/B級(知名度30)は不変。

### P3-5 — アーキタイプ副軸(`COACHING_COMPAT_ARCHETYPE`)
`getCoachingCompat(coachingType, personality, archetype)` に第3引数を追加し、
**`personality==='normal'` のときだけ**副表を見る。`standard` は全タイプ±0のまま。
第3引数省略時は従来どおり必ず `'normal'`(後方互換)。

### P3-2 — 重点ステ指導
招聘の対象選択で重点ステ(PW/SP/TE/ST・省略可)を1つ指定 → 期間中その練習選択率 ×1.25。
同ステの特化ability(×1.40)持ちが相手なら**特化のみ・非累積**。
`Engine.coach.getInviteFocusStat` / `getCoachStatSpec` を新設(`getStatSpecBoost` は後者へ委譲)。
AI招聘(`aiSeasonTrainer`)は `focusStat` を持たないため従来どおり。

### P3-1 — 指名リクエスト
`G.coachRequest = { axis, value, quarterKey }`。⚡0・費用0。翌期の市場ロールで該当者がいれば
候補**1枠目**を確保、いなければ「今期は都合がつかなかった」と1行報告(ご都合補充なし)。

### P3-3 — 常設ミニパネル + 予告
決裁タブの机上に常設パネル(候補の顔40px丸・名前・格・指導タイプ・得意スタイル/残り週数/
リクエスト状態と依頼)。**依頼もパネル内で完結、モーダル・週次ポップアップは1つも増やしていない。**

## 3. 実装中に見つけて直した設計上の穴(要レビュー2件)

### (a) 依頼の単位を「暦の四半期」から「机に並んでいる顔ぶれの期」へ
市場は tickWeek で引き直され、プレイヤーが見る manage フェーズには**翌週から**反映される。
つまり顔ぶれは暦の四半期境界より1週遅れて替わる(週14/26/38で替わる)。
当初 `getInvitePeriodKey`(暦)で「四半期1回」を判定していたところ、**週13の時点で暦は既にQ2
なのに市場はQ1のまま**のため、まだ返事の来ていない依頼を上書きできてしまった。
実測: 2季で依頼32件中28件が黙って消えていた。`getCurrentMarketPeriodKey` を新設して
「同じ顔ぶれの期に1件まで」に修正。修正後は依頼1件につき必ず報告1件が対応する。

### (b) パネルの残り週数・ティッカーの予告も同じ物差しに
上と同じ理由で、暦から数えると「あと12週」と出しながら翌週に入れ替わる嘘が出る。
`getInviteMarketWeeksLeft` は実際に顔ぶれが替わって見える週から数える(12→1)。
ティッカーの予告は替わる直前の週(13/25/37/49)にちょうど1回。
**この1行は乱数を消費しない確定枠として最後に足す**ので、既存のティッカー抽選列は動かない。
