## 背景

成長リバランス v2.0(2026-07-30 本番適用)で、追い込み練習に**熱量逓減**を入れた:

- 選手ごとの内部値 `_heat`(0〜4)。追い込みで +1、通常練習 −1、休養 −2(下限0)
- 成長倍率が `intensiveHeatTable = [1.8, 1.6, 1.4, 1.2, 1.0]` の順に落ちる
- **負傷リスクと消耗(wear)は満額のまま** = 連打は割に合わない設計

**しかし `_heat` はプレイヤーに一切見えない。** 今のままでは「なんとなく伸びが悪い」としか
映らず、間欠運用という正解にたどり着けない。**これを"読める"ようにするのが本タスク。**

## 設計原則(このプロジェクトの哲学。逸脱したら失敗)

1. **数値を表に出さない。** 「熱量3」「×1.4」のような内部値・倍率をUIに書かない
   (CLAUDE.md「数値の丸見せによるスプレッドシートゲーム化」の禁止)
2. **選手の様子として見せる。** 疲労の"見た目"で伝える。プレイヤーが
   「この子はもう限界そうだ、今週は休ませよう」と**自分で気づける**状態を作る
3. **内部変数名(`_heat`/intensive等)をプレイヤー向けテキストに出さない**

## 実装するもの

### A. 熱量の段階を「表示用の状態」に変換するヘルパー

`_heat` の生値ではなく、**3段階の状態**に畳んでUIへ渡す(名前は実装者判断でよい):

| _heat | 状態 | 意味 |
|---|---|---|
| 0 | `fresh` | 体が軽い。追い込みが最も効く |
| 1〜2 | `warm` | 効きが鈍り始めている |
| 3以上 | `heavy` | 追い込みがほぼ効かない(消耗だけ払う) |

**ヘルパーは表示専用の純粋関数**とし、GameStateに書き込まない。
`_heat` が未定義(=一度も追い込んでいない)なら `fresh` 扱い。

### B. 見せる場所(3箇所)

1. **ロスター/道場の選手行**: `heavy` の選手に控えめな視覚サイン
   (アイコン1つ or 色味。**バッジを賑やかにしない**。既存の絶好調🔥/スランプ📉バッジと
   同じ体系・同じサイズに揃える)
2. **選手詳細ポップアップ**: 状態に応じた一文を出す枠を用意する
   (**文言は仮テキストでよい**。セリフは別タスクで差し替えるので、
   `HEAT_STATE_LINES` のような**参照点だけ作っておく**。data.js には定数を作らず、
   ui側に暫定の配列を置き「※Opus起案のセリフに差し替え予定」とコメントを書く)
3. **今週の練習方針を選ぶ画面**(追い込みを選択できる場所): `heavy` の選手を追い込もうと
   したときに、**選ぶ前に分かる**表示を出す(選択を禁止はしない。社長の判断を奪わない)

### C. ツールチップ

`heavy` のサインにツールチップを付け、**仕組みを日本語で説明**する:
「追い込みを続けると体が重くなり、同じ練習でも身につきにくくなる。休ませると戻る」程度。
数値・倍率・変数名は書かない。
