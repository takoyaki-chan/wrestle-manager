## §1. AI王座戦を tier 2(ビッグマッチ)にする ← 本命

`src/match-engine.js:248-258` のとおり、`simulateMatch` の `matchTier` は
**1=通常 / 2=ビッグマッチ(PPV/タイトル/対抗戦)** で、tier 2 は
`BIGMATCH_MAX_T` / `BIGMATCH_PHASES` / `BIGMATCH_ENG` という**別テーブル**を使う。

プレイヤーは `App._normalShowMatchTier`(`src/app.js:6791`)が
`if (m.isTitle) return 2;` で王座戦を必ず tier 2 にしている。

ところが `Engine.rival.processAIWeek`(`src/management.js:9186` 付近)は
**tier を `1` に直書き**しており、**AI の王座戦も通常試合として処理されている**。

- **王座戦のカードだけ** tier 2 にする。判定は task-61 で導入した `isAiTitleCard` を使う
- **AI の通常興行は tier 1 のまま**(Keisuke 明示)。ここを間違えないこと

### なぜ効くか(コメントに残すこと)

短い試合はターン数が少なく、運のブレが均される前に決着する。
いまAI王座は「上位3人・OVR差5以内」のほぼ同格同士が短い試合で戦っており、
実質コイントスになっている。長い試合ではブレが平均化され、強いほうが勝ちやすい。
**恣意的な下駄ではなく、王座戦を王座戦として扱うだけ**である点が重要。

## §2. 挑戦資格を 上位3人 → 上位4人

`Engine.title.getEligibleChallengers`(`src/management.js:2102`):

```js
const rankingLimit = policy === 'ai' ? 3 : 5;
const maxOvrGap = policy === 'ai' ? 5 : 8;
```

- **`rankingLimit` の ai 側を 3 → 4** にする
- **`maxOvrGap` は 5 のまま**(Keisuke は上位N人だけに言及。OVR差の枠は
  「明らかに格下の王者を生まない」ための歯止めなので動かさない)
- プレイヤー側(5 / 8)は**変えない**
- 値は `src/data.js` の定数へ出す(いまコードに直書きされている)
