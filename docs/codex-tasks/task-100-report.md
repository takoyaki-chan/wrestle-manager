1. **【要判断】ポップアップ経路の治療ボタンは現在どこからも描画されていない。**
   設計doc §P2-C の「怪我ポップアップ経由も⚡1に統一」の対象である `App.executeSpecialTreatment` は、**src全体で呼び出し元が1つも無い**(定義のみ)。受け皿である `showEventPopup` の `action`(label/disabled/disabledHint/onClick)を渡している箇所も0件で、社長室Phase 5当時のボタンは配線が失われている。
   今回は**エンジン側の不整合(⚡0/対象/短縮量/費用)をすべて解消**し、`App` 側にも⚡消費と拒否理由を実装したうえで、**ボタンの新規追加はしていない**(指示書の「押せて弾かれる状態を作らない」に照らすと、存在しないボタンを復活させるかはUI設計の判断が要るため)。復活させる場合は `o.action.disabled` + `disabledHint` の既存機構がそのまま使える。
2. **B1「練習中のアクシデント」の「特別治療（-200万）」ボタンは意図的に据え置いた。**
   これは怪我**発生時**の選択肢(`_buildB1Modal` / management.js の B1分岐)で、効果は初期離脱週数の決定そのもの。特別治療**指示書**とは別系統であり、ここに「総週数10以上」を適用するとB1の選択肢が全消滅する。また不変条件「怪我の週数生成は不変」に抵触する。`test/u3-group-a-safety-net-test.js` もこのボタンの有効/無効を検査しており、現状PASS。**費用200万・⚡0のままなので、名称が同じ「特別治療」で桁が違う点は要確認**(文言を分ける等の判断はKeisukeさん/Fable側で)。
3. **団体書類のCD判定は今回まで `doc.cooldown` を無視していた**(「今週決裁済みか」だけ=常にCD1週相当)。P2-Bで参照するよう改めた際、**シーズン跨ぎで週番号が巻き戻る**(48→1)ことによる恒久ロックを避けるため、経過が負のときはCDを掛けない実装にしてある。合宿(`cooldown:1`)の挙動は完全に不変。
4. **既存セーブの長期怪我は特別治療の対象にならない場合がある。** `injury.totalWeeks` は新規発生分から記録されるため、旧セーブで**すでに進行中**の怪我は `weeksLeft` にフォールバックする(残り週数≧10なら対象、それ未満なら対象外)。対象を取りこぼす=安全側に倒れる方向で、新しい怪我からは正しく判定される。
5. **引退年齢プローブの標本が小さい**(40季で n=25〜28)。「延命側に振れていない」ことの確認には足りるが、効果量の精密測定にはなっていない。P2-Aの寿命への効きを本気で測るなら100季級か複数シードが要る(CLAUDE.mdの実行方針に照らし、今回は不必要に長く回さない方針で40季1本に留めた)。
