# task-79: Common-1 派閥内対決の興行組み込み化 + リーダー発言の帰属修正

> 起票: 2026-08-02(Keisuke実機フィードバック2件+設計裁定)
> 関連spec: faction-common-events-spec-v0.1(Common-1) / faction-rivalry-points-spec-v0.1 — 実装後に該当節を更新すること
> 設計原則: 「社長は舞台を作る人」— 対決の格(枠)を決めるのは社長。システムは強制しない

## A. リーダー発言の帰属修正(先行・小)

**症状**: Common-1モーダル(派閥内対決の打診)で、リーダーが対戦者でない場合に
リーダーのセリフが**対戦者Aの頭上**に出る。話者が分からず「セリフの分岐が壊れている」ように見える。

**原因**: [ui-common.js:11535](../../src/ui-common.js) `leaderSide = isLeaderA ? 'a' : (isLeaderB ? 'b' : 'a')`
— リーダー非当事者時のフォールバックが 'a'。セリフデータ自体(COMMON1_LINES 6×7マトリクス)は正常。

**修正**: リーダーが対戦者でない場合、対戦者の頭上には吹き出しを出さない。
コーチ帯(reporter strip)の下に**リーダー帯**(リーダーのミニ画像(chipサイズ46×66・2:3)+頭上吹き出し)を
追加してリーダーのセリフをそこに出す。吹き出しルール厳守: 画像の上・中身はセリフのみ・名前を吹き出し内に書かない。
結果モーダル(_renderCommon1MatchResult)の resultLeader / resultLoser の帰属も同様に確認する。

## B. A選択「派閥内対決を組む」の興行予約化(本体)

**現行**: A選択で即時にビッグマッチ処理(applyCommon1MatchResult)が走り、その場で試合が終わる。

**変更(2026-08-02 Keisuke裁定)**: A選択は**予約**を作るだけにする。

1. **予約データ**: `G.bookedCommon1 = { fighterAId, fighterBId, factionId, createdSeason, createdWeek }`(命名は既存の予約系に合わせて可)
2. **興行への組み込み**: 次回**通常興行**の編成画面で、予約カードが編成候補として現れる。
   **どの枠に置くかはプレイヤーの自由**(メイン/セミ/中盤)。メインに置けば既存のビッグマッチ/因縁ブーストが自然に乗る。
   システム側から枠を強制しない
3. **清算処理**: 試合が実際に行われた興行の結果処理で、既存の因縁清算(applyCommon1MatchResult相当の
   勝者/敗者処理・因縁-30〜-50)を**枠に関係なく**適用する。即時試合用の演出モーダルは興行後の結果表示に置き換え
4. **衝突ルール(全部実装)**:
   - 特別興行週(PPV / 春タッグ / 秋対抗戦 / 天頂戦 / 4団体戦 等)には組み込まない → 次の通常興行へ繰り越し
   - 挑戦状(CH系)や他の予約試合と**同一興行で重ねない**(1興行に予約消化は1件まで、先着優先)
   - 当事者が負傷/レンタル/退団/引退したら予約を**静かに破棄**(エラー・説明文なし。因縁は残る)
   - 期限: 予約から1シーズン消化できなければ自然消滅(因縁は残ったまま)
5. **エラー安全(§5-D鉄則)**: 予約の二重作成防止 / 編成画面で予約カードが置けない状態でも進行が詰まらない(fail-open) /
   興行結果処理で当事者不在でも例外を出さない

**着手前の義務**: 既存の「予約→興行組み込み」機構(挑戦状 CH系 / B3奪還挑戦 / F09対抗戦 / 頂上決戦)の
実装経路を**全部grepで列挙**し、最も近い既存経路に乗せる。新しい並行機構を発明しない。
