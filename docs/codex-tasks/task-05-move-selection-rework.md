## 背景

女子プロレス団体経営SLG。試合シミュレーションの技選択に構造的な穴があり、**クライマックスでも約14%のターンでダメージ5以下の小技が出て、そのまま決着技になる**（タイトルマッチの決め手が「ストンピング」になる）。

原因は、フェーズが進むと大技プールを引く「確率」は上がるが、**共通プールの中身が最初から最後まで不変**であること。本タスクはこれを威力ベースの3ティア制に置き換える。

## 実装仕様

仕様書 `specs/move-selection-spec-v0.1.md` の §3〜§9 を実装する。要点：

### ① 3ティア分類（§3）

- **技データ（`commonMoves` / `styleMoves`）は一切変更しない。** `d` 値で仕分けるだけ
- 小技 = d2〜5 / 中技 = d6〜10 / 大技 = d11〜16
- 選手ごとの候補集合は `commonMoves ∪ styleMoves[style]`。プール名ではなく **`d` 値でティアが決まる**（`styleMoves` の d10 は中技に落ちる）
- 分類はモジュール初期化時に一度だけ行い、以後は使い回すこと（毎ターン filter しない）

### ② フェーズ別ティア重み（§4）

`PHASES` / `BIGMATCH_PHASES` / `TAG_MATCH_CONFIG.phases` の各要素から `sCh` を削除し `tierW` を追加。

| フェーズ | 小 | 中 | 大 |
|---|---|---|---|
| Opening | 70 | 25 | 5 |
| Mid | 35 | 45 | 20 |
| End | 15 | 55 | 30 |
| Climax | 0 | 35 | 65 |

3系統とも同値を初期値とする。

### ②' 小技では決着しない（§4.5）— **本タスクの要**

**小技（d2〜5）による攻撃では、フォール決着およびギブアップ決着が発生しない。**

| 決着タイプ | 小技での発生 |
|---|---|
| フォール | **不可** |
| ギブアップ | **不可** |
| TKO | **可**（既存条件のまま。`tkoConsecutiveThreshold` / `tkoHpThreshold` は変更しない） |

- **HP下限**: 小技によるダメージでは防御側のHPが **1を下回らない**（下限1でクランプ）。小技でHP0に到達したまま決着せず膠着する事態を防ぐ
- **丸め込み（`rollup`）は本規則の対象外**。d4〜5 だが、フォール決着こそが本体。そもそもティア制の枠外（④）
- 判定は**ティアで行う**こと。ダメージ実数ではない（小技でもステータス補正で最終ダメージが9を超えることがあるため、既存の `pinAttemptMinDmg` による絞り込みとは別物）

### ③ フィニッシュ級の解禁（§5）

- d14〜16 は、**防御側の HP率が `ENG.pinAttemptHpThreshold` 以下になるまで大技ティアの抽選対象に入らない**
- **新規定数を作らないこと。** 既存の `pinAttemptHpThreshold` を参照する（通常0.35 / ビッグマッチ0.25 が自動的に効く）
- 未解禁時の大技ティア候補は d11〜13 のみ

### ④ 丸め込みの独立経路（§6）

- `rollup` はティア制の**対象外**。毎ターン、ティア抽選の**前に**丸め込み判定を行い、成立したら丸め込み技を選んでティア抽選をスキップ
- 発生率: Opening 0% / Mid 3% / End 5% / Climax 7%（`PHASES` 等に `rollupRate` として持たせる）
- `catW` から `rollup` エントリーを削除する（二重抽選の防止）
- **決着処理（`rollupHpThreshold` / `rollupBaseSuccess` / `rollupTecBonus`）は変更しない**

### ⑤ 大技クールダウン（§7）

- 大技（フィニッシュ級含む）を**選択**した次の自分のターンは大技ティアを選べない
- 命中/失敗/カウンターは問わない。選択した時点でフラグを立てる
- ファイター初期化（`gritTurns` / `kickoutCount` / `consecutiveHits` を作っている箇所）に `bigMoveCooldown` を追加
- クールダウン中は残ティアの重みを再正規化（例: Climax なら中技100%）

### ⑥ カテゴリ抽選の修正（§8）

現行はカテゴリを `catW` から引いてからプールを絞るため、該当なしのとき**プール全体からの完全ランダム**にフォールバックしている。これを廃止する。

```
1. ティアを抽選（②、⑤のクールダウン考慮）
2. そのティアの候補集合に実在するカテゴリを列挙
3. catW[style] を、列挙されたカテゴリだけで正規化
4. カテゴリ抽選 → 該当技から一様抽選
```

フォールバック分岐が不要になること（＝どのティアも必ず1つ以上の候補を持つこと）を確認し、万一の空集合に備えた防御コードは残してよいが、通常経路では到達しないこと。

## 適用範囲

`Engine.battle`（シングル）と**タッグ試合ロジック（`TAG_MATCH_CONFIG` を使う経路）の両方**に適用する。両者で技選択の実装が分かれている場合は、共通ヘルパーに切り出して二重管理を避けること。

## やってはいけないこと

- 技データ（技名・`d`値・`c`カテゴリ）の変更
- `Math.random()` の使用（必ず `Engine.rng` 経由）
- ダメージ計算式（`calcDamage`）・命中率（`calcHitRate`）・カウンター率（`calcCounterRate`）の変更
- 決着判定（`finishWeights` / pin / TKO / grit / kickout）の**パラメータ**変更（②' で必要なティア条件の追加は除く）
- 新しいバランス定数の追加（③のとおり既存の閾値を参照する）

## 検証（必須）

実装後に auto-sim を回し、**以下を数値で報告すること**。

```bash
node test/auto-sim.js 100 42
```

計測項目（`test/auto-sim.js` に一時的な計測コードを足してよい。ただし最終コミットに残すかは報告時に明示すること）:

1. **決着技のティア内訳** — 小技によるフォール／ギブアップ決着が **0件** であること（本タスクの主目的）。小技によるTKOは発生してよいので、件数を分けて報告すること
2. **フェーズ別のティア出現率** — 設計値（70/25/5 → 35/45/20 → 15/55/30 → 0/35/65）と一致するか
3. **フィニッシュ級の出現回数** — 1試合あたりの平均。0回で終わる試合の割合
4. **大技の2連続発生率** — クールダウンが効いていれば 0 のはず
5. **平均ターン数 / 時間切れ判定率** — 変更前後の比較。**本変更は3つの要因（Opening小技70への引き上げ／End大技30への引き下げ／小技で決着しない）がいずれも試合を長くする方向に働く**。`MAX_T` = 16 を超えた判定決着が増えていないか要注意。増えていた場合は数値を報告するのみとし、**対処は行わないこと**（実測してから方針を決める）
6. **MQ分布** — 全体が押し上げ/押し下げられていないか
7. **OVR差帯ごとの勝率** — 変更前から動いていないか

**5〜7 は変更前の値も測ること**（実装前に一度 auto-sim を回してベースラインを取る）。

`validateGameState` の違反が1件でも出た場合は修正してから報告すること。
