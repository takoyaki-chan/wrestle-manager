## 反映すべき確定事項

`src/data.js` の `ATTENDANCE_V2_CONFIG` / `SHOW_DRAW_CONFIG` / `VENUES` と
`src/management.js` の `Engine.attendanceV2`(`calcCardSlots` / `calcVolumeFactor` /
`calcAttendanceV2`)を**必ず読んで実値を確認**すること。この指示書と食い違ったら**実装が正**。

1. **解決した問題**: 団体人気が上がると reach がキャパを大きく超え、
   **2試合の薄い興行でも大ホールが満員**になっていた(draw下限0.3が効きすぎ)。
   試合数が動員にほぼ影響せず、「毎週2試合で満員・消耗最小」が最適解になる穴だった
2. **実効試合数 = 消費枠数**(シングル1枠・**タッグ2枠**)。
   タッグ優遇も冷遇もしない中立設計(枠=興行の尺)
3. **ボリューム係数 V** を `reach × draw` の直後に乗算(heat/揺らぎ/momentum/ソフトキャップより前)。
   `rawDemand`(=会場の熱→MQ)にも同じ V が効く
4. **適正試合数 = その会場の試合枠数 − 1**(`minMatchesByVenue`)。
   枠数は会場ごとの**上限**であり、超過は存在しない
5. **不足は累進**(1試合不足は軽く、増えるほど加速)。会場5帯で厳しさが違い、
   小会場は下限0.50で守られ、ドームが最も厳格。実値は `volumeShortageByVenueBand` を読むこと
6. **枠数フル(=適正+1)で1段だけ微弱ボーナス**(会場帯別+2〜6%、ドームが最厚)。
   `volumeExcessPerSlotByVenueBand`。上限は maxMatches−適正=1段
7. **旧 shortPenalty1/2 は撤去**(V に一本化。二重罰にしない)
8. **特別興行(PPV GRAND FINAL/天頂戦/ジュニア/春タッグ/秋対抗戦)は対象外**
   (`Engine.specialEventFinance` の固定収益経路であり `calcAttendanceV2` を通らない)

## 経済への副作用(必ず記録する)

旧実装はタッグを「1試合」と数えて不足判定していたため、**タッグ入りカードが大箱で
常に隠れペナルティを受けていた**。枠数評価でこれが解消され、auto-sim 40年で
**平均動員 +52% / 興行収入 +32%**(★5興行率は30%→20%)。
V の上限(+18%)では説明できない差は複利(満員→勢い→人気成長→reach増)によるもの。
**実機での経済ウォッチが必要**である旨と、締める場合のレバー
(`expectedDrawCurve` または超過ボーナス β)を明記する。
