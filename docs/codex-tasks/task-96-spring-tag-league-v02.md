## 6. 数値目標と不変条件(対で書く。マージ前にFableが1つずつ検算する)

- **I-1(規模)**: 出場は3/2/2/1の計8チーム・試合数12+1=13 — **ただし**返上発生時は繰り下げで埋め、6チーム未満なら中止(5チーム以下で無理に開催しない)。チーム数6〜8の全ケースをテストで固定
- **I-2(組み分け)**: 同一団体のチームが1ブロックに3つ入らない/**決勝は必ず別ブロックの1位同士**。テストで固定
- **I-3(順位の独立)**: 順位は各ブロック内で独立。全体1〜8位を作らない
- **I-4(掛け持ち禁止)**: 同一選手が同一大会に2チーム以上で出場しない(プレイヤー編成・AI自動編成・自動補完の全経路)
- **I-5(共通基盤不変)**: `Engine.tagMatch.simulateTagMatch`・`Engine.wear`・タイブレーカー規則(勝ち点→h2hミニリーグ→総MQ→決定論的乱数)のロジックは変えない。連戦消耗はブロック内で持ち越し、決勝は当該チームの最終conditionを引き継ぐ
- **I-6(報酬の据え置き)**: 殿堂pt(優勝+3/両選手)・対団体ポイント(springTag: 8)・人気+10(優勝2名のみ)・ベストタッグ称号(優勝のみ)は値・対象とも不変。賞金のみv0.2 §5へ変更
- **I-7(決定論)**: 同一シードで結果・リプレイが完全再現。simulateReplayのseedTag対応表をテストで固定
- **I-8(旧セーブ互換)**: format:2導入後も、旧形式の `G.springTagLeague`・過去シーズンの記録表示(記録タブ/選手ファイル/新聞アーカイブ)で例外・undefined露出が出ない
- **I-9(careerRecord不変)**: 優勝/準優勝のcareerRecordイベントshapeはv0.1と同一(参加チーム数が変わるだけ)。DB・選手ファイル・殿堂の集計コードを変更しない
- **I-10(進行保証)**: 13試合進行+決勝演出の待ちにはタイムアウト+二重起動防止フラグをセットで付ける(§5-D鉄則1)。1操作=1進行
