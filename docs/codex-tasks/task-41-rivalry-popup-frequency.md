## 現象(Keisuke実機 2026-07-31)

> 毎週、この「因縁の一戦」みたいな画面が出て、鬱陶しい。そんな別に節目でもないのに、
> 毎試合出てる感じがする。

実機スクリーンショットでは、**OVR52 vs 53・MQ31・★1** という平凡な試合でも
「因 縁 の 一 戦 / 🔥宿敵」のモーダルが出ていた。

## 原因(こちらで特定済み)

`src/ui-common.js` の `_queueRivalryMatchDialogue`(4841行付近):

```js
if ((r.rivalryBonus.rivalry || 0) < 30) return;   // ← 閾値が低すぎる
```

**rivalry 30 以上で無条件に発火**する。加えて:
- **1興行あたりの上限がない**(同じ興行で複数出る)
- **同じペアのクールダウンがない**(毎週同じ2人で出続ける)

## 直す方針

「**節目にだけ出る**」ようにする。以下3つを**すべて**入れること。数値は
`src/data.js` に**設定として切り出す**(将来調整できるように):

### 1. 発火の閾値を上げる

rivalry がゲーム的に意味を持つ水準まで上げる。参考: 既存コードは
`>= 40` を「ライバルと呼べる」目安に、`>= 60` を決着処理の下限に使っている
(`Engine.title.checkResolution` は `minRivalry < 60` で決着させない)。

**推奨: 60 以上**(=決着が視野に入る水準)。ただし
`isGoodRival`(好敵手)・`isBitterRival`(宿敵)の**称号持ちは閾値未満でも通す**
(称号が付いている関係は「節目」と呼べるため)。

### 2. 1興行あたりの上限

**1興行につき最大1件**(最も rivalry が高いカードだけ)。
複数該当したら rivalry 降順で1件を選ぶ。

### 3. 同じペアのクールダウン

一度出したペアは**一定期間(推奨: 8週)出さない**。
GameState に書き込む必要があるなら、**表示済み記録の最小限のフィールド**を
`G` に持つ形にしてよい(例: `_rivalryPopupSeen: { 'idA-idB': week }`)。
**セーブに残す前提で、古いエントリは自然に消えるようにする**(週が過ぎたら削除)。

## 不変条件

1. rivalry の**計算・蓄積・決着ロジックには触れない**(演出の頻度のみ)
2. 決着(`因縁決着` / `宿敵戦勝利` など)の演出は**従来どおり必ず出す**
   — これは本物の節目なので抑制対象外。**抑制するのは通常の「因縁の一戦」だけ**
3. 閾値・上限・クールダウンは `src/data.js` の設定値から読む(ハードコードしない)
4. 既存セーブで `_rivalryPopupSeen` が無くてもクラッシュしない
5. `npm test` 全PASS(149/149+新規)
