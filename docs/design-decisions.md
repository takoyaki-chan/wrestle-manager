## コアシステム

### 能力値5種の試合内での位置づけ（2026-07-20 明文化）
- **PW / SP / TE / ST の4つが試合内の能力として拮抗する。MN（マインド）はそこから一段落ちる。**MN は試合外で効いてくる能力として設計する
- MN は試合エンジン内に多数の経路を持つ（被ダメ軽減 `defMntScale` / キックアウト `kickoutMnScale` / ギブアップ耐性 `guEscapeMnScale` / フォール耐性 `pinAttemptMntPenalty` / 終盤の粘り End-8%・Climax-12%）が、**経路の数と実効果は別物**。大量シミュレーションによる実測では、既存仕様において MN の試合内効果は他4要素より低く出ている
- **不変条件**: ダメージ式の防御項 `defense = ST×defStaScale + MN×defMntScale` の比率を崩さないこと。既存仕様は `0.025 : 0.06`（ST:MN = 1:2.4）で検証済み
- **実例**: task-10（2026-07-20）で `defStaScale` を 0.0125 へ半減したところ比率が 1:4.8 となり、MN が相対的に有利な方向へずれた。task-12 で 0.025 へ復帰。**片方だけを動かして辻褄を合わせない**

### 最大HP式と ST の寄与（2026-07-20 追加）
- 最大HP = `hpBase + ST × hpScale`（通常戦は `ENG`、大一番は `BIGMATCH_ENG`）
- **不変条件: HP係数を変更するときは「ST1ポイントが総HPに占める割合」を維持すること。** 旧仕様（`100+ST×1.8`）で 0.87%。この比率が ST とパワー等の力関係を決めており、崩すとキャラクターの個性（スタミナ型）が意味を失う
- 総HPを増やすときは `hpScale` も同じ割合で増やす。`hpBase` だけ増やすと ST の価値が目減りする
- **実例**: task-09（2026-07-20）で平均試合長を伸ばすため `198+ST×1.55` としたところ、ST1ポイントの寄与が 0.87%→0.53% に落ち、大一番で ST90 と ST40 のHP差が +43%→+15% まで縮小した。task-10 で `141+ST×2.50`（通常）/ `272+ST×3.50`（大一番）へ配分を戻して是正

### MQスコア（MQ再設計 P1〜P4後・確定 2026-07-24）
> 2026-07-20の棚卸し（`docs/mq-inventory-report.md`）を起点に、2026-07-24 MQ再設計（`docs/mq-redesign-proposal-v0.5.md`）で経路一本化・外部ボーナス全面再設計・上限撤廃+記録制へ移行済み。以下はP4着地時点の実装。旧v2.0（2本経路+固定加算+外部+12キャップ）の記述は完全に置き換え。

**経路一本化 ⭐（旧「確定経路が2本あり結果が一致しない」問題は解消）**
- `Engine.mq.finalize(state, matchResult, context, profile)`（`src/management.js:2299`〜）が唯一のMQ確定関数。headless（`Engine.executeShow`）・プレイヤー画面（`App._finalizeShowImpl`）の両経路がこの1関数を呼ぶ
- profile（`normal-single`/`normal-tag`/`ppv`/`raw`/`ai-show`）で興行種別ごとの適用要素を明示。「経路は一本、仕様差はprofileで明示」が原則
- 最終値 = `max(5, baseEngineMq + external)`。**上限クランプは存在しない**（下限5のみ）。旧仕様にあった段階的`min(100,...)`クランプ（画面経路4箇所）は共通関数化に伴い全廃

- **天井（OVシーリング）**: avgOV≤50: `20+OV×0.60` / ≤80: `50+(OV-50)×1.10` / ≤100: `83+(OV-80)×0.85` / **100超: `100+0.25×(avgOV-100)`（2026-07-24追加、§3.7b）**。丸め後15〜（旧上限100は撤廃、100超ペアはこの第4セグメントで緩やかに伸びる。OV100以下のペアは1点も変わらない不変条件を維持）（`src/match-engine.js`）
- **ドラマ減点**: 基本-30。KO×8（上限2回）・カウンター×2.5（上限3）・逆転×1.5（上限3）・大技×0.4（上限6）で回復。0〜30
- **超過レイヤー ⭐（2026-07-24 P3a新設、§3.7）**: ドラマ減点を完全に回復した試合（実測0.125%・シングル）で、回復上限を超えて発生したイベント分を逓減カーブで天井の**上へ**加算（`overflow = min(12, round(4×√(excess/4)))`）。「OVシーリングは重力であって運命ではない」を式にした唯一の経路。実測: overflow平均3.75・最大7、通常興行で最大106を観測
- **ペーシング減点**: シングルは通常戦8ターン以上=0/6〜7T=3/5T以下=12、大一番18ターン以上=0/14〜17T=3/13T以下=12。特性「引き出し上手」保持時は通常6/4T・大一番14/10Tへ緩和（減点値自体は0/3/12のまま）。下限のみで上限（だらだらペナルティ）は存在しない。実測: 発動率3.20%、平均-0.239でほぼ機能していない
- **決着減点**: フォール/ギブアップはフェーズ連動(Climax:0/End:1/他:3)、ピン=0、丸め込み=1、TKO=2、タイムアウト=10。実測: 発動率8.49%、平均-0.245
- **外部加算(crowd)のみ ⭐（旧・因縁+タイトル+trust+マイルストーン+ラストランの固定加算+12キャップは全廃）**: `Engine.mq.finalize`のcontributionsは実質`crowd`（観客の熱×試合注目度）だけが非ゼロになる。他（rivalry/title/trust/milestoneMqBoost/nextMatchMq）は常に0で、後述のとおり全て「リング内化(=シミュレーションへの入力になり素点が動く)」か「集客側へ移管」された
  - **観客補正 = venueHeat(会場の熱=需要/キャパ比ベース) × engagement(その試合の注目度)**（§3.2）。旧「観客/会場+4の下駄がほぼ定数で乗る」問題を解消し、試合ごとに配分。カード編成の妙(誰をメインに置くか)がMQに正しく響くようになった
  - 会場規模は熱の器（超満員時の上限が公民館〜小ホール+2からドーム+6〜7まで段階増加、§3.2b）。ドーム興行のメインはビッグマッチ(大一番)ルールでシミュレーションされ、超過レイヤー圏内に届きやすい
  - **因縁**: 固定+1〜+5は廃止。因縁段階(45/55/65/80)がカウンター率+2〜+5pt・脱出率+0.05〜+0.15をリング内で押し上げる方式に転換（名勝負製造機と同じ機構）。加えてengagementに因縁が寄与（客がいない会場では沸きようがない、掛け算で自然に反映）
  - **タイトル**: 固定+5は廃止。王座戦は脱出率+0.10・カウンター率+4ptのリング内効果+engagement+0.2へ
  - **trust**: 事後減算-1.53×人は廃止。trust<35の選手はその試合の実効OVが-3落ちる「コンディション化」に転換（心が離れたエースの塩試合が数値操作ではなく本人の出来として現れる）
  - **マイルストーン/次戦バフ**: 固定+3の加算は廃止。該当選手の実効OVを+2するコンディション化に転換
  - **ラストラン**: 固定+2/+5は廃止（他の固定加算を解体した後では最大の下駄になるため）。出場で実効OV+1、メインでengagement+0.25（引退ロードのメインはengagement上限を1.25→1.4へ拡張）のリング内+注目度化に転換
  - **鮮度**（初顔+2/マンネリ-1〜-5）: MQ加算は全経路から廃止し、集客(動員計算)側の係数へ完全移管
- **タイトルマッチ格差ペナルティ**: 廃止済み（OVR差メタデータ自体は生成されるが、MQへの減算処理はコードにない）
- **歴代最高MQ記録制 ⭐（2026-07-24 P2/P3e、§2）**: 上限撤廃に伴い`state.mqRecord`(シングル業界記録・スタート値90)/`state.mqRecordTag`(タッグ業界記録・スタート値94)を新設。全団体・全経路(PPV/天頂戦含む)を対象にした業界記録1本ずつ。更新は`Engine.mq.updateRecord`が検知し、大ニュース新聞記事(`mqAllTimeRecord`/`mqTagRecord`、P4)として自動的に一面化される。物語系(新聞評価・年代記・実績)は記録連動の相対評価、機械系(trust/人気/成長閾値)は絶対値のまま維持
