## 2. 解決策の全体像

2つの仕組みで経済を安定化する:

### A. 運営費（orgPop連動の週次コスト）
- **名目**: 広報費・ファンサービス費・スタッフ増員費
- **式**: `運営費 = orgPop × 5万/週`
- **効果**: orgPop 65で325万/週 = シーズン約16,900万の追加支出
- **目的**: 利益率の天井を50%→25-30%に下げる自動安定化装置

### B. 設備投資（消耗品モデルの金吸い込み口）
- 2種の設備を購入。等級C/B/Aで効果と価格が異なる
- 使っていくうちに劣化し、効率が落ちる。最終的に故障する
- 余裕のある団体はA級で大金を吐き出す。カツカツの団体はC級で凌ぐ
- **核心**: 懐具合に応じた自然な支出サイクルが生まれる

## 3. 設備2種の定義

### 3.1 リング・トレーニング設備

選手の練習環境と試合環境を改善する設備。

| 効果 | C級 | B級 | A級 | 効果の理由 |
|------|-----|-----|-----|-----------|
| 練習成長ボーナス | +5% | +10% | +15% | 良い設備で効率的に練習できる |
| 試合後コンディション消耗軽減 | -1 | -2 | -3 | 良いリングは体への負担が小さい |
| 追込練習コンディション消耗軽減 | -0.5 | -0.8 | -1.2 | 設備が良いと安全にハードトレーニングできる |

**注意: MQには一切影響しない。** 試合の質はエンジンが決める。設備は「体の負担を減らす」「練習効率を上げる」という環境効果のみ。

### 3.2 メディカルケア設備

選手の医療・リハビリ環境を改善する設備。

| 効果 | C級 | B級 | A級 | 効果の理由 |
|------|-----|-----|-----|-----------|
| 怪我期間短縮 | -1週 | -1週 | -2週(min1) | 良い医療設備で回復が早い |
| コンディション回復ボーナス | +0.5/週 | +1.0/週 | +1.5/週 | トレーナー・リハビリ設備 |
| wear蓄積軽減 | ×0.9 | ×0.8 | ×0.7 | 体のケアで選手寿命が延びる |
| 怪我後成長デバフ軽減 | ×0.9 | ×0.8 | ×0.7 | リハビリ設備で復帰が早い |

## 4. 等級・価格・寿命

| 等級 | 購入費 | 寿命 | 効果率 |
|------|--------|------|--------|
| C級 | 500万 | 2シーズン(96週) | A級の60% |
| B級 | 3,000万 | 3シーズン(144週) | A級の80% |
| A級 | 15,000万 | 4シーズン(192週) | フル効果 |

### 金額の意図
- **A級2つ = 30,000万**: シーズン純利益(約30,000万)がほぼ消える
- 4シーズンごとに買い替え → 常時7,500万/シーズンの定期支出
- **運営費(16,900万) + A級維持(7,500万) = 24,400万/シーズン** → 純利益30,000万から引くと残5,600万（利益率9%）
- B級2つなら2,000万/シーズン → 純利益28,000万（まだ余裕あるが選択の余地がある）

## 5. 劣化の仕組み

### サイクル
1. 購入: 耐久度100%
2. 毎週: 耐久度が `100 ÷ 寿命(週)` ずつ自動減少
3. **効果は耐久度に比例**: 耐久度70%なら効果も70%
   - 例: A級cond回復ボーナス +1.5 × 70% = +1.05/週
4. 耐久度50%以下: 「老朽化」警告（UIで黄色バッジ）
5. 耐久度0%: 「故障」（効果ゼロ、UIで赤バッジ）
6. いつでも買い替え可能（残り耐久度は捨てて新品に交換）

### 設計意図
- 「もう60%だけどまだ使える...」「いや余裕あるしA級で新調するか」という判断が自然に発生
- 金持ち団体は早めにA級で買い替え → 大量に金を吐き出す
- カツカツの団体は壊れるまで使ってC級で凌ぐ

### 数値精度
- A級の週あたり劣化: 100/192 = 0.520833...
- 小数第2位で丸める（`Math.round(x * 100) / 100`）
- 192週後に正確に0%到達を保証

## 6. 現行コードへのフック箇所

設備なし = 現行と完全に同じ動作。全ゲッターが中立値(0 or 1.0)を返す。

### 6.1 リング・トレーニング設備のフック

**練習成長** (`management.js` calcGrowth L2684):
```
現行: baseGain = baseLearning × ratio × ageMul × coachMul × rookieMul × gritMul
変更: baseGain = 上記 × Engine.facility.getTrainingGrowthMult(G)
  → 設備なし: ×1.0（変化なし）、A級100%: ×1.15
```

**試合後コンディション消耗** (`management.js` processSettlement L5956):
```
現行: condition -= (8 + rng.int(0, 7))    // 8-15のランダム消耗
変更: condition -= Math.max(1, (8 + rng.int(0, 7)) - condReduction)
  → 設備なし: -0（変化なし）、A級100%: -3（消耗が5-12に軽減）
```

**追込練習コンディション消耗** (`management.js` L5461):
```
現行: condition -= Math.round(5 + rng.int(0, 5)) + traitBonuses
変更: condition -= Math.max(1, Math.round(5 + rng.int(0, 5) - intensiveReduction)) + traitBonuses
  → 設備なし: -0（変化なし）、A級100%: -1.2（消耗が軽減）
```

### 6.2 メディカルケア設備のフック

**コンディション回復** (`management.js` processSettlement L5969):
```
現行: baseRecovery = 3 + Engine.coach.getCondBonus(G, c.id)
変更: baseRecovery = 3 + Engine.coach.getCondBonus(G, c.id) + Engine.facility.getMedicalCondBonus(G)
  → 設備なし: +0（変化なし）、A級100%: +1.5/週
```

**怪我期間** (`management.js` executeShow L6727/6750 — injury.check呼び出し後):
```
現行: injury.check()の戻り値をそのまま使用
変更: 戻り値のinjury.weeksLeftからgetMedicalInjuryReduction(G)を引く（min 1）
  → 設備なし: -0（変化なし）、A級100%: -2週
```

**怪我後成長デバフ** (`management.js` executeShow L6727/6750 — injury.check呼び出し後):
```
現行: growthPenalty.remainingWeeksをそのまま使用
変更: remainingWeeksにgetMedicalDebuffMult(G)を掛ける（min 1）
  → 設備なし: ×1.0（変化なし）、A級100%: ×0.7
  → 重傷デバフ24週 → 17週に短縮
```

**wear蓄積** (`management.js` L2749):
```
現行: finalWear = max(1, round(finalWear × Engine.coach.getWearMult(G, nc.id)))
変更: finalWear = max(1, round(finalWear × coachWearMult × Engine.facility.getMedicalWearMult(G)))
  → 設備なし: ×1.0（変化なし）、A級100%: ×0.7
```

### 6.3 運営費（C案）

**processSettlement** (`management.js` L5721後):

      totalExpense += operatingCost

## 9. 収支シミュレーション予測

### 運営費のみ導入した場合（A級設備なし）
| シーズン | orgPop | 運営費/年 | 旧純利益 | 新純利益 | 新利益率 |
|---------|--------|----------|---------|---------|---------|
| 1 | 23 | 5,980万 | 9,172万 | 3,192万 | 22% |
| 5 | 58 | 15,080万 | 23,953万 | 8,873万 | 17% |
| 10 | 66 | 17,160万 | 31,377万 | 14,217万 | 22% |
| 20 | 68 | 17,680万 | 33,142万 | 15,462万 | 24% |

### 運営費 + A級設備2つの場合
| シーズン | 運営費 + 設備維持 | 旧純利益 | 新純利益 | 新利益率 |
|---------|-----------------|---------|---------|---------|
| 1 | 5,980万 + 0 | 9,172万 | 3,192万 | 22% |
| 5 | 15,080万 + 7,500万 | 23,953万 | 1,373万 | 3% |
| 10 | 17,160万 + 7,500万 | 31,377万 | 6,717万 | 11% |
| 20 | 17,680万 + 7,500万 | 33,142万 | 7,962万 | 12% |

**結論**: 運営費で基盤を安定させ、設備投資で「余裕分を使いたくなる」構造にする。設備を買わなくても黒字だが、買えば大幅に有利→「金を使いたくなる」動機。

## 10. 検討事項（チャットで詰めるポイント）

### 価格バランス
- A級15,000万は高すぎ/安すぎ？
- C級500万は序盤でも手が届く？（初期資金5,000万）
- 等級間の価格差が大きすぎる？（C:B:A = 1:6:30）

### 効果の強さ
- 成長+15%は大きすぎ/小さすぎ？
- cond消耗-3（8-15→5-12）は体感できる？
- wear×0.7はベテランの寿命延長としてバランス取れる？
- 怪我-2週は重傷(6-8→4-6)に対して効きすぎ？

### 劣化速度
- 2シーズン(C級)は短すぎ？買い替えが面倒になる？
- 4シーズン(A級)は長すぎ？金吸い込み不足？
- 劣化が線形でいいか？後半加速とか？

### 運営費の係数
- orgPop × 5万は適切？序盤(orgPop 23)で115万/週は重い？
- 補助金との関係（orgPop 40未満は補助金あり、運営費も低い→相殺される）
- orgPopが低い間は運営費も低いので序盤は自然に軽い

### UI/UX
- 設備を団体画面に置くか、別の画面か
- 買い替え時に確認ダイアログは必要か
- 劣化の通知タイミング（50%? 25%? 故障時?）

### ゲームデザイン
- 設備なしでもゲームクリアできる難易度を維持するか
- AI団体にも設備概念を入れるか（orgTier依存で自動保有等）
- オフシーズンのみ購入可能にするか、いつでも買えるか
