# MQ全要素棚卸しレポート

調査日: 2026-07-20

基準: task-10完了コミット `dc09ecd`、task-11計測追加後の作業ツリー

主計測: `node test/auto-sim.js 100 42`（100シーズン、seed 42）

## 0. 結論

1. MQの確定経路は1本ではない。プレイヤーが画面から興行を見る本番経路は `App._finalizeShowImpl`、headless/auto-simは `Engine.executeShow` を使い、外部補正・キャップ・trust・鮮度の扱いが異なる。
2. シングル試合エンジンは下限5だけを適用し、上限100ではクランプしない。タッグエンジンは5〜100へクランプする。プレイヤー画面経路は外部補正の各段階で100へクランプするが、`Engine.executeShow`、AI興行、PPV、イベント戦、天頂戦は最終MQを100へクランプしない。
3. 外部プラス補正の定数は文書・コメントの+15ではなく `MQ_EXTERNAL_CAP = 12`。しかもこのキャップを使うのは `Engine.executeShow` のシングルだけで、100シーズン中の到達は0/6,812試合だった。
4. 実測で最も大きい負方向要素はドラマ減点（平均-20.420）。シングルのペーシング減点は平均-0.239、発動3.20%で、依然としてかなり低頻度である。
5. 通常興行バックエンドの外部補正は観客・会場補正が平均+4.013で支配的だった。因縁は平均+1.008、trustは平均-0.029、その他は0だった。
6. 恒久的に死んでいる、または現経路から外れている要素が複数ある。ケミストリーは常に0、タイトル格差ペナルティ・コーチMQ・プロモMQ・ファン期待MQ・野心MQ・コスチュームMQは廃止済みである。一方、画面経路だけは鮮度MQをまだ加減算している。

### 1.4 プレイヤー画面の本番興行経路 (`App._finalizeShowImpl`)

2. ケミストリーを加算して直ちに`min(100, ...)`する分岐があるが、現在は常に0（`src/app.js:6144-6145`）。

## 4. 死んでいる要素・低寄与・支配的要素

### 恒久的または経路上で無効

- ケミストリー: `getMatchChemistryBonus()` が常に0。AI、画面、PPV、天頂戦に加算分岐だけが残る。
- タイトル格差ペナルティ: OVR差メタデータは通常バックエンドで作るが、加算処理は廃止コメントだけで実処理なし。
- コーチMQ、プロモstack MQ、ファン期待MQ、野心MQ、見返しMQ、コスチュームMQ、鮮度MQ（バックエンド側）は廃止済み。
- `resolveEventMatch` の汎用 `mqBonus`: 現在確認できる呼出しはすべて0。
- 片側因縁MQ: 定数が0。
- 通常バックエンドのタッグに対する因縁・タイトル・マイルストーン・trust・外部cap: 早期returnのため適用されない。

### 実測上ほぼ死んでいる/差を作りにくい

- シングルのペーシング減点: 発動3.20%、平均-0.239。
- シングルの決着減点: 発動8.49%、平均-0.245。
- タッグ長区間ペナルティ: 発動5.06%、平均-0.173。
- 通常バックエンドtrust: 発動1.81%、平均-0.029。
- +12外部cap: 到達0%、切捨て0%。

### 支配的/ほぼ定数

- ドラマ減点: 平均-20.420、発動99.81%。MQの分散を作る中心だが、中央値22でほぼ全試合に大きく掛かる。
- 観客/会場: 平均+4.013、発動99.54%、標準偏差0.438。通常興行の外部寄与の約80%を占め、auto-simでは実質的に定数に近い。
- タッグの出場偏りペナルティ: 平均-5.773、発動75.42%。タッグ固有の最大の負寄与。

値の変更提案は本タスクの範囲外なので行わない。
