# 新聞再設計 spec v0.1 — 「タブ付きデータベース」から「一枚の新聞」へ

起票 2026-08-01。`docs/newspaper-overhaul-plan.md` の N-9〜N-13 に対する設計提案。
**DRAFT。Keisuke 承認後に実装。**

## 0. 何が問題か（再掲）

今の新聞は「1面=興行 / 2面=団体比較 / 3面=因縁列伝 / 4面=MVPレース」と
**枠が先に決まっていて、中身を流し込んでいる**。その結果——

- 中身のない週でも何かが一面に来る（「ドラフト全指名が成立」・写真なし）
- 団体比較は動きがなくても毎号同じ顔で出る
- 大怪我や引退のような本当のニュースが、興行記事の下の小枠に沈む
- 各面が独立したデータベース画面になっていて、新聞を読んでいる感じがしない

新聞は逆で、**その週に起きたことの大きさが紙面の大きさを決める**。

### 在庫の扱い（Keisuke 裁定 2026-08-01）

**既存の記事文は資産ではなく候補**。新しい紙面に合うなら使う、合わないなら
書き直す・捨てる。在庫を活かすために設計を曲げない。
（§4 で死蔵158本の接続先を挙げているのは「たまたま新設計と噛み合うから」であって、
温存が目的ではない。接続してみて文面が紙面に合わなければ全面書き直しに切り替える）

## 1. 紙面構成

### 1面（Keisuke 裁定 2026-08-01: 特大1本では埋まらない。特大1+2番手2）

```
┌────────────────────────────────────┐
│ 題字・号数                          │
├──────────────────┬─────────────────┤
│ ◆特大記事（写真大）│ MVPレース小窓    │ ← 順位表3行+「詳細▶」
│   その週の最高点   ├─────────────────┤
│                   │ ◆2番手記事A      │
│                   ├─────────────────┤
│                   │ ◆2番手記事B      │
├──────────────────┴─────────────────┤
│ 黒田コメント（一面の締め）           │
└────────────────────────────────────┘
```

- **特大**: スコア1位。写真必須（人物が特定できない記事は特大に昇格させない → §3）
- **2番手A/B**: スコア2位・3位。小さめの写真+見出し+リード1文
- **MVP小窓**: 首位3名と点差だけ。クリックで現4面相当の詳細が開く（固定面は廃止）

### 2面以下（サイズ差をつける。画一的な同サイズ並びにしない）

```
┌────────────────────────────────────┐
│ ◆中記事（写真中） ← 一面級が2本ある │
│   週はここに「準特大」で置く        │
├───────────────┬────────────────────┤
│ ◇小記事        │ ◇小記事            │
├───────────────┼────────────────────┤
│ ◇小記事        │ ▪ベタ記事（文字のみ）│
└───────────────┴────────────────────┘
```

- 2面の頭は「準特大」枠。**一面級のニュースが同じ週に2本あったら、2本目はここ**
  （一面に無理に詰めず、二面トップで大きく扱う。Keisuke 裁定）
- 以降は 中記事（写真あり）/ 小記事（顔チップ）/ ベタ記事（文字だけ）の3サイズ
- 特集（§4）が発火した週は、特集が2面か3面を1枚使う

### ページ数は可変

ニュースが少ない週は2面で終わってよい。無い記事をでっち上げない。
静かな週は §4 の特集・読み物で厚みを出す。

## 2. ニュースバリュー採点

既存の `Engine.newspaper.PRIORITY`（約70種）をそのまま土台に使い、**帯**で扱いを決める。

| 帯 | スコア | 扱い |
|---|---|---|
| S | 300以上 | 一面特大の資格。複数あれば2本目は二面頭の準特大 |
| A | 200〜299 | 一面2番手 / 二面頭 |
| B | 100〜199 | 二面以下の中記事・小記事 |
| C | 100未満 | ベタ記事・埋め草。**一面には絶対に上げない** |

### 一面最低ライン（N-8 の再発防止）

特大はスコア **150以上かつ写真が付く**記事に限る。満たす記事がない週は、
特大枠を「静かな週の特集」（§4）に譲る。「ドラフト全指名が成立」のような
状況報告だけの記事が一面に来る事故を構造的に断つ。

### 足りていないニュース源（採点表への追加）

現状イベント化されていない/弱いもの。実装時に produce 側を足す:

| 追加 | 目安スコア | 中身 |
|---|---|---|
| 自団体選手の大怪我（長期離脱） | 280 | 全治週数・直近の活躍・穴の大きさ |
| 自団体選手の引退表明 | 290 | キャリア総括。写真大 |
| 連勝・連敗記録（節目） | 180 | 何連勝目か・止めた/止められた相手 |
| 移籍・引き抜き成立（自団体絡み） | 220 | 出入りの文脈（因縁・古巣） |
| ドラフト総括（N-8 の作り直し） | 160 | **指名全体から OVR 上位5名 or trainCap 上位5名を顔付きで並べる**「今年の金の卵」 |

## 3. 写真ルール

- 特大: アッパー画像 大（複数人は §2-B の隊列）。**反転禁止**
- 準特大・中記事: アッパー中
- 小記事: 顔チップ（既存の np-sub-photo）
- ベタ: 写真なし
- **写真が解決できない記事は自動的に1段格下げ**（特大→準特大→中…）。
  「一面なのに写真がない」を仕組みで防ぐ

## 4. 特集（固定面の降格先）

| 特集 | 発火条件 | 使う在庫 |
|---|---|---|
| 団体比較 | 業界順位の入れ替わり / 格付け昇降 / 対抗戦の前後 / シーズン開幕号・総括号 | **死蔵中の `KURODA_HEADLINES` 95本 + `KURODA_EDITORIAL` 63本をここに接続**。低評価帯（devastating/behind）の記事は自団体が強くなった後も「他団体を扱う記事」として出す → N-3/N-4/N-5 が同時に解消 |
| 因縁列伝 | 因縁が動いた週のみ（決着 / 再燃 / 初対決 / 9象限の遷移） | `KURODA_RELATION_NARRATIVE`。見出しは1本化し、**見出し+本文をセットで抽選**（N-6/N-7） |
| 静かな週の読み物 | S/A 帯が1本もない週 | 選手ロングインタビュー風・記録コーナー・ファンの声 特集など。既存の雰囲気テキスト在庫を転用 |

どの特集も**毎号は出ない**。「動きがあったから記事になる」を貫く。

## 5. MVPレース（N-11 / N-12）

- 固定4面を廃止。一面小窓（首位3名+点差）→ クリックで詳細ページ
- 詳細の本文を書き直す: 下位の選手に因縁の話は書かない。
  **「この順位にどう食らいついているか」**（直近の勝敗 / 点差の詰まり方 /
  追う側か逃げる側か / 残り週数）だけで構成する
- 生成は既存 `Engine.mvpRace.generateRichBlocks` を改修（テーブル化して Excel に載せる）
