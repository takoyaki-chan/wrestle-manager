# 技イラスト・大技カバレッジ計画 v0.1

> この文書は「何をどの順で制作するか」の正本である。ゲームへ安全に接続する実装手順は [試合エンジンへの技イラスト統合仕様](move-illustration-integration-spec-v0.1.md) を読む。

## 結論

技イラストは、枚数を先に決めない。ゲーム内で**大技として選ばれる技を先に漏れなくカバー**し、その後に共通の小技を足す。

現行の30枚は投げ技・関節技の基本セットとして保持する。ただし、この30枚だけではスタイル固有の決め技、特に空中技が大幅に不足しているため、完成セットとは扱わない。

## 優先度の定義

| 優先度 | 対象 | 扱い |
|---|---|---|
| **P0: 必須** | `src/data.js` のスタイル固有技のうち威力 `d >= 11` | 絵が未割当のまま実装・公開しない。決め技／見せ場なので最優先。 |
| **P1: 基本** | 共通の打撃・投げ・関節・空中・グラウンド・丸め込みを代表する技 | P0を補い、通常ターンの試合展開を読めるようにする。 |
| **P2: 任意** | 同カテゴリの細かな差分、低威力の小技 | 抜けていても試合の見せ場は損なわない。必要になった時に追加する。 |

`d >= 14` のフィニッシャー相当は、原則として専用絵にする。`d = 11–13` も、組み方・落とし方・着地が別の技に見える場合は専用絵にする。

## 共用してよい条件

名前が似ているだけでは共用しない。次の三点が同じ場合だけ、同一の絵を別名技へ割り当ててよい。

1. 攻め側の握り方・身体の向きが同じ。
2. 受け側の姿勢と落下先が同じ。
3. 見た人がどちらの技名でも違和感なく認識できる。

例：`パイルドライバー` と `パイルドライバー（喧）`、`チョークスラム` と `チョークスラム（喧）` は共用候補。`パワーボム` と `シットアウト・パワーボム`、`パイルドライバー` と `ツームストン・パイルドライバー`、`バックドロップ` と `ジャーマン・スープレックス` は共用不可。

共用する時も、マニフェストに正規名と別名を両方記録する。試合ログの技名と絵の対応を失わせない。

## 現行30枚の位置づけ

現行30枚の内訳は、打撃6・投げ14・関節／絞め10である。空中技・グラウンド攻撃・丸め込みは0枚。

P0の候補として既に存在する、または構図確認のうえ流用候補にできるのは次だけである。

- ラリアット、エルボースマッシュ
- パワーボム（現版は再作画対象）
- ジャーマン・スープレックス、バックドロップ、パイルドライバー
- 腕ひしぎ逆十字（アームバー候補）、STF、足4の字固め、アンクルホールド
- ブレーンバスター（垂直落下式として使えるかは、参照ポーズで再判定）

したがって、現行30枚はP0を完了していない暫定素材である。特にAerialは大技10件に対して専用の空中技絵が0件である。

## 制作順

1. **フィニッシャー優先**：全アクティブスタイルの `d >= 14` を作る。空中系はこの段階で必ず着手する。
2. **残るP0**：各スタイルの `d = 11–13` を埋める。共用可否は上記3条件で判定する。
3. **P1の穴埋め**：空中技、グラウンド攻撃、丸め込みを最低2〜3種ずつ追加する。共通の関節・絞め技には、首四の字とネックシザーズも含める。
4. **P2の小技**：必要な試合ログや演出が出てから追加する。

次の参照絵作成バッチは、まず `16_powerbomb` の作り直しを含め、チョークスラム、デスバレーボム、ラストライド、ツームストン、ムーンサルト、シューティング・スター・プレス、450スプラッシュ、フロッグ・スプラッシュ、スワントンを優先する。

## 試合システム由来の共通演出セット

技イラストとは別に、試合エンジンが実際に出力する状態・イベントだけを共通演出の対象にする。レフェリーの人物素材・動作は制作対象外とする。

調査元は、シングル戦の `action` / `pinAttempt` / `rollup` / `kickout` / `tkoStop` と、タッグ戦の `events` / 法定選手・控え選手の入替である。現在のエンジンには、通常ダッシュ、ロープ反動、コーナー移動、場外攻防を独立して通知するイベントはない。したがって、それらの汎用絵は今は作らず、将来その状態をエンジンへ追加した時だけ制作対象にする。

### M0: シングル・タッグ共通（最初の試合画面導入に必要）

| assetId | 作る絵／部品 | 発火するシステム状態 | 使い方 |
|---|---|---|---|
| `cover-pin` | 攻め手が倒れた相手を押さえ込む二人構図 | `pinAttempt` の `fall` / `pin`。成功・返し・救出の導入 | レフェリーは描かない。カウント数字と組み合わせる。 |
| `kickout` | 受け手が肩を上げて押さえ込みを外す二人構図 | `kickout`、または `pinAttempt` の `kickout` | フォール絵と明確に差のある返し専用構図にする。 |
| `downed` | 決着後にも使える、リング上で倒れ込む一人用ポーズ | `tkoStop` とフォール／ギブアップ後の敗者表示 | 技固有の受け身ではなく、汎用の敗北・消耗状態。 |
| `tap-out-overlay` | 上げた手／マットを叩く手の透過オーバーレイ | `pinAttempt` の `gu` が `win` になる時 | 関節技の技絵を下地に重ね、ギブアップ決着を読ませる。 |

丸め込みは独立した決着経路だが、技名を伴う `rollup` の技イラストとして扱う。別の「丸め込み共通絵」を足さず、P1の丸め込み技を最低2〜3種作る方針を維持する。

### M1: タッグ固有（タッグ観戦画面で必要）

| assetId | 作る絵／部品 | 発火するシステム状態 | 備考 |
|---|---|---|---|
| `tag-touch` | ロープ際で手を伸ばし、手が触れる二人構図 | `tactical` または消耗による通常タッチ | この二種は同一絵でよい。成立後は法定／控えの表示位置を交換する。 |
| `hot-tag-entry` | 控え選手がリングへ踏み込み、前へ出る一人用ポーズ | `hotTag` | 「前にダッシュする動き」が実際に必要なのはこのイベント。既存の全身絵をCSSで入場移動させ、専用ポーズはこの1種だけ作る。 |
| `cutin-breakup` | 控え選手が押さえ込みへ飛び込み、攻め手を引き離す三人構図 | `cutinSave` | フォール中の救出専用。`cover-pin` と連続表示する。 |

`friendlyFire` は技名・攻防構図を持たないため、新規イラストは作らない。現行の全身立ち絵に横移動・衝突フラッシュを重ねる。`betrayal` も控え選手が救出に入らないイベントなので、新規人物絵ではなく、既存の控え立ち絵を残して減彩・距離演出で表す。

### M2: 連携技の扱い

`doubleTeam` は実際の技名を伴うイベントであり、汎用の「連携中」1枚に置き換えない。現行 `STYLE_TAG_MOVES` には89定義・重複を除いて82種の連携技があるため、タッグ用の三人構図イラストは別カタログで管理する。

ただし v0.2 の再配置案では `Technique` を廃止するため、連携技カタログはスタイル再配置の実装後に確定する。タッグ用イラストを着手する時は、再配置後の候補からフィニッシャー級を先にP0化する。今の89定義をそのまま大量制作しない。

### 共通演出の制作順

1. `cover-pin`、`kickout`、`downed`、`tap-out-overlay` を、最初の技イラスト表示プロトタイプに同梱する。
2. タッグ観戦画面へ技イラストを出す段階で、`tag-touch`、`hot-tag-entry`、`cutin-breakup` を追加する。
3. タッグの再配置後データから連携技カタログを確定し、`doubleTeam` の技絵をフィニッシャー級から作る。

## 1技ごとの管理項目

各P0技は、少なくとも以下を記録する。

| 項目 | 内容 |
|---|---|
| 正規技名 | `src/data.js` と完全一致する名前 |
| スタイル／威力／カテゴリ | 技の重要度と使われ方 |
| assetId | 永続的な英字ファイル名 |
| 別名・共用先 | 共用が許可された技名だけ |
| 参照絵 | ユーザーが作成するポーズ・カメラ資料 |
| raw / master | 1024px PNGの制作元 |
| game asset | 512px WebP（暫定合成版、後に attacker / defender / overlay） |
| 検品 | 技の識別、人体の不透明性、スタイル統一、分離しやすさ |

## 完了条件

P0一覧の全技に、専用絵または承認済みの共用絵が割り当てられていること。技イラストを試合画面へ導入する最初の版では、M0の4部品も揃っていること。小技の欠落は許容するが、P0またはM0の未割当は許容しない。
