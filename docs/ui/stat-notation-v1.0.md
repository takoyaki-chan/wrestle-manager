## §1 数値の階調(「段で塗る」・7帯)

**骨格: 0=グレー → 60=白 → 上ほど濃く → 100でその系統の一番濃い色 → 100超は輝く。**
連続グラデーションではなく**帯で量子化**する(同じ帯=同じ色。列が揃い、くすんだ中間色を踏まない)。

| 帯 | 色 |
|---|---|
| 0–44 | 暗灰 `#63615b` |
| 45–59 | 明灰 `#a8a59d` |
| 60–69 | 白 `#f2f0e8` |
| 70–79 | 系統色50%(白と50%混色) |
| 80–89 | 系統色80%(白と80%混色) |
| 90–99 | **純色 + 太字** |
| 100超 | **純色を22%明るく + その色のglow(text-shadow 0 0 6px `色cc` / 0 0 14px `色55`) + 太字** |

- **系統の純色**(実装の実値。SP=緑/TE=青を取り違えないこと):
  PW `#e74c3c` / SP `#2ecc71` / TE `#3498db` / ST `#f39c12` / MN `#9b59b6` / **OVR=金 `#d4a843`**(`--gold`)
- 混色は白点 `#f2f0e8` との sRGB 線形補間
- **輝き(glow)は100超だけ**。旧DBの「OVR85+で常時glow」(`_scale6Style`)は適用画面では**廃止**する
  (輝きの稀少性が「規格外」の格を作る。01-foundations 原則11と同じ思想)
- 太字は90以上(純色帯と同時に切り替える)
- 身長・年齢など能力以外の数値は階調対象外

## §2 ステータスバー(枠越え・圧縮はみ出し)

**枠(トラック)は0–100で終わる。100超の黒い空きトラックを描かない**(「150まで育つ」錯覚の禁止)。

- ゾーン全幅=118表示単位。枠=100/118≒**84.746%**
- 表示式: `disp(v) = v (v≤100)` / `100 + (v−100)×18/50 (100<v≤150, 150で頭打ち)`
  → 110で枠+3%、130で+11%、150で+18%。**はみ出しは実寸比例ではない**(枠を越えたこと自体が記号。量は数字が語る)
- **バー自体は100超でも光らせない**(2026-08-13裁定)。輝きは§1の数値側のみ
- 実際の育成天井は `trainCap = pot × 0.55〜0.80`(ステ・プレイごと乱数)で**150台まで実在**する
  (`Engine.rival.generateTrainCap` management.js:8989)。バーの見せ方はこの事実と両立する
- **消耗で失われた天井(▼n)**: 現在値の先に同色・不透明度28%のゴーストで「失った幅」を描く+`▼n`(赤)表記
- **季節成長(+n)**: 数値の隣に緑 `+n` を維持
- バーの塗り(fill)は系統の純色(軸識別を担うため階調にしない)

## §3 レーダーチャート(五角形)

- 5軸 PW/SP/TE/ST/MN、値は0–100クランプ(従来どおり)
- **軸ラベルを系統色にする**(どの軸がどの能力か一目で分かる)
- 塗りは金(`--gold`)25%+金の輪郭(従来どおり)

## §4 適用画面

| 画面 | 適用 |
|---|---|
| **選手ファイル**(タイトル画面・新設) | §1(一覧+詳細の数値)/§2(詳細バー。ただし基準値のみで100超は出ない)/§3 |
| **DB全選手一覧**(データベースタブ) | §1(OVR+ステ5列。`_statCell`の3段塗りと`_ovrColor`適用を置き換え) |
| **選手詳細ポップアップ**(能力タブ) | §1(数値)/§2(0–150バーを置き換え)/§3(レーダー軸色) |

**非適用(今回触らない)**: 人気(`_popColor`)・体調(`_condColor`)・MQ(`_mqColor`)・絆(`_bondColor`)・開発率バー・
ランキング画面のOVR階調(v0.9独自。戦力ヒエラルキー演出として当面残す)。
他画面(ロスター表・興行準備ピッカー等)への展開は上記2画面の実機確認後に判断。

## §5 実装方針

- 階調(`statTierStyle(kind, v)` 相当)と`barDisp(v)`+バー部品CSSを **ui-common に1箇所で新設**し、
  適用3画面で共用する。**画面ごとに再実装しない**(色ドリフトの再発防止)
- `_scale6` 本体と他用途(人気・体調等)には触らない
