## 目的

社長が週ごとに能動的な経営判断を下す場所。机の上に並ぶ決裁書類から選んで朱印を押す体験を通じて、「社長としての判断」を物理メタファーで表現する。

ここで扱う判断:
- 選手への直接的なケア（信頼度介入）
- 育成施策（成長投資）
- 広報施策（団体人気）

プレイヤーの体験として、「数値操作のUI」ではなく「社長室に入って書類を片付ける時間」にすることが最大の目的。既存のケアモーダルが抱えていた「世界観との断絶」「ダサい見た目」を完全に置き換える。

## 遷移

- **入ってくる経路**: トップバーの「🏛️ 社長室」タブをクリック
- **出ていく経路**: 他のトップバータブをクリックすることで遷移
- **戻る挙動**: 専用の戻るボタンなし（トップバーのタブ切替で他画面へ）
- **遷移アニメーション**: 0.3秒フェード

## コンポーネント

### 1. 社長室HUDバー

画面上部、ナビバーの下に配置する細長い帯。ナビバーとは独立した装飾で、社長室画面でのみ表示される。

**内容**:
- 左: 現在の週と季節（例「第12週 春」）
- 左中: 資金表示（既存HUDと同じ）
- 右: 決裁枠の印鑑6個（横並び）

**見た目**:
- 背景: `var(--office-panel-dark)` の半透明 + 下エッジにゴールド1px
- 高さ: 60px
- z-index: 100（他のすべての上）
- `position: fixed` ではなく `position: sticky` で画面スクロールに追従

### 2. 壁+窓+景色エリア

画面上部の装飾背景。ナビバー+HUDバーの下から始まり、机エリアの手前まで。

**内容**:
- 背景画像: `image/shachoshitsu/wall-window-{season}.webp` (1920×400)
- 季節判定: 現在の週から自動計算（春:1-12 / 夏:13-24 / 秋:25-36 / 冬:37-48）
- object-fit: cover（画面幅に合わせて伸縮）
- 左右オーバーフロー許容（画面より広い場合は中央クロップ）

**注意**:
- このエリアには**書類や操作要素を置かない**。純粋な装飾
- HUDバーが上に重なる前提でデザインされている

### 3. 机の天板エリア

壁の下から画面下端まで。書類が並ぶメインの作業領域。

**内容**:
- 背景画像: `image/shachoshitsu/desk.webp` (1920×1020)
- object-fit: cover
- 中央に書類グリッド（4×2）を配置

**重要**:
- 画像の中央1290×660px範囲に装飾要素がない設計なので、書類はこの範囲に収める
- 机と壁の境界は、机画像の上側60pxを壁画像に重ねて馴染ませる

### 4. 書類グリッド（4×2）

机の上に書類が並ぶエリア。書類は **P3 Dashboard のパネル** の特殊形として扱う。

**構造**:
- CSS Grid 4列 × 2行
- ギャップ: 20px
- 書類サイズ: 240 × 320 px
- グリッド全体: 1020 × 660 px
- 机エリア内中央配置

**書類の並び順（固定）**:
| 位置 | 書類 | カテゴリ |
|---|---|---|
| (1,1) | bonus | care |
| (1,2) | encourage | care |
| (1,3) | refresh_leave | care |
| (1,4) | party | care |
| (2,1) | trainer | growth |
| (2,2) | camp | growth |
| (2,3) | media | pr |
| (2,4) | — | (空きスロット) |

発動条件を満たさない書類は**空きスロット化**する（グリッドの位置は固定のまま、その場所に何も表示しない）。

### 5. 書類パネル（Cream Panel 派生）

各書類は Cream Panel の派生として扱う。紙の質感と朱印の赤を活用する。書類本体は「一目で何の書類か分かる最小限の情報」だけを表示し、詳細はホバー時のツールチップに逃がす（5.1参照）。

**構成要素**:
1. **背景画像**: `image/shachoshitsu/document-blank.webp` (240×320)
2. **カテゴリタグ**: 左上に `care` / `growth` / `pr` / `hr` の小バッジ（9px程度）
3. **絵文字アイコン**: 書類中央上部に32〜36pxで表示。`DECISION_DOCS[id].icon` を参照
4. **見出しテキスト**: アイコン直下、`var(--office-text-on-cream-main)` で書類タイトル
5. **本文テキスト**: 見出し下、`var(--office-text-on-cream-sub)` で1-2行の要約
6. **コストバッジ**: 右下に「50万 / 決裁⚡1」

**状態**:
| 状態 | 見た目 |
|---|---|
| 通常 | 書類画像そのまま、クリック可能 |
| ホバー | 少し浮き上がる (`transform: translateY(-4px)`) + 影強化 + 詳細ツールチップ表示（5.1） |
| 資金不足 | `filter: brightness(0.7)` + クリック無効 + 「資金不足」ツールチップ（詳細ツールチップは出さない） |
| 決裁枠不足 | 上と同じ + ツールチップ文言変更 |
| 決裁済み | `document-stamped.webp` に差し替え + 彩度低下 + クリック無効 |

### 5.1 ホバー詳細ツールチップ

書類をホバーすると、書類本体の右側に詳細ツールチップがフェードインで表示される。これにより、書類本体に詰め込むと窮屈になる情報（具体的な効果値、使いどころ）を逃がしつつ、必要な人には即座に届ける。

**表示項目**（`DECISION_DOCS[id]` から取得）:
- **詳細説明**: `detailText` — 書類本文より踏み込んだ説明
- **効果**: `effectSummary` — 数値・期間・範囲を含む具体的な効果
- **使いどころ**: `recommendation` — いつ誰に使うべきかの指針

**ビジュアル**:
- サイズ: 約280px幅、高さは内容に応じて可変
- 背景: 暗色半透明 `rgba(24, 22, 20, 0.95)`
- ボーダー: 金色 `rgba(212, 168, 67, 0.5)` の1px
- 内部padding: 16px
- フォント: Noto Sans JP、本文12px、ラベル10px（ラベルは金色）
- 見出しラベルは「詳細」「効果」「使いどころ」

**挙動**:
- ホバー開始から **0.3秒の遅延** を置いて表示（書類間を素早く行き来した際のチラつき防止）
- 表示アニメーション: opacity 0 → 1 を 0.15s で
- 位置: 書類の右側（`left: calc(100% + 12px); top: 0`）
- **画面端対策**: グリッド右端2列（`:nth-child(4n)`, `:nth-child(4n-1)`）は左側に反転表示

**非表示条件**:
- 資金不足・決裁枠不足・決裁済みのいずれかの場合は詳細ツールチップを表示しない（状態通知の方を優先）

## レイアウト詳細

### CSS変数（新規追加）

既存のOfficeトークンをベースに、社長室専用の変数を追加する:

```css
:root {
  /* 既存のOfficeトークンをそのまま使う */
  /* --office-bg, --office-panel-cream, --office-border-cream, etc. */

  /* 社長室専用の追加 */
  --shachoshitsu-hud-bg: rgba(24, 22, 20, 0.92);  /* HUD半透明 */
  --shachoshitsu-hud-border: rgba(212, 168, 67, 0.4);
  --shachoshitsu-vermillion: #c00000;  /* 朱印の赤 */
  --shachoshitsu-vermillion-dim: #a02020;
  --shachoshitsu-hanko-glow: rgba(255, 200, 100, 0.4);
}
```

ハードコード16進色は禁止。書類の色・朱印の色は必ず変数経由で使う。

### レスポンシブ

- 基準解像度は1920×1080
- 実プレイでは様々な解像度なので、CSSで伸縮する
- 最小幅: 1280px（それ以下は横スクロール）
- 書類グリッドは `object-fit: contain` ではなく、比率維持した縮小表示

### フォント

- 書類見出し: Noto Sans JP bold
- 書類本文: Noto Sans JP regular
- コストバッジの数値: Oswald（既存のOffice系数値と同じ）

**注意**: Mincho系は使用禁止（CLAUDE.md のルール）。書類は「重厚な和書類」ではなく「現代のビジネス書類」のイメージで。

## インタラクション

### 書類クリック → 決裁実行フロー

1. プレイヤーが書類をクリック
2. **対象選手選択モーダル**（個人書類）または**確認モーダル**（団体書類）を表示
3. 対象を選択、確認ボタン
4. モーダル閉じる
5. 書類の上に朱印エフェクト（`stamp-effect.webp`）がフェードインしてバン!
6. HUDの印鑑が1本倒れる（アニメーション 0.5秒）
7. 書類が決裁済み状態（`document-stamped.webp`）に切り替わる
8. 結果トーストが画面下から登場（2秒で自動消滅）
9. サウンド再生（朱印音 + 決裁完了音）

### 決裁済み書類

- 決裁した書類はその週はそのまま机に残る（朱印が押された状態）
- 次の週進行時にリセットされ、次の週に発動条件を満たせば再び未決裁状態で表示

## 状態バリエーション

| 状態 | 表示 |
|---|---|
| 通常 | 発動条件を満たす書類が机に並ぶ |
| 空 | 発動条件を満たす書類が0の場合、机の中央に「今週決裁する案件はありません」と表示 |
| 読込中 | ゲーム自体がローカルで動作するので該当なし（初回画像読込時のみフラッシュ対策） |
| エラー | 該当なし |

## アクセシビリティ

- 書類のクリック領域は十分広く取る（240×320 px）
- キーボードナビゲーション: Tab で書類間を移動、Enter で決裁実行
- スクリーンリーダー対応: 各書類に `aria-label="ボーナス支給願、コスト50万、決裁枠1"` を設定
- 色のみに頼らない: 決裁済み状態は彩度低下だけでなく朱印画像も併用

---

## 禁止事項

- ❌ ピンクやマゼンタ色の使用（旧ケア色）
- ❌ ハート絵文字（💝）の使用
- ❌ 「ケア」という文言の使用（「決裁」「社長室」に統一）
- ❌ 小さすぎるモーダルでの表示（社長室は独立画面）
- ❌ Stage / Ceremony カテゴリの要素の流用（Office一貫）
- ❌ `var(--*)` を経由しない16進色の直書き
- ❌ Mincho系フォント

## 実装メモ

### 既存コードとの関係

- `showCareActionModal` (`src/ui-common.js`): Phase 5で削除
- `Engine.careActions` (`src/management.js`): Phase 5で `Engine.shachoshitsu` にリネーム
- `CARE_ACTIONS` (`src/data.js`): Phase 5で `DECISION_DOCS` にリネーム
- 今週画面の「💝 ケア」ボタン (`src/ui-render.js`): Phase 5で削除

### P3 Dashboard との相違

通常のP3 Dashboardは「情報パネルを並べて状況把握」だが、社長室の書類パネルは「クリックして行動」。パネル性質が違うので、既存のP3 Dashboard画面（道場・収支）とは見た目を共有しない。

社長室は**P3 Dashboardの特殊応用**として位置づけ、他の画面への流用は想定しない。

### Officeカテゴリの拡張

既存のOfficeは「事務所の机の上で書類を眺める」メタファーだったが、社長室はそれを**物理的に再現**する。テクスチャ背景画像を使うのは既存のOffice画面とは異なるアプローチだが、メタファーとしては完全に一致している。

**Office カテゴリ内の位置づけ**:
- 既存のOffice画面 = 「メタファーを抽象化したUI」
- 社長室 = 「メタファーをそのまま画面にしたUI」

両者は共存する。
