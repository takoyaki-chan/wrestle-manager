# レッスルマネージャー UI設計仕様 — 階層3：画面仕様書テンプレート

> このファイルは個別画面仕様書の**フォーマット定義**である。
> 個別画面の仕様書は本ファイルではなく `docs/ui/03-screens/<画面名>.md` として、
> 当該画面を実際に作り直すタイミングで1枚ずつ追加していく。

---

## 0. このテンプレートの使い方

### いつ書くか

ある画面を新規作成 or リファクタする**直前**に、このテンプレートに沿って `docs/ui/03-screens/<画面名>.md` を1枚作る。書いたら Claude Code にその仕様書と階層1・2を読ませて実装させる。

### なぜ事前に全画面分書かないか

- 24画面分を一度に書くと書く量が膨大で実装が止まる
- 書いてる間に階層1・2の解釈が育つので、後から書いた方が精度が上がる
- 実際に手を入れない画面の仕様書を書いても無駄

### 階層3が果たす役割

- 個別画面の設計を Claude Code に伝える具体的な指示書
- 階層1・2の抽象ルールを、その画面で「具体的にどう適用するか」を明示する
- 後から見直したときの設計記録

## 1. テンプレート

新しい画面仕様書を書くときは、以下をコピーして埋める。

````markdown
# 画面：<画面名>

**ファイル**：`docs/ui/03-screens/<screen-id>.md`
**最終更新**：YYYY-MM-DD
**実装状況**：未着手 / 実装中 / 完了

---

## 基本属性

| 項目 | 値 |
|---|---|
| 所属カテゴリ | Office / Stage / Ceremony |
| パネル様式 | Cream Panel / Dark Panel / 両方 / なし |
| レイアウトパターン | P1 Catalog / P2 Detail / P3 Dashboard / P4 Timeline / P5 Workflow / P6 Canvas / P7 Theatrical |
| 所属シーケンス | なし / S1〜S7 のいずれか |
| 使用フォント | Noto Sans JP（本文）+ Bebas Neue（数値）+ Oswald（ラベル） |
| 実装ファイル | src/index.html の該当 screen-* ID、関連JS関数 |

---

## 目的

この画面で何をする場所か、役割と情報提供の主眼を1〜3文で書く。

例：所属選手を一覧で確認し、個別選手の詳細へ導線する。コンディション・ロール・ランキングを一目で把握できること。

---

## 遷移

- **入ってくる経路**：どの画面から、どのトリガーで来るか
- **出ていく経路**：この画面からどの画面へ、何をクリックすると遷移するか
- **戻る挙動**：戻るボタンの有無と動作

---

## 骨格ワイヤーフレーム

ASCII で画面構造を描く。各領域の高さとカテゴリ、主要コンポーネントを明記する。

```
┌─ Top Bar (Office dark, 48px) ─────────────────┐
├─ Nav Bar (Office dark, 36px) ─────────────────┤
├─ Filter Bar (Cream Panel, 44px) ──────────────┤
│  [所属▼] [ロール▼] [検索...]    並替:[OVR▼]  │
├─ Grid Area (Office暖茶 bg) ───────────────────┤
│   ┌─Card──┐ ┌─Card──┐ ┌─Card──┐ ┌─Card──┐   │
│   │       │ │       │ │       │ │       │   │
│   └───────┘ └───────┘ └───────┘ └───────┘   │
└────────────────────────────────────────────────┘
```

複雑な画面の場合は別途 `docs/ui/mockups/<画面名>.html` を添付してリンクする。

---

## 構成要素（使用コンポーネント）

使用する既存コンポーネントを列挙する。各コンポーネントの内包要素も明記する。

- ComponentName1（例：FilterBar）
  - 内包：所属フィルタ、ロールフィルタ、検索ボックス、並べ替えセレクタ
- ComponentName2（例：WrestlerCard）
  - 内包：顔写真、名前、OVR、ロールバッジ、コンディションバー

新規コンポーネントが必要な場合は明記する。

---

## 情報階層（視線誘導の優先順位）

ユーザーの視線をどの順番で誘導したいか。1から番号を振って書く。

1. 最優先で見せたい要素
2. 次に目立たせる要素
3. 補助情報
4. ...

---

## 特有ルール

この画面だけの例外ルール、インタラクション挙動、アニメーションを書く。階層1・2に書かれている共通ルールは繰り返さない。

例：
- 引退選手は opacity 0.4 でグレーアウト
- 新規加入選手は右上に ★ バッジを8週間表示
- ソート変更時は全カードがフェードイン 300ms
- カードホバー時：translateY(-2px) + shadow

---

## 状態バリエーション

| 状態 | 表示 |
|---|---|
| 通常 | 上記レイアウト |
| 空 | 中央に「<該当データなし>」+ 関連画面への導線 |
| 読込中 | スケルトン表示 × N |
| エラー | 再読込ボタン付きエラーメッセージ |

---

## 関連トークン

主に使用する CSS 変数を列挙する。階層1の Foundations に存在しないトークンを使う場合は、Foundations 側に追加してから記載する。

- `--office-bg`
- `--office-panel-cream`
- `--office-border-cream`
- `--space-xl`
- `--radius-lg`
- `--t-headline`
- `--t-ovr`

---

## 階層1・2への参照

この画面の設計が階層1・2のどの原則を適用しているか、簡潔に書く。

- 階層1：Office カテゴリ、Cream Panel（紙の書類メタファー）
- 階層2：P1 Catalog の「フィルタバー固定 + コンテンツエリアはカードグリッド」を採用

---

## 未決事項

実装中に決まっていないこと、後で詰めるべきことを箇条書きで残す。
````

## 2. 完成例：ロスター一覧

````markdown
# 画面：ロスター一覧

**ファイル**：`docs/ui/03-screens/roster.md`
**最終更新**：2026-04-09（テンプレート例）
**実装状況**：未着手

---

## 基本属性

| 項目 | 値 |
|---|---|
| 所属カテゴリ | Office |
| パネル様式 | Cream Panel |
| レイアウトパターン | P1 Catalog |
| 所属シーケンス | なし |
| 使用フォント | Noto Sans JP（本文）+ Bebas Neue（OVR数値）+ Oswald（ラベル） |

## 目的

所属選手を一覧で確認し、個別選手の詳細へ導線する。コンディション・ロール・ランキングを一目で把握できること。

---

## 遷移

- **出ていく経路**：選手カードクリック → 選手詳細画面（P2 Detail）
- **戻る挙動**：ナビバー経由で他画面へ。戻るボタンは持たない

## 構成要素（使用コンポーネント）

- FilterBar（P1共通部品）
  - 内包：所属フィルタ、ロールフィルタ、検索ボックス、並べ替えセレクタ
- WrestlerCard（Cream Panel, 紙の質感, 角丸 R-LG）
  - 内包：顔写真（72×72 円形）、名前（T-HEADLINE）、OVR数値（T-OVR Bebas Neue）、ロール/スタイルバッジ、コンディションバー（幅100% × 4px）

---

## 情報階層（視線誘導の優先順位）

1. 顔写真（最優先、最大）
2. 名前
3. OVR数値（右上配置、ゴールド）
4. ロール/スタイルバッジ
5. コンディションバー（最下部）

---

## 特有ルール

- 引退選手は opacity 0.4 でグレーアウト
- 新規加入選手は右上に ★ バッジを8週間表示
- ソート変更時は全カードがフェードイン 300ms
- カードホバー時：translateY(-2px) + shadow
- 検索ヒット中は該当しないカードを opacity 0.2 に
````

## 3. 画面仕様書を書くワークフロー

ある画面を差し替えたくなったとき、Keisuke と Claude Code は以下の順で進める:

1. Keisuke が「次は X 画面を差し替えたい」と Claude Code に伝える
2. Claude Code が `docs/ui/03-screens/<X>.md` の有無をチェック
3. **存在しない場合**：このテンプレートを使って X 画面の仕様書を1枚書く（Keisuke にレビューしてもらう）
4. **存在する場合 / 書き終えた場合**：階層1・階層2・該当画面仕様書の3つを参照しつつ、X画面を実装する
5. 実装が終わったら仕様書の「実装状況」を「完了」に更新
