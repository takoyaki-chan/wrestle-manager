Mockup — In-Game Database Backport / v0.1 / 2026-08-13

本編データベースへの逆輸入 — 階調カラー・枠越えバー・レーダー軸色

選手ファイル(v0.7)で確定した表記法則を、ゲーム本編のデータベース(全選手一覧+選手詳細ポップアップの能力タブ)へ逆輸入する。本編では100超の実数値が本当に出る(天井=pot×0.55〜0.80で150台まで)ので、「100超だけが輝く」「枠を飛び越える」が実戦で生きる。

一覧の団体名・年齢・人気・成長後の数値は色見本用のダミー(進行後の想定値)。tier色はRIVAL_ORGSの実値。ソート・フィルタ・開発率・体調などの機能と行構成は変更しない(色とバーの差し替えのみ)。

§1 — DB全選手一覧: 現行の塗り vs 逆輸入(案X段)
現行 — ステは「75以上=系統色/60以上=白/未満=減光」の3段、OVRは_scale6の6段(85+は常時輝き)
逆輸入 — 全数値列を案Xの7帯へ。輝きは「100超」だけに限定(85+の常時glowは廃止)
現→変:
  • ステ列: 3段(75+系統色/60+白/未満減光) → 案Xの7帯。深町のSP107・橘のTE104のような100超が「輝く」形で自然に主役になる
  • OVR列: _scale6の6段 → 金の7帯(選手ファイルと同法則)。85+の常時glowは廃止し、輝き=100超のみ。輝きの稀少性が「規格外」の格を作る(01-foundations 原則11と同じ思想)
  • 人気列: 現行 _popColor のまま変更なし(揃えるかは§4判断点)
  • 団体バッジ・称号バッジ・年齢・ソート・フィルタ・行クリック: 変更なし
§2 — 選手詳細ポップアップ(能力タブ): 現行 vs 逆輸入

見本は成長後の想定値(ダミー): PW112(100超・枠越え) / SP84 / TE80(今季+2) / ST92(消耗で天井▼6) / MN90。レーダーは両案とも0-100クランプ(ゲーム内と同じ)。

現行 — 0-150目盛+縦線(100)、数値は3段塗り、レーダー軸は無彩

課題: 空きトラックが150まで続き「150まで育つ」と錯覚させる。消耗▼の薄バーも150基準で小さく見える

逆輸入 — 枠=100終端+圧縮はみ出し、数値は案X階調、レーダー軸は系統色

開発率・体調・コーチ・因縁・怪我の各行、ヘッダ(名前24px/OVR36px)は変更なし。変わるのは数値の塗り・バー・レーダー軸色だけ
本編固有要素の織り込み:
  • 100超(PW112): バーが枠を飛び越えて圧縮はみ出し(バー自体は光らせない)。輝きは数値側だけが担う。選手ファイルでは見本でしかなかったものが、本編では実際に出る
  • 消耗で失われた天井(ST▼6): 現在値の先に同色の半透明ゴーストで「失った幅」を描く+▼6表記(現行の薄バー表現を新ジオメトリへ移植)
  • 季節成長(TE+2): 数値の隣の緑 +2 を維持
  • レーダー軸ラベル: PW/SP/TE/ST/MN を系統色に(どの軸がどの能力か一目で分かる。選手ファイルからの逆輸入)
§3 — 実装方針(指示書に書く内容の骨子)
  • 共通ヘルパー化: 階調(`statTierStyle(kind, v)`)と枠越えバー(`barDisp(v)`+部品CSS)を ui-common に1箇所で新設し、DB一覧・選手詳細・選手ファイル(新設)の3画面で共用する。画面ごとに再実装しない(ドリフト防止)
  • 置き換え対象: `_statCell`(ui-render.js:9155)の3段塗り / `_ovrColor`+`_scale6Style`のOVR適用箇所のうちDB一覧・選手詳細 / 選手詳細のステバー(0-150)とレーダー軸
  • 触らないもの: `_scale6`本体と他の用途(_mqColor/_condColor/_popColor/_bondColor等)・ランキング画面のOVR階調(v0.9)・開発率バー。これらへの波及は§4で判断してから
  • 選手ファイル本体の実装と同一タスクに載せるか、逆輸入を別タスクに切るかは指示書作成時に分割(逆輸入は既存画面の差し替えなので回帰確認が要る)
§4 — 判断が要る点(v0.1)
  1. OVR 85+の常時glow廃止 — 現行DBは85以上が常に輝く。逆輸入後は輝き=100超だけに限定する提案(稀少性が格を作る)。85-99の強豪は「純色+太字」で十分立つ。この整理で良いか
  2. 人気列・ほかのスケール — 人気(_popColor)・体調(_condColor)・MQ(_mqColor)・絆(_bondColor)は今回触らない提案。数値言語を全部揃えるなら別途一括で(段の閾値がスケールごとに違うため設計が要る)
  3. ランキング画面との整合 — ランキングv0.9のOVR階調(白→金の独自トークン)はそのまま残すか、案Xの金帯へ寄せるか。ランキングは「戦力ヒエラルキーの演出」として独自設計した経緯があるため、当面は残す提案(乖離が気になったら後で寄せる)
  4. 消耗ゴーストの濃さ — 半透明28%。もっと薄く/ハッチング(斜線)にも振れる
  5. 適用画面の範囲 — 今回はDB一覧+選手詳細のみ。ロスター表・興行準備ピッカー・ランキング行など「数値が並ぶ他画面」への展開は、この2画面の実機確認後に判断
