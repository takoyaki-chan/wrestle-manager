選手ファイル — タイトル画面から開く全選手名鑑

タイトル画面に「選手ファイル」を新設し、全127名の能力値とプロフィールをゲーム開始前に閲覧できるようにする。潜在能力値はどの形でも載せない(基準値は機密・プレイごとに変化する旨を明記)。

ソートはゲーム内データベースと同作法(列見出しクリック・▲▼・再クリックで昇降)。行クリックで詳細が開く。このモックはソート・フィルタ・詳細がすべて実際に動く。

収録は見本18名(全6スタイル網羅・実データ転記・potはソースにも含めていない)。準拠と逸脱はソース冒頭コメント参照。

  • ステ値の色: 75以上=系統色 / 60以上=通常 / 60未満=減光(ゲーム内 `_statCell` と同じ)
  • ゲーム内DBとの差分: 団体・年齢・人気の列を外した(ゲーム開始前に存在しない値)。代わりにプロフィール要素として身長列を追加
  • 顔は 1:1 face 素材の row 40px(§2-C)。行クリックで詳細(§3)が開く

§3 — 選手詳細(モーダル)

一覧の行クリックで開く。ゲーム内選手詳細ポップアップの「能力」タブに寄せた構成: 上半身 2:3 + OVR + レーダーチャート + ステバー + 特性 + 紹介文。開発率(潜在から派生する表示)もここでは置かない。

モーダルの器は開いた一覧のテーマに追従する(比較用)。閉じる: ✕ / 背景クリック / ESC(情報を見るだけのモーダル — §5-C)。

ゲーム内ポップアップとの差分:
  • 主役画像はタイプ物差しの 2:3 梯子 XL 172×258(ゲーム内実装の 200×300 は梯子外のため載せ替え)
  • 選手名は title(18px)、OVR は display(28px)に載せ替え(実装は 24px/36px — 物差し外)
  • 開発率バー・体調・人気・給与・戦績・怪我・コーチ・因縁は出さない(ランタイム値 or 潜在派生)
  • ステバーの目盛はゲーム内と同じ 0–150(縦線=100)。初期値の「伸びる前」感が出る
§4 — 判断が要る点(実装前に決める)
  1. 入口の形とラベル — 4つ目の `.title-btn`「FIGHTER FILE」(主案) か、Credits 横の小リンクか。英字ラベルの語も要決定(FIGHTER FILE / ROSTER FILE / 日本語「選手名鑑」)
  2. 器: 案A vs 案B — 推奨は案A(ダーク)。タイトルの空気と地続き・「ゲーム内DBと同等」の要件に最短。案Bはゲーム内ロスター(Cream)と揃う利点はあるが、ゲーム外画面に書類メタファーを持ち込む根拠が弱い
  3. 詳細モーダルの器 — モックでは一覧テーマに追従。実装ではゲーム内選手詳細と共通化はできない(タイトル時点では G が無く `showFighterPopup` が動かない)ため、静的データ専用の軽量版を新設する前提。見た目をどちらに寄せるか
  4. ステバーの目盛 — ゲーム内準拠の 0–150(モック採用・成長余地が体感できる) vs 初期値が読みやすい 0–100
  5. 列構成 — 団体/年齢/人気を除外し身長を追加した。ロール(Babyface/Heel)列は入れていない(詳細側で表示)。過不足はないか
  6. 注記の文言・トーン — 「機密指定」スタンプ+資料調で書いた。です・ます調に倒すか。文言は「①記載しない ②基準値は機密 ③プレイごとに変化」の3点を必須とした
  7. デフォルトソート — OVR降順(ゲーム内DB準拠・モック採用) vs 名鑑らしく ID順/五十音順
  8. 実装スケール — 全127名は素の table + 画像 lazy loading で問題ない想定(ゲーム内DBと同規模)。personality / archetype は内部語彙のため非表示のまま
