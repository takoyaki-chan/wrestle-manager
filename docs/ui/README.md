# レッスルマネージャー UI設計仕様

新しい画面を作るとき、または既存画面に手を入れるときは、必ず以下を順に読むこと。

## 読む順序

1. **`01-foundations.md`** — 3カテゴリ（Office / Stage / Ceremony）、トークン体系、設計原則
2. **`02-layouts.md`** — レイアウトパターン（P1〜P7）、シーケンス（S1〜S7）、グローバルChrome、イベント
3. **`03-screen-template.md`** — 個別画面仕様書のテンプレートと書き方
4. **`03-screens/<該当画面>.md`** — 個別画面の詳細仕様（存在すれば）
5. **`04-ceremony.md`** — Ceremony の完全仕様（未着手）

## ディレクトリ構成

```
docs/ui/
  README.md                 ← このファイル
  01-foundations.md         ← 階層1：基礎
  02-layouts.md             ← 階層2：レイアウトパターン + シーケンス + イベント
  03-screen-template.md     ← 階層3：画面仕様書テンプレート
  03-screens/               ← 個別画面仕様書（実際の差し替え時に1枚ずつ追加）
  04-ceremony.md            ← 階層4：Ceremony 完全仕様（後で作成）
  mockups/                  ← 必要に応じてHTMLモックアップを添付
```

## マイグレーション方針

**「ルールを先に確立して、後で1画面ずつ差し替える」**

24画面を一度に作り変えることはしない。新しい画面を作るとき、または既存画面に手を入れるタイミングで、その1画面だけを階層1〜3のルールに沿って差し替えていく。階層3の `03-screens/` ディレクトリは最初は空で、差し替えが進むたびに仕様書が増えていく。

## 既存デザインシステムとの関係

`wrestle-manager-design-system.html` v1.0（リポジトリルートにある）は**部品カタログ**として継続利用する。破棄しない。ただし「設計図」としての役割は本ディレクトリのドキュメント群が担う。

## CLAUDE.md との関係

本ディレクトリのルールを Claude Code が確実に参照するため、`CLAUDE.md` に「UI実装ルール」セクションが追加されている。新しいUI作業を始める前に CLAUDE.md → このディレクトリの順で読むこと。
