# レッスルマネージャー UI設計仕様 — 05 Benchmark Kit

> 基準モックと比較観点を定義する。
> 新規画面や改修画面は、必ずどれか1つ以上の基準画面に寄せて判断する。

---

## 5-1 目的

文章ルールだけでは、以下のぶれが起きやすい。

- 情報量は合っているが余白が違う
- 説明文の長さが不自然
- 見出しの強さが既存画面より大きい
- 実データを入れた瞬間にカードが破綻する

これを防ぐため、基準モックを「参考画像」ではなく**比較対象**として運用する。

---

## 5-2 基準として使う4画面

### 1. ロスター / 一覧系

- 役割: 情報密度の基準
- 見るもの: カードサイズ、名前の長さ、数値配置、一覧から詳細への導線
- 新規UIで似るもの: 選手一覧、契約一覧、比較、スカウト候補一覧

### 2. 派閥 / 関係性系

- 役割: 空気感と軽い演出の基準
- 見るもの: 人間関係の見せ方、テキスト量、勢力差の示し方、感情を出しすぎない装飾
- 新規UIで似るもの: 派閥詳細、派閥イベント、相関図、抗争関連

### 3. 興行結果 / 振り返り系

- 役割: ドラマ性の高い画面の基準
- 見るもの: 試合結果の強弱、視線誘導、記事っぽさと管理UIの接続
- 新規UIで似るもの: 興行結果、ニュース、年表、レビュー系

### 4. 事務所 / 管理トップ系

- 役割: 日常導線の基準
- 見るもの: 主導線、補助導線、要約ブロック、操作の迷いにくさ
- 新規UIで似るもの: 社長室、スケジュール、収支、団体運営画面

---

## 5-3 実装前の使い方

新しい画面に着手する前に、以下を1分で決める。

1. この画面の主目的は何か
2. 上の4画面のどれに一番近いか
3. 情報量は基準より多いか少ないか
4. 感情表現は基準より強いか弱いか

この4点が決まらないままモックや実装に入らない。

---

## 5-4 レビュー時の比較観点

### 情報量

- 実データの名前・数値を入れても詰まりすぎていないか
- 主情報と副情報の差が見えるか

### 読み順

- 見出し → 要約 → 本文 → 補足の順で読めるか
- 目立たせたい要素が複数同時に主張していないか

### 温度感

- Office なのに演出が強すぎないか
- Stage なのに説明的すぎて冷えていないか
- Ceremony なのに事務的すぎないか

### 実装との接続

- 既存トークンで出せる表現か
- 既存パネル様式の延長で作れているか
- 新規コンポーネントを作る理由があるか

## 5-5 今回の基準モック

初期運用では、以下を基準セットとして扱う。

- `docs/ui/mockups/benchmark-reference-screens.html`
- `docs/ui/mockups/faction-events.html`
- `docs/ui/mockups/show-result-mockup.html`

このうち `benchmark-reference-screens.html` は横断的な比較用で、他2つは個別テーマの深掘り用。

---

## 5-6 実データ参照の原則

基準モックでは、ダミーの Lorem Ipsum や短すぎる仮名を使わない。

- 選手名は実データに存在する長さを使う
- role、style、trait は実データの語彙に合わせる
- OVRや各能力値は現実の分布に寄せる
- 団体人数や派閥人数は実際のゲーム進行で出る帯に合わせる

参照元は `reference-data.md` とする。

---

## 5-7 依頼テンプレート

Claude Code や Codex にUI実装を頼むときは、最低限以下を含める。

```text
対象画面:
カテゴリ:
近い基準画面:
今回触る範囲:
触らない範囲:
見せるもの:
見せないもの:
参考モック:
```

これがあるだけで、設計ずれはかなり減る。
