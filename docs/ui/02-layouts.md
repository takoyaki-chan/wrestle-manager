# レッスルマネージャー UI設計仕様 — 階層2：レイアウトシステム

> 1画面の骨組み（パターン）と、複数画面をつなぐ流れ（シーケンス）を定義する層。
> 階層1（Foundations）で決めたカテゴリ（Office / Stage / Ceremony）の上に乗る。

---

## 2-0 この層の役割

階層2が決めること:

- **A. Global Chrome** — どの画面にも共通する横断UI（トップバー・ナビバー・モーダル）の規格
- **B. Layout Patterns（P1〜P7）** — 1画面の骨組みパターン
- **C. Sequences（S1〜S7）** — 複数画面をまたいで1つの体験を作る流れ
- **D. Events** — シーケンス未満の小さな画面遷移

階層2が決めないこと:

- 個別画面の中身（→ 階層3）
- Ceremony内部の演出仕様（→ 階層4）
- カードやボタンのデザイン（→ 階層1のFoundationsと既存デザインシステム v1.0）

---

## 2-A Global Chrome

### A-1 表示環境の前提

- **デスクトップ専用**。最小幅は実質 900px、推奨 1200px 以上。
- コンテナは `max-width: 1200px` で中央寄せ、左右パディング 12px。
- モバイル/タブレット対応は仕様外。個別コンポーネントの応急的なメディアクエリは許容するが、画面全体のレイアウトはデスクトップ前提で設計する。

### A-2 トップバー

すべての画面（P7 Theatrical / Ceremony を除く）の最上部に固定的に配置する。

- **役割**：団体名・週・資金・人気などゲーム全体の状態を常時表示する場所
- **高さ**：40〜48px（内容により変動、padding `10px 16px`）
- **構成**：左に団体名（タイトル）、右に各種ステータス値（資金・人気・週・士気など）が横並び
- **タイポグラフィ**:
  - タイトル：Bebas Neue 22px、letter-spacing 3px、ゴールド系グラデーション
  - ステータスラベル：Oswald 12px、letter-spacing 1px、UPPERCASE
  - ステータス値：本文書体（Noto Sans JP）、ゴールド強調可
- **色**：Office 暖茶背景（`--office-bg`）の上に配置
- **非表示にする画面**：P7 Theatrical 全般、Ceremony 全般（全画面テイクオーバー）

### A-3 ナビゲーションバー

トップバーの直下に配置する画面切替UI。

- **役割**：ゲームの主要画面間を行き来する
- **高さ**：実質 32〜36px
- **配置**：横並び・左寄せ・`overflow-x: auto` で横スクロール可
- **タイポグラフィ**：Oswald 12px、letter-spacing 2px、UPPERCASE
- **状態**:
  - 通常：透明背景、薄ボーダー
  - hover：薄ゴールドのボーダー
  - active：ゴールドボーダー＋ゴールド文字＋薄ゴールド背景
- **項目**（実装準拠・10項目）:
  1. 今週
  2. 興行準備
  3. 団体（ロスター）
  4. スカウト
  5. ランキング
  6. データベース
  7. 収支
  8. ログ
  9. セーブ
  10. ヘルプ
- **非表示にする画面**：トップバーと同じ条件（P7 Theatrical、Ceremony）

### A-4 モーダル

画面遷移を伴わない一時的な対話/通知UI。

- **役割**：選手詳細ポップアップ、確認ダイアログ、契約交渉、B1〜B4イベント、スカウトイベント等
- **背景**：暖茶半透明（rgba(0,0,0,0.6) 程度）でバックドロップ
- **本体**：Office Cream Panel または Office Dark Panel を流用
- **配置**：中央寄せ、最大幅 720px 程度（モーダルの種類による）
- **閉じ方**：右上の閉じるボタン or バックドロップクリック or ESC キー
- **重要**：モーダルは「画面の上に重ねる」UIなので、レイアウトパターンとは独立扱い

## 2-B Layout Patterns

### 共通ルール（全パターン共通）

すべてのパターンに適用される規約。各パターンの説明では繰り返さない。

- **縦方向の構造順序**：トップバー → ナビバー → （パターン固有の本体） の順を厳守
- **余白トークン**：`--space-*` を必ず使用、ハードコード禁止
- **スクロール**：縦スクロールのみ。横スクロールはナビバーと一部例外（P4 Timeline 内のタイムライン本体）以外で禁止
- **状態バリエーション**：すべてのパターンで以下の4状態を考慮する
  - 通常
  - 空（データがない）
  - 読込中
  - エラー
- **所属カテゴリ**：原則 Office。例外は明記する。
- **Cream Panel と Dark Panel の同居**：Office 内であれば許可。同一画面内で混在してよい。

---

### P1 Catalog（カタログ型）

**概要**：たくさんの中から1つを選ぶための画面。フィルタと並べ替えで絞り込みつつ、同じ形のオブジェクトが繰り返し並ぶ。

**構造**:
```
[トップバー]
[ナビバー]
[フィルタ/検索バー]    ← 必須
[コンテンツエリア]      ← 並べ方は画面ごとに選択
```

**コンテンツエリアの並べ方（画面ごとに1つ選ぶ）**:
- **カードグリッド**（ロスター・殿堂・スカウトなど）
- **テーブル**（ランキング）

**特有ルール**:
- フィルタバーは画面上部に固定（スクロールしても残るかは画面ごとに判断）
- カードは Cream Panel ベース、テーブルは Dark Panel ベースを基本とする
- カード/行のクリックで P2 Detail へ遷移するのが基本パターン

**所属画面**：ロスター（団体）、殿堂、スカウト、ランキング

---

### P2 Detail（詳細型）

**概要**：1人の選手・1記事・1試合など、**1つの対象に集中する**画面。

**構造**:
```
[トップバー]
[ナビバー]
[ヒーローブロック]      ← 大きな見出し・顔写真など
[セクション群]          ← 縦に並ぶ詳細セクション
```

**特有ルール**:
- ヒーローブロックは画面上部の目立つ位置に配置
- 縦スクロールでセクションが続く
- 戻る導線（左上 or パンくず）を必ず提供
- セクション間は `--space-xl` で区切る

**所属画面**：選手詳細カード、新聞記事、コーチ詳細、対戦比較（暫定・詳細型の派生として扱う）

---

### P3 Dashboard（ダッシュボード型）

**概要**：複数の情報パネルを並列に配置し、**画面を見るだけで状況が把握できる**ようにする。

**構造**:
```
[トップバー]
[ナビバー]
[パネルA]  [パネルB]    ← グリッド配置
[パネルC]  [パネルD]
[パネルE（フル幅）]
```

**特有ルール**:
- パネル同士のサイズは異なってよい（情報の重要度に合わせる）
- 主要情報（最も大きいパネル）は左上に配置
- パネル数は 3〜6 を目安（多すぎると視線が散る）
- パネル間は `--space-xl` で区切る

**所属画面**：道場（本拠地）、収支、団体トップ（必要に応じて）

---

### P4 Timeline（タイムライン型）

**概要**：**時間軸が主役**の画面。時系列データを横方向に並べる、または週次で切り替える。

**構造**:
```
[トップバー]
[ナビバー]
[期間切替タブ群]        ← 週/月/シーズン切替
[タイムライン本体]      ← 横方向の時間軸 or 縦リスト
[詳細エリア]            ← 選択した時点の詳細（任意）
```

**特有ルール**:
- 横スクロール許可（タイムライン本体のみ）
- 「現在」位置を視覚的に強調する
- イベントマーカーをクリックすると詳細エリアに展開
- ログ画面の場合は時系列を縦に並べるバリエーションを使う

**所属画面**：今週（スケジュール）、ログ、関係性履歴（必要に応じて）

---

### P5 Workflow（ワークフロー型）

**概要**：複数のステップを順に進める画面。**1→2→3 と段階的に進む**ことが視覚的に明示される。

**構造**:
```
[トップバー]
[ナビバー]
[ステップインジケータ]  ← 1→2→3 の進捗を表示
[現在ステップの本体]
[戻る/次へ ボタン]
```

**特有ルール**:
- ステップインジケータは画面上部に固定
- 現在のステップだけを大きく表示（他のステップは小さくグレーアウト）
- 戻る/次へボタンは画面下部の左右に配置
- 中断・再開を許可するか、ステップごとに判断
- 進めない場合（必須項目未入力）は次へボタンを無効化

**所属画面**：興行準備（興行設定）、ドラフト交渉

**注記**：興行準備とドラフト交渉は両方 P5 だが、シーケンス（後述）が異なるため、共通ビジュアルキーは別物になる。「同じパターン＝同じ見た目」ではない。

---

### P6 Canvas（キャンバス型）

**概要**：自由に配置されたノードと線で構成される、**インタラクティブな図形操作画面**。

**構造**:
```
[トップバー]
[ナビバー]
[ツールバー]            ← ズーム・リセット等
[キャンバス本体]        ← 自由配置のノードと線
[凡例 or 詳細パネル]    ← 任意
```

**特有ルール**:
- ノードはドラッグ可能、ホバーで関連が浮き上がる
- ズーム/パン操作を許可
- レッスルマネージャーで該当する画面は1つのみ（関係性マップ）
- このパターンは他に流用しない方針

**所属画面**：関係性マップ

---

### P7 Theatrical（劇場型）

**概要**：全画面演出。トップバーとナビバーを**完全に隠す**。中央のコンテンツに集中させる非日常空間。

**構造**:
```
[（トップバー非表示）]
[（ナビバー非表示）]
[全画面背景（純黒 or 漆黒）]
[中央コンテンツ]
[最小限のコントロール]   ← 進行ボタン等
```

**特有ルール**:
- トップバー・ナビバー非表示（必須）
- 背景は純黒（Stage）または漆黒（Ceremony）
- 中央寄せの構成が基本
- アニメーションは通常UIより遅い（ease-in-out、長め）
- ESC や閉じるボタンで通常UIに戻る or シーケンスを進める
- **Stage と Ceremony の使い分け**は階層1の原則に従う:
  - Stage = 試合などの熱狂・緊張感
  - Ceremony = 式典・厳粛さ・特別な瞬間

**所属画面（Stage）**：興行進行（試合中）、試合結果、入場演出
**所属画面（Ceremony）**：年末表彰式、殿堂入り発表、引退セレモニー、その他式典系（詳細は階層4）

## 2-C Sequences

### シーケンスとは何か

複数の独立した画面を順に経由して、**1つの大きな体験**を作る単位。シーケンスは以下を定義する:

- 構成画面と順序
- 開始トリガーと終了条件
- **共通のビジュアルキー**（アクセント色・タイポ強調・効果音・トランジション様式）
- 中断・再開の可否

**重要原則**：シーケンス内では、たとえ別パターン（P5→P7→P2 など）の画面を経由しても、共通のビジュアルキーで貫かれる。シーケンスをまたぐと、そのキーは切り替わる。

---

### S1. 興行シーケンス（Show）

- **発生**：プレイヤーが興行を開催する週（毎週ではない場合あり）
- **構成画面**:
  1. 興行準備（P5 Workflow）：会場選択 → カード組み → 最終確認
  2. 試合進行（P7 Theatrical / Stage）：複数試合を順に消化
  3. 興行結果サマリ（P7 Theatrical / Stage）：MQ・収益・観客・人気変動
  4. 通常画面に復帰
- **共通ビジュアルキー**:
  - ゴールドアクセント
  - 試合中はBGM切替
  - 観客の歓声効果音
- **中断**：準備フェーズは可能、試合フェーズに入ると不可
- **頻度**：最頻出シーケンス。デザインの基準点になる

---

### S2. PPVシーケンス（年間頂上決戦）

- **発生**：Week 48・年1回
- **解放条件**：orgPop ≥ 30（未解放時はTV観戦モード）
- **構成画面**:
  1. エントリー画面（Week 43）：枠数確認・選手選出（P1 Catalog 派生）
  2. マッチメイク発表（P2 Detail 寄り、新聞風）
  3. 試合進行（P7 Theatrical / Stage）：7試合を順に消化
  4. 結果サマリ・ランキング更新（P7 → 通常）
  5. 場合によりS5 オフシーズンへ接続
- **共通ビジュアルキー**:
  - PPV専用ロゴ
  - S1 興行よりさらに重厚な演出（特別感）
  - 観客動員・メディア露出を強調
- **中断**：エントリーまでは可、試合フェーズ以降は不可
- **特徴**：S1 興行の上位互換。S1と同じ型を使いつつ、シーケンスキーで「特別感」を演出する

---

### S3. 対抗戦シーケンス（War）

- **発生**：Week 12 / 24 / 36 で確率発生（warChancePerSeason ≈ 0.55）
- **構成画面**:
  1. 挑戦状受領（モーダル）
  2. エントリー（P1 Catalog 派生・5名選出）
  3. VS対峙画面（P7 Theatrical / Stage）
  4. 5対5の試合進行（P7 Theatrical / Stage）
  5. 勝敗結果（P7 Theatrical / Stage）
  6. Heat / ランキング波及
  7. 結果新聞（P2 Detail）
- **共通ビジュアルキー**:
  - 相手団体カラーとの対比
  - 5対5の対峙構図
  - 因縁・宿敵感を強調
- **中断**：エントリーまで可、試合フェーズ以降は不可
- **注記**：B3イベント（旧名「挑戦状」）とは別物。B3はイベント側で扱う。

---

### S4. ジュニアトーナメントシーケンス

- **発生**：年1回（実装済み）
- **構成画面**:
  1. 出場発表（モーダル / 新聞風）
  2. ブラケット表示（独自UI、P6 寄り）
  3. 準々決勝（P7 Theatrical / Stage、複数試合）
  4. 準決勝（P7 Theatrical / Stage）
  5. 決勝（P7 Theatrical / Stage、特別演出）
  6. 優勝発表（P7 Theatrical / Ceremony 寄り）
- **共通ビジュアルキー**:
  - トーナメントブラケット表示の継続
  - 試合間に体力バーアニメ
  - 決勝でBGM切替・チャンピオンジングル
- **中断**：不可（一度始まると最後まで進む）
- **特徴**：ブラケットUIは他に流用なし。専用設計。

---

### S5. オフシーズンシーケンス

- **発生**：Week 48 後・年1回
- **構成画面**:
  1. 年末新聞（P2 Detail）：シーズン総括
  2. 年末表彰式（P7 Theatrical / Ceremony）：7スライド
     - メディア功労賞 → 新人王 → ベストマッチ → タイトル王者 → MVP → 殿堂入り → 一覧
  3. 殿堂入り発表演出（P7 Theatrical / Ceremony）
  4. 翌シーズン開始（通常画面復帰）
- **共通ビジュアルキー**:
  - Ceremony 厳粛系（明朝・ベルベット・ゴールド/シルバー/ブロンズ）
  - スライド進行・ファンファーレ
  - 紙吹雪・スポットライト
- **中断**：不可
- **詳細設計**：階層4 Ceremony Full Spec で完全仕様化

---

### S6. ドラフトシーケンス

- **発生**：オフシーズン中
- **構成画面**:
  1. 候補発表（新聞風 / P2 Detail）
  2. 交渉ラウンド（P5 Workflow）：複数ラウンドの入札・交渉
  3. 獲得結果（P2 Detail）
- **共通ビジュアルキー**:
  - オークション会場の雰囲気
  - 競争団体のロゴ表示
  - 緊張感のあるBGM
- **中断**：不可
- **詳細設計**：`specs/draft-negotiation-spec-v1.0.md` 参照
- **実装状況**：`feature/draft-negotiation` ブランチで進行中

---

### S7. オープニングシーケンス

- **発生**：ゲーム開始時1回
- **構成画面**：`specs/opening-sequence-spec-v1.0.md` 参照
- **共通ビジュアルキー**：Ceremony 寄りの導入演出
- **中断**：可能（スキップ）

---

### S8. 春のタッグリーグシーケンス（2026-07-17 追加）

- **発生**：週10〜12・年1回（エンジン実装済み: `Engine.springTagLeague`）
- **構成画面**:
  1. 出場発表（週10、新聞・今週バナーのみ。専用画面なし）
  2. チーム編成モーダル（週11、Office / Cream Panel。`docs/ui/03-screens/spring-tag-league.md`）
  3. リーグ戦6試合（P7 Theatrical / Stage）：**リーグ表の逐次更新が体験の主役**
  4. 決勝（P7 Theatrical / Stage、特別演出）
  5. 優勝発表（P7 Theatrical / Ceremony 寄り、JT優勝発表と同型）
- **共通ビジュアルキー**（2026-07-17 B案「エンブレム」で確定 — `docs/ui/mockups/special-events-design-v2.html`）:
  - 特別大会共通言語: 中央エンブレム画像（`image/emblem-*.png`、Keisuke制作・仮画像上書き運用）+ 金の細二重罫 + Bebas/Oswald + カラーキー1色（春=桜/夏=夏空/秋=緋/冬=白金）
  - リーグ表（順位・勝ち点・顔画像ペア）の常時表示と毎試合の加算アニメ — S4のブラケットに対応するS8の顔
  - 勝者=大会色リング / 敗者=モノクロ落ちの顔画像文法（S4改修版と共通）
  - ※S4 ジュニアのブラケットUIも同言語の「縦積みピラミッド型」に作り直す（2026-07-17 決定）
- **中断**：編成モーダルまでは可（未編成は自動編成）、リーグ興行開始後は不可
- **特徴**：S4 ジュニアの姉妹シーケンス。ブラケット→リーグ表に置き換えた構成で、進行UIはS4の試合消化を流用する

## 2-D Events

シーケンス未満の小さな画面遷移。1〜数モーダルで完結するか、既存シーケンスに乗っかる形のもの。

### イベントの3グループ

#### グループ1：小モーダル系イベント

1モーダルで完結するもの。発生 → 3択 or 確認 → 結果反映。

- **B1：練習中の怪我**（3択：特別治療 / 通常治療 / 強行出場）
- **B4：タレント活動**（CM・グラビア・バラエティなど7種から選択）
- **AI退団通知**（新聞記事1本）
- **チャンピオン怪我引退時の社長への一言ポップアップ**

**ビジュアル**：Office Cream Panel ベースのモーダル。Foundations 準拠。

---

#### グループ2：試合発展型イベント

モーダルで始まり、最終的に試合観戦画面（P7 Theatrical / Stage）に発展するもの。

- **B2：選手間の深刻対立**（話し合い / 試合決着 / 放置）

## 2-F 画面とパターンの対応表について

ここに全画面の対応表を書くことはしない。本プロジェクトのUIマイグレーション方針は **「ルールを先に確立して、後で1画面ずつ差し替える」** であり、画面ごとのパターン割り当ては**その画面を実際に差し替えるタイミング**で階層3の画面仕様書に記載する。

階層3の画面仕様書が増えていけば、結果的にこの対応表が `docs/ui/03-screens/` の目次として自然に出来上がる。
