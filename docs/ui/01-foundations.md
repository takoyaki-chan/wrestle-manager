# レッスルマネージャー UI設計仕様 — 階層1：Foundations

> このゲームのUIを構成する3つのカテゴリ、それぞれのトークン体系、設計原則を定義する。
> 階層1は最上位の合意であり、変更する場合は明示的に議論を再開する。

---

## 1-0 前提となる問題意識

- 既存の `wrestle-manager-design-system.html`（v1.0, 2026-03-26）は**部品カタログ**であり**設計図ではない**
- `src/index.html` では `var(--*)` が538箇所使われる一方、ハードコード16進カラーが579箇所残っている
- CLAUDE.md にデザインシステムへの参照が一切ない → Claude Code が実装時に参照していなかった（→ 階層3作業と同時に修正予定）
- 新画面追加のたびに色味・余白がドリフトし、「古い画面だけ浮いて見える」問題が発生

---

## 1-1 診断

既存の「DARK」テーマが**2つの役割を兼任**していたことが根本原因:

- **役割A**：Cream Panel の外枠フレーム（暖色でなければ Cream と喧嘩する）
- **役割B**：管理系単独画面の背景（暖色である必要はない）
- **役割C**：スペクタクル画面の背景（暖色だと締まらない → BLACK が応急処置で生まれた）

歴史的経緯:
- 最初は紺っぽい黒背景でスタート
- CREAM（暖色ベージュ）導入後、紺黒と喧嘩したので暖茶DARKに寄せた
- 現BLACKには過去のネイビーの残り香があり中途半端

→ **1テーマで3役割は無理**。役割ごとに分離するのが正解。

---

## 1-2 解決方針：3カテゴリ構造

UIを3つのカテゴリに分け、それぞれが独自の世界観・パレット・トークン体系を持つ。

| カテゴリ | 世界観 | 背景 | 主用途 |
|---|---|---|---|
| **Office** | 事務所の机の上で書類を眺めている | 暖茶 | 管理系画面全般 |
| **Stage** | 試合会場の暗闇 | 純黒 | 試合・興行進行 |
| **Ceremony** | 格式ある式典会場 | 漆黒 + ベルベット | 年末表彰式・殿堂入り発表など |

---

## 1-3 Office（オフィス）

### 世界観

事務所で資料や書類を広げて団体運営をしている。ロスター・殿堂・新聞は全て**「事務所の机の上で書類を眺めている」メタファー**で統一される。

### 背景

暖茶 `#24221e` 系（事務所の木目・革張りのイメージ）

### パネル様式

Office は2種類のパネル様式を内包する:

- **Dark Panel**：暗いパネル（ディスプレイ・黒板・モニター的な要素）
- **Cream Panel**：ベージュパネル（紙の書類・資料・ファイルのメタファー）
  - 副次効果：紙っぽい質感（微かなテクスチャ、角の陰影）を与える正当な理由ができる
  - 新聞画面との相性が完璧

同じ画面内で Dark Panel と Cream Panel を併置してよい。

### 属する画面

スケジュール、収支、道場、興行設定、ロスター、選手詳細、殿堂、団体設定、データベース、対戦比較、新聞、関係性マップ、モーダル類など。

### トークン命名（提案）

```
--office-bg            /* 暖茶背景 */
--office-panel-dark    /* 暗いパネル */
--office-panel-cream   /* ベージュパネル */
--office-border-*      /* 枠線 */
--office-text-on-dark-*    /* Dark Panel上の文字色 */
--office-text-on-cream-*   /* Cream Panel上の文字色 */
```

### 既存コードとのマッピング

`src/index.html` には Office 相当のCSS変数が既に存在する。新規定義ではなく、まずエイリアスとして再定義してから段階的に置き換える方針を推奨。

| 新トークン名（提案） | 既存変数 | 値 |
|---|---|---|
| `--office-bg` | `--bg-dark` | `#24221e` |
| `--office-panel-dark` | `--panel-bg` | `#181614` |
| `--office-panel-dark-deep` | `--card-bg` | `#12110e` |
| `--office-panel-cream` | `--cream-panel-bg` | `#d4ccb8` |
| `--office-panel-cream-card` | `--cream-bg-card` | `#ede8dc` |
| `--office-border-cream` | `--cream-border` | `rgba(100,85,50,0.14)` |
| `--office-text-on-dark-main` | `--text-main` | `#e8e6e0` |
| `--office-text-on-cream-main` | `--cream-text-main` | `#1e1c16` |

ゴールド系アクセント（`--gold`, `--gold-light`）は Office 内でも Stage 内でも共通利用される（カテゴリ横断アクセント）。

## 1-4 Stage（ステージ）

### 世界観

試合会場の暗闇。**照明と選手と観客だけが存在する非日常空間**。

### 背景

純黒 `#060606`（赤み・青みを排除）

### 選定理由

- 会場背景写真の色味を邪魔しない
- 金アクセントが最も引き立つ
- 暖色だと「暖炉の前で試合を観てる」感じになり緊張感が抜ける
- 過去のネイビー背景の失敗を繰り返さない

### 原則

**Cream Panel は絶対に置かない**。Stage に紙の書類は存在しない。

### 属する画面

興行進行（試合中）、試合結果、入場演出、興行終了サマリ、対抗戦試合、PPV試合、ジュニアトーナメント試合など。

### トークン命名（提案）

```
--stage-bg             /* 純黒背景 */
--stage-bg-deep        /* より深い奥行き用 */
--stage-panel          /* 情報パネル */
--stage-accent-gold    /* 金アクセント */
--stage-text-*
```

### 既存コードとのマッピング

Stage 専用の純黒トークンは現状定義されていない。新規追加が必要。実装時に Stage 専用画面に手を入れるタイミングで導入する。

## 1-5 Ceremony（セレモニー）

### 世界観

格式ある式典会場。**時間がゆっくり流れる特別な場**。厳粛さ。

### 背景

漆黒 `#080604` + ベルベット系装飾

### フォント

- **メイン（和文）**：Noto Serif JP（Weight 500/700/900）
- **アクセント（英字）**：Cormorant Garamond（Weight 500/600/700 italic）

### レイアウト

全画面テイクオーバー:

- トップバー・ナビバー非表示
- 上下レターボックス（任意）
- スライド進行方式
- 通常UIより遅いアニメーション（ease-in-out、600〜1200ms）

### 属する画面

年末表彰式、昇格戦式典、引退セレモニー、殿堂入り発表、メディア功労賞発表、ジュニアトーナメント優勝式など。

### 詳細設計

**階層4 Ceremony Full Spec で完全設計する**。本ファイルではカテゴリ定義のみ。

### 既存コードとのマッピング・未解決事項

⚠️ **重要な未解決事項**：現在の実装は Ceremony 系で2種類のセリフ書体が混在している:

- **Noto Serif JP**：年末表彰式（`.aw-header-title`, `.winner-name`, `.hof-name` 等、約13箇所）
- **Shippori Mincho**：オープニングシーケンス（`.opening-act-line`）、ドラフト演出（`.draft-narration` 等）

`--font-ceremony` 変数は `'Shippori Mincho'` で定義されているが、年末表彰式はこの変数を経由せず直接 Noto Serif JP を指定している。

**判断保留**：階層4作業時に以下を決定する:
1. Ceremony 全体の和文書体を **Noto Serif JP に統一**するか（推奨）
2. それとも **Shippori Mincho に統一**するか
3. それとも**画面ごとに別書体を許容**するか（非推奨）

### 迷いどころ

- **タイトル奪取シーン**：基本 Stage、ただし歴史的瞬間（10年ぶり奪取など）は Ceremony 要素を一部混入させる可能性 → 階層4で要判断

## 1-6 設計原則まとめ

1. **Office と Stage は画面内で同居しない**。遷移で切り替わる
2. **Cream Panel は Office 内にのみ出現する**
3. **Stage と Ceremony はどちらも非日常**だが、Stage = 熱狂、Ceremony = 厳粛 で明確に分かれる
4. **既存 `wrestle-manager-design-system.html` v1.0** は部品カタログとして残す。破棄はしない
5. **トークン命名は役割ベース**（`--office-*`, `--stage-*`, `--ceremony-*`）
6. **ハードコード16進カラー禁止**。色は必ず `var(--*)` トークンを使う
7. **既存変数からの段階的移行**を許容。新トークン名をエイリアスとして導入し、画面単位で置き換える
8. **画面の差し替えは1枚ずつ**。一度に全画面を作り変えない。階層3作業はマイグレーション単位で進む

---

## 1-7 タイポグラフィ（共通）

### 使用書体（3種、確定）

| 用途 | 書体 | 主用途 |
|---|---|---|
| 本文 | **Noto Sans JP**（Weight 300/400/700/900） | 全カテゴリの本文 |
| 数値・大見出し | **Bebas Neue** | OVR・ステータス値・スコア |
| ラベル | **Oswald**（Weight 400/600/700） | UPPERCASE のメタラベル全般 |

Office と Stage はこの3種のみで構成される。Ceremony のみ追加で和文セリフ＋英字セリフを使う（1-5 参照）。

### 確認済み事実

- セリフ書体（Shippori Mincho・Noto Serif JP）は **Office 画面では一切使わない**
- Stage 画面でもセリフ書体は使わない
- Ceremony だけがセリフ領域

## 1-8 アクセントカラー（共通）

| 用途 | トークン | 値 | 備考 |
|---|---|---|---|
| 主アクセント | `--gold` | `#d4a843` | カテゴリ横断 |
| 主アクセント明度高 | `--gold-light` | `#f0d078` | グラデーション末端等 |
| Office内Cream上のゴールド | `--cream-gold` | `#7a6530` | Cream Panel上では暗いゴールド |
| Office内Cream上のゴールド濃 | `--cream-gold-dark` | `#5c4a1e` | 同上 |
| 派閥識別色1（暖色） | `--accent-faction-1` | `#c38c54` | 琥珀系、派閥ID順で循環割当 |
| 派閥識別色2（寒色） | `--accent-faction-2` | `#6d94b8` | 群青系 |
| 派閥識別色3（紫系） | `--accent-faction-3` | `#8a7aa8` | 藤紫 |
| 派閥識別色4（緑系） | `--accent-faction-4` | `#6fa28c` | 鶯緑 |
| 対立度アクセント | `--accent-hostility` | `#d07a3e` | 対立破線・対立バッジ |

派閥識別色4種は彩度を抑え、Office/Stage のどちらの背景でも輪郭が出る中間色。相関図・DB派閥タブで派閥ID順に循環して使う（5派閥目以降は mod で周回）。
