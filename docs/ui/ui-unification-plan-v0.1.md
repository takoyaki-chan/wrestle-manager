# UI統一リデザイン計画 v0.1

> 起案 2026-07-25。「用途は同じなのに実装が割れている」箇所を、**用途ごとにリデザイン→モックアップ承認→一括改変**で潰していく。

## 経緯と方針

段階的に「触るときに直す」方式では**触られない画面が永遠に取り残される**（実例: `.speech-bubble` が画像の下に付いたまま8画面で放置されていた）。
そこで **①全体の実態把握 → ②用途ごとにリデザインしてモックで承認 → ③その用途を一括改変** の順で進める。

### 重要な前提（Keisuke 裁定 2026-07-25）

- **既存の共通部品は「既にある」だけで、設計として信用できるとは限らない。**
  `.pb-champion-*` や `_awSpeech()` のように複数画面で共有されていても、それが正しいデザインである保証はない。
- したがって **「既存部品に寄せる」ことを前提にしない**。**必ずリデザインし、モックアップで見て判断する。**
- 判断基準はモックアップ。実装の来歴や共有度ではない。

## 進め方（1用途あたり）

1. **現状の全バリエーションを1枚に並べる**（何がどう違うか可視化）
2. **リデザイン案を作る**（既存部品に寄せるとは限らない。ゼロベースで考えてよい）
3. **モックアップで承認を得る**
4. **その用途を一括改変**（全画面）
5. テスト・実機確認 → コミット

## 既知の問題（調査で判明・モック時に必ず解消する）

- `.speech-bubble`（表彰式・殿堂入り・チャンピオンで**8箇所共有**）が `margin-top:12px` で**画像の下**に付いている
- `.emr-org-badge` は実エンブレム画像ではなく**団体名の頭文字1文字**を色丸で代用。他画面（秋対抗戦・交渉）は実画像を使っており不整合
- 派閥イベント内に `verdict` クラスが**4種類**（`fevt-ign` / `fevt-peace` / `fevt-res` / `fevt-endless`）— 同一機能内での重複
- 派閥内対決（Common-1）は**プレビューが `pb-mrow`、結果が `.c1r-*`** と、同一フロー内で実装が割れている
- 秋対抗戦の優勝メンバー3人のうち**1人にしか吹き出しが出ず、他2人は空枠もない**（左右の高さが揃わない）
- コーチ担当選手チップが**CSSクラスすら使わず全てインラインstyle**（ui-render.js:2054-2064）

## テスト網の状況

回帰テストがあるのは `.emr-bubble` / `.crrm-*` / `.agw-champion*` / `.pb-mrow` / `.speech-bubble` / `.team-bubble` のみ。
それ以外（`.c1r-*` `.fc1m-*` `mdl-a/b-*` `.tcwn-*` `.cerem-*` `.fevt-*-bubble` ほか）は**テスト無し＝安全網が薄い**。改変時は実機確認を厚めに。
