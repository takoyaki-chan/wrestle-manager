# モックアップ共通ベースライン v0.6

> 起案 2026-07-25。**UI統一リデザインで作る全モックアップは、この物差しの上で作る。**
> バラバラのルールで作ったモックを並べても比較にならず、判断ができないため（Keisuke 指示）。

## この文書の位置づけ

- `docs/ui/01-foundations.md`（色・カテゴリ）を前提に、**サイズと配置の基準**を補うもの
- 既存実装には**フォントサイズの基準が存在しない**（9〜32px が場当たりに使われている）ため、ここで定める
- **モックアップ作成時は必ずこの値を使う。** 逸脱する場合はその理由をモック内に明記する

---

## 1. タイプスケール

実装の実測（`font-size` 出現頻度: 11px=300回 / 10px=252 / 12px=208 / 13px=168 / 9px=140 / 14px=122 …）を踏まえ、**使用実績のある値に寄せて7段階**に整理する。

| 役割 | サイズ | 用途 | フォント |
|---|---|---|---|
| `display` | **28px** | 大会名・最重要の数値（スコアなど） | `--font-display` (Bebas Neue) |
| `title` | **18px** | モーダル見出し・画面タイトル | `--font-body` 太字 |
| `subtitle` | **15px** | 選手名（主役）・セクション見出し | `--font-body` 太字 |
| `body` | **13px** | セリフ本文・説明文 | `--font-body` |
| `label` | **11px** | 役割ラベル・団体名・補助情報 | `--font-body` or `--font-label` |
| `caption` | **10px** | 注記・単位・日付 | `--font-body` |
| `micro` | **8px** | 英字キッカー・記号ラベル（`OVR` `MQ` など） | `--font-label` 字間広め |

**禁止**: 上記以外の中間値（16px, 17px, 21px, 22px…）を新規に使わない。既存実装の値をモックへ持ち込まない。

### 数字の扱い
- スコア・OVR・MQ などの**数値は `--font-display`**（Bebas Neue）で大きく
- 数字が縦に並ぶ表は `font-variant-numeric: tabular-nums`

## 2. 選手画像（アッパー）のサイズ

> **v0.2 で改訂（2026-07-25）。** U3 の全数調査で、顔出し実装だけで **28通りのサイズ**が使われている一方、
> **既に実装済みのもの（U1/U2 の成果物）は全部 2:3 の縦横比で揃っていた**ことが判明した。
> つまりサイズ体系は既に一貫しており、違いは「主役度の段」だけ。v0.1 の `hero 172×200`(1:1.16) は
> 実装（172×258）と一致しない誤記だったため、**実装に合わせて訂正**する。

**縦横比は 2:3 で固定。** アッパー画像の元データがこの比率なので、どの段でも顔が崩れない。
主役度に応じて**段を選ぶだけ**にし、画面ごとにサイズをその場で決めない。

| 段階 | サイズ | 用途 |
|---|---|---|
| `XL` | **172×258** | 単独の主役（優勝発表・戴冠・引退・挑戦試合の勝者） |
| `L` | **150×224** | 2人が主役（タッグ優勝）／隊列の中心（大将） |
| `M` | **132×194** | 2人を対置する（試合結果・因縁・直接対決）／隊列の脇（先鋒・中堅） |
| `S` | **108×162** | おまけ（MVP・副賞） |
| `chip` | **46×66** | 一覧・隊列・小さな並び |

**段の間は12%以上空ける。** v0.2 では6段あったが、`M 132 → S 126` が 4.5%、`S 126 → XS 120` が 4.8% しか
違わず、並べても差が読み取れなかった（`XL→L` は13%、`L→M` は12%）。
**差が分からない段は持つ意味がない**ため2段を1つに畳んだ（2026-07-25 Keisuke 指摘）。

- 角丸は `--radius-md`(6px)。下辺のみアクセント色の3px境界（勝敗・所属を示す）
- 敗者は `filter: grayscale(.9) brightness(.72)` ＋ 下辺境界を無彩色に

### 勝敗の格差の付け方

| 画面の型 | 付け方 |
|---|---|
| **2人を並置する**（試合結果・因縁・直接対決） | **サイズは同じ段に揃える。** 灰色化と下辺の色だけで表す（左右の対称性が崩れるため） |
| **1人ずつ別々に見せる**（挑戦試合の結果リアクションなど） | **勝者を一段上げてよい**（対称性の制約が無く、勝った実感を優先する） |

## 2-B. 隊列（複数人を1つの群として見せる）

> 2026-07-25 確定（案C）。秋4団体対抗戦の優勝3名／春タッグリーグの優勝2名／派閥の隊列に適用する。

**一人ずつ枠で囲まない。** 個々に額縁を付けると「団体戦なのに個人の表彰が3回並んでいる」ように見え、
チームで獲った実感が出ないため。

| 項目 | 値 |
|---|---|
| 枠 | **群の外側に1つだけ**。個々の画像に額縁を付けない |
| 重なり | 隣どうしを **18px** 重ねる。**境目の縁は付けない** |
| 1枚ごとの背景・枠 | **付けない。** アッパーは切り抜きの透過画像（webp の ALPHA チャンクで確認済み）なので、重なるのは**キャラクターのシルエットどうし**であり矩形の境目は存在しない。背景は群の枠が1つだけ持つ |
| 落ち影 | `filter: drop-shadow()` を使う（`box-shadow` は矩形に付くため誤り）。シルエットに沿って影が出る |
| 中心の扱い | 大将／主役は **z-index で手前**に出す |
| サイズ | 中心 = `L`(150×224)／脇 = `M`(132×194)。同格の2人（タッグ）は**両方 `L`** |
| 揃え | `align-items: flex-end`。中心だけ縦に大きいので両脇の上に余白ができるが、**ひな壇に立っている**見え方として許容する |
| 吹き出し・名前の列 | **画像と同じ重なり量を掛ける**。掛けないと名前と画像の中心がずれる |
| 見出し | 団体名と「優勝」などの称号を**群の頭に乗せる**（個々ではなく群に掛かるものとして） |
| 発言しない人 | **枠だけ置き、吹き出しの箱は出さない**。全員に同じ高さの予約枠を置く |

### 丸い顔アイコン（第4の系統）

道場ヘッダー・ログトースト・Glimpse・ケアモーダルなど **10箇所が丸いアイコン**（24〜96px）を使っており、
上の矩形の梯子とは形状の考え方が異なる。

**2026-07-25 確定**: 矩形に変えず、**一覧・通知専用の系統として認める**。ただし
**「小さく差し込んでいる場所」だけ**に限る（一覧の行・トースト・観察コメントなど）。
主役として顔を見せる場面では使わず、上の矩形の梯子に従う。

| 用途 | サイズ |
|---|---|
| 標準（一覧の行・通知） | **40px** |
| 背景として引かせる（道場バナーで休憩中の選手など） | **34px** |

※ 同じ画面に複数の丸アイコンが同居するとき（道場バナー）は、**大きさで役割の階層を作る**。
コーチ48px ＞ 練習中の選手40px ＞ 休憩中の選手34px。一律に揃えない。

## 2-C. 一覧に差し込む顔（正方形の face 画像）

> 2026-07-26 確定（U7 案A）。**画像の素材が2系統ある**ことを明文化する。
>
> | 素材 | 縦横比 | 使う場面 |
> |---|---|---|
> | **アッパー**（`getUpperUrl`） | **2:3** | 主役として顔と体を見せる。§2 の梯子に従う |
> | **face**（`portraitImg` / `getPortraitUrl`） | **1:1** | 一覧の行・チップに小さく差し込む。この節の梯子に従う |
>
> §2 の梯子を正方形に当てはめると顔が切れるので、正方形には**別の段**が要る。

**正方形は2段だけ。** U7 の全数調査で、正方形の顔だけで **18 / 20 / 22 / 24 / 32 / 34 / 36 / 40 / 52 / 72 / 80 の11通り**が使われていたが、
**40px 以下の8通りは並べても区別がつかない**（32→34 は6%、34→36 は6%、36→40 は11%）。段が多いのではなく、決めずに書いた結果が散らばっているだけ。

| 段階 | サイズ | 用途 |
|---|---|---|
| `row` | **40×40** | 一覧の標準の行（データベース一覧・週の行動表・選択リスト・道場の練習中） |
| `row-sm` | **24×24** | 行が詰まっている一覧・チップ（コーチ担当チップ・興行準備のピッカー） |

- 角丸は `--radius-sm`(4px)。丸（`border-radius:50%`）にするのは §2-B の通知・トースト系だけ
- 王者は `portraitImg()` が自動で枠色を変える（`.portrait-champ`）。**`getPortraitUrl` を直に書くと、この恩恵を受けられない**ので使わない

**掛かるのは「2人以上が並ぶ一覧・カード」だけ。** 1人だけを見せる場面（Glimpse・交渉の話し手・王者バッジなど）は
この節ではなく §2／§2-B に従う。**道場バナーの 34px も例外**（コーチ48 ＞ 練習中40 ＞ 休憩中34 の階層は §2-B で確定済み）。

### 正方形は 40 を超えない

52 / 72 / 80 の正方形も **`row` 40 に揃える**。正方形は「一覧に小さく差し込む」ための系統であって、
大きさで主役度を作る系統ではない（それは §2 の 2:3 梯子の仕事）。中途半端に大きい正方形は、
素材の 2:3 を切り落としながら主役にもなりきれない。

**もっと大きく顔を見せたい画面（引き抜きオファーなど）は、正方形を拡大するのではなく
アッパー画像に差し替えて §2 の梯子に乗せる。** これは形が変わるので**別の判断**として残す（2026-07-26 時点で未着手）。

### 顔が出ているなら、押せば選手詳細が開く

> 2026-07-26 確定（U7 ◆1）。

U7 の全数調査で、**顔が出ているのに押しても何も起きない一覧が12箇所**あった（引き抜きオファーは 80×80 の顔がありながら不可、年代記の3ブロック、春タッグの順位表、ブラケット全段など）。
プレイヤーから見れば**顔が出ている＝その選手の話**なので、押せることを期待する。例外を作らない。

| 一覧の型 | 押したときの動き |
|---|---|
| **見るだけの一覧**（順位表・履歴・年代記・ブラケット・結果サマリー） | 行ごと `showFighterPopup()` |
| **選ぶための一覧**（ドラフト・エントリー・カード編成） | **顔画像＝詳細を開く／行とボタン＝選択**。選択の邪魔をしない |
| 殿堂 | 殿堂専用ポップアップのまま（選手詳細より情報が多いため。例外として明記する） |

- `showFighterPopup(id, source)` の `source` は**呼び出し元の画面名**を渡す。省略すると戻り先が壊れる
- 選択用の一覧で顔に詳細を付けるときは `event.stopPropagation()` を忘れない（行の選択が同時に走る）

## 3. 吹き出し

| 項目 | 値 |
|---|---|
| 配色 | **セリフの吹き出しは白（クリーム）に黒文字。例外なし**（2026-07-26 Keisuke 確定）。背景が暗い画面でも暗い塗りの吹き出しにしない。<br>**この規則が掛かるのはセリフだけ。** 地の文・ナレーション・雰囲気テキストは白でなくてよい |
| 位置 | **キャラ画像の上**（被せない・横や下に置かない） |
| 中身 | **セリフ本文のみ**（名前・所属を入れない） |
| 高さ確保 | **予約枠**（`position:absolute` で浮かせない）。発言が無い側にも同じ高さの空枠を置き、左右の画像上端を揃える |
| 枠の高さ | `XL`〜`M` = **52px**（2行想定）／`S`・`XS` = 46px ／`chip` = 40px |
| 行数制限 | `-webkit-line-clamp: 2` |
| 本文サイズ | `body`(13px)。`S`・`XS`・`chip` 併用時は `label`(11px) |
| 空枠の出し方 | 発言が無い側は**枠だけ置き、吹き出しの箱は出さない**（空の箱が描画されるため） |
| 地の文との区別 | **地の文（話者のいないナレーション・観察）は吹き出しにしない。** 鉤括弧も付けない。**セリフ＝白い塗りつぶし／地の文＝白でない見せ方**、で区別する |
| 尻尾 | 画像の**水平中心**を指す |
| 角丸 | `--radius-lg`(10px) |

※ 実データの最長セリフは43文字（`VICTORY_LINES` / `AUTUMN_WAR_MATCH_LINES`）。52px で2行に収まる。

## 4. 縦の並び順（顔出しブロック）

```
吹き出し（予約枠）
  ↓
選手画像
  ↓
名前            subtitle(15px) 太字
役割ラベル       label(11px)
団体バッジ       ← 他団体が絡むときのみ
数値(OVR等)      display(28px) + micro(8px)の単位
```

**この順序は固定**。画面ごとに入れ替えない。要らない要素は省く（順序は変えない）。

## 5. 団体バッジ

| 項目 | 値 |
|---|---|
| エンブレム | **実画像を使う**（`orgIconHtml()`）。頭文字の代用は禁止 |
| サイズ | バッジ内 26px ／ 単独掲示 40px ／ 見出し上の強調 62px |
| 団体名 | `label`(11px) `--font-label` |
| 囲み | 角丸ピル。自陣=`--c-positive` 系／敵陣=`--accent-hostility` 系の枠線＋薄い塗り |
| 出す条件 | **他団体が絡む試合のみ**。自団体内の試合では出さない（配置は変えずバッジだけ省く） |

## 5-B. 勝敗・スコアの見せ方

> 2026-07-26 確定。実装を数えたら **31箇所**あり、しかも**同じ記号が画面によって逆の意味**になっていた
> （`●` が「勝ち」の画面と「負け」の画面が同居）。以下を唯一の正とする。

### 記号（一覧・履歴の中）

| 記号 | 意味 |
|---|---|
| **○** | 勝ち |
| **×** | 負け |
| **△** | 引き分け |

**他の組み合わせは使わない。** 特に `●` を勝ちにも負けにも使わないこと。
※ 星取の慣習（白星○／黒星●）ではなく**この組み合わせを採る**（Keisuke 決定）。現状で最も多く使われている形でもある。

### 敗者の示し方（単発の結果画面）

- **`LOSE` の文字は使わない。** 敗者は `filter: grayscale(.9) brightness(.72)` と下辺境界の無彩色化で示す
- 勝者は `WIN`（引き分けは `DRAW`）。**勝者を立て、負けを言葉で突きつけない**
- 現状 `LOSE` の文字が出るのは31箇所中1箇所だけで、既にこの作法がほぼ一貫している

### 書式

| 対象 | 書式 |
|---|---|
| 通算成績 | **`N勝N敗N分`**（分が0のときは省略可）。現状は4通りに割れている |
| スコア（対戦形式） | **em ダッシュ区切り `3 — 1`**。現状は `-` / ` - ` / ` — ` の3通り |

## 5-C. モーダルの外枠

> 2026-07-26 確定。調査の結果、共通部品 `mdl-a`(決裁・選択) / `mdl-b`(節目の演出) /
> `mdl-c`(情報パネル) / `mdl-d`(軽いダイアログ) が既にあり **33箇所が移行済み**だった。
> 新設ではなく「寄せ切れていない残りを片付ける」作業。

### 重なり順は5階層に固定する

画面を覆う枠だけで `z-index` が **25種類**あり、体系が無かった。以下の5階層だけを使う。
**新しい画面では階層を選ぶだけ。数字をその場で決めない。**

| 値 | 階層 | 何を置くか |
|---|---|---|
| **100** | 画面 | 興行結果・対抗戦など、それ自体が1つの画面として振る舞うもの |
| **200** | 通常のモーダル | 決裁・選択・情報パネル・軽いダイアログ（`mdl-a` / `b` / `c` / `d`） |
| **300** | 演出 | 試合結果・派閥イベント・移動シーン。モーダルの上に重なってよいもの |
| **400** | 式典 | オープニング・表彰式・節目セレモニー。進行を止めて見せるもの |
| **500** | 最上位 | 観戦モードの iframe・ゲームオーバー。何よりも上 |

### 閉じ方の使い分け

| 種類 | 閉じ方 |
|---|---|
| **情報を見るだけ**（選手・コーチ・殿堂入り・相関図） | **背景クリック と ESC の両方**で閉じられる |
| **選択を迫るもの・演出** | **専用ボタンのみ**。誤って閉じると進行が壊れるため |

※ 現状は42件中、背景クリックが2件・ESCが1件だけ。また「背景クリックで閉じる」ための
子側の処理だけ書いて**親側を書き忘れた**箇所が複数ある。親を実装するか子を消すかで揃える。

## 6. 余白のリズム

既存の `--space-*` を使う。**新しい余白値を作らない**。

| トークン | 値 | 主な用途 |
|---|---|---|
| `--space-xs` | 4px | 要素内の細かい隙間 |
| `--space-sm` | 8px | 名前と役割ラベルの間など |
| `--space-md` | 12px | ブロック間 |
| `--space-lg` | 16px | セクション間・カード内側の余白 |
| `--space-xl` | 24px | 画面の外周 |

- カード外周は `--space-lg`
- 左右対称レイアウトの中央カラムは **150px**（試合結果系）

## 7. 色

`docs/ui/01-foundations.md` の3カテゴリ（Office / Stage / Ceremony）に従う。

- **ハードコード16進カラー禁止。** 必ず `var(--*)` を使う
- モックアップでも**実トークン値を再現**する（実装時に色が変わるのを防ぐ）
- 勝敗: 勝=`--c-positive` / 負=`--accent-negative` / 引分=中間色
- 陣営: 自=`--c-positive` 系 / 敵=`--accent-hostility` 系

## 8. モックアップの作り方（運用）

1. **現状の全バリエーションを1枚に並べる**（何がどう違うか可視化する）
2. その下に**リデザイン案**を置く。左右または上下で比較できる形に
3. **注釈で「現→変」を明記**する
4. 変更点・判断が要る点を**画面末尾にリスト**する
5. **この文書の値を使う。** 逸脱するなら理由を書く

### やってはいけないこと
- モックごとにフォントサイズ・画像サイズ・余白の基準を変える
- 既存実装の場当たりな値をそのままモックへ持ち込む
- 「既にそうなっているから」を理由に設計判断を省く（既存部品が正しい保証はない）
