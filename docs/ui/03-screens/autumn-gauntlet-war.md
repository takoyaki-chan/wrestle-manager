## 目的

4団体各3名の勝ち抜き戦を、「誰が残り、誰が脱落し、どれだけ消耗したか」を読みながら采配する大会として見せる。代表選出からMVPまで秋色のStageブランドを保ち、通常興行画面やOfficeへ戻さない。

## 遷移

```text
Week 34 告知
  → Week 36 導入
  → 代表3名・出場順編成
  → 準決勝（1フォールずつ観戦または結果表示）
  → プレイヤー決勝進出時のみ並び替え
  → 決勝
  → 大会結果
  → MVP一言シーン
  → 今週画面
```

- Week 35 の編成phase、バナー導線、Officeモーダルは廃止。
- Week 36 開始後は `#autumnWarOverlay` がグローバルChromeを覆い、大会完了まで戻る入口を持たない。
- 保存／再読込時は `_pendingAutumnWarReplay` と `autumnWar.session` から現在地点を復元する。
- `data-phase` は `intro / entry / board / reorder / result / mvp` のいずれか。

## 共通画面骨格

### A. 導入

大会エンブレム、参加4団体の準決勝組み合わせ、次の3ステップを一画面で示す。

1. 代表3名と先鋒・中堅・大将を決める
2. 敗者が脱落し、勝者がリングへ残る
3. 準決勝後に決勝布陣を組み直す

読まなくても「代表を決める」ボタンへ進めるが、初見でもルールを把握できる密度にする。

### B. 代表編成

承認済みモックアップ：`docs/ui/mockups/autumn-gauntlet-war-entry-live-board-v0.2.html`

#### Desktop

- 自団体のフル画像3名を同一サイズで配置。
- 先鋒と大将を前列、中堅を背後かつ少し上へ置く三角配置。
- 対面側には同じ3枠の空シルエットを低彩度で置き、初戦の相手団体名・平均OVR・OVR幅だけを開示する。
- 自団体側の人物直下・右半分内に先鋒／中堅／大将の名前ボタンを置き、人物との対応を崩さない。
- 人物画像はクリック判定を持たず、名前ボタンを `z-index:30` の独立レイヤーにして重なりによる押下漏れを防ぐ。
- 相手側の人物直下には、文字も操作もない空欄3枠を置く。
- 名前ボタンで交代対象を選び、横スクロール候補棚から選手を入れ替える。

#### 375px

- L1案の縦カードを先鋒→中堅→大将の順で並べる。
- 各カードは同一画像サイズ。名前、OVR、コンディション、役割説明、交代／上下移動を持つ。
- 候補棚は横スクロール。初戦相手の平均OVR・OVR幅を省略しない。

#### 共通情報

- OVRは数値だけを強く見せ、選手データベース共通の `100 / 95 / 90 / 85 / 80 / 70 / 60` 閾値で色を変える。
- 選手画像または名前から `showFighterPopup` を開ける。
- `[おまかせ]` と未操作時の初期値は、OVR上位3名を昇順に並べて大将を最強にする。

### C. 大会進行ボード

```text
┌ 秋エンブレム / 大会名 / 現在フォール ┐
│ 準決勝→決勝の小型クライムライン       │
│ 現在の2団体×3名を全身画像で中央対面    │
│ 役割・名前：RING / WAIT / OUT          │
│ 現在フォールの2名・COND                │
│ [観戦] [1試合結果] [まとめてスキップ] │
│ 4団体全体は下部の小型ステータスレール │
└───────────────────────────────────────┘
```

- 現在対戦中の2団体を主役にし、左を対戦相手、右を自団体に固定する。プレイヤー不在のAI戦はブラケット順を使う。
- 左側の全身画像だけを反転し、左右の選手が中央へ向き合う。右側の名前枠も表示順を反転して各人物の真下に合わせる。
- 旧4団体カード一覧は小型ステータスレールへ縮小し、準決勝→決勝のクライムラインは補助情報として残す。
- コンディションバーの100%は大会上限80。表示・ARIAともこの尺度に合わせる。
- 中央6名の名前枠と現在フォールの選手名から詳細を開ける。
- `[観戦する]` と `[結果を見る]` は同じ1フォールを一度だけ確定する。観戦は同じ結果のframesをバトル画面へ渡し、終了時に再シミュレートしない。
- `[まとめてスキップ]` は確認後、現在の団体戦だけを既存 `simulateNextBout` で1フォールずつ決着まで進める。大会全体・次の団体戦は進めず、団体戦決着画面で止める。
- 3操作ボタンはDesktopで同幅48px高、375pxで3等分54px高にそろえる。
- 各フォールの対面カードは55%で両選手の掛け合いを表示し、結果ポップアップは60%で勝ち残り選手の一言を表示する。毎回必ずは出さない。

### D. 決勝前の采配

プレイヤーが決勝へ進んだ場合だけ表示する。準決勝後の回復を反映した3名のコンディションとOVRを見せ、上下操作で再配置する。相手団体名は表示するが、最終順は決勝開始まで伏せる。モバイルでも相手情報を消さない。

### E. 結果・MVP

- 結果：優勝団体、決勝スコア、優勝3名、勝ち抜き数、MVPを表示。75%で優勝チームの最多勝ち抜き選手が代表スピーチを行う。全選手カードから詳細を開ける。
- MVP：1名だけを大きく映し、`gauntlet / champion / defiant` × personality × archetype で一言を解決する。
- 掛け合い・勝ち残り・優勝スピーチはローカルseedで抽選し、同じ大会・同じフォールを再描画しても有無と文面を変えない。
- 「大会を終える」で初めて専用Overlayを閉じ、今週画面へ戻る。

## 状態と表示ルール

| 状態 | 表示 |
|---|---|
| 控え | 通常彩度、コンディション表示 |
| リング上 | 秋色の強調、`RING` |
| 脱落 | 低彩度・低輝度、`OUT`。行自体は残す |
| 元気 | 正常色 |
| 疲れが見える | 警告色 |
| 消耗が大きい | 危険色 |

## レスポンシブ

| 1001px以上 | 現在2団体の6名対面ボード、Desktop三角編成 |
| 701〜1000px | 6名対面を維持、決勝采配1列。相手情報は保持 |

## アクセシビリティ

- 専用Overlayは `role="dialog"`、`aria-modal="true"`。
- phase遷移ごとに主操作へフォーカスを移す。
- 画像だけで選手を識別させず、名前・役割・状態を併記する。
- 詳細を開く名前／画像はbutton、または Enter / Space 対応のbutton相当要素にする。
- 色だけで状態を伝えず、`RING / OUT / CONDITION` ラベルを併記する。

## デザイントークン

- 背景：`var(--stage-bg)` / `var(--stage-panel)` / `var(--stage-panel-deep)`
- 大会色：`var(--ev-autumn)` + `var(--gold)`
- 文字：`var(--stage-text-main)` / `var(--stage-text-sub)` / `var(--stage-text-dim)`
- 状態：`var(--c-positive)` / `var(--c-warning)` / `var(--c-negative)`
- `agw-` CSS内にハードコード16進カラーを追加しない。

## 実機確認項目

1. Week 34告知からWeek 36へ進み、導入画面がOffice chromeを覆う。
2. Desktopの3名が同サイズの三角配置、375pxがL1縦配置になる。
3. Desktopの役割ボタン3つが人物の真下・右半分内に収まり、どのボタンも1回で交代対象へ切り替わる。
4. 試合状況で相手が左、自団体が右に出て、左右6名が中央を向き、名前枠が人物と一致する。
5. 3操作ボタンが同寸で、観戦と1試合結果で同じフォールが重複反映されない。
6. まとめてスキップが確認後に現在の団体戦だけを決着させ、次の団体戦へ自動遷移しない。
7. 決勝進出時だけ再配置が入り、相手情報がモバイルでも残る。
8. 結果→MVP→終了まで途中でOfficeへ戻らない。
