## 目的

4団体各3名の勝ち抜き戦を、「誰が残り、誰が脱落し、どれだけ消耗したか」を読みながら采配する大会として見せる。代表選出からMVPまで秋色のStageブランドを保ち、通常興行画面やOfficeへ戻さない。

## 遷移

```text
Week 34 告知
  → Week 36 導入
  → 代表3名・出場順編成
  → 準決勝（1フォールずつ観戦または結果表示）
  → プレイヤー決勝進出時のみ並び替え
  → 決勝
  → 大会結果
  → MVP一言シーン
  → 今週画面
```

- Week 35 の編成phase、バナー導線、Officeモーダルは廃止。
- Week 36 開始後は `#autumnWarOverlay` がグローバルChromeを覆い、大会完了まで戻る入口を持たない。
- 保存／再読込時は `_pendingAutumnWarReplay` と `autumnWar.session` から現在地点を復元する。
- `data-phase` は `intro / entry / board / reorder / result / mvp` のいずれか。

## 共通画面骨格

### A. 導入

大会エンブレム、参加4団体の準決勝組み合わせ、次の3ステップを一画面で示す。

1. 代表3名と先鋒・中堅・大将を決める
2. 敗者が脱落し、勝者がリングへ残る
3. 準決勝後に決勝布陣を組み直す

読まなくても「代表を決める」ボタンへ進めるが、初見でもルールを把握できる密度にする。

### B. 代表編成

承認済みモックアップ：`docs/ui/mockups/autumn-gauntlet-war-entry-live-board-v0.2.html`

#### Desktop

- 自団体のフル画像3名を同一サイズで配置。
- 先鋒と大将を前列、中堅を背後かつ少し上へ置く三角配置。
- 対面側には同じ3枠の空シルエットを低彩度で置き、初戦の相手団体名・平均OVR・OVR幅だけを開示する。
- 自団体はシーズンごとに確定したブラケットの左右へ配置し、人物直下・自団体半分内に先鋒／中堅／大将の名前ボタンを置く。左配置時は人物・役割枠・ラベルをまとめてミラーし、対応を崩さない。
- 人物画像はクリック判定を持たず、名前ボタンを `z-index:30` の独立レイヤーにして重なりによる押下漏れを防ぐ。
- 相手側の人物直下には、文字も操作もない空欄3枠を置く。
- 名前ボタンで交代対象を選び、横スクロール候補棚から選手を入れ替える。

#### 375px

- L1案の縦カードを先鋒→中堅→大将の順で並べる。
- 各カードは同一画像サイズ。名前、OVR、コンディション、役割説明、交代／上下移動を持つ。
- 候補棚は横スクロール。初戦相手の平均OVR・OVR幅を省略しない。

#### 共通情報

- OVRは数値だけを強く見せ、選手データベース共通の `100 / 95 / 90 / 85 / 80 / 70 / 60` 閾値で色を変える。
- 選手画像または名前から `showFighterPopup` を開ける。
- `[おまかせ]` と未操作時の初期値は、OVR上位3名を昇順に並べて大将を最強にする。

### C. 大会進行ボード

```text
┌ 秋エンブレム / 大会名 / 現在フォール ┐
│ 準決勝→決勝の小型クライムライン       │
│ 現在の2団体×3名を全身画像で中央対面    │
│ 役割・名前：RING / WAIT / OUT          │
│ 現在フォールの2名・COND                │
│ [観戦] [1試合結果] [まとめてスキップ] │
│ 4団体全体は下部の小型ステータスレール │
└───────────────────────────────────────┘
```

- 現在対戦中の2団体を主役にし、プレイヤー参加の有無を問わずブラケットの `orgA / orgB` を左／右として使う。シード対戦は維持したまま各カードの左右をシーズンseedで決定し、同じ大会の再読込では変化させない。
- 左側の全身画像だけを反転し、左右の選手が中央へ向き合う。右側の名前枠も表示順を反転して各人物の真下に合わせる。
- 旧4団体カード一覧は小型ステータスレールへ縮小し、準決勝→決勝のクライムラインは補助情報として残す。
- コンディションバーの100%は大会上限80。表示・ARIAともこの尺度に合わせる。
- 中央6名の名前枠と現在フォールの選手名から詳細を開ける。
- `[観戦する]` と `[結果を見る]` は同じ1フォールを一度だけ確定する。観戦は同じ結果のframesをバトル画面へ渡し、終了時に再シミュレートしない。観戦中も秋大会BGMを停止・再開せず、そのまま継続する。
- フォール結果ポップアップと観戦リプレイも戦況ボードと同じブラケット順を引き継ぐ。選手・団体名・スコア・勝者表示・コンディション・セリフ本文を同じ表示側へそろえる。
- `[まとめてスキップ]` は確認後、現在の団体戦だけを既存 `simulateNextBout` で1フォールずつ決着まで進める。大会全体・次の団体戦は進めず、団体戦決着画面で止める。
- 3操作ボタンはDesktopで同幅48px高、375pxで3等分54px高にそろえる。
- 各フォールの対面カードは55%で両選手の掛け合いを表示し、結果ポップアップは60%で勝ち残り選手の一言を表示する。毎回必ずは出さない。

### D. 決勝前の采配

プレイヤーが決勝へ進んだ場合だけ表示する。初回の代表編成と同じ画面形式・操作方法を再利用し、Desktopは決勝ブラケット側に同サイズ全身画像3名の三角配置、375pxはL1縦カード、下部は代表3名の候補棚とする。役割枠を選んで代表選手を押すと、その選手を指定位置へ入れ替える。上下操作とおまかせ再編成も使える。

決勝では選手の追加・交代は行わず、準決勝を戦った同じ3名の出場順だけを変更する。各所に準決勝後の回復を反映したコンディションとOVRを表示する。決勝相手の団体名・平均OVR・OVR幅は表示するが、相手の最終順は決勝開始まで伏せ、モバイルでも相手情報を消さない。

### E. 結果・MVP

- 結果：優勝団体、決勝スコア、優勝3名、勝ち抜き数、MVPに加え、4団体特別大会の総分配原資と自団体の収入内訳を表示。75%で優勝チームの最多勝ち抜き選手が代表スピーチを行う。全選手カードから詳細を開ける。
- 優勝結果へ入った時点で、特別大会共通の `ff07`（MP3 `f10_victory_fanfare_v5.mp3`）を鳴らす。
- MVP：1名だけを大きく映し、`gauntlet / champion / defiant` × personality × archetype で一言を解決する。台詞は選手画像の頭上に、人物へ向けた尻尾付き吹き出しで表示する。
- MVP画面へ進む際は優勝結果のファンファーレを止め、`ff04`（Synth 試合勝利ファンファーレ f10）を鳴らす。優勝結果より強い音へ逆転させない。
- 掛け合い・勝ち残り・優勝スピーチはローカルseedで抽選し、同じ大会・同じフォールを再描画しても有無と文面を変えない。
- 「大会を終える」で初めて専用Overlayを閉じ、今週画面へ戻る。

## 共同興行の収益分配

Week 36 は通常興行を置き換えるため、順位賞金とは別に4団体合同の特別大会収益を分配する。5大特別大会の共通仕様に従い、興行収入は固定7,000万、ブランド収入は各出場チームの通常興行基礎額から個別計算する。

| 原資 | 金額 |
|---|---:|
| 特別大会の固定興行収入 | 7,000万 |

固定興行収入7,000万は出場枠へ分配する。会場費は大会主催側の負担済み経費とし、参加団体の分配金からは控除しない。入賞賞金（優勝1,200万・準優勝500万）は分配後に別途加算する。

### チケット純収益

| 枠 | 比率 | 基準 |
|---|---:|---|
| 均等参加枠 | 30% | 出場可能な参加団体で均等。通常興行を失う週の最低収入を確保 |
| 延べ出場枠 | 70% | 各フォールに出場した選手を団体別に延べ人数で集計 |

### ブランド収入

固定のスポンサー原資は設けない。各団体について、通常興行と同じ次のブランド収入を個別に算出する。

1. 代表3名の人気による興行グッズ収入
2. 団体人気と大会全体の★評価による興行放映メディア収入
3. 4団体合同大会の規模として、上記合計を大会場2興行分（×2）にする

この通常興行基礎額へ、大会結果を割合ボーナスとして加える。

| ボーナス | 加算率 | 基準 |
|---|---:|---|
| 最終順位 | 優勝+100%・準優勝+50%・準決勝敗退+20% | 大会露出と最終結果 |
| 団体フォール勝利 | 1勝ごと+5%、最大+25% | 代表チームの大会中の勝ち抜き実績 |
| MVP | +15% | MVP選手の所属団体のみ |

したがってブランド収入は `通常興行基礎額 × (1 + 最終順位率 + 勝利率 + MVP率)` となる。人気選手を出した団体や団体人気の高い団体は基礎額そのものが高くなり、同じ団体でも大会成績によって大きく増減する。

- 共同興行分配は整数万円で最大剰余法により配り、全出場枠の合計が必ず7,000万になる。
- ブランド収入は共通原資の分配ではないため、大会総収入は出場団体の人気・大会★評価・結果によって毎年変動する。
- bout明細のない旧セーブ結果は、延べ出場枠を参加団体へ均等配分する。
- 自団体の共同興行分配金と賞金は資金・シーズン総収入へ即時反映し、ゲームログと結果画面に内訳を残す。

### 優勝時の2週間想定収支

標準ケースは「準決勝4フォール＋決勝4フォール」「優勝団体の延べ出場8／大会全体24」「代表3名の人気は各60」「団体人気60」「大会★4」「優勝団体が6フォール勝利して勝利ボーナス上限」「MVPも優勝団体から選出」とする。

| 項目 | 金額 |
|---|---:|
| 共同興行・均等枠 | +525万 |
| 共同興行・延べ出場枠 | +1,633万 |
| 通常興行ブランド基礎額（グッズ90＋メディア236） | +326万 |
| 大会結果ボーナス（優勝100%＋勝利25%＋MVP15%=+140%） | +456万 |
| 優勝賞金 | +1,200万 |
| 大会週収入 小計 | **+4,140万** |
| 2週間分の選手給与＋コーチ給与 | **-5,000万** |
| 練習週収入を除く差引 | **-860万** |

したがって2週間収支は `練習週収入 - 860万`。練習週収入が500万なら-360万、800万なら-60万、1,200万なら+340万となる。MVPが他団体ならブランド加算率は125%となり、この想定では大会週収入4,092万・練習週収入を除く差引-908万になる。これはバランス確認用の想定レポートであり、ゲーム内では既存週次決算ですでに給与を控除しているため、別途5,000万を二重に引かない。

## アクセシビリティ

- 専用Overlayは `role="dialog"`、`aria-modal="true"`。
- phase遷移ごとに主操作へフォーカスを移す。
- 画像だけで選手を識別させず、名前・役割・状態を併記する。
- 詳細を開く名前／画像はbutton、または Enter / Space 対応のbutton相当要素にする。
- 色だけで状態を伝えず、`RING / OUT / CONDITION` ラベルを併記する。
