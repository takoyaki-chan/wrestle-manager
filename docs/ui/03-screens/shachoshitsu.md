## 目的

社長として週次の能動的判断（決裁）を下す部屋。決裁書類・FAスカウト・レンタル移籍という
「社長の手が届く3種の打ち手」を1画面に統合し、決裁枠（⚡）と資金の残量を見ながら「今週どの手を打つか」を決める。
契約更新交渉・解雇面談という重い一対一の場面も、同じ部屋（壁+机の舞台）で行われる。

---

## 遷移

- **入ってくる経路**：
  - ナビバー「🏛️ 社長室」。発動条件つき書類（bonus/party/special_treatment/relationship_repair）が未決裁で残る週は、ナビに**金ドットの未読バッジ**が点く（care-visibility-spec §4。開くと消え、翌週再判定）
  - 選手ポップアップの解雇ボタン → `App.startReleaseInterview` が `G._releaseInterviewTarget` を立てて社長室へ遷移し、**解雇面談モード**で開く
  - 契約更新フェーズ（`G.weekPhase === 'contractNegotiation'`）は交渉フローが `renderShachoshitsuNegotiation` でこの画面を直接描画する
- **出ていく経路**：
  - スカウトタブのドラフト速報通知 →「⚖ ドラフトへ」で `screen-scoutEvent`（BGMをtensionに切替）
  - 履歴書の「📋 詳細」「✒️ 契約交渉」、壁のレンタル中カード → 選手ポップアップ（モーダル、画面遷移なし）
  - それ以外はナビバー経由
- **戻る挙動**：戻るボタンは持たない（タブ移動）。解雇面談のみ「やっぱりやめる」で通常モードに復帰

## 構成要素（使用コンポーネント）

- **社長室HUD**（`.shachoshitsu-hud`、sticky）
  - 左: 日付（`--gold`）・資金。右はタブ連動:
    - 決裁: 「決裁枠」ラベル + `⚡n/6` + 印鑑画像列（`hanko.webp`。残量分が立ち、使用済みは倒れて彩度低下。消費時 `hanko-fall` 0.5s）
    - スカウト: 所属 n/上限 ｜ 紹介枠 n名
    - レンタル: レンタル枠 n/n ｜ 残り n枠
  - ※トップバー常設の「決裁 ⚡n/6」（care-visibility §4）と同じ値を映す
- **内部タブ**（`.shachoshitsu-tabs`）: 📋 決裁 / 🔍 スカウト / 🤝 レンタル。ドラフト週はスカウトに📰バッジ、レンタル契約中はドット。タブ状態は `G._shachoshitsuTab`（初期値はドラフト週のみ scout、他は decision）
- **サマリーバー**（`.shachoshitsu-summary`）: タブ別の1行（案件n件 / 所属・FA・紹介枠+四半期入替 / レンタル枠+紹介枠）
- **壁+窓**（`.shachoshitsu-wall`）: `wall-window-{spring|summer|autumn|winter}.webp` を週から判定。レンタルタブのみ右下に**レンタル中ストリップ**（暗色半透明カード、クリックで選手ポップアップ）
- **机**（`.shachoshitsu-desk`）: `desk.webp` 背景。タブ別コンテンツの土台

### 決裁タブ

- **決裁書類カード**（`.shachoshitsu-doc`、196×260、`document-blank.webp`）
  - 内包: カテゴリタグ（選手ケア/育成/広報/人事）、絵文字アイコン、見出し、本文1行、コスト行「金額 / ⚡n」、ホバーツールチップ（詳細/効果/使いどころの3項目。位置補正は `data-col` 1..4）
  - 微回転 ±3°（week+docId の決定論ハッシュ。毎週変わるが開き直しでは不変）
  - 机に並ぶのは `DECISION_DOC_ORDER` の9種: bonus / refresh_leave / special_treatment / party / trainer（外部コーチ招聘状）/ camp / media / relationship_repair / faction_decree。発動条件を満たさない書類は非表示で左上詰め
  - **決裁済みは消さず朱印で残す**（care-rework2 P1-4）: `is-approved`（`document-stamped.webp`）+クリック無効+理由ツールチップ「この書類は今週すでに決裁済みです。週を進めるとまた検討できます」
- **招聘市場 常設ミニパネル**（`.invite-market-panel`、care-rework2 P3-3）
  - 内包: 候補コーチ2〜3名（顔40px円形・名前・格/指導タイプ・得意スタイル。指名リクエストで来た候補は「指名」マーク）、入れ替わりまでの週数、注記「頼めるのは『どんな人を探すか』まで。誰が応じるかは決められない。」
  - **指名リクエスト行**: スタイル or 格の1軸セレクト+「頼む」（⚡0・費用0・顔ぶれの期に1回）。押せない状態は理由をボタンラベルに直書き（「オフシーズンは頼めない」「今期は依頼済み」+依頼内容の説明文）

### スカウトタブ

- **ドラフト速報通知**（開催週・交渉未開始時のみ）: 📰見出し+候補数+「⚖ ドラフトへ」
- **FA履歴書カード**（`.shachoshitsu-resume`、264px幅）
  - 内包: 加入経路/特別枠🎫/評価ティアのタグ列、アッパー画像 **172×258（2:3梯子XL段）**、名前・年齢・OVR（色分け）・スタイル/ロールbadge、5ステータスバー（推定値）、契約金・給与、「📋 詳細」「✒️ 契約交渉」
  - 契約不可は「契約不可」スタンプ+画像グレースケール+後方ソート。⛔ボタンはラッパーspanに `data-tip` で理由（知名度不足の必要人気/枠上限）を出す
  - 3件/ページのページナビ（`G._shachoshitsuScoutPage`）。並びは契約可能→不可、各群OVR降順
- **レンタルタブ**: 費用ソートボタン（安い順/高い順トグル）+ ミニ契約書カード（196px。出所タグ・顔32px・OVR・期数セレクト連動の費用表示・🤝契約ボタン。資金不足はdisabled）

### モードとモーダル（すべて mdl-a 様式 = U3グループA統一のOffice Creamモーダル）

- **契約交渉モード** `renderShachoshitsuNegotiation`: 壁は冬固定（契約更新=シーズン末）。話者ブロック（`.negc-speaker`）がある時だけ壁の高さを拡張し、長台詞でもHUDの裏にはみ出させない
- **解雇面談モード** `renderShachoshitsuReleaseInterview`: `_u3bSideHtml`（theme=dark, size L 150×224、吹き出しは画像の上・セリフのみ）+ 机上に確認カード（実行/取消）
- **決裁モーダル群**（書類クリック `App.onShachoshitsuDocClick` から分岐）:
  - 個人書類 → `showDecisionTargetModal`（候補グリッド。**クールダウン中も消さず「あとn週」グレーで後方に並べる**=care-visibility §4）→ bonus は `showBonusProposalModal`（起案4案・基準額は見せない）、refresh_leave は `showLeaveWeeksModal`（1〜4週）の第2ステップへ
  - trainer → `showInviteCoachModal`（コーチ選択が先）→ `showInviteTargetModal`（対象選手+重点ステ指定+自動延長チェック）
  - 団体書類 → `showDecisionConfirmModal` / ペア → `showDecisionPairModal` / 派閥 → `showFactionDecreeModal`
  - 結果 → `showDecisionResultModal`（トーンマーカー 🌟/💤、団体書類は非表示）
  - 招聘の過程イベント（中間報告/衝突/延長打診/卒業レポート）も同様式のモーダルで届く
- 事前チェック（⚡不足・資金不足）はモーダルを開く前にトーストではじく

## 情報階層（視線誘導の優先順位）

**決裁タブ**:
1. 机の上の書類（今週の案件そのもの）
2. HUDの決裁枠（⚡数値+印鑑の残量 — 打てる手数）
3. 招聘市場パネル（今期の顔ぶれと入れ替わり期限）
4. サマリー・資金

**スカウトタブ**: 1. ドラフト速報（あれば最優先） 2. 履歴書の顔とOVR 3. 契約可否（スタンプ/ボタン） 4. 契約金・給与

**レンタルタブ**: 1. ミニカードの顔と費用 2. HUDの枠残量 3. 壁の契約中ストリップ

## 特有ルール

- **交渉・面談中は通常レンダーを止める**: `renderShachoshitsu` は `weekPhase === 'contractNegotiation'` または `G._releaseInterviewTarget` 中は何もしない（専用レンダラーに譲る）。refreshAll等から呼ばれても交渉画面を上書きしない
- **無反応UIを置かない**: 押せない要素には必ず理由を出す（朱印書類のツールチップ / ⛔ボタンの `data-tip` / 招聘リクエストの理由ラベル）。disabledボタンはマウスイベントが発火しないため、tipはラッパーspanに付けボタンを `pointer-events:none` にする（PCホバー+スマホタップ両対応）
- **書類の微回転は決定論**（乱数を引かない）。朱印の残置は描画専用オプション `getAvailableDocs(G, {includeWeekUsed:true})` で行い、決裁可否判定の母集団は不変
- **モーダルの第2ステップ遷移では `_mdlAClose()` を呼ばない**（closeがポップアップキューを流し、第2ステップを上書きして操作不能になる既知の罠。`_mdlAOpen` の innerHTML 差し替えで遷移する）
- **決裁枠は机外アクションとも共有**: 声かけ（⚡0）・起用の約束（⚡1, bold専用）・特別治療のポップアップ経路（⚡1）・コーチ雇用（⚡2）は選手ポップアップ/コーチ画面から実行されるが、消費はこの画面のHUDに映る
- 履歴書のステータスバーは推定値（`_estimate`）を表示。確定値を漏らさない
- タブ切替・ページ送りで `Audio.play('click')`
