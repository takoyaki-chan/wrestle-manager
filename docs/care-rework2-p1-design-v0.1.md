# care-rework2 P1「気づきの再建」設計 v0.1

- **作成**: 2026-08-20(Fable)。親計画: `docs/care-rework2-plan-v0.1.md` §3 P1
- **ステータス**: ⏳ Keisukeレビュー待ち(通知チャンネルは過去にGlimpse全廃裁定が入った領域のため、実装前に方向の確認を取る)
- **前提**: P0完了済み(丸め修正・市場修理・--care計装)。P1は**表示層のみ**を触る — trust/moraleの数値と力学は一切変えない

## 0. 設計原則(3つ)

1. **数値は見せない**(07-21路線の維持)。サインは「選手の様子」「道場の空気」で語る — 熱量😮‍💨「今は休ませどき」が先例
2. **モーダルを増やさない**(08-13 Glimpse全廃裁定の尊重)。使うチャンネルは既存の世界側 — 道場の立ち姿・ロスターカードのバッジ・ティッカー・社長室の机 — だけ
3. **通知総量を増やさない**。週次ポップアップは現状比+0枚。追加するのは「見に行けば分かる」常設サインと、死んでいた既存チャンネルの復活のみ

## 1. P1-1 士気雰囲気テキストの段階較正(G12)

**問題**: テキスト段階(0-20/21-40/41-60/61-80/81+)と「good」トーン閾値(70)が実効レンジに合っていない。G13是正後の実測はケアなし平均38.3/ケアあり平均61.2で、**L5と「good」は到達率0%、実質2段階しか見えない**。道場が80.7%の週で「特に変わった様子はない」と言うため、士気の罰(成長ゼロ化・回復低下)が毎週発火しているのに平常に見える。

**変更**: `ATMOSPHERE_TEXTS` の段階閾値と、ロッカー空気ログの「good」閾値を実効レンジに再割付する。

| 段階 | 現行閾値 | 新閾値(暫定) | 意図する占有 |
|---|---|---|---|
| L1(危険) | 0-20 | **〜29** | 放置+関係悪化の複合時のみ |
| L2(重い) | 21-40 | **30-41** | ケアなし常態の下半分 — 「なんとなく重い」が日常的に見える |
| L3(平常) | 41-60 | **42-51** | ケアなしの上半分〜ケア初動 |
| L4(良い) | 61-80 | **52-62** | ケアありの常態 — 手入れの成果が見える |
| L5(最高) | 81+ | **63+** | よく手入れされた団体で時々 |
| 「good」トーン | 70+ | **58+** | 同上 |

- **最終値はFableが実装時に較正**: `--care`あり/なし各40季の週次morale分布(パーセンタイル)を実測し、「ケアなしでL4以上が10%未満/ケアありでL4以上が50%超/L5が5〜15%」を満たすよう閾値を確定する
- **不変条件**: moraleの数値・力学は不変(テキスト割付のみ)。L1〜L5の文面自体は変えない(既存文の再利用)

## 2. P1-2 信頼40〜55帯のサイン(盲点20ptの解消)

**問題**: バッジ「💭よそよそしい」は40未満、ボーナス書類の発動条件は60未満 — その間の帯が画面のどこにも出ない。ケアを打つ「きっかけ」の消滅の主因。

**変更**: ロスターカード・道場の選手立ち姿に、**trust 40〜55で低調サイン1個**を追加する。

- 表示: 既存の熱量😮‍💨と同列の状態アイコン(候補: 「🌫」または「💭」の淡色版)。ホバー/タップで様子の一文(例:「最近、目を合わせる回数が減った気がする」— 文言は実装時にOpus起草・数値語なし)
- 閾値は**ヒステリシス付き**(40〜55で点灯、57で消灯)。毎週チラつかせない
- 💭よそよそしい(40未満)は現行のまま(こちらが「濃い」段階)
- **やらないこと**: この帯でのモーダル・週次レポート行・ティッカーは出さない(常設サインのみ)。「様子が気になったら社長室へ」という導線で十分

## 3. P1-3 ロッカー空気ログの復活(G5)+頻度設計

**問題**: `LOCKER_AIR_TEXTS` 14本(「機嫌が明らかに悪い」等)が発火条件の週偶奇自己矛盾(management.js:12891)で一度も出ないデッドコード。

**変更**: 条件を修理して復活させる。ただし**そのまま直すと通知が増える**ので、頻度を設計してから:

- 発火は**非興行週・週1回まで・確率30%**(現行実装の意図を推定復元)。出力先は既存のログ/道場バナー枠(モーダル不可)
- danger帯(trust<30が対象)の文面はケア誘導を含む既存文をそのまま使う
- **不変条件**: 週次モーダル総数に影響しない(バナー/ログのみ)

## 4. P1-4 社長室の導線と⚡の可視化

1. **navバッジ**: 🏛️社長室ボタンに、**発動条件を満たしたケア系書類が1枚以上あるときだけ**ドット(数字なし)を出す。常時発動書類(休暇/招聘/合宿)はカウントしない — 「案件がある」の意味を保つ
2. **⚡残量のグローバル表示**: トップバー(資金・団体人気の並び)に「⚡n/6」を常設。**満タン時は淡く点滅**(次の回復が捨てられるサイン)。ツールチップ「決裁枠 — 4週ごとに2回復(上限6)」
3. **机のカードにCD表示**: 団体書類は「今週は決裁済み」スタンプ(現行のカード消滅をやめる — 消えると「無くなった」ように見える)。個人書類の選手単位CDは対象選択モーダル内で「あと n週」
4. **不変条件**: DPの回復量・上限・消費は一切変えない(表示のみ)

## 5. P1-5 効いた結果の見える化(G11残)

1. **合宿の遅延発現を1トーストに集約**(現行: 全員に効いているのに週1人分しか出ない) — 「合宿の手応えが出てきた(◯名)」形式
2. **最終週の無通知発現を解消**: 招聘・合宿の最終分も同じ集約トーストに乗せる
3. 週次レポートに**ケアの結果1行**(その週に決裁したものの帰結のみ。なければ行なし — 不在データの説明文は出さない原則)
4. **不変条件**: 効果値・発現タイミングは不変(通知の束ね方のみ)

## 6. 実施順と分担

P1-1(較正はFable・実装はOpus) → P1-4(⚡・バッジ) → P1-2(サイン+Opus文言) → P1-3(G5) → P1-5。実装は引き続き**Opus隔離worktree+Fable検算マージ**。文言はOpus起草→Keisuke全文レビュー。UI変更を含むためui-checkスキル自己検査+walkthrough 1本を各マージ後に実施。見積もり: 1.5〜2セッション。
