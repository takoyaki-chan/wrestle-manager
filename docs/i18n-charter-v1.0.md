# 多言語対応憲章 v1.0

このファイルは、このプロジェクトにおける**絶対の約束**である。
CLAUDE.md より優先される。例外は Keisuke の明示的な承認がある場合のみ。
「今回だけ」「後で直す」「プロトタイプだから」は例外の理由にならない。
プロトタイプの直書きが製品に残ることを、我々は前作(レッスルマネージャー)で学んだ。
前作は日本語約25,000行がコードに直書きされ、英語化を断念した。同じ轍は踏まない。

---

## 第1条 コードはテキストを知らない

プレイヤーの目に触れる文字列を、コードに直接書いてはならない。
コードが持ってよいのは**キー(ID)だけ**。実際の文章は言語リソースファイルに住む。

```js
// ❌ 違反
showText(`${w.name}が渾身のラリアットを叩き込んだ!`);

// ✅ 正しい
showText(t('battle.bigmove.lariat', { name: w.name }));
```

```
ja.json  "battle.bigmove.lariat": "{name}が渾身のラリアットを叩き込んだ!"
en.json  "battle.bigmove.lariat": "{name} drives home a crushing lariat!"
```

**対象外**(直書きしてよいもの): console.log・デバッグ出力・コードコメント・
開発者向けエラー。ただし「プレイヤーが見るかもしれない」なら対象。迷ったらキー化する。

## 第2条 文は丸ごと一文で持つ。断片を連結しない

言語によって語順は違う。文の部品を `+` や配列 join で組み立てた瞬間、
その文は翻訳不能になる。**語順の決定権は常に翻訳側(リソースファイル側)にある。**

```js
// ❌ 違反 — 日本語の語順がコードに焼き付いている
t('name') + 'が' + t('move') + 'を決めた'

// ✅ 正しい — 変数入りの完全な文をテンプレートで持つ
t('battle.finish', { name, move })
```

## 第3条 文法分岐はテキスト側に書く

単数/複数、数え方、性別などの言語固有の分岐を if 文で書いてはならない。
ICU MessageFormat 形式でリソースファイル側に書く。

```
en.json  "roster.count": "{n, plural, one {# wrestler} other {# wrestlers}}"
ja.json  "roster.count": "所属{n}名"
```

## 第4条 テーブルの軸は「ゲーム内の意味」だけ

セリフテーブルの分類軸に使ってよいのは、キャラID・アーキタイプ・状況・関係性など
**言語に依存しないゲーム内の概念だけ**。
「だぜ口調」「ですわ口調」のような日本語の言語的特徴を構造に入れてはならない。
口調はあくまで日本語リソースの中身の話であり、キーの構造に漏らさない。

キャラごとの「声」は、言語ごとの**スタイルバイブル**(キャラ別の話し方定義書)で守る。
新キャラのセリフを書き始める前に、スタイルバイブルに日本語の口調定義を1行追加すること。

## 第5条 台帳が正、コードは生成物

テキストの source of truth は台帳(スプレッドシート or 構造化ファイル)である。

```
[キー] [状況メモ(いつ誰が見る文か)] [日本語] [英語] [備考]
```

- ja.json / en.json は台帳からビルドスクリプトで**生成**する。手で直接編集しない
- 「状況メモ」列は必須。翻訳者(人間でもClaudeでも)は文脈がないと正しく訳せない
- 執筆・翻訳・レビューはすべて台帳上で行う

## 第6条 UIは「英語は日本語の1.5〜2倍長い」前提で組む

- テキスト領域は固定幅に文字数ぴったりで設計しない。折り返し・縮小・省略の逃げ道を必ず用意する
- 「決定」が「Confirm」になっても崩れないか、を新規UI作成時の自問に加える
- CJK特有の前提(全角=2文字幅、改行位置自由)に依存したレイアウト計算をしない

## 第7条 画像に文字を焼き込まない

タイトルロゴ以外、プレイヤーが読むテキストはすべてフォント描画で出す。
ボタン画像・バナー・背景に文字を入れたくなったら、テキストレイヤーを重ねる設計にする。

## 第8条 数値・日付・通貨はロケール経由で出す

`Intl.NumberFormat` / `Intl.DateTimeFormat` を使う。
「¥」「万」「第○週」のような単位・序数の直書き連結は第2条違反として扱う。

## 検証の掟 — ルールは仕組みで守る

1. **日本語グレップフック**: リソースファイル・台帳・コメント以外のソースコードに
   日本語文字 `[ぁ-んァ-ヶ一-龠]` が現れたら CI/フックで警告する。
   プロジェクト開始時にこのフック(`.claude/hooks/` + CI)を最初に設置すること。
   **ゲーム本体のコードより先に、この検証を作る。**
2. **キー差分チェック**: ja.json と en.json のキー集合の差分を検出するスクリプトを常備する。
   訳漏れは目視ではなくこのスクリプトで洗う
3. **疑似ローカライズ**: 全テキストを長い偽言語(例: `[!!! Ẅöṛḳ ṭḛẍṭ ﬂöẅ !!!]`)に
   置換して起動するモードを用意し、月1回は起動する。
   ハードコード漏れ(置換されない日本語)とレイアウト崩れがすべて可視化される

## Claude Code への直接の指示

新しいテキストを追加するときの手順は常にこの順番:

1. 台帳にキー・状況メモ・日本語を追加する
2. ビルドスクリプトで ja.json を再生成する
3. コードにはキー参照 `t('...')` だけを書く

この順番を逆にしない。「先にコードに直書きして動かし、後でキー化する」は禁止。
それが25,000行の負債の作られ方だった。

実装中に「ここは直書きの方が早い」と感じたら、それはこの憲章を破る誘惑であり、
作業を止めて Keisuke に相談すること。勝手に例外を作らない。
