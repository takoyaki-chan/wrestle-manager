# Stage A P1 設計 — i18n基盤(言語設定+t()+擬似ロケール+ガード群) v0.1

- 作成: 2026-09-01(Fable)。i18n計画(docs/i18n-english-plan-v0.1.md)P1の実装設計
- 大原則: **日本語版の見た目・挙動は1ピクセルも変えない**。P1はインフラ敷設のみ

## 設計判断(D)

- **D1: t()のキーは日本語原文**。キー名を発明しない(28,700本に命名は非現実的+計画§2層1「キーは日本語のまま維持」と同思想)。
  `t('契約更改')` → lang=ja: **引数をそのまま返す**(辞書を経由しない・ゼロコスト) / en: 辞書引き、無ければ翻訳漏れログ+原文返し(fail-open) / pseudo: `⟦契約更改~~⟧`
- **D2: プレースホルダ形式**: `t('第{n}週', {n:5})` — `{名前}` を置換。P3aで断片連結を完全文テンプレへ直すときの受け皿。ja時もプレースホルダ置換だけは行う(=ja時の返り値は現行の文字列連結結果と完全一致すること)
- **D3: 言語設定はセーブ(G)に入れない**。デバイス設定として localStorage `wm_lang`('ja'|'en'|'pseudo'、既定'ja')。`wm_audio` と同型。Engineは触らない(UI層の関数)
- **D4: 新規ファイル `src/i18n.js`** — WM_I18N(lang管理+t+辞書登録+漏れログ)。他の全スクリプトより先に読み込む(index.htmlのscript順)。**release/manifest.json に必ず追記**
- **D5: JAゴールデンテスト `test/ja-golden.js`** — 固定シードでエンジンを規定シーズン走らせ、生成テキスト(G.news全文・ティッカー・glimpse/セリフ選択結果・週次レポート文字列等、エンジンから決定的に取れるもの)をSHA256でスナップショット。`--update` で基準再生成、通常実行は完全一致検証。基準ファイルは test/fixtures/ja-golden-baseline.json。UIのDOM文字列はP1対象外(走破ハーネスの領分)
- **D6: ラチェットガード `test/i18n-ratchet.js`** — test/i18n-scan.js の計測を流用し、ファイル毎の「生日本語文字列本数」基準値(test/fixtures/i18n-ratchet-baseline.json)と比較。**増えたら失敗**(減るのは可・基準は`--update`で更新)
- **D7: 翻訳漏れログ** — lang≠'ja' で辞書ミス時のみ `console.warn('[i18n-miss]', 原文)` + フライトレコーダーへイベント記録(同一キーはセッション中1回)。ja時は一切ログしない
- **D8: 擬似ロケール** — `⟦` + 原文 + 長さ40%分の `~` + `⟧`。翻訳漏れ(t()を通っていない文字列)の可視化と英語長でのレイアウト溢れ検査を翻訳ゼロの段階で行うため
- **D9: 切替UIは出さない** — プレイヤー向け言語設定UIはStage B(P6)。P1ではdev-tools(開発パネル)に lang 切替だけ追加。プレイヤーの見た目は完全不変
- **D10: パイロット移行1箇所** — 配線が本当に生きている証明として、ui-render.js のトップバー/画面ヘッダ級のラベル5〜10本だけ t() を通す(ja時は同一文字列が返るのでゴールデン・見た目とも不変)

## 不変条件(実装後に必ず検算)

1. **I1**: lang='ja' のとき t(s) === s(プレースホルダ無しの場合。参照同一・辞書非経由)
2. **I2**: `npm test` 全green+`node test/auto-sim.js 40 42` 違反ゼロ(P1適用前後で結果不変)
3. **I3**: JAゴールデン: P1適用**前**に基準を採取し、適用**後**に完全一致すること(この順で検証する)
4. **I4**: release/manifest.json に src/i18n.js を追記済み(package-release の未記載警告が出ない)
5. **I5**: ratchet基準はP1完了時点の実測値で焼く(以後、直書き追加で失敗する状態にして納品)
6. **I6**: index.html のscript読み込み順で i18n.js が全UI/エンジンスクリプトより先

## 実装順(I3の「前後」を守るため)

1. test/ja-golden.js を先に作り、**現行mainの基準を採取**
2. src/i18n.js+index.html配線+manifest追記
3. dev-toolsにlang切替
4. パイロット移行(D10)
5. ja-golden照合(I3)→npm test→auto-sim 40季→ratchet基準焼き(I5)

## 対象外(P1でやらないこと)

- 文字列の大規模抽出(P3a)・英訳(Stage B)・プレイヤー向け設定UI(P6)
- エンジン内文字列・ロジックキーへの変更(層1はP2監査後)
- 既存テストの書き換え(追加のみ)
