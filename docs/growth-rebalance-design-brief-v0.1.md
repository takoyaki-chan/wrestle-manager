# 成長リバランス 設計指示書 v0.1

> 2026-07-26 起案。Keisuke との設計相談で方針が確定したため、**数値設計を Fable に渡すための指示書**として起こす。
> 実測データは `docs/growth-rebalance-baseline-measurement-v0.1.md` が正。

---

## 1. 何が問題か

**両端が同時に壊れている。** 「全体的に伸びすぎ」ではない。

| | 実測 | 設計目標 |
|---|---|---|
| 放置・AI団体 | 5stat中央値 **80.6%** | 91〜92% |
| 追い込み連用 | 訓練可能4statの **98%以上到達が 92.1%** | — |

一律のナーフは**悪手**。全体を下げると放置層がさらに沈み、能動層は追い込みで押し切れる。**差が縮まらないまま全部が下がる**だけ。

### 「簡単すぎ」の正体

カンストの原因は基本カーブではなく、**追い込み×1.8 を毎週積む能動プレイ**。
試合成長・コーチ特殊能力を除いた保守下限でも、訓練可能4stat（PW/SP/TE/ST）が3〜5年でカンストし、エースの65%が OVR100+ に達する。
MNT（精神）は練習で伸びず試合成長のみなので、5stat OVR の天然ブレーキになっている。

### 本当に気になっているのは「数字の高さ」ではない

Keisuke の言葉:

> なんか上限で**5人とか揃ってる**となんか冷める

**問題は「100超えが何人か」ではなく、「全員が同じ天井に張り付いて区別がつかなくなる」こと。**

実測で訓練可能4statの98%以上到達が92.1%＝**ほぼ全員が自分の上限まで行き切っている**。
そうなると選手の差は trainCap の個体差だけになり、その差が小さければ**横並びの怪物が並ぶ**。
さらに上限に達した選手は**もう伸びない**＝キャラクターが「完成品」になり、育てる物語が止まる。

## 2. 確定事項（Keisuke 裁定・2026-07-26）

| # | 決定 |
|---|---|
| 1 | **放置層の 80.6% は動かさない。** 「育てないと伸びない」が正しい姿。基本カーブには手を入れない |
| 2 | **trainCap の上限を下げる案は却下。** UI上「潜在能力」としてプレイヤーに見えている数字なので、黙って削らない |
| 3 | **触るのは「追い込み」。** そこが原因であり、かつ**プレイヤーの選択**だから |
| 4 | **追い込みのコストは「効きの逓減」ではなく「選手の消耗」として払わせる**（主役は消耗の見せ方。逓減は裏で静かに効かせる程度） |
| 5 | **「代償を払えば5人カンストは可能」を構造的に残す。** 何十年も続けたプレイヤーの特権として成立させる。ただし短命・故障だらけの団体になる |

### 用語の注意（重要）

- **UI上の「潜在能力」＝ `trainCap`**（そのプレイでその選手がどこまで上がるかの上限）
- **システム内部の `pot` は非公開。** どの選手が有利かはプレイの中から探ってもらう
- `trainCap` は `Engine.rng.derive(G.rngSeed, 選手ID, 777)` などで生成され、**プレイごとに変わる**（自団体の初期ロスターも含む。確認済み）

## 3. なぜ「消耗」なのか（設計意図）

**逓減だけだと「効率が悪くなる」だけで、プレイヤーは待てば済む。判断が生まれない。**

消耗なら「**この子を今燃やすか、長く使うか**」という選択になる。
5人カンストは「勝ち」ではなく**代償を払った結果**になり、簡単なゲームには見えなくなる。

`CLAUDE.md` の柱との対応:

- **数値はドラマの裏で動く** — 逓減率という数字ではなく、怪我と衰えという**出来事**で示す
- **辛さを避けない** — 燃やした選手が早く終わるのは残酷だが、だから報われたとき効く
- **キャラクターの人生を覗き見る** — 消耗が**本人の様子とセリフに出る**なら、それは数値ではなくドラマ
- **社長は舞台を作る人** — 追い込むかどうかは社長の判断。そこに重みを持たせる

---

## 4. 動かしてはいけない線（不変条件）

> 数値目標だけ渡すと最短経路で目標だけ満たされて設計意図が壊れる。
> 2026-07-20 に3件発生しているため、**目標と不変条件を必ず対で**扱うこと。

1. **放置層の 5stat 中央値 80.6% を下げない**（±2%以内）
2. **`trainCap` の値そのものを下げない**（見えている数字を黙って削らない）
3. **追い込みを一切使わないプレイが不利になりすぎない** — 追い込み無しでも団体は成立し、王座も獲れる
4. **5人カンストを構造的に不可能にしない** — 代償を払えば到達できる道は残す
5. **MNT が練習で伸びない構造は維持**（5stat OVR の天然ブレーキ）
6. **auto-sim が ALL CLEAR を維持**（不変条件違反 0）

## 5. Fable に問いたいこと

### 主題

**追い込みの代償を「選手の消耗」としてどう設計するか。**

### 材料（思いつく機構。これに限らない）

| 機構 | 効き方 | 懸念 |
|---|---|---|
| **怪我率の上昇** | 追い込み週数の累積で上げる | 分かりやすいが運任せで理不尽になりやすい |
| **ピークの前倒し** | 早く伸びるが早く衰える。**上限に届く選手ほど選手寿命が短い**構造になる | 衰退の実装（`Engine.retirement.getDeclinePresentation`）との噛み合わせ |
| **本人の様子・セリフ** | 「最近、朝がつらい」のような。数値が見えなくても伝わる | **これが一番大事**。ただし演出だけでは抑止力にならない |
| **信頼度・士気への影響** | 社長との関係に跳ね返る。社長室と繋がる | 既存の trust 設計との整合 |
| **連用の逓減** | 3週続けたら効きが落ちる、休むと戻る | **主役にしない**。裏で静かに効かせる程度 |

### 具体的に答えてほしいこと

1. **どの機構を主軸に据えるか**、そしてなぜか
2. **その機構の数値**（累積の刻み、効きの大きさ、回復条件）
3. **プレイヤーにどう見せるか** — 数値を出さずに「この子は消耗している」と伝える方法
4. **上記の不変条件を全部満たすことの確認**、および**満たしているかを測る方法**（どの指標を何シーズン回して見るか）

## 6. 検証の手順

1. 変更前の baseline を再取得（`test/growth-baseline-measure.js` / `test/growth-intensive-projection.js`）
2. 実装
3. **同じシード・同じシーズン数**で前後比較。母集団の違い（開始HP・カード構成）を混ぜないこと
4. 不変条件6項目をすべて確認
5. auto-sim ALL CLEAR

**較正の判断が要るときだけ 100年を1本。** グリッド比較は40年で行う（`CLAUDE.md` の auto-sim 運用ルール）。
