# Auto-Sim テストポリシー

## 概要

`test/auto-sim.js` と `test/diag-fa.js` は**エンジン整合性チェック**と**プール診断**のためのツールであり、本番プレイの完全再現ではない。

---

## auto-sim で信用してよいもの

| カテゴリ | 内容 |
|---------|------|
| 不変条件違反 | validateGameState が検出する選手消失・重複・NaN・参照破壊 |
| クラッシュ | 長期実行で例外が出ないこと |
| 無限ループ | MAX_ITER に到達しないこと |
| イベント頻度 | 対抗戦・スカウト・興行の発生率が期待範囲内 |
| 処理順序 | tickWeek パイプラインの依存関係が壊れていないこと |

## auto-sim だけでは信用しないもの

| カテゴリ | 理由 |
|---------|------|
| バランス感覚 | 「強すぎ・弱すぎ」は数値分布だけで判定不可。プレイ体験が必要 |
| 興行カード編成 | ランダムシャッフルで代用しており、因縁カード・人気配置の再現なし |
| 契約交渉 | 確率ベース自動応答。trust管理・ロスター戦略の影響が反映されない |
| ドラフト/スカウト | 簡易AI。資金配分・指名優先度・競合駆け引きの再現なし |
| ケアアクション | 未実行。信頼度管理が本番と乖離する |
| UI導線・演出 | ポップアップ表示順・タイミング依存の挙動は検証対象外 |
| orgPop/funds の絶対値 | 上記の簡略判断が蓄積するため、本番の経済バランスとは乖離する |

---

## 修正フロー

```
1. 本番で症状を確認する（セーブデータ or 実プレイ）
2. auto-sim で再現範囲を特定する（シード固定で再現可能か）
3. 修正を実装する
4. auto-sim で不変条件違反がないことを確認する
5. 本番セーブ or 実プレイで症状が解消されたことを確認する
```

**auto-sim の ALL CLEAR は「エンジンが壊れていない」の意味であり、「バランスが適切」の意味ではない。**

---

## バグ報告時の確認手順

### 最小確認テンプレート

```
## 報告
- 対象: (例: FA膨張、ドラフト候補不足)
- 発見経路: auto-sim / 実プレイ / セーブデータ

## auto-sim 上の症状
- シード: (例: 42)
- シーズン: (例: S15)
- 観測値: (例: FA=38, dormant=2)
- 期待値: (例: FA=10-20, dormant=15-25)

## 本番再現確認
- [ ] 実プレイ or セーブデータで症状を再現した
- 再現手順: (具体的な操作)
- 再現結果: (スクリーンショット or 数値)

## 判定
- auto-sim特有の誤検知 / 本番でも再現する実バグ / 未確認
```

---

## diag-fa.js について

- FA / dormantPool / retiredIds のサイズ推移を観測する診断ツール
- auto-sim と同じ簡略判断を含むため、数値の絶対値は本番と一致しない
- 「増加傾向 / 減少傾向 / 急変」のパターン検出に使い、閾値判定には使わない
- 異常を見つけたら必ず本番セーブで再確認すること
