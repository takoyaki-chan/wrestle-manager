# MQ再設計 P3b追補: リング内効果 較正計測 v0.1

作成日: 2026-07-24
測定スクリプト: `test/mq-ring-calibration.js`(新規・src/未変更)
実行コマンド: `node test/mq-ring-calibration.js 4000`

## 背景

P3b(コミット `9cb70da`)で因縁/タイトルの MQ ボーナスをリング内効果(counterPt / escape)に置き換えたところ、
100年実測で「因縁戦の OV 優位側の勝率が -8.93pt」という不変条件(±2pt)超過が発生した。escape(脱出率)ブーストが
「フォール/ギブアップでフィニッシュされかけた側」にのみ発火するため、対称付与でも劣勢側(≒ OV 劣位側)に有利へ
偏ることが疑われている。本ドキュメントは係数再設計の判断材料として、単一の対戦構成を固定し、リング内効果の
強さだけを段階的に変えたときの反応をグリッドで計測した生データを示す。**考察・推奨値の決定は本ドキュメントの
スコープ外(設計側で別途判断)。**

## 前提・固定条件

- `src/match-engine.js` の `simulateMatch(charL, charR, rng, matchTier, opts)` を直接呼び出し、`opts.rivalryRing`
  ( `{ counterPt, escape }` )と `opts.titleMatch`(boolean)を条件ごとに切り替えて測定した。
- キャラクターは `pw=sp=te=st=mn` の均一ステータス(`Engine.util.ov = round(avg of 5 stats)` なので OV と一致)。
  性格・アーキタイプ・特性はすべて `normal` / なしで統一(トレイト由来のノイズを排除)。
- **tier の扱い**: `src/management.js` L11706 `simulateMatch(charL, charR, matchRng, m.isTitle ? 2 : 1, ...)` の通り、
  実ゲームでは `isTitle=true` の試合のみ `matchTier=2`(BIGMATCH_ENG、ターン数上限・ペーシング閾値・被ダメ人気補正
  `×2.0` などが異なる)で走り、因縁(非タイトル)戦は常に `matchTier=1`。この非対称を再現するため、
  - `counterのみ` / `escape段階(4値)` / `escapeのみ` の6条件 → **tier=1**、baseline(tier1)と比較
  - `title相当`の2条件 → **tier=2**、baseline_tier2(tier2固有のbaseline)と比較
  なお `RIVALRY_RING_TABLE`(`src/management.js` L2118)の実際の値は tier1〜4 で `counterPt 2〜5 / escape 0.05〜0.15`。
  本計測の「escape段階」は counterPt を+4に固定し escape のみ 0.03〜0.15 で振った探索用グリッドであり、
  既存テーブルの値そのものではない。
- 同一対戦構成内では、全条件で同じ seed 列(`seedBase + i`, i=0..N-1)を使い回すペア比較(`test/mq-trait-probe.js`
  の作法に準拠)。`Engine.rng.create(seed)` のみ使用、`Math.random()` / `Date.now()` は不使用。
- N = 4000 seed / セル。全体で 3構成 × 10条件 × 4000 = 120,000 試合を実行(所要時間: 数秒)。
- 「OV上位側」は常に `left`(全構成で `leftOv > rightOv` に設定)。勝率は `winner === 'left'` の比率。
- 「平均キックアウト回数」は `opts.recordFrames:true` で得た最終フレームの `kickoutCountL + kickoutCountR` の平均
  (試合1本あたりの合計フィニッシュ耐え回数)。
- 「超過レイヤー発火率」は返り値 `transcend.fired`(ドラマ減点0・ペーシング減点0・決着減点≤1 を満たし、かつ
  `overflow > 0` のケース)の発生率。
- 「平均ターン数」は返り値 `turns`(=matchTurns)の平均。
