## 執筆方針（本ファイル全体で厳守した規範）

- 格言・箴言・気取った締めの一文は禁止。事実の記述で締める（2026-07-16 確定のナレーション方針）
- ベルト／王座に「世界」を冠しない

## 実装メモ（P5/P6 担当への申し送り）

- 5 type とも既存 `NEWS_HEADLINE_TEMPLATES` の `{ headline, body }` 構造にそのまま追加できる形で書いた（変数名は proposal §5.4 の指示に準拠。§5 mqTagRecord は 2026-07-24 の記録分離決定に伴う追加）。
- `{result}`（勝敗）の差し込み語は**「白星」「黒星」で確定**（2026-07-24承認）。「デビュー戦は白星に終わった」「結果は黒星」のいずれの文型でも成立する。
- `fatedRivals` の同一団体ケース（`{orgName}` == `{orgName2}`）は、**実装側で `{orgName2}` を「同門」に置換する**（2026-07-24承認）。展開例:「{orgName}の{name}と同門の{name2}」。別団体時はそのまま団体名を展開する。headline には orgName 系変数が無いため置換は body のみ。
- 号外リード文言はモーダル1行チラ見せ用（§5.3）。変数を含まない汎用案と、含む具体案を各 type に1本ずつ用意した。
- **`mqTagRecord` は一面ぶち抜き大記事レイアウト**（上下ぶち抜き＋勝者2人写真）を前提に執筆した。優勝ペア2人の写真枠は **`springTagResult` の優勝ペア写真枠を流用**する想定。他4 type（単数写真〜写真なし）とは別レイアウトになる点に注意。
- `mqTagRecord` の各 body 内の `｜` は**段落区切り**（前半＝記録更新の事実／後半＝勝者組2人への称賛）。ぶち抜きレイアウトの2段組を想定した記法で、実装時は前後段落として展開する（1行に流し込まない）。称賛段落は試合内の具体事実（技名・場面）を含まず、「二人の関係と積み上げ」「この夜の完成度」の水準に留めた。
- **変数の充填規則（2026-07-24 フェーブルレビューで追加）**: `{nameA1}` には**勝者組のOVR上位（エース側）**、`{nameA2}` に相方を入れる（チームスロット順のまま入れない）。A案「前に出て組を引っ張る{nameA1}／崩れた流れを立て直す{nameA2}」・C案「局面を作る{nameA1}／背中を信じて応える{nameA2}」の役割記述が実態と一致するための規則。B案は対称記述のため順序不問。
