# レッスルマネージャー 音響全面再設計マスタープラン

作成日: 2026-07-22  
対象: BGM、短尺ジングル、UI効果音、経営・イベント効果音、試合効果音、歓声・環境音、再生制御

## 1. この計画の目的

現在ある音を単純に差し替えるのではなく、ゲーム全体を通して次の3点を実現する。

1. 画面を見なくても「何が起きたか」「操作が成功したか」「危険な状態か」が分かる。
2. 経営ゲームとしての落ち着きと、プロレス興行としての熱気・緊張感を両立する。
3. ファミコン風の統一感を保ちながら、重要度に応じて音の格を明確に変える。

基本方針は、すべての操作に音を付けることではない。意味のある変化には音を付け、連続操作や読み物では静けさを残す。

## 2. 現状監査の要点

### 現在の強み

- 試合中は、打撃、投げ、関節、空中技、丸め込み、ミス、カウンター、大技、キックアウト、脱出、ゴングなど、主要な技カテゴリがすでに用意されている。
- BGM、SEそれぞれに音量・ミュート設定があり、Web Audioによる基礎的な再生機構も存在する。
- 王座戦、派閥イベント、ドラフト、表彰、引退、エンディングなど、重要演出の一部には専用音または専用BGMがある。

### 現在の問題

- 管理画面の多くが `click`、`error`、`event`、`coin` に集中し、意味の違う操作が同じ音に聞こえる。
- タイトル、興行準備、選手配置、会場変更、週送り、月末決算など、ゲームの節目に専用の聴覚フィードバックが不足している。
- 画面移動のたびに同じクリック音が鳴る一方、カード完成や王座戦指定など重要な成功操作が無音の箇所がある。
- 試合SEは種類があるが、軽量級・重量級、技の強弱、観客規模による差が弱い。
- 派閥・人間関係イベントは、内容の異なる場面で同じ緊張BGMや同じイベント音を共有しすぎている。
- 音声ファイルには未使用・旧版候補が多数あり、採用版・予備版・廃止候補の区別がない。
- 短い画面移動ごとにBGMを変えると騒がしくなるため、BGMの担当範囲と切替条件を整理する必要がある。

## 3. 音響の基本設計

### 3.1 音の6階層

| 階層 | 役割 | 例 |
|---|---|---|
| BGM | その場の感情と時間の流れを作る | 経営、試合前、危機、季節興行、エンディング |
| 環境音 | 場所の大きさと空気を伝える | 事務所、体育館、アリーナ、ドーム、記者会見 |
| ジングル | 結果や節目を短く確定する | 勝利、王座移動、番狂わせ、殿堂入り、ゲームオーバー |
| 演出SE | 画面演出や物語上の変化を強調する | 対戦カード表示、裏切り、復帰、契約成立 |
| 操作SE | 入力が受理されたことを伝える | 決定、取消、切替、配置、保存 |
| 試合SE | 技・リング・観客反応を伝える | 打撃、投げ、ロープ、カウント、歓声 |

同時に鳴る場合の優先順位は、重要ジングル > ゴング・決着音 > 大技SE > 通常SE > 環境音 > BGM とする。

### 3.2 統一する音色

- 基本音源はファミコン風: 2本の矩形波、三角波ベース、ノイズ、短いDPCM風サンプル。
- BGMは30～60秒の継ぎ目のないループを基本とする。
- ジングルは3～15秒。結論が1回で分かり、余韻が長すぎないものにする。
- UI音は30～300msを中心にし、メロディを持たせすぎない。
- エンディングだけは「壮大なオーケストラの終幕を、限られたファミコン音源で表現したもの」とし、ポップスにはしない。
- 歌、掛け声、ナレーション、言語として聞こえる声は原則使わない。試合の声を使う場合も、短い非言語グラントのみとする。

### 3.3 音を鳴らさないルール

- マウスホバーには原則として音を付けない。タイトルや大きなカードなど、対象を限定する。
- 数字が1ずつ増減するたびには鳴らさない。決算確定、危険域突入、目標達成など状態変化時だけ鳴らす。
- 一覧のスクロール、ログの閲覧、ヘルプ本文の展開には強い音を使わない。
- 同じ通知が連続した場合は250～500msの再生制限を設ける。
- モーダルを閉じただけでは毎回派手な取消音を鳴らさない。
- 追悼、引退直後、重大な敗北では、音を足すより一瞬の無音を演出として使う。

## 4. 全ゲームフロー別の音響計画

### 4.1 タイトル・開始・ロード

| 場面 | 必要な音 | 長さ | 優先度 |
|---|---|---:|---|
| タイトル画面 | 団体旗揚げを予感させる短いタイトルBGM | 30～45秒ループ | P0 |
| PRESS START相当 | 開始確定ブリップ | 0.5～1秒 | P0 |
| 新規ゲーム開始 | 旗揚げファンファーレ | 5～8秒 | P1 |
| 団体名・難易度決定 | 決定音の上位版 | 0.5～1秒 | P1 |
| ロード成功 | 復帰チャイム | 1～2秒 | P0 |
| ロード失敗 | 低い警告音 | 0.5～1秒 | P0 |

タイトルから経営画面へ入った時だけ、タイトルBGMから通常経営BGMへクロスフェードする。

### 4.2 共通UI・システム

最小限の共通ファミリーを作り、画面ごとに別のクリック音を増やさない。

| Cue ID | 用途 | 備考 |
|---|---|---|
| `ui_confirm` | 決定・実行 | 明るい短音 |
| `ui_cancel` | 戻る・解除 | 下降する短音 |
| `ui_tab` | 主要タブ移動 | 弱いページ切替音 |
| `ui_toggle_on` / `ui_toggle_off` | ON/OFF | 音高を対にする |
| `ui_modal_open` / `ui_modal_close` | 重要モーダル | 通常ポップアップは弱くする |
| `ui_info` | 通常通知 | 現在のnotify相当 |
| `ui_warning` | 注意 | 資金・負傷・契約期限など |
| `ui_error_soft` | 入力不足・選択不可 | 不快すぎない音 |
| `ui_error_hard` | 保存失敗・データ異常 | 明確な低音 |
| `ui_save` / `ui_load` | 保存・読込完了 | 別の音にする |
| `ui_page` | 新聞・年代記のページ | 紙音またはノイズ音 |

現在の汎用 `click` と `error` は一度に廃止せず、Cue IDへの置換を段階的に進める。

### 4.7 興行・試合前画面

#### 通常試合前

- 軽量級: 速く鋭い矩形波と細かいノイズ。高揚感と競技感。
- 重量級: 低い三角波、重いパルス、遅めの圧力。
- 因縁戦: 不協和と短い上昇反復。怒りと決着の予感。
- 王座戦: 儀式的なファンファーレ断片と戦闘リズム。

#### 春夏秋冬の特別興行

各季節2曲、合計8曲。いずれも一つ一つの試合前待機画面で使う。試合中BGMより熱量を一段下げ、82～104 BPM程度、低～中密度のリズム、未解決の和声、休符で「ゴングを待つ緊張」を作る。その背後に、通常興行とは違う季節祭典の華やぎ、儀式性、観客の期待を薄く置く。高速ドラムや陽気なカーニバルにはせず、季節差はテンポより音色、間、和声、祭典装飾で表す。

- 春A: 新しい挑戦。開幕祭典の明るい装飾と抑制した期待
- 春B: 若い対抗心。旗揚げ日の華やぎを背負った未解決感
- 夏A: 昼の熱気。祭囃子的な刻みの奥で増す圧迫感
- 夏B: 蒸し暑い祭典の夜。灯りと長い間を使う王座戦前
- 秋A: 実りの祭典。熟練者の読み合いと観客の期待
- 秋B: 大興行の格式。誇りと古い因縁にかかる低い圧力
- 冬A: 静かな冬祭典。遠い鐘、広い間、冷たい殺気
- 冬B: 年末大祭典。凱旋断片を抑え込んだ最終決戦直前

#### プレゼンテーションSE

- PPV／TV放送の短い局名風アイデント
- 対戦カード表示スラム
- VS表示
- 王者ベルト表示
- 選手名表示
- 試合開始直前の観客ビルド
- ゴング開始・終了

### 4.8 試合中

既存の技カテゴリは維持し、まず不足するバリエーションと観客反応を追加する。

#### 技・リングSE

- 軽打撃 3種、強打撃 3種

- グラウンド攻撃 2～3種
- 丸め込み開始、押さえ込み、返し
- ロープ反動、コーナー衝突、マット着地
- 空振り、カウンター、受け流し
- 大技チャージ、フィニッシャー衝撃

#### 観客反応

- 小さなどよめき

| 裏切り | 一瞬の無音から鋭い破断音 |
| 復帰 | 懐かしいモチーフの再登場 |
| 派閥結成 | 複数音が一つの和音に集まる |
| 派閥加入・離脱 | 接続／切断の対になる音 |
| 派閥分裂・解散 | 和音が崩れる下降音 |

| 挑戦受諾 | 対決確定ゴング |

文章イベントは、表示時に感情を先取りしすぎない。結果が明らかになる瞬間に音を置く。

### 4.11 ランキング・データベース・新聞・年代記

- ランキング: 順位更新時だけ上昇／下降音。閲覧だけでは鳴らさない。
- データベース: 検索・絞り込みは共通UI音。選手カード表示は軽いカード音。
- 新聞: 紙面を開く音、ページ音、重大スクープの見出しスティンガー。
- 年代記: 章を開く音、時代区切りの短いモチーフ、殿堂入りジングル。
- ログ: フィルター変更のみ弱いUI音。行ごとの音は付けない。
- ヘルプ: 見出し展開は非常に弱い音か無音。

これらの画面ごとにBGMを切り替えず、通常経営BGMを継続する。年代記、殿堂入り、追悼など大きな演出だけ例外とする。

### 4.12 シーズン終了・表彰・引退・エンディング

- シーズン終了: 一年を締める30～45秒ループまたは20秒程度の演出曲。
- 年間表彰: 賞発表用の短い上昇、受賞ファンファーレ。
- 殿堂入り: 威厳ある8～12秒ジングル。
- 引退: 選手の時間を感じる静かな8～15秒ジングル。
- 世代交代: 希望を残す8～12秒ジングル。
- ゲームオーバー: 短く明確な終止。長い曲にしない。
- エンディング: 45～60秒のシームレスループ。壮大なオーケストラ終幕の構成をファミコン音源へ圧縮し、序奏、主題、凱旋的な高まり、穏やかな帰結を持たせる。ポップ、歌、現代的なドラム、長い4分構成は避ける。

## 5. BGMの状態設計

BGMは画面単位ではなく、ゲーム状態単位で管理する。

| 状態 | 使用BGM群 |
|---|---|
| `TITLE` | タイトル |
| `MANAGEMENT_NORMAL` | 通常経営、メニュー、一覧、データ画面 |
| `MANAGEMENT_GOOD` | 好調、成長、上昇期 |
| `MANAGEMENT_FINANCE_TROUBLE` | 資金難 |
| `MANAGEMENT_UNREST` | 不穏、派閥対立、契約危機 |
| `MANAGEMENT_CRISIS` | 負傷連鎖、団体存続危機 |
| `SHOW_PREP` | 興行準備、遠い会場音を併用 |
| `PREMATCH_*` | 軽量級、重量級、因縁、王座、季節8曲など |
| `BATTLE` | 試合本編 |
| `RESULT` | 興行・試合結果。ジングル優先 |
| `CEREMONY` | 表彰、殿堂、引退、追悼 |
| `ENDING` | エンディング |

短時間で状態が往復してもBGMを頭から再生し直さない。最低再生時間を設け、モーダルでは原則として元BGMを継続する。緊張イベントは短いスティンガーで済ませ、長い場面だけ専用BGMへ移る。

## 6. 最終的な制作量の目安

既存44曲計画を土台に、音響全体では次を目標とする。

| 区分 | 最終目安 | 備考 |
|---|---:|---|
| BGMループ | 35～45曲 | 既存計画を整理・統合 |
| ジングル／スティンガー | 18～24曲 | 3～15秒 |
| 共通UI・システムSE | 12～16種 | 派生音を含む |
| 経営・契約・物語SE | 20～28種 | 状態変化中心 |
| 興行準備・放送演出SE | 14～20種 | カード作成と試合前 |
| 試合技SE | 30～40ファイル | 同一Cueのランダム差分を含む |
| 観客・環境音 | 12～16ファイル | 会場規模と反応 |

全候補を一度に作るのではなく、最終採用品は約140～185ファイルを上限とする。同じ意味の音はファミリー化し、コード側の音高・音量差で派生を作る。

## 7. 優先順位

### P0: まずゲーム全体の手触りを直す

- 共通UIの決定、取消、警告、軽いエラー、重いエラー、保存、読込
- タイトルBGMと開始音
- 週送り、新週、月末決算、資金危機、負傷、復帰
- 興行準備の選手配置、解除、入替、王座戦指定、カード完成、興行開始
- 会場規模別の観客ベース4種
- 試合SEの強弱差、ニアフォール、決着、王座移動
- 通常勝利、敗北、番狂わせ、王座移動のジングル
- BGM状態管理と音の同時再生制御

### P1: 物語と経営判断を豊かにする

- コーチ、スカウト、契約、ドラフト、移籍の専用音
- 因縁、絆、派閥、裏切り、復帰、引退のスティンガー
- PPV／TV演出、対戦カード、VS、ベルト表示
- 季節興行8曲、通常試合前4曲
- トーナメント、ジュニア大会、最終戦、PPV用BGM・ジングル
- 新聞、年代記、殿堂入り、表彰

### P2: 長期運用向けの差分

- 技SEの追加ランダム差分
- 海外遠征、ドラフト特別版、TV放送、レジェンド戦
- 会場別・時代別の歓声差分
- 低頻度イベントの専用スティンガー
- 別ゲームへ転用しやすい汎用UIファミリーの整理

## 8. 1か月制作スケジュール

### 第1週: 棚卸しと音の文法を確定

- 現在の全ファイルを「採用」「要比較」「旧版」「未使用」に分類する。
- 音量基準とファミコン音色を決める。
- 共通UI 8～12種とタイトル、経営、試合前の基準曲を作り、ゲーム内で試聴する。
- 生成物は候補番号を付け、採用前に上書きしない。

### 第2週: 興行準備と試合を完成

- カード編成SE一式を作る。
- 会場規模別の環境音と観客反応を作る。
- 既存試合SEを評価し、軽量・重量・大技の差分を追加する。
- 通常試合前4曲と季節興行8曲を優先生成する。

### 第3週: 経営・契約・物語を完成

- 週送り、決算、資金、成長、負傷を整備する。
- スカウト、契約、ドラフト、移籍を一つの音体系にする。
- 絆、因縁、派閥、裏切り、復帰、引退の演出音を作る。
- トーナメント、ジュニア大会、PPVなどの不足BGMを埋める。

### 第4週: 結果・歴史・終幕と総合調整

- 勝敗、番狂わせ、王座移動、優勝、殿堂入りなどのジングルを仕上げる。
- エンディングを45～60秒ループとして作り直す。
- 音量、ループ継ぎ目、同時発音、スマートフォン再生を確認する。
- 未採用候補を本番フォルダから分離し、音響台帳を完成させる。

## 9. 制作手段の使い分け

- BGM: 音楽生成サービスで作成し、ループ編集と音量調整を行う。
- 5～15秒のジングル: 短尺で直接作れない場合は、20～40秒の演出曲から最も良い終止部分を切り出す。
- UI・ファミコンSE: コード合成、チップチューンSEツール、効果音生成を使い分ける。UI音は生成AIだけに頼らない。
- 打撃・投げ・観客: 複数候補を作り、ゲーム内で音量と重なりを評価する。
- 切り出しは非破壊編集で行い、元ファイルを保存する。

生成回数は「完成ファイル数」ではなく「候補数」で考える。BGMは1曲あたり4～6候補、重要ジングルは3～5候補、SEは2～4候補を基準にし、契約前にサービス画面で実際のクレジット消費を確認する。

### 再生システムで追加する機能

- Cue IDから複数ファイル候補を引くレジストリ
- ランダム差分と±2～3%程度の軽いピッチ差
- カテゴリ別音量: BGM、UI、試合SE、観客・環境音、ジングル

- 短いSEの先読み、BGMと環境音の遅延読み込み
- モーダル終了時のタイマー・ループ停止
- 画面ではなくゲーム状態からBGMを決めるリゾルバ
- 開発用のCue試聴・音量確認画面

## 11. 音量・書き出し基準

- マスターはWAVで保管し、配信用はOGGを第一候補とする。
- シームレスループはMP3のエンコーダ遅延を避け、OGGで実機確認する。
- UI・技SEは原則モノラル、BGMと広い環境音はステレオを許可する。
- 全音を単体で最大音量にせず、ゴング、決着、大技にヘッドルームを残す。
- 小型スピーカー、イヤホン、スマートフォンで確認する。
- 非言語グラントを入れる場合は個別にOFFにできる設計を推奨する。

## 12. 実装順序

1. Cue ID台帳と音声レジストリを作る。
2. 現在の汎用 `click/error/event/coin` の呼び出しを場面ごとに分類する。
3. P0の操作SEと興行準備SEを接続する。
4. BGMを状態管理へ移し、画面遷移の再スタートを防ぐ。
5. 観客環境音と試合中の反応レイヤーを追加する。
6. P0ジングルを接続し、重複再生の優先順位を実装する。
7. P1の契約・物語・季節興行へ広げる。
8. 音量設定をカテゴリ別に拡張し、全体QAを行う。

## 13. 受け入れ基準

- 決定、取消、軽いエラー、重大エラーを聞き分けられる。
- 興行準備で、配置成功・解除・王座戦指定・カード完成が音だけでも分かる。
- 週送り、月末、資金危機、負傷、復帰が同じ通知音になっていない。
- 軽量級と重量級の試合が、打撃・投げ・試合前曲から聞き分けられる。
- 小会場とPPV級会場の観客規模が明確に違う。
- 勝利、番狂わせ、王座移動、優勝が別の格として聞こえる。
- 重要ジングルが重複せず、BGMが適切に下がる。
- 30～60秒BGMと環境音に継ぎ目がない。
- 同じ画面を高速で往復しても音が連打されない。
- ミュート、カテゴリ音量、ロード直後、ブラウザの自動再生制限下でも破綻しない。
- 未使用・旧版ファイルが本番レジストリへ混入しない。
