## 1. ゲーム概要

- **ジャンル**: 女子プロレス団体経営シミュレーション（ブラウザHTML+JS）
- **目標**: 弱小団体からS級団体へ成長させる。経営サバイバル達成が初期目標。
- **シーズン制**: 48週 × Nシーズン（終了なし）
- **UI**: シングルページ（iframe観戦を除く）。フレームワーク不使用。
- **データ**: キャラ98名、コーチ8名、技160種

## 3. ゲームループ（週次フロー）

### 3.1 シーズン構造
- **通常シーズン**: 48週（第1〜48週）
  - 春: Week 1〜12 / 夏: Week 13〜24 / 秋: Week 25〜36 / 冬: Week 37〜48
- **興行週**: 偶数週（Week 2,4,6,…48）= 24回/シーズン
  - Week 48 = PPV（年間最大興行）
  - 特別興行: 月末（Week 12/24/36）
  - タイトルマッチ: クォーター末（Week 12/24/36/48）のみ
- **オフシーズン**: Week 49〜52相当（offWeek 1〜4）
  - offWeek 1: シーズン末処理・引退・年末表彰式
  - offWeek 2: スカウト
  - offWeek 3: ドラフト
  - offWeek 4: 移籍ウィンドウ → 新シーズン開始

### 3.2 週次フェーズ（weekPhase）
```
null/manage → [processWeek] → settled (月末のみ停止) → [advanceWeek] → manage (次週)
                                 ↑ 非月末週は自動スキップ（_tryAutoAdvance）
```

| weekPhase | 説明 |
|-----------|------|
| `manage` | スケジュール設定・興行準備週 |
| `settled` | 月次レポート表示（week%4===0のみ） |
| `draft` | 初期ドラフト（ゲーム開始時のみ） |
| `transfer` | 移籍ウィンドウ（オフシーズン） |
| `event` | 対抗戦/頂上決戦 |
| `scoutEvent` | スカウトイベント |

### 3.3 月次自動スキップ
非月末週（week%4≠0）は processWeek 後に自動的に advanceWeek を実行し、manage画面に戻る。月末週のみ settled フェーズで停止し、月次レポートを表示する。

## 4. 経済システム

### 4.1 資金源
| 収入源 | 計算式 / 値 |
|-------|------------|
| チケット収入 | 集客数 × baseTicketPrice（会場依存） |
| グッズ収入 | 集客数 × 0.15万 |
| スポンサー収入 | orgPop依存（人気20〜で発生） |
| 放映権収入 | orgPop依存 |
| 育成補助金 | orgPop 0-19: 80万/週, 20-29: 65万/週, 30-39: 20万/週（40達成で廃止）※B-3 |

### 4.2 支出
| 支出源 | 計算式 / 値 |
|-------|------------|
| 選手給料 | OVR帯別テーブル（~10〜~450万/週） |
| コーチ給料 | コーチ別固定値 |
| 施設維持費 | 施設Lvに応じた固定費 |
| 治療費 | 軽傷20万, 中傷80万, 重傷200万 |
| 引き留め費 | 移籍交渉時 |

### 4.3 給料テーブル（OVR帯別）
| OVR帯 | 給料/週（万） |
|:-----:|:-----------:|
| ~49 | 10 |
| 50-59 | 25 |
| 60-69 | 50 |
| 70-79 | 100 |
| 80-89 | 180 |
| 90+ | 300〜450 |

### 4.4 集客計算
```
集客数 = baseAttendance(10000×orgPop) × heatMult × (1 + bonus_sum)
```
- heatMult: Cold×0.7, Cool×0.85, Warm×1.0 (旧Warm×1.1以上は現在廃止済み)
  - 実装値: Warm×1.1, Hot×1.2, On Fire×1.3
- bonus_sum: title/champ/charismaなどの加算ボーナス（上限2.0倍キャップ）

### 4.5 Heat（注目度）
- Cold / Cool / Warm / Hot / On Fire の5段階
- 興行での高MQ → Heat上昇。興行なし・低MQ → Heat低下
- 興行週に軽減衰 -0.3

## 6. 育成システム

### 6.1 trainCap
```
trainCap = factor × Potential   (factor: 0.50〜0.80)
```
選手は trainCap に向かって成長する。trainCap を超えたステータスは成長しない。

### 6.2 週間成長（練習）
```
成長量 = calcGrowth(stat) × 0.4 × penMult
```
- penMult: growthPenalty.multiplier（通常1.0, 軽傷0.7, 中傷0.4, 重傷0.15）
- `intensive` 設定時は成長ボーナスあり（体調消耗増）

### 6.3 試合成長
```
matchGrowthBase = 1.5 + opponentBonus + closeBonus(MQ≥65) + resultBonus
```
1〜2統計に分散。growthPenaltyが適用される。

### 6.4 growthPenalty
| 怪我重症度 | 残り週数 | 成長倍率 |
|:--------:|:-------:|:-------:|
| 軽傷 | 6週 | ×0.7 |
| 中傷 | 14週 | ×0.4 |
| 重傷 | 24週 | ×0.15 |
上書き: より重い方が優先。怪我回復後も残週数カウントダウン継続。

### 6.5 成長イベント（v1.8）
| イベント | 効果 | 発生条件 |
|---------|------|---------|
| ブレークスルー | OVR+1〜3 即時付与 | ランダム発生（低確率） |
| 絶好調（hotStreak） | 成長×1.5 | ランダム発生 |
| スランプ | 成長×0.5 | ランダム発生・長期不振後など |
| モチベ喪失 | 成長×0.3、24週超で自主引退 | スランプ長期継続など |

## 7. バトルエンジン・MQ

### 7.1 MQスコア構造
```
MQ = Base(10-35) + Drama(0-35) + Pacing(-10/+10) + Finish(-5/+15) + Bonus(0-30)
```
- Bonus: 名勝負製造機(+5), 逆転(+5), スタイル相性など
- 試合消耗: 20 + 被ダメ率×15 + ターン数×0.5

### 7.3 MQ外部ボーナスキャップ（Pass2）
- 外部ボーナス合計 **+15 上限**（`MQ_EXTERNAL_CAP = 15`）
- 因縁ボーナス: +3/+5/+8（rivalLevel 1/2/3）
- タイトルマッチ: +5
- コーチ効果: +2
- 超満員: +3 / 大入り: +2
- 会場ボーナス: 0〜+2（会場規模依存）
- ファン期待度一致: +5

### 7.4 タイトルマッチ格差ペナルティ（Pass2キャップ後に別途減算）
| OVR差（チャンプ − 挑戦者） | MQ減算 |
|:------------------------:|:------:|
| >10 | −3 |
| >20 | −6 |

### 7.2 コンディション補正（MQ）
| コンディション | MQ補正 |
|:------------:|:------:|
| 80〜100 | なし |
| 60〜79 | なし |
| 40〜59 | −10 |
| 20〜39 | −20 |
| 0〜19 | −30 |

## 9. 衰退・引退システム

### 9.1 wear蓄積
- **開始年齢**: 28 + durability 歳（durability: 正規分布 μ=0, σ=2）
- **蓄積量/シーズン**: 基本5 + 超過年数×2 + seasonInjuries×2
- **wear帯と効果**:
  | wear | 状態 | 効果 |
  |:---:|:----:|------|
  | 0〜19 | 正常 | なし |
  | 20〜39 | 衰え | 成長量×0.9程度 |
  | 40〜59 | 衰退期 | 成長減少+引退確率20%/シーズン |
  | 60〜79 | 末期 | 引退確率50%/シーズン |
  | 80+ | 確定 | 必然引退 |

### 9.2 引退ルート
| ルート | 説明 |
|-------|------|
| wear引退 | wear超過による通常引退（シーズン末） |
| 怪我引退（career-ending） | 重傷時追加判定（基本2〜3%、wear40+は5〜8%） |
| 怪我引退（wear超過型） | 重傷発生時にwear+怪我ボーナスが80超で即引退 |
| モチベ喪失引退 | motivationLoss継続24週超で自主引退 |
| 手動解雇 | プレイヤーによる解雇 |

### 9.3 careerHistory（経歴記録）
- 中傷・重傷・引退時に `careerHistory` に記録
- 選手詳細TABに表示


## 22. v2.0 イベントシステム（Phase 1）

### 22.1 trust パラメータ
- **値域**: 0〜100（初期値 50）
- **用途**: mentalCoeffの変動係数として機能
- **変動**: 興行結果・ケアアクションで増減。offWeek1に−1/月の自然減衰
- `Engine.trust.getTrustBand(trust)`: low/mid/high の3段階
- `Engine.trust.getEventCandidates(state)`: イベント候補選手を返す

### 22.2 通知型イベント（N1〜N5）
週25%確率で発生。処理後 `showNotifEventToast()` でトースト表示。

| ID | 内容 |
|:--:|------|
| N1 | 自主練頑張っている（trust+2〜4） |
| N2 | 体調面の心配（コンディション注意） |
| N3 | モチベ回復の兆し |
| N4 | 地道な努力（練習成長+） |
| N5 | ファンからの声援（人気+） |

### 22.3 ケアアクション（7種）
manage画面「💝ケア」ボタンから起動。資金消費でtrust・成長・体調を改善。

| アクション | 費用 | 効果 |
|-----------|:----:|------|
| 個別練習強化 | 50万 | 3週間の練習成長×1.4 |
| メンタルケア | 80万 | trust+20、スランプ解除 |
| スパ遠征 | 120万 | コンディション+30 |
| 記念グッズ製作 | 60万 | 人気+5 |
| チームビルディング | 150万 | 全員trust+10 |
| 特別コーチング | 100万 | 4週間MQ+8 |
| ファンイベント | 200万 | orgPop+3、heat上昇 |

### 22.4 選択型イベント（S1〜S6 / E1〜E6）
`Engine.eventSystem.generateChoiceEvent()` で条件に応じて生成。`showChoiceEventModal()` で3択ポップアップ表示。

| カテゴリ | ID | 概要 |
|---------|:--:|------|
| サクセス型 | S1〜S6 | 好調時の判断（e.g. 追い込み練習 vs 休養） |
| イベント型 | E1〜E6 | アクシデント系（e.g. 雨天・スポンサー交渉） |

## 23. ファン期待度

`Engine.fanExpect.generate(state)` でweek毎に最大3件生成。

### 生成優先順位
1. **priority3**: 因縁ペア（rivalLevel≥1）
2. **priority2**: チャンピオン挑戦者
3. **priority1**: 人気上位選手（pop降順）

### 効果
- 期待カードが実際の興行カードに含まれる場合 → Pass2でMQ+5（MQ_EXTERNAL_CAPに含まれる）
- 興行準備画面に「ファンの声」パネル表示。一致カードに ✓ マーク + 「MQ+5」バッジ
