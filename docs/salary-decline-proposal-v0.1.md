## §1. 現状分析 — なぜ「上がりっぱなし」になるのか

### 1.1 給与の構造(management.js `getSalary`, data.js `SALARY_PARAMS`)

```
給与 = base + popBonus + titleBonus + salaryBonus
  base     = 2.40 × e^(0.043 × contractOVR) − 8   … OVR60≈24万 / 70≈41万 / 80≈67万 / 90≈107万
  popBonus = 80 × (contractPop / 100)²             … pop50=20万 / 80=51万 / 100=80万
  titleBonus = 王者のみ +20万
  salaryBonus = 契約交渉で積んだ昇給の累積(0〜100、シーズン末に20%自然減衰)
```

`contractOVR` / `contractPop` はオフ第2週(契約更改)に**全員が現在値で再固定**される
(management.js:16832)。つまり base と popBonus には既に「衰えたら1シーズン遅れで下がる」
仕組みがある。OVR 85→78 の衰えで base は約85万→61万と、下り自体は効いている。

### 1.2 それでも上がり続ける3つの原因

**原因A: 交渉に「下り」の分岐が存在しない**
gapRatio(適正給÷現在給)の段階は `1.3+ / 1.1+ / それ未満` の3つだけ(management.js:25417)。
gapRatio < 1、つまり**衰えて現在給が適正を上回った状態は「ギャップなし」に丸められる**。
trust 40+ なら黙って現状維持で自動残留、trust <40 なら衰えていてなお昇給要求が出る
(§4.4: gap 'none' でも baseProb 0.6+)。交渉の選択肢は構造的に「上げる or 維持」しかない。

**原因B: salaryBonus のラチェット(昇給の二重乗り)**
オフ第2週の処理順は「交渉解決 → contractOVR/Pop 再固定」。昇給を飲むと salaryBonus に
積まれ、その直後の再固定で base も適正給まで上がる。**ギャップを埋めるための昇給が、
基本給の上昇と二重に乗る**。減衰は20%/季のみなので、伸び盛りに積んだボーナスが
ベテランになっても残り続ける。

**原因C: 人気は衰えない(そしてそれ自体は正しい)**
popBonus は pop の2乗で最大80万 — スター選手では base を上回る最大成分。メインを張り
続ける限り pop はほぼ落ちない(週次減衰0.5、活動で半減)ので、能力ピークを過ぎても
popBonus は高止まりする。ただし「客を呼べるベテランの給与が高い」こと自体は説得力が
あるので、**ここは削らない**(§5参照)。

## §2. 設計原則との照合

| 問い | 答え |
|---|---|
| キャラクターのドラマに見えるか | 減俸は毎年の契約更改の場で、選手との対話として起きる。ベテランへの減俸提示・選手からの自発的な減俸申し出は、キャリアの下り坂を映すドラマそのもの |
| 社長の視点から自然か | 契約更改で提示額を決めるのは最も社長らしい行為。逆に、合意なしに給与が勝手に減っていく方が不自然 |
| 数値の動きに説得力があるか | 「加齢で−N%/季」の自動減額はやらない。既存の**適正給とのギャップ**(calcGapRatio)で駆動し、下がる理由が常に数値の実態(衰え・人気低下)に紐づく |
| 演出でどう見せるか | 既存の契約交渉UI(吹き出し・セリフ・態度)にそのまま乗る。新画面不要 |

## §3. 提案① — 契約更改に「下り」の分岐を追加する(本丸)

### 3.1 gapレベルの拡張

現行の3段階を5段階へ。閾値は上りの逆数で対称にする(1/1.1≈0.91, 1/1.3≈0.77)。

```
gapRatio ≥ 1.3          'large'          (現行どおり: 強い昇給要求)
gapRatio ≥ 1.1          'mid'            (現行どおり: 昇給要求)
0.90 <  gapRatio < 1.1  'none'           (現行どおり: 自動残留/自発残留)
0.75 <  gapRatio ≤ 0.90 'decline-mid'    (新設: 緩やかな下り)
        gapRatio ≤ 0.75 'decline-large'  (新設: 明確な下り)
```

decline帯に入る実体は「salaryBonus の残滓 + 衰えの1季遅れ + 人気下落」。数値をいじらず、
既にシミュレーションが生んでいる事実をそのまま読む。

### 3.2 trust × decline のマトリクス(既存 §4 マトリクスの下半分を埋める)

| trust | decline時の振る舞い |
|---|---|
| 75+ | **自発的減俸申し出**(選手発)。「私はもう全盛期じゃない。給料は下げてくれていい」。社長の選択: **受ける**(減俸成立) / **据え置く**(「あなたの給料は下げない」— 温情。trust上昇・支出は重いまま)。voluntaryStays の対になる瞬間で、この設計の一番のドラマ |
| 40〜74 | **社長から減俸を提示できる**(提示しない自由もある — 何もしなければ現状維持)。選手の反応は trust・性格・プライド(タイトル歴/在籍年数)で分岐: 受諾 / 対案(減額幅半分) / 反発(trust低下・不満蓄積) |
| <40 | 減俸提示は**退団トリガーになりうる**(既存の移籍志願/突発退団パスへ接続)。危険を承知で切り込むか、黙って払い続けるかの選択 |

- 自発的減俸申し出は**深刻度上位のみ、季1〜2名まで**。全ベテランに配らない(スポットライトは巡るもの)。
- 減俸案件も既存の「交渉リスト上位4名」枠に同居させる。深刻度スコアは
  `(100−trust) + |gapRatio − 1| × 100` に修正(現行式は decline で負になり埋もれる)。

### 3.3 減俸額と下限

```
減額幅 = min(salaryBonus, (現在給 − 適正給) × 0.5〜0.8)
対案   = 減額幅 × 0.5
実装   = salaryBonus から減額(負値は作らない)
```

**下限は適正給(fairSalary)。減俸で適正給より下には下げられない。**
人気が高いベテランは衰えても客を呼ぶ — その分の給与は守られる、という説得力の担保であり、
「減俸で選手を搾取する」最適化プレイの防止でもある。

### 3.4 関係への影響(方向のみ。数値は較正時に確定)

- 受諾: trust 微減〜±0(納得ずくの減俸)
- 対案受諾: ±0
- 反発(拒否): trust −8〜−12 程度、不満蓄積(既存の低trust交渉パスに合流)
- **据え置き(温情)**: trust +5〜8。忠誠心特性で増幅。**decline系イベントで trust が上がるのはこの選択だけ**

## §4. 提案② — ラチェットの解消(昇給を基本給に「吸収」する)

オフ第2週の再固定時、適正給(base+popBonus)が前季の固定値から上がった分だけ
salaryBonus を減らす:

```
absorb      = max(0, fair_new − fair_old)      // fair = base + popBonus(titleBonus除く)
salaryBonus = max(0, salaryBonus − absorb)
```

解釈: **交渉での昇給は「実力が評価に追いつくまでの前払い」**。実力が追いついたら
基本給に織り込まれ、ボーナスとしては残らない。現実の年俸更改と同じ理屈で、
昇給の二重乗り(原因B)を根本から断つ。

- 伸びている選手: 給与総額は昇給直後と変わらない(内訳が bonus→base に移るだけ)。
  **次の昇給要求のギャップ計算が正常化**し、雪だるまが止まる
- 衰えている選手: fair は下がるので absorb=0。bonus は20%減衰と§3の減俸だけで削れる
- 既存の20%自然減衰は当面残す(較正で二重に削れすぎるようなら調整対象)

## §5. やらないこと

- ❌ **年齢バンドで給与を自動−N%** — 安易な加減算そのもの。ドラマに見えない
- ❌ **popBonus の加齢カット** — 人気は既にシミュレーション(週次減衰・活動判定)が管理
  している。衰えて出番が減れば pop は自然に落ち、popBonus も落ちる。二重罰にしない
- ❌ **シーズン中の週次減額** — 社長の合意なしに契約が変わるのは世界観として不自然。
  給与が動くのは契約更改の場だけ(titleBonusの着脱を除く)
- ❌ **給与適正度メーターのUI常設** — 数値丸見せのスプレッドシート化。査定額は
  交渉の場でのみ提示される

## §6. 不変条件(実装時に検算する)

1. `getSalary ≥ 0`、`salaryBonus ∈ [0, 100]`(負値を作らない — validateGameState 追加対象)
2. **減俸後給与 ≥ その時点の適正給(fairSalary)**
3. 給与が変わるのは契約更改(オフ第2週)のみ。週次で動かない
4. 自発的減俸申し出は選手発のみ・季1〜2名まで
5. decline系イベントで trust が上がるのは「据え置き(温情)」選択のみ
6. §4の吸収は給与総額を変えない(bonus→baseへの内訳移動のみ。`|salary_before − salary_after| = 0` を再固定単体で検証)

## §7. 較正計画(auto-sim)

feedback_auto_sim_policy に従い、40季グリッドで分布を見て採用値のみ100季1本。

計測する分布:
- decline-mid / decline-large の**発生数/季**(目安: ロスターの1割未満、減俸案件0〜2件/季)
- 選手個人の**給与カーブのピーク位置**(目標: 給与ピークが能力ピークの+1〜2季以内。現状は引退まで下がらないケースがある)
- 給与総支出の季推移(§4吸収の導入で全体が下振れするはず — 資金バランスへの影響量を確認)
- 退団率・trust分布が現状から大きく動かないこと

## §8. セリフ(実装とは別工程・Opus起案)

新設が必要なプール(すべて archetype 第一分岐):
1. 自発的減俸申し出(trust75+のベテラン)
2. 申し出への「据え置き」返答を受けた反応(ここが感情のピーク)
3. 減俸提示への受諾/対案/反発
4. trust<40 での減俸提示 → 退団系への接続部
