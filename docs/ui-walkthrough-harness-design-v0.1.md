# UI自動走破ハーネス 設計 v0.1（バグ徹底捜索体制②）

2026-08-13起案(Fable)。4本柱体制(①フライトレコーダー→②本書→③レア画面カタログ→④回帰規律)の②。
Keisuke承認済みの方針: 「UI・進行層のバグを実ブラウザ・実クリックで自動検出する」。

## 0. 前提の転換(このハーネスが今まで無かった理由の解消)

過去の断念理由「`G` は app.js のクロージャ内でアクセス不可」は**誤認だった**。実体は:

- `let G` は app.js **トップレベル宣言**(app.js:3797)。グローバル・レキシカルスコープにあり、後続スクリプト(ui-common等)からもメインワールドのevalからも見える
- アクセスできなかったのはプレビューツールのevalが**拡張の隔離ワールド**で走るため(DOMは共有するがJS空間は別)
- Playwrightの `page.evaluate` は**メインワールド実行**なので `G` / `App` / `Engine` / `Storage` を直接読める

**結論: 製品コード(src/)を1文字も変えずにハーネスを作れる。**テスト用フックの新設は不要。

## 2. 構成

- **Playwright**(devDependency・Chromium)。`package.json` に `devDependencies` 新設。node_modules と Playwright のブラウザキャッシュは配布物・リポジトリに入れない(.gitignore 確認)
- 置き場所: `test/ui-walkthrough/`(run-all.js の収集対象 `*-test.js` 命名を**避ける**——実行時間が桁違いのため npm test には混ぜない)
  - `run.js` — エントリ。`node test/ui-walkthrough/run.js --mode walk --seasons 1 --seed 42`
  - `server.js` — src/ を配信する使い捨てローカル静的サーバ(file://はiframe(battle-engine.html)の同一オリジン制約で不安定なためhttp必須)
  - `detectors.js` / `driver.js` / `fixtures/` — 検出器・画面駆動・起点セーブ
  - `artifacts/` — 失敗時の出力(gitignore)
- 起動前に `localStorage.wm_audio = {muted:true, bgmMuted:true}` を注入(検証ミュート鉄則)。dev-tools.js が読み込まれる開発ツリーをそのまま使う

## 3. 実行モード

- **Wモード(走破)**: 起点セーブ(fixtures/。`test/make-save.js` 資産を流用)をロード→実UIで週送り・興行予約・興行実行・交渉・イベント消化を「常に主ボタン(推奨/おまかせ)を選ぶ」方針で1〜2季回す。**進行そのものが検査**(契約フリーズ型は更改週で必ず露見する)
- **Mモード(モンキー)**: シード付き乱数で「可視かつenabledのbutton/クリック要素」からランダム選択して押す。破壊的操作の遮断リスト(セーブ削除・記録消去・リロード誘発)を持つ。週送りに重み付けして前へ進める
- 両モードとも1操作ごとに§4の検出器を通す。所要目安: Wモード1季=数分以内を目標(§5の時計加速が前提)

## 4. 検出器

- **D1 例外**: `pageerror` / `console` イベント(error全部+`[WM Debug]` warn)。1件でもFAIL(既知の無害ノイズは明示のallowlistで管理)
- **D2 スタック**: クリック後、①DOM変異(MutationObserver) ②`G.week/season/weekPhase` の変化 ③オーバーレイ構成の変化、のいずれも**5秒**起きない→同一画面の全ボタンを一巡再試行→なお不動なら**FREEZE判定**でアーティファクト出力。「閉じる手段のない可視オーバーレイ」も同判定
- **D3 テキスト**: 画面遷移ごとに可視テキストへ正規表現検査: `undefined|NaN|\[object |null`(日本語文中の自然出現は文脈チェック)+内部変数名(`morale|orgPop|weekPhase|condition` 等の英字トークン)。ヒット=FAIL
- **D4 不可視**: 新規挿入されたid付き要素/主要クラス要素のうち「display:noneでないのに実効面積0 or 親overflowで完全クリップ」を検出(全DOM常時走査はしない。遷移時の差分要素のみ=コスト制御)
- **D5 進行ウォッチドッグ**: Wモードで「実時間Nに対し週が進まない」大域監視。個別スタックをすり抜けた複合停止の最終網

## 5. 決定論と速度

- 起点=fixtureセーブ+`G.rngSeed`。同一シード同一fixtureで再現可能(UIタイマー由来の完全一致までは保証せず、**再現手順の同一性**を保証)
- **時計加速**: Playwrightの `page.clock` でsetTimeout/演出待ちを圧縮(セレモニー30秒保険等を実時間で待たない)。加速で壊れる演出があればそれ自体は報告対象にせずallowlist(実時間検証は実機の領分)
- 週の一括進行が必要な区間は開発者モード(Ctrl+Shift+D の高速進行)を利用してよい。ただし**検査対象区間は必ず実UI操作で通す**(高速進行はスキップ手段であり検査ではない)

## 6. 失敗時アーティファクト

FAIL/FREEZE 1件につき `artifacts/<日時>-<種別>/` へ: スクリーンショット / 直前アクション列(シード・step番号つき) / `G` の要約(week/season/weekPhase/開いているオーバーレイ) / consoleログ全文。**再現コマンド1行**(同シード・同fixture・同step数)をREADMEに書き出す

## 7. 運用

- 回すタイミング: UI系ファイル(app.js/ui-common/ui-render/index.html)を触ったターンの締めに**Wモード1本**(手動 or 将来Stopフック)。Mモードは夜間・節目の長回し用
- 編集毎フックには入れない(実行時間が合わない)。npm test にも入れない(§2)
- 検出→修正→**④の規律**: 見つけたバグは挙動検査型ガードテストを対で書く
