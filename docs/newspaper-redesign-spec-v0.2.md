# 新聞再設計 spec v0.2 — 「タブ付きデータベース」から「一枚の新聞」へ

起票 2026-08-01（v0.1）。同日 v0.2 に改稿。`docs/newspaper-overhaul-plan.md` の N-9〜N-13 への設計提案。
**一面構成は v0.3 モックで方向承認済み**（2026-08-01「ベスト版はとてもいい感じ」）。
残る DRAFT 部分は §2 採点・§4 特集の細部。実装は P1 から。

v0.1 からの変更（すべて 2026-08-01 の Keisuke 指摘・裁定による）:
- 紙面構成を「特大1+2番手2」の機械的な枠から、実際の新聞の一面構造へ（§1）
- 採点を「イベント種の固定点」から「**誰に起きたか**で動く合成点」へ（§2）
- 帯は重なりを許し、資格線だけ固定（§2）
- 写真が無い記事のために**記事用汎用画像**を新設（§3）
- 団体比較の特集トリガーを節目主義に（§4）
- 静かな週の読み物は**実話主義**（実際に起きたイベントの後追いだけ。捏造禁止）（§4）

## 0. 何が問題か

今の新聞は「1面=興行 / 2面=団体比較 / 3面=因縁列伝 / 4面=MVPレース」と
**枠が先に決まっていて、中身を流し込んでいる**。その結果——

- 中身のない週でも何かが一面に来る（「ドラフト全指名が成立」・写真なし）
- 団体比較は動きがなくても毎号同じ顔で出る
- 大怪我や引退のような本当のニュースが、興行記事の下の小枠に沈む
- 各面が独立したデータベース画面になっていて、新聞を読んでいる感じがしない

新聞は逆で、**その週に起きたことの大きさが紙面の大きさを決める**。

### 在庫の扱い（Keisuke 裁定）

**既存の記事文は資産ではなく候補**。新しい紙面に合うなら使う、合わないなら
書き直す・捨てる。在庫を活かすために設計を曲げない。

## 1. 紙面構成（v0.3 モックで方向承認済み）

モックアップ: `docs/ui/mockups/newspaper-redesign-best-v0.3.html`

一面は実際の新聞の構造で組む。**記事6本+定位置3つ**:

```
┌──────────────────────────────────────┐
│ 題字・号数                            │
│ きょうの紙面（面の目次・他面への誘導）   │
├───────────────────────────┬──────────┤
│ ◆一面トップ（紙面の約4割）  │ ◆肩記事   │
│   横断見出し+リード         │  2番目の  │
│   写真190×228(本文従属)     │  ニュース │
│   本文4段落(後半2段組)      ├──────────┤
│                            │ MVP小窓   │
├───────────────────────────┴──────────┤
│ ◆準トップ（中段の横帯。予告・特集向き）  │
├─────────────┬─────────────┬──────────┤
│ ◇小記事      │ ◇小記事      │ ▪短信     │
├─────────────┴─────────────┴──────────┤
│ 黒田コラム（最下段の一言。編集手帳の位置）│
└──────────────────────────────────────┘
```

- **大きさの階段 = ニュースバリュー**。トップ > 肩 > 準トップ > 小 > 短信
- **写真は記事に従属する脇役**。最大でもトップの 190×228（現行実装と同等）。
  v0.1 モックの「特大写真」は却下（邪魔・読む新聞にならない）
- **本文の分量を確保する**。トップ4段落(約400字)・肩2段落・準トップ2段落・
  小記事2〜3行・短信は「▼」区切りの連結ベタ。「パッと見る」ではなく「読む」
- **短信**: 小ネタは1本ずつ枠を取らず連結する。ニュースが多い週はここが伸びる
- **きょうの紙面**: 実際の新聞の面目次。特集（§4）が発火した号はここに載る
- **黒田コラム**: 最下段固定の一言。位置は毎号同じ（コラムは定位置が命）

### 続きの見せ方（一面の下）

**「面をめくる」に固定しない。場合により、一面の下へそのまま続く1枚（縦スクロール）でもよい**
（Keisuke 裁定 2026-08-01）。実装時にニュース量・特集の有無で判断:

> **P1 の実装**: 自団体興行の詳報は**下へ続く1枚**を採用（黒田コラムの下に
> 「本紙つづき — 自団体興行 詳報」で継ぐ）。目次から `#npShowDetail` へ飛べる。
> 面として切るのは P4 の特集から。

- 続き記事が少ない週 → 一面の下に「準特大→中→小→短信」を継ぎ足す1枚もの
- 特集（§4）が立つ号 → 特集は面として切る（「二面 移籍特集」のように目次に載せる）

どちらの形でも中身の順序は同じ: 準特大（一面トップ級の2本目）→ 特集 → 中記事 → 小記事 → 短信。
ページ数・長さは可変。**無い記事をでっち上げない**。

## 2. ニュースバリュー採点（v0.2 全面改稿）

固定点では「無名の怪我」と「王者の怪我」が同じ点になってしまう。
**同じ出来事でも、誰に起きたかで価値が変わる**ように合成点にする:

```
最終点 = 基礎点(何が起きたか)
       + 主役補正(誰に起きたか)
       + 強度補正(どれくらい大きい出来事か)
       + 文脈補正(いつ・誰との間で)
```

### 2-1. 基礎点

既存 `Engine.newspaper.PRIORITY`（約70種）を出発点に使う。ただし
`topChampionInjury`(305) のような「主役を種別に焼き込んだ」特例は廃止し、
怪我(基礎) + 王者(主役補正) に分解する。

### 2-2. 主役補正（この粒度が本体）

対象選手の「いま持っている注目」を点にする。**上位2属性だけ**を数える
（1位属性 + 2位属性×0.5、上限 +120。全部盛りで無限に跳ねるのを防ぐ）:

| 属性 | 補正 |
|---|---|
| 団体王者（自団体・他団体問わず） | +90 |
| MVPレース首位 | +80 |
| MVPレース2〜3位 | +55 |
| MVPレース4〜10位 | +30 |
| 団体のエース（org内OVR 1位） | +55 |
| 団体の主力（org内OVR トップ3） | +35 |
| 業界人気トップ3 | +45 |
| 王座挑戦が決まっている | +45 |
| 当該シーズンの大会優勝者（JT/春タッグ/秋対抗/天頂戦） | +40 |
| ルーキー逸材（見立て最上位ティアの1年目） | +35 |
| 連勝中（5連勝以上、連勝数で微増） | +25〜 |
| 派閥リーダー | +20 |
| 該当なし（中堅・無名） | +0 |

### 2-3. 強度補正（イベント内部の変数で増減）

| 例 | 増減 |
|---|---|
| 怪我: 全治週数 | +4×週数（上限 +60） |
| 連勝: 団体記録との距離 | 更新 +40 / 王手 +20 |
| MQ: 歴代記録との距離 | 更新 +80 / 肉薄 +30 |
| 移籍: 古巣・因縁の有無 | +20 |
| 王座: 初戴冠 / 長期政権の陥落 | +30 |

### 2-4. 帯（重なりを持つ。Keisuke 裁定）

基礎点の帯は**重なってよい**。固定するのは**枠の資格線**だけ:

| 枠 | 資格線 |
|---|---|
| 一面トップ | 260以上 かつ 写真あり |
| 肩・準特大 | 190以上 |
| 準トップ・中記事 | 100以上 |
| 小記事 | 50以上 |
| 短信 | それ未満 |

同じ「大怪我」（基礎140 + 全治補正）でも:
- 無名・全治6週 → 140+24+0 = **164（中記事）**
- 主力3位・全治10週 → 140+40+35 = **215（肩）**
- 王者・全治14週 → 140+56+90 = **286（一面トップ）**

### 2-5. 検算不変条件（数値目標には不変条件を対で書く）

1. 無補正（該当属性なし）の日常ネタ・練習怪我は、強度を積んでも一面トップ(260)に届かない
2. 王者または MVP 首位の長期離脱（全治10週+）は必ず一面トップ資格に届く
3. C帯基礎点（70以下）は補正上限(+120)を足しても一面トップに届かない
4. 一面トップ資格が同週に2本 → 2本目は準特大へ。3本目以降は肩・中記事へ落ちる

### 2-6. 足りていないニュース源（produce 側の追加）

| 追加 | 基礎点の目安 | 中身 |
|---|---|---|
| 自団体選手の大怪我（長期離脱） | 140+強度 | 全治週数・直近の活躍・戦線への影響 |
| 引退表明（自団体） | 180+主役 | キャリア総括 |
| 連勝・連敗の節目 | 120+強度 | 記録との距離・次の相手 |
| 移籍・引き抜き成立 | 150+主役 | 出入りの文脈（古巣・因縁） |
| ドラフト総括（N-8 の作り直し） | 150 | 指名全体から5名を顔付きで。**並びは能力値の降順にしない**（隠しステが読めると冷める）。ランダムか見立てティアで |
| **特別興行の事前記事（下記 2-7）** | **結果と同等〜それ以上** | 展望・優勝候補・注目カード。経歴と過去の結果で膨らませる |

### 2-7. 特別興行の事前記事（Keisuke 提起 2026-08-01）

**「事前の記事は、下手をすると結果の記事以上の注目度があるものです、新聞では」**（Keisuke）。

いまの `PRIORITY` は逆になっている。結果が 230〜270 なのに、
`tenchosenAnnounce` / `autumnWarAnnounce` / `springTagAnnounce` は**揃って 150**、
`juniorTournamentPreview` だけが 250。**事前記事を結果と同じ帯まで引き上げる**。
一面の**準トップは「これから起きること」が座る位置**なので、置き場はもうある（P1 実装済み）。

#### 出場選手が未確定でも書ける

「出場選手が確定していなくても、**出場条件から出られる選手はもう確定している**。
当然 OVR の高い順に出てくるのはほぼ確実なんだから、それを前提に予想記事を書いてよい」（Keisuke）。

ただし**並べる順は OVR ではなく「見えている実績」にする**（§7-9 の裁定と同じ理由。
能力値の降順に並べると隠しステが読めて冷める）。幸い、Keisuke が続けて言った
「経歴とか、今までの結果とか語れることはいくらでもある」がそのまま解になる:

| 予想の根拠に使うもの（社長にも記者にも見えている） | 使わないもの |
|---|---|
| 王座・防衛回数 / MVPレース順位 / 業界人気 | 生の OVR・各ステータス |
| 過去大会の成績（優勝・準優勝・初出場） | trainCap・潜在値・見立てティアの内部値 |
| 今季戦績・連勝連敗 / 直近の大きな勝ち負け | 怪我の内部進行値 |
| h2h（因縁・通算対戦成績）/ 派閥 | |

`careerRecord.history` と `h2h.history` に素材が揃っているので、
**本文を膨らませる原資は既にある**（P1 の宿題「本文が150〜250字しかない」への回答にもなる）。

#### 記事の型（案）

- **展望**: 何が懸かっているか / 前回王者はどうなったか / 今年の枠と日程
- **優勝候補**: 3〜5名を上の「見えている実績」で。**断定しない**（記者の予想であって結果ではない）
- **注目カード**: h2h で因縁のある組み合わせが実現しうるなら名指しで
- 外れたときに**結果記事側から拾える**と効く（「本紙の予想は外れた」）。実話主義の範囲内

**実装フェーズ**: P3（不足ニュース源）に含める。P2 の主役補正がそのまま
「優勝候補の並べ方」に使えるので、**P2 の後**が素直。

## 3. 写真ルール（v0.2: 記事用汎用画像を新設）

- 人物写真（アッパー）最優先。**反転禁止**。トップ 190×228 / 肩 84×126 / 小 46×66
- **人物が特定できない記事のために、記事用の汎用画像を用意する**（Keisuke 合意）。
  候補カテゴリ: 会場外観 / 空のリング / 満員の客席 / ベルト単体 / 調印・契約書 /
  道場 / 会見場 / 医務室（怪我） / トロフィー。置き場 `image/news/`、制作は wrestle-creative
- 優先順: 人物写真 → 汎用画像 → それも当たらなければ**小記事・短信に限定**
  （「一面なのに写真がない」を仕組みで防ぐ）

## 4. 特集（固定面の降格先）

| 特集 | 発火条件 | 使う在庫 |
|---|---|---|
| 団体比較 | **節目主義**: シーズン開幕号 / シーズン総括号 / 対抗戦・4団体戦の前後 / 天頂戦・PPV前。業界順位の入れ替わりは希少なので主トリガーにしない（起きた週は加点で一面級へ） | 死蔵中の `KURODA_HEADLINES` 95本 + `KURODA_EDITORIAL` 63本を接続。**合わなければ書き直す・捨てる** |
| 因縁列伝 | 因縁が動いた週のみ（決着 / 再燃 / 初対決 / 9象限の遷移） | `KURODA_RELATION_NARRATIVE`。見出し1本化・**見出し+本文をセットで抽選**（N-6/N-7） |
| 静かな週の読み物 | 一面トップ資格が無い週 | **実話主義（下記）** |

### 静かな週の読み物 = 後追い記事（捏造禁止。Keisuke 裁定）

実際に起きたイベントの深掘りだけを書く。直近1〜4週のイベントログ
（industryNews の載り損ね / gameLog / careerRecord.history）から素材を取る:

| 元イベント | 後追い記事 |
|---|---|
| ブレークスルー | 「覚醒の裏側」— 何が変わったか |
| メディア出演・TV | 反響記事 |
| 派閥合宿・合同企画 | ルポ |
| 継続中の連勝 | 選手特集 |
| 表彰・記録樹立 | 記録コーナー |
| 新加入から数週 | 「その後どうしてる」 |

**対応するイベントが無い週は読み物を作らない**。紙面が薄い号があってよい。

## 5. MVPレース（N-11 / N-12）

- 固定4面を廃止。一面の肩記事下に小窓（首位3名+点差、4〜5位は1行）→「詳細 ▶」で開く
  （開き方は実装しやすい方で。Keisuke 裁定）
- 詳細の本文を書き直す: 下位の選手に因縁の話は書かない。
  **「この順位にどう食らいついているか」**（直近の勝敗 / 点差の詰まり方 /
  追う側か逃げる側か / 残り週数）だけで構成
- 生成は `Engine.mvpRace.generateRichBlocks` を改修し、テーブル化して Excel に載せる

## 7. 裁定ログ（2026-08-01 Keisuke）

1. モックアップは複数パターンで比較 → v0.1(3案)・v0.2(3案) を経て
   「枠に縛られず君のベストを出せ」→ **v0.3（1案）で方向承認**（「ベスト版はとてもいい感じ」）
2. v0.1 への指摘: 特大写真は邪魔。文章量が全く足りない。「読む新聞」にする
3. 続きは「面をめくる」に固定しない。**場合により下へ続く1枚（縦スクロール）でもよい**
4. 帯は割り切らず**重なりを持たせる**。柔軟性のため
5. 主役補正の粒度で設計する（王者・主力・MVP順位で価値が変わる。例示以外も同じ粒度で）
6. 記事用の汎用画像は用意してよい（必要なら制作する）
7. 団体比較の特集は節目でよい（順位入れ替わりは希少）
8. 静かな週の読み物は実際に起きたイベントに即す。捏造記事は不可
9. ドラフト総括の並びは能力値の降順にしない。ランダムか見えている情報で
10. MVP 詳細の開き方は実装しやすい方で
11. **特別興行の事前記事は、結果記事以上の注目度を持ちうる**。出場選手が未確定でも、
    出場条件から出られる面子は確定しているので予想記事は書ける。経歴・過去の結果で膨らませる（§2-7）
