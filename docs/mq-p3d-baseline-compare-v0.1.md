# MQ再設計 P3d 物差し再較正 — 回収前後ベースライン比較 v0.1

## 位置づけ

MQ回収(P1〜P3c)の前後で、MQを閾値参照する下流システム(trust/成長/メディア収入/興行評価等)がどれだけ動いたかを **同一seed(42)・100シーズン** で比較したデータ。判断・推奨は含まない。物差し再較正(どの定数を動かすか)の判断材料として設計側でレビューする。

- **回収後(post)**: HEAD = `5baff1b`（MQ再設計P3c(C-G)まで完了）
- **回収前(pre)**: `3d3130e`（P1着手直前のベースライン）を `git worktree add ../wm-baseline-3d3130e 3d3130e` で分離取得
- 実行コマンド: `node test/auto-sim.js 100 42`（両者とも同一シード・同一シーズン数）
- 両実行とも `Result: ALL CLEAR ✓`（不変条件違反・エラー・頻度警告なし）

### 計測手段についての注記

- **fp(fill pressure)**: `3d3130e` 時点のコードには fp/pressureFactor の概念自体が存在しない（P3c で導入）。そのためベースライン側は測定不能＝比較なし。post側のみ全体・シーズン帯別・会場ティア別で掲載する。
- **超過レイヤー(transcend)発生率・mqRecord更新回数**: 同様に `3d3130e` には存在しない機構(P3a以降で追加)。post側のみ参考掲載。
- **旧コードのMQ算出経路の注意**: `3d3130e` 時点のMQは、UI経由で表示される値とheadless(auto-sim)経由で最終確定する値の間に差異があることが別途調査済み（設定バフ・演出側の丸め・表示クランプの適用箇所差）。本レポートのベースライン値はすべて **headless経路(auto-sim / processSettlement直読み)** の値であり、実機UI表示値とは一致しない可能性がある。post側も同一のheadless経路で比較しているため、pre/post間の相対比較としては有効。
- 通常興行の試合MQ・興行収入は、いずれも **自団体(player)が興行主催者となる通常週(春タッグ/秋対抗戦/天頂戦を除く)** のみを対象とする。AI団体興行・PPV・トーナメントは含まない。
- 「興行収入」は `weeklyFinance.details` のうちラベルが「チケット収入」「グッズ収入（興行ブースト）」「メディア収入（興行放映）」「メディア収入（期待カード）」「メディア収入（ライバル抗争）」で始まる income 項目の合算。週次経常収入(グッズ週次・メディア週次・プロモ収入)は含まない。
- 「シーズン末平均trust/人気」は、オフシーズン明け(季節切替検出時点)の自団体ロスター(レンタル除く)の単純平均。100シーズン分のサンプルの単純平均（シーズンごとの重み均等）。
