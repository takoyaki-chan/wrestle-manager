## バグ（即修正すべき）

### 🔴 BUG-1: 戦績経歴タブが表示されない
**原因特定済み**: `Engine.milestone` が存在しない。
ui-common.js L1514 で `Engine.milestone.get(G, c.id)` を呼んでいるが、
engine.js に `milestone` 名前空間が定義されていない → タブ1クリック時にTypeErrorでクラッシュ。

**対策**: `Engine.milestone` を実装するか、既存の `careerHistory` + `careerRecord` から
キャリア年表を構築するように書き換える。データは既に全選手に付いているので、
表示ロジックだけの問題。

### 🔴 BUG-2: スカウト「見送り」でキャラが消える
**原因特定済み**: app.js L1768-1770
```javascript
} else if (result.result === 'skipped') {
  candidates = candidates.filter(c => c.id !== candidateId); // ← ここで消している
```

## 経済バランス（優先度高）

### ⚠ ECO-1: 2年目で月収支+7000万のインフレ問題
**現行の問題構造**:
- チケット: 0.5万/人 × 12,000人(大会場) × 1.2(超満員) = **7,200万/興行**
- 興行が月2回で **14,400万** のチケット収入
- 会場費: 大会場3,200万/回 = 6,400万/月
- 給料: OVR80=150万/週×10人 = 1,500万/週 = 6,000万/月
- 固定費: (50+30)万/週 = 320万/月
- → 差し引き +1,680万/月（概算。グッズ・スポンサー・放映権で更に上乗せ）

**対策案一覧**:
1. **チケット単価を下げる**: 0.5万 → 0.3万（40%減）
2. **会場費をもっと上げる**: 大会場 3,200→5,000、ドーム 9,000→15,000
3. **給料をさらに上げる**: 表の全レンジ引き上げ
4. **累進課税を導入**: 月間利益の一定%を税金として自動徴収
5. **グッズ収入の単価見直し**: 0.08万→0.15万（現状安すぎ）
6. **スポンサー/放映権テーブル据え置き**（既にセッション16で半減済み）

### ⚠ ECO-2: チケット高い・グッズ安い（逆転問題）
**現行**: チケット 0.5万/人、グッズ 0.08万/人（6:1の比率）
→ チケット収入がグッズの6倍以上。グッズが誤差レベル。

**対策**: チケット↓ グッズ↑ でバランス修正
- 例: チケット 0.3万、グッズ 0.15万（2:1くらいに）

## HEAT システム

### ⚠ HEAT-1: 上がりっぱなし＋効果強すぎ
**現行の問題**:
- 超満員: heat +1、大入り: heat +1 → 良い興行するたびに上がる一方
- decay: 非興行週に -1.0（セッション16改修済み）だが興行のたびに上がるので実質上がりっぱなし
- On Fire（heat10+）で集客 ×2.0 は強すぎ

**HEAT_LEVELS**:
| レベル | 範囲 | 集客倍率 |
|--------|------|----------|
| Ice Cold | -6以下 | ×0.6 |
| Cold | -5〜-2 | ×0.8 |
| Neutral | -1〜+1 | ×1.0 |
| Warm | +2〜+5 | ×1.2 |
| Hot | +6〜+9 | ×1.5 |
| On Fire | +10以上 | ×2.0 |

**対策案**:
- A) **倍率を圧縮**: Warm→×1.1、Hot→×1.2、On Fire→×1.3
- B) **decay強化**: 興行週でも自然減衰を入れる（現状は興行週はdecayスキップ）
- C) **Heat上限を下げる**: ±5段階に（On Fireを廃止）
- D) **削除**（オーナーの検討事項。削除すると盛り上がり/冷え込みの演出が消えるのでリスクあり）

→ 個人的にはA+Bの組み合わせが一番バランスいいと思う。

## UX改善

### 📋 UX-1: おまかせ → 翌週に行ったのが分かりにくい
**原因**: `autoManage()` は processWeek を呼んで週が進むが、
視覚的な「週が進んだ」フィードバックが弱い。

**対策案**:
- 週処理後にヘッダーの週数表示をフラッシュアニメーション
- 「Week N → Week N+1」のトースト通知
- 週が変わったときに「🗓 Xシーズン Y週目」のバナーを一瞬表示

### 📋 UX-2: 全体的に時間経過が分かりにくい
**対策案**:
- ヘッダーに常時「Season X — Week Y / 48」を大きく表示
- 季節アイコンをヘッダーに追加（春🌸夏☀️秋🍂冬❄️）
- 週送り時のトランジションアニメーション

### 📋 UX-3: 今週ページにソート機能追加
**現行**: `G.roster.forEach` でそのまま表示（ソートなし、L666）
**対策**: ソートボタン群を追加
- 名前順（あいうえお）
- 総合順（OVR降順）
- 体調順
- 人気順

### 📋 UX-4: ランキング画面のツールチップ
**現行**: `<th title="...">` で定義済み（L1263）。HTML native titleなので
マウスホバーで1〜2秒後に表示される。モバイルでは表示されない。

**対策**: カスタムツールチップ（CSS）に置き換えて即表示＋モバイル対応

### 📋 UX-5: 新年・翌シーズン開始の儀式
**現行**: オフシーズン処理後にそのまま次シーズンに入る。特別な演出なし。

**対策案**:
- 「🌸 第Xシーズン開幕！」のフルスクリーン演出（0.5秒程度）
- 前シーズンの振り返りサマリー（順位・戦績・収支）
- 「今シーズンの目標」表示

### 📋 UX-6: 収支のデフォルト表示を月次に
**現行**: 週間コスト内訳として表示（renderFinance）
**対策**: デフォルトを「直近4週合計」に変更。週次/月次の切替タブ追加
