# 監査報告: 社長の意思決定と週次ループ

> **2026-09-25 注記**: 資金が早い時期に意味を失うという記述(発見11ほか)は、お金をほとんど使わない自動プレイヤーでの計測に基づくもので、撤回した。詳しくは統合報告 `docs/fun-audit-v0.1.md` の冒頭の追記を参照。

## 1. 要約

- 社長の決定はほぼ「隔週のカード編成(年20回)」に集中しています。選択を迫られるイベントは年3〜4回しかありません(選択型0.6〜0.75回/季、大型2.05〜2.2回/季)。
- カード編成には多くのレバーがありますが、次の3点で「意図を持って組む面白さ」が削がれています。
  - **実プレイ経路とエンジン経路の食い違いによる断線**(検証済み): プロモ蓄積が消費されない件、★評価の加点キーがずれている件。
  - **画面の数字が旧仕様のまま**: 「評価+N」が実効の2〜4倍、またはゼロの効果を表示しています。
  - **最も重い社会的コストが編成時に見えない**: 出番を外すと信頼が下がるのに、その手がかりが出ません。
- 選択型・大型イベントは「冷たい選択肢」が一方的な損で、正解が固定です。ヒントにある「約束」も追跡されていません。
- 中盤以降は資金が1年で数倍に膨らみ、円建ての選択が空洞化します。社長室ケアは「信頼の危機がロスター規模次第でしか起きない」ため、平時は治す対象がありません。
- 検査網(auto-sim)はイベントの選択を一度も適用しておらず、実プレイとは別の興行処理を回しています。上の食い違いはこの構造から生まれています。

**1. 実プレイではプロモ蓄積が消費されず、「バランス」方針が3興行目以降こっそり「練習」に変わる**
- 種別: [断線・死蔵](公称と実効の乖離)
- 根拠:
  - 出場後のリセットは Engine.executeShow の中だけにあります(management.js:15048-15052)。
  - 実プレイの興行処理(app.js `_finalizeShowImpl` 7749行〜)は Engine.executeShow を呼びません。app.js と ui-*.js に呼び出しはなく、promoStack への書き込みも app.js:5426/8039 のみです。
  - 仕様は「試合参加で全消費」(specs/promo-system-spec-v1.0.md:76)。2026-03-06 のプロモ改修 v1.0(130bbf99)で、エンジン側にだけ入りました。
  - バランスは「興行週かつ蓄積3未満ならプロモ」という判定です(management.js:13047-13056)。一方、週画面の行動予告は蓄積を見ずに常に「プロモ」と表示します(ui-render.js:1433-1436)。
- 計測(M4、1季×2シード、全員バランス。差はリセットの有無だけ):

  | 指標 | エンジン経路(auto-sim) | 実プレイ経路の再現 |
  |---|---|---|
  | 1人あたり季内プロモ回数 | 18.2 / 21.0回 | 3.0 / 3.0回 |
  | 季内人気増 | 38.1 / 39.7 | 23.5 / 19.8 |
  | 興行時の平均蓄積 | 1.01 | 2.70 |
  | 集客力への加算(1人あたり) | +8 | +21.6 |

- なぜ面白さを削ぐか: 柱③に反します。画面は「プロモ」と言い、エンジンは練習させています。「プロモで直後の興行を沸かせる」という週次のリズムが季初3回で終わります。auto-sim で較正した人気・集客(expectedDrawCurve 等)が、実プレイとは別世界の数字になっています。
- 案: 出場後の消費を両経路が通る共通ステップ(tickWeek 内の精算の興行分岐など)へ移し、行動予告も同じ判定関数を使います。修正後に人気・集客分布を1本測り直します。

- 種別: [断線・死蔵](検査網)
- 根拠:
  - auto-sim のイベント処理は存在しない `Engine.events.resolveChoice` を探し、無ければ pending を捨てるだけです(test/auto-sim.js:853-878、呼び出し2177-2178。src に定義なし)。
  - 興行は Engine.executeShow で回しています(auto-sim.js:2040)。
  - F07の消化(app.js:8494-8528)、密着取材(app.js:9254)、マイルストーンの週次資金(app.js:13237-13244)は UI 側にしかありません。
- なぜ面白さを削ぐか: 発見1・2はこの構造の産物です。信頼・士気・人気の較正が、「選択しない社長」と「実プレイと違う興行処理」の世界で行われています。
- 案: auto-sim のイベント処理を `applyChoiceEffect` / `applyLargeEventEffect` 経由の方針プレイヤーに置き換えます。興行の後処理はエンジンの単一パイプラインへ寄せます(アーキ原則②③⑤)。当面は、両経路の差分テストを1本入れます。
- 規模: M〜L / 確度: 検証済み

**8. 社長室ケアは危機があれば効くが、危機がロスター規模で決まる — 平時は治す対象が無く、慰労会だけが常設**
- 種別: [効いていない]
- 計測:
  - 大ロスター・ケアなし: 季末信頼 p25=8.4 / p10=0.0。
  - 同条件で `--care`: p25=40.2 / p10=26.7 で、ケアは効きます。ただし支出は auto-sim 自身の集計で約1.05億/季、途中で破産が1回ありました(自動プレイヤーの積極方針による)。
  - 通常ロスターでは信頼中央値79で、ボーナス書類(信頼60未満で出現)の出番がほぼありません。
  - 士気は3条件とも週平均30〜33(基準値55)。慰労会(士気60未満で出現)は事実上いつも机にあります。そのため社長室ナビの「案件あり」印(management.js:23123-23128)も常時点灯と推定します。
- なぜ面白さを削ぐか: テスターの「最近ケアアクを使っていない」は、平時ロスターで治す状況が生じないことと整合します。書類が「閾値が割れたら出る」形で、特定の子の事情に向けた一手になっていません。
- 案: 出現条件を「誰かの事情」に紐づけます。例: 外され続けている子への約束、破約の後の詫び、スランプの子を名指しで机に置く。慰労会は突然の退団・大敗・対立放置など、出来事の後にだけ出します。
- 規模: M / 確度: 検証済み(案件印は推定)

**9. 社長が「問われる」のは年3〜4回。非興行週24週の大半は1クリック**

  | 大型 | 2.05 | 2.20 |
  | 通知 | 2.30 | 2.15 |

  | 他団体直訴 | 0.15 | 0.45 |

  S1・S3・愚痴・SNS・営業試合は40季でほぼ0でした。操作量の目安は、興行週が8〜12クリック+試合数で考える瞬間は1回、非興行週は1クリック(決定は約0.2回/週)です。
- なぜ面白さを削ぐか: 週次ループの「考える瞬間」が隔週のカードに偏り、終盤はそれも作業化します(発見5・10)。
- 案: 乱数イベントを増やすのではなく、既に状態としてある事情(外された子、約束の結果、温まった因縁ペア)から、興行の翌週に最大1件を名指しで机に出します。

**10. B2「後押し」は社長が試合の能力値を直接+5する介入**
- 種別: [選択の空洞化・支配戦略](柱②「試合中の直接操作をしない」に抵触の疑い)
- 根拠: 後押しした選手の4能力を+5します(app.js:14261-14270)。結果画面には「(OVR+5バフ適用)」と表示されます(ui-common.js:15389)。

- 案: 能力値は触らず、試合前の激励を信頼・絆・見返しモードへの作用にします。後押しされなかった側の信頼低下を本当に入れます。
- 規模: S / 確度: 検証済み

**11. 資金の緊張が1年目で消え、円建ての選択肢が中盤以降ほぼ無意味になる**
- 種別: [ペーシング・長期]
- 根拠:
  - 開始資金は5,000万。ランダム編成・ケアなしでも季末資金は 1年目1.84億 → 5年目10.7億 → 20年目41.4億です。
  - 値札の例: SNS対応 -30万、ボイコット -50万、営業試合 +150万(全員の体調-8と交換)、B1特別治療 -200万、メディア 150万、慰労会 15万/人、合宿 40万/人(management.js:24833-24862、25409、data.js:21458-21533)。

- 案: コストを減らない資源(決裁枠、選手の体調・信頼、団体の評判)に置き換えるか、値札を週次収入に比例させます。経済全体は macro 担当と要調整です。
- 規模: M / 確度: 検証済み(auto-sim の支出行動は実プレイと差あり)

**12. 新しい面白さの芽: 「社長の約束帳」**

  - 社長がどんな人間かが、数値ではなく選手の言葉で映ります(柱①②)。
