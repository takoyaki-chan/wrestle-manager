## 物語化レイヤー監査レポート(新聞・年代記・経歴・記録・表彰・セリフの出し方・スポットライト)

### 1. 要約
- 新聞には記事が収まりきらずに捨てられる問題はありませんでした。問題は、そもそも記事にならない事実と、記録の表示が漏らしている事実にあります。経歴年表・年代記・殿堂の実績欄は、天頂戦・全国統一王座・秋の4団体戦・歴代最高評価を1行も描きません。その年は「特記事項なし」と表示されます。
- 「辛さ」は書かれますが「報われる瞬間」は書かれません。自団体の下位1/3の選手が紙面に出るとき、96〜97%は連敗・負傷・内紛の記事です。連敗脱出・番狂わせ・初勝利を主役にした記事の種別は存在しません。
- 自団体の看板がシーズン末に引退しても、新聞では30点の短信です。同格のAI選手なら肩記事(245点)になります。非興行週の号は、前週の自団体興行記事を今週の日付で再掲しています。
- 掲載記事の約78%は5種類の定型記事で、黒田コラムの72.5%は汎用3文です。一方でスポットライトを巡らせる素材は余っています。Glimpseは毎季107件生成され、下位選手まで全員を照らしていますが、表示できるのは最大15%です。
- 同じIDのキャラが引退5季後に新人として再登場する仕組みがあり、殿堂の二重登録や、前の人生の異名・防衛数が新しい人生の記事に混入しています。

### 3. 発見(重要度順)

**① 経歴年表・年代記・殿堂の実績欄が、最大級の実績を描かない**
- **種別:** [断線・死蔵]
- **根拠:**
  - `Engine.milestone.get`(management.js:7135-7338)の switch に次の7種の case がありません: ppvTournament / unifiedTitle / autumnWar / mqAllTimeRecord / tenchosenBestBout / juniorTournamentBestBout / feud。これらは `default:` で読み捨てられます(7336)。表示行が無い年には「特記事項なし」が入ります(7366-7367)。
  - `micro-career.js` で実測しました。この7種を含む12件の履歴を与えると年表は4行になり、天頂戦優勝・統一王座戴冠の年は「キャリア3年目 終了 / 特記事項なし」と表示されました。
  - 殿堂 `buildCareerHighlights`(21086-)と年代記 `_buildHighlights`(5906-)も天頂戦と秋の4団体戦を扱いません。一方 `calcHofPoints` はこの2つを加点します(21047/21051)。コード自身がコメントで警告している「殿堂ポイントは付くのに実績リストには出ない」ズレ(21033-21035)が実際に起きています。
  - 開眼は業界ニュース(8696)にしか出ません。
  - career-history-spec は 2026-05-02 版のままです。08-01 に「MQ歴代記録をキャリアに刻めるようにした」修正は、記録するところまでで、表示には届いていません。
- **なぜ面白さを削ぐか:** 柱①(データは人生の窓)と柱③(数値は嘘をつかない)に反します。新聞が最高点を付ける出来事の年が、本人の年表では「特記事項なし」になります。
- **案:**
  - 年表に上記7種の case と文面(英訳込み)を追加する。
  - 「特記事項なし」は表示行ではなく history の有無で判定する。
  - 殿堂の実績欄・年代記・異名タグに天頂戦と秋の4団体戦を加える。
  - 開眼を `careerRecord.history` に積む。
  - 「calcHofPoints が数える type は、実績欄が描く type にすべて含まれる」を不変条件としてテストに書く。
- **規模:** S〜M / **確度:** 検証済み

**② 自団体選手のシーズン末引退は、新聞では「30点の短信」にしかならない**
- **種別:** [効いていない](公称と実効の乖離)
- **根拠:**
  - 格付けされた引退記事 `retirementDeclare`(基礎180点+格補正最大120点+殿堂150点)は、`scanRosterNews` が季中に retiredFighters を走査したときだけ生まれます(32259-32278)。
  - その retiredFighters は表彰式の完了時に空になります(app.js:13016)。
  - 実際のUIでは、シーズン末の引退は `commitRetirements` の `type:'retirement'`(management.js:7836)になり、汎用テンプレ3本・`P.general`=30点(33131)で扱われます。
  - `micro-retire.js` で同じ選手(3度戴冠・ピークOVR88)を比較しました。UI経路は30点で短信、季中経路は265点で一面、AIの同格選手は245点で肩記事でした。
  - auto-sim 30季では、自団体の引退17人のうち16人がオフ期の引退で、格付け記事になったのは1件だけでした。
- **なぜ面白さを削ぐか:** 感情設計の「鮮烈に見せる」に反します。新年号の一面は他団体の中堅の引退が取り、自分の看板は最下段の短信になります。
- **案:**
  - newsItems を retirementDeclare 形式(reigns / peakOVR / wasChampion)で積み、既存の格付け・殿堂特別号の経路に合流させる。
  - ラストラン表明(現在はログ1行のみ)を新年号の「最後の花道」記事にする。
- **規模:** S / **確度:** 検証済み

**③ 「報われる瞬間」が記事にならない(連敗は書くが、連敗脱出・番狂わせ・初勝利は書かない)**
- **種別:** [ドラマの取りこぼし]
- **根拠:**
  - `scanRosterNews` が拾うのは、連勝・連敗の節目、長期離脱、移籍、引退だけです。
  - 自団体興行の事実を当週〜2週後の紙面が主役として拾った率(シード2本):

    | 事実 | 件数(A/B) | 主役として載った率 |
    |---|---|---|
    | 5連敗以上からの脱出 | 75 / 72 | 13.3% / 2.8% |
    | 格上撃破(OVR差10以上) | 47 / 50 | 10.6% / 2.0% |
    | 3敗以上からの初勝利 | 18 / 13 | 11.1% / 7.7% |
    | 5連勝以上を止めた | 90 / 94 | 27.8% / 19.1%(止めた側を主役にする種別は無い) |

  - 自団体の下位1/3の選手が紙面に出た記事のうち、負の記事は96% / 97%でした(上位1/3は7〜14%)。
  - 後追い記事 followUpStreak は節目記事の有無を見ていません。164本中74本が、同じ号に同じ選手の節目記事と並んでいました(32337)。
- **なぜ面白さを削ぐか:** 感情設計の「報われたとき一緒に喜べる」が欠けています。
- **案:**
  - 既存の `newsSeen.streak`(報じた節目)を使い、報じた連敗が止まった週に `loseStreakEnd`、報じた連勝を止めた選手を主役に `winStreakStopped` を積む。
  - intensityBonus に、有名度とは独立した「瞬間補正」(止めた連敗数・OVR差)を足す。
  - 後追い記事は同じ号に節目記事がある選手を除外する。
- **規模:** S〜M / **確度:** 検証済み(auto-simのランダム編成は連敗を作りやすい点に注意)

**④ 非興行週の号が、前週の自団体興行記事を今週の日付で再掲する**

- **規模:** S / **確度:** 検証済み

**⑥ 同じIDで再登場するキャラの記録が混線する**

**⑩ 雑誌取材・TV出演は「人気 +2」を見せる固定加算で、人気者にしか来ない**
- **種別:** [効いていない]
- **根拠:**
  - 対象は王者か人気55以上の選手で、効果は人気+2/+3・ヒート+1/+2の固定値です(3965)。ポップアップに「人気 +{n}」と出ます(app.js:11074/11855)。
  - 誰にでも付く決め台詞「『まだまだ頂点を譲る気はない』」が挑戦者にも付きます(3908/3913)。汎用テンプレに名指しセリフを入れないルールに反します。

- **規模:** S / **確度:** コード読解+実測
