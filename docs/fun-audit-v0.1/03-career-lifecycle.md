# 監査報告:【選手の一生】(成長・全盛期・衰え・引退・入退団)

## 1. 要約

- **一番大きい問題は、auto-sim と実プレイで自団体の選手の育ち方が違うこと**。実プレイの試合後処理(`App.finalizeShow`)だけ、試合成長に年齢倍率が掛かっていない。2026-03-10 の修正(commit 8a70414f)がエンジン側にしか入っていないためで、自団体のベテランの衰えは設計のおよそ半分の速さになる。auto-sim は別経路(`Engine.executeShow`)を測っているので、この差は見えない。
- **世界の一貫性が崩れている**。AI団体が契約満了にした23歳以上のベテランはFA市場に出る前に同じオフ週で17〜19歳に若返り、半数はそのオフのドラフトに新人として並ぶ。さらに引退者の約7割は約10季後に同じ名前と顔で再デビューし、殿堂・年代記・関係値・直接対戦成績を前世と共有してしまう。
- **人生の大筋は、見えない2つの初期値でほぼ決まる**。ピークは隠れた天井(trainCap)で決定係数0.73、引退年齢は隠れた耐久値で0.86。全員が同じ年齢カーブをたどり、遅咲きは構造的に起きない。キャリア中の出来事(怪我・スランプ)がピークに与える影響は小さい。
- **辛さの出方が偏っている**。自団体の選手の怪我はAIの約2倍(重傷は2.8倍)。一方で「壮絶な幕切れ」は120季で0件、自団体の開眼は158人生で1件。AIのキャリアの約半分は、放出されて消息が途絶える形で黙って終わる。

## 2. 発見(重要度順)

### ① 実プレイの自団体だけ、試合成長に年齢倍率が掛かっていない。auto-sim は別の処理経路を測っている
- **種別**: [断線・死蔵]
- **根拠**:
  - `src/app.js:8755-8760` の `matchGrowth` には `ageMultiplier` が掛からない。エンジン側は4経路すべてで掛けている(`management.js:15376`(シングル)、`15317`(タッグ)、`11006`(AI)、`17223`(PPV))。
  - git 8a70414f のコミットメッセージは「試合成長にageMultiplier適用: 3箇所(AI興行/Player興行/PPV)…25歳以降も年間約5.4ポイントの試合成長がdecayを打ち消していた問題を修正」。変更は `engine.js` だけで、`app.js` は触っていない。
  - 実プレイの経路にしかない処理もある: ブレークスルー(`app.js:8866`)、敗戦スランプとモメンタム、ラストラン後の引退(`app.js:9273-`)、モチベ喪失による引退(`app.js:11873-`)。
  - 逆に `_relationshipGrowthMult` とスランプ中の試合成長ゼロ化は実プレイ側にない。
  - 計測(`proj.js`、127人×4シード=508キャリア、同じ乱数で比較):
    - エンジン経路: ピーク81.1(22.7歳)、27歳時点でピーク比 −6、31歳で −12。
    - 実プレイ経路: ピーク83.7(23.9歳)、27歳で −3、31歳で −6.5。
- **なぜ面白さを削ぐか**: 成長仕様の設計原則2「年齢は残酷」が実プレイで効いていない。自団体のベテランは衰えがOVRに出ず、消耗の⬇バッジだけが進む(三本柱③「数値は嘘をつかない」に反する)。AIと自団体の成長を対称にする裁定(2026-08-01)にも反する。γやbaseLearningの較正はすべて auto-sim 経路での実測なので、Keisukeが実際に遊んでいる成長曲線は誰も測っていない。
- **面白くする案**:
  - 最小修正: `app.js` の試合成長に `ageMultiplier`、`_relationshipGrowthMult`、スランプ中ゼロ化を入れる。
  - 根本: 試合後処理の成長・怪我・成長イベント部分を純関数1本にまとめ、App もそれを呼ぶ。同じ試合結果を両経路に流して差分がゼロであることを確かめる対称性テストを常設する。
- **規模/確度**: S(最小修正)〜M(統合)/検証済み(コード+git+projection)

### ② AIの「契約満了」ベテランは、同じオフ週に17〜19歳へ若返って新人として戻ってくる
- **種別**: [ドラマの取りこぼし](世界の一貫性の断線)
- **根拠**:
  - オフ第1週の処理順は `processSeasonEnd`(`management.js:18028`)が先。ここで放出・契約退団した選手が `state.freeAgents` に直接 push される(`11776`、`11873`)。その直後のFA加齢処理(`18069-18088`)が「22歳超 → 17〜19歳で休眠プールへ」を `careerStage` を確認せずに適用する。
  - コメント上の意図は「未デビュー→若返り再投入」。scout 仕様 §9.3 は「30歳以上のFAはオフに引退候補」、`AI_TURNOVER_CFG`(`data.js:8721`)は「他団体やプレイヤーが拾える」と書いている。新聞も「フリーエージェントとなった」と報じる(`data.js:19060`)。
  - 計測(40季×3本):
    - 23歳以上で放出・FA退団した選手は各本26/30/33件。全件がFAを経由せず休眠プールへ直行していた。
    - 引退処理の無いまま消えた既成選手(3季以上在籍またはピーク85以上)は1季に約1人。年齢の中央値24〜25、ピーク中央値86、戴冠経験者は6〜8人/40季。
    - このうち約2/3が後に新人として再デビューし、半数は同じオフのうちに戻る。
  - 実例: 芝彩音。S40に28歳・ピーク101で皇武館を契約満了になり、同じオフに18歳で皇武館にドラフト入団した。
  - AIのキャリア全体では49.5%が「放出/退団 → 消息なし」で終わる。殿堂入り判定も新聞も無く、ログに「(27歳・契約満了)(退団)」の1行が出るだけ。
- **なぜ面白さを削ぐか**: 三本柱①。人生が途中で消え、しかも別人として巻き戻る。「辛さ」も「報われ」も描かれないまま、最多の終わり方が無音になっている。
- **面白くする案**:
  - 若返りを `careerStage==='prospect'` に限定する。
  - デビュー済みのベテランは1季FAに残す(社長が拾える=社長の舞台づくり)。拾われなければ仕様 §9.3 どおり「フリーのまま引退」として静かに去る型で処理し、殿堂入り判定と新聞に乗せる。
  - 実績のある放出者(ピーク85以上か戴冠経験あり)は新聞で「契約満了」を1本書く。
- **規模/確度**: S/検証済み

### ③ 転生(ID再利用)で、前世と今世の記録が混ざる
- **種別**: [ドラマの取りこぼし]、[断線・死蔵]
- **根拠**:
  - 休眠プールの補充で、引退IDが5季のクールダウン後に16〜20歳で戻る(`18139-18181`、`DORMANT_POOL_CFG.retiredCooldown=5`)。
  - 計測: 全引退者の67〜72%が約10季後(中央値)に再デビューした。殿堂入り選手は87/125、自団体の元選手は約半数(47/88)。
  - 記録はすべて選手IDで引くため、次の混線が起きる。
    - (a) 新聞の「殿堂入り引退特別号」が前世の殿堂エントリで発火する(`_findHallOfFameEntry` `31396`、`32667`、`33070`、UI側 `_npV3HofEntry`)。前世が殿堂入りしている選手の引退は40季で11〜15件、うち今世は無冠が4〜7件。
    - (b) 関係値と直接対戦成績を前世から引き継ぐ。再登場した新人の時点で rivalry 30以上の相手が中央値5人、直接対戦記録が中央値11ペアある。引退時の凍結フラグは解除されず、減衰もしない(`relationships.js:1977`、`569`)。
    - (c) 年代記は同じIDの2人目を登録しない(`5282`、`5595` のコメントは「理論上はない」)ため、2周目の自団体選手は年代記に載らない(40季で1〜2件)。年代記の顔をクリックすると現役の同名新人が開く(`ui-common.js:4041-4055` の探索順)。
  - スターは同じ顔ぶれに集中する。ピーク100以上の114人生は127人中47人から出ており、上位10人で40%。127人中28人はどの人生でもピーク85に届かなかった。
- **なぜ面白さを削ぐか**: 「その子だけの人生」が一意にならない。殿堂の顔が数季後に17歳で入団し、しかも前世の因縁を背負っている。
- **面白くする案**:
  - 記録のキーを人生単位にする(ID+何回目の人生か)。再登場時に関係値・直接対戦成績・フラグをリセットする。
  - 殿堂入り・戴冠経験者・自団体OGはクールダウンを15季程度に延ばす(20〜40季の1プレイではほぼ戻らない)。
  - 戻すなら「同じ名を継ぐ新人」として道場コメントで一言触れる(プロレスの襲名文化)。
- **規模/確度**: M/件数は検証済み、混線の経路はコード読解

### ④ 自団体の怪我はAIの約2倍、重傷は2.8倍(怪我の扱いが対称でない)
- **種別**: [効いていない]
- **根拠**:
  - 自団体は `Engine.injury.check`(基礎2.5%+体調・残りHP・ターン数、1試合あたり実効約6%、`management.js:1724`)。AIは一律3%(体調30未満なら8%)(`11090`)。
  - 計測(3本合算、1シーズン1人あたり):
    - 自団体: 怪我1.01件(軽0.48/中0.39/重0.14)、試合17.3。
    - AI: 怪我0.53件(0.33/0.13/0.05)、試合18.4。
  - projection: 自団体にAIの怪我モデルを当てると、ピーク+4.2、引退+1.0歳、怪我引退は62→12件(508人中)。
  - 怪我は成長ペナルティ(×0.15〜0.7 を6〜24週、`data.js:4078`)と消耗の加算(1件+2)に直結する。
- **なぜ面白さを削ぐか**: 自団体だけ辛い世界になっている。怪我が物語ではなく「毎週の消耗」になる(自団体9人弱で中傷以上がほぼ5週に1件)。
- **面白くする案**: 1試合あたりの怪我モデルを共通化して、AIにも体調・HP・舞台の格を効かせる。差を残すなら「自団体の試合は攻めている」などの理由を見える形で持たせる。
- **規模/確度**: S〜M/検証済み

### ⑤ 人生は見えない2つの初期値でほぼ決まり、全員が同じ年齢カーブを歩く
- **種別**: [ドラマの取りこぼし]、[見せ方]
- **根拠**:
  - 25歳まで残った選手で、入団時の隠れた天井とピークの順位相関は0.83(決定係数0.73、残差の標準偏差5.3)。
  - 自然引退の年齢は隠れた耐久値(−3〜+3)で決定係数0.86。耐久1段で+1.2年、−3なら平均22.6歳で引退する。
  - 残差への寄与: 重傷 r=−0.16、スランプ −0.08、開眼 +0.25(ただし稀)。
  - 年齢ごとのOVR中央値の変化は +8/+11/+9/+6/+4/+3(17→22歳)、23〜24歳で0、25歳から下降。個人差は小さい。
  - ピーク25歳以上は4%。晩成の特性は127人中3人しかおらず、ピーク中央値は23歳(特性なしと同じ)。開眼は19〜24歳限定。
  - 耐久値はUIにもコーチ観察の台詞にも一切出ない。自然引退が23歳以下の「早すぎる終わり」は自団体の24.6%を占めるが、引退の台詞は無冠用(A2)が当てられる。
- **なぜ面白さを削ぐか**: 挫折も大化けも燃え尽きも、隠れた初期値が順番に開いていくだけで、「そのキャリアで起きたこと」が結末を変えない。
- **面白くする案**:
  - 耐久を社長が知り得る範囲で定性的に見せる: 入団時のメディカルチェック、コーチの「骨格は強い」「長くは持たない体かもしれない」など。
  - 出来事が天井を動かす道を作る: 大舞台での自己ベストや因縁の決着で天井が小さく上がる。重傷の後遺症で天井が下がる(再査定の理由 `aftereffect` は既にあるが死に経路)。
  - 25歳以降は試合経験によるMNの伸びで「円熟」を残す。
  - 23歳以下の自然引退には専用の台詞カテゴリを用意する。
- **規模/確度**: M〜L/検証済み

### ⑥ 成長の節目通知の約6割が出ない
- **種別**: [見せ方]、[断線・死蔵]
- **根拠**:
  - OVR閾値(65, 70, …)の通過は40季あたり112〜122件以上。通知されたのは41〜50件。

  - 「限界到達」の通知は1060選手季で1件だけ。
- **なぜ面白さを削ぐか**: 鮮烈に見せるべき「伸びた瞬間」が黙って流れる。
- **面白くする案**: スナップショットを興行の前に取る。落ちた節目は選手ごとに保留して翌週以降に出す。限界到達はコーチ観察(近い天井)に合流させる。
- **規模/確度**: S/件数は検証済み、原因はコード読解

### ⑩ キャリアの長さを動かす社長の手札が「延命術」1枚に偏っている
- **種別**: [選択の空洞化・支配戦略]
- **根拠**:
  - projection(508人、方針別、実プレイ経路):
    - 延命術コーチ(35人中1人、如月薫): +2.9年、ピーク+4.3。
    - 追い込み(22歳まで): ピーク+2.7、引退−1.3年。24歳まで延ばしても上積みは無く、さらに−0.4年。
    - 25歳から試合数を10以下に: +0.4年のみ。
  - 消耗の倍率(`getWearMult`)は季末に1回だけ判定される(`8955`)。季末の直前に担当を付け替える、または招聘の4週を季末に合わせると、その季の消耗全体が半分になる(コード読解のみ、未検証)。
- **なぜ面白さを削ぐか**: 選手の使い方(試合数・休ませ方)が寿命にほとんど効かず、1人のコーチを取れるかどうかが寿命を決める。
- **面白くする案**: 延命術の効果を負荷由来の消耗(試合・怪我・追い込み)だけに掛ける。消耗を週次で積んで、コーチの効果もその週に反映する。試合数と休養の効きを強める。
- **規模/確度**: S〜M/推定(projection)+コード読解

### ⑪ 開眼が自団体ではほぼ起きない

### ⑫ 状態異常の数値が表示・仕様と違う
- **種別**: [効いていない](公称と実効の乖離)
- **根拠**:
  - 絶好調はUIで「OVR+2」と表示される(`ui-common.js:4219`)が、試合には反映されない。同じ乱数で4000試合を回すと、勝率49.6% → 49.6% で変わらない。
  - スランプ中の週次能力低下は `Math.round(整数−0.2〜0.5)` で常に0になる(48週で0pt。モチベ喪失のほうは −4.6 OVR 下がる)(`22361-22376`)。
  - スランプとモチベ喪失の `ovrDebuff` はどこからも参照されていない。
- **なぜ面白さを削ぐか**: 三本柱③の違反。
- **面白くする案**: 絶好調をラストランと同じくリング内のOV補正として効かせる。スランプの能力低下は端数を持ち越す方式にする。どちらも難しければ表示の方を直す。
- **規模/確度**: S/検証済み

## 5. 担当外だが気づいたこと

- **集客**: `calcDrawPower` の王者ボーナスは `titles.world.holderId` を参照しているが実体は `championId`、ブレークスルー直後のボーナスは `breakthroughWeeksLeft` を読むが設定箇所が無い。どちらも死に経路(`management.js:1298`、`1303`)。
- **死んだ引数**: `Engine.coach.getMatchGrowthBonus` と `getDecayReduction` は常に0を返すので、成長・衰退式の該当項は効いていない。
- **アーキテクチャ原則3への抵触**: モチベ喪失による引退とラストラン後の引退がUI層(`app.js`)で状態を直接書き換えている。auto-sim からはこの2つが見えない。
- **不変性の破れ**: `processAIContracts` と `applyExtraTurnover` が `state.freeAgents` / `state.dormantPool` を直接書き換える(`push`)。直前の状態と配列を共有している可能性がある。
