## 1. 問題

### 1.1 現状

`ORG_ASSIGN`（data.js L741〜748）が**完全にハードコード**されており、ニューゲームを何度やっても各AI団体の顔ぶれが100%同じになる。

```js
const ORG_ASSIGN = {
  player:   [],  // ドラフト後に設定
  org_s:    [1,37,2,33,65,38,66,55,67,34,46,29,60,47,30,42],  // 固定16名
  org_a:    [11,16,45,12,5,17,41,6,13,56,68,48,61],            // 固定13名
  org_b:    [3,18,31,69,28,49,70,35,71,72],                     // 固定10名
  free:     [7,26,39,40,36,14,76,73,74],                        // 固定9名
};
```

### 1.2 数値

- 全キャラ: 98名（ALL_CHARS）
- 固定配置済み: 48名（org_s:16 + org_a:13 + org_b:10 + free:9）
- pool（未登場のまま放置）: 約50名
- ドラフト候補: 31名（DRAFT_AVAILABLE_IDS）— poolと重複あり

### 1.3 何が悪いか

1. **リプレイ性がない** — 敵団体は毎回同じ、新鮮味がない
2. **50名が永久に未登場** — poolキャラが日の目を見ない
3. **A・B団体のコンセプトが死んでいる** — A「若手主体の育成団体」B「堅実経営の中堅団体」の個性が出ていない

## 3. poolの扱い — dormant/解禁サイクル

### 3.1 Keisukeの指摘

「poolがすべてフリーエージェントに出るということですか？やっぱり引退してしばらく登場を待つ選手たちや、世の中には存在していない選手たちが一定数いるようにしないと、よくないんじゃないでしょうか。そういうサイクルの設計もしてください。」

→ poolを全部FAに流すのではなく、**段階的に世界に登場させるサイクル**が必要。

### 3.2 検討中の概念

| 状態 | 意味 | 備考 |
|------|------|------|
| **org所属** | S/A/B/player/FAのいずれかに配属中 | ゲーム世界で活動している選手 |
| **dormant（休眠）** | まだ業界に登場していない | 未デビュー/別の世界にいる/準備中 |
| **retired（引退済）** | シーズン末処理で引退した選手 | 二度と戻らない（既存仕様通り） |

### 3.3 未解決の問い

- dormantから何名/シーズンを解禁するか？
- 解禁のトリガーは年齢？ランダム？プレイヤーのランキング到達？
- 学園系の若いキャラは「まだ高校生でデビュー前」、OL系は「プロレスに興味がなかった」等の設定で自然に説明できるか？
- dormantの人数の下限は？（常に一定数を非公開にしておくべきか）
