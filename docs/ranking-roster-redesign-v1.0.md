# ランキング・ロスター・団体間対戦 リデザイン設計書 v1.0

## 1. 概要

本設計書は以下の3つの課題を統合的に解決する。

1. **ランキング計算の刷新** — 頭数依存・ティア固定ハンデの廃止
2. **ロスター人数制限** — AI団体の無限膨張バグ修正 + プレイヤー上限の新設
3. **団体間対戦イベントの拡張** — 統一トーナメント新設、対抗戦強化

---

## 2. ランキング計算の刷新

### 2.1 現行の問題点

```
現行: rating = championScore(固定) + starPower(全員合算) + totalPop(全員合算)
```

- championScore: ティア固定ハンデ（S=60, A=40, B=20, Player=0or30）→ 逆転不可
- starPower/totalPop: 全員合算 → 16名 vs 12名で構造的に不利
- チャンピオンの強さ・防衛回数・団体の対戦実績が一切反映されない

### 2.2 新ランキング計算

```
rating = 基礎力スコア + 対戦ポイント
```

**基礎力スコア = TOP5平均OVR × 1.5 + TOP5平均pop × 1.0**

- TOP5: ロスター内のOVR上位5名 / pop上位5名（別々に計算）
- 少数精鋭でも大所帯でも同じ土俵で評価される
- 育成と人気管理のプレイヤー努力が直結する

**対戦ポイント = シーズン中の団体間直接対決の損益合計（シーズンリセット）**

- 勝てば奪い、負ければ奪われるゼロサム構造
- 毎シーズン0からスタート → 結果を出し続けないと維持できない
- 詳細は §4 参照

### 2.3 championScoreの廃止

- RIVAL_ORGS から `championScore` プロパティを削除
- `Engine.ranking.calcOrgRating` からchampionScore引数を削除
- `summitBonus` を廃止（対戦ポイントに統合）
- プレイヤーの `state.titles.world.championId ? 30 : 0` を廃止

### 2.4 バランスシミュレーション結果

基礎力のみ（対戦ポイント=0）:

| 団体 | TOP5 OVR | TOP5 pop | 基礎力スコア |
|------|----------|----------|-------------|
| S級（16名） | 81 | 75 | 197 |
| A級（13名） | 72 | 60 | 168 |
| B級（10名） | 63 | 41 | 136 |
| P序盤（8名） | 50 | 18 | 93 |
| P中盤（10名） | 68 | 45 | 147 |
| P終盤（12名） | 78 | 65 | 182 |

対戦ポイント込み（逆転シナリオ）:

| シナリオ | P rating | S級 rating | 差 |
|----------|----------|-----------|-----|
| P終盤 + 対抗戦勝利 + トーナメント優勝 | 214 | 195 | **P勝ち +19** |
| P中盤 + トーナメント優勝のみ | 167 | 207 | S級勝ち -40 |
| P序盤 + 対戦全勝 | 125 | 197 | S級勝ち -72 |

→ 終盤に選手が育った状態で対戦に勝てば逆転可能。序盤・中盤では対戦で勝っても基礎力差で追いつけない。正しいバランス。

## 3. ロスター人数制限

### 3.1 現行のバグ

AI団体のロスターが無限増加する。原因:

1. `aiScoutAndRecruit`: `maxPicks = min(need + 1, ...)` で idealRoster を超過可能
2. `aiInterTransfer`: `idealRoster + 2` まで許容
3. 複数獲得経路が同シーズンで独立実行される
4. 引退が少ない年が続くと蓄積

プレイヤー団体にはそもそも人数制限チェックが一切ない。

### 3.2 ハードキャップの導入

```js
const ROSTER_CAP = {
  player: 12,   // プレイヤー団体（レンタル含む）
  S: 16,        // S級
  A: 13,        // A級
  B: 10,        // B級
};
```

**プレイヤー = 12名の理由:**
- ランキングがTOP5ベースなので頭数は関係ない
- 5名スタート → ゲーム中に獲得で12名まで拡大
- 12名あれば興行の試合数（4-6試合）に十分
- 管理がしやすい規模

**AI = 現行idealRosterと同値。** これをハードキャップとして全経路に適用。

### 3.3 実装: 全獲得経路にチェック追加

**プレイヤー側:**

| 獲得経路 | 箇所 | チェック追加 |
|----------|------|-------------|
| FA契約 | app.js:1806 | `G.roster.length >= ROSTER_CAP.player` → 拒否 |
| スカウト獲得 | app.js:1899 | 同上 |
| 交渉移籍 | engine.js:3390 | `s.roster.length >= ROSTER_CAP.player` → 拒否 |
| レンタル追加 | engine.js:3680 | 既存のスロット制限に加え、総数チェック |
| 乱入後加入 | app.js:2195 | 上限時は一時追加のみ、試合後に退去 |

**AI側:**

| 獲得経路 | 修正内容 |
|----------|---------|
| aiScoutAndRecruit | `need + 1` → `need` に修正。ループ内でも `roster.length >= cap` チェック |
| aiInterTransfer | `idealRoster + 2` → `ROSTER_CAP[tier]` に統一 |
| aiFAAcquire | 既存チェックを `ROSTER_CAP[tier]` に変更 |

### 3.4 UI表示

- ロスター画面に「12/12 (上限)」のような表示
- 上限到達時、FA市場・スカウト画面に「ロスター枠上限に達しています」を表示
- 上限到達時は獲得ボタンをグレーアウト

### 3.5 既存セーブデータの互換性

- 超過状態のセーブをロードしても即解雇はしない
- 新規獲得を不可にするだけで、自然減（引退・移籍・引き抜かれ）で適正数に戻す

## 4. 団体間対戦イベント

対戦ポイントのソースとなるイベントは3種類。

### 4.1 対抗戦（現行拡張）

**現行:** 年30%確率で1回、3-5試合。勝敗で団体人気が変動。

**変更点:**
- 発生率: 30% → **50%**（年1回は高確率で発生するように）
- ポイント移動: 勝った団体が負けた団体から **12pt** 奪う
- 引き分け: 変動なし（0pt）
- AI同士の対抗戦: シーズン末に各ペアで30%判定、エースOVR差で勝敗決定

```js
// 対抗戦ポイント移動
const WAR_POINT_TRANSFER = 12;
```

### 4.2 サミットマッチ（現行拡張）

**現行:** PPV(48週)でランク2位以上、エースvs相手エース1試合。

**変更点:**
- 発生条件: ランク2位以上 → **ランク3位以上**（参加しやすく）
- ポイント移動: 勝てば **10pt** 奪う、負ければ10pt奪われる
- `summitBonus` → 対戦ポイントに統合、個別フィールド廃止

```js
const SUMMIT_POINT_TRANSFER = 10;
```

### 4.3 統一トーナメント（新規）

**コンセプト:** 年1回、全4団体の代表選手が争うトーナメント。最大の逆転チャンス。

**基本仕様:**
- 開催時期: シーズン **第24週**（シーズン中盤、ちょうど折り返し）
- 形式: 各団体から代表 **2名** を出場（プレイヤーは選択可能、AIはTOP2を自動選出）
- トーナメント形式: 8名によるシングルエリミネーション（3ラウンド）
  - 1回戦(4試合): 異団体同士で対戦（同団体は別ブロック）
  - 準決勝(2試合)
  - 決勝(1試合)
- 試合はバトルエンジンで実際に計算する

**ポイント配分（ゼロサム）:**

| 結果 | ポイント |
|------|---------|
| 優勝団体 | **+20pt** |
| 準優勝団体 | **+8pt** |
| ベスト4団体 | **±0pt** |
| 1回戦敗退団体 | **-14pt** |

合計: +20 +8 +0 -14×2 = 0（ゼロサム）

※2名出場なので、同団体の2名がともに勝ち進む場合もある。
最も成績の良い選手（最高到達ラウンド）で団体順位を判定。

**プレイヤーUI:**
- 第24週に「統一トーナメント開催」の通知イベントが発生
- 代表2名を選択する画面（怪我中の選手は選択不可）
- 各試合の結果を順次表示（バトルエンジンで処理）
- 最終結果とポイント変動を表示

**AI同士:**
- AI団体のTOP2 OVR選手を自動選出
- 試合結果はバトルエンジンで計算（シーズン末の一括処理ではなく、第24週にリアルタイム処理）

### 4.4 対戦ポイントの管理

```js
// GameState に追加
battlePoints: { player: 0, org_s: 0, org_a: 0, org_b: 0 }
```

- シーズン開始時に全団体0にリセット
- 各イベント（対抗戦・サミット・トーナメント）の結果で加減算
- ランキング計算時に `基礎力 + battlePoints[orgId]` で合算

### 4.5 対戦ポイントの年間最大値

```
理論上の最大ポイント（1団体）:
  対抗戦1勝: +12
  サミット1勝: +10
  トーナメント優勝: +20
  合計: +42pt

理論上の最低ポイント:
  対抗戦1敗: -12
  サミット1敗: -10
  トーナメント1回戦敗退: -14
  合計: -36pt
```

基礎力差（S級197 vs P終盤182 = 15pt差）に対して、対戦ポイントの振れ幅（±36〜42pt）は十分な逆転余地がある。

## 5. AI団体のランキング（C案: 統一モデル）

### 5.1 方針

AI団体もプレイヤーと全く同じランキング計算を使用する。

```
AI rating = TOP5平均OVR × 1.5 + TOP5平均pop × 1.0 + battlePoints[orgId]
```

### 5.2 AI団体間の対戦ポイント計算

**対抗戦（AI同士）:**
- シーズン末処理（processSeasonEnd）で各ペアに30%確率で発生
- 勝敗判定: 両団体のTOP3平均OVR比較 + ランダム幅
- 高OVR団体の勝率: 60-70%程度

```js
// processSeasonEnd 内に追加
function resolveAIWar(rng, org1Roster, org2Roster) {
  const ovr1 = top3avgOVR(org1Roster);
  const ovr2 = top3avgOVR(org2Roster);
  const advantage = (ovr1 - ovr2) / 30; // ±0.5程度
  const roll = Engine.rng.float(rng) + advantage;
  if (roll > 0.55) return 'org1';
  if (roll < 0.45) return 'org2';
  return 'draw';
}
```

**統一トーナメント（AIの処理）:**
- 第24週に全団体参加で実際にトーナメントを実行
- AI団体のTOP2選手を自動選出
- バトルエンジンで各試合を計算
- 結果に基づきポイント配分

**サミット（AI同士）:**
- PPV週にランク1位 vs 2位のAI対決として処理（両方AIの場合）
- エースOVR比較で勝敗判定

### 5.3 廃止される旧システム

- `RIVAL_ORGS[].championScore` → 削除
- `summitBonus` state → 削除
- `Engine.ranking.calcOrgRating(championScore, roster)` → 新計算に置換
