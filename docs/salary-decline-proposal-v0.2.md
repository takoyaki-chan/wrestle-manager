## §1. 計測で判明したこと(v0.1からの最重要変更点)

### 1.1 契約OVR制の再固定は一度も走っていない(バグ)

40季の計測で、季をまたぐ給与変動254件の**100%がsalaryBonusの増減だけで説明できた**。
つまり management.js:16832 の「契約OVR制: 来シーズンの給与基準をロスター全員に設定」は
**実際には一度も実行されていない**。

原因(コードで確認済み):
- tickWeek はオフシーズン中、冒頭(management.js:16504)で `offWeek = (s.offWeek || 0) + 1` と
  **無条件にインクリメント**する
- offWeek===2 で交渉が発生すると 16825 で `offWeek: 2` を保存して早期return
- 交渉解決後の次の tickWeek では offWeek=3 になり、**16832 の再固定を含む
  offWeek===2 ブロックの残りが丸ごとスキップされる**
- 再固定が走らないこと自体が gapRatio を毎季増大させ(実測: gap≥1.3 が92.7%)、
  ほぼ全員が毎季交渉対象になるため、一度外れたら二度と再固定に到達しない

### 1.2 これが「上がりっぱなし」の正体

給与の base+popBonus は**新人契約時の値のまま恒久固定**され、動くのは salaryBonus
(昇給ラチェット、20%/季減衰)だけ。適正給は成長で遥か上にあるため、
**衰えて実力が落ちてなお「新人時代の基本給」との差は大きく、昇給要求が止まらない**。
ピークを過ぎた選手の昇給要求が続く違和感は、ここから来ている。

### 1.3 再固定が働いていた場合の世界(再構成)

観測データから「毎季再固定されていたら」の gapRatio を再構成すると:

| 帯 | 全体 | wear>0(衰え開始後)のみ |
|---|---|---|
| ≥1.3(昇給large) | 14.2% | 3.7% |
| 1.1〜1.3(昇給mid) | 18.5% | 8.8% |
| 0.90〜1.1(none) | 23.2% | 16.2% |
| 0.75〜0.90(下りmid) | 28.0% | **41.2%** |
| ≤0.75(下りlarge) | 16.1% | **30.1%** |

再固定を直すだけで、下り帯は自然に(数値を捻じ曲げずに)出現する。
衰え開始後の71%が下り帯 — **減俸ドラマの母集団はシミュレーションが既に生んでいる**。

## §2. 改訂後の全体像 — 3層構造

```
P0(土台・バグ修正):  再固定を毎季確実に1回走らせる + 昇給吸収 + 入団経路の契約値監査
                      → 給与が実力・人気に両方向で追従する(下りはここで実現される)
P1(ドラマ層):        大きな査定減の選手を契約交渉カード化。「据え置き(温情)」の選択を社長に渡す
                      → 下り坂を黙った数値処理にせず、キャラクターの物語として見せる
P2(経済較正):        fair支払い世界では総支出が増える(実測gap中央値~1.5 = 現在は適正の2/3しか
                      払っていない)。資金バランスを計測し、必要なら SALARY_PARAMS を再スケール
```

v0.1 の「減俸提示」は、**P0の自動改定を"見せる"存在**に意味づけが変わった。
減額幅の独自計算式は不要になり(査定減=再固定がやること)、社長の選択は
「査定どおり受け入れるか、身銭を切って据え置くか」になる。

## §3. P0 — 再固定の修復と昇給吸収(実装レベル)

### 3.1 再固定の移設

- management.js offWeek===2 ブロック末尾(16831〜16839)の再固定を**削除**し、
  **offWeek===3 ブロックの先頭**(スカウトレポート生成より前)へ移設する
- offWeek===3 は早期returnより前の位置なので、交渉の有無に関わらず**毎季ちょうど1回**走る
- 対象は `s.roster` の `!isRental` 全員(現行と同じ)

### 3.2 昇給吸収(absorption) — 再固定と同時に行う

```js
// f は再固定対象の選手
const oldBP = Engine.util.getSalary({ ...f, salaryBonus: 0 }, {});   // 旧契約値の base+popBonus
const newBP = Engine.util.getSalary(
  { ...f, salaryBonus: 0, contractOVR: Engine.util.ov(f), contractPop: f.popularity || 0 }, {});
const absorb = Math.max(0, newBP - oldBP);
const newBonus = Math.max(0, (f.salaryBonus || 0) - absorb);
// → { ...f, contractOVR: Engine.util.ov(f), contractPop: f.popularity || 0, salaryBonus: newBonus }
```

解釈: 交渉での昇給は「実力が評価に追いつくまでの前払い」。追いついた分は基本給に
織り込まれ、ボーナスとしては残らない。これで昇給の二重乗り(ラチェット)が消える。

数学的性質(そのまま検証可能な不変条件):
- **伸びた選手**: 再固定後給与 = max(再固定前給与, 適正給)(丸めで±1)。
  昇給直後の再固定で給与総額は変わらず、内訳が bonus→base に移るだけ
- **衰えた選手**: absorb=0。再固定後給与 = 適正給のbase+pop + salaryBonus(+titleBonus)。
  つまり**base部分が査定どおり下がる = 給与の下り坂はここで実現される**
- salaryBonus は再固定で増えない・負にならない

### 3.3 処理順(1季サイクル)

```
offWeek1: applySeasonEnd — 加齢・wear衰え・salaryBonus×0.8減衰
offWeek2: 契約交渉 — gapRatioは「旧契約給与 vs 現在の適正給」で判定(現行どおり)、昇給はbonusへ
offWeek3: 再固定+吸収(新設位置) → スカウト
```

### 3.4 入団経路の契約値監査

「呼び出し元を全部数えてから直す」案件。`G.roster`(プレイヤーロスター)に選手オブジェクトが
入るすべての経路で、**入団時点の** `contractOVR`/`contractPop` がセットされることを保証する。
既知のセット済み: ドラフト(17599)・スカウト契約(14622)・リセット(14810)。
疑い: 移籍受け入れ・FA獲得系(14249/25873 の `salaryBonus: 0` だけ触る経路は旧値を持ち越す)。
**全経路を列挙してレポートすること**(監査結果が「セット済みのみ」ならそれでよい)。

### 3.5 P0のスコープ外(やらない)

- SALARY_PARAMS の変更(P2でFableが較正する)
- 新しい交渉タイプ・セリフ・UI(P1)
- AI団体の contractOVR/contractPop(AI団体は週次給与経済を持たない。移籍金が古い契約値を
  参照しうる点は既知の周辺課題として記録のみ)
- gapLevel 5段階化(P1)

## §4. P1 — 下り交渉カード(ドラマ層。P2較正とOpusセリフの後に実装)

### 4.1 判定比率は「査定比」を使う

昇給側の gapLevel(fair/current)とは別に、下り判定は**査定比 bpRatio = newBP / oldBP** で行う。
fair/current は bonus を分母に含むため「bonusが大きいだけの選手」も拾ってしまう。
下りカードの意味は「査定(基本給部分)が下がる」なので、比較も基本給部分同士で行う。

```
bpRatio ≤ 0.90 かつ 減額幅(oldBP−newBP) ≥ 10万 → decline-mid
bpRatio ≤ 0.75 かつ 同上                       → decline-large
```

### 4.2 trust × decline マトリクス

| trust | attitude | カードの中身 |
|---|---|---|
| 75+ | `decline_voluntary` | 選手から「私はもう全盛期じゃない。下げてくれていい」。選択: **据え置く**(温情: trust+10, morale+3) / **受け入れる**(査定どおり: trust+2 — 誇りを尊重された対等感) |
| 40〜74 | `decline` | 査定減の通告の場。選択: **据え置く**(温情: trust+6, morale+2) / **査定どおり改定**(trust≥60なら±0、<60なら−4) / **厳しく改定**(bonusも清算=給与を適正給ちょうどへ: trust−10、trust<40なら40%で移籍志願へエスカレート) |
| <40 | カードなし | 従来の低trust交渉(昇給要求/移籍志願)が優先。壊れた関係の整理は放出の領分 |

- **据え置きの実装**: 減額幅(oldBP−newBP)を salaryBonus に加算するフラグを選手に立て、
  offWeek3 の再固定が消費する(上限100は維持。超過分は据え置ききれない)
- **枠**: decline系カードは季2枚まで(減額幅の大きい順)。既存の交渉上位4名枠に同居。
  深刻度ソート(25502)は `(gapRatio−1)` が下りで負になり埋もれるため `|gapRatio−1|` に修正
- カード化されなかった下り選手は静かに再固定される(毎年の査定は契約制度として
  織り込み済み、という世界観。隠しペナルティは付けない)
- auto-sim の autoHandleContractNegotiation に新attitudeの自動応答を追加
  (decline: A30/B50/C20%、decline_voluntary: A30/B70%)

### 4.3 セリフ(Opus起案・archetype第一分岐)

CONTRACT_NEGOTIATION_LINES に新phase:
`decline_open` / `decline_voluntary_open` / `decline_hold`(据え置きへの反応 — 感情のピーク) /
`decline_accept` / `decline_strict` / `decline_voluntary_hold` / `decline_voluntary_accept`。
エスカレート後は既存 transfer 系を再利用。

### 4.4 UI

showContractNegotiationModal の attitude 分岐に追加(新画面なし):
バッジ `📉 契約査定`(decline) / `🤝 減俸申し出`(decline_voluntary)、
金額行「現在の週給: X万 → 査定: Y万(−Z万/週)」。色はCSSトークンのみ。

## §5. やらないこと(v0.1から継続+追加)

- ❌ 年齢バンドで給与を自動−N%(下りは査定=シミュレーション実数で駆動する)
- ❌ popBonus の加齢カット(人気は週次減衰と活動判定が既に管理。二重罰にしない)
- ❌ シーズン中の週次減額(給与が動くのは契約更改の場だけ。titleBonus着脱を除く)
- ❌ 給与適正度メーターの常設UI
- ❌ カード化されなかった査定減への隠しtrustペナルティ

## §6. 不変条件(実装時に1つずつ検算する)

1. 再固定は1季にちょうど1回走る(交渉あり季・なし季の両方をテストで確認)
2. `salaryBonus ∈ [0, 100]` を維持(吸収・据え置き・清算のいずれでも負値/超過を作らない)
3. 再固定単体で: 伸びた選手の給与は max(前給, 適正給)±1、衰えた選手の給与は fairBP+bonus(+title)
4. 給与が変わるのはオフシーズン処理と契約交渉のみ(シーズン中の週次で動かない)
5. decline系カードは季2枚まで・trust<40には出さない
6. decline系イベントで trust が上がるのは「据え置き」と「decline_voluntary の受け入れ」のみ
7. レンタル選手は再固定・交渉の対象外(現行維持)

## §7. P2 — 経済較正(Fable担当・task-83マージ後)

再固定が働く世界では全員が適正給を受け取るため、総支出が増える(現状は中央値で適正の2/3)。

1. task-83 マージ後、`WM_SALARY_FIXTURE=1` で40季×2シード計測:
   gap分布(目標: none帯が最頻・gap≥1.3は20%以下 ←現92.7%)、給与総支出/収入比、資金推移、
   ゲームオーバー率(現状0を維持)、退団率・引退年齢分布が現状から大きく動かないこと
2. 資金バランスが壊れる場合のみ SALARY_PARAMS の一律スケール(1.0/0.85/0.7)を40季グリッドで比較
   (スケールは baseA・offset・popMax・titleBonus に同率適用 = bonus以外を k 倍)
3. 採用値の最終確認だけ100季1本
