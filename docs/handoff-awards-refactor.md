## TASK-1: メディア功労賞 全団体対象拡張（データ層）

### 目的
AI団体の選手にもプレイヤー団体と同一精度のメディア収入個人トラッキングを追加する。

### 作業前に確認すること
1. `makeAIFighter` の return オブジェクトに `mediaRevSeason` / `talentRevSeason` / `talentCountSeason` が既にあるか
2. AI団体選手が格納されている場所（`state.rivals[].roster` 等）の構造
3. プレイヤー団体側の加算フック5箇所の実装箇所を特定する（TASK-2で追加されたフック）
4. AI団体側でB4相当処理・PPV・プロモ連動・タレント活動バフがどの関数で処理されているか
5. `resetSeasonalCounters` がAI団体選手にも適用されているか

### 実装内容

#### 1-A. AI団体選手のフィールド確保
- `makeAIFighter` の返り値に `mediaRevSeason: 0`, `talentRevSeason: 0`, `talentCountSeason: 0` がなければ追加
- 既存セーブデータにフィールドがない選手へのフォールバック（`|| 0`）を全参照箇所で担保

#### 1-B. AI団体のメディア収入加算フック
プレイヤー団体と同じ5箇所（※コードを読んで正確な関数名・箇所を特定すること）：

1. **タレント活動バフ週次収入**（processSettlement内のタレント活動バフ分岐）
2. **プロモ連動収入**（プロモイベント収入計算箇所）
3. **PPV出演料**（PPV収入分配箇所）
4. **JT（ジョイントツアー）収入**（JT収入分配箇所）
5. **タレント活動参加カウント**（B4イベント選手選択時）

AI団体で上記に相当する処理を探し、同じように該当選手の `mediaRevSeason` / `talentRevSeason` / `talentCountSeason` に加算するフックを追加する。

**注意**: AI団体の処理がプレイヤーと同じ関数を共有している場合はフック追加不要（既に走っている）。独立した関数の場合のみ追加。コードを読んで判断すること。

#### 1-C. シーズンリセット
- `resetSeasonalCounters` がAI団体選手にも適用されているか確認
- されていなければ、AI団体の全選手にも `mediaRevSeason = 0`, `talentRevSeason = 0`, `talentCountSeason = 0` のリセットを追加

#### 1-D. `selectMediaAward` の候補拡張
現在:
```js
const candidates = [...(state.roster || [])].filter(...)
```

変更: state.roster + 全AI団体のrosterを合算した候補リストに変更。
```js
// 全団体の選手を候補にする
const allWrestlers = [
  ...(state.roster || []),
  // AI団体の選手も追加（構造はコードを読んで確認）
];
const candidates = allWrestlers.filter(f => {
  const score = (f.mediaRevSeason || 0) + (f.talentRevSeason || 0);
  return score > 0;
});
```

返り値に `orgName`（所属団体名）を追加すること。プレイヤー団体の場合は `state.orgName`、AI団体の場合はその団体名。

### 検証
- auto-sim 100シーズン ALL CLEAR
- AI団体選手がメディア功労賞を受賞するケースが発生することを確認（ログ出力等で）

## TASK-3: スライドビルダー関数の書き換え（全7スライド）

### 目的
各賞のDOM生成関数をモックアップのHTML構造に合わせて書き換える。

### スライド順序（この順番で `steps` 配列に push する）

```
0. メディア功労賞（📺）— 該当者なしならスキップ
1. 新人王（🌟）— 該当者なしならスキップ  
2. ベストマッチ（🎬）— 該当なしならスキップ
3. タイトル王者（🏆）— 団体順位順、1位中央・2位左・3位右
4. MVP（👑）
5. 殿堂入り（🏛️）— 該当者なしならスキップ
6. 全受賞者一覧（📜）— 常に表示
```

### 各スライドの仕様（モックアップ準拠）

#### slide-0: メディア功労賞 `_buildMediaAward(d)`
- レイアウト: 左ポートレート＋右テキスト（`.media-layout`）
- 表示項目: 名前、団体名（`d.orgName`）、スタイル、金額大表示（万単位）、内訳2カラム（出演料/タレント活動）、活動回数、セリフ
- セリフ: `AWARD_LINES.mediaAward` から取得（既存実装を確認）

#### slide-1: 新人王 `_buildRookieAward(d)`
- レイアウト: 左ポートレート＋右テキスト（`.rookie-layout`）
- 表示項目: 名前、団体・年齢、タグ3つ（スタイル / OVR / デビュー年目）、セリフ

#### slide-2: ベストマッチ `_buildBestMatchAward(d)`
- レイアウト: 左右対称 fighter + 中央MQ（`.bestmatch-fighters`）
- 表示項目: 2選手ポートレート・名前・団体名、MQ値大表示、★（MQに応じた数）、vs、左右セリフ

#### slide-3: タイトル王者 `_buildChampionsAward(champions)`
- レイアウト: 表彰台式（`.champions-layout`）
- **団体順位順**で表示（1位団体が中央、2位が左、3位が右）
- タイトル未設置の団体は列自体を表示しない
- 順番登場アニメーション（3位→2位→1位、各0.7秒間隔）
- 各王者: ポートレート、ランクバッジ、名前、団体名、防衛回数、セリフ

#### slide-4: MVP `_buildMVPAward(d)`
- レイアウト: 左大ポートレート（王冠付き）＋右スタッツ（`.mvp-layout`）
- スタッツバー: OVR / 人気 / 勝率 / 防衛（防衛0回なら非表示）
- バーアニメーション: スライド表示時に0%から伸びる
- `data-width` 属性にパーセント値をセット、JSで `width` を遅延適用

#### slide-5: 殿堂入り `_buildHallOfFame(d)`
- レイアウト: 中央配置（`.hof-layout`）
- 演出: 金色グロー、✦星ブリンク、金文字名前、プレート（通算成績）、紙吹雪
- 該当者なしの場合はスライドごとスキップ

#### slide-6: 全受賞者一覧 `_buildAwardsSummary(awards)`
- レイアウト: 2列グリッド（`.summary-grid`）
- 全賞のアイコン＋受賞者名＋補足情報
- メディア功労賞も含める
- 殿堂入りがある場合は `full-width` で下段に大きく表示
- 殿堂入りがない場合は殿堂欄を表示しない

### ポートレート表示
- `portrait-map.js` からポートレートを取得
- ポートレートがない場合は既存の絵文字フォールバックを使用
- ポートレートサイズはスライドごとにCSS class で制御（`.portrait-main`, `.portrait-sm`, `.portrait-mvp`, `.hof-portrait`）

### セリフ表示
- 吹き出しは共通仕様（`.speech-bubble`, `#f0f0f0` 背景・黒文字・中央寄せ）
- `AWARD_LINES` の既存カテゴリからセリフ取得
- speaker名を `.speech-speaker` に表示

### 検証
- 全スライドが正しい順序で表示される
- 各スライドのレイアウトがモックアップと一致する
- 該当者なしのスライドがスキップされる
- ポートレート・セリフ・データが正しく表示される

## TASK-4: スライド制御・ナビゲーション・SE

### 目的
スライド切替制御、ナビゲーションUI、SEをモックアップ準拠で実装する。

### 実装内容

#### 4-A. ファンファーレ冒頭演出
- 表彰式開始時に `#fanfare-overlay` を表示（「シーズン N — 年間表彰式」）
- 3秒後にフェードアウトしてスライド表示開始
- フォントは Noto Serif JP / Noto Sans JP（Cinzel不使用）

#### 4-B. スライド制御
- `goToSlide(idx)` 関数: スライド切替、ヘッダー更新、ドット更新、SE再生
- `nextSlide()`: 次スライドへ。最終スライドでは「✕ 閉じる」ボタンになり、表彰式を閉じる
- スライドは動的に構築（殿堂なし・メディア功労賞なし等でスライド数が変動するため）
- スライド切替時の `slideIn` アニメーション

#### 4-C. ドットインジケータ
- スライド数に応じてドットを動的生成
- 現在のスライドに `.active` クラス

#### 4-D. タイトル王者の順番登場
- 3位→2位→1位の順に `.revealed` クラスを付与
- 各700ms間隔
- 1位登場時にMVPファンファーレSE

#### 4-E. MVPスタッツバーアニメーション
- スライド表示時にバーが0%から伸びる
- `data-width` 属性 → `style.width` を遅延適用（200ms + 150ms × index）

#### 4-F. 殿堂入り紙吹雪
- `spawnConfetti()`: 80個、5色、ランダムサイズ・形状・速度
- スライド表示300ms後に発動

#### 4-G. SE（Web Audio）
- **既存のSE関数があればそれを使う。ない場合のみモックアップの実装を参考に追加。**
- 必要なSEパターン:
  - `playChime()` — 通常スライド登場
  - `playMvpFanfare()` — MVPスライド＋タイトル王者1位登場
  - `playHofChime()` — 殿堂入りスライド
  - `playFanfare()` — 冒頭ファンファーレ
- 各スライドの `se` タイプ: メディア功労賞=normal, 新人王=normal, ベストマッチ=normal, タイトル王者=normal, MVP=mvp, 殿堂=hof, 一覧=normal

#### 4-H. パーティクル
- `#particles` に30個のパーティクル要素を動的生成
- 表彰式開始時に生成、終了時に削除

### 検証
- 全スライドがスムーズに切り替わる
- ドットインジケータが正しく連動する
- SE が各スライドで適切に鳴る
- タイトル王者の順番登場が正しく動作する
- MVPバーアニメーションが正しく動作する
- 紙吹雪が殿堂スライドで表示される

## TASK-5: 殿堂入りコーチFG演出

### 目的
殿堂入りスライドに「コーチが画面手前に登場する演出」を追加する。

### 作業前に確認すること
1. `state.coaches` の構造と、選手IDとの紐付け方法
2. コーチのポートレート画像の有無（`portrait-map.js` 形式か、絵文字代用か）
3. 殿堂入り選手が自団体かどうかの判定方法

### 演出の仕様
- **プレイヤー自団体の殿堂入り選手の場合のみ発動**
- 殿堂スライド表示1.4秒後に、画面左下からスライドイン
- レイアウト: `#hof-coach-fg`（`position: fixed`, `bottom: 0`, `left: 40px`）
- 吹き出し（上）＋ポートレート（下）の縦構成
- コーチ未割り当ての場合はコーチ演出なし
- 他スライドに移ったら `.revealed` を外して非表示に
- 他団体の殿堂入りの場合はコーチ演出なし

### セリフ
- `AWARD_LINES.hofCoach` カテゴリを `data.js` に新規追加（3〜5パターン）
- 担当コーチ名を `.speech-speaker` に表示
- セリフ例:
  - 「あの子が本当にすごい選手になりました。指導者冥利に尽きます…。」
  - 「最初に会った頃は不安だらけだったのに…立派になって…。」
  - 「殿堂入りか…私が教えたなかで一番の誇りだよ。」
  - 「この日を見届けられて、コーチ冥利に尽きます。」
  - 「あの子の努力を誰より知っている。おめでとう。」

### CSS
モックアップの `#hof-coach-fg` 関連CSSをそのまま使用（TASK-2で追加済み）。

### 検証
- プレイヤー団体の殿堂入り時にコーチが登場する
- コーチ名・セリフが正しく表示される
- 他スライドに移動したらコーチが消える
- AI団体の殿堂入り時にはコーチが表示されない
- コーチ未割り当ての場合はコーチが表示されない
