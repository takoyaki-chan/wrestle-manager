## ✅ 階層1：Foundations — 確定内容

### 前提となる問題意識

- 既存の `wrestle-manager-design-system.html`（v1.0, 2026-03-26）は**部品カタログ**であり**設計図ではない**
- `src/index.html` では `var(--)` が538箇所使われる一方、ハードコード16進カラーが579箇所残っている
- CLAUDE.md にデザインシステムへの参照が一切ない → Claude Code が実装時に参照していない
- 新画面追加のたびに色味・余白がドリフトし、「古い画面だけ浮いて見える」問題が発生

### 診断

既存の「DARK」テーマが**2つの役割を兼任**していたことが根本原因：

- 役割A：Cream Panel の外枠フレーム（暖色でなければCreamと喧嘩する）
- 役割B：管理系単独画面の背景（暖色である必要はない）
- 役割C：スペクタクル画面の背景（暖色だと締まらない → BLACKが応急処置で生まれた）

歴史的経緯：
- 最初は紺っぽい黒背景でスタート
- CREAM（暖色ベージュ）導入後、紺黒と喧嘩したので暖茶DARKに寄せた
- 現BLACKには過去のネイビーの残り香があり中途半端

### 解決方針：3カテゴリ構造（Office / Stage / Ceremony）

---

### 1. Office（オフィス）

**世界観**：事務所で資料や書類を広げて団体運営をしている。ロスター・殿堂・新聞は全て「事務所の机の上で書類を眺めている」メタファーで統一される。

**背景**：暖茶 `#24221e` 系（事務所の木目・革張りのイメージ）

**パネル様式**は2種類を内包する：

- **Dark Panel**：暗いパネル（ディスプレイ・黒板・モニター的な要素）
- **Cream Panel**：ベージュパネル（紙の書類・資料・ファイルのメタファー）
  - 副次効果：紙っぽい質感（微かなテクスチャ、角の陰影）を与える正当な理由ができる
  - 新聞画面との相性が完璧

**属する画面**：
- スケジュール、財務、道場、興行設定
- ロスター一覧・選手詳細、殿堂、団体設定、データベース・対戦比較
- 新聞、関係性マップ、モーダル類

**トークン命名**：
```
--office-bg            /* 暖茶背景 */
--office-panel-dark    /* 暗いパネル */
--office-panel-cream   /* ベージュパネル */
--office-border-*
--office-text-on-dark-*
--office-text-on-cream-*
```

---

### 2. Stage（ステージ）

**世界観**：試合会場の暗闇。照明と選手と観客だけが存在する非日常空間。

**背景**：純黒 `#060606`（赤み・青みを排除）

**選定理由**：
- 会場背景写真の色味を邪魔しない
- 金アクセントが最も引き立つ
- 暖色だと「暖炉の前で試合を観てる」感じになり緊張感が抜ける
- 過去のネイビー背景の失敗を繰り返さない

**原則**：Cream Panel は**絶対に置かない**

**属する画面**：興行進行（試合中）、試合結果、入場演出、興行終了サマリ

**トークン命名**：
```
--stage-bg             /* 純黒背景 */
--stage-bg-deep        /* より深い奥行き用 */
--stage-panel          /* 情報パネル */
--stage-accent-gold    /* 金アクセント */
--stage-text-*
```

---

### 3. Ceremony（セレモニー）

**世界観**：格式ある式典会場。時間がゆっくり流れる特別な場。厳粛さ。

**背景**：漆黒 `#080604` + ベルベット系装飾

**フォント**：明朝系
- メイン（和文）：**Noto Serif JP**（Weight 500/700/900）
- アクセント（英字）：**Cormorant Garamond**（Weight 500/600/700 italic）

**レイアウト**：全画面テイクオーバー
- トップバー・ナビバー非表示
- 上下レターボックス（任意）
- スライド進行方式
- 通常UIより遅いアニメーション（ease-in-out、600〜1200ms）

**属する画面**：年末表彰式、昇格戦式典、引退セレモニー、殿堂入り発表、メディア功労賞発表、ジュニアトーナメント優勝式

**迷いどころ**（後で決定）：
- タイトル奪取シーン → 基本Stage、ただし歴史的瞬間（10年ぶり奪取など）はCeremony要素を一部混入させる可能性

**詳細は階層4で完全設計する**

---

### 設計原則まとめ

1. Office と Stage は画面内で同居しない。遷移で切り替わる
2. Cream Panel は Office 内にのみ出現する
3. Stage と Ceremony はどちらも非日常だが、Stage = 熱狂、Ceremony = 厳粛 で明確に分かれる
4. 既存 `wrestle-manager-design-system.html` v1.0 は部品カタログとして残す。破棄はしない
5. トークン命名は役割ベース（`--office-*`, `--stage-*`, `--ceremony-*`）

## 🟡 階層2：Layout System — ドラフト（未承認）

### 概念

階層2は**画面の型を何種類か定義する**層。家の設計で言えば「1LDK」「2LDK」「メゾネット」のような間取りのカテゴリ。24画面を全部ゼロから設計する代わりに、「このゲームには X 種類の画面の型がある」と決めて各画面をそのどれかに当てはめる。これで設計コストが激減する。

### 7パターン案（未承認・要レビュー）

**P1. Catalog（カタログ型）**
- フィルタバー＋グリッド/リストで並ぶ
- 使用画面：ロスター一覧、殿堂、ランキング、コーチ一覧、団体設定
- 所属カテゴリ：Office（Cream Panelが並ぶ）

**P2. Detail（詳細型）**
- 1つの対象に集中、縦スクロールでセクション分割
- 使用画面：選手詳細、新聞記事、コーチ詳細
- 所属カテゴリ：Office

**P3. Dashboard（ダッシュボード型）**
- 複数の情報パネルが並列配置
- 使用画面：道場（本拠地）、財務、団体トップ
- 所属カテゴリ：Office（Dark Panel中心）

**P4. Timeline（タイムライン型）**
- 時系列データの横スクロール or 週次表示
- 使用画面:スケジュール、関係性履歴
- 所属カテゴリ：Office

**P5. Workflow（ワークフロー型）**
- 複数ステップを順に進める
- 使用画面：興行設定（会場→マッチカード→最終確認）、ドラフト交渉
- 所属カテゴリ：Office

**P6. Canvas（キャンバス型）**
- 自由配置・インタラクティブ図形
- 使用画面：関係性マップ
- 所属カテゴリ：Office

**P7. Theatrical（劇場型）**
- 全画面演出、トップバー・ナビを隠す（or 透過）
- 使用画面：興行進行、試合結果、入場演出、セレモニー全般
- 所属カテゴリ：Stage または Ceremony

### 各パターンが定義すべき共通ルール（次セッションで肉付け）

- グローバル構造（トップバー高さ、ナビバー高さ、コンテンツ最大幅、ガター）
- 余白ルール
- スクロール挙動
- ブレイクポイント（desktop / tablet / mobile）
- 空状態・読込中・エラー状態の扱い

### 未決事項

- 7パターンで過不足ないか要確認
- 各パターンの共通ルールは次セッションで詰める
- レッスルマネージャーの既存画面で「このどれにも当てはまらない」ものがないか棚卸し要

## 🟡 階層3：Screen Specifications — フォーマット案（未承認）

### 概念

階層3は**個別画面ごとの指示書**。「この画面はどの型を使って、そこに何を何の順で配置して、どういうルールを守るか」を1画面ずつ書いたもの。Claude Code に実装依頼するときの**設計図そのもの**。階層2の型を指定して、そこに固有情報を乗せる形で書く。

### 仕様書フォーマット案（1画面分）

```markdown
### 画面：画面名 (Screen Name)

**所属カテゴリ**：Office / Stage / Ceremony
**パネル様式**：Dark Panel / Cream Panel / なし
**レイアウトパターン**：P1〜P7のどれか
**使用フォント**：本文フォント + ラベルフォント

#### 目的
この画面で何をする場所か、役割と情報提供の主眼

#### 骨格ワイヤーフレーム
ASCII図で画面レイアウトを表現
（各領域の高さ、テーマ色、主要コンポーネントを明記）

#### 構成要素（使用コンポーネント）
- 使用する既存コンポーネントを列挙
- 各コンポーネントの内包要素と配置

#### 情報階層（視線誘導の優先順位）
1. 最優先で見せたい要素
2. 次に目立たせる要素
...

#### 特有ルール
- この画面だけの例外ルール
- インタラクション挙動
- アニメーション

#### 状態バリエーション
- 通常
- 空
- 読込中
- エラー

#### 関連トークン
使用する主なCSS変数
```

## Appendix A：ロスター一覧 仕様書サンプル（階層3の完成イメージ）

```
### 画面：ロスター一覧 (Roster List)

**所属カテゴリ**：Office
**パネル様式**：Cream Panel
**レイアウトパターン**：P1 Catalog
**使用フォント**：Noto Sans JP (body) + Oswald (ラベル)

#### 目的
所属選手を一覧で確認し、個別選手の詳細へ導線する。
コンディション・ロール・ランキングを一目で把握できること。

#### 骨格ワイヤーフレーム
┌─ Top Bar (Office dark, 48px) ─────────────────┐
├─ Nav Bar (Office dark, 40px) ─────────────────┤
├─ Filter Bar (Cream Panel, 44px) ──────────────┤
│  [所属▼] [ロール▼] [検索...]     並替:[OVR▼]  │
├─ Grid Area (Office暖茶 bg)────────────────────┤
│   ┌─Card──┐ ┌─Card──┐ ┌─Card──┐ ┌─Card──┐   │
│   │ Face  │ │       │ │       │ │       │   │
│   │ Name  │ │ ...   │ │       │ │       │   │
│   │ OVR   │ │       │ │       │ │       │   │
│   │ Badge │ │       │ │       │ │       │   │
│   │ Cond  │ │       │ │       │ │       │   │
│   └───────┘ └───────┘ └───────┘ └───────┘   │
│   (4列グリッド、カード間 --space-xl)          │
└────────────────────────────────────────────────┘

#### 構成要素（使用コンポーネント）
- FilterBar（P1共通部品）
- WrestlerCard（Cream Panel, 紙の質感, 角丸 R-LG）
  - 内包：P-2XL face portrait（72x72 円形）
  - 内包：Name (T-HEADLINE)
  - 内包：OVR値 (T-OVR Bebas Neue gradient)
  - 内包：Role Badge / Style Badge
  - 内包：Condition Bar (幅100%, 4px)

#### 情報階層（視線誘導の優先順位）
1. 顔写真（最優先、一番大きい）
2. 名前
3. OVR数値（右上に配置、金色）
4. ロール/スタイルバッジ
5. コンディションバー（最下部）

#### 特有ルール
- 引退選手は opacity 0.4 でグレーアウト
- 新規加入選手は右上に ★ バッジを8週間表示
- ソート変更時は全カードがフェードイン 300ms
- カードホバー時：わずかに浮き上がる（translateY(-2px) + shadow）
- 検索ヒット中は該当しないカードを opacity 0.2 に

#### 状態バリエーション
- 通常：上記
- 空：中央に「所属選手がいません」＋「ドラフトへ」導線ボタン
- 読込中：スケルトンカード × 8 を表示
- エラー：再読込ボタン付きエラーメッセージ

#### 関連トークン
--office-bg, --office-panel-cream, --office-border-cream
--space-xl (カード間), --radius-lg (カード角丸)
--t-headline, --t-ovr
```
