# 既存テキスト修正指示

## 概要

`_renderDbOrgCompare` 内の既存テキスト生成関数を、黒田幸子のトーンに合わせて修正する。
既存テキストは「解説者口調」でフラットすぎるため、黒田の辛辣さと同じ温度感に揃える。

**注意:** これらのテキストは黒田のセリフではなく、マッチアップカード内の解説文。
ただし団体比較タブ全体のトーンを統一するため、黒田のコラムと温度差がありすぎないようにする。

---

## 1. getMatchupCopy() の修正

### エース比較（ace）

| OVR差 | 現行 | 修正案 |
|-------|------|--------|
| ≤-8 | エース比較はかなり厳しい。看板に据えると飲まれて終わる。 | **エース比較？ 話にならない。看板に据えたら向こうのサンドバッグにされるだけだ。** |
| ≤-4 | エース比較は分が悪い。真っ向から当てると主導権を持っていかれやすい。 | **エース比較は正直キツい。真っ向勝負を挑んでも、主導権を握られる展開が目に見えている。** |
| <3 | エース比較は十分勝負になる。ここを五分で持ち帰れれば興行全体が締まる。 | **エース比較は互角。ここを五分で返せるなら、興行の格がまるで違ってくる。** |
| <8 | エース比較はこちらが前に出られる。堂々とメインの顔にして押し切りたい。 | **エース比較は明確にこちらが上。メインの看板に据えて、堂々と押し切ればいい。** |
| ≥8 | エース比較は完全にこちらの土俵。相手の看板ごと食うつもりで前面に出していい。 | **エース比較は圧勝。相手の看板ごと食い潰すつもりで前に出していい。遠慮は要らない。** |

| OVR差 | 現行 | 修正案 |

| <3 | No.2対決は拮抗。ここを取り切れるかで団体の厚み評価が変わる。 | **No.2対決は互角。ここで勝ち切れるかどうかが、団体の「層の厚さ」の証明になる。** |

| OVR差 | 現行 | 修正案 |
|-------|------|--------|

| <8 | No.3比較はこちらが上。下支えの強さとして素直にアピールできる。 | **三番手でも勝っている。層の厚さを示す意味で、一番分かりやすい優位だ。** |

## 4. gradeDesc の修正

Engine.js 内の `getOrgCompareAnalysis()` で生成される gradeDesc。
ここは黒田のヘッドラインと並ぶので、トーンを揃える。

| グレード | 現行 | 修正案 |
|---------|------|--------|
| D | 全面的に劣勢。長期戦略での巻き返しが必要。 | **全面劣勢。正面から勝てる要素がない。** |
| C | 複数項目で差がある。弱点の補強が急務。 | **複数項目で後手。課題が多い。** |
| B | 互角の勝負。戦略次第で十分勝てる。 | **互角。戦略次第で勝てる。** |
| B+ | 優勢。強みを活かせば安定して上回れる。 | **優勢。リードを活かし切れるか。** |
| A | 圧倒的優位。この差を維持したい。 | **圧倒的優位。死角なし。** |

※ gradeDesc は短い補足文なので、簡潔に。詳細は黒田のコラムに任せる。

---

## 5. summaryText の修正方針

Engine.js 内で自動生成される `summaryText` は、黒田コラム（KURODA_EDITORIAL）で完全に置き換える。
**summaryText 自体は残すが、表示上は黒田コラムのほうを優先する。**

既存の `db-cmp-org-summary-note` 内の summaryText は
「団体比較メモ」として残すか、黒田コラムに統合して削除するかはUI実装時に判断。

---

## 実装方法

上記の修正は全て ui-render.js 内の `_renderDbOrgCompare()` 関数内で行う。
engine.js の `getOrgCompareAnalysis()` の gradeDesc も合わせて修正。
