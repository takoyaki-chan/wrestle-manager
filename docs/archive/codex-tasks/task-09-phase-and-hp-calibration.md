## 背景

task-08 の統制比較により、**エンジン自体は正常**であることが確認された。同一カード・全員全快・同一シードなら大一番は通常試合より全帯で +37〜40% 長い（12.2 → 17.0ターン）。最大HP比 1.42倍がそのまま効いており、それを打ち消すダメージ過多も無い。

前回「大一番に起承転結が存在しない」と見えたのは、実運用サンプルの **66.75% が連戦疲労で開始HPが減った試合**（大半が秋の4団体勝ち残り戦）だったことによる誤読である。あれは E-4 の設計が正しく機能している姿だった。

**しかし全快だけを見ても、まだ問題は残っている。**

| | 平均ターン | Climax到達 | Climax平均滞在 |
|---|---|---|---|
| 通常試合 | 12.22 | 50.43% | 1.13T |
| 大一番（全快のみ） | 15.51 | 27.01% | 0.66T |

フェーズ表は通常16ターン・大一番24ターンを想定して組まれているが、実際の試合長と噛み合っていない。**Climax が「段階」ではなく「試合が終わる瞬間」になっている。**

## 本タスクの要点：①と②は同時に較正すること

対処には2つの軸があり、**片方だけでは成立しない**。

- **① フェーズ境界を実測に合わせる** — Climax の開始を前倒しする
- **② 試合そのものを長くする** — HP係数の引き上げ

①だけを行うと、**Climax の高い倍率（通常1.30 / 大一番1.20）と大技重みが前倒しされ、試合がさらに短くなる**。すると Climax 到達率がまた下がり、堂々巡りになる。**フィードバックループがあるため、①②を一体の探索として扱うこと。**

### 併せて対処する既知の課題

**残課題A': フィニッシュ級をクールダウンの対象外にする**

フィニッシュ級の解禁判定は攻撃前に行われるため、**HPを解禁閾値以下に落とす一撃そのものにはフィニッシュ級を使えない**。かつその一撃はたいてい大技なので**クールダウンが立ち、次ターンも使えない**。結果「大技で解禁 → 中技 → ようやくフィニッシュ級」と最短2ターンの遅れが構造的に発生している。

→ **フィニッシュ級（d14〜16）をクールダウンの対象外とする。**「大技で畳み掛けてフィニッシュ」はプロレスとして自然であり、解禁条件（HP閾値）が別途あるため乱発にはならない。

なお通常大技（d11〜13）のクールダウンは**維持する**（大技連打の防止が目的のため）。

**残課題B: 大技の実効上限が約50%**

大技を撃った次のターンは中技以下になるため、`tierW` の大技に50を超える値を設定しても実現しない（Climax 65% → 実測45.12%）。設定値が挙動を表していないため今後の較正で誤解を生む。**探索の結果に合わせて実態に近い値へ書き換えること。**

ただし残課題A' でフィニッシュ級がクールダウン対象外になるため、実効上限は50%より上がる。実測して確定すること。

## 事前調査（実装前に必ず行うこと）

`MAX_T` / 試合ターン数 / 最大HP を変更すると、試合シミュレーション以外へ波及する可能性がある。**実装前に依存関係を洗い出し、報告すること。**

判明している範囲:

- `MAX_T` / `BIGMATCH_MAX_T` の参照は `src/match-engine.js:226` の1箇所のみ
- `Engine.wear` は **HP比（`hpRatio`）ベース**のため、最大HPを変えても連戦消耗の挙動は比率として保たれる見込み

**調査済み（本タスク作成時に確認）:**

- **MQ のペーシング減点は下限のみ**（`match-engine.js` §3、L664付近）。大一番は13ターン以上、通常試合は7ターン以上で減点0。**長い試合へのペナルティは存在しない**ため、試合を伸ばしても MQ 上の不利益はない
  - ※ `docs/design-decisions.md` に「17+=6（だらだら）」という上限減点の記載があるが、これは**古い情報**であり現行コードには存在しない（同ドキュメントは修正済み）
  - なお大一番の理想下限が13ターンであるため、**平均22ターンへ伸ばした後はこの閾値の見直しを検討する余地がある**（全試合が余裕で減点0になり、ペーシング減点が機能しなくなるため）。本タスクでは変更せず、所見として報告すること
- **決着減点はフェーズ連動**（同 §4）。Climax到達率の上昇は MQ を押し上げる（回帰条件を参照）

**未確認のため調査が必要なもの:**

- MQ のその他の項目がダメージ総量・HP残量に依存していないか
- 怪我判定・コンディション消費が試合ターン数に依存していないか
- タッグ試合（`TAG_MATCH_CONFIG`、`maxTotalTurns: 50`）への波及。**本タスクではタッグの較正は行わないが、共通パラメータの変更が影響するなら報告すること**
- セーブデータ互換（HP係数の変更が既存セーブに影響しないか）

依存が見つかり、かつ変更禁止ファイル（`management.js` 等）に手を入れないと解決できない場合は、**実装を止めて報告すること。**
