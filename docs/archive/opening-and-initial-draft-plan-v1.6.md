### 1.1 v1.0からの継承事項

| 論点 | 結論 | 理由 |
|---|---|---|
| 初期ドラフトにセリ機構を入れるか | **入れない** | 「奪い合いのドラマ」は年2回の本編スカウトに集約してこそ希少価値が出る |
| 何を流用するか | **見た目・トーン** のみ | 視覚言語だけ継承、機構は不要 |
| オープニングの方向性 | **社長就任の儀式** | ムービー寄りにせず、静かな演出 |
| 固定2名のセリフ | **書かない** | `generateDraftConfig()` でプレイごとに2名が変わる（`data.js` L335-417）|
| フロー順 | タイトル → 団体設定 → 難易度 → **オープニング** → 初期ドラフト → 本編 | — |

### 1.3 セーブ/ロード処理の設計判断（v1.1新規）

**ロード時スキップは追加実装不要**。理由:

- `Storage.autoSave()` は `completeDraft()` 末尾で初めて呼ばれる（`app.js` L2754）
- opening 中は autoSave が存在し得ない → ロード時は必ず draft 以降の状態が復元される
- opening 中は navBar が非表示なので手動セーブも呼べない（後述 L134 改修）
- → **「セーブデータあり時のオープニングスキップ」は構造上自動的に達成される**

## 2. オープニングシーンの仕様

### 2.1 全体構成

`confirmDifficulty()`（`app.js` L2668）の直後、`weekPhase='draft'` に入る前に新フェーズ `weekPhase='opening'` を挿入する。

### 2.2 演出シーケンス（4幕構成・推定30〜40秒）

各幕は黒地フェード+短文+クリックで進行。スキップ可能。

**幕1: 暗転からの団体名提示**
- BGM `kaimaku`（既存・序曲）をフェードイン
- 黒画面に団体名がタイプライター風に出現
- 続けて短いナレーション1行

**幕2: 立ち上がりの宣言（案II・個に集中）**
- 世界観説明はしない
- 「この団体が今、立ち上がったばかりであること」だけを1〜2行で語る
- 例: 「{年}年、ここに新しい旗が立つ。/ まだ、誰の名前も知られていない。」

**幕3: 仲間の紹介（固定2名の登場・数値非表示）**
- 2名のポートレートが左右からフェードイン
- ナレーションで包む（個別セリフは出さない）
- **名前のみ表示**。OVR/スタイル/ロールは出さない（論点3）
- 例:
  > 「設立メンバーは2名。
  > 　{名前1}と{名前2}。
  > 　名前と顔だけは知っている。これから一緒に、何を見ることになるだろうか。」

**幕4: ドラフトへの導入（案C・ナレーション残存）**
- ナレーション: 「では、仲間を選びに行こう。あと3人。」
- 黒画面はフェードアウトするが、**この一文は画面最上部に残ったままドラフト画面に持ち越される**
- 固定メンバーと候補カードがその下にスライドイン

### 2.3 ナレーション原則

- **テンプレ禁止**（CLAUDE.md準拠）。世界観共通のナレーションとして書くため「テンプレ量産」には該当しない
- **語り口は中立**。黒田風ではない
- 文字数は1幕あたり最大80文字程度。読点で改行
- 動的挿入: `{orgName}` `{season}` `{固定メンバー名}` のみ

### 2.4 スキップ仕様（案P）

- 画面右下隅に `>> skip` を半透明テキストリンクで常時表示
- ESC キーでも反応
- セーブデータからのロード時は構造上自動スキップ（§1.3）

### 2.5 BGM

- `kaimaku` を幕1〜幕4まで継続再生
- **BGM 尺確認済: `bgm/bgm_kaimaku_v1.mp3` = 81.84秒**
- オープニングは 30〜40秒で幕4からドラフト画面に移行するが、`Audio.bgm.playForState()` で draft も kaimaku を返すため、BGM はドラフト前半まで自然に流れ込み、選曲タイミングで `management` に切り替わる
- `Audio.bgm.playForState()` (`app.js` L863) を以下に変更:
  ```js
  if (G.weekPhase === 'draft' || G.weekPhase === 'opening') { BGM.play('kaimaku'); return; }
  ```

### 2.6 ナレーション原稿(確定版)

**動的変数**: `{orgName}` `{name1}` `{name2}` のみ。`{year}` は使用しない(毎回1年目スタートのため演出として死ぬ)。

**フォント**: ナレーション本文は `var(--font-ceremony)` (= Shippori Mincho、儀式専用)、選手名は `var(--font-body)` (= Noto Sans JP、本編連続性)。

#### 幕1 - 旗を揚げる
> 今、ひとつの団体が旗を揚げようとしている。
> 団体の名は「{orgName}」。

#### 幕2 - 弱小団体としての宣言
> 後ろ盾があるわけではない。
> 期待されているわけでもない。
> いつまで経営が続くかわからない弱小団体。
>
> 業界へ爪痕を残すことはできるだろうか。

#### 幕3 - 仲間の紹介(数値非表示・upper画像左右配置)
> 新団体旗揚げの噂を聞きつけ、集まったのは2名。
> {name1}と{name2}。
> 彼女たちと共に、ここから業界への挑戦が始まる。

- 2名の `image/upper/upper_*.webp` を左右からフェードイン (left: translateX(-30px)→0, right: translateX(30px)→0)
- 名前のみ表示。OVR / スタイル / ロールはここでは出さない (論点3確定事項)
- **名前表示はゴシック (Noto Sans JP, 13px, 700, letter-spacing 0.15em) ── 本編との連続性を断ち切らない (v1.3 確定事項)**
- ナレーション本文だけが明朝。名前は本編フォントに統一

#### 幕4 - ドラフトへの導入(案C: draft画面に持ち越し)
> さらに3名。
> 立ち上げメンバーを選びに行こう。

- フェードアウト後、ドラフト画面の最上部にこのテキストブロックが残った状態で表示される
- ドラフト画面の `<div class="draft-narration">` として再描画する方式 (DOM残存より実装容易)
- その下に「数字は推定値。本当の姿は、リングの上でしか分からない。」を小さく添える

#### 完了演出 - §3.5 で使用
> {orgName}
> 始動

- 「{orgName}」と「始動」の二段組み、上が小さく下が大きい
- letter-spacing は「始動」を 0.4em 程度まで広げて重厚感を出す

#### 原稿の作成基準
- 中立ナレーション(黒田風ではない)
- テンプレ表現を使わない(「やったー」「がんばります」など禁止)
- 各幕は最大80字程度
- 「業界」の語は幕2と幕3で1回ずつ計2回(リフレイン効果)
- 「旗を揚げる」(幕1) と「旗は立った」(他案) は時制衝突するため幕2では旗の比喩を使わない

## 3. 初期ドラフトUI刷新の仕様（案α: 部分移植）

### 3.1 何を変えるか・何を変えないか

| 項目 | 扱い |
|---|---|
| 候補6名から3名選ぶ基本ルール | **変えない** |
| 資金チェック・契約金システム | **変えない**（既に新システム準拠） |
| ライバル団体の介入 | **入れない** |
| 既存の `STYLE_META` / `ROLE_META` / `makeStatBars` | **そのまま流用** |
| ヘッダー文言 | 刷新（より儀式的に） |
| セクションラベル | **`news-sec-label` 構造**を移植（縦罫線+小見出し+トラッキング広め英字） |
| 二段見出し | 「FIRST ROSTER / 設立に集う5名」のような階層構造 |
| マーク表記（◎○△） | **使わない**（他団体の興味度なので初期ドラフトには無意味） |
| コーチ評価バッジ | 「コーチ所感」枠として再構成（`scout-quote` 装飾を流用） |
| 確定ボタンの演出 | 強化（「就任」感を出す） |

### 3.2 持ち込まないもの（ダークUIに浮く要素）

- ❌ 紙テクスチャ（`#f8eed2`/`#f0e0ba` 系の paper 背景）
- ❌ `--ink` 系インク色（既存の `--gold`/`--text` を維持）
- ❌ Bebas Neue / Oswald フォント
- ❌ 赤タイトルバー

### 3.3 トーン変更のポイント

現状ヘッダー（`ui-render.js` L262-269）:
> 「あなたの団体には2名の所属選手がいます。候補6名の中から3名を選んで...」

→ よりドラマ寄りに:
> 「あと3人。
> 　この中から、あなたの団体の最初のシーズンを共に戦う仲間を選ぶ。
> 　数字は推定値。本当の姿は、リングの上でしか分からない。」

### 3.4 案Cによる繋ぎの実装

幕4の最終ナレーションが画面最上部に残った状態でドラフト画面が描画される。具体的には:

- `renderOpeningScreen()` が幕4で出力した「では、仲間を選びに行こう。あと3人。」のテキストブロックを**そのまま DOM に残したまま**、その下に `weekContent` がフェードイン
- もしくは `renderWeekScreen()` のドラフト分岐の最上部に同じテキストを描画（CSS transition でスライドイン）
- 実装容易性から後者を推奨

### 3.5 完了演出（案X・5名横並び）

`completeDraft()`（`app.js` L2727）の現状:
- 5名分の `showEventPopup` を 100ms間隔で順次表示

→ 以下に変更:
- 既存の順次ポップアップは削除
- 全画面オーバーレイで **5名の `image/upper/upper_*.webp`** を横並び表示
- 各画像は 256×384 縦長 (2:3)。940px コンテナで1人約180px幅で表示可能
- 並び順: 固定メンバー2名を両端、選択した3名を中央（左固定 → 選択3名 → 右固定）
- 「{orgName}、始動」というナレーションで締める
- フェードアウト → 通常の本編画面（`weekPhase='manage'`）へ

## 4. 影響範囲とコード変更ポイント（v1.1新規・実装ガイド）

| ファイル | 行 | 改修内容 |

| `src/ui-render.js` | L262-269 | 初期ドラフトのヘッダー文言とセクションラベル装飾を刷新 |

### 4.2 触らない箇所

- `Engine.createInitialState`（`management.js` L9726）の `weekPhase: isDraft ? 'draft' : 'manage'` は**触らない**
- 理由: ここを変えると auto-sim（test/auto-sim.js）が壊れる
- opening への遷移は `confirmDifficulty()` 側で上書きする設計

### 4.3 auto-sim への影響

- **影響なし**。tickWeek (`management.js` L9100台) は `'manage'` 以降のフェーズしか扱わない
- `'opening'` は `'draft'` と同様、ゲーム開始前の特殊フェーズとして tickWeek の外側で完結する
- ただし validPhases 配列への追加は必須（§4.1）

### 4.4 セーブデータ互換性

- 既存セーブには `weekPhase: 'opening'` は含まれない → 互換性問題なし
- セーブからのロード時は draft 以降の状態が復元され、opening は実行されない（§1.3）

## 6. やらないことリスト

CLAUDE.md「やらないこと」に倣って、本作業で**やらない**ことを明示:

- ❌ 初期ドラフトに他団体を入れる（案B/Cは却下済み）
- ❌ 固定2名にキャラ別セリフを書く（プレイごとに変わるため破綻する）
- ❌ オープニングを長尺ムービー化する（30〜40秒以内）
- ❌ オープニングにプレイヤー操作を入れる（クリック進行とスキップのみ）
- ❌ 新ドラフトの「マーク（◎○△）」を初期ドラフトに転用する（意味が違う）
- ❌ 既存の契約金システム・資金チェックロジックの変更
- ❌ 紙テクスチャ・赤タイトルバーなど新聞テーマのフル移植
- ❌ 幕3 で固定2名の能力値を表示する（論点3で確定）
- ❌ 幕2 で世界観の説明をする（論点6で確定）
- ❌ `Engine.createInitialState` の `weekPhase` 初期値の変更（auto-sim を壊す）
- ❌ ロード時スキップの明示実装（構造上自動達成される）

## 7. リスクと懸念

| リスク | 対策 |
|---|---|
| ナレーションがテンプレ臭くなる | 実装時にレビュー。中立トーンで「個に集中」を貫く |
| オープニングが長すぎてスキップされる | 4幕30〜40秒以内に収める。各幕クリックで即進行 |
| 案Cの繋ぎが技術的に難しい | DOM残存方式ではなく `renderWeekScreen` 内に同テキストを再描画する方式で代替可 |
| 集合写真5名がモバイル幅で破綻 | upper画像 (2:3) を縦横比維持で `flex` 配置、最小幅で1名60px程度まで縮退許容 |
| validPhases 追加忘れ | ステップ2を最初に実行することで防止 |
| `kaimaku` BGMの尺がオープニングに対して短すぎる/長すぎる | ステップ1の最後に確認、必要ならループ再生 |
