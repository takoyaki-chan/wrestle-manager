> 仕様書 `battle-ui-spec-v1.0.md` の§10に挙げた未策定事項を、次回すぐ議論に入れるようにまとめたもの。各項目に「現状」「決めるべきこと」「選択肢・論点」を記載。

## 1. フェーズ遷移演出

### 現状
- バトルエンジンには4フェーズがある: Opening → Mid → End → Climax（ビッグマッチも同じ4段階、ターン配分が違う）
- 現行のフェーズ遷移時の演出:
  - 中央パネルのpillテキストがフラッシュ（`pill.classList.add('flash')`、0.6秒）
  - `sfx.phaseChg()` SE（短い電子音）
  - ライバリーカットインの判定（`tryRivalryCutin`）
  - ビッグマッチのClimaxフェーズ突入時は親フレームにBGM切り替え通知
- 視覚的にはpillのフラッシュだけなので、正直フェーズが変わったことに気付きにくい

### 決めるべきこと
- 新UIでフェーズ遷移をどう視覚的に見せるか
- HUDバーやパネルの色調がフェーズで変化するか
- Climax突入時に特別な演出を入れるか（BGM切り替えとの連動はある）

### 選択肢・論点
- **案A: HUDのPHASE表示の強調のみ**（現行の延長。pilのフラッシュを派手にするだけ）
- **案B: パネル全体の色調変化**（Opening=青灰、Mid=通常、End=やや赤み、Climax=赤+ゴールド強調。スキャンラインやビネットの色がじわっと変わる）
- **案C: Climax突入時のみ特別演出**（暗転+テキスト「CLIMAX!」表示。他フェーズは控えめ）
- 実装タイミング: Phase 1（レイアウト刷新）と一緒にやっておくと二度手間にならない
- ライバリーカットインはPhase 3（カットインシステム刷新）で対応するので、ここでは視覚演出のみ

## 2. 勝利演出

### 現状
- 現行の勝利画面 (`renderResult`):
  - 暗いオーバーレイの上にresult-boxが表示される
  - 勝者のface画像（丸枠）+ 勝者名（Bebas Neue 48px、ゴールドグラデーション）+ 決まり手テキスト + 勝利セリフ
  - SE: finChime（和音チャイム）→ 0.8秒後 victoryFanfare（ブラスファンファーレ）
  - 引き分けの場合は「DRAW」テキストのみ
- 勝者の表示にはface画像（56px丸アイコン）しか使っていない

### 決めるべきこと
- 新UIでは画像をupper or fullのどちらに変えるか
- 画面構成（オーバーレイ形式を維持するか、画面全体を使うか）
- 決まり手・勝利セリフの表示方法
- 勝利演出のタイムライン（現行は段階的にフェードイン: box→画像→名前→決まり手→セリフ→CLOSEボタン）

### 選択肢・論点
- **画像**: upper画像（勝者の正面ポートレート、表情が見える。感情表現向き）が自然。full画像は対戦カードで使ったので差別化の意味でもupperが良いかもしれない
- **構成**:
  - 案A: 現行オーバーレイの画像をupperに差し替えるだけ（最小工数）
  - 案B: 画面全体を使った勝利画面（パネルを消してupper画像を大きく表示、名前・決まり手をかっこよく配置）
- bellx3（カンカンカン）はフォール勝ちでは鳴らないがギブアップ勝ちで鳴る。この使い分けは維持するか
- 引き分けの演出は現行のままでいいか

## 3. ピンフォール / ギブアップ演出（FINISH CLICK SYSTEM）

### 現状
- 現行には「FINISH CLICK SYSTEM」という独自の演出がある:
  - 大技が入ってHP0以下になると、即座に終了せずに「フォール/ギブアップ判定画面」に入る
  - 暗転オーバーレイ + サスペンスドローン（不穏な持続音、heartbeat付き）が流れ始める
  - 実況テキストで煽り（「入ったか…！？ スリーカウントなるかーーーっ！！」等、5パターンランダム）
  - 画面下部にパルスするボタン（例:「3カウント…！」）が出る
  - プレイヤーがクリック → カウント演出（countPop: 72pxの数字がドンドンと出る）
  - 判定: キックアウト成功の場合は「返したーーーっ！！」+ 粘り（grit）バフ発動。失敗なら3カウントで決着
  - ギブアップ版も同様（ロープブレイク判定）
- この演出はプロレスの「カウント2.9で返す」緊張感を再現する重要なシステム

### 決めるべきこと
- 新UIのデザインに合わせた視覚的な調整
- カウント数字の表示位置・デザイン（現行は画面中央に72px）
- サスペンスドローンは維持するか（音のシステムは良い。視覚側の問題）
- 暗転オーバーレイのデザイン（現行はradial-gradientの暗幕）
- フォールボタンの見た目（現行は赤→ゴールドのグラデーション枠、パルスアニメ付き）
- キックアウト時のflash演出（現行は `finish-flash` + `kickout-flash`）を新ダメージ表現体系とどう統合するか

### 選択肢・論点
- 基本的にFINISH CLICK SYSTEMのロジック・フロー自体は完成しているので、**視覚デザインの差し替え**が主な作業
- ダメージボイス（§7-3）との連携: 決着直前のカウント演出中にダメージボイスを入れる余地がある
- キックアウト成功時の「返した」演出に、カウンター演出と同じ「防御側フラッシュ」を流用できるかもしれない
- ギブアップ時のbellx3（カンカンカン）は現行で良い演出なので維持したい

## 4. PPVマッチカード

### 現状
- full画像の3箇所活用のうちの2つ目
- PPV興行（Grand Finalなど）の開始前に全カード一覧を見せる画面
- 既存の仕様書: `ppv-grand-final-spec-v2.0.md`
- 1興行あたり3〜5試合が入る
- 現行ではPPVマッチカード的な演出画面は未実装

### 決めるべきこと
- レイアウト（縦並び or グリッド or 横スクロール）
- 各カードに表示する情報量（選手名だけか、スタイル・戦績・タイトル情報も入れるか）
- 1画面に全試合入れるか、スクロールが必要か
- 対戦カード紹介画面（§2-1で確定済み）のデザインとの統一感
- PPVの規模感を見せる演出（通常興行との差別化）

### 選択肢・論点
- 対戦カード紹介画面はポスター構図（左右にfull画像+中央テキスト）で確定しているので、PPVマッチカードはそれを**縮小版で縦に並べる**のが自然かもしれない
- 3試合なら1画面に収まるが、5試合だとスクロール or 小さめ表示が必要
- 「PPVポスター」としての一枚絵感を出すなら、全試合を1画面に詰め込みたい
- 各カードをクリックして、そのカードの対戦カード紹介画面（§2-1）に入る導線が必要

## 5. 練習画面の選手詳細（馬体確認）

### 現状
- full画像の3箇所活用のうちの3つ目
- ウィニングポストの馬体確認画面がイメージ元
- 練習画面（道場画面）で選手をクリックしたときに表示
- 既存の `showFighterPopup` はupper画像+能力値+感情情報を表示する汎用ポップアップ
- 馬体確認はそれとは**別の画面**として設計する（目的が違う: セリフ・感情ではなく身体の状態確認）

### 決めるべきこと
- full画像の横に表示するフィジカル情報の最終リスト
- レイアウト（full画像が左で情報が右？ それとも逆？）
- full画像の表示サイズ（画面の何%を占めるか）
- showFighterPopupとの導線（馬体確認画面から既存ポップアップに遷移できるか）
- この画面への遷移方法（選手クリック→即馬体確認？ それとも既存ポップアップ内にボタン追加？）

### 表示候補（引き継ぎドキュメントから）
- コンディション
- 疲労 / wear
- 今週の練習メニュー
- trainCapとの距離（成長伸びしろ）
- 怪我リスク
- ※セリフや感情ではなく「身体の状態」が目的

## 6. BGM/SE詳細調整

### 現状
- Web Audio APIで全SEを生成している（外部音声ファイルなし）
- 今回のUI刷新で追加・変更したSE:
  - bigmoveCharge: 低音ライザー（溜め音）— 新規
  - bigmoveImpact: 重い衝撃音 — 新規
  - counterSE: 重い衝撃ノイズ「バケッ！」— 差し替え（旧: 高音ピョン）
  - cutinSlide: 短い高音スワイプ — 新規
  - dmgVoice: 鈍い低音 — 新規
- 既存SEで残っているもの: hitStrike/Throw/Sub/Aerial/Ground/Rollup、missSE、kickoutSE、guEscapeSE、heartbeatSE、count、finImpact、finChime、gong/gongStart、bellx3、phaseChg、victoryFanfare、hover/select/deselect/lockIn/fightStart/ready
- BGMは親フレーム側で管理（battle-engine.htmlはiframe）

### 決めるべきこと
- 新規SEの音色が実際の試合フローの中で自然かどうかの通し確認
- 各SEの音量バランス（現行で音量差が気になる箇所があるか）
- 対戦カード遷移時のゴング音（gongStart）のタイミング微調整
- 既存SEの中で新UIに合わなくなったものがあるか

### 論点
- SEの調整は実際に通しで試合を流しながらでないとわからない部分が多い
- Phase 7（統合テスト）で合わせてやるのが効率的
- 大きな音色変更が必要になった場合はその場で対応

## 7. getUpperUrl リファクタ

### 現状
- `getUpperUrl(id)` という関数が `data.js` にあるが、実際にはstand画像のパス（`image/stand/stand_{name}.webp`）を返している
- 関数名と実態が完全にミスマッチ
- battle-engine.htmlの立ち絵表示はこの関数を使っている
- 新UIではstand画像（パネル表示用）とupper画像（カットイン用）を明確に使い分ける必要がある

### 決めるべきこと
- リファクタ方針: 
  - A: `getUpperUrl` を `getStandUrl` にリネーム + 新規 `getUpperUrl` をupper画像パス用に作成
  - B: `getUpperUrl` はそのまま残して `getStandUrl` を新規追加 + upper画像用の `getUpperPortraitUrl` 等を別名で追加
- 呼び出し元の全箇所洗い出し（battle-engine.html内 + 他のファイル）

### 論点
- 方針Aが意味的に正しいが、他ファイルから `getUpperUrl` を呼んでいる箇所があると破壊的変更になる
- Phase 0（下準備）で機械的にやれる作業。実装時にClaude Codeでgrepして全箇所確認すればよい
- `getFullUrl(id)` の追加もこのタイミングで一緒にやる

## 優先度の提案

| 優先度 | 項目 | 理由 |
|---|---|---|
| **高** | 1. フェーズ遷移演出 | Phase 1実装前に決めないと二度手間 |
| **高** | 3. ピンフォール/ギブアップ演出 | 試合のクライマックスに直結。ダメージボイスとの連携もある |
| **中** | 2. 勝利演出 | 決着後の画面。upper画像に差し替えるだけならシンプル |
| **中** | 7. getUpperUrlリファクタ | Phase 0で機械的にやれる。方針だけ決めればよい |
| **低** | 4. PPVマッチカード | full画像活用だがバトル画面本体とは独立。後回し可 |
| **低** | 5. 練習画面の選手詳細 | 同上。バトルUI刷新後でも問題ない |
| **低** | 6. BGM/SE調整 | 統合テスト時に合わせてやるのが効率的 |
