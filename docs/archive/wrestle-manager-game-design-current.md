## 1. ゲームの全体像

### 1.1 コンセプト

**女子プロレス団体経営シミュレーション**。プレイヤーは弱小団体のオーナーとして選手をスカウト・育成し、興行を組み、ライバル団体を超えて業界の頂点を目指す。

| 項目 | 内容 |
|------|------|
| ジャンル | 団体経営シミュレーション |
| プレイヤーの役割 | 団体オーナー（プロデューサー型） |
| 試合 | AI自動進行＋ビジュアル観戦 |
| 配布形態 | 単一HTMLファイル（ZIP同梱画像） |
| 技術構成 | バニラJS、フレームワーク不使用 |

### 1.2 ゲーム目標

| 種別 | 条件 |
|------|------|
| **勝利** | 団体ランキング1位（EMPRESSを超える） |
| **敗北** | 借金1,000万円超でゲームオーバー |
| **クリア後** | 永続プレイ可能 |

### 1.3 v0.1設計からの主な変化

v0.1は「バトルエンジンの再設計」がスコープの中心だった。現在は以下が大きく拡張・変化している：

- **ライバル団体AI（3団体）** — v0.1では「優先度：中」だったものが、ゲームの中核コンテンツとして完全設計・実装済み
- **経済サバイバル** — 「序盤は赤字前提」の厳しい経営バランスが確立。サバイバルゲージとして可視化
- **移籍・引き抜きシステム** — 四半期ごとの移籍ウィンドウ、エース認定、レンタルなど、v0.1時点では未構想だったシステム群
- **ミッションシステム** — ゲーム進行のガイドとなる目標システムの追加
- **ビジュアルバトルエンジン統合** — iframe内でリアルタイム観戦できる演出システム
- **アーキテクチャの5原則確立** — Engine純粋関数化、GameState不変化など、コードの品質基盤が確立
- **コーチのティア再編** — v0.1のS/A/B 3ティアから、実装では専門/全般/MQ/POPの4種8名体制に発展

## 2. 時間の流れ — シーズン構造

### 2.1 年間カレンダー

| 項目 | 値 |
|------|---|
| 1シーズン | 48週（4四半期 × 12週） |
| オフシーズン | 4週間 |
| 定期興行 | 24回（2週に1回） |
| 特別興行 | 3回（Q1〜Q3末） |
| PPV | 1回（Q4末 — 年間最大の大会） |

### 2.2 週間サイクル

ゲームの基本リズムは**2週サイクル**。

| 週 | 種別 | プレイヤー操作 |
|:--:|:----:|--------------|
| 奇数週 | 非興行週 | 練習/プロモ/休養の指示、カード編成準備 |
| 偶数週 | 興行週 | マッチカード確定、興行実行、結果確認 |

### 2.3 年間イベントカレンダー

| 時期 | イベント |
|------|---------|
| Q1第12週 | Q1末特別興行 |
| Q2 | 春の入団テスト（スカウト） |
| Q2第12週 | Q2末特別興行 |
| Q2末〜Q3末 | 対抗戦（30%/シーズン） |
| Q3 | 夏の入団テスト（スカウト） |
| Q3第12週 | Q3末特別興行 |
| Q4 | 新人王トーナメント（20歳以下） |
| Q4第12週 | PPV（全タイトルマッチ必須＋条件次第で頂上決戦） |
| シーズン後 | オフシーズン4週間（引退・スカウト・AI処理） |

### 2.4 オフシーズン処理

4週間で以下を自動＋手動処理する：

1. コンディション全回復・怪我回復
2. 引退判定（年齢・古傷・後遺症に基づく）
3. AI団体のシーズン末一括処理（成長・衰退・人気変動・引退・スカウト・AI間移籍）
4. 契約更新・給与再計算
5. メインスカウト（オフ第2週）
6. ランキング再計算

## 3. 選手システム

### 3.1 パラメータ体系（5種・200段階制）

| パラメータ | 略称 | スケール | 役割 |
|-----------|------|---------|------|
| Power | PWR | 0〜200（実質上限130-140） | 打撃・投げのダメージ基礎値 |
| Speed | SPD | 0〜200（実質上限130-140） | 行動順・回避率・飛び技スケール |
| Technique | TEC | 0〜200（実質上限130-140） | 命中率・カウンター率・関節技スケール |
| Stamina | STA | 0〜200（実質上限130-140） | HP算出・被ダメ軽減 |
| Mental | MNT | 0〜100（固定・成長しない） | キックアウト・ギブアップ耐性・粘り |

**実力の目安**：

| 値域 | 意味 |
|------|------|
| 30-50 | 新人 |
| 50-90 | 一般〜中堅 |
| 90-100 | トップ層 |
| 100超 | 「こいつ強くなったな」ライン |
| 130-140 | 育成で到達しうる現実的な天井 |

### 3.2 数値レイヤー構造

選手の能力には4層のレイヤーがあり、プレイヤーに見えるのは「現在値」だけ。

```
入団時の値 < Notion値 ≤ trainCap ≤ 潜在値 ≤ 200
```

| レイヤー | 名称 | 公開 | 説明 |
|---------|------|:----:|------|
| 現在値 | value | ✅ | プレイヤーが見る実際のステータス |
| Notion値 | notionValue | ❌ | 「一人前になった時の能力」の内部基準 |
| 育成上限 | trainCap | ❌ | ニューゲームごとにランダム生成 |
| 潜在値 | potential | ❌ | 理論上の才能の天井 |

**潜在値公式**: `min(185, round(初期値 × 1.3 + 60))`  
→ 弱キャラほど高倍率で伸びる設計。弱者も育成で実用圏に到達可能。

### 3.3 戦闘スタイル（6種）

| スタイル | 特徴 |
|---------|------|
| Striker | 打撃主体、安定ダメージ |
| Grappler | 投げ・フォール狙い |
| Submission | 関節技・ギブアップ狙い |
| Aerial | 飛び技・ハイリスクハイリターン |
| Allrounder | 万能型 |
| Brawler | ラフファイト |

分布: allrounder(25), striker(14), submission(14), grappler(12), brawler(9), aerial(6)

### 3.4 ヒール度（4種）

| ヒール度 | 分布 |
|---------|:----:|
| ベビーフェイス | 34名 |
| ニュートラル | 30名 |
| ヒール | 14名 |
| ダーティ | 2名 |

### 3.5 選手のライフサイクル

```
入団（15〜17歳）→ 若手期（高成長）→ 黄金期（安定成長）→ 全盛期（成長鈍化）
→ ベテラン期（衰退開始、30歳〜）→ 引退（35歳〜確率判定、39歳確定）
```

### 3.6 固有特性（traits）— 設計完了・未実装

30種の特性を4カテゴリに分類。1キャラ2〜4個割り当て。

| カテゴリ | 例 |
|---------|---|
| バトル系（10種） | 鉄壁、爆発力、速攻、カウンターの女王 など |
| 成長系（6種） | 天才、大器晩成、努力の人、鉄の体 など |
| 経営系（6種） | スター性、名勝負製造機、ドル箱、カリスマ など |
| メンタル系（6種） | 逆境○、闘志、威圧感、負けず嫌い など |
| 複合・特殊（2種） | エースの器、後輩育成 |

マイナス特性は最大1個。マイナス持ちはプラス特性を1個多く持てる。

## 4. バトルエンジン（v4.1b tuneB）

### 4.1 設計思想

「結局パワーとHP上げゲーにならない」よう、5パラメータすべてが勝敗に有意に影響する構造。

### 4.2 毎ターンの処理フロー

```
1. 行動順決定 — SPD差＋モメンタムで確率決定
2. 技選択（AI）— フェーズ・スタイルに応じてtier別重み選択
3. 命中判定 — 大技ほど外れやすい（TEC攻撃補正 vs SPD回避補正）
4. ダメージ計算 — パラメータ × 技スケール × フェーズ乗数 × モメンタム × ランダム
5. カウンター判定 — 攻撃成功後に防御側が切り返す可能性
6. 決着判定 — HP0以下 or フォール狙い or 特殊条件
7. モメンタム更新
```

### 4.3 フェーズ制（試合の4段階）

| フェーズ | ターン | ダメージ乗数 | スタイル技確率 |
|---------|:-----:|:----------:|:------------:|
| Opening | 1-4 | ×0.9 | 20% |
| Mid | 5-8 | ×1.05 | 40% |
| End | 9-12 | ×1.2 | 55% |
| Climax | 13-20 | ×1.4 | 70% |

### 4.4 技テーブル

全160技を6カテゴリ × 4ティアで構成。スタイル専用技プール併設。

| カテゴリ | 主スケール | 決着傾向 |
|---------|----------|---------|
| Strike | PWR | フォール向き |
| Throw | PWR＋TEC | フォール高確率 |
| Submission | TEC＋MNT | ギブアップ狙い |
| Aerial | SPD | ハイリスクハイリターン |
| Ground | TEC | 制圧型 |
| Rollup | TEC | 番狂わせ（丸め込み） |

### 4.5 決着タイプ

| 決着 | 条件 | 特徴 |
|------|------|------|
| フォール | HP≤0 + 投げ/打撃系 | MNTでキックアウト判定（最大2回） |
| ギブアップ | HP≤0 + 関節技系 | MNTで脱出判定 |
| フォール狙い | HP<30%で発動 | 途中決着の緊張感 |
| 丸め込み | Rollup技 + HP≤25% | 番狂わせ枠 |
| TKO | 打撃連続被弾 | レフェリーストップ（低確率） |
| タイムアップ | ターン20超過 | HP残量比較で判定勝ち or ドロー |

### 4.6 粘りバフ（Grit）

キックアウト成功時に発動。2ターン被ダメ-20%、カウンター率+10%。「返した直後のブーストドラマ」を演出。

### 4.7 逓減関数（eff()）

100超えのパラメータが戦闘計算でインフレしないよう、逓減関数で有効値に変換。育成の上限到達感を担保。

## 5. 育成・トレーニング

### 5.1 プレイヤーの判断ポイント

選手ごとに毎週、3択を選択：

| 選択 | 効果 | コンディション消耗 |
|------|------|:----------------:|
| 練習 | パラメータ成長 | -5 |
| プロモ | 人気UP（能力成長なし） | -2 |
| 休養 | 回復のみ | 0 |

### 5.2 成長の仕組み

成長は才能に自然に引っ張られ、ランダム要素もある。MNTは成長しない（先天固定）。

```
growth = base × coachMul × ageMul × condMul × random
```

- **年齢による成長率変化**: 新人期1.3 → 若手期1.15 → 黄金期1.0 → ベテラン0.4 → 晩年0.1
- **Notion値への収束**: Notion値以下なら加速、超えたら鈍化
- **trainCapでの天井**: trainCapを超えると成長はほぼ停止

### 5.3 コーチシステム（8名、同時雇用最大3名）

| コーチ種別 | 人数 | 効果 | 週コスト |
|-----------|:----:|------|:------:|
| 専門コーチ（PW/SP/TE/ST/MN） | 5名 | 専門ステ×2.0、他ステ×1.2 | 25〜40万 |
| 全般コーチ | 1名 | 全ステ×1.4 | 30万 |
| MQコーチ | 1名 | 担当選手の試合MQ+3 | 30万 |
| POPコーチ | 1名 | 担当選手のプロモ人気+1 | 20万 |

1コーチあたり最大4名担当、1選手につき1コーチまで。

### 5.4 強化練習

任意で選択可能な高リスク高リターンオプション：
- 成長×1.5
- コンディション消耗2倍
- 8%で練習負傷（1-2週離脱）
- 体調50以上、最大2週連続まで

### 5.5 施設アップグレード（5施設 × 3段階）

| 施設 | 効果 |
|------|------|
| トレーニング施設 | 練習効率UP |
| 医療施設 | 怪我回復速度UP |
| メディア施設 | プロモ効果UP |
| 選手寮 | コンディション回復UP |
| スカウト網 | スカウト候補の質UP |

## 6. コンディション・怪我

### 6.1 コンディション

0〜100の値。試合・練習で消耗、休養で回復。低いと怪我リスク増大＋パフォーマンス低下。ローテーション管理が必須のゲーム判断を生む。

### 6.2 怪我

| 重症度 | 離脱期間 | 強行出場 |
|--------|:-------:|:-------:|
| 軽傷 | 1-2週 | 可（悪化リスクあり） |
| 中傷 | 3-6週 | 可（悪化リスク大） |
| 重傷 | 8-16週 | 不可 |

### 6.3 古傷・後遺症

- **古傷**: 累積型。同じ部位の怪我が蓄積すると発生
- **後遺症**: 隠蔽→発覚→克服の3段階。低確率で乗り越えられる
- **引退勧告**: 後遺症3個以上で引退を勧告

## 7. MQスコア＋人気システム

### 7.1 MQスコア（マッチクオリティ）

試合ごとに算出される0〜100の品質評価値。

```
MQ = Base（実力）+ Drama（見せ場）+ Pacing（試合長）+ Finish（決着）+ Bonus（外部補正）
```

| MQランク | スコア | 勝者への影響 | 敗者への影響 |
|---------|:-----:|:-----------:|:-----------:|
| ★★★★★ 歴史的名勝負 | 90+ | 人気 大UP | 人気 UP |
| ★★★★ 名勝負 | 70-89 | 人気 UP | 人気 微UP |
| ★★★ 好勝負 | 50-69 | 人気 微UP | 変動なし |
| ★★ 凡戦 | 30-49 | 変動なし | 人気 微DOWN |
| ★ 塗試合 | 29以下 | 人気 微DOWN | 人気 DOWN |

### 7.2 人気（二層構造）

| 人気の種類 | 影響先 |
|-----------|--------|
| **個人人気** | 集客力、グッズ収入、MQ基礎点、スカウト時の団体魅力 |
| **団体人気** | スポンサー収入、会場規模上限、スカウト候補の質、ランキング |

### 7.3 Heat（団体の勢い）

5段階のHeatランクが集客倍率を決める。毎週自然減衰するため、常に熱いカードを組み続ける必要がある。

| ランク | 集客倍率 |
|-------|:-------:|
| ICE | ×0.6 |
| COLD | ×0.8 |
| NEUTRAL | ×1.0 |
| HOT | ×1.2 |
| BLAZING | ×1.4 |

### 7.4 ライバル度（個人間の因縁）

4段階: NONE → KNOWN → RIVAL → FEUD  
繰り返し好勝負・タイトル争いで因縁が深まる。RIVAL以上で決着戦を組むと、ライバル度消費→両者人気大UP。

## 8. 経済システム

### 8.1 設計の核心

「序盤は赤字前提」。サバイバルゲージで黒字化への進捗を可視化。Heatが経済を動かす構造。

### 8.2 収入源

| 収入 | 備考 |
|------|------|
| 興行収入 | 観客数×チケット単価。最大の収入源 |
| グッズ収入 | 人気選手に依存 |
| スポンサー | 団体人気に連動 |
| 放映権 | 団体ランクに応じた定期収入 |

### 8.3 支出項目

| 事務運営費 | 20万/週（固定） |
| 興行開催費 | 会場規模に応じたコスト |

### 8.4 会場（6段階）

## 9. タイトル/ベルトシステム

### 9.1 3階級制

タイトルはゲーム開始時に存在しない。団体の成長に応じてプレイヤーが設立する。

| タイトル格 | デフォルト名 | 設立条件 | championScore |
|:---------:|:-----------:|---------|:------------:|
| メジャー | 無差別級王座 | 選手16名＋準メジャー存在＋人気30+ | 30 |
| 準メジャー | ハイパーファイト王座 | 選手12名＋マイナー存在 | 20 |
| マイナー | ライジング王座 | 選手8名以上 | 10 |

名称はプレイヤーがいつでも自由に変更可能。

### 9.2 防衛義務

12週（3ヶ月）に1回防衛戦を組む義務。怪我等で組めない場合はタイトル返上。

### 9.3 ジュニアチャンピオン

タイトル（ベルト）ではなくシーズン限定称号。Q4に20歳以下を対象にトーナメント開催。受賞者は人気+10、成長ボーナス。

## 10. スカウトシステム

### 10.1 年2回のビッグイベント

| 回 | 時期 | 候補人数 |
|:--:|------|:-------:|
| 第1回 | オフシーズン第2週 | 8〜10名 |
| 第2回 | Q3第5週 | 4〜6名 |

### 10.2 情報の不完全性

潜在値もtrainCapも見えない。「この子は化けるかも」の直感と賭け。

### 10.3 契約金方式

即戦力度（現在値）と才能度（潜在値）の複合評価で契約金が決定。安い原石 vs 高い即戦力のトレードオフ。

### 10.4 他団体との競合

逸材ほどAI団体も狙ってくる。

| 候補ランク | AI競合率 |
|:---------:|:-------:|
| 逸材 | 80% |
| 有望 | 40% |
| 原石 | 10% |

### 10.5 選手の出自

スカウト候補にはNotionデータベースの既存80キャラが「登場年齢」に達した時点で出現するほか、ランダム生成の新人も混ざる。

## 11. ライバル団体AI

### 11.1 3つのAI団体

| 略称 | 正式名 | ティア | ゲーム上の役割 |
|:----:|--------|:-----:|-------------|

### 11.3 AI団体の行動パターン

AI選手もフルセットの能力値を持ち、プレイヤー団体と同じ計算式で成長・衰退する。ただし毎週処理ではなくシーズン末に一括更新。

### 11.4 団体間インタラクション

| システム | 概要 |
|---------|------|
| **エース認定** | 各団体1名限定。引き抜き防御100% |

| **頂上決戦** | ランキング2位以上＋PPV週。シーズン最終盤の大一番 |
| **AI間移籍** | AI団体同士での選手移動もシーズン末に発生 |

### 12.1 評価値の構成

## 16. まとめ — v0.1からの変遷

v0.1設計書は「バトルエンジンの再設計」と「5パラメータの200段階化」が中心で、「レッスルエンジェルス型ゲームの骨格をどう組むか」を探る段階だった。

現在のv0.97は、**11本の仕様書に基づいた本格的な団体経営シミュレーション**として、以下が確立している：

1. **週間サイクル＋年間カレンダー** — 48週制で興行、特別興行、PPV、オフシーズンが構造化されたリズム
2. **4層パラメータ＋才能収束型育成** — 「あとどれだけ伸びるかは育ててみないとわからない」偶然性
3. **MQ→人気→経済→経営判断の循環** — 試合の質が経営を駆動する設計
4. **3つのライバル団体AI** — 顔の見える対戦相手との移籍・引き抜き・抗争ドラマ
5. **経営サバイバル** — 序盤赤字から黒字化への緊張感
6. **堅牢なアーキテクチャ** — 純粋関数＋不変GameState＋seed乱数の5原則

v0.1の「設計フェーズ（コーディング着手前）」から約2日間で、7,794行の実動するゲームと11本の仕様書を生み出した開発速度は驚異的であり、v1.0配布に向けた残タスクは主にバランス調整、特性実装、配布準備の3点に集約されている。
