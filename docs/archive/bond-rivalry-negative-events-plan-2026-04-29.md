# Bond/Rivalry の数値が原因で発火するネガティブイベント 設計プラン

作成日: 2026-04-29

## Context

「bond が低いことによって起こるネガティブイベント、または bond/rivalry の数字が原因で起こるネガティブイベント」
を網羅的に洗い出し、空白地帯を補う追加施策を確定するためのプラン。

絞り込み基準:
- ✅ 含める: `bond < X` `rivalry ≥ Y` のように **bond/rivalry の値そのものが if 条件**になっているもの
- ❌ 除外: A-1〜A-4 のような契約離脱イベント(bond/rivalry は結果として動くだけ)、
  M-03/M-15 等の試合結果起点(マッチ結果がトリガー)、G1〜G4 給与不満、O-08 突然離脱(trust トリガー)

仕様の正は `specs/relationship-system-spec-v2.0.md` / `v2.2.md`、実装は `src/relationships.js` / `src/management.js` / `src/ui-render.js`。

## 2. 空白地帯(追加施策で埋める対象)

- **Z-1**: 試合中の Bond ペナルティが存在しない(Rivalry MQ ボーナスの裏返しが無い)
- **Z-2**: タッグ/カード編成画面で bond/rivalry の警告・ペナルティが無い
- **Z-3**: 突然離脱・不出場確率に bond/rivalry が直接乗っていない(trust 経由のみ)
- **Z-4**: Bond 単独低帯トリガーがほぼ無い(複合条件ばかりで「冷淡」帯が空白)
- **Z-5**: 興行全体の orgPop / 動員への bond/rivalry 直結効果が無い
- **Z-6**: 中間嫌悪帯(bond 20-30 ∧ rivalry 30-50)のグリンプス・セリフが薄い
- **Z-7**: コーチング/育成への bond/rivalry 反映が W-3 の ×1.15 のみ ← **今回不採用**
- **Z-8**: 集団効果(3名以上の険悪)が線形和止まり、相転移が無い
- **Z-9**: W-1 の発火が確率5%でプレイヤーが気付きにくい(視覚化弱)
- **Z-10**: 険悪状態を解消する修復チャネルが無い

## 3. W-4 (M-07) 1.5%/週 の確率検算 → 要キャップ

毎週独立判定の場合、条件維持期間別の発火確率:
- 1年(52週): **54.4%**
- 2年(104週): **79.2%**
- 3年(156週): **90.5%**

**決定**: **キャラ生涯1回上限**を入れる。一度覚醒した選手は二度目の覚醒イベントを起こさない。
独立のメンテ修正として今回ついでに入れる。

## 4. UI 表現(1-C)強化

### 強化方針: 内部分類を UI に表出させる
- 相関図画面で `pure_hatred` `bitter_feud` 等の**極端ペアだけ**日本語ラベル表示
- ラベルは**シンプル**(短語、文学的に凝らない) — 例: 「憎悪」「因縁」など2-4文字
- 中間帯はラベルなし(存在感を持たせる必要のある関係だけ可視化)
- ペア線の色味/太さで関係性の険悪度を可視化(数字は出さない)
- 詳細パネル展開時に該当ペアの直近グリンプス履歴(U-3/U-4)を表示

### 残論点(実装時確定)
- ラベル候補語: 「憎悪」「因縁」等の短語の最終確定

## 5. 採用提案リスト

### P-1【最優先】タッグ編成 Bond ペナルティ + 警告
- **空白**: Z-1 / Z-2
- bond ≤ 20 のパートナー: **試合中の全能力 −3**(設定ステータスを下げる扱い、試合内部ロジック非依存)
- tag-call 演出オフ、試合後 trust −1
- 編成画面では赤色マーカーと一言警告
- **MQ ボーナス/ペナルティは入れない**(MQ 排除方針)
- **依存**: タッグマッチ仕様 v0.1 が動いている前提。タッグ未実装ならその実装後に着手

### P-2 中間嫌悪帯グリンプス追加
- **空白**: Z-4 / Z-6
- `bond ≤ 25 ∧ rivalry < 30` を「coldness(冷淡)」として新スナップショット種別追加
- 「お互いの存在を見ないようにしている」フレーバー、月1回上限、orgPop 影響なし

### P-3 興行への波及(逓減パーセンテージ)
- **空白**: Z-5
- **動員ボーナス**(該当タグペア=pure_hatred/bitter_feud を含むカードごと):
  - 1カード目: +5%
  - 2カード目: +3%
  - 3カード目: +2%
  - 4カード目以降: +1%
  - 上限合計: **+12% 程度**(発散防止)
- **アクシデント率(敵対派閥との単発試合のみ)**: 通常 X% → **約2倍**
  - 具体値はベース率次第で +5pt 〜 +10pt の範囲で調整
  - ベース率は実装時にコードを読んで確認してから確定

### P-4 派閥的険悪閾値(段階的相転移、簡素化)
- **空白**: Z-8
- 同団体内で `bond ≤ 30` ペアの数で段階発火:
  - **3組**: ロッカー荒廃モーダル(orgPop −1、全体 morale −2)
  - **5組**: 派閥スピンオフイベント抽選(派閥システムと接続)
- ❌ 「分裂の予兆」+ 練習効率低下: 不採用
- ❌ 三角嫌悪: 不採用
- ✅ **嫌悪伝染**: empathic 系性格の選手が、自分の Bond ≥ 60 の親友(A)が誰かを Bond ≤ 15 で嫌っているのを目撃すると、その対象への Bond −1〜−2(月1回)
- **派閥システム未実装の場合**: 5組派閥スピンオフ部分は保留マーカーを入れて先送り。3組ロッカー荒廃 + 嫌悪伝染は先行実装

### P-5 コーチング bond 反映 ❌不採用

### P-6 修復チャネル(社長室の決裁メニュー)
- **空白**: Z-10
- **対象**: W-1 状態の発火が累計 4 回以上のペア(慢性的険悪)
- **形式**: 社長室の**決裁メニュー**として常駐(回数無制限)
  - 社長アクションポイント: **2 pt**
  - 金銭コスト: **¥1,000,000**
- 成功で双方向 bond +5〜+10、失敗で据え置き(rivalry には触らない)
- shachoshitsu spec と接続

### P-7 険悪可視化(アイコン + セリフ)
- **空白**: Z-9
- **相関図**: 険悪マーカー(ペア線/接続点)
  - 絵柄: 火花/稲妻は既存使用済みのため避け、**人物系の険悪表現**(怒った表情、睨み合う2人のシルエット、口論する人物アイコン等)
  - トリガー: U-1/U-2 タグ持ちペアのみ(`pure_hatred` / `bitter_feud` = rivalry ≥ 60 ∧ bond ≤ 30)
  - 数字は出さない、絵のみ
- **ロッカー画面**: アイコン表示はしない
  - **団体画面上のバナー領域(選手アイコン+セリフ表示)**で、低 bond / 高 rivalry の選手から「練習中の独り言」風セリフとして**恨みつらみ/敵意のこもった言葉**が混ざるようにする
  - 既存「練習中セリフ」表示の語彙バリエーションに、険悪状態専用のフレーズプールを追加する形
  - 例: 「あいつのこと考えると練習に身が入らない…」「次に当たったら絶対…」
- 数値影響なし、純演出枠
- **残論点**: アイコン具体絵柄、セリフ本数(初版5-10本程度)

### P-8 完全断絶 (Cold Severance)
- **空白**: Z-4(bond 単独低帯)
- トリガー: `bond ≤ 10 ∧ rivalry < 30`(無関心の極地)
- 効果: 月1回、片方の trust −0.5、専用スナップショット「視線も合わせない」
- ❌ 派閥またぎ強化は不採用(冷たい関係は派閥対立とは別軸のドラマなので絡めない)

### P-9 ナレーション・グリンプス
- **空白**: Z-4 / Z-6
- **bond 低帯のペアに対するナレーション型グリンプス**
- 視点は**1つ**(記者または解説者の三人称視点)に統一、その視点内で言い回しのバリエーションを 5 本用意
- トリガー:
  - `bond ≤ 15` ペアが同興行出場時、月1回程度
- パターン例:
  - 「○○と××は、控え室で一度も目を合わせなかったという」
  - 「インタビュー後、○○は××の名前を口にしなかった」
  - 「リング上ですれ違った瞬間、空気が凍ったように見えた」
- 初版5本、数値影響なし、純演出枠

## 6. 検証方針

- 全提案が `relationships.js` / `management.js` 編集 → **auto-sim フックが自動で回る**
- 数値リバランス系(P-3 / P-4 / P-8): **100×100(10,000シーズン)の手動テスト推奨**
- UI 系(P-1 / P-6 / P-7 / P-9 / 1-C 強化): **ユーザー手動確認**

## 7. 実装方針

- **P-1〜P-9 + 1-C UI 強化を一括実装**(段階的コミット)
- 派閥システム未実装の場合は **P-4 の 5組派閥スピンオフ部分**だけ保留マーカー
- P-1 はタッグマッチ仕様 v0.1 の実装状況に依存。未実装ならタッグ実装後に着手
- W-4 (M-07) 生涯1回キャップは独立のメンテ修正として同梱
- 同一ブランチで段階的にコミット → auto-sim 検証 → コミット

## 8. 実装着手時に確認する残論点

- **P-3 アクシデント率**: 既存ベース率をコード確認後に「約2倍」の具体値を確定
- **P-7 相関図アイコン**: 人物系の絵柄具体デザイン
- **P-7 ロッカー険悪セリフ**: 専用フレーズプールの本数
- **1-C UI ラベル候補語**: 「憎悪」「因縁」等の短語確定
- **タッグ仕様実装状況**: P-1 着手可否の判断
- **派閥システム実装状況**: P-4 5組部分の先行実装可否
