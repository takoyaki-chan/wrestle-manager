# MQ改修仕様書 ドラフト v0.1

---

## 改修の目的

1. キックアウトバグ修正に伴うbaseMQ上昇を吸収しつつ、正しいドラマ評価を実現する
2. 「長すぎ」ペナルティを撤廃し、決着した長期戦を正当に評価する
3. 外部MQソースの整理・削減により、キャップ+15内での意味ある差別化を実現する
4. タイトルマッチ・ファン期待カードに集客・盛り上げ効果を新設する

---

## A. baseMQ改修

### A-1. キックアウトバグ修正

**現状**: fall/tko からのキックアウト成功時に `totalKickouts++` が抜けている。
**修正**: fall/tko キックアウト成功時にも `totalKickouts++` を追加。

```javascript
// engine.js 354-361行目 — fall/tko キックアウト
if (fType === 'fall' || fType === 'tko') {
  const koChance = B.calcKickoutChance(def, ph, eng);
  if (Engine.rng.float(rng) < koChance) {
    escaped = true;
    def.hp = Math.round(def.mhp * 0.05);
    def.kickoutCount++;
    def.gritTurns = eng.gritDuration;
    totalKickouts++;  // ★ 追加
    log.push(`  → ${def.name}がキックアウト！ Grit発動！`);
  }
}
```

**影響**: baseMQが平均10〜15点上昇する → §A-3で吸収する。

### A-2. ペーシング減点の変更

**現状**: ターン数が理想帯を超えると「長すぎ」ペナルティ-6。
**変更**: 「長すぎ」ペナルティを撤廃。短すぎ（スコアッシュ）ペナルティは維持。

| ターン数 | 現状 | → 改定 |
|:--------:|:----:|:------:|
| **通常マッチ (MAX_T=20)** | | |
| 7〜14 | 0 | 0 |
| 5〜6 | -3 | -3 |
| 15〜16 | -3 | **0** |
| <5 | -12 | -12 |
| >16 | -6 | **0** |
| **ビッグマッチ (MAX_T=24)** | | |
| 13〜21 | 0 | 0 |
| 10〜12 | -3 | -3 |
| 22〜23 | -3 | **0** |
| <10 | -12 | -12 |
| >23 | -6 | **0** |

**設計意図**: 決着がついた長期戦は熱戦。タイムアウトは決着減点-10で既に罰されている。

**影響**: baseMQがさらに最大+6上昇する → §A-3で吸収する。

### A-3. ドラマ減点パラメータ再調整（要検討）

A-1とA-2でbaseMQが大幅に上がるため、ドラマ減点で吸収する必要がある。

**方針案**: ドラマ減点の初期値を30から引き上げる or 各回復量を引き下げる。

→ **ここは auto-sim 100シーズンで検証してから決定**。数値を仮置きして回し、現在と同等の分布になるよう調整する。Claude Code実装時のタスク。

## B. 外部MQソース改定

### B-1. 値の変更

| # | ソース | 現状 | → 改定 | 変更理由 |
|---|--------|:----:|:------:|----------|
| ① | タイトルマッチ | +10 | **+5** | キャップ圧迫の最大原因。+5でも外部ソース中最大級 |
| ② | ファン期待カード | +5 | **+2.5** | 期待＝MQ向上ではない。半減 |
| ④ | 好敵手 | +2 | +2 | 維持 |
| ⑤ | 宿怨 | +3 | **+2** | 好敵手と同格 |
| ⑫ | ラストラン基本 | +3 | **+2** | 引退試合の重み自体は維持、値を抑制 |
| ⑬ | ラストランメイン | +5 | **+3** | メインに置いた報酬は残すが抑制 |

### B-2. カーブ変更

**③ライバル因縁 MQボーナス**

| rivalry | 現状 | → 改定 |
|:-------:|:----:|:------:|
| 0〜44 | +1 (30+) | **0** |
| 45〜54 | +2 | **+1** |
| 55〜64 | +2〜+3 | **+2** |
| 65〜79 | +3〜+4 | **+3** |
| 80+ | +5〜+6 | **+4** |

```javascript
// 改定後
getRivalryMQBonus(rivalry) {
  if (rivalry == null || rivalry < 45) return 0;
  if (rivalry < 55) return 1;
  if (rivalry < 65) return 2;
  if (rivalry < 80) return 3;
  return 4;
}
```

### B-3. 削除

| # | ソース | 理由 |
|---|--------|------|
| ⑥ | 一方的因縁 MQ+1 | イベント発生原因として残す。MQソースからは外す |
| ⑧ | ケミストリー +1 | 削除 |
| ⑭ | ラストラン因縁相手 +3/+5 | 削除 |
| ⑮ | 見返しモード +2 | MQである必要なし。代替効果は別途検討 |
| ⑯ | コスチュームデビュー +2 | 同上 |
| ⑱ | 野心 +1 | 特性の効果として別途再設計 |

### B-4. 維持（変更なし）

| # | ソース | 値 |
|---|--------|:--:|
| ⑦ | pendingClashBonus | +1〜+2 |
| ⑨ | プロモスタック | +1.3〜+3.9 |
| ⑩ | 会場熱気 | +1〜+3 |
| ⑪ | 会場規模 | +0〜+3 |
| ⑰ | カード鮮度（初顔合わせ） | +2 |

### B-5. 改定後の理論最大

通常ケース（ラストランなし）:
タイトル(5) + ファン期待(2.5) + 因縁max(4) + 好敵手(2) + clash(2) + プロモ(3.9) + 会場熱気(3) + 会場規模(3) + 鮮度(2) = **27.4** → キャップ+15

ラストラン込み最大:
上記 + ラストラン(2) + ラストランメイン(3) = **32.4** → キャップ+15

**通常プレイでの想定レンジ: +5〜+12**
- 前座（鮮度+2のみ）: +2
- 中堅カード（因縁+2, プロモ+1.3, 会場+2）: +5〜+6
- メインイベント（タイトル+5, 因縁+3, プロモ+2.6, 会場+4）: +12〜+15（キャップ）
- 全部盛り: +15（キャップ、余裕あり）

→ キャップ+15を維持しても、通常プレイで飽和しにくくなった。

## C. 集客乗算ボーナスの変更

集客計算は加算式: `totalMult = 1.0 + titleBonus + champBonus + charismaBonus + rivalryBonus + ...`（上限2.0倍）

### C-1. タイトルマッチ集客ボーナス

MQ +10 → +5 に減らした補填。

| | 現状 | → 改定 |
|--|:----:|:------:|
| 集客ボーナス | +0.15 | **+0.20** |

### C-2. ファン期待カード集客ボーナス（新規）

MQ +5 → +2.5 に減らした補填。現状集客効果なし → 新規追加。

| | 現状 | → 改定 |
|--|:----:|:------:|
| 集客ボーナス | なし | **+0.08** |

calcAttendance 内の totalMult 計算に `fanExpectBonus` を加算する。
ファン期待カードが複数ある場合は1件あたり+0.08の加算（totalMultの上限2.0で自然にキャップ）。

### C-3. 既存（変更なし）

| 要素 | 値 | 備考 |
|------|:--:|------|
| 王者がカードにいる | +0.10 | 維持 |
| 華トレイト | +0.05 | 維持 |
| ライバル因縁 | 最大+0.08 | 維持（rivalry60+、カード位置で変動） |

## D. マンネリ（カード鮮度）緩和

### D-1. ペナルティ値: 固定 → ランダム幅 & 最大値引き下げ

| 対戦回数(ウィンドウ内) | 現状 | → 改定 |
|:----------------------:|:----:|:------:|
| 1〜2回目 | 0 | 0 |
| 3回目 | -3（固定） | **-1〜-3（ランダム）** |
| 4回目 | -5（固定） | **-2〜-4（ランダム）** |
| 5回目+ | -8（固定） | **-3〜-5（ランダム）** |

**設計意図**:
- 最大-8 → 最大-5 に引き下げ。-8が毎週続く重圧を解消
- ランダム幅で毎回微妙に違う評価 → 「はっきりしすぎ」問題を解消
- ランダムソースは週次rngから派生

### D-2. ウィンドウ: ロスター規模で可変

| ロスター人数 | 現状 | → 改定 |
|:------------:|:----:|:------:|
| 8人以下 | 12興行 | **8興行** |
| 9〜12人 | 12興行 | **10興行** |
| 13人以上 | 12興行 | 12興行（維持） |

**設計意図**:
- 小規模団体はカード被りが構造的に避けられない
- ウィンドウを縮めることで「古い対戦が早く忘れられる」
- 小規模のファンは同じカードへの許容度が高い、という世界観

### D-3. AI自動編成への影響（変更なし）

| 判定 | AI挙動 |
|------|--------|
| マンネリ（3回目） | priority降格 |
| 深刻なマンネリ（4回目+） | 完全除外 |

→ AI側の閾値は `freshnessResult.bonus` の値で判定しているので、ランダム化しても自然に追従する。
