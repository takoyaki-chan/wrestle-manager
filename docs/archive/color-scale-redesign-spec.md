# 数値カラースケール 再設計仕様

## 背景・問題意識

現状、ゲーム内の数値表示には統一されたカラーリングルールがない。
`gold / green / text-sub` を場当たり的に使い分けているだけで、
「数字が高いほど色が輝く」という視覚的スケール感がない。

PPV TV観戦画面のMQカラー議論で確立した原則をゲーム全体に適用する。

---

## 設計原則

### 1. 色はスケールである

数値の高低を「色の系統ごと変化する温度スケール」で表す。

- **低い** → 冷たい色（青灰系）
- **中間** → 中性〜暖色系
- **高い** → 暖かい色（琥珀〜金系）

単に明るさを変えるだけでなく、色相ごと変わることで
「どの帯にいるか」が一目でわかる。

### 2. どの帯でも「見える」色を使う

序盤はMQ40・OVR55台が当たり前。その状況でずっと暗い色を
見せ続けるのはプレイヤー体験として辛い。
低い帯にも「この数値はこのレベル」と読める固有の色を割り当てる。

### 3. 相対的でなく絶対的なスケール

色はゲームフェーズによって変化しない。
MQ40はいつでも同じ色。プレイヤーが「この色 = このレベル」を
ゲームを通じて学習できるようにする。

## 共通カラースケール（6段階）

```
S帯  80+  #f0d078  明るい金（glow付き）  ← 名勝負・最高水準
A帯  70+  #d4a843  金                    ← 好試合・一流
B帯  60+  #c4853a  琥珀                  ← 良い・中の上
C帯  50+  #b89870  くすんだ暖色          ← 並・標準
D帯  40+  #8090a8  スチールブルー        ← 平凡・中の下
E帯  40未 #607080  冷灰                  ← 低水準・要改善
```

グロー（`text-shadow`）はS帯のみ。他帯には付けない。

## 実装方針

### ヘルパー関数として一元管理

`ui-common.js` または `ui-render.js` に共通ヘルパーを追加し、
各所で個別定義していたカラー分岐を置き換える。

```js
// 共通6段階スケール
function mqColor(mq)   { return _scale6(mq,  [80,70,60,50,40]); }
function ovrColor(ovr) { return _scale6(ovr, [85,75,65,55,45]); }
function trustColor(t) { return _scale6(t,   [80,65,50,35,20]); }
function condColor(c)  { return _scale6(c,   [90,75,60,45,30]); }
function popColor(p)   { return _scale6(p,   [70,55,40,28,15]); }
function bondColor(b)  { return _scale6(b,   [80,65,50,35,20]); }

const _SCALE6 = ['#f0d078','#d4a843','#c4853a','#b89870','#8090a8','#607080'];
function _scale6(v, thresholds) {
  for (let i = 0; i < thresholds.length; i++) {
    if (v >= thresholds[i]) return _SCALE6[i];
  }
  return _SCALE6[5];
}
```

### 置き換え優先順位

1. MQ（表示箇所が多く効果が大きい）
2. OVR（選手カード全体に影響）
3. Trust（団体画面・ポップアップ）
4. Condition（興行準備・選手ポップアップ）
5. Popularity / Bond / Rivalry（ポップアップ・相関図）
6. orgPop（ヘッダー・収支）

### 注意事項

- **グロー（text-shadow）はS帯のみ**。多用しない
- **背景色に使う場合**はopacity 15-20%に落とす（`color + '26'` など）
- **バー（progress bar）**は同色を使う。glowは不要
- 既存の `.mq-gold` `.coach-effect.mq` などクラス名は残しつつ
  CSS変数で色だけ差し替えると影響範囲が最小
