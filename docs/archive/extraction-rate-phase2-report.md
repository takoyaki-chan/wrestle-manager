# 引き出し率システム Phase 2 検証レポート

**検証日**: 2026-03-09
**検証スクリプト**: `test/extraction-rate-phase2.js` (10シード × 8シーズン)

---

## 1. 検証目的

Phase 1 で判明した「trainCapベース天井は機能しない」問題を受け、提案D（速度乗数・イベント乗数・achievableMax天井）の3要素を個別・複合で検証し、目標OVR差15前後を達成するパラメータセットを特定する。

**目標値**:
- 放置 vs 全力 OVR差: **15前後**
- ワンランク逆転（下位全力 vs 上位放置）: **確実に成立**
- 2ランク逆転: **ギリギリ接近〜逆転が可能**

---

## 2. 重要な発見: 天井メカニズムの否定

**trainCap天井は逆効果。achievableMax天井も不採用。**

調査の結果、キャラクターの実質的な成長上限はtrainCapではなく **ageMultiplier**（27歳以上で成長率0）であることが判明。

```
trainCap (top tier stat平均)    = ~162
convergence閾値 (trainCap × 0.15) = stat ~137 で減速開始
実測ピークOVR                    = ~76 (trainCapの47%)
```

キャラクターはtrainCapやconvergenceに到達する遥か手前で、ageMultiplierによる成長窓（age 17-26）の終了で頭打ちになる。

trainCapを引き下げる天井メカニズム（achievableRatioBase=0.55）を適用すると、convergence閾値がstat ~75付近まで降下し、全品質レベルで早期減速→差別化が崩壊した。achievableRatioBase=1.0の「緩やかな天井」でもfullcareの成長上限を抑制する方向に作用し、OVR差は5-9に縮小。

**結論: 速度乗数 + イベント確率乗数のみで設計する。天井は不使用。**

## 4. 推奨パラメータ (Set I)

```
qualitySpeedMul = 0.00 + quality × 1.70
  放置(Q=0.10): ×0.17   普通(Q=0.45): ×0.77   全力(Q=0.84): ×1.43   溺愛(Q=0.96): ×1.63

qualityBTMul = 0.00 + quality × 2.20
  放置(Q=0.10): ×0.22   普通(Q=0.45): ×0.99   全力(Q=0.84): ×1.85   溺愛(Q=0.96): ×2.11

qualitySlumpMul = 4.00 - quality × 3.80
  放置(Q=0.10): ×3.62   普通(Q=0.45): ×2.29   全力(Q=0.84): ×0.81   溺愛(Q=0.96): ×0.35
```

**適用対象** (4箇所):
1. **練習成長** (`Engine.growth.calcGrowth`): `result × qualitySpeedMul`
2. **試合成長** (`GROWTH_CONFIG.matchGrowthBase`): `base × qualitySpeedMul`
3. **ブレイクスルー確率** (`Engine.growthEvents.calcBreakthroughProb`): `prob × qualityBTMul`
4. **スランプ確率** (`Engine.growthEvents.checkSlump`): `prob × qualitySlumpMul`

**不使用**: achievableMax天井、convergenceRatio変更、フラットボーナス

## 7. 残っている課題と懸念点

### 7-1. ティア間のOVR差ばらつき
top/upper/lowerで14-15達成だが、middle=12.3、bottom=10.9で目標15に不足。低ティアは成長余地（ageMultiplier窓内の蓄積可能量）が小さく、均一乗数では構造的にOVR差が縮小する。完全均一化には、ティア依存の乗数調整か、成長モデル自体の変更が必要。

### 7-2. 放置側のOVR低下
放置（speed ×0.17）ではS1初期値より低いOVRに沈む場合がある（例: bottom放置 43.3→41.5）。slump×3.62の影響で成長量をスランプ損失が上回るため。「手をかけないと衰退する」はゲーム設計意図に合致するが、AI団体選手にも適用される点に注意。

### 7-3. quality値の算出方法
本検証は固定Q値（0.10/0.45/0.84/0.96）でテストしたが、実装時には「プレイヤーの行動」→「quality値」の変換ロジックが必要。出場頻度・ケアアクション・コーチ割当て・スケジュール等の行動履歴から逆算する仕組みの設計が別途必要。

### 7-4. AI団体への適用
AI団体のquality値をどう決めるか。ティア別にQ=0.40-0.55あたりの固定値を使うのが自然。プレイヤー団体の放置選手（Q≈0.10）とAI団体選手（Q≈0.45）のOVR差が自然になるよう調整が必要。

### 7-5. 未パッチの成長イベント
現行パッチはBT確率とスランプ確率のみ。以下も品質乗数の対象とすべきか要検討:
- **ホットストリーク**: BT成功時15%で発生（BT確率パッチで間接的に品質依存済み）。効果量（+15%成長）自体の変更は未検討
- **モチベーション低下**: スランプとは別の負のイベント。低品質でより発生しやすくするのは設計意図に合致

### 7-6. 長期バランス
S8-S9ではageMultiplierの低下により全品質レベルのOVRが停滞・低下する。引き出し率の効果は主にS2-S6（age 18-24）の成長窓に集中する。30歳以降の選手には引き出し率がほぼ無効になるため、ベテラン選手の差別化には別の仕組み（経験値ボーナス等）が必要になる可能性がある。
