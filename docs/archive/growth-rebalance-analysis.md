# 選手成長リバランス v1.0 — バランス検証レポート

## 検証概要

growth-rebalance-design-v1.0 の実装後コード（engine.js / data.js）をベースに、プレイヤー団体 vs S級AI団体のOVR推移を **Monte Carlo 2,000回** でシミュレーションし、成長の内訳を分析した。

## 2. 根本原因: 試合成長がseasonBudget外で無制限に加算されている

### 2.1 プレイヤーの成長内訳（逸材テンプレート、1シーズン分）

| 年齢 | ageMul | 練習成長 | 試合成長 | 合計 | OVR換算 |
|------|--------|---------|---------|------|---------|
| 17歳 | 0.8 | 18.4pt | 23.2pt | 41.6pt | +8.3 |
| 21歳 | 1.3 | 19.0pt | 23.3pt | 42.3pt | +8.5 |
| 25歳 | 1.0 | 18.6pt | 23.3pt | 41.9pt | +8.4 |
| 27歳 | 0.6 | 15.1pt | 23.2pt | 38.3pt | +7.7 |

### 2.2 AI S級の成長（同条件）

| 年齢 | ageMul | seasonBudget | OVR換算 |
|------|--------|-------------|---------|
| 17歳 | 0.8 | 10.7 | +2.0 |
| 21歳 | 1.3 | 17.4 | +3.2 |
| 25歳 | 1.0 | 13.4 | +2.1 |
| 27歳 | 0.6 | 8.0 | +1.0 |

### 2.3 問題の構造

```
プレイヤー年間成長 = 練習成長(~19pt) + 試合成長(~23pt) = ~42pt
AI年間成長         = seasonBudget × 共有ロジック          = ~13-17pt

→ プレイヤーはAI S級の 2.5-3倍 の速度で成長
```

**試合成長が成長全体の55-60%を占め、ageMultiplierの影響をほぼ受けない。**
matchGrowthBase = 0.7 は年齢に関係なく固定で、24試合/シーズン × 0.97pt/試合（期待値）= 23.2pt。
これだけでAI S級の seasonBudget 全体（17.4pt）を超えている。

### 2.4 ageMultiplier が機能していない

設計書では「12シーズンかけて段階的にピーク到達」を目指したが、試合成長が支配的なため、ageMultiplierが 0.8 でも 1.3 でも年間OVRはほぼ同じ +8pt。年齢カーブの設計意図が完全に打ち消されている。

### 2.5 もう一つの問題: calcGrowth の `/9` と実際の練習回数

```
calcGrowth: perPractice = seasonBudget × 0.6 × share / 9
```

設計書は「各ステ9週の練習」を想定しているが、実際は:
- 48週中24週が練習可能（偶数週=興行）
- pickGrowthStatは5ステから一様選択（mn含む）
- mn選択時は calcGrowth が 0 を返す（成長なし）
- 有効練習 = 24 × 0.8 = 19.2回 / 4ステ = **4.8回/ステ**

`/9` で割っているが実際は4.8回しかないため、練習成長は設計の約53%。ただし試合成長が膨大なので結果的にトータルは「多すぎる」方向。

## 3. 「緩すぎる」の実態

プレイヤーから「全キャラ突き抜けている」という声が出ている理由:

1. **試合成長が無制限**: seasonBudgetの枠外で、毎試合 0.7+ のbase growthが発生
2. **試合数が多い**: 24興行/シーズン × ほぼ全員出場（小規模ロスター）
3. **年齢カーブが効かない**: 27歳でも17歳でもOVR+7-8/年
4. **AIは年+2-3止まり**: seasonBudgetに制限されているため頭打ち
5. **結果**: S5-6で追いつき、S10以降は圧倒的優位

---

## 4. バランス調整案

### 案A: matchGrowthBase を下げる（推奨: 最小の変更で効果大）

```
matchGrowthBase: 0.7 → 0.25-0.35
```

試合成長を 1試合あたり ~0.35pt に下げると、24試合で ~8.4pt。
練習成長 ~19pt + 試合成長 ~8.4pt = ~27pt → OVR+5.4/年（ageMul=1.0時）。

AIのseasonBudget（13.4-17.4pt）との差が縮まり、コーチやスケジュール管理で差をつける設計が機能するようになる。

### 案B: 試合成長をseasonBudget内に統合する（設計書の理想に最も忠実）

```
matchSharePerGame = seasonBudget × (1 - practiceShare) / expectedMatches
                  = 8.0 × ageMul × coachMul × 0.4 / 24
```

試合成長もageMultiplierの影響下に入り、年齢カーブが完全に機能する。
ただし「強い相手に勝つ」「好試合ボーナス」等の試合固有の面白さが薄れるリスク。

### 案C: aiMatchEquivalent を引き上げる

```
aiMatchEquivalent: 1.15 → 2.5-3.0
```

AIが強くなりすぎる可能性。根本解決にはならない。

### 案D: 試合数による逓減（折衷案として良い）

```
12試合目まで: matchGrowthBase × 1.0
13-20試合: matchGrowthBase × 0.5
21試合以降: matchGrowthBase × 0.2
```

出場管理に戦略性が生まれる。ロスターが大きくなれば1人あたりの試合が減り、自然な逓減に。

### 案E: ageMultiplier を試合成長にも適用する

```
matchGrowth = (matchGrowthBase + bonuses) × ageMultiplier(age)
```

最小限の修正で年齢カーブが全成長に効く。ただしbase値の問題は残る。

---

## 5. 推奨: 案A + 案E の組み合わせ

```js
// engine.js: 試合成長計算部分
const matchGrowthBase = 0.30;  // 0.7 → 0.30 に引き下げ
const ageMul = ageMultiplier(fighter.age, fighter.traits);
let matchGrowth = (matchGrowthBase + opponentBonus + closeMatchBonus + resultBonus) * ageMul;
```

期待される結果:
- 21歳(ageMul=1.3): 試合 ~11pt + 練習 ~19pt = ~30pt → OVR+6/年
- 27歳(ageMul=0.6): 試合 ~5pt + 練習 ~15pt = ~20pt → OVR+4/年
- AI S級(21歳): seasonBudget 17.4pt → OVR+3.2/年

プレイヤーはまだAIより速く成長するが、差は2倍程度に抑えられる。S級に追いつくにはS7-8程度が目安になり、「全キャラ突き抜け」はS12以降にずれる。

---

## 6. `/9` 問題について

これは直接のバランス崩壊原因ではないが、設計意図との乖離があるため記録:

- 設計書: 各ステ9回の練習を想定
- 実装: 各ステ~4.8回（24練習週 ÷ 5ステ均等）

修正する場合は `/9` を `/5` に変更するが、同時に試合成長の調整も必要。単独では練習成長が約2倍になり、さらにバランスが崩れる。
