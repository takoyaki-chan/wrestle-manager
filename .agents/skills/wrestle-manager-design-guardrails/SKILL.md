# 目的

Wrestle-Managerの中心体験と既存実装を、一般論や大規模改修から守る。このスキルは `sakurai-game-design-review` より上位とする。

# 優先順位

1. ユーザーの最新の明示指示
2. このスキル
3. 現在の仕様・既存コード
4. 現在作業中のブランチ・未コミット変更
5. 実際の動作、プレイテスト、ユーザー報告
6. 汎用ゲームデザイン原則

# 作業開始時

- 現在のブランチ、worktree、`git status`を確認する。
- 未コミット変更のあるファイルは差分を読んでから触る。
- ユーザーが別のCodex窓やブランチで並行作業している前提で扱う。
- 大規模リファクタリング、全面複製、新状態システムを初期案にしない。
- 最小変更で達成できる案から進める。

# 中心体験

Wrestle-Managerは、女子プロレス団体の経営、育成、編成、試合観戦を通じて、選手の個性、成長、因縁、勝負の流れを楽しむゲームである。

重視するもの:

- 経営上の判断
- 選手ごとの尖った個性
- 試合を見て理解・応援できること
- 結果の因果を確認できること
- 団体や選手の物語を想像できること

# 試合画面

- 俯瞰リングを基本とする。
- 技発生時、リング中央付近へ技画像を短時間オーバーレイする。
- 技画像を常設パネルとして追加しない。
- 能力値、HP、OVR、ダメージログを安易に隠さない。
- ログは小さく整理してよいが、技名、正確なダメージ、HP変化、決着理由を後から確認可能にする。
- 中央実況は現在の出来事、履歴ログは過去の因果確認という役割に分ける。
- 通常技、大技、必殺技、決着の重要度を時間・音・表示で分ける。
- CPUの結果をインチキに見せず、能力・状態・ログから理由を追えるようにする。

# テンポ

削る対象:

- 処理待ち
- 意味のない画面遷移
- 同じ確認操作
- 読めないまま過ぎる表示

守る対象:

- 技前の溜め
- 大技の決定的瞬間
- ダウン後の余韻
- 反撃前の緊張
- 決着の重み

# 技画像

標準素材は次の方向で統一する。

- 攻め側: 画面右
- 受け側: 画面左
- 攻め手: 左向き

左側の選手が攻撃する場合は標準素材を反転して使う。

- 1技1画像で、一覧表や説明図にしない。
- 輪郭だけでも攻守、向き、技の形が分かるようにする。
- 人物内部の穴、欠損、半透明を作らない。
- 素材単体ではなく、リング、ゲージ、実況、ログと合成した画面で採否を決める。
- 技画像カテゴリは30個を基準セットとし、100以上の技をカテゴリIDへ割り当てる。
- まず基準セットを検証し、確認前に無制限に画像を増やさない。

# ReplayとEngine

- 現行の、勝敗・技・ダメージ等を先に計算してframesを再生するReplay方式を維持する。
- 表示改善だけのために `match-engine.js` を大きく作り替えない。
- 新しい戦闘状態システムを勝手に追加しない。
- 本編とデモで別のバトルエンジンを複製しない。
- UIはstateを直接書き換えず、Engine API経由で更新する。
- 描画中にstateを書き換えない。

# データと公開デモ

- 公開デモへ製品版全選手データ、未公開画像、秘密情報、個人情報を含めない。
- デモ専用のlocalStorage名前空間を使い、本編セーブと干渉させない。
- 保存形式を変える場合は既存セーブの互換性と移行を確認する。
- バトルデモは共有Engineを使う独立Webアプリとして扱い、本編を丸ごと複製しない。

# ブランチと作業保護

- mainとバトルデモ等の作業を混ぜない。
- ユーザーが依頼していないcheckout、reset、ファイル削除、初期化を行わない。
- 別ブランチ、別worktree、別Codex窓の作業を巻き込まない。
- 変更前に触るファイルと触らない範囲を明示する。

# 汎用原則との衝突

- 「HUDを減らす」より、能力値・OVR・ログの常時確認を優先する。
- 「テンポを速くする」より、プロレスの溜め・余韻・緊張を守る。
- 「初心者向けに簡略化する」より、経営・観戦の深さを守り、説明と入口で対応する。
